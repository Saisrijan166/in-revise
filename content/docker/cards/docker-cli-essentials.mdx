## What it is

The Docker CLI is the `docker` command you type in a terminal; it sends each request to the Docker daemon (see [Docker architecture](card:docker-architecture)). Most commands act either on an image (the packaged app) or on a container (one running copy of it). This concept collects the commands you use every day, grouped by the step of the [container lifecycle](card:container-lifecycle) they belong to.

## Why it exists

Many commands sound alike: `run` and `start`, `rm` and `rmi`, `stop` and `kill`. Mix them up and you create a second container when you meant to restart the first, or delete an image you still need. Knowing which command creates, starts, enters or deletes which object keeps your machine tidy and your debugging fast.

## How it works

| Step | Command |
|---|---|
| Build, list images | `docker build -t payment-service:1.4.0 .`, `docker images` |
| Run in the background | `docker run -d --name pay -p 8080:8080 payment-service:1.4.0` |
| List containers | `docker ps` (running), `docker ps -a` (all) |
| Look inside | `docker logs -f pay`, `docker exec -it pay sh`, `docker inspect pay`, `docker stats` |
| Stop, start, restart | `docker stop pay`, `docker start pay`, `docker restart pay` |
| Delete | `docker rm pay` (`-f` if running), `docker rmi payment-service:1.4.0` |
| Move images | `docker pull redis:8`, `docker push <registry>/payment-service:1.4.0` |
| Disk and cleanup | `docker system df`, `docker system prune` |

1. `docker build` turns a Dockerfile into an image with a name and tag.
2. `docker run` creates a container from that image and starts it. `-d` (detached) runs it in the background; `--name` gives it a name you can type instead of its ID.
3. `docker ps` shows that it is up. `docker logs` prints what the app wrote to its console, and `docker exec -it pay sh` opens a shell inside it: `-i` keeps input open and `-t` gives you a terminal.
4. `docker stop` ends the main process; `docker start` runs the same container again.
5. `docker rm` deletes the container, then `docker rmi` can delete the image.

## Example

A short session with the payment service (a stand-in app), with the real output:

```bash
docker run -d --name pay -p 8080:8080 payment-service:1.4.0
docker stop pay && docker start pay
docker logs pay
docker rm pay
```

```text output
4e09d626d3b3cd47b8ca2c66509b93fe674be8033cd4bc3c613877d4b7a3f346
pay
pay
payment-service started on 8080
SIGTERM received: finishing in-flight payment
Shutdown complete
payment-service started on 8080
Error response from daemon: cannot remove container "pay": container is running: stop the container before removing or force remove
```

What to notice:

- `docker run -d` prints the new container's ID and returns at once; the app keeps running in the background.
- After `stop` and `start`, `docker logs` shows both runs. `start` reused the same container; a second `docker run --name pay` would fail, because that name is taken.
- `docker rm` refuses a running container. Stop it first, or use `docker rm -f`.

## Rules and defaults

- **`docker run` and missing images:** with the default `--pull missing`, Docker pulls the image only when it is not on the machine already.
- **`docker rmi` refuses** while any container, running or stopped, uses the image, unless you add `-f`.
- **`docker system prune`:** removes stopped containers, networks no container uses, dangling (untagged) images and unused build cache. `-a` also removes every image no container uses. `--volumes` adds anonymous volumes no container uses; named volumes are never removed by it.
- **`save` vs `export`:** `docker save` writes an image, with its layers and tags, to a tar file (`docker load` reads it back). `docker export` writes one container's filesystem, without its volumes and without image history.

## Not to be confused with

`docker run` makes a new container from an image, `docker start` resumes an existing stopped container, and `docker exec` adds a command to a running container. Rule: run to create, start to resume, exec to look inside.

## Common mistakes

- **"docker ps shows all my containers."** It shows only running ones. A crashed container appears only with `docker ps -a`.
- **"Leaving the exec shell stops the container."** The shell is an extra process; the container runs on as long as its main process runs.

## Interview Qs

### What is the difference between docker run and docker start?

`docker run` creates a new container from an image and starts it, every time. `docker start` runs an existing stopped container again, with its writable layer and logs from before. Running `docker run` twice with the same `--name` fails, because the first container still exists.

### How do you get a shell inside a running container?

`docker exec -it pay sh`, or `bash` if the image has it. It starts an extra process next to the main one, so leaving the shell does not stop the container. If the container has already exited, start it first or read its `docker logs`.

### What does docker system prune remove?

Stopped containers, networks that no container uses, dangling images and unused build cache. With `-a` it also removes all images that no container uses; with `--volumes` it adds anonymous volumes. Named volumes, which usually hold database data, stay.
