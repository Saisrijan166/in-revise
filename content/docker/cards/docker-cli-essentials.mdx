## Why it exists

A dozen commands cover daily work. Knowing which one creates, starts, enters or deletes what keeps you from losing a container.

## How it works

| Task | Command |
|---|---|
| Build, list images | `docker build -t payment-service:1.4.0 .`, `docker images` |
| Run detached | `docker run -d --name pay -p 8080:8080 payment-service:1.4.0` |
| List containers | `docker ps`, `docker ps -a` |
| Logs, shell | `docker logs -f pay`, `docker exec -it pay sh` |
| Stop, start, restart | `docker stop pay`, `docker start pay`, `docker restart pay` |
| Delete | `docker rm pay` (`-f` if running), `docker rmi payment-service:1.4.0` |
| Inspect, live usage | `docker inspect pay`, `docker stats` |
| Copy out, disk, cleanup | `docker cp pay:/tmp/heap.hprof .`, `docker system df`, `docker system prune` |
| Pull, push | `docker pull redis:8`, `docker push <registry>/payment-service:1.4.0` |
| Image as a file | `docker save -o pay.tar payment-service:1.4.0`, `docker load -i pay.tar` |

- `save` keeps the image's layers and tags; `export` dumps one container's filesystem, without volume contents.
- Stop vs kill: [lifecycle](card:container-lifecycle). Log options: [logging](card:container-logging).

## Interview Qs

### docker run vs docker start?

`run` creates a new container from an image each time. `start` brings back an existing stopped container with its writable layer intact. A second `docker run` gives a second container.

### How do you get a shell in a running container?

`docker exec -it pay sh` (or `bash` if the image has it). It adds a process next to PID 1, so leaving the shell does not stop the container.

### What does docker system prune remove?

Stopped containers, unused networks, dangling images and unused build cache. `-a` also removes every image no container uses; `--volumes` adds anonymous volumes. Named volumes stay.
