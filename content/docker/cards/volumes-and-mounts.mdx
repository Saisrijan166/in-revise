## Why it exists

A container's files sit in a writable layer deleted with the container. Databases and uploads need storage that outlives it.

## How it works

<Compare id="volume-vs-bind-mount-vs-tmpfs" />

- An empty volume mounted on a non-empty image folder is first filled with the image's files.
- A bind mount, or a non-empty volume, hides the image's files at that path.
- `--mount type=volume,src=pgdata,dst=/data` is preferred: explicit, every option; `-v` is shorter.

## Example

```bash
docker volume create pgdata
# postgres 18+: mount the parent folder, not /var/lib/postgresql/data
docker run -d --name postgres --network payments-net --env-file pg.env \
  -v pgdata:/var/lib/postgresql postgres:18
docker rm -f postgres            # pgdata is kept
docker volume inspect pgdata     # Mountpoint: /var/lib/docker/volumes/pgdata/_data
```

## Defaults

| What | Default | Where |
|---|---|---|
| `docker volume prune` | Removes unused anonymous volumes; `-a` for named | Since Engine 23.0 |
| Empty volume over image files | Files are copied in; `volume-nocopy` stops it | Docker Engine 29 |
| postgres data mount | `/var/lib/postgresql` (18+); `/var/lib/postgresql/data` (17 and below) | postgres official image |

## Interview Qs

### How do you upgrade a database container without losing data?

Keep the data directory on a named volume. Remove the old container and run the new image with the same volume.

### Where are Docker volumes stored?

On Linux under `/var/lib/docker/volumes/<name>/_data`. Use them through containers, not by editing those files.

### Volume or bind mount for a Spring Boot app in development?

Bind-mount the source or config you edit on the host; use a named volume for the database. Bind mounts tie the container to the host's folder layout.
