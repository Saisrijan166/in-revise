## What it is

A registry is a server that stores [images](card:images-and-layers) so other machines can download them. `docker push` uploads an image and `docker pull` downloads one. Docker Hub is the public registry Docker uses by default; companies also run private ones. Inside a registry, each app has a repository, and each version in it is found by a tag, a name such as `1.4.0`, or by a digest, a hash of the exact content.

## Why it exists

`docker build` stores the payment-service image only on the machine that built it. The test server and the production servers need that same image. Copying image files around by hand is slow and easy to get wrong. A registry gives one place to push the image once and pull it anywhere, and a precise name for which version you want.

## How it works

1. You give the local image a full name that starts with the registry's address, using `docker tag`.
2. `docker push` uploads the layers the registry does not have yet, plus a manifest: a small file that lists the image's layers. The registry replies with the digest, the sha256 hash of that manifest.
3. A server runs `docker pull` with the tag. The registry looks up which manifest the tag points to now, and the server downloads only the layers it is missing.
4. If someone later pushes a different image with the same tag, the tag moves to the new manifest. The old digest still finds the old image.

So the key is: a tag is a pointer that can move, a digest is the content itself.

## Example

A private registry runs on this machine at `localhost:5000`, started from Docker's own registry image with `docker run -d -p 5000:5000 registry:3`. The payment-service image goes in and comes back out by digest.

```bash
docker tag payment-service:1.4.0 localhost:5000/payments/payment-service:1.4.0
docker push localhost:5000/payments/payment-service:1.4.0 | tail -1
docker pull -q localhost:5000/payments/payment-service@sha256:b708dc5a1185f3b55b4b3f6761d8a9519de3cfff034a8a235fa81853e831c0ea
```

```text output
1.4.0: digest: sha256:b708dc5a1185f3b55b4b3f6761d8a9519de3cfff034a8a235fa81853e831c0ea size: 856
localhost:5000/payments/payment-service@sha256:b708dc5a1185f3b55b4b3f6761d8a9519de3cfff034a8a235fa81853e831c0ea
```

What to notice:

- `docker tag` copies no data; it adds a second name to the same local image. The first part of that name, `localhost:5000`, tells Docker which registry to push to.
- The last line of `docker push` prints the digest (and the manifest's size in bytes). CI can save this value and pass it to the deploy.
- The pull uses `@sha256:…` instead of `:1.4.0`. If 1.4.0 is pushed again tomorrow, this line still pulls exactly the image you tested.

## Rules and defaults

| Part of the name | Example | If you leave it out |
|---|---|---|
| Registry host (and port) | `localhost:5000` | `docker.io`, which is Docker Hub |
| Namespace | `payments` | `library`, the home of Docker Official Images |
| Repository | `payment-service` | required |
| Tag | `:1.4.0` | `:latest` |
| Digest | `@sha256:…` | not used |

- **Login:** `docker login <host>` before pushing, and before pulling from a private repository.
- **Docker Hub limits:** 100 pulls per 6 hours per IPv4 address (or IPv6 /64 subnet) without login; 200 for a Personal account; Pro, Team and Business are unlimited under fair use.
- **No registry needed locally:** `docker build` then `docker run` on the same machine never touches a registry.

## Not to be confused with

A registry is the whole server, such as Docker Hub. A repository is one app's set of images inside it, such as `payments/payment-service`. A tag is a movable label on one image in that repository; a digest is a fixed hash of its content. Rule: tag for people, digest for machines that must get the same bytes.

## Common mistakes

- **"Only latest can change."** Any tag can be pushed again with new content, `1.4.0` included. Only a digest is fixed.

## Interview Qs

### Registry vs repository vs Docker Hub: what is the difference?

A registry is the service that stores and serves images. A repository is one collection of related images inside it, usually one app, with a tag per version. Docker Hub is Docker's public registry and the one Docker uses when a name has no host.

### How do you make sure production runs exactly the image you tested?

Deploy by digest, `name@sha256:…`, not by tag. A tag can be pushed again with new content, but a digest is a hash of the content, so a different image always has a different digest. CI records the digest after the push and passes it to the deploy.

### CI fails to pull from Docker Hub with a rate-limit error. Why, and how do you fix it?

Without login, Docker Hub allows 100 pulls per 6 hours per IP address, and CI jobs often share one IP. Log in with an account, which raises or removes the limit by plan, or mirror the images you need into your own registry.
