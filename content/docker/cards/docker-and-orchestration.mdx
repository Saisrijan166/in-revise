## Why it exists

With `docker run` or Compose on one server, the app dies with that server. An orchestrator spreads containers over many machines and keeps them running.

## How it works

<Compare id="docker-vs-compose-vs-kubernetes" />

- Kubernetes talks to a runtime through the Container Runtime Interface, not to dockerd ([Docker's layers](card:docker-architecture)).
- Docker Swarm mode is built into Docker Engine for a cluster of Docker hosts.
- Compose can serve production on a single server ([Compose](card:docker-compose)).

## Interview Qs

### Does Kubernetes replace Docker?

No. Docker builds images and runs containers; Kubernetes orchestrates them across nodes. Since 1.24 it does not need Docker Engine on nodes, but images built with Docker still run unchanged.

### Can Kubernetes run without Docker?

Yes. Each node needs a CRI runtime such as containerd or CRI-O. Docker Engine works only through the cri-dockerd adapter.

### Is Docker Compose the same as Kubernetes?

No. Compose starts a multi-container app on one Docker host, mostly for development and tests. Kubernetes schedules across a cluster, replaces failed containers and rolls out updates.
