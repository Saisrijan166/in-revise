## Why it exists

A container's ports are reachable from the host and from its own network, but not from other machines. Publishing maps a host port to a container port so clients outside can call the service.

## How it works

<Compare id="expose-vs-publish" />

- Order is outside:inside, so `-p 9090:8080` sends host port 9090 to the app's 8080.
- `-p 8080` or `-P` lets Docker pick a free host port; read it with `docker port`.
- In [host network mode](card:docker-networking) `-p` is ignored: the app uses host ports directly.

## Example

```bash
docker run -d --name payment-service -p 127.0.0.1:8080:8080 payment-service:1.4.0
docker run -d --name payment-test -P payment-service:1.4.0
docker port payment-test
# 8080/tcp -> 0.0.0.0:55021
```

## Defaults

| What | Default | Where |
|---|---|---|
| Host address when none is given | All interfaces (0.0.0.0) | Docker Engine 29 |
| Protocol | TCP; add `/udp` for UDP | EXPOSE and `-p` |
| Host port for `-P` or `-p 8080` | Random port from the ephemeral range | Docker Engine 29 on Linux |

## Interview Qs

### What is the difference between EXPOSE and -p?

EXPOSE records the app's port in the image and publishes nothing. `-p` at run time opens a host port and forwards it to the container. `-P` publishes all EXPOSEd ports to random host ports.

### Do two containers need published ports to talk to each other?

No. On the same Docker network they use the container port directly, for example `postgres:5432`. Publish only what clients outside the host need.

### How do you keep a published port off the internet?

Bind it to loopback, `-p 127.0.0.1:8080:8080`, or do not publish it. On Linux, ufw does not block published ports.
