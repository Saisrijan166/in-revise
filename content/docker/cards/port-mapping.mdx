## What it is

Publishing a port means opening a port on the host and forwarding its traffic to a port inside a container. You do it at run time with `-p HOST_PORT:CONTAINER_PORT`. The container port is where the app listens, for example 8080 for the payment service. The host port is what a browser or another machine calls.

## Why it exists

A container has its own network stack, as [Docker networks](card:docker-networking) showed. By default, machines outside the Docker host and containers on other networks cannot reach its ports. That is safe, but a browser, a mobile app or a load balancer must still call the payment service. Publishing opens exactly one door: the host port you choose, forwarded to the app's port.

## How it works

<Compare id="expose-vs-publish" />

1. You run `docker run -p 9090:8080 payment-service:1.4.0`.
2. Docker adds a forwarding rule on the host: traffic to host port 9090 goes to port 8080 of this container.
3. A client calls `http://<host>:9090`. With no IP in `-p`, every address of the host accepts it, so other machines can call it too.
4. The request reaches the app inside the container on port 8080. The app must listen on `0.0.0.0`, or the forwarded traffic is refused.

So the key is: `-p` is the only thing that opens a port to the outside; EXPOSE only describes it.

## Example

The payment service runs twice: once published to this host only, and once with `-P`, which lets Docker pick the host port.

```bash
docker run -d --name payment-service -p 127.0.0.1:9090:8080 payment-service:1.4.0
curl localhost:9090/health

docker run -d --name payment-test -P payment-service:1.4.0
docker port payment-test
# 8080/tcp -> 0.0.0.0:32769
# 8080/tcp -> [::]:32769
```

What to notice:

- `127.0.0.1:9090:8080` makes the health check work from this host, but another machine calling port 9090 gets no answer.
- `-P` publishes only the ports listed with EXPOSE in the image, here 8080, each to a random free host port. `docker port` shows which one.
- The two `docker port` lines show the default: no IP was given, so the port is open on all IPv4 (`0.0.0.0`) and IPv6 (`[::]`) addresses.
- If the app inside listened on `127.0.0.1:8080` instead of `0.0.0.0:8080`, the curl would fail even with `-p`.

## Rules and defaults

- **Format:** `-p [HOST_IP:]HOST_PORT:CONTAINER_PORT[/udp]`. TCP is the default protocol.
- **Host address:** with no IP, Docker publishes on all host addresses, `0.0.0.0` and `[::]` (Docker Engine 29). Docker's docs call this insecure by default.
- **Firewall:** on Linux, Docker writes its own iptables rules, so a ufw rule that blocks the port does not stop a published port.
- **No host port:** `-p 8080` or `-P` gets a random free host port; `docker port` or `docker ps` shows it.
- **Host network mode:** with `--network host`, Docker discards `-p` and prints a warning, because the app already uses the host's ports directly.
- **Between containers:** containers on the same network reach every port of each other with no publishing.

## Not to be confused with

`EXPOSE 8080` is a Dockerfile instruction that records the app's port in the image as information; it opens nothing. `-p 8080:8080` is a run-time flag that opens a host port and forwards it into the container. Rule: EXPOSE documents, `-p` opens.

## Common mistakes

- **Publishing the database "so the app can reach it".** On one network the app uses `postgres:5432` with no `-p`. Publish the database only when a tool on the host must connect, and then on `127.0.0.1`.
- **Swapping the order.** `-p 8080:9090` forwards host 8080 to container 9090. The host side always comes first.

## Interview Qs

### What is the difference between EXPOSE and -p?

EXPOSE records the app's port in the image and publishes nothing. `-p` at run time opens a host port and forwards it to the container port. `-P` publishes every EXPOSEd port to random host ports, so EXPOSE matters only together with `-P`.

### Do two containers need published ports to talk to each other?

No. Containers on the same network reach each other's container ports directly, for example `postgres:5432`. Publish only what clients outside the Docker host need, which keeps the database off the host's ports.

### How do you keep a published port off the internet?

Bind it to loopback with `-p 127.0.0.1:9090:8080`, so only the Docker host can connect, or do not publish it at all. On Linux, do not rely on ufw: Docker's own iptables rules let published ports through.
