## Why it exists

An image rebuilt per environment may not match the one that passed the tests. Building once and promoting it means production runs exactly what CI checked.

## How it works

<Steps label="One pipeline run for payment-service">
  <Step title="Build">docker buildx build with a registry cache ([build cache](card:build-cache)).</Step>
  <Step title="Test">Unit tests, then integration tests with Testcontainers.</Step>
  <Step title="Scan">Fail on serious CVEs ([secure images](card:image-security)).</Step>
  <Step title="Tag and push">Git SHA and 1.4.0 to the [registry](card:registries).</Step>
  <Step title="Deploy">Staging, then prod, by digest; config comes from the environment ([config](card:env-and-secrets)).</Step>
</Steps>

- A release is never changed: a fix means a new build and a new tag.
- CI that needs Docker: Docker-in-Docker needs `--privileged`; mounting the host's docker.sock hands over the host ([runtime security](card:container-runtime-security)).

## Example

```java
@Testcontainers
@SpringBootTest
class PaymentRepositoryTest {
    @Container @ServiceConnection
    static PostgreSQLContainer postgres = new PostgreSQLContainer("postgres:18");
    @Autowired PaymentRepository payments;
    @Test
    void savesUpiPayment() {
        payments.save(new Payment("UPI", 500));     // a ₹500 UPI payment
        assertEquals(1, payments.count());
    }
}
```

## Interview Qs

### How would you build and deploy a Docker image in CI/CD?

Build once with a cache, run tests, scan, tag with the git SHA and version, push. Deploy that image by digest to staging, then prod, changing only config.

### Why not deploy `latest` to production?

It is a movable tag, not a version. Two hosts can pull different images and a rollback has no fixed target. Use a unique tag and the [digest](compare:tag-vs-digest).

### How do you test code that needs a real database?

Testcontainers starts Postgres in a throwaway container for the tests; Spring Boot's @ServiceConnection points the app at it. No shared test database, no mocks of SQL.
