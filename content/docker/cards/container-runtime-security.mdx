## Why it exists

Containers share one kernel with the host ([namespaces and cgroups](card:namespaces-and-cgroups)). A default container is fairly safe, but a few flags can hand it the whole machine.

## How it works

| Setting | What it stops |
|---|---|
| `--read-only` + `--tmpfs /tmp` | writes to the root filesystem; scratch space stays in memory |
| `--cap-drop ALL` | root-only kernel actions, such as raw sockets |
| `--security-opt no-new-privileges=true` | processes gaining new privileges after start |
| no `--privileged` | full host access: all capabilities and devices |
| no `docker.sock` mount | the container taking over the daemon, and so the host |

- Run as a non-root user too: see [Secure Images](card:image-security).
- The default seccomp profile blocks about 44 of 300+ system calls; never use `seccomp=unconfined`.
- CPU and memory caps against noisy neighbours are in [resource limits](card:resource-limits).

## Example

```bash
docker run -d --name payment-service \
  --read-only --tmpfs /tmp \
  --cap-drop ALL \
  --security-opt no-new-privileges=true \
  -p 8080:8080 payment-service:1.4.0
```

## Interview Qs

### Are containers completely isolated?

No. They share the host kernel, so isolation depends on configuration: dropped capabilities, seccomp, AppArmor or SELinux, a non-root user, and not adding risky flags like `--privileged`.

### What does --privileged do?

Every capability, all host devices, and relaxed AppArmor or SELinux. It exists for special cases such as Docker inside Docker; never use it for apps.

### Rootless mode vs userns-remap?

Both map container root to an unprivileged host user. With userns-remap the daemon still runs as root; in rootless mode the daemon and the containers both run as a normal user.
