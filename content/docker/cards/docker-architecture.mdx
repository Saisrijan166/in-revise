## What it is

Docker is a client-server system. The `docker` command you type is only the client: it sends each command as a request to dockerd, the Docker daemon. A daemon is a program that runs in the background all the time; dockerd builds [images](card:images-and-layers), pulls them from [registries](card:registries) and runs containers. To start a container, dockerd uses two smaller tools: containerd, which manages containers, and runc, which asks the kernel to start the container's process.

## Why it exists

Running containers needs a program that stays alive after your command ends: it must watch the payment-service container, keep its logs and restart it if it crashes. It also needs root rights to use kernel features. A short-lived command cannot do that. So Docker splits the work: one long-running daemon does it, and thin clients, such as the CLI, Docker Compose or a CI tool, talk to it through one API, from the same machine or another one.

What happens when you type `docker run payment-service:1.4.0`:

1. The CLI turns the command into an HTTP request to the Docker API and sends it to the daemon, by default through the Unix socket `/var/run/docker.sock`.
2. dockerd checks its local image store. If the image is missing, it pulls it from the registry first.
3. dockerd creates the container: it adds a writable layer on top of the image and creates a network interface with an IP address.
4. dockerd hands the container to containerd, which calls runc. runc sets up the isolation, explained in [namespaces and cgroups](card:namespaces-and-cgroups), and starts the process.

So the key is: the CLI only asks; dockerd decides; containerd and runc do the low-level start.

## Example

Two questions that show the layers of the engine on a Linux host:

```bash
docker version --format '{{range .Server.Components}}{{println .Name .Version}}{{end}}'
curl -s --unix-socket /var/run/docker.sock http://localhost/version | grep -o '"ApiVersion":"[^"]*"' | head -1
ls -l /var/run/docker.sock
```

```text output
Engine 29.1.3
containerd 2.2.1
runc 1.3.4-0ubuntu1~24.04.1
docker-init 0.19.0

"ApiVersion":"1.52"
srw-rw---- 1 root docker 0 Oct 22 10:12 /var/run/docker.sock
```

What to notice:

- The daemon reports the parts from the diagram: Engine (dockerd), containerd and runc. docker-init is a tiny helper process you meet in [PID 1 and signals](card:signals-and-graceful-shutdown).
- `curl` talks to the same socket and gets an answer without the docker CLI at all. The CLI is just one client of this HTTP API.
- The socket belongs to `root` and the `docker` group. Anyone who can write to it can tell a root daemon what to do.

## Rules and defaults

- **Socket:** on Linux the CLI connects to `unix:///var/run/docker.sock` by default. Point it at another daemon with `-H`, the `DOCKER_HOST` variable or a `docker context`.
- **Root-level access:** the daemon runs as root unless you use rootless mode, and Docker's docs warn that the `docker` group grants root-level privileges. Hardening is in [runtime security](card:container-runtime-security).
- **Runtime:** dockerd's default OCI runtime is runc.
- **Image store:** since Docker Engine 29.0, fresh installs use the containerd image store; hosts upgraded from older versions keep the classic storage driver, such as overlay2.
- **Registry optional:** `docker build` followed by `docker run` on one machine never needs a registry.

## Not to be confused with

Docker Engine is the open-source server and client: dockerd, its API and the docker CLI. Docker Desktop is a desktop app that packages the engine, Compose and a Linux VM for laptops. Rule: servers run Docker Engine; developer laptops on macOS or Windows usually run Docker Desktop.

## Interview Qs

### What happens when you type docker run?

The CLI sends an API call to dockerd. dockerd pulls the image if it is missing, creates the container with a writable layer and a network interface, and hands it to containerd, which starts the process through runc.

### Do you need a registry to run a container?

No. `docker build` stores the image in the daemon's local store and `docker run` uses it from there. A registry is needed only to share images between machines, such as from CI to servers.

### Why is access to the Docker socket dangerous?

The socket is the API of a daemon that runs as root. Anyone who can call it can start a privileged container or mount the host's files, which is the same as root on the host. Treat the docker group, and mounting docker.sock into a container, as granting root.

### Is Docker free for companies?

Docker Engine is open source. Docker Desktop is free for personal use, education, non-commercial open source and small companies (under 250 employees and under USD 10 million revenue); larger companies and governments need a paid subscription.
