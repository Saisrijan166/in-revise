## Why it exists

Building and running containers needs a long-running service with root access to the kernel. Splitting client and daemon lets any tool, local or remote, drive it through one API.

## How it works

<Mermaid
  alt="The docker CLI sends REST API calls over the Unix socket /var/run/docker.sock to dockerd. dockerd passes containers to containerd, which calls runc, which starts the container. dockerd also pulls images from and pushes images to a registry."
  chart={`flowchart LR
  CLI([docker CLI]) -- "REST API, docker.sock" --> D[dockerd]
  D --> C[containerd]
  C --> R[runc]
  R --> K([Container])
  D <-->|"pull / push"| REG[(Registry)]`}
/>

- Docker Desktop bundles dockerd, the CLI and Compose, with a Linux VM on macOS and Windows.
- Anyone who can reach docker.sock controls the host: see [runtime security](card:container-runtime-security).

## Example

```bash
docker build -t payment-service:1.4.0 .            # Dockerfile -> image (stored locally)
docker run -d -p 8080:8080 payment-service:1.4.0   # image -> container
docker version     # Client section, then Server: Engine, containerd, runc
```

## Interview Qs

### What happens when you type docker run?

The CLI calls the daemon's API. dockerd pulls the image if it is missing, creates the container with a writable layer and a network interface, and containerd starts it through runc.

### Do you need a registry to run a container?

No. docker build stores the image locally and docker run uses it. A registry is needed only to share images between machines, such as CI and servers.

### Is Docker free for companies?

Docker Engine is open source. Docker Desktop is free for personal use, education, non-commercial open source and small businesses (under 250 employees and under USD 10 million revenue); larger companies and governments must pay.
