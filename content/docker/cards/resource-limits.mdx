## Why it exists

One leaking container can starve the host, and a host out of memory may kill any process, even the Docker daemon. Limits keep the damage inside one container.

## How it works

| Flag | What it does |
|---|---|
| `--memory` (`-m`) | Hard cap, at least 6 MB; over it, an OOM kill |
| `--memory-reservation` | Soft limit, used only when the host runs short |
| `--memory-swap` | Memory plus swap; unset means swap as large again |
| `--cpus` | Hard cap (CFS quota); over it, throttled |
| `--cpu-shares` | Relative weight; counts only when CPUs are busy |
| `--pids-limit` | Maximum processes; then `fork()` fails |

- Compose: `deploy.resources.limits` (`cpus`, `memory`, `pids`), or `mem_limit` and `cpus` on the service.
- How the JVM sizes its heap from the limit: [Java in containers](card:java-in-containers).

## Example

```bash
# --memory-swap = --memory: no swap
docker run -d --name pay --memory 1g --memory-swap 1g --cpus 1.5 \
  --pids-limit 200 payment-service:1.4.0
docker inspect -f '{{.State.OOMKilled}}' pay
```

## Defaults

| What | Default | Where |
|---|---|---|
| Memory and CPU | No limit | Docker Engine 29 |
| `--cpu-shares` | 1024 | Docker Engine 29 |
| `--cpu-period` | 100 ms (`--cpus 1.5` = quota 150 ms per period) | Docker Engine 29 |

## Interview Qs

### What happens when a container goes over its memory limit? Its CPU limit?

Memory: the kernel's OOM killer kills a process in it; if that is PID 1 the container exits and `docker inspect` shows `OOMKilled: true`. CPU: it is throttled to its quota and runs slower, but keeps running.

### Limit vs reservation?

A limit is a ceiling the container cannot pass. `--memory-reservation` is a soft limit and `--cpu-shares` a relative weight; both act only when the host is short of memory or CPU.
