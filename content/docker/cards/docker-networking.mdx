## Why it exists

Each container has its own network stack and a dynamically assigned IP. payment-service needs a stable way to find postgres.

## How it works

| Driver | What it gives | Use it for |
|---|---|---|
| bridge (default) | Private network on one host | Single containers, quick tests |
| User-defined bridge | Same, plus name lookup and isolation | Every multi-container app |
| host | Shares the host's network; no own IP | Speed or many ports: no NAT |
| none | No network at all | Fully isolated jobs |
| overlay | One network across many Docker hosts | Swarm services |

- A container can join several networks: `docker network connect`.
- Compose creates one network per project for you: see [Docker Compose](card:docker-compose).
- Opening a port to the outside world is a separate step: [Publishing Ports](card:port-mapping).

## Example

```bash
docker network create payments-net
docker run -d --name postgres --network payments-net --env-file pg.env postgres:18
docker run -d --name payment-service --network payments-net -p 8080:8080 \
  -e SPRING_DATASOURCE_URL=jdbc:postgresql://postgres:5432/payments \
  payment-service:1.4.0
```

## Defaults

| What | Default | Where |
|---|---|---|
| Network when `--network` is not given | Default bridge (named `bridge`) | Docker Engine 29 on Linux |
| DNS server on user-defined networks | 127.0.0.11, forwards other names to the host's DNS | Docker Engine 29 |

## Interview Qs

### The app calls localhost:5432 and cannot reach Postgres in another container. Why?

Inside a container, localhost is that container's own loopback. Put both on one user-defined network and use the container or service name: `postgres:5432`.

### How does a container reach a service running on the host?

Use `host.docker.internal`. Docker Desktop resolves it; on Linux add `--add-host host.docker.internal:host-gateway`.
