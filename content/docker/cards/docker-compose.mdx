## Why it exists

The payment service needs Postgres and Redis too. Three long docker run commands are error-prone; one file makes it repeatable.

## How it works

<Mermaid
  alt="docker compose up reads compose.yaml in the folder payments and creates the network payments_default. The containers payment-service, postgres and redis join that network. The named volume pgdata is attached to postgres."
  chart={`flowchart LR
  F[compose.yaml] --> U[docker compose up]
  U --> N((payments_default))
  N --- A[payment-service]
  N --- P[(postgres)]
  N --- R[(redis)]
  P --- V[(volume pgdata)]`}
/>

- Inside the network the app uses the container port (`postgres:5432`); host ports are for outside access.
- Change one service and run `up` again: that container is recreated with a new IP but the same name.

## Example

```yaml
services:
  payment-service:
    build: .
    ports: ["8080:8080"]
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/payments
      SPRING_DATASOURCE_USERNAME: postgres
      SPRING_DATASOURCE_PASSWORD: "${DB_PASSWORD}"
  postgres:
    image: postgres:18
    environment: { POSTGRES_DB: payments, POSTGRES_PASSWORD: "${DB_PASSWORD}" }
    volumes: ["pgdata:/var/lib/postgresql"]
  redis: { image: "redis:8" }
volumes: { pgdata: {} }
```

Everyday commands:

```bash
docker compose up -d --build   # build, start in the background
docker compose ps
docker compose logs payment-service
docker compose down            # keeps pgdata
docker compose down -v         # deletes pgdata too
```

## Interview Qs

### What is Docker Compose and when do you use it?

It runs a multi-container app from one YAML file: for local development, CI tests and single hosts. Across many machines you need an [orchestrator](card:docker-and-orchestration).

### How do containers in one Compose project talk to each other?

All services join the project's default network under their service names. The app connects to `postgres:5432`, never an IP: IPs change on recreate.

### What is the difference between docker compose down and down -v?

down removes the project's containers and networks; named volumes stay. down -v also deletes the file's named volumes and anonymous volumes.
