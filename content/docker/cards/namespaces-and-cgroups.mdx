## Why it exists

Processes on one host can see and starve each other. The kernel needs a way to hide other processes from a group and to cap what that group uses.

## How it works

  alt="A container process gets two kinds of kernel features. Namespaces control what it can see: PID, network, mount, UTS, IPC, user and cgroup namespaces. cgroups control how much it can use: memory, CPU, number of PIDs and I/O. Both run on one shared host kernel."

- The flags that set the limits are in [resource limits](card:resource-limits).
- Isolation is real but not complete; harden it with [runtime security](card:container-runtime-security).

## Example

```bash
docker run --rm alpine ps          # PID namespace: it sees only itself
PID   USER     TIME  COMMAND
    1 root      0:00 ps
docker run --rm --memory 512m alpine cat /sys/fs/cgroup/memory.max
536870912                          # cgroup v2 memory limit: 512 MiB
```

## Interview Qs

### How does Docker isolate containers?

With Linux namespaces and cgroups. Namespaces give each container its own process tree, network stack, mounts and hostname. cgroups limit and account its CPU, memory and process count, so one container cannot starve the host.

### Are containers completely isolated?

No. All containers share the host kernel, so a kernel flaw or a weak setting, such as extra capabilities or host mounts, can break isolation. A VM gives a stronger boundary.
