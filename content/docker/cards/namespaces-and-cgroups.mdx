## What it is

A container is a normal host process that the kernel isolates with two Linux features. Namespaces control what the process can see: each namespace gives it a private copy of one thing, such as the list of processes, the network or the hostname. cgroups, short for control groups, control how much it can use: CPU, memory, number of processes and disk I/O. runc sets up both when [dockerd starts a container](card:docker-architecture).

## Why it exists

Without isolation, the payment-service process on a shared server can see every other process, clash with other apps over ports and files, and a memory leak in it can use up the host's RAM until other apps are killed. Namespaces hide everything that does not belong to the container. cgroups cap what it may use. Because both are built into the kernel, Docker gets this isolation without booting a [second OS](card:containers-and-vms).

## How it works

1. On `docker run`, runc creates a new set of namespaces for the container: PID (process IDs), network, mount (the file view), UTS (the hostname), IPC (shared memory between processes) and cgroup.
2. runc places the process in a new cgroup, with any limits you asked for, such as a memory cap.
3. The process starts inside them. In its PID namespace it is PID 1, in its mount namespace it sees only the image's files, and in its network namespace it has its own IP address and ports.
4. While it runs, the kernel counts its CPU and memory use in the cgroup and enforces the limits.
5. From the host, it is still an ordinary process, with a normal host PID.

So the key is: namespaces change the view, cgroups change the budget, and the kernel stays shared.

## Example

The same `sleep` process seen from two sides, then a memory limit read back from the cgroup:

```bash
docker run --rm alpine:3.22 ps                       # the container's view
docker run -d --name pay-ns-demo alpine:3.22 sleep 300 >/dev/null
pgrep -a -f 'sleep 300'                              # the host's view
docker rm -f pay-ns-demo >/dev/null
docker run --rm --memory 512m alpine:3.22 cat /sys/fs/cgroup/memory.max
```

```text output
PID   USER     TIME  COMMAND
    1 root      0:00 ps
204947 sleep 300
536870912
```

What to notice:

- Inside the container, `ps` sees only itself, as PID 1: the PID namespace hides every host process.
- The host sees the container's `sleep` as a normal process with a large host PID. A container is not a separate machine.
- `--memory 512m` wrote 536870912 bytes (512 MiB) into the container's cgroup file `memory.max`. The kernel enforces that number. The flags and what happens at the limit are in [resource limits](card:resource-limits).

## Rules and defaults

- **User namespace off:** Docker does not use a user namespace by default, so root inside a container runs as user ID 0, the host's root, though with fewer privileges. Enable `userns-remap` to map it to an unprivileged host user.
- **cgroup namespace:** private by default for each container on cgroup v2 hosts (`--default-cgroupns-mode`).
- **cgroup version:** Docker Engine 29 deprecates cgroup v1, with support until at least May 2029; current distributions such as Ubuntu 21.10 and later use cgroup v2.

## Not to be confused with

A namespace changes what a process can see, such as its own process list. A cgroup changes how much a process can use, such as at most 512 MiB of memory. Rule: namespaces for visibility, cgroups for resources.

## Common mistakes

- **"Containers are fully isolated, like VMs."** They share the host kernel. Extra capabilities, `--privileged` or host mounts weaken the walls; hardening is in [runtime security](card:container-runtime-security).

## Interview Qs

### How does Docker isolate containers?

With two Linux kernel features. Namespaces give each container its own process tree, network stack, mounts and hostname, so it cannot see other processes. cgroups limit and measure its CPU, memory and process count, so it cannot starve the host when limits are set.

### Are containers completely isolated?

No. All containers share the host kernel, so a kernel flaw, or a weak setting such as `--privileged`, extra capabilities or a host mount, can break isolation. A VM gives a stronger boundary because it has its own kernel.

### What is the difference between a namespace and a cgroup?

A namespace limits what a process can see: its own PIDs, network or mounts. A cgroup limits how much it can use: CPU, memory, process count and I/O. A container uses both together.
