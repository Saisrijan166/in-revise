## Why it exists

A container stops when its main process ends. You must know each state, and when Docker brings a container back.

## How it works

<Mermaid
  alt="create gives a created container; start makes it running; pause and unpause toggle paused; the process ending, stop or kill make it exited; start or a restart policy runs it again; rm removes it."
  chart={`stateDiagram-v2
  [*] --> created: docker create
  created --> running: docker start
  running --> paused: docker pause
  paused --> running: docker unpause
  running --> exited: process ends, stop, kill
  exited --> running: docker start or restart policy
  exited --> [*]: docker rm`}
/>

- Other statuses: restarting, removing, dead. Paused uses the cgroup freezer.
- The app's side: [graceful shutdown](card:signals-and-graceful-shutdown). Exit codes: [troubleshooting](card:troubleshooting-containers).

## Example

```bash
docker run -d --name pay --restart unless-stopped payment-service:1.4.0
```

| `--restart` | Restarts when it exits | When the daemon restarts |
|---|---|---|
| `no` | Never | Not started |
| `on-failure[:max-retries]` | Only on a non-zero exit code | Not started |
| `always` | Yes, unless you stopped it | Started, even if you stopped it |
| `unless-stopped` | Yes, unless you stopped it | Started, unless you stopped it |

## Defaults

| What | Default | Where |
|---|---|---|
| Restart policy | `no` | Docker Engine 29 |
| Stop grace period | 10 s Linux, 30 s Windows (`-t`, `--stop-timeout`) | Docker Engine 29 |
| Stop signal | `SIGTERM` (`STOPSIGNAL`, `--stop-signal`) | Docker Engine 29 |

## Interview Qs

### The service crashed at night and stayed down. Why?

The default restart policy is `no`; use `--restart on-failure` or `unless-stopped`. A crash loop is restarted with a doubling delay, from 100 ms up to 1 minute.

### always vs unless-stopped?

Both restart on any exit. After a manual stop and a daemon restart, `always` starts it again; `unless-stopped` leaves it stopped.
