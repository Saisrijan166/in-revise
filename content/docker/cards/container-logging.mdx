## Why it exists

Containers come and go, so log files inside them are hard to reach. Writing to stdout lets Docker decide where logs go.

## How it works

<Mermaid
  alt="The service writes to stdout and stderr; the logging driver stores lines in host files (json-file, local) that docker logs reads, or sends them to a central store (fluentd, awslogs) while a dual logging cache keeps docker logs working."
  chart={`flowchart LR
  A[payment-service] -- "stdout / stderr" --> D{Logging driver}
  D -- "json-file or local" --> F[(Files on the host)]
  D -- "fluentd, awslogs" --> R[(Central log store)]
  D -. "dual logging cache" .-> F
  F --> L[docker logs]`}
/>

- Set the driver in `daemon.json` (new containers only) or per container with `--log-driver` and `--log-opt`.
- The engine's own logs are separate: `journalctl -xu docker.service` on Linux.

## Example

```json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
```

## Defaults

| What | Default | Where |
|---|---|---|
| Logging driver | `json-file` | Docker Engine 29 |
| json-file `max-size` / `max-file` | -1 (no limit) / 1 | Docker Engine 29 |
| local driver, dual-logging cache | 5 files × 20 MB, compressed | Docker Engine 29 |

## Interview Qs

### docker logs is empty, but the app runs. Why?

The app writes to a file instead of stdout and stderr, or the driver is `none`, or a remote driver runs with the dual-logging cache off. Log to the console; the nginx image links its log files to `/dev/stdout`.

### Container logs filled the host disk. Fix?

json-file does not rotate by default. Set `max-size` and `max-file` in `daemon.json` (as strings) and recreate the containers, or use the `local` driver.

### Where should production logs go?

Off the host, to a central store: a driver such as fluentd, awslogs or gcplogs. `docker logs` still works through the dual-logging cache.
