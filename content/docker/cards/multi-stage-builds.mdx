## Why it exists

The JDK, Maven and source code are needed to build a Java app, not to run it. Shipping them makes the image bigger and adds software to patch.

## How it works

<Mermaid
  alt="Two stages. The build stage on eclipse-temurin 25 JDK holds Maven, sources and the Maven cache and produces the jar. COPY --from=build moves only the jar into the final stage on eclipse-temurin 25 JRE, which becomes payment-service:1.4.0. The JDK, sources and Maven cache stay behind."
  chart={`flowchart LR
  B["Stage build: 25-jdk, Maven, src, ~/.m2"] -- "COPY --from=build: jar only" --> F["Final stage: 25-jre + jar"]
  F --> I(["payment-service:1.4.0"])
  B -. stays behind .-> X["JDK, sources, ~/.m2"]`}
/>

- BuildKit builds only the stages the target needs.
- Naming stages keeps `COPY --from` working when stages are reordered.
- Base image choice: [image size](card:image-size-optimization); jar layers: [Java in containers](card:java-in-containers).

## Example

```dockerfile
FROM eclipse-temurin:25-jdk AS build
WORKDIR /src
COPY mvnw pom.xml ./
COPY .mvn .mvn
RUN ./mvnw dependency:go-offline
COPY src src
RUN ./mvnw package -DskipTests

FROM eclipse-temurin:25-jre
COPY --from=build /src/target/payment-service-1.4.0.jar /app/app.jar
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

## Interview Qs

### What is a multi-stage build, and why use it?

A Dockerfile with several FROM stages. Early stages compile; the final stage copies only the result. The image ships without build tools, so it is smaller and has fewer packages to patch.

### How do you run tests or debug a single stage?

Build with `--target`, for example `docker build --target build .`. The build stops at that stage, which is useful for a test or debug stage.
