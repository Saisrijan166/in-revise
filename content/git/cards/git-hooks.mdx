## What it is

A hook is a script that Git runs by itself when a certain event happens, such as making a commit or pushing. You put the script in the [.git](card:git-directory) `hooks/` folder (or a folder named by `core.hooksPath`) and Git calls it at the right moment. If the script exits with a non-zero code, Git stops the action. Some hooks run on your machine (client hooks); others run on the remote when it receives a push (server hooks).

## Why it exists

Teams want the same checks to run every time, not only when someone remembers. A formatter should run before each commit; tests should pass before a push; a commit message should follow a format. Without hooks you rely on people doing this by hand, and bad commits slip in. Hooks automate the checks at the exact moment they matter, and server hooks let the remote reject a push that breaks the rules, which no client-side habit can guarantee.

## How it works

| Hook | Side | When it runs | Common use |
|---|---|---|---|
| `pre-commit` | Client | Before the commit is created | Lint and format; abort on failure |
| `commit-msg` | Client | After the message is written | Check the message format |
| `pre-push` | Client | Before a push is sent | Run tests; abort if they fail |
| `pre-receive` | Server | Once per push, before refs update | Accept or reject the whole push |
| `update` | Server | Once per ref being updated | Reject a single ref |

1. The event fires (for example you run `git commit`).
2. Git looks for the matching hook file and runs it if it is present and executable.
3. A zero exit lets the action continue; a non-zero exit aborts it. Client hooks like `pre-commit` can be skipped with `--no-verify`.

## Example

A tiny `pre-commit` hook that blocks a commit with whitespace errors:

```bash
# .git/hooks/pre-commit  (make it executable: chmod +x)
#!/bin/sh
git diff --cached --check || {
  echo "Fix whitespace errors before committing." >&2
  exit 1
}
```

What to notice:

- The file must be named `pre-commit` and have the executable bit, or Git ignores it.
- `git diff --cached --check` fails when staged changes have whitespace errors, so the hook exits non-zero and the commit is aborted.
- This hook is local only. It is not pushed, so a clone will not have it until it is installed there.

## Rules and defaults

| What | Default | Note |
|---|---|---|
| Location | `.git/hooks` | Change with `core.hooksPath` |
| Shipped with a clone | No | Not versioned; a clone gets only sample hooks |
| Runs if | Executable bit set | A non-executable file is ignored |
| Bypass (client) | `--no-verify` | Skips `pre-commit` and `commit-msg` |

- To share hooks, commit them to a tracked folder (for example `.githooks`) and set `git config core.hooksPath .githooks`, or use a tool such as Husky or pre-commit.

## Common mistakes

- **"Hooks are pushed with the repo."** They live in `.git/hooks`, which is not versioned. A clone gets only sample hooks.
- **"A client hook enforces a policy."** It can be bypassed with `--no-verify` or simply missing. For a real rule, use a server hook or a protected branch.
- **"The hook did nothing."** It is often not executable, or has the wrong name. Git only runs an executable file with the exact hook name.

## Interview Qs

### What are Git hooks?

Scripts Git runs automatically on events such as commit and push. Client hooks like `pre-commit`, `commit-msg` and `pre-push` run on your machine; server hooks like `pre-receive` and `update` run on the remote. A non-zero exit aborts the action, so they enforce checks.

### Are hooks shared when someone clones the repo?

No. Hooks live in `.git/hooks`, which is not versioned or pushed, so a clone starts with only sample hooks. Teams share them by committing scripts to a tracked folder and setting `core.hooksPath`, or with a tool like Husky.

### Where would you enforce a rule the whole team must follow?

On the server, with a `pre-receive` or `update` hook, or a protected-branch rule. Client hooks can be bypassed with `--no-verify` or may not be installed, so they cannot guarantee a policy across everyone.
