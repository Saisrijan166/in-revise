## What it is

Git keeps your work in three areas. The [working directory](term:working-directory) is the set of files on disk you are editing. The [staging area](term:staging-area), also called the index, is where you gather the exact changes that will go into the next commit. The local repository is the committed history, stored in the hidden `.git` folder. [HEAD](term:head) is a pointer to your current commit, so Git knows what your next commit builds on.

## Why it exists

You often change several things at once but want each commit to be one clear, self-contained change. Without a middle step, every commit would sweep up every edit in the folder, giving a messy history that is hard to read or undo. The staging area lets you choose exactly which changes go into the next commit, so you can split unrelated edits into separate, meaningful commits and review what you are about to save before you save it.

## How it works

<Steps label="The add then commit flow">
<Step title="Edit in the working directory">
You change files on disk. Git sees them as modified but does nothing yet.
</Step>
<Step title="Stage with git add">
`git add <file>` copies that change into the staging area, the planned next commit. You can stage some files and leave others.
</Step>
<Step title="Commit with git commit">
`git commit` saves the staged changes as a snapshot in the repository and moves HEAD to the new commit. The staging area is now clean.
</Step>
<Step title="Repeat">
Working directory, staging and the last commit now match for the files you committed. Edit again to start over.
</Step>
</Steps>

## Example

Two files changed, but only one belongs in this commit:

```bash
git add Payment.java
git status --short
git commit -m "Validate payment amount"
```

```text output
M  Payment.java
 M config.yaml
[main 4f2a9c1] Validate payment amount
 1 file changed, 6 insertions(+)
```

What to notice:

- `M ` on the left (staged) is `Payment.java`; ` M` on the right (not staged) is `config.yaml`.
- The commit saved only the staged file. `config.yaml` is still a pending change in the working directory, ready for its own commit.

## Common mistakes

- **"git commit saves all my edits."** It saves only staged changes. Run `git add` first, or use `git commit -a` to auto-stage already-tracked files.
- **"Staging and committing are one action."** They are two steps on purpose, so you choose what each commit contains. See [git add](card:staging-and-add) and [git commit](card:git-commit).
- **"HEAD is a file I edit."** HEAD is a pointer Git moves for you; it marks the commit your next commit will build on.

## Interview Qs

### What are the three areas in Git?

The working directory (files you edit on disk), the staging area or index (changes picked for the next commit), and the local repository (committed history in `.git`). `git add` moves changes from the first to the second; `git commit` from the second to the third.

### What is the staging area for?

It lets you choose exactly which changes go into the next commit, so each commit is one clear change. You can stage some files and leave others, and review what is staged with `git status` or `git diff --staged` before committing.

### What is HEAD?

HEAD is a pointer to your current commit, usually through the branch you are on. Your next commit is created as a child of HEAD, and HEAD then moves to that new commit.
