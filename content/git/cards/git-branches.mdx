## What it is

A branch is a named, movable pointer to a single [commit](card:how-git-stores-data). Because a commit already links back to its parents, naming one commit gives you a whole line of history. When you make a new commit on a branch, Git just moves that branch's pointer forward to the new commit. `git branch` with no name lists branches; with a name it creates a new one.

## Why it exists

You often need to try a risky change, like a refund feature, without breaking the code that already works. Without branches you would copy the whole project into another folder and later struggle to merge the two back together. A branch solves this cheaply: it marks a line of work with one small pointer, so you can start a feature, leave main untouched, and bring the work back later. Many people can work in parallel in the same repository.

## How it works

1. `git branch feature` writes a new pointer named `feature` at the current commit. No files are copied.
2. Both `main` and `feature` now point to the same commit, so they share all history so far.
3. You switch to `feature` and commit. Git moves only the `feature` pointer forward; `main` stays where it was.
4. The branches now diverge. Git still stores shared commits once; only the differing commits are new.

## Example

Create a branch, confirm it points at the same commit as main, then see delete refuse an unmerged branch:

```bash
git branch feature-refund
git log --oneline -1 feature-refund
git switch feature-refund && git commit -am "wip refund"
git switch main
git branch -d feature-refund
```

```text output
a1b2c3d add payment service
Switched to branch 'main'
error: the branch 'feature-refund' is not fully merged.
hint: If you are sure you want to delete it, run 'git branch -D feature-refund'.
```

What to notice:

- `git branch` created the pointer instantly and left `main` current; the first `git log` shows it starts at the same commit as main.
- `-d` refused because `feature-refund` has a commit not merged into main, so Git protects you from losing it. `-D` would force the delete.

## Rules and defaults

| What | Rule | Where |
|---|---|---|
| Create | `git branch <name>` points at HEAD and does not switch | git-branch |
| List | `git branch` lists; the current branch has a `*` | git-branch |
| Safe delete | `-d` deletes only a branch merged into upstream or HEAD | git-branch |
| Force delete | `-D` = `--delete --force`, deletes even if unmerged | git-branch |
| Default name | built-in default is `master`; `init.defaultBranch` overrides it | git-init (Git 2.x; changes to main in Git 3.0) |

- To create and switch in one step, use [git switch -c](card:switching-branches), not `git branch`.

## Common mistakes

- **"Creating a branch makes a copy of the files."** It writes one pointer. The working tree changes only when you switch and then commit different things.
- **"-d always deletes the branch."** `-d` refuses an unmerged branch to protect its commits; use `-D` to force it.
- **"git init makes a main branch now."** Git's built-in default is still `master`; only `init.defaultBranch`, `-b`, or a host like GitHub gives you `main`.

## Interview Qs

### What is a branch in Git?

A lightweight, movable pointer to a commit. Creating one copies no files; it just names a commit. As you commit on the branch, Git moves the pointer forward, so the branch always points to the latest commit on that line of work.

### What is the difference between git branch -d and -D?

`-d` is a safe delete: Git removes the branch only if it is fully merged into its upstream or HEAD, so you do not lose commits. `-D` is `--delete --force`; it deletes the branch even if it has unmerged work.

### Is the default branch name main or master?

Git's own built-in default is still `master`; it changes to `main` only in Git 3.0. You get `main` today by setting `init.defaultBranch main`, passing `git init -b main`, or starting the repo on a host like GitHub, which defaults to `main`.
