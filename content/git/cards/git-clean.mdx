## What it is

`git clean` deletes untracked files from your working tree: new files Git is not tracking yet. It leaves tracked files alone, whether staged or committed. With `-d` it also removes untracked directories, and with `-x` it removes ignored files too. Because the files are not in Git, deleting them is permanent.

## Why it exists

A build or a half-finished experiment can leave dozens of stray files that Git keeps reporting as untracked. Deleting them by hand is slow and error-prone. `git clean` sweeps them in one command, so you can get back to a pristine working tree. It only touches untracked files so it never endangers work you have committed.

## How it works

Git refuses to delete anything unless you confirm, so the safe routine is preview, then delete:

```bash
git clean -nd        # dry run: list what would be removed
git clean -fd        # force: actually remove untracked files and dirs
```

- `-n` previews, `-f` deletes (required because `clean.requireForce` defaults to `true`).
- `-d` adds untracked directories; without it, clean skips them.
- `-x` also deletes ignored files; `-X` deletes only ignored files, keeping other untracked ones.

## Example

```bash
git status -s
git clean -nd
```

```text output
?? debug.log
?? scratch/
Would remove debug.log
Would remove scratch/
```

What to notice: `-n` lists exactly what would go without touching anything, and `-d` is why the whole `scratch/` directory is included. Swapping `-n` for `-f` performs the deletion. The committed and staged files never appear, because clean ignores tracked files.

## Common mistakes

- **Running -f without -n first.** There is no recycle bin; untracked files are gone. Preview with `-n` every time.
- **Expecting ignored files to go.** Plain clean keeps them. Add `-x` to also remove ignored build output.
- **Thinking it undoes edits.** Edits to tracked files need [git restore](card:git-restore) or [git reset](card:git-reset); clean only removes untracked files.

## Interview Qs

### What does git clean do, and how is it different from git reset?

`git clean` deletes untracked files from the working tree. `git reset` moves the branch and can change tracked files and staging. Clean only removes files Git is not tracking; reset never touches untracked files.

### How do you safely remove all untracked files and directories?

Run `git clean -nd` first to preview, then `git clean -fd` to delete. `-d` includes untracked directories and `-f` is required to actually remove anything. Deleted files cannot be recovered.

### How do you also delete ignored files like build output?

Add `-x`: `git clean -fdx` removes untracked and ignored files, giving a pristine tree. Use `-X` instead if you want to delete only the ignored files and keep other untracked ones.
