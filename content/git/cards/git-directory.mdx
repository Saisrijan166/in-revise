## What it is

`.git` is a hidden folder at the root of every repository, created by `git init` or `git clone`. It is the repository: everything Git knows lives inside it. The files you edit sit next to it in the [working directory](card:working-staging-repo); `.git` holds the history, the branches, the staging area and the settings. The folders you edit are separate from the `.git` data that tracks them.

## Why it exists

Git keeps all its bookkeeping in one place so the rest of the folder is just your project, clean and portable. Because the whole repository is self-contained in `.git`, cloning is a plain copy and nothing is stored on a central server you depend on. Keeping the [objects](card:git-objects) and refs here also means your working files are never polluted with Git metadata; you can zip the project, and Git's data travels with it in that one folder.

## How it works

| Inside `.git` | Holds |
|---|---|
| `objects/` | Every object: blobs, trees, commits and tags, the full history |
| `refs/` | Pointers: `refs/heads` (branches), `refs/tags`, `refs/remotes` |
| `HEAD` | Which branch or commit you are on now |
| `index` | The staging area: the content for your next commit |
| `config` | This repository's settings (remotes, user overrides) |
| `hooks/` | Scripts Git can run on events like commit and push |

1. When you commit, Git writes new objects into `objects/` and moves the current branch in `refs/heads`.
2. `HEAD` follows your current branch, so Git always knows what the next commit's parent is.
3. `git add` updates the `index`; `git commit` turns the index into a new tree and commit.

## Common mistakes

- **"Deleting .git deletes my code."** It deletes history, branches and staging only. Working files stay, but untracked.
- **"HEAD is the latest commit."** HEAD is where *you* are, usually a branch pointer; that branch's tip is the latest commit on it. See [HEAD and detached HEAD](card:head-and-detached-head).
- **"The staging area is a separate folder."** It is the single `index` file inside `.git`, not a directory of copies.

## Interview Qs

### What is inside the .git directory?

The whole repository: `objects/` (all history as blobs, trees and commits), `refs/` (branch and tag pointers), `HEAD` (your current position), the `index` (staging area), `config` (repo settings) and `hooks/` (event scripts). Your working files live outside it.

### What happens if you delete the .git folder?

Git stops tracking the project. You lose the history, all branches and tags, remotes and the staging area. The current working files stay on disk, untracked. If a remote or another clone exists, you can re-clone and recover; otherwise the history is gone.

### What is the index?

The `index` file inside `.git` is the staging area. It records exactly what the next commit will contain. `git add` writes to it, and `git commit` builds a tree and commit from it. `git status` compares the working tree, the index and HEAD.
