## What it is

`git commit --amend` lets you redo your most recent [commit](card:git-commit). Despite the name, it does not change that commit in place. It creates a new commit from your current staged [snapshot](term:snapshot) plus the old commit's message, and makes your branch point to this new commit instead. The old commit is left behind with its original hash.

## Why it exists

You commit, then spot a typo in the message or realise one file was never staged. Without amend you would add a second tiny "fix message" or "oops, missed a file" commit, cluttering the history. Amend folds the correction into the last commit so the history stays clean, as if you had got it right the first time.

## How it works

1. Stage any extra change you want in the commit (`git add`), or stage nothing to only edit the message.
2. Run `git commit --amend`. Git prepares a new commit: your staged tree, the same parent as the old commit, and the old message as a starting point.
3. The editor opens so you can change the message. Add `--no-edit` to keep the old message unchanged.
4. The branch now points to the new commit. The old commit still exists in the [reflog](card:git-reflog) for a while but is no longer on the branch.

## Example

You committed, then realised a file was missing. Fix it in one amended commit:

```bash
git add forgotten_file.c
git commit --amend --no-edit
git log --oneline -1
```

```text output
9f1c2ab (HEAD -> main) Add parser for payment webhook
```

What to notice:

- The file is now part of the last commit, not a separate one. The message is unchanged because of `--no-edit`.
- The short hash `9f1c2ab` is new: the old commit had a different hash. Anything pushed before this would now be out of sync with the remote.

## Common mistakes

- **Amending a pushed commit.** The hash changes, so the next push is rejected and needs a force push, which rewrites shared history.
- **Thinking `--amend` only edits the message.** It rebuilds the whole commit from what is currently staged. If you forgot to stage your fix, it is not included.

## Interview Qs

### Does git commit --amend change the commit id?

Yes. Amend does not edit the commit in place; it creates a new commit with a new hash that replaces the old tip. The branch moves to the new commit and the old one is orphaned.

### When is it unsafe to amend a commit?

When the commit has already been pushed or shared. Amending rewrites history, so the remote and teammates still have the old commit. Pushing then needs `--force-with-lease` and can disrupt anyone who built on the old commit.

### How do you add a forgotten file to your last commit?

Stage the file with `git add`, then run `git commit --amend --no-edit`. The file is folded into the last commit and the message stays the same. Do this only before pushing.
