## What it is

Switching branches means moving HEAD from one [branch](card:git-branches) to another, so Git updates your working files to match that branch. `git switch` is the modern command for this: it changes branches only. `git checkout` is the older command that switches branches and also restores file contents, so one word did two very different jobs. `git restore` is the newer command for the file job alone.

## Why it exists

`git checkout` was overloaded. The same command moved you between branches and quietly replaced file contents, so a slip like `git checkout name` could overwrite a file instead of switching. Beginners found this confusing and sometimes lost edits. Git 2.23 split it into two clearer commands: `git switch` for branches and [git restore](card:git-restore) for files. Each does one job, with a safer, more obvious set of options, while `git checkout` stays for people used to it.

## How it works

| Command | Job | Example |
|---|---|---|
| `git switch <branch>` | Move to an existing branch | `git switch main` |
| `git switch -c <branch>` | Create a branch at HEAD and switch to it | `git switch -c feature` |
| `git checkout <branch>` | Switch branches (older command) | `git checkout main` |
| `git checkout <file>` | Restore a file (old file mode) | `git checkout -- app.java` |
| `git restore <file>` | Discard working-tree changes to a file | `git restore app.java` |

1. You run `git switch feature`. Git checks your uncommitted changes first.
2. If none of them would be overwritten, Git moves HEAD to `feature` and updates the working tree.
3. If a change would be lost, Git aborts with an error instead of overwriting it. You commit, [stash](card:git-restore), or use `-m` to carry the change across.

## Example

Create and switch in one step, then watch a switch abort because of an uncommitted edit:

```bash
git switch -c feature-refund
echo "edit" >> app.java
git switch main
```

```text output
Switched to a new branch 'feature-refund'
error: Your local changes to the following files would be overwritten by checkout:
	app.java
Please commit your changes or stash them before you switch branches.
Aborting
```

What to notice:

- `git switch -c` created `feature-refund` and moved onto it in one command, the same as `git branch` then `git switch`.
- The second switch aborted: Git will not silently overwrite the uncommitted edit to `app.java`. Commit or stash it first, or use `git switch -m` to merge the change into the target branch.

## Rules and defaults

- **switch = branches, restore = files, checkout = both.** Added in Git 2.23; `git checkout` still works for both jobs.
- **-c creates and switches:** `git switch -c <name>` equals `git branch <name>` then `git switch <name>`, done as one safe step.
- **Protects your work:** a switch aborts if it would overwrite uncommitted changes; use commit, `git stash`, or `git switch -m` to proceed.
- **Detaching:** `git switch --detach <commit>` goes to a [detached HEAD](card:head-and-detached-head); plain `git switch <branch>` stays attached.

## Common mistakes

- **"git checkout only switches branches."** It also restores files, which is exactly why it could overwrite them; prefer `git switch` and `git restore`.
- **"A dirty working tree always blocks a switch."** It blocks only if a changed file differs on the target branch; unrelated changes travel with you.
- **"git switch restores a file to an old version."** That is `git restore`'s job; `git switch` moves between branches.

## Interview Qs

### What is the difference between git switch and git checkout?

`git switch` only changes branches (with `-c` to create one). `git checkout` is the older command that both switches branches and restores files, so it was easy to misuse. Git 2.23 split it: `git switch` for branches, `git restore` for files.

### Can you switch branches with uncommitted changes?

Sometimes. Git allows it if no changed file differs on the target branch. If switching would overwrite an uncommitted change, Git aborts. Commit or `git stash` the work first, or use `git switch -m` to merge the changes into the target branch.

### How do you create a branch and switch to it in one command?

`git switch -c <name>`. It creates the branch at the current commit and moves HEAD onto it in one step, the same as `git branch <name>` followed by `git switch <name>`. The older form is `git checkout -b <name>`.
