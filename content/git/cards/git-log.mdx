## What it is

`git log` lists the commits in your repository, newest first, each with its hash, author, date and message. It is how you read the project's story: who changed what and why. `git log --oneline` compresses each commit to a single line for a quick scan, and `git show` opens one commit in full, including the exact diff it made. All three read [commits](card:git-commit) that already exist locally.

## Why it exists

A week after you write code, you cannot remember what each change was for, and a teammate has no idea at all. The commit messages and history answer that, but only if you can read them. `git log` turns the chain of commits into a readable list, so you can find when a line was added, which commit introduced a bug, or what a release contained. Without it, history would be stored but unreadable.

## How it works

```bash
git log
git log --oneline
git log --oneline --graph
git show 9f2a1c4
```

```text output
9f2a1c4 Add refund endpoint
3b7e018 Validate payment amount
a1c90f2 Initial commit
```

1. `git log` walks from the current commit back through each parent, printing newest first.
2. `--oneline` prints just the abbreviated hash and the first line of each message (the output above).
3. `--graph` adds ASCII lines on the left that show where branches split and merged.
4. `git show <hash>` prints one commit's message and metadata, then the full diff of the lines it changed.

What to notice: `--oneline` is ideal for scanning many commits, while `git show` zooms into one. Both only show commits that exist in your local repository.

## Common mistakes

- **Expecting remote-only commits.** `git log` reads local history. A teammate's new commits appear only after `git fetch` or `git pull`.
- **Confusing git log with git show.** `log` lists many commits; `show` opens one commit with its full diff.
- **Forgetting --oneline for scanning.** The default output is verbose; `--oneline` (often with `--graph`) is far easier to read.

## Interview Qs

### What does git log --oneline show?

One line per commit: the abbreviated commit hash and the first line of the message, newest first. It is the quickest way to scan history. Adding `--graph` also draws how branches split and merged.

### What is the difference between git log and git show?

`git log` lists many commits with their metadata and messages. `git show` focuses on a single commit (HEAD by default, or a given hash) and prints its message plus the full diff of the lines it changed.

### Does git log show commits that are only on the remote?

No. It reads the commits in your local repository. Commits that exist only on the remote show up after you run `git fetch` or `git pull`, which brings them into your local history.
