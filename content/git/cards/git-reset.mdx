## What it is

`git reset` moves your current branch and [HEAD](term:head) to a commit you name, such as `HEAD~1` (one commit back). The three modes decide what happens to your changes: `--soft` leaves them staged, `--mixed` (the default) leaves them unstaged, and `--hard` discards them. Because it drops commits off the branch, it rewrites history.

## Why it exists

A [commit](card:git-commit) you made too early, with the wrong message or the wrong files, should not stay in the history you share. `git reset` lets you move the branch back to a clean point and rebuild from there. Without it you would be stuck adding awkward extra commits to patch mistakes, instead of undoing them before anyone sees them.

## How it works

<Compare id="reset-soft-mixed-hard" />

1. You pick a target commit, usually `HEAD~1`, `HEAD~2`, or a specific hash.
2. Git moves the branch pointer and HEAD to that commit, so the commits after it are no longer on the branch.
3. The mode decides the rest: `--soft` touches nothing else; `--mixed` resets the staging area to match the target; `--hard` resets both the staging area and your tracked working files.

## Example

```bash
git commit -m "half-done work"      # oops, committed too early
git reset --soft HEAD~1             # undo the commit, keep changes staged
git status -s
```

```text output
M  src/App.java
```

What to notice: the `M` is in the left column, so the change is still staged. The branch moved back one commit but nothing was lost. With `--mixed` the `M` would move to the right column (unstaged); with `--hard` the file would not appear at all, because the change would be gone.

## Common mistakes

- **Using --hard to tidy up.** It silently deletes uncommitted work in tracked files. Prefer `--mixed` or `--soft` unless you truly want the changes gone.
- **Resetting pushed commits.** Rewriting shared history breaks everyone else's branch. On pushed commits use [git revert](card:git-revert) instead.
- **Confusing reset with restore.** [git restore](card:git-restore) fixes files and staging without moving the branch; reset moves the branch.

## Interview Qs

### What is the difference between reset --soft, --mixed and --hard?

All three move the branch to an earlier commit. `--soft` keeps the undone changes staged, `--mixed` (the default) keeps them unstaged, and `--hard` discards them so the working tree matches the target commit. Only `--hard` can lose uncommitted work.

### How do you undo the last commit but keep the code staged?

`git reset --soft HEAD~1`. The branch moves back one commit and all the changes stay in the staging area, so you can immediately re-commit them with a corrected message.

### Why is git reset risky on a shared branch?

It rewrites history by dropping commits others may already have. Your push gets rejected, or forcing it leaves teammates with diverged branches. Use [git revert](card:git-revert) to undo pushed commits safely.
