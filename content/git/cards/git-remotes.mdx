## What it is

A remote is a named connection to another copy of your repository, usually one hosted on a server like GitHub or GitLab. The name, such as [origin](term:origin), is a short alias for a URL, stored in your repository's own config. You use the name instead of typing the full URL every time you sync. A repository can have several remotes at once.

## Why it exists

Your commits live only on your machine until you send them somewhere. To share work with a team, you need to point Git at a hosted copy and refer to it over and over. Typing the full URL each time would be slow and error-prone. A remote gives that URL a short, memorable name, so commands like push and [pull](card:fetch-pull-push) stay simple. Without remotes, there would be no agreed place for the team's shared history to live.

## How it works

<Steps>
  <Step title="Clone sets origin">git clone copies a repo and automatically adds one remote named origin, pointing at the URL you cloned from.</Step>
  <Step title="List remotes">git remote -v shows every remote name with its fetch URL and push URL.</Step>
  <Step title="Add more">`git remote add <name> <url>` adds another remote, for example a backup server or a fork's upstream.</Step>
  <Step title="Rename or remove">`git remote rename old new` updates the name; `git remote remove <name>` deletes the remote and its tracking branches.</Step>
</Steps>

1. A remote is only a label plus a URL in `.git/config`; it holds no commits itself.
2. You sync with a remote by name using fetch, pull and push.
3. `origin` is a convention, not a keyword: you may rename it, though most tools expect it.

## Example

A fresh clone already has origin; here we add a second remote and list both:

```bash
git clone https://github.com/acme/pay.git
cd pay
git remote add backup https://git.internal/acme/pay.git
git remote -v
```

```text output
origin	https://github.com/acme/pay.git (fetch)
origin	https://github.com/acme/pay.git (push)
backup	https://git.internal/acme/pay.git (fetch)
backup	https://git.internal/acme/pay.git (push)
```

What to notice:

- Clone created `origin` for us; we only added `backup`.
- Each remote prints two lines because the fetch URL and push URL are listed separately, even when they are the same.
- To push to the backup you now name it: `git push backup main`.

## Rules and defaults

| What | Default | Where |
|---|---|---|
| Remote name from clone | `origin` | git clone (Git 2.x) |
| Remotes in a fresh init | none | git init |

- **Add:** `git remote add <name> <url>`; the name must be unique in the repo.
- **Remove:** `git remote remove <name>` (alias `rm`) also deletes that remote's tracking branches.
- **Rename:** `git remote rename <old> <new>` updates the tracking branches and config too.
- Changing a remote's name or URL only edits your local config; it does nothing to the server.

## Common mistakes

- **"origin is special."** It is only the default name. Any remote can be used the same way; origin just happens to be what clone picks.
- **"git remote add creates a repo on the server."** It only records a URL locally. The hosted repo must already exist for fetch and push to work.

## Interview Qs

### What is a remote in Git?

A remote is a named URL pointing to another copy of the repository, usually hosted on a server. The name is a short alias stored in your local config, so you can fetch, pull and push by name instead of typing the full URL.

### What is origin?

origin is the default name that git clone gives to the remote it copied from. It is a convention, not a keyword: you could rename it, but most commands and hosting tools expect a remote called origin.

### How do you add or view remotes?

git remote -v lists every remote with its fetch and push URLs. `git remote add <name> <url>` adds a new one, git remote rename changes a name, and git remote remove deletes a remote and its tracking branches.
