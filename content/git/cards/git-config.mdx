## What it is

`git config` reads and sets Git's settings. The most important ones are your identity, `user.name` and `user.email`, which Git records in every commit you make. Settings live in three places, called scopes: `--system` (every user on the machine), `--global` (your user account) and `--local` (the current repository). A plain `git config` write goes to the local scope by default.

## Why it exists

Git stamps each commit with an author name and email, so the history shows who did what. If you never set them, Git may guess from the machine's hostname and leave confusing or wrong author info on your commits, which is hard to fix later. Scopes exist because one default is not enough: you want one identity for most work, but a different email for a client's repo, or a machine-wide setting an admin sets once. Scopes let a specific repo override your general default.

## How it works

| Scope | Flag | File | Applies to |
|---|---|---|---|
| System | `--system` | `/etc/gitconfig` | Every user on the machine |
| Global | `--global` | `~/.gitconfig` | Your user, all repos |
| Local | `--local` (default) | `.git/config` | The current repository |

1. Git reads all three files, from least to most specific: system, then global, then local.
2. When the same key is set in more than one, the last one read wins, so **local overrides global overrides system**.
3. `git config --list` prints the merged result; add `--show-scope` or `--show-origin` to see where each value came from.

## Example

Set your identity once for all repos, then override the email in one:

```bash
git config --global user.name "Asha Rao"
git config --global user.email "asha@personal.com"
git config --local user.email "asha@work.com"
git config user.email
```

```text output
asha@work.com
```

What to notice:

- The first two commands write to `~/.gitconfig`, so they apply everywhere.
- Inside this repo, the local email overrides the global one, so commits here use the work address while other repos keep the personal one.

## Rules and defaults

- **Default write scope:** a `git config` write with no scope flag goes to `--local` (this repo).
- **Identity is not optional for commits:** without `user.name` and `user.email`, Git may refuse to commit or record a guessed author.
- **Read everything:** `git config --list` merges all scopes; a value can appear more than once, and the most specific one applies.

## Common mistakes

- **"Global settings can't be changed per project."** A local value overrides the global one for that repo.
- **"--local is needed to set repo settings."** Local is the default scope for writes, so the flag is optional inside a repo.
- **"Setting user.email fixes past commits."** It only affects new commits; old commits keep the author they were made with.

## Interview Qs

### How do you set your name and email in Git?

`git config --global user.name "Your Name"` and `git config --global user.email "you@example.com"`. Global applies to all your repos; drop `--global` (or use `--local`) to set it for just the current repository.

### What are the config scopes and which one wins?

System (all users), global (your user) and local (one repo). Git reads them in that order and the last wins, so local overrides global overrides system. The most specific scope always takes precedence.

### How do you see all your Git settings?

`git config --list` prints the merged settings from all scopes. Add `--show-origin` to see which file each value came from, or `--show-scope` to see its scope.
