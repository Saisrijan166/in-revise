## What it is

`git status` is a read-only command that tells you where every changed file currently sits. It sorts files into three groups: changes already in the [staging area](term:staging-area) for the next commit, changes in your working directory that are not staged yet, and untracked files that Git has never been told to track. It is the command you run most, before and after every `git add` and `git commit`.

## Why it exists

Git keeps your work in three places at once: the working directory you edit, the staging area you are preparing, and the last commit. You cannot see these from the files alone. Without `git status` you would not know which edits are about to be committed and which will be silently left out, so you would commit the wrong set of changes. It is the safe way to look before you commit, because it writes nothing.

## How it works

```bash
git status
git status -s
```

```text output
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	modified:   app.yaml
Changes not staged for commit:
	modified:   app.java
Untracked files:
	notes.txt
```

1. Git compares the staging area with the last commit, and lists those files as "Changes to be committed" (staged).
2. It compares the working directory with the staging area, and lists those as "Changes not staged for commit".
3. It lists files that are in neither as "Untracked files".
4. `git status -s` prints the same thing compactly: two columns per file, the first for the staging area and the second for the working directory, and `??` for untracked.

What to notice: only the staged group (`app.yaml`) goes in the next commit. `app.java` and `notes.txt` are shown so you remember them, but they are left out until you stage them.

## Common mistakes

- **Thinking every listed file will be committed.** Only the "Changes to be committed" group is. Run `git add` to move the others in.
- **Forgetting untracked files.** A brand-new file shows as `??` (or under "Untracked files") and needs one `git add` before it is ever committed.
- **Reading the two short columns backwards.** First column = staged, second = working directory.

## Interview Qs

### What are the three sections of git status output?

Changes to be committed (staged, differ from the last commit), changes not staged for commit (differ from the staging area), and untracked files (new files Git is not tracking). Only the staged section is included in the next commit.

### What does git status -s show?

A compact view with two status columns per file: the first is the staging area, the second is the working directory. `M ` means staged, ` M` means modified but not staged, and `??` marks an untracked file.

### Does git status change anything?

No. It only reads and reports the state of your working directory, staging area and last commit. It is safe to run as often as you like, which is why it is the command you run before every add and commit.
