## What it is

The reflog is a local log of every position [HEAD](term:head) and your branches have held: each commit, [reset](card:git-reset), rebase and branch switch. Even when a command like `git reset --hard` makes commits disappear from the branch, the reflog still remembers their hashes, so you can find them and move the branch back. It is the safety net for "I lost my work".

## Why it exists

Commands that move the branch, like [git reset](card:git-reset) and rebase, can leave commits with nothing pointing at them. They are not deleted immediately, but you cannot see them in `git log` and you do not know their hashes. The reflog records where you were before each move, so there is always a trail back to a good state after a mistake.

## How it works

```bash
git reflog
git reset --hard HEAD@{1}
```

```text output
7d3af21 HEAD@{0}: reset: moving to HEAD~3
a9c01e4 HEAD@{1}: commit: add refund endpoint
```

What to notice: `HEAD@{1}` is where HEAD was one move ago, just before the hard reset, holding the commit you thought you lost. Resetting to it moves the branch back to `a9c01e4` and the work returns. You can also save it without moving the branch: `git switch -c recovered a9c01e4`.

## Rules and defaults

| What | Default | Where |
|---|---|---|
| Reachable entries kept for | 90 days | gc.reflogExpire |
| Unreachable entries kept for | 30 days | gc.reflogExpireUnreachable |
| Shared with clones/remotes | No | reflog is local only |

- After the expiry window, `git gc` can prune the entry and the lost commit may then be collected, so recover sooner rather than later.
- `git reflog` with no arguments shows HEAD's log; name a branch, like `git reflog main`, to see that branch's moves.

## Common mistakes

- **Assuming --hard deleted the commit.** It only moved the branch. The reflog still holds the hash until it expires.
- **Expecting the reflog on a fresh clone.** It is local and never pushed, so a clone starts with its own empty reflog.
- **Waiting too long.** Unreachable entries can be pruned after 30 days; recover promptly.

## Interview Qs

### How do you recover a commit lost to git reset --hard?

Run `git reflog` to find the entry from just before the reset (its hash or `HEAD@{1}`), then `git reset --hard HEAD@{1}` to move the branch back, or `git switch -c <name> <hash>` to save it on a new branch. The commit was never deleted.

### What is the reflog and how is it different from git log?

`git log` shows the commit history reachable from a branch. The reflog is a local record of every move of HEAD and branches, including resets and rebases, so it can point to commits that are no longer in any branch's history.

### How long do reflog entries last?

By default reachable entries are kept for 90 days and unreachable ones for 30 days (`gc.reflogExpire` and `gc.reflogExpireUnreachable`), after which `git gc` can prune them. Recover lost work before then.
