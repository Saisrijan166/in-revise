## What it is

Git is a [distributed version control](term:distributed-version-control) system. A version control system records the history of your files, so you can see what changed, who changed it, and go back to any earlier version. "Distributed" means every clone of the project carries the full history, not just the newest files. Git saves your work as [snapshots](term:snapshot): each save stores what every file looked like at that moment.

## Why it exists

Without version control you keep copies like `app_final`, `app_final2`, `app_really_final`, email zipped folders as backups, and still cannot tell what changed or undo one bad edit safely. Older tools kept the history on one central server, so you needed a network for almost everything and lost the history if that server died. Git puts the whole history on every machine, so you can work, commit and read history offline, and no single server is the only copy.

## How it works

<Steps label="Working with Git, with and without a remote">
<Step title="Work locally">
You edit files, then commit. Each commit is a snapshot saved in your own clone. This needs no network.
</Step>
<Step title="Clone carries everything">
When someone clones the project, Git copies the full history, so their machine has every past version too.
</Step>
<Step title="Sync when you want">
To share, you push your commits to a remote (often on GitHub); to get others' work, you pull. The remote is optional.
</Step>
</Steps>

## Analogy

<Analogy title="A save button with unlimited, named undo" limit="Unlike a game save, Git also merges work from many people and keeps who-changed-what for every line.">
A video game lets you save at any point and reload an old save. Git is that save button for a whole project: each commit is a named save of all your files, and you can jump back to any one. The difference is that everyone on the team has the full set of saves on their own machine.
</Analogy>

## Example

A new project goes under Git in three commands, with no account or internet needed:

```bash
git init
git add .
git commit -m "Initial payment service"
```

```text output
Initialized empty Git repository in /home/dev/payment/.git/
[main (root-commit) 9a1c2e4] Initial payment service
 3 files changed, 112 insertions(+)
```

What to notice:

- `git init` made the repository locally; nothing was sent anywhere.
- The commit is saved on your disk. Sharing it on GitHub is a separate, later step with `git push`.

## Not to be confused with

Git is the version control tool that runs on your computer and works with no internet. GitHub (like GitLab and Bitbucket) is a website that hosts Git repositories for sharing and review. Rule: you use Git; you push to GitHub.

## Common mistakes

- **"You need GitHub to use Git."** You do not. Git is complete on its own; remotes are optional.
- **"Git stores the differences between versions."** Git stores full snapshots and reuses unchanged files. See [how Git stores data](card:how-git-stores-data).

## Interview Qs

### What is Git?

Git is a distributed version control system that tracks the full history of a set of files. Each commit is a snapshot, and every clone holds the complete history, so most actions work offline.

### What is the difference between Git and GitHub?

Git is the version control tool on your computer. GitHub is a website that hosts Git repositories and adds collaboration features like pull requests and issues. GitLab and Bitbucket are alternatives. You can use Git with none of them.

### Why is a distributed system better than a centralized one?

Every clone has the whole history, so you commit, branch and view history offline and fast. There is no single server whose loss destroys the history, and no network round trip for everyday actions.
