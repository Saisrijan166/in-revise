## What it is

`git rm` and `git mv` delete and rename tracked files while staging the change for you. `git rm <file>` removes the file from disk and stages the removal. `git rm --cached <file>` is different: it stops Git tracking the file but leaves it on disk. `git mv <old> <new>` renames or moves a tracked file and stages that in one step. All three save you the extra `git add`.

## Why it exists

You could delete or rename a file with your normal tools and then `git add` the change, but that is two steps and easy to half-finish, leaving Git confused about what happened. `git rm` and `git mv` do the file operation and the staging together, so the next commit records a clean delete or rename. And `git rm --cached` solves a specific need: untracking a file you should never have committed, such as a secret, without deleting your copy.

## How it works

```bash
git rm old.txt            # delete from disk, stage the removal
git rm --cached .env      # stop tracking, keep the file on disk
git mv Util.java Helper.java   # rename, stage both sides
```

```text output
rm 'old.txt'
rm '.env'
```

1. `git rm` deletes the file from the working directory and stages the deletion, so the next commit no longer contains it.
2. `git rm --cached` removes the file only from Git's tracking and stages that; the file stays on disk and would show as untracked afterwards.
3. `git mv old new` is a shortcut for renaming the file and staging the removal of the old name and the add of the new one.

What to notice: the only difference between the first two commands is `--cached`, but one deletes your file and the other keeps it.

## Common mistakes

- **Using git rm when you meant git rm --cached.** Plain `git rm` deletes the file from disk. To merely untrack it, add `--cached`.
- **Thinking git mv is needed for a rename.** You can rename with any tool and then stage both names; Git detects the rename. `git mv` just does it in one step.
- **Forgetting -r for a folder.** `git rm` needs `-r` to remove a directory given by name.

## Interview Qs

### What is the difference between git rm and git rm --cached?

`git rm` deletes the file from disk and stages the removal. `git rm --cached` only stops Git tracking the file and stages that, leaving the file on disk. Use `--cached` to untrack a file, such as a secret, without losing it.

### What does git mv do?

It renames or moves a tracked file and stages the change in one command. It is equivalent to renaming the file yourself and then staging the old and new paths, which Git records as a rename.

### Do you have to use git rm and git mv?

No. You can delete or rename files with normal tools and then `git add` the result; Git will record the removal or detect the rename. `git rm` and `git mv` just combine the file operation and the staging into a single step.
