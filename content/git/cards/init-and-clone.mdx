## What it is

`git init` creates a new, empty Git repository in the current folder by making a hidden `.git` directory. Nothing is tracked yet; you start the history with your first [add and commit](card:working-staging-repo). `git clone` does the opposite starting point: it copies an existing repository from a URL, bringing down its full history, then checks out the latest version so you can work. These are the two ways to begin, depending on whether the project already exists.

## Why it exists

Projects start in two ways. Sometimes you have a new idea and an empty folder, and you need a fresh repository to begin tracking it. Other times the project already exists on a server, and you need your own working copy with the whole history so you can build on past work and share changes. `git init` covers the first case, `git clone` the second. Without clone you would have to init an empty repo and wire up the remote and history by hand.

## How it works

| | `git init` | `git clone <url>` |
|---|---|---|
| Starts from | An empty or existing local folder | An existing remote repository |
| History | None; you create the first commit | Full history downloaded |
| Remote | None set up | `origin` added automatically |
| Working files | Whatever is already in the folder | Latest version checked out |
| Use for | A brand-new project | Joining an existing project |

1. `git init` writes the `.git` folder; the repository exists but has no commits.
2. `git clone` creates a folder, downloads the repository's objects (every version of every file), records the source as the remote `origin`, and checks out the default branch.

## Example

Starting a new project versus joining an existing one:

```bash
git init payment-service
git clone https://github.com/acme/payment-service.git
```

```text output
Initialized empty Git repository in /home/dev/payment-service/.git/
Cloning into 'payment-service'...
remote: Enumerating objects: 842, done.
Receiving objects: 100% (842/842), 1.2 MiB, done.
```

What to notice:

- `git init` made an empty repository with no commits; you would `git add` and `git commit` to begin.
- `git clone` downloaded 842 objects, the whole history, not just the current files, and set up `origin` pointing at the URL.

## Common mistakes

- **"Clone only downloads the latest code."** It copies the full history and every branch into `.git`, then checks out the latest commit.
- **"Use git init to get a teammate's project."** Use `git clone`; `init` makes an empty repo with no history or remote.
- **"You must add the remote manually after cloning."** Clone sets up `origin` for you.

## Interview Qs

### What is the difference between git init and git clone?

`git init` creates a new, empty repository in the current folder, with no history. `git clone` copies an existing remote repository, downloading its full history and every version of every file, sets up a remote named `origin`, and checks out the latest version.

### Does git clone download the whole history or just the latest files?

The whole history by default: every commit and every version of every file go into the local `.git` folder, and the latest commit is checked out into your working directory. A `--depth` shallow clone can limit how much history comes down.

### What remote does git clone set up?

It records the source URL as a remote named `origin` automatically, so you can `git fetch`, `git pull` and `git push` to it without extra setup. You can change the name with `-o` / `--origin`.
