## What it is

`git revert` undoes a commit by recording a brand-new commit whose changes are the exact opposite of the one you chose. The original commit stays in history; the revert sits on top and cancels its effect. Because it only adds to history and never rewrites it, it is safe to use on a branch other people share.

## Why it exists

Once a commit is pushed, others have it. [git reset](card:git-reset) would rewrite that shared history and break their branches. You still need a way to undo the change, so Git offers one that only moves forward: `git revert` adds a new commit, so the history everyone already pulled stays valid and your fix is just the next commit.

1. You name the commit to undo, for example `git revert <hash>`.
2. Git works out the reverse of that commit's changes and applies them to your working tree.
3. It commits the result as a new commit, with a message that records which commit was reverted.
4. For a merge commit you add `-m <parent-number>` so Git knows which parent is the mainline to revert against.

## Example

```bash
git revert HEAD --no-edit
git log --oneline -2
```

```text output
b91f3a2 Revert "Add broken discount rule"
4c0d7e1 Add broken discount rule
```

What to notice: the broken commit `4c0d7e1` is still there; a new commit `b91f3a2` sits on top and cancels it. No history was rewritten, so this can be pushed to a shared branch straight away. To undo the undo, you would revert `b91f3a2`.

## Common mistakes

- **Expecting the bad commit to vanish.** Revert adds a commit; it never removes one. If you must erase an unpushed commit, that is [git reset](card:git-reset).
- **Reverting a merge without -m.** Git refuses because it cannot guess the mainline parent. Add `-m 1` to keep the branch you merged into.
- **Reverting with a dirty tree.** Revert needs a clean working tree (no uncommitted changes); commit or stash first.

## Interview Qs

### What is the difference between git reset and git revert?

`reset` moves the branch to an earlier commit and rewrites history, so it suits local, unpushed commits. `revert` adds a new commit that cancels an old one and keeps history, so it is the safe choice for commits already pushed to a shared branch.

### How do you undo a commit that is already pushed?

Use `git revert <commit>`. It creates a new commit that reverses the change while keeping all history, so you can push it without disturbing anyone who already pulled the branch.

### How do you revert a merge commit?

A merge has two parents, so Git cannot tell which side to keep. Add `-m <parent-number>`, usually `git revert -m 1 <merge>`, to revert against the first parent (the branch you merged into).
