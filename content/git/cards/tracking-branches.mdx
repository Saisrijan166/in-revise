## What it is

A remote-tracking branch, written like origin/main, is a local pointer that shows where the remote's branch was the last time you fetched. It is read-only: you do not commit on it. An upstream (or tracking) link connects one of your local branches to a remote branch, so Git knows where plain [push and pull](card:fetch-pull-push) should go without you naming the remote and branch.

## Why it exists

Git needs to tell you how your work compares with the team's: are you ahead, behind, or in sync? A remote-tracking branch gives a fixed reference to compare against, updated only when you fetch. An upstream saves you from typing `git push origin main` every time. Without these, every push and pull would need the full remote and branch, and "am I up to date?" would be hard to answer.

## How it works

| Branch kind | Example | Updated by | You commit on it? |
|---|---|---|---|
| Local branch | `main` | your commits | Yes |
| Remote-tracking | `origin/main` | git fetch / pull | No |
| Upstream link | `main → origin/main` | push -u, set once | n/a |

1. `git fetch` moves origin/* to match the remote; your local branches do not move.
2. Set the upstream once with `git push -u origin <branch>`; after that, plain `git push` and `git pull` use it.
3. `git branch -vv` lists each local branch with its upstream and whether it is ahead or behind.

## Example

Push a new branch, set its upstream, then check the links:

```bash
git switch -c feature-pay
git push -u origin feature-pay
git branch -vv
```

```text output
Branch 'feature-pay' set up to track 'origin/feature-pay'.
* feature-pay 3a9f0c1 [origin/feature-pay] add payment endpoint
  main        9f8e7d6 [origin/main] release 1.4
```

What to notice:

- `-u` set the upstream, so later `git push` and `git pull` on feature-pay need no arguments.
- `branch -vv` shows each branch's upstream in brackets; "ahead"/"behind" would appear there after you commit or fetch.
- `git branch -r` would list origin/feature-pay and origin/main; `-a` lists local and remote together.

## Rules and defaults

- **origin/main is a cache:** it moves only on fetch or pull, not when the server changes.
- **-u sets upstream once:** run it per branch; afterwards push and pull need no arguments on that branch.
- **Ahead/behind counts** are measured against the remote-tracking branch as of your last fetch, so fetch first for a true picture.
- `git branch -r` shows remote-tracking branches, `-a` shows all, `-vv` adds upstream and ahead/behind.

## Common mistakes

- **"origin/main is the live server."** It is a local snapshot from your last fetch; it can be stale.
- **"Every push needs the remote and branch named."** Only until you set an upstream with push -u; after that, push and pull run bare.

## Interview Qs

### What is a remote-tracking branch?

A read-only local pointer, such as origin/main, that records where the remote branch was at your last fetch. You compare your work against it and never commit on it directly; it moves only when you fetch or pull.

### What does git push -u do?

It pushes the branch and sets its upstream (tracking) link to the remote branch. After that, plain git push and git pull on that branch work with no arguments, because Git knows which remote branch to use.

### How do you see which remote branch your branch tracks?

Run git branch -vv. It lists each local branch with its upstream in brackets, like [origin/main], and whether it is ahead or behind. git branch -r lists remote-tracking branches and -a lists all branches.
