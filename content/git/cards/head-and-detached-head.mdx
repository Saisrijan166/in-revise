## What it is

HEAD is a special pointer that marks where you are now. Normally HEAD points to a [branch](card:git-branches), and that branch points to a commit, so HEAD finds the current commit through the branch. A detached HEAD is when HEAD skips the branch and points directly at a commit. You are then "on no branch": you can look around and commit, but those commits are not attached to any branch name.

## Why it exists

HEAD lets Git know which branch a new commit should move forward, and which files to put in your working tree. Sometimes you want to visit an old commit or a tag to check out how the code looked, without being on a branch. Git allows that by detaching HEAD. The risk is that work done there has no branch to hold it: once you switch away, nothing points to those commits, and Git's cleanup can remove them. Knowing this lets you save the work in time.

1. Normally HEAD names your branch. You commit, and Git moves both the branch and HEAD forward together.
2. You check out a commit id or a tag. HEAD now points straight at that commit, with no branch in between: a detached HEAD.
3. You commit. The new commit's only reference is HEAD, not any branch.
4. You switch to another branch. HEAD moves there, so nothing points to the commits you just made.
5. Those commits stay recoverable for a while via [git reflog](card:git-reflog), then routine garbage collection deletes them.

## Example

Detach at the previous commit, make a commit, switch away, and see Git warn that it is unreachable:

```bash
git switch --detach HEAD~1
git commit -am "experiment"
git switch main
```

```text output
HEAD is now at 9fc9555 add refund validation
[detached HEAD 4d1a0b2] experiment
Warning: you are leaving 1 commit behind, not connected to any of your branches:
  4d1a0b2 experiment
If you want to keep it, create a branch: git switch -c <new-branch-name> 4d1a0b2
```

What to notice:

- The prompt shows `detached HEAD` and the commit lands with no branch attached.
- Git itself warns you are "leaving 1 commit behind" and tells you to run `git switch -c` to keep it. Ignore it and the commit becomes eligible for garbage collection.

## Rules and defaults

- **How you detach:** checking out a commit id or a tag, or `git switch --detach <commit>`; `git checkout <branch>` stays attached.
- **Why it is useful:** inspecting or testing an old state, or a throwaway experiment you are happy to discard.
- **Keep the work:** `git switch -c <name>` (or `git checkout -b <name>`) makes a branch at the current commit and reattaches HEAD. `git branch <name>` saves it but leaves HEAD detached.
- **Recover after leaving:** `git reflog` lists recent HEAD positions so you can find the lost commit id and branch from it.

## Common mistakes

- **"My detached-HEAD commits are on the branch I started from."** They are on no branch; only HEAD referenced them, and HEAD has moved.
- **"They are gone forever the moment I switch."** Not immediately: [git reflog](card:git-reflog) can recover them until garbage collection runs.
- **"git branch saves my place, so I can leave."** `git branch` leaves HEAD detached; use `git switch -c` to also move onto the new branch.

## Interview Qs

### What is HEAD in Git?

A pointer to where you currently are. Normally HEAD points to your current branch, and that branch points to the current commit, so HEAD reaches the commit through the branch. New commits move the branch, and HEAD with it.

### What is a detached HEAD and why is it risky?

HEAD points directly at a commit instead of a branch. New commits made there belong to no branch, so once you switch away nothing references them and Git's garbage collection can delete them. Save them with `git switch -c` or recover them with `git reflog`.

### How do you end up in a detached HEAD, and how do you keep work done there?

You detach by checking out a commit id or a tag, or with `git switch --detach`. To keep commits made there, run `git switch -c <name>` to create a branch at the current commit and reattach HEAD before switching away.
