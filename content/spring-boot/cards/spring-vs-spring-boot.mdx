## Why it exists

With plain Spring you choose compatible library versions, declare the infrastructure beans yourself and usually deploy a war to a separate server. Spring Boot does that setup for you, with defaults you can change.

## How it works

<Compare id="spring-framework-vs-spring-boot" />

- [Starters](card:starters) pick the libraries, [auto-configuration](card:auto-configuration) creates the beans, and the [embedded server](card:embedded-server) runs inside the jar.
- Your own beans and properties can replace any part of Boot's setup.

## Example

The whole web app: one class, one controller, no XML.

```java
@SpringBootApplication
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}

@RestController
class HelloController {
    @GetMapping("/hello")
    String hello() { return "Hello"; }
}
```

With `spring-boot-starter-webmvc` in the build, this starts Tomcat on port 8080 and serves `/hello`.

## Interview Qs

### What is the difference between Spring and Spring Boot?

Spring Framework is the core: dependency injection, MVC, data access and transactions, which you configure. Spring Boot builds on it and adds starters, auto-configuration, an embedded server and production features, so an app runs with almost no setup.

### What are the main features of Spring Boot?

Starters for dependency sets, auto-configuration from the classpath, an embedded web server for `java -jar`, externalized configuration, and Actuator for health and metrics. It generates no code and needs no XML.

### Can you use Spring without Spring Boot?

Yes. Boot is optional: you can configure Spring Framework yourself with `@Configuration` classes and deploy a war to a servlet container. Boot only saves you that setup; the framework underneath is the same.
