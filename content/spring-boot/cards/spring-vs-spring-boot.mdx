## What it is

Spring Framework is a Java framework whose core is a container: an object that creates your application's objects, called beans, and connects them. It also has modules for web apps (Spring MVC), database access and transactions. Spring Boot is built on top of Spring Framework. It does not replace Spring; it sets Spring up with sensible defaults and runs the app from a plain `main` method.

This topic teaches the Spring part first: the container, beans and how they connect. The Boot Basics topic then shows what Boot adds.

## Why it exists

With plain Spring, every project started with the same setup: choosing library versions that work together, writing configuration for a database connection pool and a JSON converter, and deploying the app as a war file (a packaged web app) to a Tomcat server installed separately. That took time, and it broke when one version did not match another. Spring Boot does this setup for you with defaults that are tested together, so you change only what your app really needs.

## How it works

| Setup job | Plain Spring | Spring Boot |
| --- | --- | --- |
| Pick libraries and versions | You choose each version | A [starter](card:starters) brings a tested set |
| Create common objects (database pool, JSON converter) | You write the configuration | [Auto-configuration](card:auto-configuration) creates them |
| Run a web server | Install Tomcat, deploy a war | An [embedded server](card:embedded-server) starts inside the jar |
| Settings per environment | Your own solution | [Externalized configuration](card:externalized-configuration) |
| Health checks and metrics | Your own code | [Actuator](card:actuator) endpoints |

When you start a Spring Boot app:

1. You run the `main` method, which calls `SpringApplication.run`.
2. Boot creates the Spring container, the object that will hold your objects. The next concept, [IoC and the Spring Container](card:ioc-container), explains it.
3. The container registers the classes you wrote, then auto-configuration adds the common objects you did not write.
4. For a web app, Boot starts the embedded Tomcat on port 8080, and the app serves requests.

So Boot does not change what Spring does; it changes who does the setup.

## Example

The smallest payment service: one main class and one web endpoint.

```java
@SpringBootApplication
public class PaymentApplication {
    public static void main(String[] args) {
        SpringApplication.run(PaymentApplication.class, args);
    }
}

@RestController
class PaymentController {
    @GetMapping("/payments/ping")
    String ping() { return "Payment service is running"; }
}
```

What to notice:

- `@SpringBootApplication` and `SpringApplication` are the Boot parts. They switch on scanning and auto-configuration, then start everything; you will see the details in [@SpringBootApplication](card:spring-boot-application).
- `@RestController` and `@GetMapping` are Spring MVC annotations, not Boot ones. Boot only set Spring MVC up.
- With `spring-boot-starter-webmvc` on the classpath, `java -jar` starts Tomcat, and `GET http://localhost:8080/payments/ping` returns the text. No XML, no war, no installed server.

## Rules and defaults

- **Versions (Spring Boot 4.1):** needs Java 17 or later and Spring Framework 7.0.x. The supported embedded servers are Tomcat 11.0 and Jetty 12.1.
- **Port and web starter:** [Embedded Server](card:embedded-server) shows how to change port 8080, and [Starters](card:starters) explains the 4.0 rename of the web starter to `spring-boot-starter-webmvc`.
- **Your settings win:** a bean or a property you define replaces Boot's default.
- **DevTools:** the optional [DevTools](card:devtools) module restarts the app when your classes change, and it switches itself off in a packaged jar.

## Not to be confused with

[Spring MVC](card:spring-mvc) is one module of Spring Framework: the web framework that sends each HTTP request to a controller method. Spring Boot is not a web framework; it sets up Spring MVC, and the rest of Spring, for you. Rule: Spring MVC handles web requests; Spring Boot sets up and runs the whole app.

## Common mistakes

- **"Code in a Boot app is Boot code."** Most annotations you write every day, such as `@Service`, `@Autowired` and `@Transactional`, come from Spring Framework. Boot adds only a few of its own, such as `@SpringBootApplication` and `@ConfigurationProperties`.

## Interview Qs

### If Spring already exists, why was Spring Boot created?

Plain Spring needed a lot of repeated setup: matching library versions, writing infrastructure beans and deploying to a separate server. Boot adds starters, auto-configuration, an embedded server, external configuration and Actuator, so the same Spring runs with almost no setup while every default stays changeable.

### If Spring MVC handles web apps, why do we need Spring Boot?

They work at different levels. Spring MVC is the web framework that maps requests to controllers. Boot sets up the whole application around it, including Spring MVC itself, JSON conversion and an embedded Tomcat, and starts it with `java -jar`.

### Can you use Spring without Spring Boot?

Yes. You write the configuration classes yourself, choose the library versions and deploy a war to a servlet container. Boot is optional; the framework underneath is the same.
