## Why it exists

Plain Spring left you to align library versions, declare infrastructure beans and deploy a war to a separate server. Spring Boot does that setup with defaults you can change.

## How it works

<Compare id="spring-framework-vs-mvc-vs-boot" />

- [Starters](card:starters) bring the libraries, [auto-configuration](card:auto-configuration) creates the beans, the [embedded server](card:embedded-server) runs inside the jar.
- [DevTools](card:devtools) restarts the app when classes change; it switches itself off in a packaged jar.

## Example

```java
@SpringBootApplication
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}

@RestController
class HelloController {
    @GetMapping("/hello")
    String hello() { return "Hello"; }
}
```

With `spring-boot-starter-webmvc` this starts Tomcat on port 8080. No XML, no war.

## Interview Qs

### If Spring already exists, why was Spring Boot created?

Spring needed a lot of manual setup: versions, infrastructure beans, a server. Boot adds starters, auto-configuration, an embedded server, external configuration and Actuator, so the same Spring runs with little setup.

### If Spring MVC handles web apps, why do we need Spring Boot?

They work at different levels. Spring MVC is the web framework. Boot sets up the whole app around it, including Spring MVC itself and an embedded Tomcat.

### Can you use Spring without Spring Boot?

Yes. You write the `@Configuration` classes yourself and deploy a war to a servlet container. Boot is optional; the framework underneath is the same.
