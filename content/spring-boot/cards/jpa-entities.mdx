## Why it exists

Java code works with objects; a relational database stores rows linked by foreign keys. JPA maps classes to tables and object links to foreign keys, so you load and save objects instead of writing SQL by hand.

## How it works

<Mermaid
  alt="Entity states. New: persist() makes it Managed. Managed: remove() makes it Removed, and its row is deleted at flush or commit. When the transaction ends, or on detach() or clear(), a Managed entity becomes Detached. merge() copies a Detached entity back onto a Managed one."
  chart={`flowchart LR
  N([New]) -- "persist()" --> M([Managed])
  M -- "remove()" --> R([Removed])
  R -- "flush or commit" --> X[(Row deleted)]
  M -- "transaction ends, detach(), clear()" --> D([Detached])
  D -- "merge()" --> M`}
/>

- The [persistence context](card:persistence-context) holds one managed instance per id. [Dirty checking](card:dirty-checking) finds changed fields and writes them at flush.
- In a one-to-many pair, the `@ManyToOne` side is the [owning side](card:owning-side); the `@OneToMany` side sets `mappedBy`.
- With `GenerationType.AUTO`, the default, Hibernate uses a sequence if the database has them, else a table.

## Example

```java
@Entity
public class Author {
    @Id @GeneratedValue(strategy = GenerationType.SEQUENCE)
    private Long id;

    @OneToMany(mappedBy = "author", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<Book> books = new ArrayList<>();

    public void addBook(Book book) {      // keep both sides in sync
        books.add(book);
        book.setAuthor(this);             // the owning side writes author_id
    }
}
```

The child holds the foreign key:

```java
@Entity
public class Book {
    @Id @GeneratedValue(strategy = GenerationType.SEQUENCE)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY)    // owning side; EAGER if left out
    @JoinColumn(name = "author_id")
    private Author author;
}
```

## Interview Qs

### What are the states of an entity?

New (transient): not saved yet. Managed: in a persistence context; changes are saved at flush. Detached: has an id but is no longer tracked, for example after the transaction ends. Removed: marked for deletion at flush or commit. merge() copies a detached entity onto a managed one.

### What is the owning side, and what does mappedBy do?

The owning side's field decides what is written to the foreign key. In a one-to-many pair it is the @ManyToOne side. The @OneToMany side sets mappedBy to the owner's field name; changes made only on that side are not written.

### Can an entity be final, or a record?

No. Jakarta Persistence requires a non-final class with non-final methods and persistent fields, and a public or protected no-arg constructor. Enums, records and interfaces cannot be entities. Records work well as DTO projections instead.

### What do CascadeType.ALL and orphanRemoval do?

Persisting, merging or deleting the parent does the same to its children, and a child removed from the collection is deleted at flush. Use them for parts owned by one parent, such as order lines; the spec says REMOVE belongs only on one-to-one or one-to-many.
