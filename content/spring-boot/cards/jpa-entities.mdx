## What it is

A JPA entity is a Java class whose objects are stored as rows in a database table, such as `Payment` stored in the `payment` table. You mark the class with `@Entity` and its primary key field with `@Id`. Relationship annotations, such as `@ManyToOne`, describe how entities point to each other. In the database that link is a foreign key: a column, such as `payment.customer_id`, that holds the id of a row in another table.

## Why it exists

Java objects link through references: `payment.getCustomer()`. Tables link through foreign key columns. Without a mapping you would write the join yourself, copy the columns into two objects, and on save pull the customer's id out and put it in the right column. Entity annotations state once which field is which column and which reference is which foreign key, so Hibernate writes the joins and fills the foreign key for you.

## How it works

| Annotation | Means | Default fetch (JPA 3.2) |
| --- | --- | --- |
| `@ManyToOne` | Many payments point to one customer; this field holds the foreign key | EAGER |
| `@OneToMany` | The customer's list of payments | LAZY |
| `@OneToOne` | One row is linked to exactly one row | EAGER |
| `@ManyToMany` | Rows on both sides are linked through a join table | LAZY |

1. At startup, Hibernate reads every `@Entity` class and maps the class to a table and each field to a column.
2. For each relationship it finds the owning side, the field that becomes the foreign key column. In a two-way one-to-many link, JPA requires this to be the `@ManyToOne` field, here `Payment.customer`.
3. The other side, `Customer.payments`, says `mappedBy = "customer"`. This marks it as a mirror of the owner's field, so Hibernate writes nothing for it.
4. When Hibernate writes a payment, it fills `customer_id` from `Payment.customer`. A change made only to the list never reaches the database.

So there is one foreign key in the database, and only one side of the Java pair controls it.

## Example

A customer has many payments. The payment row holds the link:

```java
@Entity
public class Customer {
    @Id @GeneratedValue private Long id;
    @OneToMany(mappedBy = "customer", cascade = CascadeType.PERSIST)
    private List<Payment> payments = new ArrayList<>();
    public void addPayment(Payment p) { payments.add(p); p.setCustomer(this); }
}
@Entity
public class Payment {
    @Id @GeneratedValue private Long id;
    private BigDecimal amount;  private String status;
    @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "customer_id")
    private Customer customer;                     // owning side: holds the foreign key
    void setCustomer(Customer c) { customer = c; }
}
```

What to notice:

- `mappedBy = "customer"` names the field in `Payment`. Without it, Hibernate would treat the list as a second, separate relationship and expect a join table.
- `addPayment` sets both sides. If it only called `payments.add(p)`, the objects would look linked in memory, but `customer_id` would stay empty.
- `cascade = CascadeType.PERSIST` means saving a new customer also saves the new payments in its list.
- `fetch = FetchType.LAZY` overrides the EAGER default of `@ManyToOne`. You will see why in [lazy loading](card:lazy-loading-n-plus-one).

## Rules and defaults

- **Entity class (JPA 3.2):** it needs `@Entity`, an `@Id`, and a public or protected constructor with no parameters. It must be a top-level or static nested class and must not be final. A record, enum or interface cannot be an entity.
- **Id generation:** `@GeneratedValue` lets the database or Hibernate create the id. Its default strategy is `AUTO`, where the provider picks one for your database.
- **Cascade types:** `CascadeType.ALL` means PERSIST, MERGE, REMOVE, REFRESH and DETACH together.
- **orphanRemoval:** `false` by default. With `true`, a child taken out of the parent's list is deleted.

## Not to be confused with

- **Owning side and parent:** the parent in business terms (`Customer`) is not the owning side. The owner is the entity whose table holds the foreign key column (`Payment`). Rule: owning side = the table with the foreign key.
- **Fetch type and ownership:** LAZY or EAGER says *when* an association is loaded. It has nothing to do with which side writes the foreign key.

## Interview Qs

### What is the owning side, and what does mappedBy do?

The owning side is the field JPA reads to write the foreign key. In a bidirectional one-to-many, the spec requires it to be the @ManyToOne side. The other side sets mappedBy to the owner's field name. Changes made only on the mappedBy side are not saved.

### CascadeType.REMOVE or orphanRemoval?

CascadeType.REMOVE deletes the children when the parent itself is deleted. orphanRemoval = true also deletes a child that is only removed from the parent's collection while the parent stays. Use either only for children owned by one parent, such as order lines, never for shared data.

### Can a Java record be an entity?

No. The JPA spec forbids records, enums and interfaces as entities, because an entity class and its fields must not be final, and a record is final with final fields. Records work well as DTOs or as query results.
