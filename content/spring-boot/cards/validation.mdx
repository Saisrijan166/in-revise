## Why it exists

Every API must reject bad input: blank names, wrong emails, negative amounts. Declared constraints are checked the same way everywhere, before your code runs, instead of if-checks in each controller.

## How it works

| Constraint | Rejects | `"   "` (spaces) passes? |
| --- | --- | --- |
| `@NotNull` | null | Yes |
| `@NotEmpty` | null, empty string or collection | Yes |
| `@NotBlank` | null, empty, whitespace only | No |
| `@Size`, `@Min`, `@Email`, `@Pattern` | wrong length, value or format; null passes | Depends |

- `@Valid` on a field cascades into a nested object.
- Constraints right on parameters, like `@Min(1)` on a `@RequestParam`, raise `HandlerMethodValidationException`; handle both exceptions.

## Example

```java
record SignupRequest(
        @NotBlank String name,
        @NotNull @Email String email,
        @NotNull @Size(min = 8) String password) { }

@PostMapping("/signup")
ResponseEntity<Void> signup(@Valid @RequestBody SignupRequest request) {
    accounts.create(request);                          // runs only when valid
    return ResponseEntity.status(HttpStatus.CREATED).build();
}
```

## Interview Qs

### How do you validate a request body in Spring Boot?

Add spring-boot-starter-validation, put Jakarta constraints on the DTO fields, and mark the @RequestBody parameter with @Valid. Invalid input throws MethodArgumentNotValidException, which becomes 400 before the method body runs.

### @NotNull vs @NotEmpty vs @NotBlank?

@NotNull only rejects null. @NotEmpty also rejects an empty string or collection. @NotBlank is for text: it also rejects whitespace only, so "   " fails.

### @Valid vs @Validated?

@Valid is the Jakarta annotation: validate this object and cascade into nested ones. @Validated is Spring's: it can name validation groups, and on a class it turns on method validation.
