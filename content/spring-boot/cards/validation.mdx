## Why it exists

Every API must reject bad input: blank names, wrong emails, negative amounts. Hand-written if checks in each controller repeat and drift; declared constraints are checked the same way everywhere, before your code runs.

## How it works

<Mermaid
  alt="Validation flow. A JSON request body is converted into the DTO. The validator checks the constraints, such as @NotBlank and @Email. If all pass, the controller method runs. If any fail, MethodArgumentNotValidException is thrown and the client gets a 400 response, which a @RestControllerAdvice or ProblemDetail can format."
  chart={`flowchart LR
  B([JSON body]) --> C["Converter builds the DTO"]
  C --> V{"Constraints pass?"}
  V -- yes --> M["Controller method runs"]
  V -- no --> E["MethodArgumentNotValidException"]
  E --> R(["400 Bad Request"])`}
/>

- `@Valid` on a field cascades into a nested object; constraints on record components work too.
- Constraints placed directly on parameters use Spring MVC's built-in method validation (Framework 6.1+). Handle both exceptions: they are built alike.
- `@NotNull`: not null. `@NotEmpty`: also not empty. `@NotBlank` (strings): also not only whitespace.

## Example

```java
record SignupRequest(
        @NotBlank String name,
        @NotBlank @Email String email,
        @NotNull @Size(min = 8) String password) { }

@PostMapping("/signup")
ResponseEntity<Void> signup(@Valid @RequestBody SignupRequest request) {
    accounts.create(request);                  // runs only when valid
    return ResponseEntity.status(HttpStatus.CREATED).build();
}

@GetMapping("/items")
List<Item> items(@RequestParam @Min(1) int page) { ... }   // page=0 gives 400
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Validator | Hibernate Validator 9.1 (Jakarta Validation 3.1) | Spring Boot 4.1, `spring-boot-starter-validation` |
| Failed `@Valid @RequestBody` | `MethodArgumentNotValidException`, 400 | Spring Framework 7.0 |
| Failed parameter constraint | `HandlerMethodValidationException`, 400 | Spring Framework 6.1+ |
| Group of a constraint with none named | `Default` | Jakarta Validation 3.1 |

## Interview Qs

### How do you validate a request body in Spring Boot?

Add spring-boot-starter-validation, put Jakarta constraints such as @NotBlank, @Email and @Size on the DTO fields, and annotate the @RequestBody parameter with @Valid. Invalid input raises MethodArgumentNotValidException, which becomes 400 before the method body runs.

### @Valid vs @Validated?

@Valid is the Jakarta annotation: it validates an object and cascades into nested ones. @Validated is Spring's variant: it can name validation groups, and on a class it turns on method validation through a proxy.

### How do you return the field errors to the client?

Handle MethodArgumentNotValidException in a @RestControllerAdvice and map getFieldErrors() to field and message pairs, for example as an extra property of a ProblemDetail. A BindingResult parameter handles them inside the method instead.

### @NotNull vs @NotEmpty vs @NotBlank?

@NotNull only rejects null. @NotEmpty also rejects an empty string, collection, map or array. @NotBlank is for strings: not null and at least one non-whitespace character, so "   " fails.
