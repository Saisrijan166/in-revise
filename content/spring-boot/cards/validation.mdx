## What it is

Bean Validation is a Jakarta standard for checking an object's fields with annotations. Each annotation, called a constraint, states one rule, such as `@NotBlank` (text must not be empty) or `@Positive` (number must be above zero). You put constraints on the fields of a request [DTO](card:dto). When you mark the `@RequestBody` parameter with `@Valid`, Spring runs every rule before calling your controller method.

## Why it exists

Every API must reject bad input: a missing amount, a negative amount, a currency code of the wrong length. Without validation you would write `if` checks at the top of each method, and each endpoint would word its errors differently. Constraints state the rules once, on the DTO, and Spring checks them the same way for every request that uses it.

## How it works

| Constraint | Rejects | Does `"  "` (only spaces) pass? |
| --- | --- | --- |
| `@NotNull` | null | Yes |
| `@NotEmpty` | null, empty string or empty collection | Yes |
| `@NotBlank` | null, empty, or only whitespace | No |
| `@Size`, `@Positive`, `@Email`, `@Pattern` | wrong length, value or format; **null passes** | Depends on the rule |

1. The message converter reads the JSON body into a `PaymentRequest`.
2. Because the parameter has `@Valid`, Spring passes the object to the validator, Hibernate Validator, which the starter brings.
3. The validator checks every constraint on every field and collects all failures, not just the first.
4. If there is at least one failure, Spring throws `MethodArgumentNotValidException`, which becomes 400 Bad Request. Your method is never called.
5. If all checks pass, your method runs with an object you can trust.

## Example

The same `PaymentRequest` from DTOs, now with constraints, and the create endpoint that uses it:

```java
record PaymentRequest(
        @NotNull @Positive BigDecimal amount,       // @Positive alone lets null through
        @NotBlank @Size(min = 3, max = 3) String currency) { }

@PostMapping("/payments")
ResponseEntity<PaymentResponse> create(@Valid @RequestBody PaymentRequest request) {
    PaymentResponse saved = service.create(request);   // runs only if every check passed
    return ResponseEntity.created(URI.create("/payments/" + saved.id())).body(saved);
}
```

What to notice:

- `{"amount": -5, "currency": ""}` fails three rules at once: `@Positive`, `@NotBlank` and `@Size`. The exception lists all of them.
- `@NotNull` and `@Positive` work together: `@Positive` checks the value, `@NotNull` checks that a value exists.
- Remove `@Valid` and nothing is checked: the constraints are only declarations until something asks the validator to run them.

## Rules and defaults

- **Setup:** add `spring-boot-starter-validation`. It brings Hibernate Validator, the reference implementation of the standard.
- **Nested objects:** put `@Valid` on a field that holds another object so the validator checks that object too.
- **Constraints directly on parameters:** for example `@Min(1)` on a `@RequestParam`. Spring Framework 6.1 and later then validate the whole method and throw `HandlerMethodValidationException`, also 400. Handle both exceptions.
- **Services:** put `@Validated` on a service class to check constraints on its method parameters. A failure there throws `ConstraintViolationException`, which Spring MVC does not map to 400 by itself, so the client gets 500 unless you handle it.

## Not to be confused with

`@Valid` is the Jakarta annotation that says "validate this object, and cascade into nested objects". `@Validated` is Spring's annotation: it can name validation groups, and on a class it switches on method validation. Rule: `@Valid` on parameters and fields; `@Validated` on a bean class.

## Interview Qs

### How do you validate a request body in Spring Boot?

Add spring-boot-starter-validation, put Jakarta constraints such as @NotNull and @Positive on the DTO fields, and mark the @RequestBody parameter with @Valid. Invalid input throws MethodArgumentNotValidException, which Spring answers with 400 before the method body runs. A global exception handler then shapes the error.

### What is the difference between @NotNull, @NotEmpty and @NotBlank?

@NotNull only rejects null. @NotEmpty also rejects an empty string or an empty collection. @NotBlank is for text and also rejects a string of only spaces. So "   " passes @NotNull and @NotEmpty but fails @NotBlank.

### Should you validate in the controller or in the service?

Both have a place. Validate the shape of the input at the controller with @Valid, so bad requests stop early with 400. Business rules, such as "the amount must not exceed the customer's limit", need data from the database and belong in the service.
