## Why it exists

One business action often makes several writes that must all succeed or all fail. Coding begin, commit and rollback by hand everywhere is repetitive and error-prone.

## How it works

<Mermaid
  alt="A caller calls the Spring proxy, which begins a transaction and calls your method. If the method returns, or throws a checked exception, the proxy commits. If it throws a RuntimeException or an Error, the proxy rolls back."
  chart={`flowchart LR
  C[Caller] --> P["Proxy: begin"]
  P --> M[Your method]
  M -- "returns, or checked exception" --> CM[Commit]
  M -- "RuntimeException or Error" --> RB[Roll back]`}
/>

- A call from inside the same object skips the proxy, so no transaction starts (see [Spring proxies](card:aop-proxies)).
- A caught exception never reaches the proxy, so it commits. Rethrow it to roll back.
- The proxy hands the real work to a `PlatformTransactionManager`, such as `JpaTransactionManager`.

## Example

```java
@Service
public class PaymentService {
    // repositories injected through the constructor

    @Transactional(rollbackFor = PaymentException.class)
    public void pay(long orderId, BigDecimal amount) throws PaymentException {
        payments.save(new Payment(orderId, amount));
        accounts.debit(orderId, amount);   // throws: both writes roll back
    }
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Propagation | `REQUIRED` | Spring Framework 7.0 |
| Isolation | `DEFAULT`: the database's own level | Spring Framework 7.0 |
| readOnly | `false` | Spring Framework 7.0 |
| Rolls back on | `RuntimeException`, `Error` | Spring Framework 7.0 |

## Interview Qs

### How does @Transactional work if it is only an annotation?

Spring wraps the bean in a proxy. The proxy asks the transaction manager to begin, calls your method, then commits or rolls back.

### Why does @Transactional sometimes not work?

The call skipped the proxy (self-invocation, a private method, an object made with new), or the exception was checked or caught inside the method, so the proxy committed.

### Why put it on the service layer?

One business action may call several repositories. Starting the transaction there makes the whole action commit or roll back together.
