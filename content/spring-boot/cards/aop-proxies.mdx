## Why it exists

Logging, security checks, transactions and caching are needed in many classes. AOP writes such cross-cutting code once and applies it to the methods you choose, without editing those classes.

## How it works

<Mermaid
  alt="A caller calls placeOrder on what it thinks is OrderService, but it holds a proxy. The proxy runs the advice, for example starts a transaction, then calls the real OrderService. Inside the real object, a call to this.audit goes straight to the same object and skips the proxy, so no advice runs for it."
  chart={`flowchart LR
  C[Caller] -- "placeOrder()" --> P["Proxy: advice runs here"]
  P -- "then calls" --> T[Real OrderService]
  T -- "this.audit(): skips the proxy" --> T`}
/>

- Spring AOP advises only method executions on beans; to advise fields, constructors or self-calls, use AspectJ weaving.
- A JDK proxy implements the bean's interfaces; a CGLIB proxy is a generated subclass. See [JDK vs CGLIB](compare:jdk-proxy-vs-cglib).
- `@Transactional`, `@Async` and `@Cacheable` all work through these proxies, so they share the self-invocation gap.

## Analogy

<Analogy title="The receptionist" limit="A proxy sees only calls made on it, and only for methods it can override or implement.">
Visitors to the manager (the bean) pass the receptionist (the proxy), who signs them in (the advice). When the manager walks to the next desk to talk to a colleague (a self-call), no one signs anything.
</Analogy>

## Example

```java
@Aspect
@Component                                    // @Aspect alone is not found by scanning
public class TimingAspect {
    private static final Logger log = LoggerFactory.getLogger(TimingAspect.class);

    @Around("execution(* com.shop.service..*.*(..))")   // pointcut: every service method
    public Object time(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.nanoTime();
        try {
            return pjp.proceed();             // call the real method
        } finally {
            log.info("{} took {} ms", pjp.getSignature(), (System.nanoTime() - start) / 1_000_000);
        }
    }
}
```

```xml
<!-- Needed for @Aspect classes; the Spring Boot 4.x starter name -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aspectj</artifactId>
</dependency>
```

## Interview Qs

### What are aspect, advice, pointcut and join point?

An aspect is a class holding cross-cutting logic, like timing. A join point is a point in execution; in Spring AOP always a method execution. A pointcut is an expression that selects join points. Advice is the code that runs there.

### JDK dynamic proxy vs CGLIB?

A JDK proxy implements the bean's interfaces, so only interface methods are advised and it cannot be injected as the concrete class. CGLIB generates a subclass, so it needs no interface but cannot advise final methods. Spring Boot uses CGLIB by default.

### Why does @Transactional not work when I call the method from the same class?

Spring applies it through a proxy, and an internal call uses `this`, the real object, so the proxy never sees it. Move the method into another bean, or use AspectJ weaving, which changes the bytecode instead of using a proxy.

### What types of advice are there?

@Before, @AfterReturning (after a normal return), @AfterThrowing (after an exception), @After (always, like finally) and @Around, which wraps the call and decides whether to call `proceed()`. Use the least powerful one that does the job.
