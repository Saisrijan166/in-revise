## Why it exists

Instances start, stop and move, so addresses keep changing. Services need a live directory to register in and look up by name.

## How it works

<Mermaid
  alt="Eureka flow. Two orders instances register with the Eureka server and send heartbeats. The checkout service fetches the registry. When checkout calls http://orders, Spring Cloud LoadBalancer picks orders instance 2."
  chart={`flowchart LR
  O1[orders 1] -- "register, heartbeat" --> E[(Eureka server)]
  O2[orders 2] -- "register, heartbeat" --> E
  C[checkout] -- "fetch registry" --> E
  C -- "http://orders: LoadBalancer picks one" --> O2`}
/>

- Silent instances are dropped; self-preservation pauses this when many go silent together.
- Spring Cloud LoadBalancer uses round robin by default.
- On Kubernetes, a Service with a DNS name often replaces Eureka.

## Example

```java
@Bean
@LoadBalanced
RestClient.Builder restClientBuilder() {
    return RestClient.builder();
}

// builder: the injected @LoadBalanced RestClient.Builder
// "orders" is a service name, resolved through Eureka
Order order = builder.build().get().uri("http://orders/orders/{id}", 42)
        .retrieve().body(Order.class);
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Heartbeat (lease renewal) | Every 30 s | Spring Cloud Netflix 5.0 |
| Instance dropped after | 90 s without a heartbeat | Spring Cloud Netflix 5.0 |
| Client registry fetch | Every 30 s | Spring Cloud Netflix 5.0 |
| Self-preservation | On, renewal threshold 0.85 | Spring Cloud Netflix 5.0 |

## Interview Qs

### How does Eureka work?

Each instance registers on startup and sends a heartbeat every 30 s; the server drops it after 90 s of silence. Callers fetch and cache the registry, and a client-side load balancer picks an instance per call.

### What is self-preservation mode?

When far more instances go silent than expected, the server stops evicting them, so a network fault does not wipe out a healthy registry. The cost: dead instances may stay listed for a while.

### Do you need Eureka on Kubernetes?

Often not. Kubernetes gives each Service a DNS name and tracks the Pods behind it.
