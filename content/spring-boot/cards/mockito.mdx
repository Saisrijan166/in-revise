## What it is

Mockito is a library that creates **fake objects** for tests. A fake, called a mock, has the same methods as the real class, but does nothing unless you tell it what to return. `@Mock` creates a fake inside a plain test class. `@MockitoBean` creates one and puts it into the Spring context, so beans that [depend on](card:dependency-injection) the real class get the fake instead.

## Why it exists

To test the rules inside `PaymentService`, you should not need a running database or a real fraud-check API. Without fakes, a test would fail whenever the network or the database is down, and you could not easily make the database return "not found". A mock replaces each dependency with something you control, so the test checks only your logic.

## How it works

<Steps label="A Mockito unit test">
  <Step title="Create">`@Mock` makes a fake for each dependency; `@InjectMocks` creates the class under test and passes the fakes in.</Step>
  <Step title="Stub">`when(...).thenReturn(...)` says what a fake returns for a given call.</Step>
  <Step title="Act">The test calls the real method under test.</Step>
  <Step title="Check">Assert on the result, or `verify(...)` that a call happened.</Step>
</Steps>

1. `MockitoExtension` creates a mock for every `@Mock` field before each test.
2. For the `@InjectMocks` field, Mockito calls the biggest constructor and passes in the matching mocks. Only a class with a no-argument constructor gets setter or field injection instead.
3. You stub only the calls this test needs. A call you did not stub returns an empty value, such as `null`, `0` or an empty list.
4. After the act step, you check the result, the calls, or both.

## Example

This unit test checks that paying saves a payment with status `PAID`. No Spring starts and no database runs.

```java
@ExtendWith(MockitoExtension.class)
class PaymentServiceTests {
    @Mock PaymentRepository repo;
    @InjectMocks PaymentService service;

    @Test
    void savesPaidPayment() {
        when(repo.save(any(Payment.class))).thenAnswer(call -> call.getArgument(0));

        PaymentResponse response = service.pay(new PaymentRequest(new BigDecimal("500.00")));

        assertThat(response.status()).isEqualTo("PAID");
        verify(repo).save(any(Payment.class));
    }
}
```

What to notice:

- `thenAnswer(call -> call.getArgument(0))` makes the fake `save` return the payment it was given, like the real repository does.
- Without that stub, `save` returns `null`, and the service would fail when it reads the saved payment.
- `verify(repo).save(...)` fails the test if `pay` forgot to save.

## Rules and defaults

- **Strict stubs:** with `MockitoExtension`, a stub the code never calls fails the test with `UnnecessaryStubbingException`.
- **`@MockitoBean` placement:** on a field of a Spring test class; it replaces the bean of that type, or creates one if none exists.
- **Reset:** `@MockitoBean` fakes are reset after each test method by default, so stubs do not leak into the next test.
- **No proxy:** a `@MockitoBean` fake is never wrapped in a Spring proxy, so its `@Transactional` or `@Cacheable` behaviour is gone (see [proxies](card:aop-proxies)).
- **Spy:** a spy (`@Spy`, or `@MockitoSpyBean` in Spring) wraps a real object; real methods run unless you stub them.

## Not to be confused with

A **stub** is a fake that returns canned answers, so you check the result. A **mock** is a fake you check for calls, such as "was `save()` called once?". Rule: stub = controls what comes back; mock = checks what was called. In Mockito one fake object does both.

## Interview Qs

### Mock vs stub?

A stub returns canned answers, such as "`findById(1)` returns this payment", and you then check the result. A mock is used to check interactions, such as "was `save()` called once?". Mockito creates one kind of object that can do both, so the difference is in how the test uses it.

### If Mockito's @Mock exists, why do we need @MockitoBean?

`@Mock` lives only inside the test class, and Spring does not know about it. When Spring creates the object under test, as in `@WebMvcTest`, the fake must be a bean in the context so Spring can inject it. `@MockitoBean` replaces the real bean there.

### What replaced @MockBean?

Spring Framework's `@MockitoBean` and `@MockitoSpyBean`, added in 6.2. Spring Boot's `@MockBean` and `@SpyBean` were deprecated in 3.4 and removed in 4.0, so a Boot 4 project must use the new annotations.
