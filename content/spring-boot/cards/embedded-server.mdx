## Why it exists

Classic Java web apps were packaged as a war and deployed into a separately installed server. With the server embedded, the app is one self-contained jar that starts with `java -jar`, which suits containers and the cloud.

## How it works

| You add | Server you get | Used for |
| --- | --- | --- |
| `spring-boot-starter-webmvc` | Tomcat 11.0 (default) | Servlet apps |
| webmvc without `spring-boot-starter-tomcat`, plus `spring-boot-starter-jetty` | Jetty 12.1 | Servlet apps |
| `spring-boot-starter-webflux` | Reactor Netty (default) | Reactive apps |

- Set the port with `server.port` or the `SERVER_PORT` variable. `0` picks a free port; tests read it with `@LocalServerPort`.
- On shutdown the server stops accepting new requests and lets running ones finish, up to `spring.lifecycle.timeout-per-shutdown-phase`.
- An IDE stop may skip graceful shutdown if it does not send a proper `SIGTERM`.

## Example

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc</artifactId>
    <exclusions>
        <exclusion>  <!-- drop Tomcat -->
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-tomcat</artifactId>
        </exclusion>
    </exclusions>
</dependency>
<dependency>  <!-- use Jetty instead -->
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jetty</artifactId>
</dependency>
```

```properties
server.port=9090
# graceful is already the default since Spring Boot 3.4
server.shutdown=graceful
spring.lifecycle.timeout-per-shutdown-phase=20s
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Servlet server | Tomcat 11.0.24 | Spring Boot 4.1.1 |
| Reactive server | Reactor Netty 1.3.7 | Spring Boot 4.1.1 |
| `server.port` | `8080` | Spring Boot 4.1 |
| `server.shutdown` | `graceful` (was `immediate` before 3.4) | Spring Boot 3.4 and later |
| `spring.lifecycle.timeout-per-shutdown-phase` | `30s` | Spring Boot 4.1 |
| `server.tomcat.threads.max` | `200` (ignored with virtual threads) | Spring Boot 4.1 |

## Interview Qs

### Which embedded servers does Spring Boot support, and how do you change the default?

Tomcat (the default) and Jetty for servlet apps; Reactor Netty is the WebFlux default. Spring Boot 4 removed Undertow. To switch, exclude `spring-boot-starter-tomcat` from the web starter and add `spring-boot-starter-jetty`.

### How do you change the port, or pick a random one?

Set `server.port=9090` in application.properties, or the `SERVER_PORT` environment variable. `server.port=0` picks a free port; in tests, read it with `@LocalServerPort`.

### Can you disable the embedded server?

Yes. `spring.main.web-application-type=none` starts the app without any web server. `server.port=-1` keeps the web context but opens no HTTP port.

### What happens to running requests on shutdown?

Since Boot 3.4, graceful shutdown is the default: the server stops accepting new requests and lets running ones finish, up to 30 s per shutdown phase. `server.shutdown=immediate` turns it off.
