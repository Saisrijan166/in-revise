## What it is

An embedded server is a web server, such as Tomcat, that runs inside your application as a normal library. A web server is the program that listens on a network port and passes each HTTP request to your code. With an embedded server, `java -jar payment.jar` starts the server and your app in one process, with nothing installed on the machine beforehand.

## Why it exists

Classic Java web apps were packaged as a war file and copied into a Tomcat that someone had installed and configured on the server. Every machine needed the right Tomcat version and settings, and the app could not run on its own. With the server inside the jar, the app carries its own server and settings. The same jar runs on a laptop, a VM or in a container, which is what Docker and Kubernetes expect.

## How it works

| You add | Server you get | Web stack |
| --- | --- | --- |
| `spring-boot-starter-webmvc` | Tomcat (default) | Servlet (Spring MVC) |
| webmvc without `spring-boot-starter-tomcat`, plus `spring-boot-starter-jetty` | Jetty | Servlet (Spring MVC) |
| `spring-boot-starter-webflux` | Reactor Netty (default) | Reactive (WebFlux) |

1. The web [starter](card:starters) puts the server's jars on the classpath.
2. [Auto-configuration](card:auto-configuration) sees those classes and creates a web server factory bean for that server.
3. During the context refresh in [startup](card:application-startup), Boot uses the factory to start the server on `server.port`.
4. Each incoming request goes to Spring MVC's front controller, which you will see in [DispatcherServlet](card:dispatcher-servlet).
5. When the app stops, the server stops taking new requests and lets running ones finish.

## Example

The payment service runs in a container on port 9090 and gives running payments 20 seconds to finish on shutdown:

```properties
server.port=9090
# graceful is already the default; immediate would cut requests off
server.shutdown=graceful
spring.lifecycle.timeout-per-shutdown-phase=20s
```

What to notice:

- `server.port=9090` replaces the default 8080. You can also pass it at start-up as `--server.port=9090` or the `SERVER_PORT` environment variable, without editing the file.
- `server.shutdown=graceful` is shown only to make it visible; leaving the line out gives the same behaviour.
- With `timeout-per-shutdown-phase=20s`, a request still running after 20 seconds is cut off. Leave the line out and the limit is 30 seconds.

## Rules and defaults

| What | Default | Where |
| --- | --- | --- |
| `server.port` | `8080` | Spring Boot 4.1 |
| `server.shutdown` | `graceful` (since 3.4) | Spring Boot 4.1 |
| `spring.lifecycle.timeout-per-shutdown-phase` | `30s` | Spring Boot 4.1 |

- **Special ports:** `server.port=0` picks a free port; `server.port=-1` creates the web context but opens no HTTP port, which is sometimes useful in tests.
- **No web server at all:** set `spring.main.web-application-type=none`, or keep web starters off the classpath. The app then runs its runners and exits, unless something else keeps it alive.
- **Reactive apps:** WebFlux can also run on Tomcat or Jetty instead of Reactor Netty.
- **Changed in 4.0:** Undertow and its starter were removed; Boot 4 needs Servlet 6.1, which Undertow does not support yet.

## Interview Qs

### Which embedded servers does Spring Boot support, and how do you switch?

Servlet apps run on Tomcat, the default, or Jetty. WebFlux apps default to Reactor Netty. Boot 4 removed Undertow. To switch to Jetty, exclude `spring-boot-starter-tomcat` from `spring-boot-starter-webmvc` and add `spring-boot-starter-jetty`; auto-configuration then starts Jetty instead.

### How do you change the port, or pick a random one?

Set `server.port=9090` in `application.properties`, pass `--server.port=9090`, or set the `SERVER_PORT` environment variable. `server.port=0` picks a free port, which helps when several copies or tests run on one machine.

### What is graceful shutdown, and is it on by default?

On shutdown the server stops accepting new requests and gives running ones time to finish. Since Boot 3.4 it is on by default for Tomcat, Jetty and Reactor Netty, with up to 30 seconds per shutdown phase. `server.shutdown=immediate` turns it off.
