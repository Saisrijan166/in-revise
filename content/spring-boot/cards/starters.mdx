## Why it exists

Picking compatible versions of many libraries by hand is slow and breaks easily. A starter bundles the libraries for one feature, and the BOM fixes one tested version of each.

## How it works

| Starter | Brings |
| --- | --- |
| `spring-boot-starter-webmvc` | Spring MVC and embedded Tomcat |
| `spring-boot-starter-data-jpa` | Spring Data JPA with Hibernate |
| `spring-boot-starter-validation` | Bean Validation with Hibernate Validator |
| `spring-boot-starter-test` | JUnit Jupiter, Hamcrest and Mockito |

- Maven gets the BOM by inheriting `spring-boot-starter-parent`, or by importing `spring-boot-dependencies` when it must keep another parent.
- Gradle builds use the same BOM ([Maven or Gradle](card:build-tools) both work).

## Example

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.1</version>
</parent>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc</artifactId>
    <!-- no version: the BOM manages it -->
</dependency>
```

## Interview Qs

### What is a Spring Boot starter?

A dependency descriptor that brings a tested set of libraries for one feature. `spring-boot-starter-data-jpa` brings Spring Data JPA and Hibernate, so you add one dependency instead of many.

### How does Spring Boot manage dependency versions?

Through the `spring-boot-dependencies` BOM, inherited via the starter parent or imported. You leave out versions; upgrading Boot moves every managed library to a combination tested together.

### How do you override one managed version?

With the parent, set its version property, such as `slf4j.version`. With an imported BOM, declare that dependency before the Boot BOM. Each Boot release is tested with its own set, so do it with care.
