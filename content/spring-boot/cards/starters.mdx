## What it is

A starter is a single Maven or Gradle dependency that brings a whole feature. `spring-boot-starter-webmvc`, for example, brings Spring MVC, the Jackson JSON library and an embedded Tomcat server. Behind the starters sits a **BOM** (bill of materials): a list inside Spring Boot that fixes one tested version for each library it manages. Together they decide which jars your app gets and at which versions.

## Why it exists

Without starters, a web app needs Spring MVC, Jackson, Tomcat and a logging library, each added by hand with a version you chose. Pick one wrong version and the app fails at runtime with a missing method or class. Starters replace that list with one dependency, and the BOM picks versions that the Boot team tested together. Upgrading Boot then upgrades all of them in one step.

## How it works

1. Your build file inherits `spring-boot-starter-parent` (Maven), or imports the `spring-boot-dependencies` BOM when it must keep a company parent POM. Gradle uses the same BOM.
2. You add starters, and any other managed library, without a version.
3. The build tool looks up each missing version in the BOM.
4. Each starter pulls in its libraries, plus the Boot module that holds that feature's [auto-configuration](card:auto-configuration), which you meet next.

## Example

The payment service needs a REST API and PostgreSQL. Its `pom.xml` names the parent once and no other versions:

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.1</version>
</parent>
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc</artifactId>
    </dependency>
    <dependency>
        <groupId>org.postgresql</groupId>
        <artifactId>postgresql</artifactId>
    </dependency>
</dependencies>
```

What to notice:

- Neither dependency has a `<version>`. Both come from the BOM, because Boot manages the PostgreSQL driver too.
- The parent's version, `4.1.1`, is the only version you choose. Changing it upgrades every managed library together.
- If you remove the parent and import no BOM, Maven rejects the build, because the two dependencies now have no version.

## Rules and defaults

- **Naming:** official starters are named `spring-boot-starter-*`. A third-party starter must not start with `spring-boot`; it is named like `acme-spring-boot-starter`.
- **Override one version:** with the parent, set that library's version property, such as `<postgresql.version>`. Boot tests each release with its own set, so do this only for a reason, such as a security fix.
- **Java level:** `spring-boot-starter-parent` 4.1 compiles for Java 17 and uses UTF-8 source encoding. Set `<java.version>25</java.version>` to target Java 25.
- **What you add yourself:** the database driver, and `spring-boot-starter-validation` for [`@Valid`](card:validation).
- **Changed in 4.0:** Boot is split into small modules, and `spring-boot-starter-web` is deprecated in favour of `spring-boot-starter-webmvc`. Each technology also has its own test starter, such as `spring-boot-starter-webmvc-test`.

## Not to be confused with

A starter decides **which jars** are on the classpath. [Auto-configuration](card:auto-configuration) decides **which beans** Boot builds from those jars. Rule: starter = jars and versions; auto-configuration = beans.

## Interview Qs

### What is a Spring Boot starter, and why use one?

It is one dependency that brings a tested set of libraries for one feature. `spring-boot-starter-data-jpa` brings Spring Data JPA, Hibernate and the connection pool. You add one line instead of many and avoid version clashes between them.

### How does Spring Boot manage dependency versions?

Through the `spring-boot-dependencies` BOM, which you get by inheriting `spring-boot-starter-parent` or by importing the BOM. You leave versions out, the BOM fills them in, and upgrading Boot moves every managed library to a combination tested together.

### How do you override one managed version?

With the parent, set its version property, such as `<postgresql.version>`. With an imported BOM, list that dependency with its version in `dependencyManagement`, before the Boot BOM. Each Boot release is tested with its own versions, so override only for a reason, such as a security fix.
