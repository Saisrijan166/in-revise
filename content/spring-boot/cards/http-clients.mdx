## Why it exists

Services call other services over HTTP. A client turns Java objects into requests and responses back into objects, and handles errors and timeouts so your code does not.

## How it works

<Compare id="restclient-vs-webclient-vs-resttemplate" />

- Set connect and read timeouts, for example `spring.http.clients.read-timeout=5s`, so a slow service cannot hold your threads.
- A 4xx or 5xx response throws an exception by default; `onStatus(...)` handles it your way.
- OpenFeign still works but is feature-complete; its docs suggest HTTP service clients.

## Example

```java
@Service
class PriceClient {
    private final RestClient http;
    PriceClient(RestClient.Builder builder) {                // auto-configured by Boot
        this.http = builder.baseUrl("https://prices.example.com").build();
    }
    Price price(String sku) {
        return http.get().uri("/prices/{sku}", sku)
                .retrieve().body(Price.class);              // 4xx/5xx throw
    }
}
```

## Interview Qs

### RestTemplate vs RestClient vs WebClient?

RestTemplate is the classic blocking client with template methods; Framework 7.0 deprecates it, with removal planned for 8.0. RestClient is also blocking, with a fluent API. WebClient is non-blocking and reactive. New blocking code should use RestClient.

### If RestClient can call APIs, why do we need WebClient?

Different execution models. RestClient blocks the calling thread until the response arrives. WebClient returns Mono or Flux, does not wait, and supports streaming, so it fits WebFlux apps.

### What is an HTTP service client?

A Java interface whose methods carry @GetExchange or @PostExchange. Spring generates a proxy that makes the calls through RestClient or WebClient, so you declare the API once instead of building each request.
