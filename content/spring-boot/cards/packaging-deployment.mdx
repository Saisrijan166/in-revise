## Why it exists

Java has no standard way to run a jar that contains other jars. Spring Boot's loader makes one self-contained file that runs wherever Java runs; layers then make container builds cache well.

## How it works

| Layer, in image order | Holds | Likely to change |
| --- | --- | --- |
| `dependencies` | Released libraries from `BOOT-INF/lib` | Least |
| `spring-boot-loader` | The launcher classes | Low |
| `snapshot-dependencies` | `SNAPSHOT` libraries | Higher |
| `application` | Your classes and resources | Most |

- `java -jar app.jar`: the manifest's `Main-Class` is `JarLauncher`; it loads `BOOT-INF/lib`, then calls your `Start-Class`.
- Docker rebuilds only changed layers, so a code change ships just the small `application` layer.
- Must deploy into an existing Tomcat? See [jar vs war](compare:jar-vs-war).

## Example

```bash
./mvnw package                                     # target/app.jar, executable
java -jar target/app.jar                           # the embedded server starts
java -Djarmode=tools -jar target/app.jar extract   # app/app.jar + app/lib/
./mvnw spring-boot:build-image                     # OCI image with buildpacks

# Java 25+: one training run, then faster starts
cd app
java -XX:AOTCacheOutput=app.aot -Dspring.context.exit=onRefresh -jar app.jar
java -XX:AOTCache=app.aot -jar app.jar
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `layers.idx` in the jar | Included | Spring Boot 4.1 Maven plugin |
| Buildpacks builder | `paketobuildpacks/builder-noble-java-tiny:latest` | Spring Boot 4.1 Maven plugin |
| Image name | `docker.io/library/${project.artifactId}:${project.version}` | Spring Boot 4.1 Maven plugin |
| Startup cache | AOT cache on Java 25+, CDS before that | Spring Boot 4.1 |

## Interview Qs

### How do you deploy a Spring Boot app as a jar and as a war?

Jar: `mvn package`, then `java -jar app.jar`; the server is inside. War: set packaging to `war`, extend `SpringBootServletInitializer`, mark `spring-boot-starter-tomcat` as `provided`, and deploy to a servlet container. Built by the Boot plugin, the war also runs with `java -jar`.

### What is inside a Spring Boot fat jar?

The manifest names `JarLauncher` as `Main-Class` and your class as `Start-Class`. Your classes are in `BOOT-INF/classes`, dependency jars are nested unchanged in `BOOT-INF/lib`, and the loader classes read those nested jars.

### Why use a layered jar for Docker images?

Docker caches image layers and rebuilds only what changed. Libraries change rarely and your code changes every build, so putting dependencies first means a rebuild ships only the small application layer.

### How can a JVM app start faster without going native?

Run it extracted with `-Djarmode=tools extract`. On Java 25+, add an AOT cache from a training run; before Java 25, use CDS. Spring AOT code (build with `-Pnative`, run with `-Dspring.aot.enabled=true`) helps too.
