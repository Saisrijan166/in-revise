## Why it exists

Stopping and starting the app after every code change wastes time. DevTools restarts it for you, faster than a cold start, and sets development-friendly defaults.

## How it works

<Mermaid
  alt="DevTools restart flow. You edit and build, which changes the classpath. DevTools sees the change, throws away the restart class loader and creates a new one that loads your classes again. The base class loader, which holds third-party jars, is kept, so the app restarts quickly."
  chart={`flowchart LR
  E[Edit and build] --> W{Classpath changed?}
  W -- yes --> R[Drop the restart class loader]
  R --> N[New restart class loader loads your classes]
  N --> S([App restarted])
  B[(Base class loader: third-party jars, kept)] -.-> S`}
/>

- It watches the classpath, so a restart follows a build (Eclipse builds on save; IntelliJ IDEA needs Build Project).
- Too slow, or class-loading problems? Reloading tools such as JRebel rewrite classes instead of restarting.
- Restart works with `mvn spring-boot:run` and `gradle bootRun` too; keep forking enabled.

## Example

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-devtools</artifactId>
    <!-- not passed on to modules that depend on this one -->
    <optional>true</optional>
</dependency>
```

```properties
# restart only when this file changes
spring.devtools.restart.trigger-file=.reloadtrigger
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `spring.devtools.restart.enabled` | `true` | Spring Boot 4.1 DevTools |
| `spring.devtools.restart.poll-interval` | `1s` | Spring Boot 4.1 DevTools |
| `spring.devtools.restart.quiet-period` | `400ms` | Spring Boot 4.1 DevTools |
| `spring.devtools.livereload.enabled` | `false` | Spring Boot 4.0 and later |
| `spring.thymeleaf.cache` (set by DevTools) | `false` | Spring Boot 4.1 DevTools |

## Interview Qs

### What is Spring Boot DevTools used for?

Faster development: automatic restart on classpath changes, development defaults such as no template caching, and optional remote restart. It is for development only and switches itself off in a packaged app.

### Why is a DevTools restart faster than a cold start?

Classes that do not change, such as third-party jars, stay loaded in a base class loader. Only your own classes are in a restart class loader, which is thrown away and recreated on each restart.

### Is DevTools active in production?

No. It is disabled when the app is started with `java -jar` or from a special class loader, and repackaged jars leave it out by default. Mark it `optional` in Maven or `developmentOnly` in Gradle, and never enable remote DevTools in production.
