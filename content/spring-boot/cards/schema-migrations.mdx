## Why it exists

Every environment needs the same schema, and schema changes must ship with the code that needs them. Letting Hibernate alter tables on its own is unpredictable and leaves no record of what changed.

## How it works

<Mermaid
  alt="At startup Flyway reads its history table, flyway_schema_history. If there are pending scripts, it runs them in version order and records each version and checksum. Then JPA starts, with ddl-auto set to validate."
  chart={`flowchart LR
  S([App starts]) --> H[Read flyway_schema_history]
  H --> P{Pending scripts?}
  P -- yes --> R[Run them in version order]
  R --> W[Record version and checksum]
  W --> J["Start JPA, ddl-auto=validate"]
  P -- no --> J`}
/>

- An applied script that was edited no longer matches its checksum, so migrate refuses to run. Fix forward with a new version.
- `schema.sql` and `data.sql` run only for embedded databases by default. Boot advises using Flyway or Liquibase alone.

## Example

Files in `src/main/resources/db/migration`, run in version order: `V1__create_book.sql`, `V2__add_isbn_to_book.sql`, then repeatable `R__` scripts.

```sql
-- V2__add_isbn_to_book.sql
ALTER TABLE book ADD COLUMN isbn VARCHAR(13);
CREATE UNIQUE INDEX ux_book_isbn ON book (isbn);
```

The starter, plus the module for your database:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-flyway</artifactId>
</dependency>
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-database-postgresql</artifactId>
</dependency>
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `ddl-auto`, embedded DB and no Flyway or Liquibase | `create-drop` | Spring Boot 4.1 |
| `ddl-auto`, any other case | `none` | Spring Boot 4.1 |
| Flyway scripts | `classpath:db/migration` | Spring Boot 4.1 |
| Liquibase changelog | `db/changelog/db.changelog-master.yaml` | Spring Boot 4.1 |
| `schema.sql`, `data.sql` | Embedded databases only (`spring.sql.init.mode`) | Spring Boot 4.1 |
| Validate before migrate | On (`validateOnMigrate`) | Flyway |

## Interview Qs

### Why not ddl-auto=update in production?

It only adds what is missing and alters column types. It keeps no history, migrates no data, and a renamed field becomes a new column next to the old one. Versioned scripts are reviewed and repeatable; let Hibernate only validate.

### How does Flyway know what to run?

Its flyway_schema_history table lists each applied version with a checksum. At startup it runs the scripts with newer versions, in order. Repeatable R__ scripts run after them whenever their checksum changes.

### Flyway vs Liquibase?

Flyway runs SQL files ordered by version number, so it is simple. Liquibase runs changesets from a changelog in XML, YAML, JSON or SQL, with database-independent change types and a rollback command. Both run at Boot startup and keep a history table.
