## What it is

Spring Cloud is a family of projects, built on Spring Boot, for apps made of many small services (microservices). Each project solves one problem that only appears once services talk to each other, such as finding another service's address. You add them like any other [starter](card:starters), and they configure themselves the Boot way. A **release train** is the set of Spring Cloud project versions that are tested together and released under one name, such as 2025.1.x.

## Why it exists

Say the payment service is split out of a big app, next to an order service and a notification service. Now each service needs its config, has to find the others although their addresses change, needs one public entry point, and must survive when another service is slow. Writing that code yourself, in every service, is a lot of repeated, tricky work. Spring Cloud gives a tested library for each problem.

## How it works

| Problem between services | Spring Cloud answer |
| --- | --- |
| Config spread over many apps | [Config Server](card:config-server) |
| Instances come and go | [Eureka](card:service-discovery-eureka), Consul or Kubernetes |
| One door for all clients | [Spring Cloud Gateway](card:spring-cloud-gateway) |
| A called service is failing | [Circuit breaker and retry](card:resilience4j) |
| Events between services | [Kafka](card:spring-kafka), Spring Cloud Stream |

1. You import the release train BOM once, in `dependencyManagement`.
2. You add the starters you need, such as the Eureka client, with no version numbers.
3. The BOM supplies versions that work together and with your Boot line.
4. Each starter brings auto-configuration, so most setup is properties, not code.

## Example

The payment service's `pom.xml` imports the release train that matches Spring Boot 4.1:

```xml
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>org.springframework.cloud</groupId>
      <artifactId>spring-cloud-dependencies</artifactId>
      <version>2025.1.3</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>
```

What to notice:

- `scope import` with `type pom` copies the BOM's version list into your project; it adds no library by itself.
- After this, a starter such as `spring-cloud-starter-netflix-eureka-client` needs no `<version>`.
- Change only this one version when you upgrade Spring Cloud, and check the train supports your Boot version.

## Rules and defaults

- **Compatibility:** 2025.1.x (Oakwood) supports Spring Boot 4.0.x, and 4.1.x from 2025.1.2. 2025.0.x (Northfields) is for Boot 3.5.x.
- **Versions:** the Boot parent or BOM does not manage Spring Cloud. Without the train BOM you must pin every Spring Cloud artifact yourself.
- **Removed modules:** Hystrix, Ribbon and Zuul were removed in 2020.0. Eureka is still supported.
- **Calling by name:** a service calls another by its name through [HTTP clients](card:http-clients) and Spring Cloud LoadBalancer.

## Not to be confused with

[Spring Boot](card:spring-vs-spring-boot) makes **one** service easy to build and run. Spring Cloud handles what happens **between** services. Rule: Boot = inside one service; Cloud = across many services.

## Interview Qs

### Spring Boot vs Spring Cloud?

Spring Boot builds one production-ready service with auto-configuration and an embedded server. Spring Cloud is a set of projects on top of Boot for the patterns between services: central config, discovery, a gateway, client-side load balancing, circuit breakers and messaging. A Spring Cloud app is always a Boot app.

### What is a release train?

One BOM, `spring-cloud-dependencies`, listing versions of all Spring Cloud projects that were tested together. Since 2020.0 trains are numbered by year, with a code name such as Oakwood. You import it and leave versions off the Spring Cloud starters. For Boot 4.1, use 2025.1.x from 2025.1.2.

### What happened to Hystrix, Ribbon and Zuul?

They were removed in Spring Cloud 2020.0. Use Resilience4j for circuit breakers, Spring Cloud LoadBalancer for client-side load balancing and Spring Cloud Gateway for routing. Eureka, from the same Netflix family, is still supported.
