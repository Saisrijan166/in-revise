## Why it exists

Splitting an app into many services adds new problems: where config lives, how services find each other, how requests are routed, and how calls survive failures. Spring Cloud answers each one with a Spring Boot-style library.

## How it works

| Problem between services | Spring Cloud answer |
| --- | --- |
| Config spread over many apps | [Config Server](card:config-server) |
| Instances come and go | [Eureka](card:service-discovery-eureka), Consul, or Kubernetes |
| One entry point for clients | [Spring Cloud Gateway](card:spring-cloud-gateway) |
| Calling another service | [OpenFeign](card:openfeign) or HTTP Service Clients, with Spring Cloud LoadBalancer |
| A dependency is failing | [Circuit breakers with Resilience4j](card:resilience4j) |
| Events between services | Spring Cloud Stream and Bus; [Spring for Apache Kafka](card:spring-kafka) |

- All versions come from one release train BOM. Spring Boot does not manage it, so you pick the train that matches your Boot version.
- Trains use calendar versions since 2020.0, with London Tube station codenames: 2025.1 is Oakwood.

## Example

Import the release train once; Spring Cloud starters then need no versions:

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.cloud</groupId>
            <artifactId>spring-cloud-dependencies</artifactId>
            <version>2025.1.3</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

## Interview Qs

### What is Spring Cloud, and how is it different from Spring Boot?

Spring Boot builds one production-ready app. Spring Cloud is a set of libraries on top of Boot for the patterns between many apps: central config, discovery, a gateway, load balancing, circuit breakers and messaging.

### What is a release train, and which one fits Spring Boot 4.1?

One BOM of Spring Cloud project versions tested together, named by calendar since 2020.0. For Boot 4.1 use 2025.1.x (Oakwood) from 2025.1.2; 2025.1.3 came out on 20-08-2026. Import the BOM and leave versions off the starters.

### What happened to Hystrix, Ribbon and Zuul?

Spring put them into maintenance mode in 2018 and removed them in 2020.0. Use Resilience4j for circuit breakers, Spring Cloud LoadBalancer for client-side load balancing and Spring Cloud Gateway for routing. Eureka is the Netflix part that stays.
