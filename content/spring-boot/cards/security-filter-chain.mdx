## Why it exists

Every request must be checked before it reaches a controller. Servlet filters run first, so Spring Security puts its checks there.

## How it works

<Mermaid
  alt="Request path through Spring Security. The servlet container calls DelegatingFilterProxy, which calls the FilterChainProxy bean. FilterChainProxy picks the first SecurityFilterChain that matches and runs its filters in order: CsrfFilter, login filters, ExceptionTranslationFilter, AuthorizationFilter. Then the request reaches the DispatcherServlet."
  chart={`flowchart TD
  R([Request]) --> D["DelegatingFilterProxy (servlet filter)"]
  D --> F["FilterChainProxy (Spring bean)"]
  F -- "first matching chain" --> C1[CsrfFilter]
  C1 --> C2["Login filters: form, Basic, bearer"]
  C2 --> C3[ExceptionTranslationFilter]
  C3 --> C4[AuthorizationFilter]
  C4 --> S([DispatcherServlet])`}
/>

- Several chains are allowed; only the first match runs, so keep the catch-all chain last.
- Add your own filter with `addFilterBefore`, `addFilterAfter` or `addFilterAt`.

## Example

```java
@Bean
SecurityFilterChain api(HttpSecurity http) throws Exception {
    http.authorizeHttpRequests(auth -> auth
            .requestMatchers("/public/**").permitAll()
            .anyRequest().authenticated())
        .httpBasic(Customizer.withDefaults());
    return http.build();
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| User | `user`, random password logged at WARN | Spring Boot 4.1 |
| Default chain | Whole app needs login; form login or HTTP Basic | Spring Boot 4.1 |
| Your own `SecurityFilterChain` | Replaces the rules; the default user stays | Spring Boot 4.1 |

## Interview Qs

### What happens when you add spring-boot-starter-security?

The whole app, Actuator included, needs login. Boot creates the user `user` with a random password printed in the log, and uses form login or HTTP Basic depending on the request.

### DelegatingFilterProxy vs FilterChainProxy?

DelegatingFilterProxy is a plain servlet filter registered with the container; it looks up a Spring bean lazily. That bean is FilterChainProxy, which picks the first matching SecurityFilterChain and runs its filters.

### How do you configure security without WebSecurityConfigurerAdapter?

Declare a `SecurityFilterChain` bean that configures `HttpSecurity` with lambdas and returns `http.build()`. The adapter was deprecated in 5.7 and removed in 6.0.
