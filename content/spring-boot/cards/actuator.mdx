## Why it exists

Operators and platforms need to ask a running app: are you healthy, what are your numbers, what is your configuration? Actuator answers over HTTP or JMX, with no custom code.

## How it works

<Mermaid
  alt="Health aggregation. The db, diskspace and ping health indicators each report a status. Actuator combines them. If all are UP, /actuator/health returns UP with HTTP 200. If any is DOWN, it returns DOWN with HTTP 503."
  chart={`flowchart LR
  DB[db indicator] --> A{Combine statuses}
  DS[diskspace indicator] --> A
  P[ping indicator] --> A
  A -- "all UP" --> U["UP: HTTP 200"]
  A -- "any DOWN" --> D["DOWN: HTTP 503"]`}
/>

- An endpoint must be accessible and **exposed** to be reachable. `exclude` wins over `include`, and `*` exposes everything.
- With Spring Security present and no `SecurityFilterChain` of your own, Boot secures every endpoint except health.
- Liveness and readiness are health groups; add checks to readiness with `management.endpoint.health.group.readiness.include`.

## Example

```properties
management.endpoints.web.exposure.include=health,info,prometheus
management.endpoint.health.show-details=when-authorized
# Actuator on its own port, not open to the internet
management.server.port=8081
```

```bash
$ curl localhost:8081/actuator/health/readiness
{"status":"UP"}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Exposed over HTTP and JMX | `health` only | Spring Boot 4.1 |
| Base path | `/actuator` | Spring Boot 4.1 |
| `management.endpoint.health.show-details` | `never` | Spring Boot 4.1 |
| Liveness and readiness probes | Enabled | Spring Boot 4.0+ |
| `heapdump` access | `none` | Spring Boot 3.5+ |
| `shutdown` endpoint | Disabled | Spring Boot 4.1 |
| `env` and `configprops` values | Masked as `******` | Spring Boot 4.1 |

## Interview Qs

### What is Spring Boot Actuator?

A module that adds production-ready endpoints to a running app: health, info, metrics, loggers, env, beans, mappings, thread and heap dumps. Add `spring-boot-starter-actuator` and expose the endpoints you need over HTTP or JMX.

### Which endpoints are exposed by default, and how do you expose more?

Only `health`, over both HTTP and JMX. Set `management.endpoints.web.exposure.include`, for example `health,info,prometheus`; `exclude` wins over `include`. Never expose `*` on a public app without securing it.

### Liveness vs readiness?

Liveness asks whether the app can still work; if it keeps failing, Kubernetes restarts the container. Readiness asks whether it can take traffic now; if it fails, the pod is taken out of the Service but not restarted.

### How do you secure Actuator endpoints?

Expose only what you need, serve them on a separate `management.server.port` that is not public, and add a `SecurityFilterChain` rule, such as `EndpointRequest.toAnyEndpoint()` with an admin role. Keep `env` and `heapdump` closed.
