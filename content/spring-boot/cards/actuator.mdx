## What it is

Spring Boot Actuator is a module that adds production endpoints to your app. An endpoint is a URL, such as `/actuator/health`, that returns facts about the running app: whether it is healthy, its metrics, its configuration, its log levels. You add one [starter](card:starters) and the endpoints appear, with no code of your own.

## Why it exists

Once the payment service runs on servers, other tools need to ask it questions. A load balancer asks "can you take requests?", Kubernetes asks "are you stuck?", and monitoring asks "how many requests per second?". Without Actuator you would write and secure these URLs yourself in every service. Actuator gives every Boot app the same, ready answers.

## How it works

1. At startup, Boot creates a health indicator for each thing it can check, such as `db` when a `DataSource` exists.
2. A tool calls `/actuator/health`. Actuator asks every indicator for its status.
3. It combines them: one `DOWN` makes the whole result `DOWN`.
4. It maps the status to an HTTP code: `UP` gives 200, `DOWN` gives 503. A load balancer or Kubernetes reads only that code.

Kubernetes calls two more URLs as probes: `/actuator/health/liveness` to decide whether to restart the app, and `/actuator/health/readiness` to decide whether to send it traffic. They work the same way, but each has its own small set of checks.

## Example

This custom check tells Actuator whether the payment service can reach its fraud-check API.

```java
@Component
class FraudCheckHealthIndicator implements HealthIndicator {
    private final FraudCheckClient fraud;

    FraudCheckHealthIndicator(FraudCheckClient fraud) { this.fraud = fraud; }

    @Override
    public Health health() {
        return fraud.ping()
                ? Health.up().build()
                : Health.down().withDetail("fraudApi", "not reachable").build();
    }
}
```

What to notice:

- The entry is named after the bean without the `HealthIndicator` suffix, so it shows as `fraudCheck`.
- When it returns `down()`, the whole `/actuator/health` turns `DOWN` and returns 503.
- It is not part of the liveness or readiness group unless you add it, for example with `management.endpoint.health.group.readiness.include=readinessState,fraudCheck`.

## Rules and defaults

- **Exposure:** only `health` is exposed over HTTP and over JMX, Java's built-in management interface. Add more with `management.endpoints.web.exposure.include=health,info,prometheus`; `exclude` wins over `include`.
- **Security:** with Spring Security and no `SecurityFilterChain` of your own, Boot secures every actuator endpoint except health. With your own chain, the rules are yours to write.
- **Details:** `management.endpoint.health.show-details` is `never` by default; `when-authorized` shows them to authorised users, `always` to everyone.
- **Probe timing:** liveness turns `CORRECT` once the context is refreshed; readiness turns `ACCEPTING_TRAFFIC` only after the [runners](card:application-startup) have run. During graceful shutdown, readiness switches to `REFUSING_TRAFFIC`.
- **Probe groups:** Spring Boot adds no other checks, such as `db`, to liveness or readiness. You add them deliberately.
- **Shutdown endpoint:** off by default. Access to `shutdown` and `heapdump` is restricted unless you open it.

## Not to be confused with

**Exposing** an endpoint makes it reachable over HTTP or JMX. **Securing** it decides who may call it. Rule: exposure = is the URL there at all; security = who gets in. An exposed but unsecured `env` endpoint is open to anyone.

## Interview Qs

### Which endpoints are exposed by default, and how do you expose more?

Only `health`, over both HTTP and JMX. List others in `management.endpoints.web.exposure.include`; anything in `exclude` stays hidden even if included. Never expose `*` on a public app without security, because `env`, `beans` and `heapdump` reveal internals.

### Liveness vs readiness?

Liveness asks "is the app broken beyond repair?"; if it keeps failing, Kubernetes restarts the container. Readiness asks "can it take requests right now?"; if not, Kubernetes stops sending traffic but does not restart it. Readiness is down during startup and graceful shutdown.

### How do you write a custom health check?

Create a bean that implements `HealthIndicator` and return `Health.up()` or `Health.down()` with optional details. Actuator adds it to `/actuator/health` under the bean name without the `HealthIndicator` suffix. Add it to a probe group only if failing it should change that probe.

### How do you secure Actuator?

Expose only the endpoints you need, then add a `SecurityFilterChain` rule for `EndpointRequest.toAnyEndpoint()` that requires an admin role. Keep `env` and `heapdump` closed, or on a separate management port that only the internal network can reach.
