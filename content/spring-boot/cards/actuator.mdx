## Why it exists

Load balancers, Kubernetes and monitoring tools need to ask a running app: are you healthy, and what are your numbers? Actuator answers over HTTP or JMX with no custom code.

## How it works

<Mermaid
  alt="Health aggregation. The db, diskspace and ping health indicators each report a status. Actuator combines them. If all are UP, /actuator/health returns UP with HTTP 200. If any is DOWN, it returns DOWN with HTTP 503."
  chart={`flowchart LR
  DB[db indicator] --> A{Combine}
  DS[diskspace indicator] --> A
  P[ping indicator] --> A
  A -- "all UP" --> U["UP: HTTP 200"]
  A -- "any DOWN" --> D["DOWN: HTTP 503"]`}
/>

- An endpoint must be exposed to be reachable; `exclude` wins over `include`.
- With Spring Security and no chain of your own, Boot secures every endpoint except health.

## Example

```properties
management.endpoints.web.exposure.include=health,info,prometheus
management.endpoint.health.show-details=when-authorized
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Exposed over HTTP and JMX | `health` only | Spring Boot 4.1 |
| `management.endpoint.health.show-details` | `never` | Spring Boot 4.1 |
| `shutdown` endpoint | Disabled | Spring Boot 4.1 |
| Liveness and readiness groups | Enabled | Spring Boot 4.0+ |

## Interview Qs

### Which endpoints are exposed by default, and how do you expose more?

Only `health`. List others in `management.endpoints.web.exposure.include`; `exclude` wins over `include`. Do not expose `*` on a public app without security.

### Liveness vs readiness?

Liveness: can the app still work? If it keeps failing, Kubernetes restarts it. Readiness: can it take traffic now? If not, Kubernetes stops sending requests but does not restart it.

### How do you secure Actuator?

Expose only what you need, add a `SecurityFilterChain` rule for `EndpointRequest.toAnyEndpoint()` with an admin role, and keep `env` and `heapdump` closed.
