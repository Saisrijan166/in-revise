## Why it exists

A direct call makes a service wait for, and fail with, the service it calls. Events through Kafka decouple them: the producer does not wait.

## How it works

- Spring commits offsets after processing, so a crash can redeliver records.

## Example

```java
@KafkaListener(topics = "orders", groupId = "billing")
public void onOrder(OrderPlaced event) {
    billing.chargeOnce(event);   // idempotent: safe if redelivered
}

@Bean
DefaultErrorHandler errorHandler(KafkaTemplate<?, ?> template) {
    var toDlt = new DeadLetterPublishingRecoverer(template);   // orders-dlt
    return new DefaultErrorHandler(toDlt, new FixedBackOff(1000L, 2));
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Offset commit | AckMode `BATCH`, after a poll's records are processed | Spring Kafka 4.1 |
| Error handler | 10 attempts, no delay, then the record is logged | Spring Kafka 4.1 |
| Dead-letter topic | `<topic>-dlt`, same partition | Spring Kafka 4.1 |
| Delivery | At least once | Apache Kafka 4.2 |

## Interview Qs

### What is a consumer group?

Consumers sharing a group id split a topic's partitions, one consumer per partition. Every group gets all messages; consumers beyond the partition count sit idle.

### How do you keep messages in order?

Kafka keeps order only within a partition. Give related events the same key, such as the order id, so they land in one partition.

### What happens when a listener keeps failing on a record?

DefaultErrorHandler retries it, then logs it. With a DeadLetterPublishingRecoverer it goes to `<topic>-dlt`, so the partition moves on and the record is kept.
