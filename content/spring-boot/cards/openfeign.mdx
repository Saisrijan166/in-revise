## Why it exists

Calling another service with a hand-built HTTP request repeats URLs, encoding and error handling in every call. Feign lets you declare the remote API once, as a Java interface.

## How it works

<Mermaid
  alt="OpenFeign flow. OrderService calls client.getOrder(42) on the OrdersClient interface. A generated Feign proxy turns it into an HTTP request. Spring Cloud LoadBalancer resolves the service id orders to an instance, which receives GET /orders/42."
  chart={`flowchart LR
  S[OrderService] -- "client.getOrder(42)" --> P[Feign proxy for OrdersClient]
  P -- "service id: orders" --> LB[Spring Cloud LoadBalancer]
  LB -- "GET /orders/42" --> I[orders instance]`}
/>

- Settings per client live under `spring.cloud.openfeign.client.config.<name>`; use `default` for all clients.
- Fallbacks: `fallback` (a bean implementing the interface) or `fallbackFactory` (to see the cause), once circuit breaking is on.
- The OpenFeign docs call the project feature-complete and suggest Spring HTTP Service Clients ([compare](compare:openfeign-vs-http-service-clients)).

## Example

Add `spring-cloud-starter-openfeign` and put `@EnableFeignClients` on the main class:

```java
@FeignClient(name = "orders", fallback = OrdersFallback.class)
public interface OrdersClient {
    @GetMapping("/orders/{id}")
    Order getOrder(@PathVariable Long id);
}

@Component
class OrdersFallback implements OrdersClient {
    @Override
    public Order getOrder(Long id) {
        return Order.unknown(id);   // the call failed or the circuit is open
    }
}
```

Tune one client and switch on circuit breaking:

```properties
spring.cloud.openfeign.client.config.orders.connect-timeout=2000
spring.cloud.openfeign.client.config.orders.read-timeout=5000
spring.cloud.openfeign.circuitbreaker.enabled=true
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Connect / read timeout | 10 s / 60 s (Feign `Request.Options`) | When nothing is configured |
| Retries | None (`Retryer.NEVER_RETRY`) | Spring Cloud OpenFeign 5.0 |
| Logger level | `NONE` | Spring Cloud OpenFeign 5.0 |
| Circuit breaker | Off | Spring Cloud OpenFeign 5.0 |

## Interview Qs

### What is Feign, and how is it different from RestClient?

Feign is declarative: you write an interface and Spring Cloud generates the client. With RestClient you build each request in code. Spring's HTTP Service Clients bring the same interface style to RestClient itself.

### How does a Feign client find the service?

The @FeignClient name is a service id. When no url is set, Spring Cloud LoadBalancer resolves it to an instance from discovery, such as Eureka, round robin by default.

### How do you add a fallback to a Feign client?

Set spring.cloud.openfeign.circuitbreaker.enabled=true with a Spring Cloud CircuitBreaker implementation such as Resilience4j. Then point fallback to a bean that implements the interface, or fallbackFactory to also get the exception.

### Should a new project use OpenFeign?

Its docs call it feature-complete and suggest Spring HTTP Service Clients (@HttpExchange), which support blocking and reactive stacks and, since Spring Cloud 2025.1, load balancing. Keeping Feign where it already works is fine.
