## Why it exists

Apps often have several beans of one type, such as two payment gateways. Matching by type alone cannot pick one, so Spring needs a rule, or it refuses to guess.

## How it works

<Mermaid
  alt="Choosing a bean for one injection point. If exactly one bean matches the type, it is injected. If several match, a @Qualifier at the injection point first keeps only the beans with that qualifier or name. Then, if exactly one is @Primary, it is injected. Else, if a bean is named like the parameter, it is injected. Otherwise startup fails with NoUniqueBeanDefinitionException."
  chart={`flowchart TD
  T([Inject PaymentGateway]) --> N{How many beans match?}
  N -- one --> OK([Inject it])
  N -- several --> Q["@Qualifier? keep only those"]
  Q --> P{"Exactly one @Primary?"}
  P -- yes --> OK
  P -- no --> NM{"A bean named like the parameter?"}
  NM -- yes --> OK
  NM -- no --> X[NoUniqueBeanDefinitionException]`}
/>

- The bean name is also its default qualifier, so `@Qualifier("cardGateway")` finds the bean named `cardGateway`.
- A qualifier is a filter, not a unique id: several beans may share one.

## Example

```java
@Service @Primary
class UpiGateway implements PaymentGateway { }

@Service                               // bean name: cardGateway
class CardGateway implements PaymentGateway { }

@Service
class CheckoutService {
    CheckoutService(PaymentGateway usual,                            // UpiGateway
                    @Qualifier("cardGateway") PaymentGateway card,   // exact choice
                    List<PaymentGateway> all) { }                    // both
}
```

## Interview Qs

### Two beans implement the same interface. What happens?

Injecting the interface fails at startup with NoUniqueBeanDefinitionException. Mark the usual bean @Primary, or use @Qualifier at the injection point to name the one you want.

### If @Primary already picks a bean, why do we need @Qualifier?

@Primary sets one default for every injection point. @Qualifier lets one class ask for a different bean. When both apply, @Qualifier wins, because it filters the candidates first.

### How do you inject all implementations of an interface?

Inject `List<PaymentGateway>`, sorted by `@Order` if set, or `Map<String, PaymentGateway>` keyed by bean name. This is a common way to build a strategy lookup.
