## What it is

`@RestController` marks a class whose methods answer HTTP requests with data, not with web pages. It is a [stereotype](card:component-scanning), so component scanning finds it and makes it a bean, the way it finds `@Service`. It combines two annotations: `@Controller`, which marks a web controller, and `@ResponseBody`, which says "write the return value into the response body". In the [request flow](card:dispatcher-servlet), that value goes to a message converter, which turns it into JSON.

## Why it exists

Some apps build HTML pages on the server; most backends today send data to mobile apps, browsers and other services. Spring MVC serves both with one controller model. The only question is what a return value means: the name of a page to render, or the data itself. Writing `@ResponseBody` on every method of an API would be noise, so `@RestController` sets it once for the whole class.

## How it works

<Compare id="controller-vs-restcontroller" />

1. Component scanning finds the class, and the HandlerMapping records each mapped method in it.
2. A request arrives and the matching method runs and returns a value, for example a `PaymentResponse`.
3. Because of `@ResponseBody`, Spring does not look for a view. It picks a message converter that can write this type in a format the client accepts, usually JSON.
4. The converter (Jackson) writes the object's fields as JSON into the body. The status is 200 unless you set another one.

So the annotation decides one thing: whether a return value is a view name or the body itself.

## Example

The `PaymentController` from the request flow, now with a read endpoint and a create endpoint that answers 201:

```java
@RestController                                    // @Controller + @ResponseBody
@RequestMapping("/payments")
class PaymentController {
    private final PaymentService service;
    PaymentController(PaymentService service) { this.service = service; }
    @GetMapping("/{id}")
    PaymentResponse get(@PathVariable long id) {
        return service.find(id);                   // 200 OK, body = JSON
    }
    @PostMapping
    ResponseEntity<PaymentResponse> create(@RequestBody PaymentRequest request) {
        PaymentResponse saved = service.create(request);
        return ResponseEntity.created(URI.create("/payments/" + saved.id())).body(saved);
    }
}
```

What to notice:

- `get` returns a plain object. Spring writes it as JSON with status 200 and no extra code.
- `create` returns a `ResponseEntity`. `created(uri)` sets status 201 and the `Location` header, which tells the client the URL of the new payment.
- Change `@RestController` to `@Controller` and `get` breaks: Spring would look for a view to render instead of writing the object to the body.

## Rules and defaults

- **Default status:** a method that returns normally answers 200 OK. Use `@ResponseStatus(HttpStatus.CREATED)` for one fixed status, or `ResponseEntity` when it varies.
- **JSON:** Spring Boot 4.0 and later use Jackson 3, whose classes live in `tools.jackson` packages. The Jackson annotations such as `@JsonProperty` keep their old package.
- **What to return:** return a [DTO](card:dto) such as `PaymentResponse`, not the database entity. You will see why in the next concepts.

## Common mistakes

- **"The controller should hold the business rules."** Keep the controller thin: it reads the request and shapes the response. Rules such as "a payment above the limit needs a fraud check" belong in `PaymentService`, where other callers and tests can reuse them.

## Interview Qs

### If @RestController exists, why do we still need @Controller?

For server-rendered pages. A @Controller method returns a view name, and a template engine such as Thymeleaf renders the HTML. A @RestController always writes data to the body. Use the one that matches what the client expects.

### When do you return ResponseEntity instead of the object itself?

When the status or headers depend on the outcome: 201 with a Location header after a create, 404 when nothing was found, or a custom header. For one fixed status, @ResponseStatus on the method is enough.

### How does a Java object become JSON in the response?

The return value goes to an HttpMessageConverter chosen for the return type and the format the client accepts. For JSON, Spring Boot uses Jackson, which reads the object's properties, or a record's components, and writes them as JSON fields.
