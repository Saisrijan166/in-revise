## Why it exists

Some apps render HTML on the server; most APIs send data to apps and other services. One controller model serves both; the annotation decides if a return value is a page name or data.

## How it works

<Compare id="controller-vs-restcontroller" />

- `ResponseEntity` sets the status and headers per call; `@ResponseStatus(HttpStatus.CREATED)` sets one fixed status.
- Return a [DTO](card:dto), not the database entity.

## Example

```java
@RestController
@RequestMapping("/payments")
class PaymentController {
    private final PaymentService service;
    PaymentController(PaymentService service) { this.service = service; }

    @GetMapping("/{id}")
    PaymentResponse get(@PathVariable long id) { return service.find(id); }   // 200 + JSON

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)                                       // 201
    PaymentResponse create(@RequestBody CreatePayment request) { return service.create(request); }
}
```

## Interview Qs

### If @RestController exists, why do we still need @Controller?

For server-rendered pages. A @Controller method returns a view name that a template engine renders as HTML; @RestController always writes data to the body. Use the one that matches the response style.

### When do you return ResponseEntity?

When the status or headers depend on the outcome: 201 with a Location header after a create, or 404 when nothing is found. For one fixed status, @ResponseStatus on the method is enough.

### How does an object become JSON?

The method's return value goes to an HttpMessageConverter chosen for the requested media type. For JSON, Spring Boot uses Jackson, which reads the object's properties and writes them out.
