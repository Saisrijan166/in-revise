## Why it exists

The container must know which objects to manage. For your own classes an annotation is enough; for a library class you cannot edit, you write a method that builds it.

## How it works

<Compare id="component-vs-bean-annotation" />

- `@Repository` adds persistence exception translation; `@Service` is treated exactly like `@Component`.
- `@Configuration` classes are subclassed with CGLIB, so a call to a `@Bean` method returns the shared bean. With `proxyBeanMethods = false` (lite mode) there is no subclass: pass beans in as method parameters.
- Spring Framework 7 adds `BeanRegistrar`, to register beans in code with `if` or `for` logic.

## Example

```java
@Configuration
public class TimeConfig {

    @Bean                                   // a JDK class: you cannot annotate it
    Clock clock() {
        return Clock.system(ZoneId.of("Asia/Kolkata"));
    }
}

@Service                                    // your class: scanned, Spring calls the constructor
public class InvoiceService {
    private final Clock clock;

    InvoiceService(Clock clock) { this.clock = clock; }
}
```

## Interview Qs

### @Component vs @Bean?

@Component goes on a class and is found by component scanning; Spring calls the constructor. @Bean goes on a method in a configuration class; your code builds the object. Use @Bean for library classes or when creation needs logic.

### @Component, @Service, @Repository, @Controller: what is the difference?

All four register a bean through scanning. @Service only names the layer. @Repository adds translation of persistence exceptions into Spring's DataAccessException. @Controller marks a Spring MVC controller.

### What does proxyBeanMethods = false change?

Spring no longer subclasses the @Configuration class, so a direct call to another @Bean method creates a new object instead of returning the bean. It saves runtime overhead; take collaborators as @Bean method parameters instead.

### What is the default bean name?

For a scanned class, the simple class name with a lowercase first letter, like `invoiceService`. For a @Bean method, the method name. Both can be set explicitly, for example `@Service("billing")`.
