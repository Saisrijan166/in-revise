## Why it exists

Without one central place, every controller repeats try/catch blocks and each endpoint returns a different error shape. One advice class gives every error the right status and the same body.

## How it works

<Mermaid
  alt="Where an exception goes. It is thrown in a service and passes up through the controller. Spring first looks for an @ExceptionHandler in that controller, then in a @RestControllerAdvice. A handler returns a ProblemDetail with a status. If nothing handles it, Boot's /error endpoint returns a generic JSON error."
  chart={`flowchart TD
  E([Exception thrown in service]) --> L{"@ExceptionHandler in that controller?"}
  L -- no --> G{"@ExceptionHandler in @RestControllerAdvice?"}
  L -- yes --> P["ProblemDetail + status"]
  G -- yes --> P
  G -- no --> X["Boot /error: generic JSON"]`}
/>

- Handlers in the controller run before global ones in an advice.

## Example

```java
@RestControllerAdvice
class ApiErrors {
    @ExceptionHandler(PaymentNotFoundException.class)
    ProblemDetail notFound(PaymentNotFoundException ex) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
        pd.setTitle("Payment not found");
        return pd;                        // application/problem+json, status 404
    }
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| ProblemDetail for built-in MVC errors | Off (`spring.mvc.problemdetails.enabled=false`) | Spring Boot 4.1 |
| Fallback for unhandled errors | `/error` (`spring.web.error.path`) | Spring Boot 4.1 |
| Message and stack trace in `/error` | `never` (`spring.web.error.include-message`, `include-stacktrace`) | Spring Boot 4.1 |

## Interview Qs

### How do you handle exceptions globally in Spring Boot?

Create a @RestControllerAdvice class with @ExceptionHandler methods, one per exception type, each returning a ProblemDetail or ResponseEntity with the right status. It applies to all controllers.

### If @ExceptionHandler handles exceptions, why do we need @ControllerAdvice?

@ExceptionHandler is the handling mechanism, but in a controller it covers only that controller. @ControllerAdvice is the global place, so one set of handlers serves every controller.

### What is ProblemDetail?

Spring's class for RFC 9457 problem details: a standard JSON error body with type, title, status, detail and instance, sent as application/problem+json.
