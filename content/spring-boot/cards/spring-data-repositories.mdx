## Why it exists

Every entity needs the same data-access code: save, find by id, page through, query by a few fields. Spring Data JPA lets you declare an interface instead, and generates that code.

- Boot finds repository interfaces under the main class's package and creates one bean each; CRUD calls go to [SimpleJpaRepository](card:simple-jpa-repository).
- A query method uses a declared query (`@Query`, then a named query) if there is one; otherwise the query is derived from its name.
- Return a [projection](card:projections), an interface or a record, to load only some fields.

## Example

```java
public interface BookRepository extends JpaRepository<Book, Long> {

    List<Book> findByAuthorAndPriceLessThan(String author, BigDecimal max);   // derived

    boolean existsByIsbn(String isbn);                                        // derived

    @Query("select b from Book b where b.price > :min")
    Page<Book> findExpensive(@Param("min") BigDecimal min, Pageable pageable); // JPQL

    List<BookTitle> findByAuthor(String author);   // projection: record BookTitle(String title)
}
```

Ask for the first 20 rows, sorted: `books.findExpensive(min, PageRequest.of(0, 20, Sort.by("title")))`.

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Query lookup | `CREATE_IF_NOT_FOUND`: declared query first, else derive from the name | Spring Data JPA 4.1 |
| CRUD read methods | Transactional, `readOnly = true` | `SimpleJpaRepository`, Spring Data JPA 4.1 |
| Your own query methods | No transaction settings | Spring Data JPA 4.1 |
| `@Modifying` query | Does not clear the persistence context (`clearAutomatically = false`) | Spring Data JPA 4.1 |

## Interview Qs

### CrudRepository vs JpaRepository?

CrudRepository has the basic CRUD methods and returns Iterable. JpaRepository extends the List versions of the CRUD and paging interfaces and adds JPA extras: flush, saveAndFlush, batch deletes, getReferenceById and query by example. In a JPA app you usually extend JpaRepository.

### findById vs getReferenceById?

findById queries the database and returns an Optional, empty when the row is missing. getReferenceById returns a reference that is usually not checked yet; a missing row throws EntityNotFoundException on first access. getOne and getById are its deprecated old names.

### How does Spring Data build a query from a method name?

It splits the name at By. Before it: the subject, such as find, exists, count, delete, First10 or Distinct. After it: properties joined by And or Or, with keywords like LessThan, Like, IgnoreCase, and OrderBy for sorting.

### Page or Slice?

Page knows the total, so Spring Data runs an extra count query, which can be costly on big tables. Slice reads one row more than the page size to learn whether a next page exists. Use Slice when the UI only needs "next".
