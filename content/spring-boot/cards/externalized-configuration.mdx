## Why it exists

One jar must run in dev, test and production with different URLs, ports and secrets. Values kept outside the code need no rebuild per environment and stay out of Git.

## How it works

| Rank (1 wins) | Source | Example |
| --- | --- | --- |
| 1 | [Command-line arguments](card:command-line-args) | `--server.port=9000` |
| 2 | [Java system properties](card:java-system-properties) | `-Dserver.port=9000` |
| 3 | [OS environment variables](card:os-environment-variables) | `SERVER_PORT=9000` |
| 4 | [Config files](card:config-data-files) | `application.properties` or `application.yml` |

- Short list: the full one has 15 sources; test properties even beat the command line.
- Env var form: dots become `_`, dashes are dropped, all upper case.
- The two file formats hold the same keys: [properties vs YAML](compare:properties-vs-yaml).

## Example

```bash
java -jar app.jar                       # 8080 from application.properties
SERVER_PORT=9090 java -jar app.jar      # env var wins: 9090
java -jar app.jar --server.port=9000    # command line wins: 9000
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Config file name | `application` (change with `spring.config.name`) | Spring Boot 4.1 |
| Folders searched | `classpath:/`, `classpath:/config/`, `./`, `./config/`, `./config/*/`; later wins | Spring Boot 4.1 |

## Interview Qs

### Where can Spring Boot read configuration from?

Config files inside and outside the jar (plain and profile-specific), environment variables, Java system properties and command-line arguments, among others. All of them land in one `Environment`, and a higher source overrides a lower one.

### An env var and application.properties set the same key. Which wins?

The environment variable. From the top: command-line arguments, Java system properties, environment variables, then config files. Among files, outside the jar beats inside.

### How do you keep secrets out of the jar?

Reference them with a placeholder such as `${DB_PASSWORD}` and supply the value at deploy time as an env var or a mounted file (a configuration tree). Spring Boot has no built-in encryption; Spring Cloud Vault can store them.
