## Why it exists

Every Boot app needs the same three annotations on its main class. One meta-annotation replaces them and keeps every project set up the same way.

## How it works

<Mermaid
  alt="@SpringBootApplication is made of three annotations: @SpringBootConfiguration marks the app's configuration class, @EnableAutoConfiguration creates beans from the classpath, and @ComponentScan scans the main class's package and everything below it."
  chart={`flowchart TD
  A["@SpringBootApplication"] --> B["@SpringBootConfiguration: the app's config class"]
  A --> C["@EnableAutoConfiguration: beans from the classpath"]
  A --> D["@ComponentScan: this package and below"]`}
/>

```text
com.example.shop
 +- ShopApplication.java         @SpringBootApplication
 +- order/OrderService.java      found
 +- customer/CustomerApi.java    found
com.example.billing
 +- InvoiceService.java          NOT found: outside the tree
```

- Use only one `@SpringBootApplication` (or `@EnableAutoConfiguration`) per app, on the primary configuration class.
- `exclude` and `excludeName` switch off chosen [auto-configurations](card:excluding-auto-configuration).

## Example

```java
package com.example.shop;   // root package: scanning starts here

@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}
```

## Interview Qs

### What does @SpringBootApplication do internally?

It is a meta-annotation for `@SpringBootConfiguration` (a configuration class), `@EnableAutoConfiguration` (beans from the classpath) and `@ComponentScan` (components from this package down). You can declare the parts separately instead.

### A @Service is not found and injection fails. Why?

It is probably outside the main class's package tree, so component scanning never sees it. Move the main class to the root package, or add the other package with `scanBasePackages`.

### Where should the main class go?

In the root package, above all other classes, for example `com.example.shop`. Component, entity and repository scanning all start from that package. Avoid the default (unnamed) package: then every class in every jar is read.
