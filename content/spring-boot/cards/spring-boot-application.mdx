## What it is

`@SpringBootApplication` is the annotation you put on the class that holds `main()`. It is a shortcut for three annotations: `@SpringBootConfiguration`, `@EnableAutoConfiguration` and `@ComponentScan`. You already know the last two jobs: [component scanning](card:component-scanning) finds your own beans, and [auto-configuration](card:auto-configuration) adds Boot's beans. This annotation switches both on and marks the class as the app's configuration.

## Why it exists

Almost every Boot app needs the same three annotations on its main class. Writing them out each time is noise, and forgetting one breaks the app in a confusing way: without scanning, none of your services exist. One annotation gives every project the same, correct setup in one line, and it still lets you tune each part through its attributes.

## How it works

1. `main()` passes the annotated class to `SpringApplication.run`.
2. `@SpringBootConfiguration` makes that class a configuration class, so it may also hold your own `@Bean` methods.
3. `@ComponentScan` registers every `@Component`, `@Service`, `@Repository` and `@RestController` in the main class's package and its sub-packages.
4. `@EnableAutoConfiguration` then lets Boot add its own beans for the gaps your beans leave.

So the package of the main class matters: it is where every search starts.

## Example

The payment service keeps its main class in the root package, above `controller`, `service` and `repository`:

```java
package com.example.payment;   // root package: every search starts here

@SpringBootApplication
public class PaymentApplication {

    public static void main(String[] args) {
        SpringApplication.run(PaymentApplication.class, args);
    }

    @Bean
    Clock clock() { return Clock.systemUTC(); }
}
```

What to notice:

- Because the class sits in `com.example.payment`, `PaymentController` in `com.example.payment.controller` is found. A class in `com.example.audit` would not be.
- JPA also uses this package to look for `@Entity` classes, so the `Payment` entity must be under it too.
- The `clock()` method works here because `@SpringBootConfiguration` makes the main class a configuration class. `PaymentService` can now inject a `Clock`.

## Rules and defaults

- **Only one:** add a single `@SpringBootApplication` (or `@EnableAutoConfiguration`) per app.
- **Attributes:** `exclude` and `excludeName` (auto-configuration), `scanBasePackages` and `scanBasePackageClasses` (scanning), and `proxyBeanMethods`, which defaults to `true`.
- **Tests:** `@SpringBootTest` searches up the packages for the `@SpringBootConfiguration` class, so tests in the same package tree find the app without extra setup.
- **Parts are optional:** you can write the three annotations yourself, or leave out scanning and add your classes with `@Import`.
- **Default package:** never leave the main class without a `package` line; then every class in every jar is scanned.

## Not to be confused with

`@EnableAutoConfiguration` only turns on Boot's beans. `@SpringBootApplication` includes it, plus scanning and the configuration role. Rule: `@EnableAutoConfiguration` = one part; `@SpringBootApplication` = the usual set of three.

## Interview Qs

### What does @SpringBootApplication do?

It combines three annotations. `@SpringBootConfiguration` marks the class as the app's configuration, `@EnableAutoConfiguration` lets Boot add beans from the jars on the classpath, and `@ComponentScan` registers your components from the main class's package down.

### If @EnableAutoConfiguration does auto-configuration, why do we need @SpringBootApplication?

`@EnableAutoConfiguration` is only one part. A normal app also needs component scanning for its own classes and a configuration class that tests can find. `@SpringBootApplication` gives all three in one line, which is why every generated project uses it.

### Where should the main class go, and why?

In the root package, above all other classes, such as `com.example.payment`. Component scanning and JPA entity search both start from its package and go down, so a class outside that tree is not found.
