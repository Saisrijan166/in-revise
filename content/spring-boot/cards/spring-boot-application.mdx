## Why it exists

Every Boot app needs the same three annotations on its main class. One meta-annotation replaces them and keeps every project set up the same way.

## How it works

<Mermaid
  alt="@SpringBootApplication is made of three annotations: @SpringBootConfiguration marks the app's configuration class, @EnableAutoConfiguration turns on auto-configuration, and @ComponentScan scans the main class's package and everything below it."
  chart={`flowchart TD
  A["@SpringBootApplication"] --> B["@SpringBootConfiguration: config class"]
  A --> C["@EnableAutoConfiguration: auto-config on"]
  A --> D["@ComponentScan: this package and below"]`}
/>

- You may use the three parts separately; without scanning, add your classes with `@Import`.
- A bean outside the main package is missed: see [component scanning](card:component-scanning).

## Example

```java
package com.example.shop;    // root package: scanning starts here

@SpringBootApplication
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}
```

## Interview Qs

### What does @SpringBootApplication do?

It is a meta-annotation for `@SpringBootConfiguration` (a configuration class), `@EnableAutoConfiguration` (auto-configuration) and `@ComponentScan` (components from this package down).

### If @EnableAutoConfiguration does auto-configuration, why use @SpringBootApplication?

`@EnableAutoConfiguration` is one part only. `@SpringBootApplication` also marks the configuration class and turns on scanning, the usual set for a Boot app in one line.

### Where should the main class go?

In the root package, above all other classes, such as `com.example.shop`. Scanning starts from its package, so classes elsewhere are not found.
