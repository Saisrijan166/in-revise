## Why it exists

Every request needs the same steps: find the code, convert the input, call it, write the output, handle errors. Spring MVC does these once, in one servlet, so controllers hold only business logic.

## How it works

<Mermaid
  alt="Request flow in a Spring Boot web app. The client request passes the servlet filters, including security, and reaches DispatcherServlet. A HandlerMapping finds the controller method. A HandlerAdapter calls the controller, which calls the service, which calls the repository, which talks to the database. On the way back, an HttpMessageConverter writes the result as JSON."
  chart={`flowchart TD
  C([Client]) --> F["Filters (incl. security)"]
  F --> DS[DispatcherServlet]
  DS --> HM["HandlerMapping: which method?"]
  HM --> HA["HandlerAdapter: bind args, call"]
  HA --> CT[Controller]
  CT --> SV["Service (business logic)"]
  SV --> RP[Repository]
  RP --> DB[(Database)]
  CT -. "return value" .-> MC["HttpMessageConverter: JSON"]
  MC -.-> C`}
/>

- Keep each layer to one job: the controller handles HTTP, the service holds the rules, the repository talks to the database.
- Filters run before DispatcherServlet; interceptors run inside it ([Filters, Interceptors and AOP](card:filters-interceptors)).
- Cross-cutting work such as [transactions](card:transactional) wraps service methods through [AOP](card:spring-aop).

## Interview Qs

### What is the front controller pattern in Spring MVC?

One central servlet, DispatcherServlet, receives every request and runs the shared steps. Helper beans such as HandlerMapping, HandlerAdapter and the message converters do the actual work.

### Walk me through a request to a REST endpoint.

Filters run, then DispatcherServlet. A HandlerMapping finds the method, a HandlerAdapter binds the arguments and calls it. The controller calls the service and repository. A message converter writes the result as JSON.

### HandlerMapping vs HandlerAdapter?

HandlerMapping decides which handler serves the request. HandlerAdapter knows how to call that kind of handler, so DispatcherServlet does not depend on any handler type.
