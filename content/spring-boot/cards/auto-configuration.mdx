## Why it exists

Most apps need the same infrastructure beans, such as a DataSource or a JSON mapper. Auto-configuration creates them for you and steps aside when you define your own.

## How it works

<Mermaid
  alt="Auto-configuration flow. Your own beans are registered first. Boot then reads the auto-configuration classes listed in each jar. For each one it checks the conditions: is the class on the classpath, is there no bean of yours of that type, does the property allow it. If yes, Boot creates its bean; if no, it skips it."
  chart={`flowchart TD
  U[1. Your beans are registered] --> L[2. Boot reads the listed auto-configurations]
  L --> C{3. Class present? No bean of yours? Property allows it?}
  C -- yes --> NEW[Create Boot's bean]
  C -- no --> SKIP[Skip it: back off]`}
/>

- Example: HSQLDB on the classpath and no `DataSource` bean gives an in-memory database. Declare a `DataSource` and that support backs away.
- How Boot knows what to configure: jars on the classpath, your properties, and the beans you already have.

## Example

```java
@AutoConfiguration
@ConditionalOnClass(AcmeClient.class)    // only if the library is present
public class AcmeAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean            // back off if the app has one
    AcmeClient acmeClient() {
        return new AcmeClient();
    }
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `@ConditionalOnProperty` matches | the property exists and is not `false` | Spring Boot 4.1 |

## Interview Qs

### How does Spring Boot know what to configure?

It reads the auto-configuration classes listed in each jar. Each has conditions on the classpath, properties, web app type and existing beans. Only those whose conditions match add beans.

### How do you disable one auto-configuration?

Use `exclude` on `@SpringBootApplication`, `excludeName` when the class is not on the classpath, or the `spring.autoconfigure.exclude` property.

### Why was a bean (not) auto-configured?

Start the app with `--debug`. It logs the condition evaluation report: each auto-configuration with the conditions that matched or failed.
