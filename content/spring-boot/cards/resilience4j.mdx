## What it is

Resilience4j is a library of guards for calls to other services. The two most used are the **circuit breaker** and **retry**. A circuit breaker watches a call's failures and, when too many fail, stops making the call for a while and fails at once. A retry repeats a failed call a few times, because many faults last only a moment. When a guard gives up, a **fallback** method can return a safe answer instead. In Spring Boot you apply them with annotations, which work through [AOP proxies](card:aop-proxies).

## Why it exists

The payment service calls fraud-check over HTTP. If fraud-check hangs, every payment request waits for the timeout, holding a thread. Soon all threads are waiting and the payment service is down too, although its own code is fine: one sick service has spread its failure. A circuit breaker cuts the call off quickly. A retry hides short blips, such as one dropped connection, so users do not see an error for them.

1. **Closed:** every call goes through, and the breaker records whether it succeeded in a sliding window of recent calls.
2. When the failure rate in that window passes the threshold, the breaker moves to **Open**.
3. **Open:** calls are rejected at once with `CallNotPermittedException`, without touching the network, and the fallback answers if one is set.
4. After the wait time, it moves to **Half-open** and lets a few trial calls through.
5. If the failure rate of the trial calls is below the threshold, it closes again; otherwise it opens again.

## Example

The payment service guards its call to fraud-check. When fraud-check cannot answer, the payment is sent for manual review instead of failing.

```java
@CircuitBreaker(name = "fraudCheck")
@Retry(name = "fraudCheck", fallbackMethod = "reviewLater")
public FraudResult check(PaymentRequest request) {
    return http.post().uri("/checks").body(request).retrieve().body(FraudResult.class);
}

private FraudResult reviewLater(PaymentRequest request, Exception cause) {
    return FraudResult.manualReview();   // all attempts failed
}
```

What to notice:

- Both annotations use the name `fraudCheck`, so they read their settings from `resilience4j.circuitbreaker.instances.fraudCheck.*` and `resilience4j.retry.instances.fraudCheck.*`.
- The fallback has the same parameters plus one exception. It runs when all attempts have failed. While the circuit is open, each attempt fails fast, but Retry still waits between them unless you ignore `CallNotPermittedException` (see Common mistakes).
- The fallback is on `@Retry`, the outer guard. On `@CircuitBreaker` it would hide each failure from Retry.
- Calling `check` from another method of the same class skips the proxy, so neither guard runs.

## Rules and defaults

- **Setup:** add `resilience4j-spring-boot4` and `spring-boot-starter-aspectj`, because the annotations are applied by aspects.
- **Breaker defaults (Resilience4j 2.4):** opens at a 50% failure rate over the last 100 calls, stays open 60 s, then allows 10 trial calls.
- **Retry defaults (Resilience4j 2.4):** 3 attempts in total, including the first call, 500 ms apart.
- **Aspect order:** Retry ( CircuitBreaker ( RateLimiter ( TimeLimiter ( Bulkhead ( your method ) ) ) ) ).
- **Fallback matching:** if several fallbacks exist, the one whose exception type is closest to the thrown one is used.
- **Spring's own `@Retryable` (Framework 7.0):** 3 retries after the first call, 1 s apart; switch it on with `@EnableResilientMethods`. It has no circuit breaker.

## Common mistakes

- **"Retry every failure."** Retrying a non-idempotent call, such as charging a card, can charge twice. Retry only safe or [idempotent](card:rest-api-design) calls, or send an idempotency key.
- **Retrying while the circuit is open.** Each attempt fails fast anyway. Add `CallNotPermittedException` to the retry's `ignoreExceptions` to stop at once.

## Interview Qs

### Explain the circuit breaker states.

Closed: calls pass and outcomes are recorded. Open: once the failure rate passes the threshold, calls fail at once without reaching the service. Half-open: after a wait, a few trial calls decide whether the breaker closes again or opens again.

### How does fallbackMethod work?

It names a method in the same class with the same parameters plus one exception parameter. When the guarded call fails, or the circuit is open, Resilience4j calls it and returns its value. With several fallbacks, the best-matching exception type wins, so an open circuit can be handled apart from other errors.

### Why combine retry with a circuit breaker?

They handle different faults. Retry rides out short blips; the breaker stops calls during a real outage, so you do not pile retries onto a sick service. Retry is the outer guard, so once the breaker is open, each attempt fails fast.
