## What it is

A bean's scope decides how many objects the [container](card:ioc-container) makes from one bean definition, and how long each one lives. The default scope, singleton, means one shared object for the whole container: every class that injects `PaymentService` gets the same object. The prototype scope means a new object every time the bean is requested. Web apps also have scopes tied to one HTTP request or one user session.

## Why it exists

Most beans, like `PaymentService`, hold no data about one user or one call; they only have methods and other beans. One shared object is then cheapest and safe. A few objects do hold data for one use, such as a receipt being built for one payment. Sharing such an object would mix different users' data, so each use needs its own object.

## How it works

| Scope | One object per | Works in |
| --- | --- | --- |
| singleton (default) | container | any app |
| prototype | request for the bean | any app |
| request | HTTP request | web apps |
| session | HTTP session | web apps |
| application | `ServletContext` (the running web app) | web apps |
| websocket | WebSocket session | web apps |

1. You set the scope on the bean. No annotation means singleton; `@Scope("prototype")`, `@RequestScope` or `@SessionScope` choose another.
2. For a singleton, the container creates the object once, usually at startup, and hands the same object to everyone.
3. For a prototype, the container creates a new object each time the bean is injected or fetched with `getBean`, then keeps no record of it.
4. For request or session scope, the container keeps one object per HTTP request or per user session, and drops it when that request or session ends.

So a scope answers one question: who shares this object?

## Example

`PaymentService` keeps the default scope; `PaymentReceipt` is a prototype.

```java
@Component
class PaymentService { }                 // singleton: the default

@Component
@Scope("prototype")
class PaymentReceipt { }                 // a new object per request for the bean

public class Main {
    public static void main(String[] args) {
        var context = new AnnotationConfigApplicationContext(PaymentService.class, PaymentReceipt.class);
        System.out.println(context.getBean(PaymentService.class) == context.getBean(PaymentService.class));
        System.out.println(context.getBean(PaymentReceipt.class) == context.getBean(PaymentReceipt.class));
    }
}
```

```text output
true
false
```

What to notice:

- `true`: both calls returned the one shared `PaymentService`.
- `false`: each `getBean` call built a new `PaymentReceipt`.
- If `PaymentService` took a `PaymentReceipt` in its constructor, it would get one receipt, once, and keep it. To get a new receipt each time, inject `ObjectProvider<PaymentReceipt>` and call `getObject()` whenever you need one.

## Rules and defaults

- **Default:** singleton, one object per container and per bean definition (Spring Framework 7.0).
- **Thread safety:** Spring does not make a singleton thread-safe. Many requests call the same object at once, so keep it stateless, or protect any shared state yourself.
- **Prototype cleanup:** Spring does not run destroy callbacks, such as `@PreDestroy`, for prototype beans; the code that uses them must clean up.
- **Web scopes:** request, session, application and websocket need a web-aware `ApplicationContext`; in a Spring MVC app this works with no extra setup.
- **Rule of thumb from the Spring docs:** prototype for stateful beans, singleton for stateless beans.

## Not to be confused with

The Singleton design pattern (from the "Gang of Four" book) makes a class allow only one object per class loader, usually through a private constructor. A Spring singleton is an ordinary class: the container simply creates one object per bean definition, and your code could still call `new`. Rule: the pattern's class forbids a second object; Spring's container just does not make one.

## Interview Qs

### What is the default scope, and is it thread-safe?

Singleton: one object per container, shared by all threads. Spring does not make it thread-safe; that depends on your code. Keep singletons stateless, or guard shared state with thread-safe types or locks.

### A prototype bean is injected into a singleton. What happens?

The singleton gets one prototype object when the singleton is created and keeps it for its whole life, so the prototype behaves like a singleton there. To get a new object each time, inject `ObjectProvider<T>` and call `getObject()`.

### When would you use request or session scope?

For data that belongs to one HTTP request or one user session, such as the current request's trace details or a user's shopping cart. They work only in a web application context.
