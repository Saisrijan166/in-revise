## Why it exists

Most beans hold no per-user state, so one shared copy is cheapest. A few hold state for one caller, one HTTP request or one session, and need their own copy.

## How it works

| Scope | One instance per | Works in |
| --- | --- | --- |
| singleton (default) | container | any app |
| prototype | request for the bean | any app |
| request | HTTP request | web apps |
| session | HTTP session | web apps |
| application | `ServletContext` | web apps |
| websocket | WebSocket session | web apps |

- Set it with `@Scope("prototype")`, or `@RequestScope` and `@SessionScope` for web scopes.
- For a fresh prototype inside a singleton, inject `ObjectProvider<T>` and call `getObject()`.

## Interview Qs

### What is the default scope, and is it thread-safe?

Singleton: one instance per container, shared by all threads. Spring does not make it thread-safe; that depends on your code. Keep singletons stateless, or guard shared state.

### A prototype bean is injected into a singleton. What happens?

The singleton gets one prototype instance when it is created and keeps it forever. To get a new one each time, inject `ObjectProvider<T>` and call `getObject()`.

### When would you use request or session scope?

For data that belongs to one HTTP request or one user session, such as the current user's preferences. They work only in a web application context.
