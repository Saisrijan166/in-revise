## Why it exists

Most beans hold no per-user state, so one shared copy is cheapest. Some objects hold state for one caller, one HTTP request or one session, and need their own copy.

## How it works

| Scope | One instance per | How to set it |
| --- | --- | --- |
| singleton (default) | container, per bean definition | nothing |
| prototype | request for the bean | `@Scope("prototype")` |
| request | HTTP request | `@RequestScope` |
| session | HTTP session | `@SessionScope` |
| application | `ServletContext` | `@ApplicationScope` |
| websocket | WebSocket session | `@WebSocketScope` |

- Spring never calls destroy callbacks on prototypes; the code that asked for the bean must clean up.
- A singleton gets its dependencies once. To use a shorter-lived bean inside it, inject a [scoped proxy](card:scoped-proxy) (the `@RequestScope` default) or an `ObjectProvider`.

## Example

```java
@Component
@Scope("prototype")
public class ReportBuilder { /* holds state for one report */ }

@Service
public class ReportService {
    private final ObjectProvider<ReportBuilder> builders;

    ReportService(ObjectProvider<ReportBuilder> builders) { this.builders = builders; }

    Report monthly() {
        ReportBuilder b = builders.getObject();     // a new instance on every call
        return b.title("Monthly").build();
    }
}
```

## Interview Qs

### What is the default scope, and is it thread-safe?

Singleton: one instance per container, shared by every thread. Spring does not make it thread-safe for you, so keep singletons stateless, or protect state that changes with thread-safe types or locks.

### Singleton vs prototype?

Singleton: one shared instance, created at startup and destroyed on shutdown. Prototype: a new instance each time the bean is requested, and Spring never calls its destroy callbacks. Use prototype only for stateful objects.

### A prototype bean injected into a singleton: what happens?

The singleton gets one prototype instance when it is created and keeps it. To get a new one each time, inject `ObjectProvider<T>` and call `getObject()`, or declare a `@Lookup` method.

### How do you use a request-scoped bean inside a singleton?

Through a scoped proxy. `@RequestScope` creates one by default: the singleton holds the proxy, and each call goes to the bean of the current HTTP request.
