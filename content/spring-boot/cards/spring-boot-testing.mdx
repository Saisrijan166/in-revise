## Why it exists

Auto-configuring the whole app is often too much for one test. Spring Boot lets you start everything, only one layer (a slice), or no Spring at all.

## How it works

<Compare id="springboottest-vs-slices" />

- **Unit tests** need no Spring: create the class with `new` and pass in mocks. They run fastest.
- [@MockitoBean](card:mockito-bean) replaces a bean in the test context with a Mockito mock, reset after each test.
- Spring caches each test context by its configuration. A different mix of mocks, profiles or properties starts a new context.

## Example

```java
@WebMvcTest(OrderController.class)
class OrderControllerTests {

    @Autowired MockMvcTester mvc;
    @MockitoBean OrderService orders;   // the slice has no @Service beans

    @Test
    void returnsOrder() {
        when(orders.find(1L)).thenReturn(new Order(1L, "NEW"));
        assertThat(mvc.get().uri("/orders/1"))
            .hasStatusOk()
            .bodyJson().isLenientlyEqualTo("{\"status\":\"NEW\"}");
    }
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `@SpringBootTest` web environment | `MOCK`: no server starts | Spring Boot 4.1 |
| A `@Transactional` test | Rolled back after each test method | Spring Boot 4.1 |
| `@DataJpaTest`, `@JdbcTest` | Transactional, rolled back; JPA SQL is logged | Spring Boot 4.1 |
| Context cache size | 32 contexts; least recently used is closed | Spring Framework 7.0 |
| `@MockitoBean` reset | After each test method | Spring Framework 6.2+ |

## Interview Qs

### @SpringBootTest vs @WebMvcTest?

`@SpringBootTest` starts the full application context, for end-to-end tests. `@WebMvcTest` loads only the web layer: controllers, advice, filters and MockMvc. Services are not loaded, so you mock them with `@MockitoBean`.

### How do you keep a large test suite fast?

Prefer plain unit tests and slices. Let Spring reuse cached contexts: keep the same configuration, mocks and properties across test classes, avoid needless `@DirtiesContext`, and do not fork a new JVM for each test class.

### Is a RANDOM_PORT test rolled back by @Transactional?

No. The HTTP client and the server run in separate threads, so the server's transaction commits. Clean up the data yourself, or use the default MOCK environment, where the test's transaction is rolled back.

### @MockBean vs @MockitoBean?

`@MockBean` was Spring Boot's own annotation: deprecated in 3.4, removed in 4.0. Use Spring Framework's `@MockitoBean` and `@MockitoSpyBean` (since 6.2). They go on test-class fields, not in `@Configuration` classes.
