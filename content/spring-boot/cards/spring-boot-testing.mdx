## Why it exists

Starting the whole app for every test is slow. Spring Boot lets each test load only what it checks: nothing, one layer, or everything.

## How it works

<Compare id="unit-vs-slice-vs-springboottest" />

- A slice loads one layer's beans and a small set of auto-configuration.
- Only one slice annotation per test class; combining slices is not supported.
- Spring caches each test context; the same configuration reuses it.

## Example

```java
@WebMvcTest(OrderController.class)
class OrderControllerTests {
    @Autowired MockMvcTester mvc;
    @MockitoBean OrderService orders;   // not loaded by the slice

    @Test
    void returnsOrder() {
        when(orders.find(1L)).thenReturn(new Order(1L, "NEW"));
        assertThat(mvc.get().uri("/orders/1")).hasStatusOk();
    }
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `@SpringBootTest` web environment | `MOCK`: no server starts | Spring Boot 4.1 |
| `@DataJpaTest` | Transactional, rolled back; embedded DB if on the classpath | Spring Boot 4.1 |
| MockMvc in `@SpringBootTest` | Needs `@AutoConfigureMockMvc` | Spring Boot 4.0+ |

## Interview Qs

### If JUnit and Mockito can test a service, why use @SpringBootTest?

They test different things. A unit test checks one class in isolation and runs fast. `@SpringBootTest` checks that the real beans, configuration and database work together, so it is slower and used less.

### If @SpringBootTest loads everything, why use @WebMvcTest?

Loading everything is wasted time for a controller test. `@WebMvcTest` loads only the web layer, so it checks mappings, validation, JSON and status codes quickly.

### Is a RANDOM_PORT test rolled back by @Transactional?

No. The real server handles the request on another thread, in its own transaction, which commits. Clean up the data yourself.
