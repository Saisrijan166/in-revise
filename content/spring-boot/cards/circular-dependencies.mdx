## Why it exists

Two beans that need each other cannot both be built first. The loop usually means they share a job that belongs in a third class, so Spring Boot fails early.

## How it works

<Mermaid
  alt="Before: OrderService needs InvoiceService and InvoiceService needs OrderService, a cycle that fails at startup. After: the shared logic moves into a new TaxCalculator bean; both services use TaxCalculator, and neither needs the other."
  chart={`flowchart LR
  subgraph BAD [Cycle: fails at startup]
    A[OrderService] -- needs --> B[InvoiceService]
    B -- needs --> A
  end
  subgraph GOOD [Fixed: a third bean]
    A2[OrderService] --> T[TaxCalculator]
    B2[InvoiceService] --> T
  end`}
/>

- With [constructor injection](card:dependency-injection) neither bean can be created first, so even plain Spring fails.
- `@Lazy` hides the design problem; use it only as a stopgap.

## Example

```java
@Service
class OrderService {
    private final InvoiceService invoices;

    OrderService(@Lazy InvoiceService invoices) {   // a proxy, resolved on first call
        this.invoices = invoices;
    }
}
```

## Interview Qs

### How do you fix a circular dependency?

Best: redesign, moving the shared logic into a third bean. Quick fix: `@Lazy` on one dependency. Last resort: `spring.main.allow-circular-references=true`, which never fixes constructor cycles.

### Why does constructor injection expose cycles?

Spring cannot call either constructor without the other object, so startup fails with BeanCurrentlyInCreationException. That is useful: you see the design problem on day one.
