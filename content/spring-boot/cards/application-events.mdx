## Why it exists

After an order is paid, mail, stock and loyalty code must react. If the payment service calls them all, it depends on all of them. With events it only says "payment done".

## How it works

<Steps label="An event from publish to listener">
  <Step title="Publish">`PaymentService` calls `publisher.publishEvent(new PaymentCompleted(id))`.</Step>
  <Step title="Match">Spring finds every `@EventListener` method whose parameter type fits the event.</Step>
  <Step title="Run">By default each listener runs now, on the same thread, inside the publisher's transaction.</Step>
  <Step title="Return">`publishEvent` returns only after all listeners finish.</Step>
</Steps>

- An `@Async` listener's exception does not reach the publisher, and it cannot publish a new event by returning one.
- `@TransactionalEventListener` phases: `BEFORE_COMMIT`, `AFTER_COMMIT` (default), `AFTER_ROLLBACK`, `AFTER_COMPLETION`.
- `@Order` sets which listener runs first.

## Example

```java
public record PaymentCompleted(long orderId) {}

@Service
class PaymentService {
    private final ApplicationEventPublisher events;
    PaymentService(ApplicationEventPublisher events) { this.events = events; }
    @Transactional
    public void pay(long id) { /* save */ events.publishEvent(new PaymentCompleted(id)); }
}

@Component
class ReceiptMailer {
    @TransactionalEventListener   // only after the payment commits
    void on(PaymentCompleted e) { /* send the receipt */ }
}
```

## Interview Qs

### Are Spring events asynchronous?

No. By default `publishEvent` blocks until every listener has run, on the same thread. Add `@Async` (with `@EnableAsync`) to a listener to run it on another thread.

### Why use @TransactionalEventListener instead of @EventListener?

A plain listener runs before the commit, so it may email a receipt for a payment that later rolls back. `@TransactionalEventListener` waits for the commit by default, and does not run at all without a transaction.

### Spring events vs Kafka?

Spring events are delivered inside one running app, between its beans. Use a broker such as Kafka when other services must receive the message.
