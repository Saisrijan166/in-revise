## Why it exists

Logging, security checks, metrics and transactions are needed in many classes. Without AOP the same lines repeat in every method; an aspect writes them once.

## How it works

| Term | Question it answers | Example |
| --- | --- | --- |
| Aspect | Where does the shared logic live? | `TimingAspect` with `@Aspect` |
| Join point | Where could it run? | Any bean method call |
| Pointcut | Where should it run? | `execution(* com.shop.service..*.*(..))` |
| Advice | What runs, and when? | `@Before`, `@AfterReturning`, `@AfterThrowing`, `@After`, `@Around` |
| Weaving | How is it attached? | At runtime, through a [proxy](card:aop-proxies) |

- `@Around` is the most powerful advice; the docs advise using the least powerful one that does the job.
- Spring AOP is for method calls on beans; it is not a full AOP language like AspectJ.

## Example

```java
@Aspect
@Component
public class TimingAspect {
    @Around("execution(* com.shop.service..*.*(..))")   // pointcut
    public Object time(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.nanoTime();
        try { return pjp.proceed(); }                    // run the real method
        finally { System.out.println(pjp.getSignature() + " " + (System.nanoTime() - start)); }
    }
}
```

## Interview Qs

### What are aspect, advice, pointcut and join point?

An aspect is the class with the shared logic. A join point is a place it could run; in Spring AOP, a method execution. A pointcut selects join points. Advice is the code that runs there.

### What kinds of advice are there?

`@Before`, `@AfterReturning` (normal return), `@AfterThrowing` (exception), `@After` (always, like finally) and `@Around`, which wraps the call and decides whether to call `proceed()`.

### Spring AOP vs AspectJ?

Spring AOP weaves at runtime through proxies and advises only method executions on Spring beans. AspectJ weaves into the bytecode at compile or load time, so it can also advise more, such as field access.
