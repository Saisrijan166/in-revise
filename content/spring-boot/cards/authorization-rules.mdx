## Why it exists

Being logged in is not enough: an ordinary user must not reach admin pages or another user's data. Rules decide that per URL and, for finer checks, per method call.

## How it works

| | URL rules | Method rules |
| --- | --- | --- |
| Where | `authorizeHttpRequests` in the SecurityFilterChain | `@PreAuthorize` and friends on bean methods |
| Can check | Path, HTTP method, the user's authorities | Arguments, return value, any SpEL expression |
| Switched on | Whenever you write rules | `@EnableMethodSecurity` |
| On denial | Anonymous: asked to log in; logged in: 403 | AccessDeniedException, a 403 in a web request |

- `@EnableMethodSecurity` turns on `@PreAuthorize`, `@PostAuthorize`, `@PreFilter` and `@PostFilter`; `@Secured` and `@RolesAllowed` need extra flags.
- Method checks run in a [proxy](card:aop-proxies): a call from another method of the same class skips them.

## Example

```java
http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/admin/**").hasRole("ADMIN")              // needs ROLE_ADMIN
    .requestMatchers(HttpMethod.GET, "/products/**").permitAll()
    .anyRequest().authenticated());                             // catch-all, last
```

```java
@Configuration
@EnableMethodSecurity
class MethodSecurityConfig {}

@Service
public class AccountService {
    @PreAuthorize("hasAuthority('SCOPE_accounts.write')")
    public void close(long id) { /* ... */ }

    @PostAuthorize("returnObject.owner == authentication.name")
    public Account find(long id) { return accounts.findById(id).orElseThrow(); }
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Method security | Off until `@EnableMethodSecurity` | Spring Boot 4.1 |
| `@EnableMethodSecurity` turns on | Pre/post annotations; `@Secured` and JSR-250 stay off | Spring Security 7.1 |
| Role prefix | `ROLE_` (change it with a `GrantedAuthorityDefaults` bean) | Spring Security 7.1 |

## Interview Qs

### hasRole vs hasAuthority?

Both check the user's GrantedAuthorities. `hasRole("ADMIN")` adds the ROLE_ prefix and looks for ROLE_ADMIN; `hasAuthority("ADMIN")` looks for exactly ADMIN. Use hasAuthority for fine permissions and JWT scopes such as SCOPE_read.

### @PreAuthorize vs @Secured?

@Secured only lists role names and needs `securedEnabled = true`; Spring calls it legacy. @PreAuthorize is on with @EnableMethodSecurity and takes SpEL, so it can check arguments, the current user and custom beans.

### Does the order of requestMatchers matter?

Yes. AuthorizationFilter applies only the first rule that matches, so put specific paths before broad ones and end with `anyRequest()`, usually `authenticated()` or, for an allow-list, `denyAll()`.

### URL security or method security?

Both. URL rules are a coarse first gate in the filter chain. Method rules guard the service layer, whichever controller calls it, and can check data, such as whether the returned object belongs to the current user.
