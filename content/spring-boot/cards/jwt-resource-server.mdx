## Why it exists

APIs called by mobile apps, single-page apps or other services cannot rely on a browser session. Each request carries an access token instead, and the API must check it quickly, without calling the issuer every time.

## How it works

<Mermaid
  alt="JWT resource server flow. 1: the client logs in at the authorization server. 2: the authorization server returns a signed JWT. 3: the client calls your API with the header Authorization: Bearer and the JWT. 4: your API gets the issuer's public keys from its JWK Set. Then it checks the signature, exp, nbf and iss. If the checks pass, the controller runs with SCOPE_ authorities. If not, the API answers 401 with a WWW-Authenticate Bearer header."
  chart={`flowchart LR
  C([Client]) -- "1. log in" --> AS[Authorization server]
  AS -- "2. signed JWT" --> C
  C -- "3. Authorization: Bearer JWT" --> RS["Your API (resource server)"]
  RS -.->|"4. public keys (JWK Set)"| AS
  RS --> V{"signature, exp, nbf, iss OK?"}
  V -- yes --> RUN([Controller runs])
  V -- no --> DENY(["401 + WWW-Authenticate"])`}
/>

- **Lazy discovery:** the first request with a JWT triggers it, so the API starts even when the issuer is down.
- Set `audiences` so a token issued for another API is rejected.

## Example

```properties
spring.security.oauth2.resourceserver.jwt.issuer-uri=https://idp.example.com/realms/shop
spring.security.oauth2.resourceserver.jwt.audiences=orders-api
```

```java
@Bean
SecurityFilterChain api(HttpSecurity http) {
    http.authorizeHttpRequests(auth -> auth
            .requestMatchers(HttpMethod.GET, "/orders/**").hasAuthority("SCOPE_orders.read")
            .anyRequest().authenticated())
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()));
    return http.build();
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Trusted signing algorithm | RS256 only (`jws-algorithms`) | Spring Security 7.1, Spring Boot 4.1 |
| Clock skew for exp and nbf | 60 seconds | Spring Security 7.1 |
| Claims checked | iss, exp, nbf; aud only when `audiences` is set | Spring Security 7.1 |
| Authority prefix for scopes | `SCOPE_` | Spring Security 7.1 |
| Chain if you define none | Every request needs a valid JWT | Spring Boot 4.1 |

## Interview Qs

### What is a JWT?

A compact, URL-safe token of claims. A signed JWT has a header, a payload and a signature, each Base64url-encoded and joined by dots. The signature proves who issued it and that nobody changed it; the payload is readable by anyone.

### How does Spring validate a JWT?

From `issuer-uri` it discovers the issuer's JWK Set. On each request it checks the signature with the matching public key, then exp and nbf (60 seconds of skew) and iss, plus aud if configured. Scopes become SCOPE_ authorities.

### Session or JWT for a REST API?

A session is simple and ends at once on logout, but the server must keep it. A JWT lets any instance check a request with no shared state, but a stolen token works until it expires, so keep tokens short-lived.

### How do you log a user out when you use JWTs?

There is no server session to end. Keep access tokens short-lived and revoke the refresh token at the authorization server. To cut access at once, keep a denylist of token ids (`jti`) and check it on each request.
