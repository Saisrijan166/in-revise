## Why it exists

Libraries log through different APIs, and each environment wants different detail and output. Spring Boot routes them all to one backend with sensible defaults, so logging is set with properties instead of a long XML file.

## How it works

<Mermaid
  alt="Logging flow. Your code calls the SLF4J API. Spring calls Commons Logging. Libraries that use Java Util Logging or the Log4j API are routed through bridges. All of them reach Logback, which writes INFO and above to the console, and also to a rolling file when logging.file.name is set."
  chart={`flowchart LR
  A["Your code: SLF4J Logger"] --> L["Logback"]
  B["Spring: Commons Logging"] --> L
  C["Libraries: JUL, Log4j API"] -- bridges --> L
  L --> CON["Console: INFO and above"]
  L -. "if logging.file.name is set" .-> F["Rolling file"]`}
/>

- [Log groups](card:log-groups) set many loggers at once: the built-in `web` and `sql` groups, or your own with `logging.group.*`.
- Logging starts before the `ApplicationContext`, so `@PropertySource` files cannot configure it; use `application.properties` or env vars.
- To use [Log4j2](card:log4j2), exclude `spring-boot-starter-logging` and add `spring-boot-starter-log4j2`.

## Example

```java
private static final Logger log = LoggerFactory.getLogger(OrderService.class);

void place(Order order) {
    log.debug("Placing order {}", order.id());   // {} is filled only if DEBUG is on
}
```

```properties
logging.level.root=warn
logging.level.com.example.orders=debug
logging.file.name=logs/app.log
logging.structured.format.file=ecs
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Logging system | Logback (logback-classic 1.5.38) | `spring-boot-starter-logging`, Spring Boot 4.1.1 |
| Console output | `ERROR`, `WARN` and `INFO` | Spring Boot 4.1 |
| Log file | none, console only | Spring Boot 4.1 |
| `logging.logback.rollingpolicy.max-file-size` | `10MB` | Spring Boot 4.1 |
| `logging.logback.rollingpolicy.max-history` | `7` archive files | Spring Boot 4.1 |

## Interview Qs

### Which logging framework does Spring Boot use by default?

Logback, through `spring-boot-starter-logging`, which every starter depends on. Spring Boot itself logs through Commons Logging, and bridges route Java Util Logging and Log4j API calls to Logback too. Your own code should use the SLF4J API.

### How do you enable debug logging?

For your code, set `logging.level.com.example=debug`, or the env var `LOGGING_LEVEL_COM_EXAMPLE=DEBUG`. `--debug` only raises core loggers and prints the auto-configuration conditions report. On a running app, POST a new level to `/actuator/loggers/{name}`.

### How do you switch from Logback to Log4j2?

Exclude `spring-boot-starter-logging` from the starters and add `spring-boot-starter-log4j2`. Put a custom setup in `log4j2-spring.xml`. Keep calling the SLF4J API, and your code does not change.

### logback.xml or logback-spring.xml?

`logback-spring.xml`. Spring Boot then controls initialisation fully, and you can use `<springProfile>` and `<springProperty>`. A plain `logback.xml` is loaded too early for those extensions.
