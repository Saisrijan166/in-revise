## What it is

Logging is how the app writes a record of what it did, with a time, a **level** and the class that wrote it. A level says how important a line is, from TRACE (most detail) to ERROR. Your code calls **SLF4J**, a logging API with no output of its own. Behind it, **Logback** does the writing; the Spring Boot starters bring Logback and set it up for you, so logging works with no setup file.

## Why it exists

`System.out.println` has no levels, no time, no class name and no way to send lines to a file. In production you want only important lines; while chasing a bug you want every detail from one class. A logging library gives each line a level, and properties choose which levels print. Coding against SLF4J also means the backend, such as Logback or Log4j2, can change without touching your code.

## How it works

<Mermaid

1. A class gets a logger named after itself, such as `com.example.payment.PaymentService`.
2. The code calls `log.debug(...)`, `log.info(...)` or another level method.
3. Logback finds that logger's level. If `logging.level` sets none for the package, it uses the root level, INFO by default.
4. If the line's level is at or above the logger's level, Logback formats it and writes it to the console, and to the file if one is set. Otherwise the call returns at once.

## Example

`PaymentService` in the payment service logs each payment. Payment 41 passes the fraud check; for payment 42 the check throws:

```java
@Service
class PaymentService {
    private static final Logger log = LoggerFactory.getLogger(PaymentService.class);
    private final FraudCheckClient fraudCheck;
    PaymentService(FraudCheckClient fraudCheck) { this.fraudCheck = fraudCheck; }
    void pay(Long paymentId) {
        log.debug("Checking fraud for payment {}", paymentId);   // hidden at INFO
        try {
            fraudCheck.verify(paymentId);
            log.info("Payment {} completed", paymentId);
        } catch (IllegalStateException e) {
            log.warn("Payment {} failed the fraud check", paymentId, e);
        }
    }
}
```

```text output
2026-10-21T16:49:58.614+05:30  INFO 108067 --- [           main] com.example.payment.PaymentService       : Payment 41 completed
2026-10-21T16:49:58.614+05:30  WARN 108067 --- [           main] com.example.payment.PaymentService       : Payment 42 failed the fraud check

java.lang.IllegalStateException: Fraud service timed out
```

What to notice:

- The DEBUG lines are missing, because the default level is INFO. With `logging.level.com.example.payment=debug`, "Checking fraud for payment 41" and "… 42" appear too.
- Each line shows the time, level, process id, thread, logger name and message: Boot's default console format.
- The exception passed as the last argument, after the `{}` values, is printed with its stack trace below the WARN line.

## Rules and defaults

| What | Default | Where |
| --- | --- | --- |
| Logging library | Logback | Spring Boot 4.1 starters |
| Console output | `ERROR`, `WARN` and `INFO` | Spring Boot 4.1 |
| Log file | none, console only | Spring Boot 4.1 |
| File rotation (Logback) | new file at 10 MB, 7 archives kept | Spring Boot 4.1 |

- **Your own Logback file:** name it `logback-spring.xml`, not `logback.xml`. Boot then controls when it loads, and Spring extensions such as `<springProfile>` work.
- **File settings:** `logging.file.name=payment.log` writes that file; `logging.file.path=/var/log` writes `spring.log` into that folder. If both are set, only the name is used.
- **Groups:** `logging.level.web=debug` or `logging.level.sql=debug` raise Boot's predefined groups of Spring web or SQL loggers at once.
- **JSON logs:** `logging.structured.format.console=ecs` (or `gelf`, `logstash`) prints each line as JSON for log tools (since Boot 3.4).
- **Log4j2 instead:** exclude `spring-boot-starter-logging` and add `spring-boot-starter-log4j2`; your SLF4J code stays the same.

## Common mistakes

- **"Setting logging levels in a @PropertySource file."** Logging starts before the application context exists, and `@PropertySource` files are added too late for `logging.*`, as [externalized configuration](card:externalized-configuration) explains. Use `application.properties`, environment variables or command-line arguments.

## Interview Qs

### Which logging framework does Spring Boot use by default?

Logback, when you use the starters. Your code should call the SLF4J API, so the backend can change, for example to Log4j2 by swapping `spring-boot-starter-logging` for `spring-boot-starter-log4j2`, without code changes.

### How do you enable debug logging for your own code?

Set `logging.level.com.example.payment=debug`, or the environment variable `LOGGING_LEVEL_COM_EXAMPLE_PAYMENT=DEBUG`. The `--debug` flag only raises a few core loggers and prints the auto-configuration report; it does not change your packages.

### Why use {} placeholders instead of string concatenation?

With `"Paid " + id` the string is built even when the level is off. With `"Paid {}", id`, SLF4J checks the level first and builds the message only if it will be printed. That saves work in hot code paths at levels such as DEBUG.
