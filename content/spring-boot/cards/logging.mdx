## Why it exists

`System.out.println` has no levels, no files and no format. A logging API with levels lets each environment show more or less detail, set with properties instead of code changes.

## How it works

  alt="Logging path. Your code calls the SLF4J Logger. Logback receives the call and checks the level. Lines at INFO and above go to the console by default, and also to a log file when logging.file.name is set."
  chart={`flowchart LR
  A["Your code: SLF4J Logger"] --> L["Logback: level check"]
  L --> CON["Console: INFO and above"]

/>

- Custom setup goes in `logback-spring.xml`, not `logback.xml`, so Spring extensions work.
- [Structured logging](card:structured-logging) writes JSON (ECS, GELF, Logstash) for log tools, since Spring Boot 3.4.

## Example

```java
private static final Logger log = LoggerFactory.getLogger(PaymentService.class);

void pay(String paymentId) {
    log.debug("Paying {}", paymentId);   // skipped cheaply unless DEBUG is on
    log.info("Payment processed: {}", paymentId);
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Logging library | Logback | Spring Boot 4.1 starters |
| Console output | `ERROR`, `WARN` and `INFO` | Spring Boot 4.1 |
| Log file | none, console only | Spring Boot 4.1 |
| File rotation (Logback) | new file at 10 MB, 7 archives kept | Spring Boot 4.1 |

## Interview Qs

### Which logging framework does Spring Boot use by default?

Logback, when you use the starters. Your code should call the SLF4J API, so the backend can change (for example to Log4j2) without code changes.

### How do you enable debug logging for your own code?

Set `logging.level.com.example=debug`, or the env var `LOGGING_LEVEL_COM_EXAMPLE=DEBUG`. The `--debug` flag only raises core loggers and prints the auto-configuration report.

### Why use {} placeholders instead of string concatenation?

With `"Paid " + id` the string is built even when the level is off. With `"Paid {}", id` SLF4J checks the level first and builds the message only if it will be logged.
