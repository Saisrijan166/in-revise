## Why it exists

Browsers send a site's cookies with every request to it, even one started by another site: that makes CSRF possible. Browsers also stop scripts from reading other origins' responses unless the server agrees: CORS is how it agrees.

## How it works

<Compare id="csrf-vs-cors" />

- With `CookieCsrfTokenRepository`, JavaScript reads the `XSRF-TOKEN` cookie and sends it back in the `X-XSRF-TOKEN` header.
- `CorsFilter` sits before `CsrfFilter` and the login filters, so preflights are answered before any login check.
- While CSRF is on, logout must be a POST.

## Example

```java
@Bean
SecurityFilterChain web(HttpSecurity http) {
    http.authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
        .formLogin(Customizer.withDefaults())
        .csrf(csrf -> csrf.spa());       // CSRF setup for a single-page app
    return http.build();                 // CORS is on: the bean below exists
}
```

```java
@Bean
UrlBasedCorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration config = new CorsConfiguration();     // allows nothing yet
    config.setAllowedOrigins(List.of("https://app.example.com"));
    config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE"));
    config.setAllowedHeaders(List.of("Content-Type", "Authorization"));
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/api/**", config);
    return source;
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| CSRF protection | On | Spring Security 7.1 |
| CSRF token store | HTTP session (`HttpSessionCsrfTokenRepository`) | Spring Security 7.1 |
| Token in a request | `X-CSRF-TOKEN` or `X-XSRF-TOKEN` header, or `_csrf` parameter | Spring Security 7.1 |
| CORS in Spring Security | Off, unless `cors()` is set or a `UrlBasedCorsConfigurationSource` bean exists | Spring Security 7.1 |
| `@CrossOrigin` | All origins and headers, max age 30 minutes, no credentials | Spring Framework 7.0 |

## Interview Qs

### What is CSRF, and how does Spring Security stop it?

Another site makes the user's browser send a request to your app, and the browser adds your session cookie. Spring requires a secret CSRF token on unsafe methods such as POST; the other site cannot read it, so the forged request is rejected with 403.

### When can you disable CSRF?

When no browser sends requests with automatic credentials: for example an API used only by other services, or one that takes bearer tokens in a header. Cookie sessions and HTTP Basic used from a browser still need it.

### What is a preflight request?

Before a cross-origin request that is not simple, such as a PUT or a JSON POST, the browser sends OPTIONS with `Access-Control-Request-Method`. The real request follows only if the answer allows it. Preflights carry no cookies.

### CORS still fails after adding @CrossOrigin. Why?

With Spring Security, the preflight reaches the security filters first and is rejected as unauthenticated. Enable `http.cors()` so CorsFilter answers it before login checks; it then uses Spring MVC's CORS settings. Disabling CORS does not help: the browser enforces it.
