## Why it exists

Some logic must run for many requests: logging, request IDs, compression, auth checks. Writing it in every controller repeats code; filters and interceptors run it around the request once, at two different depths.

## How it works

<Compare id="filter-vs-interceptor" />

- Order of one request: filters, DispatcherServlet, `preHandle`, controller, `postHandle`, view, `afterCompletion`, then the filters unwind.
- `postHandle` and `afterCompletion` run in reverse order; `afterCompletion` runs on any outcome, but only if `preHandle` returned true.
- Extend `OncePerRequestFilter`: it aims to run exactly once per request dispatch, on any servlet container.

## Example

```java
@Component                                         // a Servlet filter, for every request
class RequestIdFilter extends OncePerRequestFilter {
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res,
            FilterChain chain) throws ServletException, IOException {
        res.setHeader("X-Request-Id", UUID.randomUUID().toString());
        chain.doFilter(req, res);                  // pass it on, or stop here
    }
}

@Configuration                                     // an interceptor, only for /api/**
class WebConfig implements WebMvcConfigurer {
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new AuditInterceptor()).addPathPatterns("/api/**");
    }
}
```

## Interview Qs

### Filter vs interceptor?

A filter is part of the Servlet API and runs before DispatcherServlet for every request; it can wrap or replace the request and response. An interceptor is part of Spring MVC, runs inside DispatcherServlet, and knows which handler was chosen.

### Explain preHandle, postHandle and afterCompletion.

preHandle runs before the handler; returning false stops the request. postHandle runs after the handler, before the view renders. afterCompletion runs when the request is done, even after an error, and suits cleanup.

### How do you control the order of filters in Spring Boot?

Put @Order on the filter class or implement Ordered. If you cannot change the class, register it with a FilterRegistrationBean and call setOrder. @Order on the @Bean method does not work for filters.
