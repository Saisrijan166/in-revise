## Why it exists

Some reads are slow or costly and return the same result many times, such as a product lookup. Caching them by hand fills every method with "get it, else load it and put it" code.

## How it works

<Mermaid
  alt="A call to a @Cacheable method reaches the proxy, which builds the key and checks the cache. On a hit it returns the cached value without running the method. On a miss it runs the method, stores the result under the key, and returns it."
  chart={`flowchart LR
  C([Call find 42]) --> P{"Proxy: key 42 in cache?"}
  P -- hit --> R([Return cached value])
  P -- miss --> M[Run the method]
  M --> S[Store result under key 42]
  S --> R`}
/>

- Spring's cache is an abstraction; a provider stores the data. Boot uses the first it finds: Generic, JCache, Hazelcast, Infinispan, Couchbase, Redis, Caffeine, Cache2k, then Simple.
- No locks by default: several threads may load the same missing key. `sync = true` lets one compute while the others wait.
- Use public methods: on other methods the annotations are silently ignored.

## Example

```java
@Configuration
@EnableCaching
class CacheConfig { }

@Service
public class ProductService {   // repository injected through the constructor
    @Cacheable(cacheNames = "products", key = "#id")
    public Product find(long id) { return repository.findById(id).orElseThrow(); }

    @CachePut(cacheNames = "products", key = "#product.id")
    public Product update(Product product) { return repository.save(product); }

    @CacheEvict(cacheNames = "products", key = "#id")
    public void delete(long id) { repository.deleteById(id); }
}
```

```properties
spring.cache.cache-names=products
spring.cache.caffeine.spec=maximumSize=500,expireAfterAccess=600s
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Provider | First found, ending with Simple (`ConcurrentHashMap`) | Spring Boot 4.1 |
| Expiry with Simple | None | Spring Framework 7.0 |
| Key | `SimpleKeyGenerator` from the arguments | Spring Framework 7.0 |
| `@CacheEvict` timing | After the method (`beforeInvocation = false`) | Spring Framework 7.0 |

## Interview Qs

### @Cacheable vs @CachePut vs @CacheEvict?

@Cacheable skips the method when the key is already cached. @CachePut always runs the method and stores the result, for updates. @CacheEvict removes an entry, or every entry with allEntries = true, for deletes. Do not put @Cacheable and @CachePut on the same method.

### Why is my @Cacheable not working?

Usually the call does not pass through the proxy: self-invocation, a non-public method, or an object made with new. Also check that @EnableCaching is present and that the key really repeats.

### How do you set a TTL?

Not on the annotation: the abstraction leaves expiry to the provider. Use spring.cache.redis.time-to-live for Redis, or a Caffeine spec such as expireAfterAccess=600s. The default Simple cache never expires entries.
