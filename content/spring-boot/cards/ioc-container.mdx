## Why it exists

Without a container, every class creates its own collaborators with `new`, so classes are tied together and hard to test. The container takes over creating and connecting the objects.

## How it works

<Mermaid
  alt="Configuration metadata (scanned @Component classes, @Bean methods or XML) and your plain classes go into the ApplicationContext. The context turns the metadata into bean definitions, creates the beans, injects their dependencies and hands out ready beans."
  chart={`flowchart LR
  M["Metadata: @Component, @Bean, XML"] --> C[ApplicationContext]
  P[Your plain classes] --> C
  C --> D[Bean definitions]
  D --> B["Ready beans, dependencies injected"]`}
/>

- At startup the context creates every singleton bean, unless it is marked `@Lazy`, and runs each bean's [lifecycle](card:bean-lifecycle) callbacks.
- In Spring Boot, `SpringApplication.run` picks the context type from the classpath: with Spring MVC it is `AnnotationConfigServletWebServerApplicationContext`.
- Application code should almost never call `getBean()`; let the container inject instead.

## Example

```java
@Service
public class OrderService {
    private final PaymentClient payments;   // a bean the container supplies

    public OrderService(PaymentClient payments) {
        this.payments = payments;
    }
}

// Spring Boot creates and refreshes the container
ConfigurableApplicationContext ctx = SpringApplication.run(ShopApplication.class, args);
OrderService orders = ctx.getBean(OrderService.class);   // demos only; prefer injection
```

## Interview Qs

### What is IoC, and what is the IoC container?

Inversion of control means your code does not create or look up its collaborators; the container does. In Spring the container is the ApplicationContext: it reads bean definitions, creates the beans, injects dependencies and manages their lifecycle.

### BeanFactory vs ApplicationContext?

BeanFactory is the basic interface that creates and wires beans. ApplicationContext extends it with events, i18n messages, AOP integration, automatic post-processor registration and eager singletons. Use ApplicationContext; Spring Boot always creates one.

### What is a Spring bean?

An object that the IoC container creates, wires and manages. An object you create yourself with `new` is not a bean: the container does not inject into it or manage its lifecycle.

### Why are singletons created at startup?

So configuration mistakes, such as a missing dependency, fail when the app starts, not hours later on first use. The cost is more startup time and memory. Mark a bean `@Lazy` to delay it.
