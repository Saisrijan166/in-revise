## What it is

The Spring container is the object that creates and manages your application's objects. Each object it manages is called a bean. Inversion of control (IoC) is the idea behind it: your code no longer controls when its objects are created and connected; the container does. In Spring the container is an `ApplicationContext`, and [Spring Boot](card:spring-vs-spring-boot) creates one for you when the app starts.

## Why it exists

Without a container, each class builds its own helpers: `PaymentController` calls `new PaymentService()`, which calls `new PaymentRepository()`. Every class is then fixed to one concrete class, so a test cannot swap in a fake database, and changing one constructor means editing every place that calls it. With a container, you describe each object once. The container builds them in the right order and shares them wherever they are needed.

## How it works

1. At startup, Spring Boot creates the `ApplicationContext`.
2. The container collects bean definitions, the recipe for each bean. They come from classes you mark with `@Component`, from `@Bean` methods (both explained in [@Component vs @Bean](card:component-vs-bean)) and from Boot's [auto-configuration](card:auto-configuration).
3. It creates the beans, by default during startup, and passes each one the other beans it needs. This passing is [dependency injection](card:dependency-injection), the next concept.
4. The beans are ready. Your code uses these same objects until the app stops and the container closes.

So the container, not your code, decides when objects are created and which object each class receives.

## Example

Spring Boot normally creates the container for you. Here we create one by hand to watch what it does.

```java
@Component
class PaymentService {
    PaymentService() { System.out.println("PaymentService created"); }
}

public class Main {
    public static void main(String[] args) {
        var context = new AnnotationConfigApplicationContext(PaymentService.class);
        System.out.println("Container ready");
        PaymentService first = context.getBean(PaymentService.class);
        PaymentService second = context.getBean(PaymentService.class);
        System.out.println(first == second);
    }
}
```

```text output
PaymentService created
Container ready
true
```

What to notice:

- "PaymentService created" prints before "Container ready": the container builds beans while it starts, not when you first ask for them.
- `getBean` returns the same object both times, so `first == second` is `true`. By default each bean is one shared object; [Bean Scopes](card:bean-scopes) shows the other choices.
- In a Boot app you never write the `new AnnotationConfigApplicationContext` line: `SpringApplication.run` creates the context, and [component scanning](card:component-scanning) finds the `@Component` classes.
- If you write `new PaymentService()` yourself, you get an object the container knows nothing about: it injects nothing into it and never cleans it up.

## Rules and defaults

- **Eager by default:** an `ApplicationContext` creates all its shared (singleton) beans during startup, so configuration errors appear at once. [Bean Lifecycle](card:bean-lifecycle) shows how `@Lazy` changes this.
- **Who creates it:** in Spring Boot, `SpringApplication.run` creates the `ApplicationContext` and returns it.
- **Use ApplicationContext:** the Spring docs recommend it over a bare `BeanFactory` unless you need full control over bean processing.

## Not to be confused with

`BeanFactory` is the basic container interface: it holds bean definitions, creates beans and wires them. `ApplicationContext` extends it and adds events, messages in several languages, easy AOP integration and automatic setup of the container's helper processors. Rule: `BeanFactory` is the engine; `ApplicationContext` is the complete container you actually use.

## Interview Qs

### What is IoC, and what is the IoC container?

Inversion of control means your code does not create or look up its collaborators; the container does. In Spring the container is the `ApplicationContext`. It reads bean definitions, creates the beans, injects their dependencies and manages their lifecycle until the app stops.

### What is a Spring bean? Is every object in a Spring app a bean?

A bean is an object that the IoC container creates, wires and manages. Not every object is one: an object you create with `new`, such as a DTO or a local helper, is a plain Java object. Spring injects nothing into it and does not manage it.

### BeanFactory vs ApplicationContext?

`BeanFactory` is the basic container that creates and wires beans. `ApplicationContext` extends it with event publishing, i18n messages, AOP integration and automatic registration of post-processors, and it creates singletons eagerly at startup. Use `ApplicationContext`; Spring Boot always creates one.
