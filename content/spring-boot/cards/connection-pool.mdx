## Why it exists

Opening a database connection for every request is slow. A pool opens a set of connections once and lends them to threads, which give them back when done.

## How it works

<Mermaid
  alt="Threads 1 to 10 each borrow a connection from a pool of 10 open connections and give it back when done. Thread 11 finds none free and waits up to 30 seconds, then gets an SQLException."
  chart={`flowchart LR
  T1[Thread 1] -- "borrow, return" --> P[("Pool: 10 open connections")]
  T10[Thread 10] -- "borrow, return" --> P
  T11[Thread 11] -. "none free: waits up to 30 s" .-> P
  P --> DB[(Database)]`}
/>

- Boot picks HikariCP whenever it is present; `spring.datasource.type` chooses another pool.
- Keep `max-lifetime` a few seconds below any database or network connection limit.
- `leak-detection-threshold` logs a connection held too long, a sign of code that never returns it.

## Example

```properties
spring.datasource.url=jdbc:postgresql://db:5432/shop
spring.datasource.hikari.maximum-pool-size=10
spring.datasource.hikari.connection-timeout=5000
spring.datasource.hikari.leak-detection-threshold=20000
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `maximumPoolSize` | 10 | HikariCP 7.0 |
| `minimumIdle` | Same as `maximumPoolSize` (fixed size) | HikariCP 7.0 |
| `connectionTimeout` | 30 s | HikariCP 7.0 |
| `maxLifetime` | 30 min | HikariCP 7.0 |

## Interview Qs

### Which connection pool does Spring Boot use?

HikariCP, chosen whenever it is on the classpath; the jdbc and data-jpa starters bring it in. Without it Boot tries Tomcat JDBC, then DBCP2, then Oracle UCP.

### How do you size the pool?

Smaller than most expect. HikariCP's guide starts at cores x 2 plus disks, about 10 for a 4-core server with one disk, then load-test.

### Threads fail waiting for a connection. What do you check?

All connections stayed busy for the whole timeout. Look for long transactions and leaked connections first, then whether the pool size fits the load.
