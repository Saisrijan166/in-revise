## Why it exists

Spring needs to know which of your classes to turn into beans. Scanning a known package tree finds them without listing each one.

## How it works

<Mermaid
  alt="The main class sits in com.example. Scanning covers com.example and its sub-packages com.example.service and com.example.web, so PaymentService and PaymentController become beans. A class in com.other.audit is outside, so it is not scanned and is not a bean."
  chart={`flowchart TD
  M["com.example: @SpringBootApplication"] --> S["com.example.service: PaymentService"]
  M --> W["com.example.web: PaymentController"]
  O["com.other.audit: AuditService"]
  S --> OK([Beans])
  W --> OK
  O -. not scanned .-> X([No bean])`}
/>

- Setting `scanBasePackages` replaces the default, so list the main package too.
- It affects only component scanning, not `@Entity` or Spring Data repository scanning.

## Example

```java
@SpringBootApplication(scanBasePackages = {"com.example", "com.other.audit"})
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}
```

## Interview Qs

### My @Service is not found at startup. Why?

Most often it sits outside the main class's package tree, so scanning never sees it. Move it under the main package, or add its package with scanBasePackages or @ComponentScan.

### Where should the main class go?

In the root package, above all other classes. Then the default scan covers the whole project and nothing from other libraries.
