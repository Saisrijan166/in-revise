## What it is

[@Component](card:component-vs-bean) marks a class as a bean; component scanning is how Spring finds those marked classes. At startup Spring reads the classes in a set of packages, called the base packages, and registers every class marked `@Component` or a stereotype such as `@Service`. In Spring Boot the base package is the package of your main class, the one with `@SpringBootApplication`, together with every package below it.

## Why it exists

Without scanning, you would list every bean class by hand, as the container example did with `new AnnotationConfigApplicationContext(PaymentService.class)`. A real app has dozens of beans, and forgetting one means a startup failure. Scanning a known package tree finds them all, so a new `@Service` works as soon as you create it in the right package.

## How it works

1. `@SpringBootApplication` includes `@ComponentScan` with no packages given, so the base package is the main class's own package.
2. At startup Spring reads the classes in that package and in all its sub-packages, looking for `@Component`, either directly or through a stereotype.
3. Each class it finds gets a bean definition, named after the class.
4. A class in any other package is never read, so it never becomes a bean. If another bean needs it, startup fails.

So the position of the main class decides what Spring can see.

## Example

The payment service has one class outside the main package tree:

```text
com.example.payments           PaymentApplication (@SpringBootApplication)
com.example.payments.web       PaymentController   found
com.example.payments.service   PaymentService      found
com.example.audit              AuditService        NOT found
```

One fix is to name both packages:

```java
@SpringBootApplication(scanBasePackages = {"com.example.payments", "com.example.audit"})
public class PaymentApplication {
    public static void main(String[] args) {
        SpringApplication.run(PaymentApplication.class, args);
    }
}
```

What to notice:

- `com.example.audit` is a sibling of `com.example.payments`, not a sub-package. Without the fix, a bean that injects `AuditService` stops startup, and Boot reports that a bean of type `AuditService` "could not be found".
- `scanBasePackages` replaces the default, which is why `com.example.payments` is listed again.
- The cleaner fix is to move `PaymentApplication` up to `com.example`, so both trees sit below it.

## Rules and defaults

- **Default base package:** the package of the `@SpringBootApplication` class and all its sub-packages.
- **Main class placement:** the Spring Boot docs recommend a root package above all your other classes.
- **Default package:** never leave classes without a `package` line. Boot would then read every class of every jar on the classpath.
- **Only components:** `scanBasePackages` changes component scanning only. JPA `@Entity` classes are found through the main class's package by a separate mechanism.
- **Other ways in:** `@ComponentScan("com.example.audit")` on any `@Configuration` class also adds a package.

## Not to be confused with

[Auto-configuration](card:auto-configuration) also adds beans at startup, but it is not found by scanning. Boot reads its auto-configuration classes from a list inside its own jars. Rule: scanning finds your classes in your packages; auto-configuration adds Boot's classes from its jars.

## Interview Qs

### My @Service is not found at startup. Why?

Most often it sits outside the main class's package tree, so scanning never reads it. Check that its package starts with the main class's package. Then move the class, move the main class up, or add the package with `scanBasePackages` or `@ComponentScan`.

### Where should the main class go?

In the root package, above all other classes of the project. Then the default scan covers the whole project and nothing from other libraries.

### Does Spring scan every jar for components?

No. It reads only the base packages and their sub-packages. Library classes become beans in other ways: through your `@Bean` methods or through Boot's auto-configuration.
