## What it is

Adapter is a class that sits between your code and another class whose methods do not match what your code calls. The class your code expects is the **target** interface; the mismatched class you must use is the **adaptee**. The adapter implements the target, holds the adaptee inside it, and in each method converts your call into the adaptee's call. This is [composition over inheritance](card:composition-over-inheritance): the adapter wraps the adaptee rather than extending it.

## Why it exists

You often must use a third-party SDK or a legacy class whose method names and argument types are not the ones your code uses, and you cannot change that class. If every caller talked to it directly, the SDK's types and quirks would spread through the whole codebase, and swapping the SDK later would mean editing every caller. An adapter puts all of that translation in one class, so callers stay unaware of the SDK.

## How it works

  chart={`flowchart LR

1. Your code calls `charge` on the `PaymentGateway` interface, which is the only payment interface it knows.
2. The bean behind that interface is a `UpiAdapter`, which implements `PaymentGateway`.
3. Inside `charge`, the adapter converts the arguments, for example rupees into the paise count the SDK wants.
4. It calls the SDK's own method, `makePaymentInPaise`, and translates the result or errors back if needed.

So the key is that callers see only the target interface, while the adapter alone knows the adaptee.

## Example

`UpiAdapter` makes a third-party SDK usable through your `PaymentGateway`.

```java
class UpiAdapter implements PaymentGateway {             // target: your interface
    private final ExternalUpiSdk sdk;                     // adaptee: the SDK you cannot change
    UpiAdapter(ExternalUpiSdk sdk) { this.sdk = sdk; }

    @Override
    public void charge(BigDecimal amount) {               // your call: rupees, e.g. 500 or 500.00
        long paise = amount.movePointRight(2).longValueExact();   // 500 -> 50000
        sdk.makePaymentInPaise(paise);                    // the SDK's call
    }
}
```

What to notice:

- The class implements `PaymentGateway`, so anywhere a `PaymentGateway` is expected, a `UpiAdapter` fits. Callers never mention the SDK.
- `charge` takes rupees as `BigDecimal`; the SDK wants a `long` count of paise. The adapter does the conversion, which is its whole purpose.
- `movePointRight(2)` shifts 500 to 50000; `longValueExact` throws if a fraction of a paisa is left, so a bad amount fails loudly instead of silently rounding.
- Swap this SDK for another provider and you write a new adapter; `PaymentService` and the rest of the code do not change.

## Rules and defaults

- **Object adapter vs class adapter:** an object adapter holds the adaptee in a field and delegates to it; a class adapter inherits from the adaptee. The object form is preferred because it does not tie you to one concrete class.
- **One job:** the adapter only translates. Anything extra, such as retry or logging, belongs in a separate [decorator](card:decorator).
- **In the JDK:** `InputStreamReader` adapts a byte `InputStream` so it can be read as characters.
- **In Spring MVC:** a `HandlerAdapter` lets the `DispatcherServlet` call controllers of different shapes through one interface.

## Not to be confused with

A [decorator](card:decorator) also wraps an object and delegates, but it keeps the same interface and adds behaviour. An adapter changes the interface and adds nothing. Rule: different method on each side means Adapter; same method with extra work means Decorator.

## Interview Qs

### Where would you use Adapter in a payment system?

Wrap each provider's SDK behind your own `PaymentGateway` interface. Your services depend only on that interface, so adding or replacing a provider means writing one new adapter, not changing code across the system.

### What is the difference between an object adapter and a class adapter?

An object adapter holds the adaptee in a field and delegates to it, so it can adapt any subclass of the adaptee. A class adapter inherits from the adaptee, which ties it to that one concrete class. The object adapter is looser and usually preferred.

### Why convert rupees to paise with BigDecimal, not double?

A `double` cannot hold many decimal amounts such as 0.1 exactly, so money maths drifts by tiny amounts. `BigDecimal` is exact, and `longValueExact` throws if a sub-paisa fraction is left, turning a silent rounding bug into a loud error.
