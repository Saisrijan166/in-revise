## Why it exists

The same design problems return in project after project. A shared name such as Strategy or Adapter replaces a long explanation with one word and a tested structure.

## How it works

| Family | What it organises | The GoF patterns |
|---|---|---|
| Creational (5) | How objects are made | [Singleton](card:singleton), [Factory Method](card:factory-method), [Abstract Factory](card:abstract-factory), [Builder](card:builder), [Prototype](card:prototype) |
| Structural (7) | How classes and objects fit together | [Adapter](card:adapter), [Bridge](card:bridge), [Composite](card:composite), [Decorator](card:decorator), [Facade](card:facade), [Flyweight](card:flyweight), [Proxy](card:proxy) |
| Behavioural (11) | How objects share work and talk | [Chain of Responsibility](card:chain-of-responsibility), [Command](card:command), [Interpreter](card:interpreter), [Iterator](card:iterator), [Mediator](card:mediator), [Memento](card:memento), [Observer](card:observer), [State](card:state), [Strategy](card:strategy), [Template Method](card:template-method), [Visitor](card:visitor) |

- Widely used but not GoF: [Repository](card:repository-and-dao), [dependency injection](card:dependency-injection) and [MVC](card:mvc).
- A pattern used where simple code would do is an [anti-pattern](card:anti-patterns).
- How to explain one in an interview: [choosing a pattern](card:choosing-a-pattern).

## Interview Qs

### What are the types of design patterns?

Three GoF families: creational patterns control object creation (Builder), structural ones assemble objects (Adapter), behavioural ones share responsibilities (Strategy). Above them sit architectural patterns; below them, language idioms.

### Are patterns still useful with lambdas and modern Java?

Yes. The ideas stay; the code shrinks. A [Strategy](card:strategy) can be a lambda, a [Singleton](card:singleton) an enum, and pattern matching for switch (Java 21) over sealed types often replaces a [Visitor](card:visitor).
