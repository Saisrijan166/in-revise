## Why it exists

`new PaymentRequest(amount, "INR", UPI, null, null, key)` is easy to get wrong. A builder names each value and leaves out the optional ones.

## How it works

<Mermaid
  alt="Builder flow: start a PaymentRequest builder, set the amount of 500 rupees and the method UPI, optionally set a note, then call build, which checks the required fields and returns the finished PaymentRequest."
  chart={`flowchart LR
  B([new Builder]) --> A["amount(500)"] --> M["method(UPI)"] --> N["note(...) optional"] --> X{"build(): required set?"}

- JDK example: `HttpRequest.newBuilder()` (Java 11); its `build()` throws if no URI is set and returns an immutable request.
- The GoF form adds a [director](card:gof-builder) that runs the steps in a fixed order.

## Example

```java
public record PaymentRequest(BigDecimal amount, PaymentMethod method, String note) {
    public PaymentRequest {                                      // runs on build()
        Objects.requireNonNull(amount, "amount"); Objects.requireNonNull(method, "method");
    }
    public static final class Builder {
        private BigDecimal amount; private PaymentMethod method; private String note;
        public Builder amount(BigDecimal v) { amount = v; return this; }
        public Builder method(PaymentMethod v) { method = v; return this; }
        public Builder note(String v) { note = v; return this; }          // optional
        public PaymentRequest build() { return new PaymentRequest(amount, method, note); }
    }
}
```

## Interview Qs

### What problem does Builder solve that constructors cannot?

Long parameter lists with optional values. Overloaded constructors multiply and same-typed arguments are easy to swap. A builder names each value, skips optional ones and checks the result once in `build()`.

### How is Builder different from Abstract Factory?

Builder assembles one complex object step by step and returns it at the end. [Abstract Factory](card:abstract-factory) returns each product of a matching family at once.
