## Why it exists

Code that asks for a refund should not have to run it now, or know how. Packing the request as an object lets a job runner queue it and run it later.

## How it works

<Mermaid
  alt="A controller submits a RefundCommand for payment P1 to a job runner. Later the runner calls execute, and the command calls refund on RefundService."
  chart={`sequenceDiagram
  participant C as Client (controller)
  participant J as Invoker (job runner)
  participant K as RefundCommand
  participant R as Receiver (RefundService)
  C->>J: submit(new RefundCommand(service, "P1"))
  J->>K: execute()
  K->>R: refund("P1")`}
/>

- The invoker knows only `execute()`, so one runner handles refunds, payouts and reminders.
- For undo, keep executed commands in a history; a [Memento](card:memento) can save the state to restore.

## Example

```java
interface PaymentCommand { void execute(); }

class RefundCommand implements PaymentCommand {
    private final RefundService service; private final String paymentId;
    RefundCommand(RefundService s, String id) { service = s; paymentId = id; }
    public void execute() { service.refund(paymentId); }         // the receiver does the work
}
class JobRunner {                                                 // the invoker
    private final Queue<PaymentCommand> queue = new ArrayDeque<>();
    void submit(PaymentCommand c) { queue.add(c); }
    void runAll() { while (!queue.isEmpty()) queue.poll().execute(); }
}
```

## Interview Qs

### A refund must run later from a queue. Command or Strategy?

Command. A refund is one requested action with its own data, run later by a job runner. Strategy fits when one job, like paying, has several interchangeable ways. See [Command vs Strategy](compare:command-vs-strategy).

### How does Command support undo and redo?

Each command also gets an undo() that reverses it. Executed commands go on a history stack: undo pops one and calls undo(); redo runs it again.

### Where does the JDK use Command?

Runnable and Callable. You submit a task object to an ExecutorService, which decides when and on which thread it runs. Runnable is a functional interface, so a lambda works.
