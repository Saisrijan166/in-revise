## Why it exists

A customer's payment history may sit in pages, a tree or a list. Callers should loop over payments the same way, whatever the storage is.

## How it works

<Steps label="One loop over a hidden collection">
  <Step title="Ask for an iterator">The caller calls `history.iterator()`; the enhanced for loop does this for you.</Step>
  <Step title="hasNext()">Is there another payment? If not, stop.</Step>
  <Step title="next()">Get the next payment and use it.</Step>
  <Step title="remove() if needed">Drop the payment just returned, safely, through the iterator.</Step>
</Steps>

- [External iteration](card:external-iteration) is your loop; [internal iteration](card:internal-iteration) is `forEach` (Java 8).

## Example

```java
record Payment(String id, BigDecimal amount) { }
class PaymentHistory implements Iterable<Payment> {
    private final List<List<Payment>> pages;              // hidden structure
    PaymentHistory(List<List<Payment>> pages) { this.pages = pages; }

    public Iterator<Payment> iterator() {
        return pages.stream().flatMap(List::stream).iterator();
    }
}
var history = new PaymentHistory(List.of(List.of(new Payment("p1", BigDecimal.TEN)),
        List.of(new Payment("p2", BigDecimal.ONE))));     // two pages
for (Payment p : history) System.out.println(p.id());    // the caller never sees the pages
```

```text output
p1
p2
```

## Interview Qs

### Fail-fast vs fail-safe iterators?

ArrayList's iterator is fail-fast: it throws ConcurrentModificationException, on a best-effort basis. Most java.util.concurrent collections are weakly consistent instead: they never throw it and may or may not show later changes.

### What does the enhanced for loop need?

An array or any `Iterable`. For an `Iterable`, the loop is translated into calls to `iterator()`, `hasNext()` and `next()`.
