## What it is

A facade is one class that offers a simple method in front of a subsystem of many classes. Callers use the facade's method instead of calling the subsystem classes themselves, so they do not need to know which classes exist or in what order to call them. The facade does not replace those classes or hide them; it just gives the common case one easy entry point. Code that needs finer control can still reach the subsystem directly.

## Why it exists

Paying may need five classes called in a fixed order: validate the request, run a fraud check, charge the gateway, issue a receipt, then notify the customer. If every controller does that itself, the same sequence is repeated everywhere, and changing it, such as adding a step, means editing every caller and risks getting the order wrong. A facade holds the sequence in one place, so callers make one call and changes happen once.

## How it works

1. The controller calls one method, `PaymentFacade.pay(request)`, and passes the request.
2. The facade calls the subsystem classes in order: validate, fraud check, charge, issue receipt, notify.
3. Each class does its own real work; the facade only arranges the calls and passes data between them.
4. The facade returns a simple result, such as the receipt, so the caller never sees the subsystem.

So the key is that the facade orchestrates; it holds no business logic of its own.

## Example

Without a facade every caller repeats the steps; with one, a caller makes a single call.

```java
// Without a facade, every caller repeats the steps, in the right order:
validator.check(request);
fraud.screen(request);
gateway.charge(request.amount());
Receipt receipt = receipts.issue(request);
notifier.paid(receipt);

// With a facade, callers make one call:
Receipt same = paymentFacade.pay(request);
```

What to notice:

- The first block spreads the five-step order across every caller; forget a step in one place and that path is wrong.
- `paymentFacade.pay(request)` runs the same five steps inside the facade, so each caller does one thing.
- Add or reorder a step, and you change only `pay`, not the callers.
- The facade still delegates to `validator`, `fraud`, `gateway` and the rest; it does not do their work itself.

## Rules and defaults

- **No business logic:** a facade orchestrates calls; the real work stays in the subsystem classes, or the facade becomes a [god object](card:anti-patterns).
- **Keep it focused:** if a facade grows too large, split it into smaller facades by area before it couples to the whole app.
- **Not a gate:** the subsystem classes stay public and usable; the facade only adds an easier path.
- **Real example:** SLF4J, the Simple Logging Facade for Java, is a logging facade; your code logs through its API and the actual framework is chosen on the classpath at deploy time.

## Not to be confused with

A [proxy](card:proxy) stands in front of one object and keeps that object's exact interface; a facade defines its own new, simpler interface over many objects. An [adapter](card:adapter) converts one existing interface into another the caller expects, while a facade invents a simpler one over a whole subsystem. Rule: new simple interface over many classes means Facade.

## Interview Qs

### What problem does Facade solve?

It shields callers from a complex subsystem. Callers depend on one simple class instead of many, so they do not learn the subsystem's classes or call order, and a change inside the subsystem is made once in the facade rather than in every caller.

### Give a real example of a facade in Java.

SLF4J, the Simple Logging Facade for Java. Application code logs through its one API, and the real framework, such as Logback or `java.util.logging`, is bound at deploy time. Swapping the framework does not change the logging calls in your code.

### How is a Facade different from an Adapter?

An adapter makes one existing, mismatched interface usable by converting its calls into the interface you expect. A facade invents a new, simpler interface over a whole subsystem of classes. Adapter is about fitting one class; Facade is about simplifying many.
