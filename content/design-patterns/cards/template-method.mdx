## Why it exists

Several payment processors repeat the same validate, pay and notify flow. Copies drift apart; a template keeps the flow in one place and varies only the payment step.

## How it works

<Steps label="process(amount): the order is fixed in the base class">
  <Step title="validate(amount)">Shared code: reject zero or negative amounts.</Step>
  <Step title="executePayment(amount)">Abstract: each subclass, UPI or card, implements it.</Step>
  <Step title="afterPayment()">Hook: empty by default; override it to send a receipt.</Step>
</Steps>

- The base class calls the subclass, not the other way round: the Hollywood principle.
- Mark the template `final`; Java does not let a subclass override a final method.

## Example

```java
abstract class PaymentProcessor {
    public final void process(BigDecimal amount) {             // the template method
        if (amount.signum() <= 0) throw new IllegalArgumentException("amount");
        executePayment(amount);                                  // varies per subclass
        afterPayment();                                          // hook
    }
    protected abstract void executePayment(BigDecimal amount);
    protected void afterPayment() { }                            // empty by default
}
class UpiProcessor extends PaymentProcessor {
    protected void executePayment(BigDecimal amount) { System.out.println("UPI " + amount); }
}
```

## Interview Qs

### Template Method or Strategy?

Template Method varies steps through subclasses, fixed once the class is chosen. Strategy passes in an object, so behaviour can change at runtime. Fixed order with one varying step: Template Method. Whole algorithm varies: Strategy.

### Where does the JDK use Template Method?

java.util.AbstractList. Extend it and implement get(int) and size(); its iterator and other methods are built on them. For a modifiable list, also override set, add and remove.

### What is a hook method?

An optional step with an empty or default body that the template calls. A subclass overrides it only when it needs to, such as sending a receipt after payment.
