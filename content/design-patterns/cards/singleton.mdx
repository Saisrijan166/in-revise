## Why it exists

Some things should exist once, like an app-wide config. Singleton stops other code calling `new` and hands everyone the same object.

## How it works

| Way | Created | Thread-safe |
|---|---|---|
| Eager `static final` field | When the class initialises | Yes, through class initialisation |
| `synchronized getInstance()` | On first call | Yes, but locks on every call |
| [Double-checked locking](card:double-checked-locking) | On first call | Only if the field is `volatile` |
| [Holder class](card:holder-idiom) | On first call | Yes, through class initialisation |
| [Enum](card:enum-singleton) | When the enum initialises | Yes, and no reflective or deserialised copies |

- Overuse turns into hidden global state: see [anti-patterns](card:anti-patterns).

## Example

```java
public final class PaymentConfig {
    private static volatile PaymentConfig instance;      // volatile is required
    private PaymentConfig() { }
    public static PaymentConfig getInstance() {
        if (instance == null) {                          // 1st check, no lock
            synchronized (PaymentConfig.class) {
                if (instance == null) instance = new PaymentConfig();   // 2nd check
            }
        }
        return instance;
    }
}
```

## Defaults

| What | Default | Where |
|---|---|---|
| Bean scope | singleton | Spring Framework 7.0 |

## Interview Qs

### How do you make a singleton thread-safe?

Use a one-constant enum or the holder idiom: the nested class is initialised on first use, and the JVM makes that safe. Double-checked locking works only with a `volatile` field.

### Why does double-checked locking need volatile?

Without it, the constructor's writes and the write of the reference can be reordered. Another thread may then see a non-null instance with default field values. Since Java 5, `volatile` forbids that reordering.

### Is a Spring singleton bean the same as a GoF singleton?

No. GoF fixes one instance per ClassLoader. Spring keeps one per bean definition per container, so two definitions of one class give two instances.
