## Why it exists

One method doing authentication, permission, amount and fraud checks grows into a long if-else. Separate handlers keep each check small and easy to add or reorder.

## How it works

<Steps label="Paying ₹500: the request passes each handler in order">
  <Step title="Authentication">Is the user logged in? If not, stop here.</Step>
  <Step title="Permission">May this user pay from this account?</Step>
  <Step title="Amount validation">Is ₹500 above zero and within the limit?</Step>
  <Step title="Fraud check">Does it look unusual? Hold or stop it.</Step>
  <Step title="Payment processing">The last link charges the payment.</Step>
</Steps>

- Each handler knows only the next one, so a new check does not edit the others.
- Classic form: the first handler that can deal with it does, and stops. Filters: every handler runs.
- [Decorator](card:decorator) also wraps calls in a line, but never stops the flow.

## Example

```java
public class AuthFilter implements Filter {               // jakarta.servlet.Filter
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        if (((HttpServletRequest) req).getHeader("Authorization") == null) {
            ((HttpServletResponse) res).sendError(HttpServletResponse.SC_UNAUTHORIZED);
            return;                                        // stop: do not pass it on
        }
        chain.doFilter(req, res);                          // pass to the next filter
    }
}
```

## Interview Qs

### What problem does Chain of Responsibility solve?

It replaces one big block of checks with small handlers linked in order. Checks can then be added, removed or reordered without touching the others.

### How do Servlet filters and Spring Security use it?

Each Servlet filter does its work and calls chain.doFilter() to pass the request on, or returns to block it. Spring Security's FilterChainProxy picks the first matching SecurityFilterChain and runs its filters in order.

### What happens if no handler deals with the request?

It falls off the end unhandled. End the chain with a default handler, or let the last link reject the request with a clear error.
