## What it is

A factory is code whose job is to create objects for you, so the rest of the app does not call `new` on concrete classes. "Factory" covers three things. A **simple factory** is a method with a switch that returns the class; common, but not in the Gang of Four's 23 patterns. The **Factory Method** is a GoF pattern where a superclass declares a creating method and a subclass overrides it to make a different object. A **static factory method** replaces a constructor with a named static call, like `List.of(...)`.

## Why it exists

Spread `new UpiGateway()` and `if` checks through your business code, and every time a new payment type arrives you hunt down each of those spots and edit them. Miss one and you ship a bug. A factory puts the "which class?" decision in a single place. Business code asks for a `PaymentGateway` by its type and gets back the interface, so it never depends on the concrete classes and does not change when a new type is added.

## How it works

The three forms differ in how the class is chosen.

| Kind | How it picks the class | Payment example |
|---|---|---|
| Simple factory | A switch on the input, in one method | `GatewayFactory.create(UPI)` |
| Factory Method (GoF) | A subclass overrides the creating method | `UpiCheckout extends Checkout` |
| Static factory method | A named static method instead of `new` | `List.of(...)` (Java 9) |

1. The caller names what it wants by type, for example the `PaymentMethod` enum value `UPI`, not the class `UpiGateway`.
2. A simple factory runs a switch and returns a new object of the matching class, typed as the interface.
3. In the GoF form there is no switch: the base `Checkout` calls its own `createGateway()`, and whichever subclass you used decides the class.
4. So the key is that callers hold only the product interface; the knowledge of concrete classes sits inside the factory.

## Example

A simple factory picks the gateway. The switch is the one place that names the concrete classes.

```java
enum PaymentMethod { UPI, CARD, WALLET }

final class GatewayFactory {
    static PaymentGateway create(PaymentMethod method) {
        return switch (method) {          // switch expression (Java 14)
            case UPI -> new UpiGateway();
            case CARD -> new CardGateway();
            case WALLET -> new WalletGateway();
        };                                // no default needed: every constant is listed
    }
}
GatewayFactory.create(PaymentMethod.CARD).charge(BigDecimal.valueOf(500));
```

```text output
Card charged 500
```

What to notice:

- Callers pass the `PaymentMethod` enum, not a class, so they never see `UpiGateway` or `CardGateway`.
- The switch is exhaustive over the enum, so no `default` branch is needed. Add a `WALLET` without a case and the code does not compile, which turns a runtime bug into a compile error.
- The return type is the `PaymentGateway` interface. If you later rename a concrete class, only this method changes.

## Rules and defaults

- **Simple factory is not GoF:** it is a widely used technique, but not one of the 23 named patterns. Say "simple factory" in an interview, not "the Factory pattern".
- **Factory Method needs inheritance:** a subclass must override the creating method. If there is no subclass overriding anything, it is not this pattern.
- **Exhaustive switch:** a `switch` expression over an enum with every constant listed needs no `default` (Java 14+), and the compiler flags a missing case.
- **In Spring:** you can inject `Map<String, PaymentGateway>`, where the keys are bean names, instead of writing a switch. Keep a factory when creation needs runtime data or complex rules.

## Not to be confused with

A factory decides **which object to create**. [Strategy](card:strategy) is **the behaviour** that object then carries out. They often team up: a factory (or Spring) picks a strategy, and the service runs it. See also [Factory Method vs Abstract Factory](card:factory-method-vs-abstract-factory), which creates a whole matching family rather than one product.

## Interview Qs

### What is the difference between a static factory method and the Factory Method pattern?

A static factory method is a named static method used instead of a constructor, such as `List.of`. The GoF Factory Method relies on inheritance: a superclass declares a creating method and a subclass overrides it to change the product. A static method cannot be overridden, so it is not the GoF pattern, even though both are called "factories".

### Why use a factory instead of calling new directly?

Calling `new` on a concrete class ties the caller to that class and scatters the choice across the code. A factory keeps the decision in one place and hands back an interface, so callers do not change when a new type is added and you cannot accidentally depend on a concrete class.

### Does Spring remove the need for factories?

Often. Spring creates the beans, and injecting a `Map<String, PaymentGateway>` gives a lookup by bean name without a switch. A factory still earns its place when creation depends on runtime input or needs complex rules that configuration cannot express.
