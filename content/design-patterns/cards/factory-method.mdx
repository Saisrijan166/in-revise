## Why it exists

Business code should not be full of `new UpiPayment()` and `if` checks. A factory keeps the "which class?" decision in one place.

## How it works

| Kind | How it picks the class | Payment example |
|---|---|---|
| [Simple factory](card:simple-factory) | A switch on the input | `PaymentFactory.create(PaymentMethod.UPI)` |
| [Factory Method](card:gof-factory-method) | A subclass overrides `createStrategy()` | `UpiCheckout extends Checkout` |
| [Static factory method](card:static-factory-method) | A named static method | `List.of(...)` (Java 9) |

- A new payment method still edits the switch: see [Open-Closed](card:open-closed).
- In Spring, inject `Map<String, PaymentStrategy>`: keys are bean names. Keep a factory when creation rules are complex.

## Example

```java
enum PaymentMethod { UPI, CARD, WALLET }

final class PaymentFactory {
    static PaymentStrategy create(PaymentMethod method) {
        return switch (method) {          // switch expression (Java 14): no default
            case UPI -> new UpiPayment();
            case CARD -> new CardPayment();
            case WALLET -> new WalletPayment();
        };
    }
}
System.out.println(PaymentFactory.create(PaymentMethod.UPI).getClass().getSimpleName());
```

```text output
UpiPayment
```

## Interview Qs

### What is the difference between a static factory method and the Factory Method pattern?

A static factory method is a named static method used instead of a constructor. Factory Method relies on inheritance: a subclass overrides the creating method. A static method cannot be overridden, so it is not the GoF pattern.

### Does Spring remove the need for factories?

Often. Spring creates the beans, and a `Map<String, PaymentStrategy>` gives a lookup by bean name. A factory still helps when creation needs runtime data or complex rules.
