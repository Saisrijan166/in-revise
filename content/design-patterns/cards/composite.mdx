## Why it exists

Some data is a tree: a payment split into parts, a menu with sub-menus. Without a shared interface, every caller needs if-else checks for "single item or group?".

## How it works

<Mermaid
  alt="A CompositePayment of 500 rupees holds two children: a WalletPayment of 300 rupees and a UpiPayment of 200 rupees. Calling pay on the composite calls pay on each child."
  chart={`flowchart TD
  S["CompositePayment ₹500"] -- "pay(₹300)" --> W["WalletPayment (leaf)"]
  S -- "pay(₹200)" --> U["UpiPayment (leaf)"]`}
/>

- The caller holds a `PaymentStrategy` and never checks what kind it is.
- In the JDK, `java.awt.Container` is a `Component` that holds other components.
- [Visitor](card:visitor) can run one operation over a whole Composite tree; a [Decorator](card:decorator) is like a Composite with one child.

## Example

```java
class CompositePayment implements PaymentStrategy {                   // composite
    private final Map<PaymentStrategy, BigDecimal> parts = new LinkedHashMap<>();
    CompositePayment add(PaymentStrategy part, BigDecimal share) { parts.put(part, share); return this; }
    @Override
    public void pay(BigDecimal total) {                               // same method as a leaf
        BigDecimal sum = parts.values().stream().reduce(BigDecimal.ZERO, BigDecimal::add);
        if (sum.compareTo(total) != 0) throw new IllegalArgumentException("shares must add up to " + total);
        parts.forEach((part, share) -> part.pay(share));              // a part may be a composite too
    }
}
new CompositePayment().add(a -> System.out.println("Wallet " + a), BigDecimal.valueOf(300))
    .add(a -> System.out.println("UPI " + a), BigDecimal.valueOf(200)).pay(BigDecimal.valueOf(500));
```

```text output
Wallet 300
UPI 200
```

## Interview Qs

### When would you use Composite?

When the model is naturally a tree and callers should treat one item and a group the same way: products packed in nested boxes, UI containers, or a payment split across methods.

### Where should add and remove child go?

Only on the container: leaves stay clean, but callers must know which kind they hold. On the shared interface: callers treat every node alike, but leaves get empty methods.
