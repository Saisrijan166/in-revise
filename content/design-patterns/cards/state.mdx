## Why it exists

A payment's status decides what `confirm()` or `refund()` may do. Without the pattern every method repeats a switch on status, and each new status edits them all.

## How it works

<Mermaid
  alt="Payment lifecycle: CREATED to PENDING on submit; PENDING to SUCCESS or FAILED; SUCCESS to REFUND_PENDING on refund, then REFUNDED. FAILED and REFUNDED are final."
  chart={`stateDiagram-v2
  [*] --> CREATED
  CREATED --> PENDING: submit
  PENDING --> SUCCESS: provider confirms
  PENDING --> FAILED: provider declines
  SUCCESS --> REFUND_PENDING: refund
  REFUND_PENDING --> REFUNDED: refund settles
  FAILED --> [*]
  REFUNDED --> [*]`}
/>

- Every state answers the same events; an event a state does not allow throws at once.
- Unlike [Strategy](card:strategy), states may know each other and can switch the context themselves.

## Example

```java
enum PaymentState {
    CREATED { PaymentState submit()  { return PENDING; } },
    PENDING { PaymentState confirm() { return SUCCESS; } },
    SUCCESS { PaymentState refund()  { return REFUND_PENDING; } },
    FAILED, REFUND_PENDING, REFUNDED;
    PaymentState submit()  { throw new IllegalStateException(this + ": cannot submit"); }
    PaymentState confirm() { throw new IllegalStateException(this + ": cannot confirm"); }
    PaymentState refund()  { throw new IllegalStateException(this + ": cannot refund"); }
}
class Payment {                                        // the context
    private PaymentState state = PaymentState.CREATED;
    void refund() { state = state.refund(); } }        // FAILED.refund() throws
```

## Interview Qs

### How is State different from Strategy?

Both delegate to a helper object. In Strategy the client picks the algorithm and strategies never know each other. In State the states can know each other and move the context to the next state as events arrive. See [Strategy vs State](compare:strategy-vs-state).

### When is the State pattern overkill?

When there are only a few states that rarely change; a simple switch is clearer. Use State when many methods depend on the status.
