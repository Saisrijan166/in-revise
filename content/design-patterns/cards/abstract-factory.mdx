## Why it exists

Some objects only work together, like the payment and refund clients of one provider mode. Creating each one separately makes it easy to mix sandbox and live by mistake.

## How it works

<Compare id="factory-method-vs-abstract-factory" />

- The client sees only interfaces: the factory and each product.
- Pick the concrete factory once, at startup, from config.

## Example

```java
interface PaymentClient { void charge(BigDecimal amount); }
interface RefundClient { void refund(String paymentId); }

interface ProviderFactory {                       // one method per product
    PaymentClient paymentClient();
    RefundClient refundClient();
}

class SandboxProviderFactory implements ProviderFactory {
    public PaymentClient paymentClient() { return amount -> System.out.println("test charge " + amount); }
    public RefundClient refundClient() { return id -> System.out.println("test refund " + id); }
}
```

## Interview Qs

### When should you prefer Abstract Factory over Factory Method?

When several products must be created together and must match. Factory Method decides one product; Abstract Factory guarantees the whole set comes from one variant.

### What is its main drawback?

Adding a new product type changes the factory interface, so every concrete factory must change too. It also adds many small interfaces and classes.
