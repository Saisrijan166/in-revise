## Why it exists

One method full of if-else branches for UPI, card and wallet must be edited for every new payment method. Strategy moves each branch into its own class.

## How it works

<Mermaid
  alt="The client gives UpiPayment to PaymentService, which calls pay on PaymentStrategy. UPI, card and wallet classes implement it."
  chart={`flowchart LR
  C[Client] -- "picks UpiPayment" --> S[PaymentService]
  S -- "pay(500)" --> I{{PaymentStrategy}}
  I --> U[UpiPayment]
  I --> K[CardPayment]
  I --> W[WalletPayment]`}
/>

- The context knows only the interface, so a new method does not touch it ([Open/Closed](card:open-closed)).
- The client, a [factory](card:factory-method) or Spring picks the strategy; the context just runs it.
- Strategies are independent: none knows the others.

## Example

```java
interface PaymentStrategy { void pay(BigDecimal amount); }   // one abstract method

class UpiPayment implements PaymentStrategy {
    public void pay(BigDecimal amount) { System.out.println("UPI " + amount); }
}
class PaymentService {                                        // the context
    private final PaymentStrategy strategy;
    PaymentService(PaymentStrategy strategy) { this.strategy = strategy; }
    void checkout(BigDecimal amount) { strategy.pay(amount); }
}
// new PaymentService(new UpiPayment()).checkout(BigDecimal.valueOf(500));
// new PaymentService(a -> System.out.println("Wallet " + a));   // a lambda as the strategy
```

## Interview Qs

### What is the role of the context in Strategy?

The context, here PaymentService, holds the strategy interface and delegates the work to it. It does not know which concrete strategy it holds, so strategies change without changing it.

### How does Strategy support the Open/Closed Principle?

Adding WalletPayment means one new class that implements PaymentStrategy. PaymentService and the other strategies stay untouched; only the place that chooses the strategy learns the new option.

### Where does the JDK use Strategy?

Comparator. Pass a different comparator to Collections.sort or Arrays.sort to change the order without changing the sort code. It is a functional interface, so a lambda works too.
