## What it is

Dynamic typing means a variable's type is determined at runtime from the object it is bound to, not declared in the source. Strong typing means Python does not silently convert between unrelated types: an operation on incompatible types raises an error instead of guessing. These describe two separate things. Dynamic versus static is about *when* types are known; strong versus weak is about *how strict* the rules are. Python is both dynamic and strong.

## Why it exists

Dynamic typing removes type declarations, so code is shorter and more flexible, and the same function can work on any object that behaves correctly (duck typing). Strong typing prevents a whole class of silent bugs: without it, `"1" + 1` might quietly become `"11"` or `2`, hiding a mistake. Python chooses flexibility in *when* types are checked but strictness in *what* it allows, so errors surface loudly rather than corrupting data.

## How it works

| Axis | Meaning | Python | Java |
|---|---|---|---|
| Dynamic vs static | When the type is fixed | Dynamic (runtime) | Static (compile time) |
| Strong vs weak | Silent coercion allowed? | Strong (no) | Strong (no) |

1. You bind a name to an object; its type comes from the object.
2. An operation checks the operand types at runtime.
3. If the types do not support the operation, Python raises `TypeError` rather than coercing.

## Example

```python
x = 5            # x is an int now
x = "five"       # same name, now a str (dynamic)
print(x)
print("1" + 1)   # strong typing: no silent mixing
```

```text output
five
Traceback (most recent call last):
TypeError: can only concatenate str (not "int") to str
```

What to notice: rebinding `x` from `int` to `str` is fine, that is dynamic typing. But `"1" + 1` raises `TypeError` instead of producing `"11"` or `2`, because strong typing refuses to guess. You must convert with `str(1)` or `int("1")`.

## Rules and defaults

- Types are checked at runtime; there is no compile-time type check (hints are optional and not enforced).
- Mixing numeric types is allowed (`1 + 2.0` gives `3.0`); mixing unrelated types like `str` and `int` is not.
- Explicit conversion is required: `int()`, `float()`, `str()`.

## Common mistakes

- **Equating dynamic with weak.** Python is dynamic but strict; it raises on bad mixes.
- **Expecting "5" to work as a number.** Convert input strings with `int()` before arithmetic.
- **Assuming type hints enforce types.** They are for tools and readers; the runtime ignores them.

## Interview Qs

### Is Python strongly or weakly typed?

Strongly typed. It does not silently coerce between unrelated types. `"1" + 1` raises `TypeError`; you must convert explicitly. Weakly typed languages would quietly produce `"11"` or `2`.

### What is the difference between dynamic typing and weak typing?

Dynamic typing is about *when* the type is known: at runtime, from the object. Weak typing is about *whether* unrelated types are coerced silently. Python is dynamic but strong, so it is flexible about when yet strict about mixing.

### What is duck typing?

Code that cares about an object's methods, not its class: "if it walks and quacks like a duck, treat it as one." A function works on any object that supports the operations it uses, which fits dynamic typing.
