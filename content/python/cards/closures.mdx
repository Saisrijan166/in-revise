## What it is

A closure is an inner function that remembers the variables of the function that created it, even after that outer function has returned. It is possible because Python has **first-class functions**: a function is an object you can pass as an argument, return from another function, and store in a variable. A function that takes or returns another function is called a **higher-order function**. When an inner function uses a name from its enclosing scope, that name is kept alive with the inner function.

## Why it exists

Sometimes you want to build a customised function on the fly, like "a discount function fixed at 10%", without a class and without repeating the rate everywhere. A closure lets the outer function capture that setting and bake it into the inner function it returns. The returned function carries its own private data, so each one remembers its own configuration.

## How it works

<Steps>
  <Step title="Outer runs">`make_discount(rate)` sets a local `rate`.</Step>
  <Step title="Inner uses it">The inner function reads `rate` from the enclosing scope.</Step>
  <Step title="Return inner">`make_discount` returns the inner function and finishes.</Step>
  <Step title="Still remembers">The returned function keeps using the captured `rate` on each call.</Step>
</Steps>

1. The inner function refers to a variable it did not define itself (a free variable).
2. Python binds that variable to the enclosing scope and keeps it alive.
3. Each call to the outer function makes a new closure with its own captured value.

## Example

```python
def make_discount(rate):
    def apply(price):
        return price - price * rate   # remembers rate
    return apply

ten_off = make_discount(0.10)
print(ten_off(200))
```

```text output
180.0
```

What to notice: `make_discount(0.10)` returns the inner `apply`, which has closed over `rate = 0.10`. Even though `make_discount` has already returned, `ten_off(200)` still sees that rate and applies a 10% discount. A `make_discount(0.25)` would carry its own separate rate.

## Rules and defaults

| What | Behaviour |
|---|---|
| Captured name | a free variable, bound to the enclosing scope |
| Lifetime | the enclosing variable lives as long as the closure does |
| Reference, not copy | the closure sees later changes to the variable |
| Rebinding inside | needs `nonlocal` to change the enclosing variable |
| Pure function | uses only its inputs and has no side effects; easier to test |

## Common mistakes

- **Expecting a snapshot.** A closure holds a reference, so if the enclosing variable changes later (as in a loop), all closures see the final value. Capture with a default argument to freeze it.
- **Forgetting `nonlocal` to update.** Reading the enclosing variable works; rebinding it from inside needs `nonlocal`.
- **Reaching for a class too soon.** A single-method configurable function is often cleaner as a closure.

## Interview Qs

### What is a closure?

An inner function that remembers variables from its enclosing function, even after that function has returned. It keeps those variables alive, so the returned function carries its own private state, like a rate or a counter, without needing a class.

### What does "first-class functions" mean in Python?

Functions are objects: you can assign them to variables, store them in lists or dicts, pass them as arguments, and return them from other functions. This is what makes closures, higher-order functions and decorators possible.

### What is a higher-order function?

A function that takes a function as an argument, returns a function, or both. Built-ins like `map`, `filter` and `sorted` (via its `key`) are higher-order, and any function that builds and returns a closure is too.
