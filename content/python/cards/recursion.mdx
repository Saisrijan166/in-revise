## What it is

Recursion is when a function solves a problem by calling itself on a smaller version of the same problem. It needs two parts: a **base case**, the simplest input that returns an answer directly, and a **recursive case**, where the function calls itself on a smaller input and builds on that result. Each call must move toward the base case so the chain eventually stops. Classic examples are factorial, tree walks and divide-and-conquer algorithms.

## Why it exists

Some problems are naturally defined in terms of themselves: a factorial is `n` times the factorial of `n-1`; a folder's size is the sum of its files plus the size of its subfolders. Recursion lets you write the solution the same way the problem is described, which is often shorter and clearer than managing your own stack with a loop.

## How it works

<Steps>
  <Step title="Check base case">If the input is simple enough, return the answer directly.</Step>
  <Step title="Recurse">Otherwise call the function on a smaller input.</Step>
  <Step title="Wait">The current call pauses on the stack until the inner call returns.</Step>
  <Step title="Unwind">Base case returns, then each waiting call combines its value and returns, back up to the first call.</Step>
</Steps>

1. Each call adds a frame to the call stack.
2. The base case returns without recursing, which starts the unwinding.
3. Without a base case, or without shrinking, the stack grows until `RecursionError`.

## Example

```python
def factorial(n):
    if n < 2:           # base case: 0! and 1! are 1
        return 1
    return n * factorial(n - 1)   # recursive case

print(factorial(5))
```

```text output
120
```

What to notice: `factorial(5)` waits for `factorial(4)`, which waits for `factorial(3)`, and so on down to `factorial(1)`, which returns 1 without recursing. Then the calls unwind, multiplying back up: 1, 2, 6, 24, 120. The base case `n < 2` is what stops the chain.

## Rules and defaults

| What | Default / behaviour |
|---|---|
| Recursion limit | about 1000 by default (`sys.getrecursionlimit()`) |
| Too deep | raises `RecursionError` |
| Change limit | `sys.setrecursionlimit(n)`, but too high can crash the interpreter |
| Tail-call optimisation | none in CPython; every call keeps its frame |
| Alternative | rewrite deep recursion as a loop, or use an explicit stack |

## Common mistakes

- **No base case, or one that is never reached.** The function recurses until `RecursionError`. Make sure each call shrinks toward the base.
- **Relying on tail recursion for depth.** Python does not optimise tail calls, so deep recursion still overflows the stack. Use a loop.
- **Raising the limit to fix deep recursion.** A very high `setrecursionlimit` can crash the process; an iterative version is safer.

## Interview Qs

### What two parts must every recursive function have?

A base case and a recursive case. The base case returns an answer directly for the simplest input and stops the recursion. The recursive case calls the function on a smaller input and moves toward the base case.

### Does Python optimise tail recursion?

No. CPython does not do tail-call optimisation, by design, so it can keep full tracebacks. Every recursive call adds a stack frame, so deep tail recursion still raises `RecursionError`. Rewrite such code as a loop.

### What is the default recursion limit and what happens when you exceed it?

The default limit is about 1000 nested calls (`sys.getrecursionlimit()`). Exceeding it raises `RecursionError`. You can raise it with `sys.setrecursionlimit`, but setting it too high risks crashing the interpreter.
