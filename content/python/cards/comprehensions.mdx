## What it is

A comprehension builds a collection from an iterable in a single expression. `[expr for item in iterable]` builds a [list](card:lists); `{expr}` builds a [set](card:sets); `{key: value for ...}` builds a [dict](card:dictionaries); and `(expr for ...)` is a generator expression, which is lazy. An optional `if` at the end keeps only matching items.

## Why it exists

Turning one collection into another, often filtering as you go, is extremely common: the names from a list of orders, the squares of some numbers, a lookup built from pairs. Writing that as an empty list plus a loop plus `append` takes several lines and hides the intent. A comprehension says "a list of this, for each item, where this is true" in one readable line, and the generator form does it without holding everything in memory.

## How it works

```python
result = [expr for item in iterable if condition]
#         ^^^^ what to keep   ^^^^ source    ^^^^ optional filter
```

1. Python loops over the iterable.
2. It applies the `if` filter (if present) and keeps items that pass.
3. It evaluates `expr` for each kept item and collects the results into the chosen type.

Swap the brackets to change the output: `[]` list, `{}` set, `{k: v}` dict, `()` lazy generator.

## Example

```python
orders = [{"name": "pen", "qty": 2}, {"name": "ink", "qty": 0}, {"name": "pad", "qty": 5}]
names = [o["name"] for o in orders if o["qty"] > 0]   # list
by_qty = {o["name"]: o["qty"] for o in orders}        # dict
total = sum(o["qty"] for o in orders)                 # generator, no list built
print(names, by_qty, total)
```

```text output
['pen', 'pad'] {'pen': 2, 'ink': 0, 'pad': 5} 7
```

What to notice: the list comprehension filtered out the zero-qty order with its `if`. The dict comprehension built a name-to-qty map. The generator expression inside `sum` streamed the quantities without building an intermediate list, which matters for large data.

## Rules and defaults

- The `if` goes at the end and filters; an `if/else` before the `for` chooses the value instead.
- `[]` builds a list, `{}` a set, `{k: v}` a dict, `()` a generator expression.
- A generator expression is lazy and consumed once: no indexing, no `len()`, one pass.
- The loop variable does not leak out of the comprehension into the surrounding scope.

## Not to be confused with

A generator expression `(..)` looks like a list comprehension but builds nothing up front and is consumed after one pass. Rule: use a list comprehension when you need the full list; use a generator expression for large or streamed data read once. See [List comprehension vs Generator expression](compare:list-comp-vs-generator-expr).

## Common mistakes

- **Expecting `(..)` to be a tuple.** It is a generator expression; use `tuple(...)` for a tuple.
- **Reusing a generator.** After one loop it is exhausted and yields nothing more.
- **Cramming heavy logic in.** A deeply nested comprehension is harder to read than a plain loop; keep it simple.

## Interview Qs

### What is a list comprehension?

A one-line way to build a list from an iterable: `[expr for item in iterable if condition]`. It loops, optionally filters with the `if`, and collects `expr` for each kept item. It is clearer than an empty list plus a loop with `append`.

### How do you build a dict with a comprehension?

Use the `{key: value for ...}` form, for example `{o["name"]: o["qty"] for o in orders}`. It loops over the iterable and inserts each key-value pair, with an optional `if` to filter.

### What is the difference between a list comprehension and a generator expression?

Square brackets build the whole list in memory at once, so you can index and reuse it. Parentheses make a generator expression that yields one item at a time, uses little memory, has no length, and is consumed after one pass. Use it for large or streamed data.
