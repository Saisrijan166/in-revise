## What it is

The **Method Resolution Order (MRO)** is the fixed sequence of classes Python searches when it looks up a method or attribute on an object. With [inheritance](card:inheritance), and especially multiple inheritance, more than one class could supply a method, so Python needs one definite order. It builds this order with an algorithm called **C3 linearisation**, and `super()` uses it to decide which class comes next.

## Why it exists

With multiple inheritance, a "diamond" can form: `D` inherits `B` and `C`, both of which inherit `A`. Which `A`-provided method wins, and does `A` get searched once or twice? Without a rule this is ambiguous and error-prone. The MRO gives a single, predictable order where every class appears exactly once and every child comes before its parents, so method lookup and `super()` chains are consistent.

## How it works

<Mermaid chart="classDiagram
  A <|-- B
  A <|-- C
  B <|-- D
  C <|-- D" alt="A diamond: A is the base; B and C both inherit A; D inherits both B and C." />

1. Python computes the MRO with C3 linearisation when the class is defined.
2. For `class D(B, C)` the order is `D, B, C, A, object`.
3. A lookup walks this list and stops at the first class that has the method.
4. `super()` in any method calls the next class in the MRO after the current one.

## Example

```python
class A:
    def who(self): return "A"
class B(A):
    def who(self): return "B -> " + super().who()
class C(A):
    def who(self): return "C -> " + super().who()
class D(B, C): pass

print([c.__name__ for c in D.__mro__])
print(D().who())
```

```text output
['D', 'B', 'C', 'A', 'object']
```

Then `D().who()` returns `"B -> C -> A"`. What to notice: `D.__mro__` lists each class once, children before parents. In `B.who`, `super()` goes to `C` (the next in the MRO), not straight to `A`, which is why `A` is searched only once.

## Rules and defaults

- Read the order with `ClassName.__mro__` (a tuple) or `ClassName.mro()` (a list).
- Each class appears exactly once; a subclass always precedes its base classes.
- `object` is always last.
- If no consistent C3 order exists, the class definition raises `TypeError`.
- `issubclass(D, A)` and `isinstance(obj, A)` are consistent with the MRO.

## Common mistakes

- **Reading super() as the direct parent.** It is the next class in the MRO.
- **Calling base __init__ methods by name** in multiple inheritance, which can run a shared base twice.
- **Designing deep diamonds** that produce an inconsistent MRO and a `TypeError` at definition.

## Interview Qs

### What is the MRO?

The Method Resolution Order is the fixed order in which Python searches classes to find a method or attribute. It is built by C3 linearisation, so each class appears once and children come before parents. Inspect it with `Cls.__mro__`.

### How does super() relate to the MRO?

`super()` does not call a fixed parent; it calls the next class in the current object's MRO after the current class. This threads a call through all bases consistently, ensuring each runs once in multiple inheritance.

### How do you view a class's MRO?

Use `ClassName.__mro__`, which returns a tuple of classes in search order, or `ClassName.mro()`, which returns the same as a list. `help(ClassName)` also shows it.
