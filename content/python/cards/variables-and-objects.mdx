## What it is

In Python a variable is a name bound to an object. The object lives in memory and holds the actual data; the name is just a label that refers to it. Everything you use, numbers, strings, lists, functions and even classes, is an object with an identity, a type and a value. Assigning `b = a` binds the name `b` to the same object `a` refers to; it does not make a copy.

## Why it exists

A simple, uniform model, "names refer to objects", lets one rule explain all assignment, argument passing and return values. You never declare a type for a name, so code stays short, and the same name can refer to different objects over its life. The cost is that two names can share one mutable object, so a change through one name is visible through the other.

## How it works

<Mermaid chart="flowchart LR
  A[name: a] --> O((list object [1, 2]))
  B[name: b] --> O" alt="Two names, a and b, both pointing at one shared list object" />

1. An object is created in memory when you write a literal like `[1, 2]`.
2. Assignment binds a name to that object; several names can bind to the same one.
3. Rebinding a name (`a = "hi"`) points it at a new object and leaves the old one alone.

## Example

```python
order = {"item": "apple", "qty": 2}
same = order            # binds another name to the SAME dict
same["qty"] = 5
print(order["qty"])     # changed through "same"
x = 10
x = "ten"               # the name now points at a str
print(x)
```

```text output
5
ten
```

What to notice: `same = order` did not copy the dict, so editing through `same` changed `order` too. The name `x` happily moves from an `int` to a `str`, which is dynamic binding at work.

## Rules and defaults

- Assignment never copies; it binds a name to an existing object.
- `a, b = 1, 2` and `a = b = 0` bind multiple names in one statement.
- A name must be bound before use, or Python raises `NameError`.

## Common mistakes

- **Expecting b = a to copy.** For mutable objects, both names share edits; copy explicitly when needed.
- **Thinking types are fixed.** A name can be rebound to any type at any time.
- **Confusing rebinding with mutating.** `a = [...]` rebinds the name; `a.append(x)` mutates the shared object.

## Interview Qs

### Is a Python variable a value or a reference?

A reference: the name refers to an object in memory. Assignment binds the name to the object without copying, so multiple names can refer to the same object.

### What does "everything is an object" mean?

Every value, from an integer to a function or a class, is an object with an identity, a type and a value. That is why you can store functions in lists, pass classes as arguments, and call methods on literals.

### Does Python pass arguments by value or by reference?

Neither exactly; it passes the object reference by value. The function gets a new name bound to the same object, so mutating a mutable argument is visible to the caller, but rebinding the parameter is not.
