## What it is

These three built-ins make [loops](card:loops) cleaner. `range(start, stop, step)` produces a sequence of integers, where `stop` is excluded. `enumerate(iterable)` pairs each item with its position, so you get the index without a manual counter. `zip(a, b, ...)` walks several iterables at once, giving one item from each per pass. All three are lazy: they yield values as you loop rather than building a full list.

## Why it exists

Plain loops often need the same extras: a run of numbers, an index alongside each item, or two lists walked together. Writing those by hand with counters and indexing is noisy and error-prone. `range`, `enumerate` and `zip` express each intent directly, so `for i, name in enumerate(orders):` or `for id, amount in zip(ids, amounts):` reads as exactly what it does.

## How it works

1. `range(start, stop, step)`: yields `start`, `start+step`, ... while below `stop` (above it when `step` is negative). `stop` is never produced.
2. `enumerate(iterable, start=0)`: yields `(count, item)`, with `count` beginning at `start`.
3. `zip(*iterables)`: yields a tuple of one item from each, and stops when the shortest runs out; `strict=True` (Python 3.10+) raises `ValueError` if lengths differ.

## Example

```python
ids = [101, 102, 103]
amounts = [12, 40]
for i, (oid, amt) in enumerate(zip(ids, amounts), start=1):
    print(i, oid, amt)
```

```text output
1 101 12
2 102 40
```

What to notice: `zip` pairs `ids` with `amounts` but stops at the shorter list, so `103` is dropped. `enumerate(..., start=1)` numbers the pairs from `1`. One loop reads an index and two lists together with no manual counter or indexing.

## Rules and defaults

| What | Default | Where |
|---|---|---|
| `range` stop | excluded | Python 3+ |
| `range` step | `1`; may be negative | Python 3+ |
| `enumerate` start | `0` | Python 3+ |
| `zip` length | stops at the shortest | Python 3+ |
| `zip(..., strict=True)` | raises on unequal lengths | Python 3.10+ |

## Common mistakes

- Expecting `range(1, 5)` to include `5`. The stop is excluded; it yields `1, 2, 3, 4`.
- Looping `for i in range(len(x)): x[i]` instead of `for i, item in enumerate(x):`.
- Forgetting `zip` silently drops extra items from longer iterables; use `strict=True` to catch mismatches.

## Interview Qs

### Why does range(stop) not include stop?

`range` is half-open: it starts at `0` (or `start`) and yields values up to but not including `stop`. This makes `range(len(x))` cover exactly the valid indices `0 .. len(x)-1`, and lengths add up cleanly.

### How do you loop with both the index and the value?

Use `enumerate`: `for i, item in enumerate(items):`. It yields `(index, item)` pairs, with the index starting at `0` by default or at any `start` you pass. This is cleaner than indexing with `range(len(items))`.

### What happens when zip gets iterables of different lengths?

By default `zip` stops at the shortest, dropping the extra items from longer ones. Since Python 3.10 you can pass `strict=True` to raise a `ValueError` when the lengths differ, which catches accidental mismatches.
