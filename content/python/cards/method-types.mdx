## What it is

A class can hold three kinds of method. An **instance method** is the default: its first parameter is `self`, the object it was called on, so it uses one object's data. A **class method**, marked `@classmethod`, takes `cls`, the class itself, and is the usual way to write alternative constructors. A **static method**, marked `@staticmethod`, takes neither `self` nor `cls`; it is a plain function grouped inside the class for tidiness.

## Why it exists

Not every function in a class acts on a single object. Some build objects in different ways (an `Order` from a dict, from a database row), which needs the class, not an instance. Others are helpers that just belong near the class but need no object at all. Instead of putting these outside the class or faking an unused `self`, Python gives `@classmethod` and `@staticmethod` so each method declares exactly what it works on.

## How it works

<Compare id="instance-class-static-method" />

1. Default method: first parameter `self`, uses the object.
2. Add `@classmethod` and take `cls` to work on the class, for factories.
3. Add `@staticmethod` and take no special first parameter for a utility.
4. `cls` refers to the actual class called on, so factories work correctly for subclasses.

## Example

```python
class Order:
    tax = 0.1
    def __init__(self, amount):
        self.amount = amount
    def total(self):                 # instance: uses self
        return self.amount * (1 + Order.tax)
    @classmethod
    def free(cls):                   # factory: builds an Order
        return cls(0)
    @staticmethod
    def valid(amount):               # utility: no self/cls
        return amount >= 0

print(Order(100).total(), Order.free().amount, Order.valid(-5))
```

```text output
110.00000000000001 0 False
```

What to notice: `total` reads one object via `self`. `free` is a factory using `cls`, so a subclass would build its own type. `valid` touches no object or class state, so it is static.

## Rules and defaults

- Instance methods can read both instance and class data; class methods read class data; static methods read neither directly.
- `@classmethod` and `@staticmethod` can be called on the class or an instance.
- A class method's `cls` is the actual class the call was made on, which is what makes factory methods subclass-safe.
- Omitting `@staticmethod` on a no-`self` function makes it fail when called on an instance (it would receive the instance as the first argument).

## Common mistakes

- **Using a static method that then needs the object.** Make it an instance method instead.
- **Hard-coding the class name** in a factory instead of `cls`, breaking subclasses.
- **Forgetting @staticmethod** on a utility, so calling it on an instance passes the instance in unexpectedly.

## Interview Qs

### When would you use a classmethod?

For alternative constructors (factory methods) and logic that works on class-level data. It takes `cls`, so returning `cls(...)` builds the correct type even for subclasses, for example `Order.from_dict(data)`.

### Difference between a static method and a plain function?

Behaviour is the same, but a static method lives inside the class namespace, grouping a related helper with the class. It takes no `self` or `cls`. A plain function sits at module level.

### Can a static method access instance attributes?

No. It receives neither `self` nor `cls`, so it cannot reach instance or class state directly. If it needs the object, it should be an instance method; if it needs the class, a class method.
