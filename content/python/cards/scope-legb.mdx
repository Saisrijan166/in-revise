## What it is

A scope is the region where a name is visible. When you use a name, Python searches four scopes in order, the **LEGB** rule: **Local** (names in the current function), **Enclosing** (names in an outer function that wraps it), **Global** (names at the top level of the module), and **Built-in** (names like `len` and `print`). The first match wins. The `global` statement lets a function rebind a module-level name, and `nonlocal` lets a nested function rebind a name in its nearest enclosing function.

## Why it exists

Functions need their own private names so a variable in one function does not clash with one in another. LEGB gives each name a clear, predictable place to be found, and keeps locals separate by default. But sometimes a function really must change a shared outer variable, like a counter. `global` and `nonlocal` make that intent explicit, so changing an outer name is a deliberate choice, not an accident.

## How it works

  U[Use a name] --> L[Local]

1. Python looks for the name Local first, then Enclosing, Global, and Built-in.
2. The first scope that has the name wins; a local can shadow a global of the same name.
3. Assigning a name inside a function makes it local for that whole function, unless you declared it `global` or `nonlocal`.

## Example

```python
count = 0                 # global

def add():
    global count          # rebind the module-level name
    count += 1

add(); add()
print(count)
```

```text output
2
```

What to notice: without `global count`, the `count += 1` would treat `count` as local, read it before assignment, and raise `UnboundLocalError`. Declaring `global count` tells Python to rebind the module-level name, so the two calls raise it to 2.

## Rules and defaults

| What | Behaviour |
|---|---|
| Lookup order | Local, Enclosing, Global, Built-in |
| Assigning a name | makes it local for the whole function |
| `global x` | assignments to `x` rebind the module-level `x` |
| `nonlocal x` | assignments to `x` rebind `x` in the nearest enclosing function |
| Reading an outer name | works with no keyword; only rebinding needs `global`/`nonlocal` |

## Common mistakes

- **Assuming you can assign to a global freely.** Assignment makes a local; reading before it raises `UnboundLocalError`. Declare `global` to rebind the module name.
- **Using `global` for an enclosing (not module) name.** `global` only reaches the module level; use `nonlocal` for an outer function's variable.
- **Shadowing a built-in.** Naming a variable `list` or `len` hides the built-in in that scope and breaks later calls.

## Interview Qs

### What is the LEGB rule?

The order Python searches for a name: Local, then Enclosing (outer functions), then Global (module level), then Built-in. The first scope that defines the name wins, which is why a local variable can shadow a global or built-in of the same name.

### What is the difference between global and nonlocal?

`global` makes assignments inside a function rebind a name at the module (global) level. `nonlocal` makes them rebind a name in the nearest enclosing function, used in closures. `nonlocal` cannot reach the module level, and `global` cannot reach an enclosing function.

### Why does assigning to a variable you only meant to read raise UnboundLocalError?

Because any assignment to a name inside a function makes that name local for the entire function. Reading it before the assignment finds no local value yet, so Python raises `UnboundLocalError`. Declare it `global` or `nonlocal` to use the outer name.
