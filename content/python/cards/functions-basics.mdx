## What it is

A function is a named, reusable block of code. You create one with the `def` keyword, give it a name and a list of parameters, and write its body indented below. **Parameters** are the names listed in the definition; **arguments** are the real values you pass when you call it. Inside the body, `return` hands a value back to the caller and stops the function. The first line of the body may be a string, called a docstring, that describes what the function does.

## Why it exists

The same steps often need to run many times with different values, like working out the total of an order. Without functions you would copy those steps everywhere, and fixing a bug would mean editing every copy. A function writes the logic once and lets you call it by name with different arguments, so the code stays short and changes in one place.

## How it works

<Steps>
  <Step title="Define">`def order_total(price, qty):` names the function and its parameters.</Step>
  <Step title="Body">The indented lines do the work using the parameter names.</Step>
  <Step title="Return">`return price * qty` sends a value back and ends the function.</Step>
  <Step title="Call">`order_total(50, 3)` runs the body with those arguments and evaluates to 150.</Step>
</Steps>

1. Calling the function runs its body with the arguments bound to the parameters.
2. `return` ends the function and gives its value to the caller.
3. If the body finishes with no `return`, the call still gives back `None`.

## Example

```python
def order_total(price, qty):
    "Total for one order line."
    return price * qty

def show_total(price, qty):
    print(price * qty)      # displays, but no return

a = order_total(50, 3)      # a = 150
b = show_total(50, 3)       # prints 150, b = None
print(a, b)
```

```text output
150
150 None
```

What to notice: `order_total` returns a number, so `a` holds 150 and can be reused. `show_total` only prints; it has no `return`, so `b` is `None`. The two look identical on screen, but only the returned value can be stored and used later.

## Rules and defaults

| What | Behaviour |
|---|---|
| Missing `return` | The function returns `None` |
| `return` with no value | Same as returning `None`, and ends the function |
| Docstring | The first string in the body; shown by `help(func)` and stored in `func.__doc__` |
| Calling | Arguments are matched to parameters left to right |

## Common mistakes

- **Printing instead of returning.** `print(x)` shows a value but the caller gets `None`. Use `return` when you need the value later.
- **Expecting code after `return` to run.** `return` ends the function immediately; lines below it are never reached.
- **Forgetting the parentheses.** `order_total` is the function object; `order_total(50, 3)` actually calls it.

## Interview Qs

### What is the difference between a parameter and an argument?

A parameter is a name in the function definition, like `price` in `def order_total(price, qty)`. An argument is the actual value you pass when calling, like `50` in `order_total(50, 3)`. Parameters receive arguments.

### What does a function return if it has no return statement?

It returns `None`. Every Python function returns something; with no `return`, or a bare `return`, that value is `None`. This is why assigning the result of a print-only function gives `None`.

### What is a docstring?

A string written as the first line of a function body. It documents the function and is stored in `__doc__`, shown by `help()`. Tools and IDEs read it, so it is the standard way to describe what a function does.
