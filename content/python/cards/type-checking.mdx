## What it is

Python gives you three tools to inspect an object. `type(x)` returns the object's exact class. `isinstance(x, C)` returns `True` if `x` is an instance of class `C` or any subclass of it, and it accepts a tuple of classes to test several at once. `id(x)` returns the object's identity, a number unique for the object while it exists (in CPython, its memory address). Together they answer "what is this?" and "is this the same object?".

## Why it exists

Because Python is dynamically typed, code often needs to check what it received before acting. `isinstance` lets you accept a type and all its subclasses, which keeps inheritance and [polymorphism](card:polymorphism) working. `type` comparison is stricter and rejects subclasses, which is occasionally what you want but usually a bug. `id` lets you tell whether two names point at the same object, which underlies the `is` operator.

## How it works

The `isinstance`-versus-`type` difference is shown side by side in [this comparison](compare:type-vs-isinstance).

1. `type(x)` returns the class; `type(x) == C` is `True` only for an exact match.
2. `isinstance(x, C)` is `True` for `C` or any subclass; `isinstance(x, (A, B))` tests a tuple.
3. `id(x)` returns the identity; `x is y` is a shortcut for `id(x) == id(y)`.

## Example

```python
print(type(5))
print(isinstance(5, int))
print(isinstance(True, int))   # bool is a subclass of int
print(type(True) == int)       # exact match fails
```

```text output
<class 'int'>
True
True
False
```

What to notice: `isinstance(True, int)` is `True` because `bool` subclasses `int`, but `type(True) == int` is `False` because the exact class is `bool`. This is exactly why `isinstance` is the recommended check: it respects the inheritance you usually want.

## Rules and defaults

- `isinstance` is the recommended way to check types; `type() ==` is for the rare "exact class only" case.
- `isinstance(x, (A, B, C))` accepts a tuple and is `True` if `x` matches any of them.
- `id(x)` is unique only among live objects; a freed object's id can be reused later.

## Common mistakes

- **Using type() == C for input checks.** It rejects valid subclasses; prefer `isinstance`.
- **Comparing ids across runs.** `id` values are not stable between program runs and mean nothing persistent.
- **Forgetting the bool/int relationship.** `isinstance(True, int)` is `True`; exclude bool explicitly if you must.

## Interview Qs

### Why is isinstance() preferred over type()?

`isinstance` returns `True` for the class or any subclass, so it respects inheritance and keeps polymorphic code working. `type(x) == C` matches only the exact class and silently rejects valid subclasses.

### What does id() return?

The object's identity: an integer unique for that object while it lives. In CPython it is the memory address. The `is` operator compares identities, so `x is y` is effectively `id(x) == id(y)`.

### How do you check if a value is one of several types?

Pass a tuple to `isinstance`: `isinstance(x, (int, float))` is `True` if `x` is an int or a float (or a subclass). This is cleaner than chaining several `type` comparisons.
