## What it is

A `lambda` is a small anonymous function, meaning a function with no name, written inline. Its body is a single expression, and the value of that expression is returned automatically, with no `return` keyword. `lambda x: x * 2` is the same as a `def` that takes `x` and returns `x * 2`. Lambdas are most useful where a function needs to be passed as an argument, such as the `key` of `sorted` or the callback of `map` and `filter`.

## Why it exists

Often a function is needed only once, in one spot, like "sort these orders by their total". Writing a full `def` with a name for such a throwaway helper adds noise and a name that is never reused. A lambda lets you write that one-expression function right where it is used, keeping the logic next to the call that needs it.

## How it works

<Steps>
  <Step title="Write it">`lambda o: o['total']` takes `o` and returns its total.</Step>
  <Step title="Pass it">Hand it to `sorted(orders, key=...)` as the key function.</Step>
  <Step title="Each call">`sorted` calls the lambda on every order to get its sort value.</Step>
  <Step title="Result">Orders come back sorted by total, no named helper left behind.</Step>
</Steps>

1. The lambda is an ordinary function object; it just has no name.
2. The single expression after the colon is evaluated and returned on each call.
3. It captures variables from the surrounding scope, like any nested function.

## Example

```python
orders = [{"item": "book", "total": 30},
          {"item": "pen", "total": 10}]

cheapest_first = sorted(orders, key=lambda o: o["total"])
print([o["item"] for o in cheapest_first])
```

```text output
['pen', 'book']
```

What to notice: `lambda o: o["total"]` is a tiny function that pulls out each order's total. `sorted` calls it on every order and orders them by that value, so the pen (10) comes before the book (30). No separate named function was needed.

## Rules and defaults

| What | Behaviour |
|---|---|
| Body | exactly one expression; its value is returned |
| Statements | not allowed (no `if` blocks, loops, assignments, `return`) |
| Arguments | supports defaults, `*args`, `**kwargs`, like `def` |
| Name | none; `__name__` is `'<lambda>'` |
| When to prefer `def` | any multi-step logic or anything you reuse |

## Common mistakes

- **Cramming logic in.** A lambda holds one expression. A conditional expression `a if cond else b` is fine, but loops and assignments are not; switch to `def`.
- **Assigning a lambda to a name.** `f = lambda x: x` works but defeats the purpose and hurts tracebacks; just use `def f(x)`.
- **Late binding in a loop.** `[lambda: i for i in range(3)]` all return 2; capture with a default `lambda i=i: i`.

## Interview Qs

### What is a lambda and when would you use one?

A lambda is an anonymous, one-expression function. Use it for a short throwaway function passed as an argument, such as the `key` of `sorted`, or a callback for `map` or `filter`, where defining a named function would be overkill.

### What can a lambda not do that a def can?

A lambda's body is a single expression, so it cannot hold statements: no assignments, loops, `if` blocks or multiple lines. It also has no name. For anything with multiple steps, use a named `def`.

### Is a lambda faster or different from a normal function?

No. A lambda produces the same kind of function object as `def`; it is only a syntax for defining one inline without a name. There is no performance difference.
