## What it is

**Polymorphism** means the same method name produces different behaviour depending on the object. It appears two ways in Python. Through [overriding](card:inheritance), each class in a hierarchy gives its own version of a method. Through **duck typing**, Python calls a method on any object that has it, without checking the object's class ("if it quacks like a duck, treat it as one"). Python has no traditional **method overloading** by signature.

## Why it exists

You often want one piece of code to handle many types the same way: charge every payment, draw every shape. Without polymorphism you would write `if`/`elif` on the type and branch for each one. Instead, you call a shared method name and let each object supply its own behaviour. New types plug in without touching the calling code, which keeps it loosely coupled.

## How it works

1. Several classes define a method with the same name (say `pay`).
2. Calling `obj.pay()` runs the version belonging to that object's class.
3. Duck typing means the loop never checks the class, only that `pay` exists.
4. For flexible arguments, use defaults or `*args`, since a second `def` of the same name just replaces the first.

## Example

```python
class UpiPayment:
    def pay(self): return "paid by UPI"

class CardPayment:
    def pay(self): return "paid by card"

for p in [UpiPayment(), CardPayment()]:
    print(p.pay())        # each object's own pay runs
```

```text output
paid by UPI
paid by card
```

What to notice: the loop calls `pay()` without knowing or caring which class each object is. Different objects respond differently to the same call, and the two classes share no base class, which duck typing allows.

## Rules and defaults

- Method lookup is dynamic: the object's actual class decides which method runs.
- Duck typing checks for the method at call time, not the class.
- A second `def` with an existing name in the same class overwrites the first; there is no overload resolution.
- For varying arguments, use default values, `*args`/`**kwargs`, or `functools.singledispatch`.

## Not to be confused with

Overriding and overloading sound alike but differ. Overriding is a child replacing a parent method of the same name and signature; it is real in Python. Overloading is defining several methods with the same name but different signatures; Python does not support it. Rule: vary behaviour by class with overriding; vary call shape with default or variadic arguments.

## Common mistakes

- **Expecting overloading.** Two methods with the same name leave only the last.
- **Checking type with isinstance everywhere** instead of relying on duck typing.
- **Assuming polymorphism needs a shared base class.** Duck typing needs only the method to exist.

## Interview Qs

### What is duck typing?

Python decides what an object can do by whether it has the needed method or attribute, not by its class. If an object has a `pay()` method, code can call it, regardless of type. "If it quacks like a duck, treat it as a duck."

### Does Python support method overloading?

No. Defining two methods with the same name keeps only the last one. To accept different argument shapes, use default arguments, `*args`/`**kwargs`, or `functools.singledispatch`.

### How is overriding different from overloading?

Overriding is a subclass replacing an inherited method with the same name and signature, and Python supports it. Overloading is several same-named methods with different signatures, which Python does not support.
