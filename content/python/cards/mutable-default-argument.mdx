## What it is

When you write a function with a default value, like `def f(x, items=[])`, Python evaluates that default expression once, at the moment the `def` statement runs, and stores the resulting object on the function. Every call that omits the argument reuses that same object. If the default is mutable, like a list or dict, all those calls share one object, so changes made in one call are still there in the next. This surprises almost everyone the first time.

## Why it exists

This is not a special rule for defaults; it follows from a general Python rule: an expression in a `def` line is evaluated when the function is defined, not each time it is called. That keeps definition cheap and predictable. The side effect is that a mutable default becomes shared state. The trap exists because the intuitive reading ("fresh list each call") clashes with how Python actually binds defaults.

## How it works

1. Python runs the `def` statement and evaluates each default value once.
2. It stores those default objects on the function (`f.__defaults__`).
3. Each call that omits the argument reuses the stored object, so a mutable default accumulates changes.

## Example

```python
def add_order(item, cart=[]):   # trap: one shared list
    cart.append(item)
    return cart

print(add_order("apple"))
print(add_order("milk"))        # expected ["milk"], but...
```

```text output
['apple']
['apple', 'milk']
```

What to notice: the second call did not start with an empty cart. The default list was created once and reused, so `"apple"` is still in it. The list grows with every call that omits `cart`.

## Rules and defaults

- Default values are evaluated once, when the `def` runs; they are not re-evaluated per call.
- The safe pattern is a `None` sentinel:

```python
def add_order(item, cart=None):
    if cart is None:
        cart = []           # fresh list every call
    cart.append(item)
    return cart
```

- Immutable defaults (`0`, `""`, `None`, a tuple) never cause this, because they cannot be changed in place.

## Common mistakes

- **Using [] or {} as a default.** It is shared across calls; use `None` and build inside.
- **"Fixing" it with cart = cart.** That rebinds nothing useful; the default is still the shared object.
- **Thinking it only bites lists.** Any mutable default (dict, set, custom object) has the same bug.

## Interview Qs

### Why does a function with a mutable default argument "remember" old values?

Because the default is evaluated once, at definition time, and the same object is reused on every call that omits the argument. Mutating it (appending to a list) persists into later calls.

### How do you fix the mutable default argument problem?

Default the parameter to `None`, then inside the function check `if arg is None: arg = []`. This creates a fresh object on each call, so calls no longer share state.

### Are immutable defaults affected?

No. Immutable defaults like `0`, `""` or `None` cannot be changed in place, so there is nothing to accumulate. The problem is specific to mutable defaults such as lists, dicts and sets.
