## What it is

**Encapsulation** means bundling an object's data with the methods that use it, and signalling which parts are internal. Python does this with naming, not access control: a plain `name` is public, a leading underscore `_name` means "internal, please leave alone", and a double leading underscore `__name` triggers **name mangling**, renaming it to `_Class__name`. A [property](term:property) lets you add getter and setter logic behind plain attribute syntax.

## Why it exists

You want callers to use an object through a stable interface and not depend on its internals, so you can change those internals later. Marking attributes as internal tells readers what is safe to use. Python chooses convention over enforcement: there is no real `private`, because the language trusts developers ("we are all consenting adults"). Name mangling exists for one concrete reason, to stop a subclass accidentally overwriting a base class's attribute.

## How it works

| Form | Meaning | Enforced? |
|---|---|---|
| `name` | Public: part of the normal interface | n/a |
| `_name` | Internal by convention | No |
| `__name` | Name-mangled to `_Class__name` | No (just renamed) |
| `property` | Managed attribute with get/set logic | Logic runs, syntax stays plain |

1. Use a plain name for anything callers should use.
2. Prefix with `_` to mark it internal.
3. Prefix with `__` only to avoid clashes in subclass hierarchies.
4. Reach for `property` when a value needs validation or computation.

## Example

```python
class Order:
    def __init__(self, total):
        self.id = "A1"       # public
        self._status = "new"  # internal by convention
        self.__total = total  # mangled to _Order__total

o = Order(100)
print(o.id, o._status)
print(o._Order__total)        # still reachable
```

```text output
A1 new
100
```

What to notice: `o.__total` would fail, but the value is only renamed, so `o._Order__total` reads it. The underscores communicate intent; they do not lock anything. Public `id` and internal `_status` are both freely accessible.

## Rules and defaults

- One leading underscore is pure convention; nothing stops access.
- Two leading underscores (with at most one trailing) trigger name mangling inside the class body.
- `__dunder__` names (two leading and two trailing) are not mangled; they are special methods.
- Use `property` to validate or compute without changing how callers write `obj.x`.

## Common mistakes

- **Expecting __name to be unreachable.** It is just `_Class__name`.
- **Using __name for ordinary privacy.** Mangling is for avoiding subclass clashes; `_name` is the normal "internal" marker.
- **Writing get_x()/set_x() methods** when a `property` gives the same control with cleaner attribute syntax.

## Interview Qs

### Does Python have private variables?

Not truly. A single underscore marks an attribute as internal by convention, and a double underscore triggers name mangling to `_Class__name`. Neither blocks access; Python signals intent rather than enforcing it like Java.

### What is name mangling?

Inside a class, an attribute named `__x` is rewritten to `_ClassName__x`. This prevents a subclass from accidentally overriding a base class's attribute of the same name. It is not a security or access-control feature.

### When would you use property?

When a value needs validation, computation, or read-only access but you want callers to keep plain attribute syntax like `order.price`. A `property` runs your getter or setter on each access.
