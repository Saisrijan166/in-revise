## What it is

`map`, `filter` and `reduce` run a function over a sequence in three ways. `map(fn, items)` applies `fn` to every item and gives back the transformed items. `filter(fn, items)` keeps only the items for which `fn` returns true. `reduce(fn, items)` combines items pairwise into one value, like a running total. In Python 3, `map` and `filter` return *lazy* iterators, so you wrap them in `list()` to get the results; `reduce` lives in the `functools` module.

## Why it exists

These express a common shape — transform, select, or accumulate over a collection — in one clear line, often with a [lambda](card:lambda). `map` and `filter` being lazy means they can feed large or streamed data without building an intermediate list. Knowing they are iterators (not lists) avoids the classic surprise of printing a `map` object or consuming it twice by mistake.

## How it works

```python
from functools import reduce

totals = [100, 250, 50]
doubled = list(map(lambda t: t * 2, totals))        # transform each
big = list(filter(lambda t: t >= 100, totals))      # keep matching
grand = reduce(lambda a, b: a + b, totals)          # fold into one
print(doubled, big, grand)
```

```text output
[200, 500, 100] [100, 250] 400
```

What to notice: `map` and `filter` are wrapped in `list()` to materialise them; without that they stay lazy iterators. `reduce` walks left to right, keeping a running accumulator (100, then 350, then 400). A list comprehension often replaces `map`/`filter` more readably.

## Rules and defaults

- `map` and `filter` return lazy, one-pass iterators; consume them once, via `list()`, a loop, or `sum()`.
- `filter(None, items)` keeps the truthy items.
- `map` can take several iterables: `map(fn, a, b)` calls `fn(a_i, b_i)` and stops at the shortest.
- `reduce` is not a built-in; import it from `functools`. Pass a third argument as the starting value for empty-safe folds.

## Common mistakes

- Printing or returning a `map`/`filter` object and expecting the values — wrap it in `list()`.
- Reusing a `map`/`filter` result after it was already consumed; it is empty the second time.
- Forgetting `from functools import reduce`, or using `reduce` where a plain `sum()`/`max()` is clearer.

## Interview Qs

### Do map and filter return lists in Python 3?

No. They return lazy iterators (`map` and `filter` objects) that produce values on demand and are consumed once. Wrap them in `list()` (or loop over them) to materialise the results. Python 2's versions returned lists, which is a common source of confusion.

### What does reduce do and where is it?

`reduce(fn, items)` folds a sequence into one value by applying `fn` cumulatively: `fn(fn(a, b), c)`, and so on. It is used for totals, products or custom accumulation. It is not a built-in — import it with `from functools import reduce`.

### When would you prefer a comprehension over map/filter?

When readability matters and the transform or test is simple. `[t*2 for t in totals if t >= 100]` is often clearer than nested `map`/`filter` with lambdas, and it directly produces a list. Use `map`/`filter` for existing named functions or lazy pipelines.
