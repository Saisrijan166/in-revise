## What it is

**File handling** is reading from and writing to files on disk. The built-in `open(path, mode)` returns a *file object*; the `mode` string says what you may do and how. Wrapping it in a [with](card:context-managers) block, `with open(path) as f:`, closes the file automatically when the block ends, even if the body raises. You read with `read()`, `readline()` or `readlines()`, write with `write()`, or loop over the file to get its lines one at a time.

## Why it exists

Programs need to save and reload data that outlives one run: orders, logs, config, exports. An open file is a limited OS resource, so forgetting to close it can leak handles or leave writes unflushed. `with open(...)` solves this by guaranteeing the close, and the different modes stop accidents — `x` refuses to clobber an existing file, while `w` and `a` make the overwrite-versus-append choice explicit.

## How it works

```python
# write two orders, then read them back
with open("orders.txt", "w") as f:
    f.write("book\n")
    f.write("pen\n")

with open("orders.txt") as f:      # mode defaults to "r"
    for line in f:                 # lazy, one line at a time
        print(line.strip())
```

```text output
book
pen
```

What to notice: the first `with` opens in `"w"`, so it starts from an empty file and writes two lines. The second opens in the default read mode and loops the file lazily, printing each stripped line. Both files close automatically at the end of their blocks.

## Rules and defaults

| Mode | Meaning |
|---|---|
| `r` | Read (default); the file must exist |
| `w` | Write; creates the file, or truncates it to empty first |
| `a` | Append; creates if missing, writes at the end |
| `x` | Create new; fails with `FileExistsError` if it exists |
| `b` / `t` | Binary vs text; text is the default and uses an encoding |

- The default is text mode (`str`); binary mode (`rb`, `wb`) reads and writes `bytes`.
- Always use `with` (or call `close()`); otherwise buffered writes may not reach disk.
- `read()` returns the whole file, `readline()` one line, `readlines()` a list of lines; looping the file is the memory-light option.

## Common mistakes

- Using `"w"` expecting to add text — it erases the file first; use `"a"` to append.
- Not using `with` and forgetting `close()`, so writes stay buffered or handles leak.
- Reading a huge file with `read()` or `readlines()` instead of looping it line by line.

## Interview Qs

### Why use with open() instead of open() and close()?

`with open(...)` is a context manager: it closes the file automatically when the block ends, even if an exception is raised inside. Manual `open()`/`close()` leaks the handle whenever an error skips the `close()`. `with` makes the cleanup guaranteed.

### What is the difference between modes w and a?

`"w"` truncates the file to empty on open, so old content is lost before you write. `"a"` keeps the existing content and writes at the end. Use `"a"` for logs or any append-only output.

### How do you read a large file without using too much memory?

Loop over the file object: `for line in f:`. It reads one line at a time lazily, so memory stays roughly constant. Avoid `read()` and `readlines()`, which load the entire file into memory at once.
