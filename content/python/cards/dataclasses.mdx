## What it is

A **dataclass** is a class marked with the `@dataclass` decorator from the `dataclasses` module. You list fields as typed annotations, and the decorator auto-generates the boilerplate methods: `__init__` (a constructor taking each field), `__repr__` (a readable representation) and `__eq__` (field-by-field equality). It is designed for [classes](card:class-and-object) whose main purpose is to carry data, such as an order or a config record.

## Why it exists

A plain data-holding class forces you to hand-write a constructor that assigns each field, a `__repr__` for debugging, and an `__eq__` so two equal records compare equal. That is repetitive and easy to get wrong. `@dataclass` writes all of it from the field list, so the class stays short and its intent — "this holds these fields" — is obvious. It also gives value equality for free, which plain classes lack.

## How it works

```python
from dataclasses import dataclass

@dataclass
class Order:
    item: str
    qty: int = 1          # field with a default

a = Order("book", 2)
b = Order("book", 2)
print(a)
print(a == b)             # value equality
```

```text output
Order(item='book', qty=2)
True
```

What to notice: no `__init__` or `__repr__` was written, yet `Order("book", 2)` constructs and prints cleanly. `a == b` is `True` because the generated `__eq__` compares fields, not object identity. A plain class would print an address and compare `a == b` as `False`.

## Rules and defaults

- `@dataclass` generates `__init__`, `__repr__` and `__eq__` by default.
- Fields with defaults must come after fields without them, like function arguments.
- Mutable defaults must use `field(default_factory=list)` (or `dict`, `set`); a bare `[]` is shared and raises an error for known mutable types.
- Options include `@dataclass(frozen=True)` for immutable, read-only instances, and `order=True` to add comparison methods.

## Common mistakes

- Giving a field a mutable default like `[]` or `{}` directly instead of `field(default_factory=...)`.
- Placing a field with a default before one without — this is a syntax error.
- Expecting a dataclass to validate types; the annotations are hints only and are not enforced.

## Interview Qs

### What does @dataclass generate for you?

From the typed fields it generates `__init__`, `__repr__` and `__eq__` automatically. That removes the boilerplate constructor, the debug representation, and value-based equality you would otherwise write by hand for a data-holding class.

### How is dataclass equality different from a normal class?

A normal class's `__eq__` defaults to identity, so two separate instances are unequal even with the same data. A dataclass generates `__eq__` that compares all fields, so two instances with equal fields compare equal.

### How do you give a dataclass field a list default safely?

Use `field(default_factory=list)` from `dataclasses`. A bare `items: list = []` would be shared across all instances, like the mutable-default-argument trap. `default_factory` runs per instance, giving each its own fresh list.
