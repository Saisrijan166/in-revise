## What it is

A web framework is a library that handles the repetitive parts of a web app: routing a URL to your code, reading the request, and returning a response. The three you meet most in Python are **Django**, **Flask** and **FastAPI**. They differ in how much they give you by default and whether they are built for async.

## Why it exists

Writing a web server by hand means re-solving the same problems: matching URLs, parsing form data, talking to a database, validating input. A framework packages these so you write only the parts unique to your app. The choice matters because each one trades off convenience against control: more built-in features mean faster start but stronger conventions.

## How it works

<Compare id="django-flask-fastapi" />

1. **Django** ships an ORM, admin site, auth and migrations, so a database-backed site works with little setup but you follow its structure.
2. **Flask** gives routing and a request object; you add the database layer, validation and extensions yourself.
3. **FastAPI** reads your Python type hints with Pydantic to validate each request and build interactive OpenAPI docs automatically, and runs on async (ASGI).

## Rules and defaults

| What | Default | Where |
|---|---|---|
| Server model | WSGI (sync) | Django, Flask |
| Server model | ASGI (async) | FastAPI |
| Request validation | Manual / forms | Flask, Django |
| Request validation | Pydantic from type hints | FastAPI |

Django added ASGI/async support over its 4.x and 5.x releases, so it can run async views too.

## Common mistakes

- **Choosing FastAPI only for speed.** Pick it for typed APIs and auto docs; a CPU-bound task still blocks the event loop.
- **Reaching for Django for a tiny service.** Its structure is overkill when you need two endpoints; Flask or FastAPI is lighter.
- **Forgetting FastAPI needs an ASGI server** such as Uvicorn to run, not a plain WSGI one.

## Interview Qs

### When would you choose Flask over Django?

For a small or focused app where I want to pick each piece myself (database, validation, auth). Flask gives routing and little else, so there is less to learn and less imposed structure than Django's batteries-included stack.

### What makes FastAPI's validation special?

It reuses your Python type hints. A Pydantic model on the request body both validates incoming JSON and documents the schema, and FastAPI turns that into interactive OpenAPI (Swagger) docs with no extra code.

### Are Django and Flask async?

They are WSGI frameworks and run synchronously by default. Django has added async view support over recent releases. FastAPI is async-first (ASGI) from the start, which suits many concurrent I/O-bound requests.
