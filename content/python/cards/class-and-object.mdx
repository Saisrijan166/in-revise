## What it is

A **class** is a blueprint that describes what data an object holds (**attributes**) and what it can do (**methods**). An **object** is one concrete thing built from that blueprint, with its own attribute values. Inside a method, `self` is the object the method was called on. The special method `__init__` runs when you create an object and sets up its starting attributes.

## Why it exists

Without classes you would pass the same loose variables (an order's id, items and total) into every function by hand, and nothing would keep them together. A class bundles related data and the functions that act on it into one type. You then build many independent objects from it, each carrying its own values, instead of juggling parallel variables.

## How it works

<Steps>
  <Step title="Define the class">Write `class Order:` with methods inside it, including `__init__`.</Step>
  <Step title="Create an object">Call `Order("A1")`. Python makes a new instance and passes it to `__init__` as `self`.</Step>
  <Step title="__init__ sets attributes">`self.id = id` stores data on that specific object.</Step>
  <Step title="Call methods">`o.total()` runs `total` with `o` bound to `self`, so it reads that object's data.</Step>
</Steps>

## Example

```python
class Order:
    def __init__(self, id, items):
        self.id = id        # attribute on this object
        self.items = items

    def count(self):        # method; self is the current order
        return len(self.items)

o = Order("A1", ["pen", "book"])
print(o.id, o.count())
```

```text output
A1 2
```

What to notice: `Order("A1", ["pen", "book"])` creates one object and runs `__init__` with it as `self`. The attributes `id` and `items` live on that object, so `o.count()` reads `o`'s own items. A second order would have its own separate values.

## Rules and defaults

- `self` is passed automatically; you never pass it yourself in `o.count()`.
- `__init__` must not `return` a value (other than `None`); it only sets up the instance.
- Attributes set with `self.x = ...` are per-object; variables set directly in the class body are shared by all objects.
- `self` is a convention, not a keyword, but always use it.

## Common mistakes

- **Forgetting self in a method signature.** `def count():` fails with a "takes 0 positional arguments" error when called on an object.
- **Thinking self is a keyword.** It is just the first parameter's name.
- **Returning a value from __init__.** It should only initialise; returning anything but `None` raises `TypeError`.

## Interview Qs

### What is the difference between a class and an object?

A class is a blueprint that defines attributes and methods. An object is a concrete instance built from that class, holding its own attribute values. One class can produce many independent objects.

### What is self in Python?

`self` is the current instance, passed automatically as the first parameter of an instance method. It lets the method read and change that object's attributes. It is a naming convention, not a keyword.

### What does __init__ do?

`__init__` is called right after an object is created and initialises its attributes, for example `self.id = id`. It is commonly called the constructor, though technically it initialises an instance that `__new__` has already created.
