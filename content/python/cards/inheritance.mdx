## What it is

**Inheritance** lets a new class (the **child** or subclass) reuse the attributes and methods of an existing class (the **parent** or base). The child can add new methods, and it can **override** a parent method to give its own version. Inside an overriding method, [super()](card:class-and-object) calls the parent's version following the [MRO](card:mro). It models an is-a relationship: a `PriorityOrder` is an `Order`.

## Why it exists

Many types share behaviour. Without inheritance you would copy the shared code into each class and keep every copy in sync by hand. Inheritance puts common attributes and methods in one base class and lets specific types extend it, overriding only what differs. This removes duplication and makes a group of related types easy to treat uniformly.

## How it works

1. Write `class PriorityOrder(Order):` to inherit everything from `Order`.
2. Add or override methods in the child.
3. Call `super().method(...)` to run the parent's version and extend it.
4. Build child objects; they respond to both inherited and new methods.

## Example

```python
class Order:
    def __init__(self, amount):
        self.amount = amount
    def total(self):
        return self.amount

class PriorityOrder(Order):
    def total(self):               # override
        return super().total() + 50  # reuse parent, add fee

print(PriorityOrder(100).total())
```

```text output
150
```

What to notice: `PriorityOrder` inherits `__init__` from `Order`, so it needs no constructor of its own. Its `total` overrides the parent's but calls `super().total()` to reuse the base amount, then adds the fee, instead of copying the parent's logic.

## Rules and defaults

- A class with no explicit base implicitly inherits from `object`.
- Inheritance types: **single** (one parent), **multiple** (several parents), **multilevel** (grandparent to parent to child), **hierarchical** (many children of one parent), **hybrid** (a mix).
- In an overriding `__init__`, call `super().__init__(...)` so the parent sets up its part.
- `super()` follows the MRO, not a fixed parent name.

## Not to be confused with

Inheritance is an **is-a** relation; composition is a **has-a** relation where one object holds another. A `Car` is not an `Engine`, so give it an engine attribute rather than inheriting. Rule: inherit only when the child truly is a kind of the parent; otherwise compose.

## Common mistakes

- **Using inheritance for has-a.** A `Car` should hold an `Engine`, not inherit from it.
- **Calling the parent by name** instead of `super()`, which breaks with multiple inheritance.
- **Forgetting super().__init__** in a child's `__init__`, leaving parent attributes unset.

## Interview Qs

### What is method overriding?

A child class defines a method with the same name as one in its parent, replacing the parent's behaviour for objects of the child. Calling the method on a child object runs the child's version.

### What does super() do?

`super()` returns a proxy that calls the next class's method in the [MRO](card:mro), usually the parent. It is used to extend a parent method (for example `super().__init__(...)`) without naming the parent class directly.

### What are the types of inheritance in Python?

Single (one parent), multiple (several parents), multilevel (a chain), hierarchical (many children of one parent), and hybrid (a combination). Python supports all of them, resolving methods through the MRO.
