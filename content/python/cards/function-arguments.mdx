## What it is

Python matches arguments to parameters in two ways. **Positional** arguments match by order. **Keyword** arguments match by name, like `order(qty=3)`, so order does not matter. A **default** gives a parameter a fallback value used when the caller leaves it out. For a variable number of arguments, `*args` collects any extra positional values into a tuple and `**kwargs` collects any extra named values into a dict. The single and double stars do the collecting; the names `args` and `kwargs` are only a convention.

## Why it exists

A function often has one required value and several optional ones, and sometimes an unknown number of inputs. Defaults let callers skip the common options. Keyword arguments let them pass values by name, which is clearer than remembering an order. `*args` and `**kwargs` let one function accept any number of positional or named arguments, which is how wrappers and flexible APIs pass whatever they are given straight through.

## How it works

<Compare id="args-vs-kwargs" />

1. In a call, positional arguments fill parameters left to right, then keyword arguments fill the rest by name.
2. Any parameter with a default may be omitted.
3. In the signature the order is: normal positional, then `*args`, then keyword-only params, then `**kwargs`.
4. Extra positional values land in the `*args` tuple; extra named values land in the `**kwargs` dict.

## Example

```python
def make_order(item, qty=1, *extras, **options):
    return item, qty, extras, options

print(make_order("book"))
print(make_order("book", 2, "gift", "urgent", wrap=True))
```

```text output
('book', 1, (), {})
('book', 2, ('gift', 'urgent'), {'wrap': True})
```

What to notice: in the first call only `item` is given, so `qty` uses its default `1` and both `extras` and `options` are empty. In the second, `2` sets `qty`, the extra positional values collect into the `extras` tuple, and `wrap=True` collects into the `options` dict.

## Rules and defaults

| What | Behaviour |
|---|---|
| Signature order | positional, `*args`, keyword-only, `**kwargs` |
| `*args` | the extra positional arguments, as a tuple (empty if none) |
| `**kwargs` | the extra keyword arguments, as a dict (empty if none) |
| Unpacking | `f(*mylist, **mydict)` spreads a list and dict back into a call |
| Default evaluated | once, when the `def` runs (watch mutable defaults) |

## Common mistakes

- **Thinking the names matter.** `*items` and `**opts` behave exactly like `*args` and `**kwargs`. The stars do the work.
- **A positional argument after a keyword one.** `f(x=1, 2)` is a syntax error; keyword arguments come last.
- **Using a mutable default** like `def f(x=[])`. The list is created once and shared across calls; use `None` and create it inside.

## Interview Qs

### What is the difference between *args and **kwargs?

`*args` collects extra positional arguments into a tuple; `**kwargs` collects extra keyword arguments into a dict of name to value. Together they let a function accept any number of positional and named arguments. The stars matter, not the names.

### What does the star do in a function call like f(*mylist)?

In a call it unpacks: `f(*mylist)` spreads the list items into separate positional arguments, and `f(**mydict)` spreads a dict into keyword arguments. The same `*` and `**` both collect in a definition and spread in a call.

### Why avoid a mutable default argument such as def f(x=[])?

The default is created once when the function is defined and reused on every call, so changes to the list persist between calls. Use `x=None` and set `x = []` inside the function instead.
