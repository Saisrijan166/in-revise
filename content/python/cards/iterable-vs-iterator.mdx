## What it is

An **iterable** is any object you can loop over, such as a list, string, dict, set or [range](card:loops). When you ask it for an iterator with the built-in `iter()`, it gives one back. An **iterator** is the object that actually walks through the items: calling `next()` on it returns the next item and moves forward, remembering where it stopped. When nothing is left, `next()` raises `StopIteration`.

## Why it exists

A `for` loop must work the same way over a list, a file, a dict or a range, without knowing how each one stores data. Splitting the roles solves this: every collection only has to hand back an iterator, and every iterator only has to answer `next()`. Without this shared protocol, each container would need its own loop syntax, and lazy sources like files or [generators](card:generators) could not be looped at all.

## How it works

<Steps>
  <Step title="Get the iterator">`iter(orders)` returns a fresh iterator positioned before the first item.</Step>
  <Step title="Pull an item">`next(it)` returns the next order and advances the position.</Step>
  <Step title="Pull again">Each `next(it)` call gives the following item; the iterator holds the state.</Step>
  <Step title="Run out">When no items remain, `next(it)` raises `StopIteration`, which a for-loop catches to end quietly.</Step>
</Steps>

1. A `for x in orders` loop does these steps for you: it calls `iter()` once, then `next()` repeatedly.
2. The iterable can be reused; each `iter()` call gives a new, independent iterator.

## Example

```python
orders = ["book", "pen"]     # a list: iterable, not an iterator
it = iter(orders)            # ask for its iterator
print(next(it))
print(next(it))
print(next(it))              # nothing left
```

```text output
book
pen
Traceback (most recent call last):
StopIteration
```

What to notice: `orders` itself never steps; `iter()` returns a separate `it` that does. The third `next()` runs past the end and raises `StopIteration`. A `for` loop over `orders` would stop silently instead of raising, because it handles that exception internally.

## Rules and defaults

- `iter(obj)` needs `obj` to define `__iter__` (or the older `__getitem__`); otherwise it raises `TypeError`.
- An iterator's `__iter__` returns itself, so every iterator is also an iterable.
- Calling `iter()` twice on a list gives two independent iterators; calling `iter()` on an iterator returns the same, already-advanced one.

## Not to be confused with

A [generator](card:generators) is a specific, easy way to build an iterator using `yield`. Rule: iterator is the protocol (any class with `__next__`); a generator is one common implementation of it.

## Common mistakes

- Calling `next()` directly on a list, dict or string — they are iterables, not iterators.
- Expecting `StopIteration` to crash a `for` loop. The loop is built to catch it and stop.
- Assuming you can loop an iterator twice. Once exhausted, it stays empty; get a new one with `iter()`.

## Interview Qs

### What is the difference between an iterable and an iterator?

An iterable can return an iterator via `iter()` and may be looped many times. An iterator is the stateful object that yields one item per `next()` call and raises `StopIteration` when done. Every iterator is iterable, but not every iterable is an iterator.

### How does a for loop actually work internally?

It calls `iter()` on the iterable once to get an iterator, then calls `next()` on that iterator repeatedly, binding each result to the loop variable. When `next()` raises `StopIteration`, the loop ends without showing an error.

### Can you call next() on a list?

No. A list is iterable but not an iterator, so it has no `__next__`. You first do `it = iter(my_list)`, then `next(it)`. Calling `next()` on the list directly raises `TypeError`.
