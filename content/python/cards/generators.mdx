## What it is

A **generator** is a function that uses `yield` instead of `return`. Calling it does not run the body; it returns a *generator object*, which is an [iterator](card:iterable-vs-iterator). Each time you call `next()` on it (or loop over it), the body runs up to the next `yield`, produces that value, and pauses with every local variable preserved. The next `next()` resumes right after that `yield`. This makes values arrive lazily, one at a time.

## Why it exists

Building a full list of results wastes memory when the sequence is huge, streamed, or endless. Reading a million orders from a file into a list needs space for all million; a generator yields one order at a time, so memory stays flat no matter the size. Generators also let you express infinite sequences (page after page) and stop early without computing values you never use.

## How it works

```python
def read_orders(path):
    with open(path) as f:
        for line in f:
            yield line.strip()   # hand out one order, then pause
```

1. `read_orders("orders.txt")` returns a generator object and opens nothing yet.
2. The first `next()` runs the body until the first `yield`, returning one order line.
3. Each later `next()` resumes after the `yield` and reads the next line lazily.
4. When the file ends, the function returns, which raises `StopIteration` to stop any loop.

## Example

```python
def first_totals():
    yield 100
    yield 250

g = first_totals()
print(next(g))
print(next(g))
```

```text output
100
250
```

What to notice: `first_totals()` returns `g` without running any `yield`. The first `next(g)` runs to `yield 100` and pauses; the second resumes and runs to `yield 250`. A third `next(g)` would raise `StopIteration`, because the function has no more code to run.

## Rules and defaults

- A generator is created the moment any `yield` appears in a function body.
- State (locals, loop position) is frozen at each `yield` and restored on resume.
- A generator is a one-shot iterator: after it is exhausted it stays empty; call the function again for a fresh one.
- `yield from sub` delegates to another iterable, forwarding all its values.

## Not to be confused with

A [list comprehension](compare:list-comp-vs-generator-expr) `[x for x in xs]` builds the whole list in memory now; a generator expression `(x for x in xs)` is lazy like a generator. Rule: square brackets are eager, round brackets are lazy.

## Common mistakes

- Expecting body code (like a print or a DB call) to run at call time. It runs only when the generator is pulled.
- Looping a generator twice and finding it empty the second time.
- Using a generator where you need random access or `len()` — it supports neither; convert with `list()` first if required.

## Interview Qs

### What does yield do?

`yield` returns a value from a generator and pauses the function, saving all local state. The next `next()` call resumes execution right after the `yield`. This lets the function produce a sequence lazily, one value per request, instead of all at once.

### Why are generators memory-efficient?

They hold only the current item and their paused state, not the whole sequence. Processing a huge or infinite stream (like lines of a big file) uses roughly constant memory, whereas building a list would need space for every element at once.

### Can you iterate over a generator twice?

No. A generator is a one-pass iterator. After it is exhausted, looping again yields nothing. To iterate again, call the generator function once more to get a new generator object.
