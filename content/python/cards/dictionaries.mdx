## What it is

A dictionary (`dict`) maps keys to values, written as `{"qty": 3, "price": 50}`. Each key is unique and must be [hashable](card:sets); values can repeat and be any type. You look up a value by its key in about O(1) using hashing. Since Python 3.7 a dict keeps the order in which keys were inserted.

## Why it exists

Lists find things by position, but real data is usually looked up by name: an order by its id, a price by a product code, a count by a word. A dict gives direct key-to-value lookup without scanning, so it stays fast as data grows. It is Python's workhorse for structured records (like one order), caches and counts, and it underlies objects and keyword arguments.

## How it works

<Compare id="list-set-dict" />

1. Create with `{key: value, ...}` or `dict(...)`; keys must be hashable and unique.
2. Read with `d[key]` (raises `KeyError` if missing) or `d.get(key, default)` (safe).
3. Loop with the views: `d.keys()`, `d.values()`, `d.items()`; iterating the dict itself yields keys.

## Example

```python
order = {"id": "A1", "qty": 3, "price": 50}
order["total"] = order["qty"] * order["price"]   # add a key
print(order.get("discount", 0))                  # safe: default 0
for key, value in order.items():
    print(key, value)
```

```text output
0
id A1
qty 3
price 50
total 150
```

What to notice: assigning to a new key `"total"` adds it. `get("discount", 0)` returns the default `0` without raising, unlike `order["discount"]`. Looping with `items()` gives key-value pairs, and they come out in insertion order, which dicts guarantee since Python 3.7.

## Rules and defaults

| What | Behaviour |
|---|---|
| Missing key with `d[k]` | raises `KeyError` |
| Missing key with `d.get(k)` | returns `None`, or the default you pass |
| Key rule | must be hashable and unique; a list cannot be a key |
| Values | any type; may repeat |
| Order | insertion order kept since Python 3.7 |

## Common mistakes

- **Using `d[key]` for maybe-missing keys.** It raises `KeyError`. Use `get` or check `key in d`.
- **Trying a list as a key.** Lists are unhashable; use a tuple of hashables instead.
- **Relying on sort order before 3.7.** Only 3.7+ guarantees insertion order; for sorted output, use `sorted(d.items())`.

## Interview Qs

### What is the difference between d[key] and d.get(key)?

`d[key]` returns the value but raises `KeyError` if the key is absent. `d.get(key)` returns `None` (or a default you pass, like `d.get(key, 0)`) instead of raising. Use `get` when the key may be missing.

### Do dictionaries keep order?

Yes, since Python 3.7 a dict preserves insertion order as a language guarantee (it was an implementation detail in 3.6). Earlier versions did not guarantee any order.

### What can be a dictionary key?

Any hashable, unique object: numbers, strings, and tuples whose items are hashable. Mutable objects like lists or sets are unhashable and raise `TypeError` when used as keys.
