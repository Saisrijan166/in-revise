## What it is

`collections` is a standard-library module with specialised container types that go beyond the built-in [list](card:lists) and [dict](card:dictionaries). The common four are **Counter** (counts how often each item appears), **defaultdict** (a dict that creates a default value for a missing key), **deque** (a double-ended queue with fast adds and removes at both ends), and **namedtuple** (a tuple whose positions have names). They solve frequent tasks that plain containers do awkwardly.

## Why it exists

Some patterns come up constantly: counting items, grouping values by key, using a queue, or giving tuple fields readable names. Doing these with a plain dict or list means repetitive code (checking if a key exists before appending) or hidden slowness (removing from the front of a list is O(n)). `collections` provides tuned types that make the code shorter and fast, so you reach for the right tool instead of rebuilding it.

## How it works

```python
from collections import Counter, defaultdict, deque, namedtuple

items = ["apple", "pear", "apple", "fig", "apple"]
print(Counter(items).most_common(1))     # top item

groups = defaultdict(list)               # missing key -> new list
groups["fruit"].append("apple")
print(groups)

q = deque([1, 2, 3])
q.appendleft(0)                          # O(1) at the front
print(q.popleft())                       # O(1) remove from front

Point = namedtuple("Point", "x y")
print(Point(2, 5).x)
```

```text output
[('apple', 3)]
defaultdict(<class 'list'>, {'fruit': ['apple']})
0
2
```

What to notice: `Counter` tallies in one call, `defaultdict(list)` creates the list for a new key so `append` just works, `deque` adds and removes at the front in O(1), and `namedtuple` lets you read `.x` instead of index `[0]`.

## Rules and defaults

- `Counter` returns 0 for a missing item instead of raising `KeyError`.
- `defaultdict(factory)` calls the factory (like `list` or `int`) the first time a key is accessed.
- `deque` gives O(1) `append`/`appendleft`/`pop`/`popleft`; indexing in the middle is O(n).
- `OrderedDict` is seldom needed since plain dicts keep insertion order (Python 3.7+).

## Common mistakes

- Using `list.pop(0)` as a queue (O(n)); use `deque.popleft()` (O(1)).
- Counting with a plain dict and manual `if key in d` checks instead of `Counter` or `defaultdict`.
- Expecting a `namedtuple` to be mutable; it is a tuple, so fields cannot be reassigned.

## Interview Qs

### When would you use defaultdict over a plain dict?

When you group or accumulate values by key. `defaultdict(list)` creates an empty list for a missing key automatically, so you can append without checking if the key exists first, avoiding `KeyError` and boilerplate.

### Why use deque instead of a list for a queue?

`deque.popleft()` and `appendleft()` are O(1), while `list.pop(0)` and `insert(0, x)` are O(n) because every element shifts. For a FIFO queue at scale, deque is much faster.

### Do you still need OrderedDict?

Rarely. Plain dicts keep insertion order since Python 3.7. OrderedDict only adds a few order-specific methods like `move_to_end`, so most code can just use a normal dict.
