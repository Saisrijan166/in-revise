## What it is

A **module** is a single `.py` file holding reusable code: functions, classes, and variables. A **package** is a folder of modules grouped under a name; it usually has an `__init__.py`, though a namespace package can leave it out. You bring names from a module into your file with `import`. Every module has a `__name__` variable, which Python sets to `"__main__"` when the file is run directly and to the module's name when it is imported.

## Why it exists

A program split into small files is easier to read, reuse, and test than one giant file. Modules let you keep related code together and import just what you need elsewhere. Packages scale that up to many files under one namespace. The `__name__` check lets one file work both as a reusable module and as a runnable script, without its script code firing every time something imports it.

## How it works

```python
# orders.py
def total(order):
    return sum(order)

if __name__ == "__main__":      # only when run directly
    print(total([10, 20, 30]))
```

```python
# shop.py
import orders                   # does NOT print; just defines total
from orders import total        # bring one name in
import orders as o              # alias
print(total([5, 5]))
```

```text output
10
```

What to notice: running `orders.py` prints `60` because `__name__` is `"__main__"`. Importing it from `shop.py` does not print, because `__name__` is then `"orders"`, so the guarded block is skipped; only `total` is defined.

## Rules and defaults

- Importing a module runs its top-level code once; later imports reuse the cached module.
- `__name__` is `"__main__"` only when the file is run directly.
- A package needs `__init__.py` to be a regular package; without it, it can still work as a namespace package.
- Prefer `import x` or `from x import y`; avoid `from x import *` in application code.

## Common mistakes

- Leaving script code unguarded, so it runs on import.
- Using `from x import *`, which hides where names come from and can clash.
- Confusing a module (one file) with a package (a folder of modules).

## Interview Qs

### What is the difference between a module and a package?

A module is a single `.py` file of reusable code. A package is a folder of modules under one namespace, usually with an `__init__.py` (a namespace package can omit it). You import from both the same way.

### What does `if __name__ == "__main__":` do?

It runs the block only when the file is executed directly, because `__name__` is then `"__main__"`. When the file is imported, `__name__` is the module's name, so the block is skipped. It keeps script code from firing on import.

### Why avoid `from module import *`?

It pulls in every public name, so you cannot tell where a name came from and it can silently overwrite names you already have. Explicit imports keep code clear and avoid clashes.
