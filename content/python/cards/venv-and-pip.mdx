## What it is

A virtual environment (**venv**) is an isolated folder holding one project's Python packages, separate from the system Python and from other projects. **pip** is Python's package installer; it downloads packages from **PyPI** (the Python Package Index) into whichever environment is active. A **requirements.txt** file lists the exact packages and versions a project needs, so anyone can recreate the same environment.

## Why it exists

Different projects often need different versions of the same library. If everything installs into one shared Python, upgrading a package for one project can break another. A venv gives each project its own private set of packages, so their versions never clash. requirements.txt makes that set reproducible: a teammate or a server can rebuild the exact environment from one command.

## How it works

```bash
python -m venv venv            # create the environment
source venv/bin/activate       # activate (Windows: venv\Scripts\activate)
pip install requests           # installs into THIS venv only
pip freeze > requirements.txt  # record exact versions
```

```bash
# on another machine, in a fresh venv:
pip install -r requirements.txt
deactivate                     # leave the environment
```

What to notice: `python -m venv venv` makes the folder, and activating it points `pip` and `python` at that folder. Installs now stay local to the project. `pip freeze` writes the pinned versions, and `pip install -r` rebuilds the identical set anywhere.

## Rules and defaults

| What | Default | Where |
|---|---|---|
| venv tool | built in | `python -m venv` (stdlib) |
| Package source | PyPI | pip default index |
| Install scope | active environment | after activation |
| Lock file name | `requirements.txt` | convention |

- Without an active venv, pip installs globally or to the user site, which projects then share.
- Activation must be repeated in each new shell session.

## Common mistakes

- Running `pip install` before activating the venv, so packages go global.
- Committing the `venv/` folder to Git instead of `requirements.txt`.
- Forgetting to re-run `pip install -r requirements.txt` after cloning, then hitting missing-module errors.

## Interview Qs

### What problem does a virtual environment solve?

It isolates one project's dependencies from other projects and the system Python. Each project gets its own package versions, so upgrading a library for one project cannot break another.

### How do you share a project's dependencies with a teammate?

Run `pip freeze > requirements.txt` to record the installed packages and versions, commit that file, and have the teammate run `pip install -r requirements.txt` inside a fresh venv to rebuild the same set.

### What is the difference between pip and venv?

`venv` creates and isolates an environment. `pip` installs packages into whichever environment is active. venv decides where packages live; pip puts them there.
