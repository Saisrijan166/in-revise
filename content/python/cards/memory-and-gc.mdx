## What it is

Python manages memory for you, so you never free objects by hand. CPython, the standard implementation, uses reference counting: each object keeps a count of how many references point to it. When that count drops to zero, the object is destroyed and its memory reclaimed at once. Reference counting alone cannot free objects that reference each other in a cycle, so a separate cyclic garbage collector (the `gc` module) periodically finds and clears those cycles.

## Why it exists

Manual memory management (as in C) is powerful but error-prone: forget to free and you leak memory; free too early and you crash. Automatic reclamation removes that whole class of bugs. Reference counting frees objects promptly, the moment they are no longer used, which keeps memory tight. The cyclic collector exists to catch the one case counting misses: two or more objects that keep each other alive even though nothing else references them.

## How it works

1. Binding a name to an object raises its reference count; losing a reference lowers it.
2. When the count reaches zero, CPython frees the object immediately.
3. The cyclic collector scans for groups that reference only each other and reclaims them.

## Example

```python
import sys
a = [1, 2, 3]
b = a                 # second reference to the same list
print(sys.getrefcount(a) >= 2)
del a                 # removes the name a, not the list
print(b)              # list still alive through b
```

```text output
True
[1, 2, 3]
```

What to notice: `b = a` gives the list a second reference. `del a` only removes the name `a`; the list survives because `b` still points at it, so its count is not zero. The object is freed only when the last reference goes.

## Rules and defaults

- Reference counting is a CPython detail; PyPy and Jython use different garbage collectors.
- The cyclic collector runs automatically; `gc.collect()` forces a pass, `gc.disable()` turns the cycle collector off (counting still runs).
- `del x` unbinds the name; it frees the object only if that was the last reference.

## Common mistakes

- **Thinking del frees memory.** It removes a name; the object lives until no references remain.
- **Assuming reference counting is the language.** It is CPython's strategy, not a Python rule.
- **Ignoring cycles.** Two objects referencing each other need the cyclic collector; counting alone will not free them.

## Interview Qs

### How does CPython manage memory?

Mainly by reference counting: each object counts its references, and when the count reaches zero the object is freed immediately. A separate cyclic garbage collector reclaims objects trapped in reference cycles that counting cannot free.

### What does the del statement do?

It removes a name binding. The object it referred to is freed only if that was its last reference. So `del` controls names, not object lifetime directly.

### Why does Python need a cyclic garbage collector if it has reference counting?

Reference counting cannot free a cycle: if two objects reference each other, each keeps the other's count above zero even when nothing else uses them. The cyclic collector detects such groups and reclaims them.
