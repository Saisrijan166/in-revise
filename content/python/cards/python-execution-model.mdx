## What it is

The execution model is the path your code takes from a `.py` file to output. CPython, the standard implementation, first compiles the source into bytecode: a compact, low-level instruction set that the Python Virtual Machine (PVM) understands. The bytecode is cached in `.pyc` files inside a `__pycache__` folder so unchanged modules are not recompiled. The PVM then runs the bytecode instruction by instruction.

## Why it exists

Running source text directly every time would be slow and would repeat the same parsing work on every run. Compiling once to bytecode, then running that on a virtual machine, keeps Python portable (the same bytecode runs anywhere the VM runs) while avoiding repeated compilation. Caching the bytecode means importing a large module a second time skips the compile step entirely.

## How it works

<Steps>
  <Step title="Write source">You save a `.py` file of Python statements.</Step>
  <Step title="Compile to bytecode">CPython parses and compiles the module to bytecode, cached as a `.pyc` in `__pycache__`.</Step>
  <Step title="Run on the PVM">The Python Virtual Machine reads the bytecode and executes each instruction.</Step>
  <Step title="Produce output">Side effects (printing, files, network) happen as the VM runs.</Step>
</Steps>

1. Imported modules are compiled and cached; the top-level script you run is compiled but not cached.
2. CPython is written in C; PyPy, Jython and others run the same language differently.
3. The REPL runs one statement at a time and prints each result.

## Rules and defaults

| What | Default | Where |
|---|---|---|
| Reference implementation | CPython | written in C |
| Bytecode cache | `__pycache__/*.pyc` | since Python 3.2 |
| Faster alternative | PyPy (JIT compiler) | separate download |
| JVM alternative | Jython | runs on the JVM |

The GIL is a CPython detail, not a language rule; PyPy's free-threaded work and other implementations differ. The optional free-threaded CPython build is officially supported from Python 3.14 (PEP 779), but it is opt-in, not the default.

## Common mistakes

- **Thinking .pyc is machine code.** It is portable bytecode; only the VM runs it.
- **Assuming the GIL is part of Python.** It belongs to CPython's standard build, not the language.
- **Editing files in __pycache__.** They are generated; delete them freely, they rebuild.

## Interview Qs

### What is the PVM?

The Python Virtual Machine is the runtime loop inside CPython that reads compiled bytecode and executes each instruction. It is what actually runs your program after the source has been compiled to bytecode.

### What is the difference between CPython, PyPy and Jython?

CPython is the standard implementation in C that compiles to bytecode and interprets it. PyPy adds a just-in-time compiler for speed. Jython compiles Python to JVM bytecode so it runs on the Java platform.

### What is a .pyc file?

A cached file of compiled bytecode stored in `__pycache__`. On import, if the source is unchanged, CPython reuses the `.pyc` and skips recompiling, which speeds up startup.
