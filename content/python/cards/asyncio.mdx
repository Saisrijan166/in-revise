## What it is

`asyncio` is Python's standard library for asynchronous, single-threaded concurrency. You write a **coroutine** with `async def`. Calling it returns a coroutine object that does not run yet. Inside it, `await` on an **awaitable** (another coroutine, a task, or a future) suspends the coroutine until that awaitable is ready. An **event loop** drives all the coroutines on one thread, switching whenever one awaits. `asyncio.run(main())` creates the loop, runs `main()`, and closes the loop.

## Why it exists

Threads can overlap I/O waits, but each thread uses memory and needs locks for shared state. For thousands of mostly-waiting connections, that gets expensive and error-prone. asyncio overlaps the same waits on a single thread with no locks, because only one coroutine runs at a time and it yields control explicitly at each `await`. This makes high-concurrency I/O servers cheap and the code easy to reason about.

## How it works

<Steps>
  <Step title="Define">Write coroutines with async def; awaitables sit inside them.</Step>
  <Step title="Start the loop">asyncio.run(main()) starts one event loop on one thread.</Step>
  <Step title="await">A coroutine hits await and suspends, handing the loop back.</Step>
  <Step title="Switch">The loop runs another ready coroutine; when the awaited result arrives, the first resumes.</Step>
</Steps>

## Example

```python
import asyncio

async def pack(order_id):
    await asyncio.sleep(1)          # yields; other coroutines run
    print(f"order {order_id} packed")

async def main():
    await asyncio.gather(pack(1), pack(2), pack(3))

asyncio.run(main())
```

```text output
order 1 packed
order 2 packed
order 3 packed
```

What to notice: `asyncio.gather` runs the three coroutines concurrently on one thread. Each `await asyncio.sleep(1)` yields, so the three one-second waits overlap and the whole thing takes about one second, not three. No threads are created.

## Rules and defaults

- `async def` returns a coroutine that only runs when awaited or scheduled on the loop.
- `await` suspends the current coroutine; it does not start a thread or use another core.
- One event loop runs per thread; `asyncio.run()` is the usual entry point.
- A blocking call (`time.sleep`, heavy CPU, a sync DB driver) stalls the whole loop; offload it with `asyncio.to_thread()` or a process pool.

## Not to be confused with

**Threading** uses several OS threads with pre-emptive switching; **asyncio** uses one thread with cooperative switching at `await`. Rule: asyncio gives concurrency on one thread; it never gives CPU parallelism.

## Common mistakes

- Calling a blocking function inside a coroutine, freezing the whole loop.
- Thinking `await` spawns a thread or runs code in parallel; it only yields control.
- Forgetting to `await` a coroutine, so it never runs (and often warns "coroutine was never awaited").

## Interview Qs

### What do async and await do?

`async def` defines a coroutine. `await` suspends the coroutine until the awaitable it waits on is ready, letting the event loop run other coroutines meanwhile. When the result arrives, the coroutine resumes where it left off.

### Does asyncio use multiple threads or cores?

No. All coroutines run on one thread driven by a single event loop. It gives concurrency by overlapping I/O waits, not parallelism. For CPU parallelism you still need multiprocessing.

### When is asyncio the wrong choice?

For CPU-bound work. A heavy computation or a blocking call does not yield, so it stalls the single event-loop thread and freezes every other coroutine. Use threads or processes for that.
