## What it is

`==` and `is` both compare two things, but they ask different questions. `==` asks "do these have the same value?" and runs the object's `__eq__` method. `is` asks "are these the exact same object in memory?" and compares each object's `id`. Two separate objects can be equal (`==` true) while not being identical (`is` false).

## Why it exists

Sometimes you care about the value, and sometimes about the object. Two different lists `[1, 2]` and `[1, 2]` hold equal data but are separate objects you can change independently. `==` lets you ask about the data; `is` lets you ask whether two names share one object. Mixing them up gives code that works by luck and then breaks on a larger value.

## How it works

<Compare id="is-vs-equals" />

1. `a == b` calls `a.__eq__(b)`, so a class can define what "equal value" means.
2. `a is b` is `True` only when `id(a) == id(b)` — one object, two names.
3. `None`, `True` and `False` are singletons: exactly one object each exists, so `is` is the correct, fast test for them.

## Example

```python
a = [1, 2]
b = [1, 2]
print(a == b, a is b)     # equal value, different objects
x = 256
y = 256
print(x is y)             # cached small int (implementation detail)
```

```text output
True False
True
```

What to notice: `a == b` is `True` because the contents match, but `a is b` is `False` because they are two separate lists. `x is y` looks `True` only because CPython caches small ints `-5` to `256`, so both names reuse one object; this is an implementation detail, not a rule you should use.

## Rules and defaults

| What | Behaviour | Where |
|---|---|---|
| `==` default | compares by identity unless `__eq__` is defined | Python 3+ |
| `is` | compares `id()` (same object) | Python 3+ |
| Small int cache | ints `-5` to `256` are interned | CPython detail |
| Test for None | always `x is None` | PEP 8 |

## Common mistakes

- Writing `if x == None`. Use `if x is None`; `None` is a singleton and `__eq__` could be overridden.
- Using `is` to compare numbers or strings and relying on interning. It is not guaranteed.
- Thinking equal objects must be identical. Equal value does not mean the same object.

## Interview Qs

### What is the difference between == and is?

`==` compares value by calling `__eq__`; `is` compares identity, meaning whether both names point to the same object (same `id`). Two equal lists are `==` but not `is`.

### Why should you write `x is None` instead of `x == None`?

`None` is a single, unique object, so identity is the exact and fastest check. `==` could be redefined by a class's `__eq__`, so `x == None` might behave unexpectedly, while `x is None` always works.

### Why can `1000 is 1000` be False but `256 is 256` True?

CPython interns small integers from `-5` to `256`, reusing one object, so `is` is `True` for them. `1000` is outside that cache, so the two may be distinct objects. Never use `is` to compare values.
