## What it is

A string (`str`) is an immutable sequence of characters, written with single or double quotes. Immutable means you cannot change a character after the string is made; any change produces a new string. Because it is a [sequence](card:builtin-data-types), you can read characters by position (indexing), take a part of it (slicing), and loop over it.

## Why it exists

Almost every program handles text: names, order ids, messages, file lines. Strings give one safe type for text with a rich set of operations. Making them immutable means a string you pass to a function cannot be changed behind your back, so text can be shared and used as a dictionary key without surprises. The cost is that building text step by step creates new strings.

## How it works

<Steps>
<Step title="Index">`s[0]` reads the first character, `s[-1]` the last. Out-of-range raises `IndexError`.</Step>
<Step title="Slice">`s[a:b:step]` returns characters from `a` up to but not including `b`. Missing parts default to start, end and step 1.</Step>
<Step title="Reverse">`s[::-1]` walks the string with a step of -1, giving it backwards.</Step>
<Step title="Format">An f-string, `f"{value}"`, inserts values into text, with optional specs like `:.2f`.</Step>
</Steps>

## Example

```python
order_id = "ORD-00042"
print(order_id[:3])        # slice: first 3 chars
print(order_id[-5:])       # slice: last 5 chars
total = 1299.5
print(f"{order_id}: Rs {total:,.2f}")   # f-string with format spec
```

```text output
ORD
00042
ORD-00042: Rs 1,299.50
```

What to notice: the end index in a slice is excluded, so `[:3]` gives three characters. `[-5:]` starts five from the end. The f-string reads values inline, and `:,.2f` adds a thousands comma and two decimals, far clearer than joining pieces by hand.

## Rules and defaults

| What | Behaviour |
|---|---|
| Item assignment | Not allowed: `s[0] = 'x'` raises `TypeError` |
| Slice end | Always excluded; `s[0:3]` is 3 characters |
| Over-slicing | Safe: `s[:999]` returns what exists, no error |
| Preferred formatting | f-strings (3.6+); `.format()` and `%` still work |

f-strings vs the older styles, one line each:

```python
name, qty = "pen", 3
print(f"{qty} x {name}")              # f-string: preferred
print("{} x {}".format(qty, name))    # str.format: older
print("%d x %s" % (qty, name))        # %: oldest, C-style
```

```text output
3 x pen
3 x pen
3 x pen
```

What to notice: all three produce the same text. f-strings read left to right with the values in place, so they are the clearest and the fastest; `.format()` and `%` are older styles you will still meet in existing code.

## Common mistakes

- **Trying to edit in place.** `s[0] = 'H'` fails. Build a new string instead.
- **Forgetting the end is excluded.** `s[0:3]` gives 3 characters, not 4.
- **Using `+` in a big loop.** Each `+` makes a new string; join a list instead: `"".join(parts)`.

## Interview Qs

### Are Python strings mutable?

No. Strings are immutable. Any operation that looks like a change, such as `s.upper()` or `s + "!"`, returns a new string and leaves the original unchanged.

### How do you reverse a string?

Slice with a step of -1: `s[::-1]`. It walks the string backwards and returns a new reversed string.

### Which string formatting style should you use?

f-strings (`f"{x}"`), available since Python 3.6. They are the most readable and the fastest. `.format()` and `%`-formatting still work and appear in older code.
