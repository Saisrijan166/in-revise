## What it is

**Abstraction** means showing what an object does through a clear interface while hiding how it does it. In Python you express a required interface with an **abstract base class (ABC)**: a class that inherits from `ABC` and marks some methods with `@abstractmethod`. Those methods have no real body; every concrete subclass must implement them. A class that still has an unimplemented abstract method cannot be instantiated.

## Why it exists

When many types must share a shape, for example every payment method needs `pay`, you want to guarantee each one provides it, and fail early if one forgets. Plain [duck typing](card:polymorphism) only fails when the missing method is actually called, perhaps in production. An ABC turns the interface into a checked contract: Python refuses to create an object that has not implemented the required methods, so the mistake surfaces at object creation.

## How it works

1. Import `ABC` and `abstractmethod` from the `abc` module.
2. Subclass `ABC` and decorate the required methods with `@abstractmethod`.
3. Any subclass must implement every abstract method to become concrete.
4. Instantiating the ABC itself, or a subclass that skipped a method, raises `TypeError`.

## Example

```python
from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount): ...

class UpiPayment(Payment):
    def pay(self, amount):
        return f"paid {amount} by UPI"

print(UpiPayment().pay(100))
```

```text output
paid 100 by UPI
```

What to notice: `Payment` cannot be created directly because `pay` is abstract. `UpiPayment` implements `pay`, so it is concrete and can be instantiated. If `UpiPayment` had omitted `pay`, calling `UpiPayment()` would raise `TypeError`.

## Rules and defaults

- The class must inherit from `ABC` (or set `metaclass=ABCMeta`); `@abstractmethod` alone does nothing.
- A class is abstract while any inherited abstract method is unimplemented, and cannot be instantiated.
- Stack `@abstractmethod` under `@property`, `@classmethod` or `@staticmethod` (with abstractmethod innermost) for abstract versions of those.
- An abstract method may still have a body that subclasses call via `super()`.

## Common mistakes

- **Marking a method abstract without inheriting ABC**, so nothing is enforced.
- **Putting @abstractmethod above @property** instead of innermost, which breaks the abstraction.
- **Expecting an abstract method to have no body ever.** It can, and `super()` can call it.

## Interview Qs

### How do you create an abstract class in Python?

Inherit from `ABC` (from the `abc` module) and decorate required methods with `@abstractmethod`. Subclasses must implement those methods. The abstract class itself cannot be instantiated.

### What happens if a subclass does not implement an abstract method?

The subclass is still considered abstract, so trying to instantiate it raises `TypeError` naming the missing method. The object cannot be created until every abstract method is implemented.

### Abstraction vs encapsulation?

Abstraction hides implementation behind an interface (what it does). [Encapsulation](card:encapsulation) bundles data with methods and controls access to internal state (how data is protected). They are complementary, not the same.
