## Why it exists

One server's RAM and CPU cap how much data and how many writes Redis takes. Cluster spreads keys over several primaries.

## How it works

<Mermaid
  alt="The client hashes each key to a slot and sends it to the owner: primary A has slots 0-5500, B 5501-11000, C 11001-16383. Each has one replica."
  chart={`flowchart LR
  C[Client] -- "slot = CRC16(key) mod 16384" --> B
  C --> A
  C --> PC
  A[(Primary A: 0-5500)] --> A1[(Replica A1)]
  B[(Primary B: 5501-11000)] --> B1[(Replica B1)]
  PC[(Primary C: 11001-16383)] --> C1[(Replica C1)]`}
/>

- A node that does not own the slot replies MOVED; cluster clients cache the slot map.
- At least 3 primaries; 3 primaries plus 3 replicas is the recommended start.
- Spring Boot: `spring.data.redis.cluster.nodes` lists seed nodes for [the client](card:spring-data-redis).

## Example

```text
CLUSTER KEYSLOT payment:PAY101                   -> (integer) 4122
MSET merchant:42:config A merchant:43:config B
-> (error) CROSSSLOT Keys in request don't hash to the same slot
MSET {merchant:42}:config A {merchant:42}:limits B   -> OK  (both slot 7650)

-- redis-cli without -c, connected to the wrong node
GET payment:PAY101   -> (error) MOVED 4122 10.0.0.1:6379
```

## Interview Qs

### How do you update two keys atomically in Cluster?

Give them one hash tag, like `{order:PAY101}:status` and `{order:PAY101}:events`. They share a slot, so MULTI/EXEC or Lua works.

### What is the difference between MOVED and ASK?

MOVED: the slot lives on another node now; update the map. ASK: the slot is migrating; send only this command there, after ASKING.

### Sentinel or Cluster?

Sentinel while one primary holds all the data; Cluster when it must be split. See [Sentinel vs Cluster](compare:sentinel-vs-cluster).
