## Why it exists

MULTI/EXEC cannot use a value it reads, and WATCH needs retry loops. A script moves the whole read-decide-write logic to the server and runs it at once.

## How it works

| | EVAL | EVALSHA | FCALL |
|---|---|---|---|
| You send | the script text | its SHA1 digest | the function name |
| Code lives in | the request | script cache, volatile | the database, persisted |
| Load with | nothing | SCRIPT LOAD | FUNCTION LOAD |
| Since | Redis 2.6 | Redis 2.6 | Redis 7.0 |

- Key names built inside a script are unsafe in Cluster; declared keys must share one slot ([Redis Cluster](card:redis-cluster)).
- The lock release script is in [distributed locks](card:distributed-locks); the token bucket in [rate limiting](card:rate-limiting-with-redis).

## Example

```lua
-- mark_paid.lua: KEYS[1] payment, KEYS[2] merchant total, ARGV[1] paise
if redis.call('GET', KEYS[1]) ~= 'PENDING' then
  return 0
end
redis.call('SET', KEYS[1], 'PAID')
return redis.call('INCRBY', KEYS[2], ARGV[1])
-- redis-cli --eval mark_paid.lua payment:PAY101 merchant:42:paise:2026-10-20 , 50000
```

| What | Default | Where |

## Interview Qs

### When do you choose a Lua script over MULTI/EXEC?

When a later command depends on an earlier reply, such as "mark PAID only if still PENDING". MULTI/EXEC only queues commands; WATCH needs a retry loop. A script reads and writes in one atomic step.

### EVALSHA returns NOSCRIPT. Why, and what do you do?

The script cache is not persisted: a restart, a failover or SCRIPT FLUSH empties it. Run SCRIPT LOAD and retry, or fall back to EVAL; Spring's RedisTemplate falls back for you.
