## Why it exists

Hand-written [cache-aside](card:cache-aside) code repeats in every service. Spring's cache abstraction moves it into annotations; Spring Boot backs them with Redis.

## How it works

<Mermaid
  alt="Another bean calls find for PAY101. Spring's cache proxy checks Redis for the key payments::PAY101. On a hit it returns the cached value without running the method. On a miss it runs find, stores the result in Redis and returns it. A call to find from inside the same class goes straight to the method and skips the proxy."
  chart={`flowchart TD
  C(["Other bean: find PAY101"]) --> P{"Proxy: payments::PAY101 in Redis?"}
  P -- hit --> RET([Return cached value])
  P -- miss --> M["Run find"]
  M --> S[Store result in Redis] --> RET
  SELF(["this.find inside the class"]) -.-> M`}
/>

- The value serialiser is chosen in [Spring Data Redis](card:spring-data-redis).
- When Redis fails, [failure handling](card:redis-failure-handling) can turn cache errors into misses.

## Example

```java
@Service
class PaymentQueryService {
    private final PaymentRepository repo;
    PaymentQueryService(PaymentRepository repo) { this.repo = repo; }

    @Cacheable(cacheNames = "payments", key = "#id")    // Redis key payments::PAY101
    public PaymentView find(String id) { return repo.load(id); }

    @CacheEvict(cacheNames = "payments", key = "#id")
    public void refund(String id) { repo.refund(id); }
}
```

```properties
spring.cache.redis.time-to-live=10m
spring.cache.redis.cache-null-values=false
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Entry TTL | never expires | `spring.cache.redis.time-to-live`, Spring Boot 4.1 |
| Cache `null` results | yes | `spring.cache.redis.cache-null-values`, Spring Boot 4.1 |
| Key prefix | the cache name plus `::` | `spring.cache.redis.use-key-prefix`, Spring Boot 4.1 |

## Interview Qs

### How do you give each cache its own TTL?

Register a `RedisCacheManagerBuilderCustomizer` bean and call `withCacheConfiguration("payments", RedisCacheConfiguration.defaultCacheConfig().entryTtl(Duration.ofMinutes(5)))` for each cache name.

### Does @CacheEvict run before or after the method?

After it completes successfully, so a failed refund keeps the entry. `beforeInvocation = true` evicts first, even if the method throws; `allEntries = true` clears the whole cache.
