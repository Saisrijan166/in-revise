## Why it exists

Most caching is "give me the value for this key". The string is the simplest value Redis has, and every other trick (counters, bits, locks) starts from it.

## How it works

| You store | Commands | Where it goes deeper |
|---|---|---|
| Text, JSON, HTML | SET, GET, MGET, MSET | [Cache-aside](card:cache-aside) |
| A number | INCR, INCRBY | [One command is atomic](card:single-command-atomicity) |
| Bits or small integers | SETBIT, BITFIELD | [Bitmaps](card:bitmaps-hyperloglog) |

- SET overwrites any old value, whatever its type.
- SET NX as a lock: see [distributed locks](card:distributed-locks); expiry rules: [TTL](card:ttl-and-expiration).

## Example

```text
SET payment:PAY101 PENDING EX 300     -- OK, expires in 300 s
SET payment:PAY101 SUCCESS NX         -- (nil): key exists, NX refuses
SET payment:PAY101 SUCCESS XX GET     -- "PENDING" (old value), now SUCCESS
TTL payment:PAY101                    -- -1: that SET dropped the TTL
MGET payment:PAY101 payment:PAY102    -- 1) "SUCCESS" 2) (nil)
```

## Defaults

| What | Default | Where |
|---|---|---|
| Largest string value | 512 MB (`proto-max-bulk-len`) | Redis Open Source 8.10 |

## Interview Qs

### What can a Redis string hold?

Any bytes up to 512 MB by default: text, numbers, serialised JSON, even an image. It is binary-safe, so Redis never interprets the bytes unless you call a number or bit command.

### Why use MGET instead of many GETs?

MGET reads many keys in one round trip, and atomically. Missing keys, or keys that are not strings, come back as nil.
