## What it is

A string is the simplest kind of value in Redis: one key holds one sequence of bytes. Redis strings are binary-safe, which means Redis stores the bytes exactly as you send them and never checks whether they are text. So a string can hold a status word like `PENDING`, a number, a JSON text or even an image, up to 512 MB. You write it with `SET` and read it with `GET`.

## Why it exists

Most caching is "give me the value for this key". The payment service reads the status of payment 9001 and the config of merchant 42 on every request. Without Redis, each read goes to PostgreSQL. With a string per key, the service stores the value once and reads it back in one fast command. Counters, flags and simple locks are also strings, so this is the type you will use most.

## How it works

| You store | Commands | Taught in |
|---|---|---|
| Text, JSON, a status | SET, GET, MGET, MSET | this concept |
| A number you add to | INCR, INCRBY | [Atomic commands](card:single-command-atomicity) |
| One bit per user id | SETBIT, BITCOUNT | [Bitmaps](card:bitmaps-hyperloglog) |

1. `SET key value` creates the key, or replaces its old value whatever type it was. It also removes any expiry the key had.
2. Options change the write: `EX 300` makes the key expire after 300 seconds, `NX` writes only if the key does not exist yet, and `XX` writes only if it does.
3. `GET key` returns the value, or nil if the key does not exist.
4. `MGET` reads several keys in one command, and `MSET` writes several, so you pay for one network round trip instead of many.

So the key is: one key, one whole value, written and read in one step.

## Example

The payment service stores the status of payment 9001 and caches merchant 42's config as a JSON text.

```bash
redis-cli SET payment:9001:status PENDING EX 300
redis-cli SET payment:9001:status PAID NX
redis-cli SET payment:9001:status PAID XX GET
redis-cli TTL payment:9001:status
redis-cli SET merchant:42:config '{"name":"Asha Stores","upiEnabled":true}' EX 600
redis-cli MGET payment:9001:status merchant:42:config payment:9002:status
```

```text output
OK
(nil)
"PENDING"
(integer) -1
OK
1) "PAID"
2) "{\"name\":\"Asha Stores\",\"upiEnabled\":true}"
3) (nil)
```

What to notice:

- `NX` refused the second write and returned nil, because the key already existed. This "only if missing" write is the base of the [Redis lock](card:distributed-locks) you will see later.
- `XX GET` wrote `PAID` and returned the old value, `PENDING`, in the same command.
- `TTL` returned -1, which means "no expiry". The third SET removed the 300-second expiry from the first. [TTL and key expiry](card:ttl-and-expiration) covers this in full.
- `MGET` returned nil for `payment:9002:status`, which does not exist. It does not fail.

## Rules and defaults

- **Size limit:** a string value can be up to 512 MB by default (`proto-max-bulk-len`, Redis Open Source 8.10).
- **SET overwrites any type:** if the key held a hash or a list, SET replaces it with a string.
- **Conditional writes:** `NX` and `XX` exist since Redis 2.6.12. Since Redis 8.4, `IFEQ value` writes only if the current value equals the one you give.
- **MSET is atomic:** no client sees some keys written and others not. `MSETNX` writes all keys only if none of them exists.

## Not to be confused with

A string holds one whole value, so a JSON text in a string must be rewritten whole to change one field. A [hash](card:hashes) holds separate fields under one key, so you change one field alone. A [JSON document](card:json-and-query-engine) can also change one part of a nested object. Rule: string = the whole value at once; hash or JSON = one field at a time.

## Interview Qs

### What can a Redis string hold?

Any bytes up to 512 MB by default: text, a number, serialised JSON or an image. It is binary-safe, so Redis does not interpret the bytes. Only number or bit commands, such as INCR or SETBIT, read them as a number or as bits.

### Why use MGET instead of many GET calls?

MGET reads many keys in one command, so you pay for one network round trip instead of one per key, and the round trip usually costs more than the command itself. Missing keys, or keys that are not strings, come back as nil instead of an error.

### What does SET with NX do, and where is it used?

SET key value NX writes only if the key does not exist and returns nil otherwise, as one atomic step. Two clients racing on the same key cannot both succeed, so it is used for "first one wins" flags and, with an expiry, for simple locks.
