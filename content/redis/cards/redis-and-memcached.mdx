## Why it exists

Both are in-memory caches, so interviewers ask which one to pick. The difference is features and operations, not the basic idea.

## How it works

<Compare id="redis-vs-memcached" />

- Memcached spreads keys by hashing in the client; Redis has [Redis Cluster](card:redis-cluster) built in.
- Memcached keeps data only across a clean restart with warm restart (1.5.18+); a crash loses it.

## Interview Qs

### When would you still choose Memcached?

For a simple cache of serialised objects on large multi-core nodes, where losing the data is fine and you need no types, replication or persistence.

### Does Memcached replicate data?

No. Memcached servers do not talk to each other: no replication or synchronisation. If a node dies, its keys are gone and the app reloads them from the database.
