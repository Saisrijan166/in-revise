## Why it exists

Redis runs most commands in under a microsecond, but each reply waits for the network. With a 250 ms round trip, one-at-a-time calls manage only 4 requests a second.

## How it works

<Compare id="pipelining-vs-multi-exec-vs-lua" />

- Fewer `read()` and `write()` system calls too, so throughput can rise to about 10 times.
- In Spring, `executePipelined` runs a callback in one pipeline ([Spring Data Redis](card:spring-data-redis)).

## Example

```java
// Status and TTL of many payments: 2 commands each, 1 round trip
List<Object> replies = stringRedisTemplate.executePipelined(
    (RedisCallback<Object>) conn -> {
        StringRedisConnection c = new DefaultStringRedisConnection(conn);
        for (String id : List.of("PAY101", "PAY102", "PAY103")) {
            c.get("payment:" + id);
            c.ttl("payment:" + id);
        }
        return null; // must be null: the replies come back as the list
    });
```

## Interview Qs

### What is pipelining and when would you use it?

Sending many commands without waiting for each reply, then reading all replies together. Use it for bulk loads or many independent reads and writes, when one variadic command such as MGET cannot do the job.

### Is a pipeline the same as MULTI/EXEC?

No. A pipeline only batches network traffic; other clients' commands can run between yours. MULTI/EXEC runs the queued commands with no other client in between.
