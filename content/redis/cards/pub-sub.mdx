## Why it exists

When a payment succeeds, several app servers may need to know at once, for example to push a live update to the customer's screen. Pub/Sub broadcasts it in one call.

## How it works

- In Redis Cluster, sharded Pub/Sub (Redis 7.0+) keeps a channel's messages inside one shard.
- Pub/Sub, list or stream for a queue: [compare](compare:pub-sub-vs-lists-vs-streams).

## Example

```text
SUBSCRIBE payment-events              -- client A waits for messages
PSUBSCRIBE payment-*                  -- client B: any channel matching the pattern
PUBLISH payment-events "PAY101 SUCCESS"   -- (integer) 2: two subscribers got it
```

## Interview Qs

### Is Redis Pub/Sub reliable?

No. Delivery is at-most-once: a subscriber that is disconnected or fails while handling a message loses it, and Redis keeps no history. Use streams with consumer groups when every message must be processed.

### What are keyspace notifications?

Pub/Sub events that Redis publishes when keys change or expire, for example on channel `__keyevent@0__:expired`. They are off by default and, like all Pub/Sub, are lost if no client is listening.
