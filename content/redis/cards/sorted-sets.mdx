## What it is

A sorted set is a [set](card:sets) where every member also has a score, a floating-point number. Members are still unique, but Redis keeps them ordered by score, from lowest to highest. When two members have the same score, Redis orders them by name. Sorted sets are often called ZSETs, which is why their commands start with Z.

## Why it exists

A leaderboard of merchants by today's payment volume, built in SQL, runs `ORDER BY volume DESC LIMIT 10` on every page view, and the database sorts again each time. A sorted set keeps the order up to date as each payment comes in, so "top 10" and "where is merchant 42?" are read straight from an already ordered structure.

## How it works

Merchants ranked by payment volume today (key `rank:merchants:2026-10-21`):

| Member | Score | ZREVRANK (0 = top) |
|---|---|---|
| merchant:42 | 98000 | 0 |
| merchant:8 | 75500 | 1 |
| merchant:17 | 75500 | 2 |

1. Each payment runs `ZINCRBY key amount member`. Redis adds to the member's score, or creates the member with that score.
2. Redis moves the member to its new place in the order in O(log n) steps, so the set is never out of order.
3. `ZRANGE key 0 9 REV WITHSCORES` walks the ordered structure from the top and returns the first ten with their scores.
4. `ZREVRANK key member` returns the member's position counted from the highest score, starting at 0.

So the key is: you pay a little on every write, and reads need no sorting.

## Example

Payment 9001 adds ₹500 to merchant 42's volume, then the dashboard reads the top two and merchant 17's rank.

```bash
redis-cli ZADD rank:merchants:2026-10-21 97500 merchant:42 75500 merchant:8 75500 merchant:17
redis-cli ZINCRBY rank:merchants:2026-10-21 500 merchant:42
redis-cli ZRANGE rank:merchants:2026-10-21 0 1 REV WITHSCORES
redis-cli ZREVRANK rank:merchants:2026-10-21 merchant:17
redis-cli ZRANGE rank:merchants:2026-10-21 0 0
```

```text output
(integer) 3
"98000"
1) "merchant:42"
2) "98000"
3) "merchant:8"
4) "75500"
(integer) 2
1) "merchant:17"
```

What to notice:

- `ZINCRBY` returned the new score, 98000, so the app does not need a second read.
- With `REV`, merchant:8 comes before merchant:17 although both have 75500. Equal scores sort by name, and REV flips that order too.
- Without `REV`, `ZRANGE 0 0` returned the lowest member, merchant:17, not the leader.
- One key per day (`...:2026-10-21`) gives a fresh board each day; old boards can expire.

## Rules and defaults

- **Score type:** a double-precision floating-point number. Integers up to 2^53 are stored exactly, so a Unix time in milliseconds works as a score.
- **One range command (Redis 6.2+):** `ZRANGE` takes `BYSCORE`, `BYLEX`, `REV` and `LIMIT`. The older `ZREVRANGE`, `ZRANGEBYSCORE` and `ZREVRANGEBYSCORE` are deprecated.
- **Inside:** a skip list (a sorted linked list with extra "express" links that skip ahead) keeps the order, and a hash table maps each member to its score.
- **Ranks:** `ZRANK` counts from the lowest score, `ZREVRANK` from the highest; both start at 0.

## Common mistakes

- **"A sorted set can hold the same member twice with two scores."** Members are unique. ZADD on an existing member replaces its score; use a different member name, such as the payment id, for each entry.

## Interview Qs

### How would you build a real-time leaderboard?

One sorted set per board, for example per day. ZINCRBY the member's score on each event. Read the top N with ZRANGE ... REV WITHSCORES and a member's place with ZREVRANK. Each update is O(log n), so it stays fast with millions of members.

### Why is a sorted set fast for both updates and range reads?

It keeps two structures. A hash table finds a member's score in one step. A skip list keeps members in score order, so an update moves one member in O(log n) and a range read walks the already ordered list.

### What else can a sorted set do besides leaderboards?

Any score works as an index. With a timestamp as the score it becomes a time-ordered index: you will use this for sliding-window [rate limiting](card:rate-limiting-with-redis) and for delayed jobs in [queues](card:queues-with-redis).
