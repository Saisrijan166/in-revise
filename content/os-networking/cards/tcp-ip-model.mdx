## Why it exists

OSI describes jobs; TCP/IP is what hosts actually implement. Knowing its four layers and how headers nest explains every packet capture and every "which layer?" question.

## How it works

<Compare id="osi-vs-tcp-ip" />

- Sender: data goes down the stack, gaining a header at each layer. Receiver: it goes up, losing them.
- Names follow the layer: TCP sends segments, IP sends packets, Ethernet sends frames.
- Practical stacks: HTTPS is HTTP, TLS, TCP, IP, Ethernet; HTTP/3 runs on QUIC over UDP ([HTTP versions](card:http-versions)).

## Example

Our `GET https://api.shop.example/orders/42` leaving the client, after TLS encrypts the HTTP bytes:

```text
Application  [ TLS record: encrypted HTTP request ]                  message
Transport    [ TCP hdr | TLS record ]                                segment
Internet     [ IP hdr: 192.0.2.10 -> 203.0.113.5 | TCP | TLS ]       packet
Link         [ Ethernet hdr: MACs | IP | TCP | TLS | FCS trailer ]   frame
Physical     0110100101... on copper, fibre or radio                 bits
```

## Interview Qs

### OSI vs TCP/IP: what is the difference?

OSI is a 7-layer reference model from ISO; TCP/IP is the 4-layer suite the Internet runs. TCP/IP folds OSI 5 to 7 into Application and OSI 1 and 2 into Link.

### What is encapsulation?

Each layer treats what it gets from above as data and puts its own header in front: a TCP segment goes inside an IP packet, which goes inside an Ethernet frame. The receiver removes the headers in reverse order.

### What is a PDU?

A protocol data unit: the chunk one layer works with. Transport: segment (TCP) or datagram (UDP). Internet: packet. Link: frame. Physical: bits.
