## What it is

The TCP/IP model is the four-layer stack that computers on the Internet actually implement: Application, Transport, Internet and Link. It does the same jobs as the [OSI model](card:osi-model) but with fewer boxes, because it was built to describe real protocols rather than to teach. Its central idea is encapsulation: as your data goes down the stack, each layer wraps what it got from above inside its own header, like putting a letter in an envelope, then that envelope in a bigger one.

## Why it exists

OSI describes the jobs; TCP/IP is what hosts actually run, so it is the model you use to explain a real packet. Without understanding how headers nest, a packet capture looks like meaningless bytes, and questions like "which layer added this?" have no answer. Knowing the four layers and how each one wraps the data lets you read any capture and place any protocol exactly.

## How it works

1. The app's data starts at the Application layer (for example, an HTTP request).
2. The Transport layer (TCP) adds a header with port numbers and a sequence number; the result is called a segment.
3. The Internet layer (IP) adds a header with source and destination IP addresses; the result is a packet.
4. The Link layer (Ethernet) adds a header with MAC addresses and a trailer for error checking; the result is a frame.
5. The frame becomes bits on the wire. The receiver reverses all of this, stripping one header per layer, until the Application layer gets the original data back.

So the key is that the name of the data unit tells you which layer you are looking at: segment, packet, frame.

## Example

This shows the same `GET https://api.shop.example/orders/42` leaving the client, after TLS has encrypted the HTTP bytes, growing a header at each layer.

```text
Application  [ TLS record: encrypted HTTP request ]                  message
Transport    [ TCP hdr | TLS record ]                                segment
Internet     [ IP hdr: 192.0.2.10 -> 203.0.113.5 | TCP | TLS ]       packet
Link         [ Ethernet hdr: MACs | IP | TCP | TLS | FCS trailer ]   frame
Physical     0110100101... on copper, fibre or radio                 bits
```

What to notice:

- Each row wraps the row above it: the TCP header sits in front of the TLS record, and the IP header sits in front of the whole TCP segment. Nothing from above is changed, only wrapped.
- The name on the right changes per layer (segment, packet, frame). This is why interviewers expect "segment" for TCP and "packet" for IP, not the word "packet" for everything.
- The Link layer adds a trailer (FCS) as well as a header, used to detect a corrupted frame. If you removed the IP header row, the frame would have no destination address and no router could forward it.

## Rules and defaults

- **Layer names (RFC 1122):** Application, Transport, Internet, Link, from top to bottom. The Link layer is sometimes called "Network Access".
- **Encapsulation on send, decapsulation on receive:** headers are added going down and removed going up, one layer at a time.
- **PDU names:** message (application), segment for TCP or datagram for UDP (transport), packet (internet), frame (link), bits (physical).
- **Common real stacks:** HTTPS is HTTP over TLS over TCP over IP over Ethernet; [HTTP/3](card:http-versions) runs on QUIC over UDP instead of TCP.

## Not to be confused with

A **PDU** (protocol data unit) is the chunk of data one layer works with; its name changes per layer. **Encapsulation** is the act of wrapping that chunk in a new header to form the PDU of the layer below. Rule: encapsulation is the process; the PDU (segment, packet, frame) is the thing it produces.

## Interview Qs

### OSI vs TCP/IP: what is the difference?

OSI is a seven-layer reference model from ISO, used for teaching and naming. TCP/IP is the four-layer suite the Internet actually runs, defined by IETF RFCs. TCP/IP folds OSI layers 5 to 7 into one Application layer and OSI layers 1 and 2 into one Link layer.

### What is encapsulation?

Each layer treats what it gets from the layer above as plain data and puts its own header in front of it. A TCP segment goes inside an IP packet, which goes inside an Ethernet frame. The receiver does the reverse, decapsulation, removing one header per layer until the app gets its data.

### What is a PDU?

A protocol data unit: the chunk of data one layer works with. At the transport layer it is a segment (TCP) or datagram (UDP), at the internet layer a packet, at the link layer a frame, and at the physical layer just bits. The name tells you which layer you are at.
