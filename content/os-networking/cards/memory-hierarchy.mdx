## Why it exists

RAM is far slower than the CPU. Small caches near the core keep copies of recent data, so most reads never wait for RAM.

## How it works

- Times are rough, from Norvig's typical-PC table.
- A miss copies the whole cache line up, so its neighbours become cheap.
- Address translations have their own cache, the [TLB](card:paging-and-page-faults); file data sits in the [page cache](card:files-and-file-descriptors).

## Interview Qs

### What is locality of reference?

Programs reuse recent data (temporal) and touch data next to it (spatial). Every cache, the TLB included, bets on this.

### Why is looping over an array faster than walking a linked list?

Array elements sit side by side, so one cache line brings several. List nodes can be anywhere, so each step may miss.

### What is false sharing?

Two threads write different variables that share one cache line, so the line bounces between cores. Pad or separate hot fields; since Java 8 the JVM can pad marked fields itself (JEP 142, used inside the JDK).
