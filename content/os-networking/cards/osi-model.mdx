## Why it exists

Network software is too big to reason about as one piece. OSI cuts it into seven jobs, so people can say which job a protocol, device or fault belongs to.

## How it works

| # | Layer | Answers | Examples | Device |
|---|---|---|---|---|
| 7 | Application | What does the app want to say? | HTTP, DNS, SMTP, SSH | |
| 6 | Presentation | How is the data written? | UTF-8, JSON, compression | |
| 5 | Session | Which dialogue is this? | rarely a separate thing | |
| 4 | Transport | Which program, and reliably? | TCP, UDP | |
| 3 | Network | Which path to the host? | IP, ICMP | Router |
| 2 | Data link | Which device on this link? | Ethernet, Wi-Fi, MAC | Switch |
| 1 | Physical | How do bits travel? | copper, fibre, radio | Hub |

## Interview Qs

### Explain the OSI model.

A 7-layer reference model for network communication. Lower layers move bits, frames and packets (physical, data link, network); transport gives end-to-end delivery; the top three handle sessions, data format and the app protocol.

### Where do HTTP, TCP, IP and Ethernet sit?

HTTP is layer 7, TCP (and UDP) layer 4, IP layer 3, Ethernet layer 2. Our `GET /orders/42` is HTTP, carried by TCP, inside IP packets, inside Ethernet frames.

### If the Internet runs TCP/IP, why learn OSI?

It is the shared vocabulary. "An L4 load balancer" or "an L7 firewall" uses OSI numbers, and naming the layer tells you where to look when something breaks.
