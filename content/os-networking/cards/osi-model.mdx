## What it is

The OSI model (Open Systems Interconnection) is a way to describe network communication as seven stacked layers, each doing one job. Layer 1 at the bottom moves raw bits over a wire or radio; layer 7 at the top is the app's own protocol, like HTTP. Each layer only talks to the layer right above and right below it. It is a reference model: a shared map for naming where a protocol, device or fault belongs, not a piece of software you install.

## Why it exists

A full network stack, from electrical signals up to a web request, is too large to reason about as one block. Without a shared breakdown, two engineers describing the same problem would use different words and talk past each other. OSI cuts the work into seven named jobs, so you can say "this is a layer 3 routing problem" or "an L7 load balancer" and everyone knows exactly which part you mean.

## How it works

Each layer takes a service from the layer below and offers a service to the layer above. The table reads bottom to top, the way bits turn into a full message.

| # | Layer | The question it answers | Examples | Device |
|---|---|---|---|---|
| 7 | Application | What does the app want to say? | HTTP, DNS, SMTP, SSH | |
| 6 | Presentation | How is the data written and encoded? | UTF-8, JSON, compression | |
| 5 | Session | Which dialogue does this belong to? | rarely a separate layer today | |
| 4 | Transport | Which program, and delivered reliably? | TCP, UDP | |
| 3 | Network | Which path to the far host? | IP, ICMP | Router |
| 2 | Data link | Which device on this one link? | Ethernet, Wi-Fi, MAC | Switch |
| 1 | Physical | How do the bits physically travel? | copper, fibre, radio | Hub |

1. The sending app hands its data to layer 7, which passes it down, layer by layer, towards the wire.
2. Each lower layer adds what it needs: layer 4 adds a port to pick the program, layer 3 adds an address to pick the host, layer 2 adds a MAC to pick the device on the link.
3. Layer 1 turns the result into signals and sends them.
4. The receiver reverses this, each layer reading its own part, until the app's data reaches layer 7 at the other end.

So the key is that each layer only worries about its own job and trusts the layers below to handle theirs.

## Example

Opening the shop API with `GET /orders/42` uses several layers at once. This shows which protocol runs at which layer.

```text
Layer 7  Application   HTTP: GET /orders/42
Layer 4  Transport     TCP: port 443, in-order delivery
Layer 3  Network       IP: 192.0.2.10 -> 203.0.113.5
Layer 2  Data link     Ethernet: MAC address of the next device
Layer 1  Physical      electrical or light signals on the wire
```

What to notice:

- The one request touches four layers at the same time: HTTP rides inside TCP, which rides inside IP, which rides inside Ethernet.
- The IP address (layer 3) names the far host; the port 443 (layer 4) names the program on it; the MAC (layer 2) names only the next device on this link, not the far host.
- Layers 5 and 6 do not appear as separate steps here, because the app and its TLS library handle that work. The [TCP/IP model](card:tcp-ip-model) folds them away entirely.

## Rules and defaults

- **It is a model, not code:** OSI defines no protocols you can run. The matching real protocols come from other standards (IP, TCP, HTTP).
- **Layer order is fixed:** physical (1), data link (2), network (3), transport (4), session (5), presentation (6), application (7). The mnemonic "Please Do Not Throw Sausage Pizza Away" reads bottom to top.
- **Approximate placement:** some protocols span layers. TLS is often drawn across 5 to 7; treat any single-layer label as a close fit, not a law.

## Not to be confused with

OSI is the seven-layer reference map used for naming and teaching. The [TCP/IP model](card:tcp-ip-model) is the four-layer stack the Internet actually runs. Rule: OSI gives you the vocabulary (L4, L7); TCP/IP gives you the protocols that carry real traffic.

## Interview Qs

### Explain the OSI model.

A seven-layer reference model for network communication. The lower layers move bits, frames and packets (physical, data link, network); the transport layer gives end-to-end delivery between programs; the top three handle sessions, data format and the app's own protocol. Each layer serves the one above it.

### Where do HTTP, TCP, IP and Ethernet sit?

HTTP is layer 7 (application), TCP and UDP are layer 4 (transport), IP is layer 3 (network), and Ethernet is layer 2 (data link). A `GET /orders/42` is HTTP, carried by TCP, inside IP packets, inside Ethernet frames on each link.

### If the Internet runs TCP/IP, why learn OSI?

Because it is the shared vocabulary. Phrases like "an L4 load balancer" or "an L7 firewall" use OSI layer numbers, and naming the layer of a fault tells everyone where to look. TCP/IP tells you how traffic really flows; OSI tells you what to call each part.
