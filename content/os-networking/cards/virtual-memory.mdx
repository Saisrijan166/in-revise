## Why it exists

With raw physical RAM, one bad pointer could corrupt another program, and each program would need to know where it was loaded.

## How it works

<Mermaid
  alt="Processes A and B both use address 0x1000; the MMU and page tables map them to RAM frames 7 and 2. A swapped-out page lives on disk."
  chart={`flowchart LR
  A["Process A: 0x1000"] --> M{{"MMU + page tables"}}
  B["Process B: 0x1000"] --> M
  M --> F7[(RAM frame 7)]
  M --> F2[(RAM frame 2)]
  M -. "page swapped out" .-> S[(Swap space)]`}
/>

- An invalid address or a write to a read-only page gives SIGSEGV: a segmentation fault.
- Pages, page tables and faults: [paging](card:paging-and-page-faults). RAM running short: [page replacement](card:page-replacement).
- A container at its cgroup memory.max limit triggers the OOM killer inside that cgroup.

## Example

An idle JVM: about 4.6 GiB of virtual memory (VSZ), only about 40 MiB in RAM (RSS).

```bash
java -Xmx2g Idle &                # a JVM that only sleeps
ps -o pid,vsz,rss,comm -C java
```

```text output
    PID    VSZ   RSS COMMAND
 723322 4863172 40832 java
```

## Interview Qs

### What is virtual memory and why do we need it?

Each process sees its own address space, mapped to RAM page by page. It isolates processes, hides physical addresses and gives RAM only to pages actually touched.

### malloc succeeded, yet the process was killed later. How?

Linux overcommits by default: the allocation only reserves address space. When pages are touched and RAM (or the cgroup limit) runs out and cannot be reclaimed, the OOM killer kills a process.

### VSZ vs RSS?

VSZ is all the virtual memory a process has mapped; RSS is the part now in RAM. Watch RSS against the memory limit.
