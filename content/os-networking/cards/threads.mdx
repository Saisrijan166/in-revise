## Why it exists

A process per request wastes memory and makes sharing data slow. Threads let one process work on many requests at once over one shared heap.

## How it works

<Compare id="process-vs-thread" />

- Three requests to `/orders/42` can run on three threads of one JVM, reading the same cached order.
- Thread states follow the [process states](card:processes); how many threads to run is [thread pools](card:thread-pools).
- Models: 1:1 (kernel threads, Java platform threads), M:1 (old green threads), M:N ([virtual threads](card:virtual-thread)).

## Example

Two platform threads in one process (example run; the order can change):

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Runnable request = () -> {
            long pid = ProcessHandle.current().pid();        // local: on this thread's stack
            System.out.println(Thread.currentThread().getName() + " runs in PID " + pid);
        };
        Thread a = Thread.ofPlatform().name("req-1").start(request);
        Thread b = Thread.ofPlatform().name("req-2").start(request);
        a.join();                                            // wait for both
        b.join();
    }
}
```

```text output
req-1 runs in PID 726710
req-2 runs in PID 726710
```

## Interview Qs

### Process vs thread?

A process is an isolated running program with its own address space. A thread runs inside a process and shares its memory and files: cheaper to create and quicker to talk to, but a bug can hurt every thread.

### Why is a thread cheaper than a process?

Creating one needs no new address space or page tables. Switching between threads of the same process keeps the page table, so the TLB need not be flushed.

### User threads vs kernel threads?

The kernel schedules kernel threads. A runtime inside the process schedules user threads. Java virtual threads are user-mode threads that the JDK mounts on a few platform (carrier) threads.
