## What it is

A **thread** is one path of execution inside a [process](card:processes). A process with one thread does one thing at a time; a process with several threads can make progress on several things, all inside the same memory. Every thread has its own call stack (where its local variables and current method calls live) and its own CPU registers, but all the threads of a process share the same heap, the same code and the same open files. So threads are the workers; the process is the shared workplace.

## Why it exists

A server that handled each request in its own process would pay a lot: a full private address space per request, and slow inter-process messaging whenever two requests need the same data, such as a shared cache. Threads remove both costs. One process can run many threads over one shared heap, so creating a worker is cheap and sharing data between workers is just reading the same memory. The price is that shared data now needs [locks](card:locks) to stay correct.

## How it works

The comparison lays out what a process and a thread each own, which is the heart of this concept.

<Compare id="process-vs-thread" />

1. A process starts with one thread, the one running `main`.
2. The program asks for more threads; the kernel (or the Java runtime) creates each with its own stack and registers but points them at the same heap and code.
3. The [scheduler](card:cpu-scheduling) runs the ready threads, switching between them, so they appear to run together.
4. Each thread follows the same states as a process (Ready, Running, Blocked), but they all share the one address space, so switching between threads of one process is cheaper than switching between processes.

So the key is that threads trade isolation for cheap, fast sharing inside one process.

## Example

Two threads in one Java process print the process's PID. The PID is the same for both, which proves they live in one process (the two lines can print in either order).

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Runnable request = () -> {
            long pid = ProcessHandle.current().pid();        // the process this thread runs in
            System.out.println(Thread.currentThread().getName() + " runs in PID " + pid);
        };
        Thread a = Thread.ofPlatform().name("req-1").start(request);
        Thread b = Thread.ofPlatform().name("req-2").start(request);
        a.join();                                            // wait for both to finish
        b.join();
    }
}
```

```text output
req-1 runs in PID 81199
req-2 runs in PID 81199
```

What to notice:

- Both threads print the same PID, because a thread does not have its own PID; it shares the one of its process.
- The thread name differs (`req-1`, `req-2`) because the name is per thread, not per process.
- `join()` makes `main` wait for each thread; without it, `main` could end and the program exit before the threads print.

## Rules and defaults

- **Shared versus private:** the heap, code, globals and open file descriptors are shared across threads; the stack, registers, program counter and thread-local storage are private to each thread.
- **Linux uses a 1:1 model:** each Java platform thread is one [kernel thread](card:kernel-thread) that the kernel schedules; they are made with the `clone` system call.
- **Threading models:** 1:1 (kernel threads, Java platform threads), M:1 (old green threads), and M:N, where many [user threads](card:user-thread) run on a few kernel threads. Java 21's [virtual threads](card:virtual-thread) are the M:N case.
- **A signal that kills acts per process:** a fatal fault ends all threads, because the signal disposition belongs to the process, not one thread.

## Interview Qs

### What is the difference between a process and a thread?

A process is an isolated running program with its own address space, PID and open files. A thread is a path of execution inside a process; it shares that memory and those files with the other threads. Threads are cheaper to create and faster to share data, but they give no isolation, so a bug in one thread can corrupt or crash all of them.

### Why is creating a thread cheaper than creating a process?

Creating a process needs a new address space and new page tables, which the kernel must build. A thread reuses the process's address space, so it needs only a new stack and registers. Switching between threads of one process is also cheaper, because the page table stays the same, so the [TLB](card:tlb) need not be flushed.

### What is the difference between a user thread and a kernel thread?

A kernel thread is scheduled directly by the kernel; on Linux each Java platform thread is one. A user thread is scheduled by a runtime inside the process, so the kernel does not see it separately. Java virtual threads are user-mode threads that the JDK runs on a small pool of platform (carrier) threads.
