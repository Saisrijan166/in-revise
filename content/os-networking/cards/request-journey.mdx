## Why it exists

"What happens when you open a URL?" tests whether you can join OS and network ideas into one path, with a trade-off at each hop.

## How it works

<Steps label="GET https://api.shop.example/orders/42">
  <Step title="Resolve">[DNS](card:dns) turns api.shop.example into an IP address.</Step>
  <Step title="Connect">[TCP handshake](card:tcp-handshake), then [TLS 1.3](card:tls-https); HTTP/3 uses QUIC ([versions](card:http-versions)).</Step>
  <Step title="Travel">Packets cross [routers](card:switches-and-routers) and [NAT](card:ip-addressing).</Step>
  <Step title="Balance">The [load balancer](card:load-balancers-and-proxies) picks a healthy instance.</Step>
  <Step title="Accept">The kernel queues the connection on the listening [socket](card:ports-and-sockets); the server accepts it ([epoll](card:io-multiplexing)).</Step>
  <Step title="Run">A [pool thread](card:thread-pools) in the JVM [process](card:processes) runs the code on its [stack and the heap](card:stack-and-heap).</Step>
  <Step title="Query">A pooled connection runs the SQL ([pooling](card:connection-pooling)).</Step>
  <Step title="Read">PostgreSQL reads from the [page cache or disk](card:files-and-file-descriptors).</Step>
  <Step title="Return">The response goes back the same way, [cached](card:caching-and-cdn) where allowed.</Step>
</Steps>

| Symptom or question | Concept |
|---|---|
| Slow only for far-away users | [Latency](card:latency-and-bandwidth), [CDN](card:caching-and-cdn) |
| Timeouts under load | [Thread pools](card:thread-pools), [pooling](card:connection-pooling), [failures](card:network-failures) |
| Duplicate payment after a retry | [Idempotency](card:network-failures) |
| "Too many open files" | [File descriptors](card:files-and-file-descriptors) |
| Many TIME_WAIT sockets | [TCP close](card:tcp-handshake) |
| Counter wrong under load | [Race conditions](card:race-conditions) |
| Threads stuck waiting on each other | [Deadlocks](card:deadlocks) |
| Container killed as memory grows | [Virtual memory](card:virtual-memory) |
| Protocol for live chat | [Real-time connections](card:real-time-connections) |

## Interview Qs

### What happens when you type a URL and press Enter?

Draw the map first, then go hop by hop: DNS, TCP and TLS, load balancer, server thread, database, response. Name one trade-off per hop, mention caching, and end with what can fail.

### Where does the time go in that request?

First in round trips (DNS, TCP, TLS, the request), then in server work and queries: see the [counted example](card:latency-and-bandwidth).
