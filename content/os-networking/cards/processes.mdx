## What it is

A **process** is a program while it is running. A program is just a file on disk; the moment the OS loads it and gives it memory and a CPU share, it becomes a process. Each process gets its own private [virtual memory](card:virtual-memory), its own process ID (**PID**), and its own set of open files, and the kernel keeps all of this separate from every other process. The kernel tracks each one in a record called the **process control block (PCB)**: its PID, state, saved registers and memory map.

## Why it exists

Many programs share one machine, and they must not read or corrupt each other's memory. If they all used the same memory, a bug in one could silently damage another, and a crash could take down everything. A process wraps one running program in its own private address space, so each one sees only its own data. That is the OS's main unit of isolation: three copies of a server run as three processes, and one crashing leaves the other two serving.

## How it works

A process moves through a few states while it runs. The kernel keeps it ready, running or waiting, as shown here.

1. A parent process calls `fork`, and the kernel makes a child that is a copy of the parent, with a new PID.
2. The child usually calls `exec`, which throws away the copied program and loads the real one it wants to run.
3. The new program runs, moving between Ready, Running and Blocked as the [scheduler](card:cpu-scheduling) and its I/O allow.
4. When it finishes, it exits and becomes a zombie: dead, but still holding its PID and exit status.
5. The parent calls `wait`, reads the exit status and lets the kernel finally remove the child.

So the key is that `fork` copies, `exec` replaces, and `wait` cleans up.

## Example

A child can finish before its parent reaps it. This shell line starts a short `sleep 0.2` as the child of a longer `sleep 3`, then lists both after one second (PIDs vary between runs).

```bash
(sleep 0.2 & exec sleep 3) &
sleep 1; ps -o pid,ppid,stat,cmd --ppid $! -p $!
```

```text output
    PID    PPID STAT CMD
 726508  726507 S    sleep 3
 726510  726508 Z    [sleep] <defunct>
```

What to notice:

- The `Z` state and `<defunct>` mark the inner `sleep 0.2`: it has exited, but its parent `sleep 3` is still running and has not called `wait()`, so it lingers as a zombie.
- The `S` process is the still-sleeping parent. The zombie holds only a PID and an exit status, not memory or CPU.
- If the parent exited instead of sleeping, init (PID 1) would adopt the zombie and reap it at once, and it would vanish from the list.

## Rules and defaults

- **fork return value:** `fork` returns twice. The parent gets the child's PID (greater than 0), and the child gets 0, which is how each side knows who it is.
- **exec keeps the PID:** a successful `exec` does not return, because the old program is gone; the PID, open files and parent stay the same.
- **Memory is isolated, but shared cheaply at first:** after `fork`, parent and child share pages read-only via [copy-on-write](card:copy-on-write), and a page is copied only when one side writes to it.
- **A [container](card:linux-container) is still just processes:** it is a process tree with its own [namespaces](term:namespace-linux) and [cgroup](term:cgroup) limits, all sharing the one host kernel, not a separate machine.

## Interview Qs

### What is the difference between a program and a process?

A program is a passive file on disk: code and data that does nothing by itself. A process is that program in execution, with its own memory, a PID, open files, a call stack and registers. One program can run as many processes at once, and each process is isolated from the others.

### What are a zombie process and an orphan process?

A zombie has already exited, but its parent has not called `wait()`, so the kernel keeps its PID and exit status until the parent reads them. An orphan is the opposite: it is still running after its parent died, so init (PID 1) or a subreaper adopts it and will reap it when it exits.

### Why does `fork` return two different values?

It runs once but returns in two processes. In the parent it returns the new child's PID, so the parent can later `wait` for that exact child. In the child it returns 0. Code checks the return value to branch: 0 means "I am the child", a positive number means "I am the parent".
