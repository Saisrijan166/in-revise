## What it is

A port is a 16-bit number (0 to 65535) that picks which program on a host a connection is for. The [IP address](card:ip-addressing) gets a packet to the right machine; the port gets it to the right program, such as the web server on 443 or PostgreSQL on 5432. A socket is the OS handle for one end of a conversation. The program is given the socket as a [file descriptor](card:files-and-file-descriptors), the same handle it uses for files, and reads and writes through it.

## Why it exists

One host runs many programs, and each talks to many peers at once: a web server, a database, an SSH session. Without ports, the OS could not tell which arriving packet belongs to which program. And without a per-connection handle, a program could not keep thousands of clients apart. Ports solve the first problem by labelling the program; sockets solve the second by giving each conversation its own OS object with its own buffers.

## How it works

These are the system calls a TCP server and client make to set up a connection.

<Steps label="TCP socket calls">
  <Step title="Server: socket(), bind()">The server creates an endpoint, then attaches it to an address and port, such as 0.0.0.0:8080.</Step>
  <Step title="Server: listen()">The server marks the socket passive. Completed handshakes queue up, bounded by the listen backlog.</Step>
  <Step title="Client: socket(), connect()">The client creates its own endpoint; the kernel picks an ephemeral source port and connects to the server.</Step>
  <Step title="Server: accept()">accept() returns a new connected socket for that client. The original listening socket stays open for the next client.</Step>
</Steps>

So the key is that `accept()` gives each client its own socket, while the listening socket keeps waiting.

## Example

This tiny server and client run in one program. The client port is ephemeral, so it changes on each run.

```java
import java.io.*; import java.net.*;
public class Hello {
  public static void main(String[] args) throws IOException {
    try (var server = new ServerSocket(8080);         // socket + bind + listen
         var client = new Socket("localhost", 8080);  // client: socket + connect
         var conn = server.accept()) {                // a NEW socket for this client
      conn.getOutputStream().write("hello\n".getBytes());
      var in = new BufferedReader(new InputStreamReader(client.getInputStream()));
      System.out.println(in.readLine() + " | server port " + conn.getLocalPort() + ", client port " + conn.getPort());
    }
  }
}
```

```text output
hello | server port 8080, client port 47554
```

What to notice:

- `new ServerSocket(8080)` does `socket()`, `bind()` and `listen()` in one step; `server.accept()` returns `conn`, a separate socket for this client.
- The server port stays 8080 for every client, but the client port (47554 here) is an ephemeral port the kernel chose. On the next run it would differ.
- `conn` and the listening `server` are two different sockets. If you did not keep the listening socket, the server could not accept a second client.

## Rules and defaults

- **Port ranges (RFC 6335):** system/well-known 0-1023 (need privilege to bind on Linux), user/registered 1024-49151, dynamic/ephemeral 49152-65535.
- **Ephemeral port range on Linux:** default `32768-60999`, set by `net.ipv4.ip_local_port_range`. Many short-lived outbound connections can run this range out.
- **Bind address matters:** `127.0.0.1` accepts only same-host clients; `0.0.0.0` accepts on all interfaces.
- **Backlog:** pending completed connections queue up to the listen backlog; on Linux the cap is `net.core.somaxconn`, 4096 since kernel 5.4 (was 128).

## Not to be confused with

A **port** is just a number inside the TCP or UDP header; nothing is "open" until a program binds it. A **socket** is the live OS object (a file descriptor) that a program reads and writes; a connected one is tied to one 4-tuple. Rule: the port names the program, the socket is the handle to one actual connection.

## Interview Qs

### How can one server port serve thousands of clients?

A TCP connection is identified by its 4-tuple: source IP, source port, destination IP, destination port. Every client arrives with a different source IP or source port, so each accepted socket on, say, port 8080 is a distinct connection. The OS uses the full 4-tuple to route data to the right socket.

### What is the difference between a port and a socket?

A port is a 16-bit number in the TCP or UDP header that selects the program. A socket is the operating system object, exposed as a file descriptor, that a program reads and writes; a connected socket is bound to exactly one 4-tuple. One listening socket can produce thousands of connected sockets.

### Name some well-known ports.

22 is SSH, 53 is DNS, 80 is HTTP, 443 is HTTPS, and 5432 is PostgreSQL. Port 8080 is registered as an HTTP alternate and is common for app servers in development. Ports 0 to 1023 are the well-known range and usually need privilege to bind.
