## What it is

An operating system (OS) is the software that sits between your programs and the hardware. Its core is the **kernel**: the one program that controls the CPU, memory, disks and network cards, and shares them among every program that is running. Your own code does not touch hardware directly. It runs in a restricted CPU mode called **user mode**, and when it needs something privileged, it asks the kernel through a **system call**.

## Why it exists

Many programs run on one machine and share one CPU, one block of memory and one disk. If every program could drive the hardware itself, one buggy program could overwrite another's memory or crash the disk. So the CPU offers two modes. In user mode it refuses dangerous instructions, so an app can only ask; in kernel mode the kernel does the dangerous work after checking it. That is how the OS keeps programs isolated and the machine safe.

## How it works

The table shows the two modes side by side; the key difference is what each one is allowed to do.

<Compare id="user-mode-vs-kernel-mode" />

1. Your program runs normally in user mode until it needs the hardware, for example to read a file.
2. It calls a library function such as `read`; the library puts the request in CPU registers and runs a special **trap** instruction.
3. The trap switches the CPU into kernel mode and jumps to the kernel's handler for that system call.
4. The kernel checks that the request is allowed, does the work, and runs a return-from-trap instruction that switches back to user mode.
5. Your program continues on the same thread, right after the `read` call, now with the data.

So the key is that the kernel is the only code that touches the hardware, and a system call is the single guarded door your program uses to reach it.

## Example

Running `cat` to print a file makes exactly these system calls. `strace` lists the system calls a program makes; here it reads a file and writes it to the screen (library-loading lines cut).

```bash
strace -e trace=openat,read,write,close cat order.txt > /dev/null
```

```text output
openat(AT_FDCWD, "order.txt", O_RDONLY) = 3
read(3, "order 42 total 1499\n", 131072) = 20
write(1, "order 42 total 1499\n", 20)   = 20
read(3, "", 131072)                     = 0
close(3)                                = 0
```

What to notice:

- `openat` asks the kernel to open the file and returns `3`, a small integer the program now uses to refer to the open file.
- `read` copies the file's bytes into the program; the `20` is how many bytes it got. The second `read` returns `0`, which means the end of the file.
- `write` to `1` (the screen) hands the bytes back to the kernel to display. Every line here is the program crossing into the kernel and back; between the lines it runs in user mode.

## Rules and defaults

- **Two things enter the kernel, not one:** a system call (your program asks), and an [interrupt](card:interrupt) (a device such as the timer or disk signals the CPU). A [trap](card:trap) is the CPU entering the kernel because of the running instruction, such as a system call or a divide by zero.
- **Privileged instructions are blocked in user mode:** the CPU raises an exception instead of running them, so an app cannot drive devices or reach another program's memory.
- **Kernel designs differ:** Linux is a [monolithic kernel](card:monolithic-kernel) (all OS services run in kernel mode, which is fast but one bug can crash everything); a [microkernel](card:microkernel) keeps the kernel tiny and runs services such as the file system as user-mode programs.

## Interview Qs

### What is a system call, and how is it different from a normal function call?

A normal function call stays in user mode. A system call is a request into the kernel: the library puts the call number and arguments in registers and runs a trap instruction, which switches the CPU to kernel mode. The kernel checks the request, does the privileged work and returns the result or an error.

### Why do CPUs have user mode and kernel mode at all?

So one program cannot drive devices or read another program's memory. In user mode the CPU blocks privileged instructions and limits which memory the program can reach, so a bug or an attack stays contained. Only kernel code, entered through a trap, is allowed to run those instructions.

### What is the difference between a monolithic kernel and a microkernel?

In a monolithic kernel (Linux) all OS services, such as the file system and drivers, run together in kernel mode; this is fast, but one bug can crash the whole system. A microkernel (Minix, QNX, seL4) keeps the kernel small and runs most services as user-mode processes that talk by messages, trading some speed for stronger isolation.
