## Why it exists

Many programs share one CPU, memory and disk. The OS gives each a safe virtual view and checks every hardware request, so one program cannot break another.

## How it works

<Compare id="user-mode-vs-kernel-mode" />

- Path: app code, then a library (glibc, the JVM), then a trap instruction, then the kernel, then return-from-trap.
- [Interrupts](card:interrupt) come from devices; [traps](card:trap) come from the running instruction: a syscall, divide by zero, a [page fault](card:paging-and-page-faults).
- Linux is a [monolithic kernel](card:monolithic-kernel); a [microkernel](card:microkernel) runs the file system and other services as user-mode servers.

## Example

The Spring Boot JVM reads files and sockets the same way. A local run (library-loading lines cut):

```bash
strace -e trace=openat,read,write,close cat order.txt > /dev/null
```

```text output
openat(AT_FDCWD, "order.txt", O_RDONLY) = 3
read(3, "order 42 total 1499\n", 131072) = 20
write(1, "order 42 total 1499\n", 20)   = 20
read(3, "", 131072)                     = 0
close(3)                                = 0
close(1)                                = 0
close(2)                                = 0
+++ exited with 0 +++
```

## Interview Qs

### What is a system call?

A controlled entry into the kernel. The library puts the call number and arguments in registers and traps to kernel mode; the kernel checks and does the work, then returns the result or an error.

### Why have user mode and kernel mode?

So a buggy or hostile program cannot drive devices or read another process's memory. The CPU refuses privileged instructions in user mode; only kernel code, entered through traps, may run them.

### Monolithic kernel vs microkernel?

Monolithic (Linux): all OS services run in kernel mode, fast but one bug can crash everything. Microkernel (Minix, QNX, L4): a small kernel passes messages to services running as user-mode processes.
