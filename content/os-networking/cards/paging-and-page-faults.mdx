## Why it exists

Giving each process one contiguous block of RAM wastes memory in gaps. Fixed-size pages can go in any free frame, and only touched pages need RAM.

## How it works

<Steps label="Translating one virtual address">
<Step title="Split">The address becomes a virtual page number plus an offset inside the page.</Step>
<Step title="TLB">A hit gives the frame number at once.</Step>
<Step title="Page table">On a TLB miss, look up the page table and cache the entry in the TLB.</Step>
<Step title="Page fault">Page not present: the kernel allocates or reads the page, updates the table and retries.</Step>
<Step title="Combine">Frame number plus offset is the physical address.</Step>
</Steps>

- Demand paging: a page gets RAM only when first touched.
- Pages remove external fragmentation; the unused tail of a last page is internal fragmentation.
- When RAM is full, a page must go: [page replacement](card:page-replacement).

## Interview Qs

### Page table vs TLB?

The page table is the full map from virtual pages to frames, kept in memory. The TLB is a small CPU cache of recent entries from it, so most translations skip the table walk.

### What happens on a page fault?

The CPU traps to the kernel. If the page is valid, the kernel maps a page without disk I/O (minor) or reads it from disk (major), then retries. If not, the process gets SIGSEGV.

### Paging vs segmentation?

Paging uses fixed-size pages; segmentation uses variable-size segments such as code, heap and stack. See [Paging vs Segmentation](compare:paging-vs-segmentation).
