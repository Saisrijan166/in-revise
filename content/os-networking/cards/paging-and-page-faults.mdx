## What it is

Paging is how [virtual memory](card:virtual-memory) is actually built. The OS cuts each process's address space into fixed-size blocks called pages, and cuts RAM into blocks of the same size called frames. A page table, one per process, records which frame holds each page. The TLB (Translation Lookaside Buffer) is a small cache inside the CPU that remembers recent page-to-frame mappings so the common translation is fast.

## Why it exists

If you gave each process one contiguous block of RAM, you would waste memory in the gaps left between blocks and struggle to find a gap big enough when memory is busy. Fixed-size pages solve this: any page can go in any free frame, so there are no awkward gaps to fit. Paging also lets the OS give a process RAM only for the pages it actually touches, instead of all of its address space at once.

## How it works

<Steps label="Translating one virtual address">
<Step title="Split the address">The virtual address is split into a virtual page number and an offset inside the page.</Step>
<Step title="Check the TLB">The CPU looks up the page number in the TLB; a hit gives the frame number at once.</Step>
<Step title="Walk the page table">On a TLB miss, the CPU reads the page table in RAM to find the frame, then caches that entry in the TLB.</Step>
<Step title="Handle a page fault">If the page is not present in RAM, the CPU traps to the kernel, which allocates or reads the page, updates the table, and retries the instruction.</Step>
<Step title="Combine">The frame number plus the offset gives the final physical address.</Step>
</Steps>

So the key is that most accesses are fast TLB hits, and the page table and page faults handle the rarer cases behind the scenes.

## Example

This reads the page size and huge-page size of a Linux machine, the fixed block sizes paging works in.

```bash
getconf PAGESIZE
grep Hugepagesize /proc/meminfo
```

```text output
4096
Hugepagesize:       2048 kB
```

What to notice:

- `PAGESIZE` is 4096 bytes (4 KiB), the standard page and frame size on x86-64 Linux, so all mapping happens in 4 KiB units.
- `Hugepagesize` is 2048 kB (2 MiB): one huge page covers 512 normal pages with a single TLB entry, so huge pages stretch how much memory the TLB can cover.
- These sizes are why a process's RSS always moves in multiples of 4 KiB.

## Rules and defaults

- **Page size:** 4 KiB on x86-64 Linux by default; huge pages are 2 MiB, or 1 GiB where the CPU supports them.
- **Demand paging:** a page is given a real frame only when it is first touched, not when it is allocated.
- **Fault types:** a minor fault is served without disk I/O (for example a fresh zeroed page or a page already in the page cache); a major fault must read the page from disk and is far slower.
- **Fragmentation:** paging removes external fragmentation (no gaps between blocks), but the unused tail of the last page of an allocation is internal fragmentation.
- **When RAM is full:** a new page needs a frame, so the OS must evict one; that choice is [page replacement](card:page-replacement).

## Not to be confused with

- **Paging:** memory is split into fixed-size pages, each placed in any free frame.
- **[Segmentation](card:paging-vs-segmentation):** memory is split into variable-size segments that match logical parts such as code, heap and stack.

Rule: paging = fixed-size blocks and a page table; segmentation = variable-size blocks sized to the program's logical parts.

## Interview Qs

### What is the difference between a page table and a TLB?

The page table is the full map from every virtual page to its frame, kept in RAM, one per process. The TLB is a small cache inside the CPU holding recently used entries from that table. Most translations hit the TLB and skip the slower page-table walk in memory.

### What happens on a page fault?

The CPU traps to the kernel. If the page is valid but not in RAM, the kernel either maps a page with no disk I/O (minor fault) or reads it from disk (major fault), updates the page table, and retries the instruction. If the address is invalid, the process gets SIGSEGV instead.

### What is the difference between paging and segmentation?

Paging uses fixed-size pages placed in any free frame, mapped by a page table. Segmentation uses variable-size segments, one per logical part like code or stack, each with a base and a bound. Modern x86-64 systems use paging; see [Paging vs Segmentation](compare:paging-vs-segmentation).
