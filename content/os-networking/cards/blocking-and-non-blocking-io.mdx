## Why it exists

Backend work is mostly waiting: a database call takes milliseconds while the CPU sits idle ([concurrency](card:concurrency-and-parallelism)). How a thread waits decides how many threads you need.

## How it works

<Compare id="blocking-vs-non-blocking-io" />

| Model | The thread... | Linux example |
|---|---|---|
| Blocking, sync | sleeps inside the call until data is copied | plain `read()` |
| Non-blocking, sync | gets EAGAIN, comes back later | `O_NONBLOCK` |
| Readiness (multiplexed) | waits on many fds, then reads the ready ones | [epoll](card:io-multiplexing) |
| Async completion | submits the work; the kernel reports when done | io_uring, POSIX aio |

- The first three are synchronous: your thread still copies the data.
- Java 21+ [virtual threads](card:thread-pools) make blocking code cheap again.

## Example

In non-blocking mode a Java NIO read returns 0 bytes instead of waiting:

```java
var addr = new InetSocketAddress("localhost", 8080);
try (var server = ServerSocketChannel.open().bind(addr);
     var client = SocketChannel.open(addr);
     var conn = server.accept()) {
    conn.configureBlocking(false);                  // like O_NONBLOCK
    System.out.println("non-blocking read: " + conn.read(ByteBuffer.allocate(64)));
    conn.configureBlocking(true);                   // reads wait again
    client.write(ByteBuffer.wrap("GET /orders/42".getBytes()));
    System.out.println("blocking read: " + conn.read(ByteBuffer.allocate(64)));
}
```

```text output
non-blocking read: 0
blocking read: 14
```

## Interview Qs

### Blocking vs non-blocking I/O?

Blocking I/O makes the calling thread wait until the operation can complete. Non-blocking I/O returns at once, with EAGAIN if nothing is ready, so the thread can serve other work and come back when the fd is ready.

### Is non-blocking the same as asynchronous?

No. Non-blocking means the call does not wait; you still wait for readiness and copy the data yourself. Asynchronous I/O hands the whole operation to the kernel, which reports completion, as io_uring does.
