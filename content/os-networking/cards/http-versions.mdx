## Why it exists

Pages and APIs make many requests at once. Opening a connection per request is slow, and waiting in line on one connection is slow too.

## How it works

<Compare id="http1-vs-http2-vs-http3" />

- Client and server agree the version in the TLS handshake with [ALPN](card:alpn); servers advertise HTTP/3 with [Alt-Svc](card:alt-svc).
- QUIC [connection IDs](card:connection-migration) keep a connection alive when a phone moves from Wi-Fi to mobile data.

## Defaults

| What | Default | Where |
|---|---|---|
| Persistent connections | On | HTTP/1.1 (RFC 9112) |
| Parallel connections per origin | About 6 | Browsers over HTTP/1.1 (MDN) |

## Interview Qs

### Why does HTTP/3 run over UDP?

UDP already works across existing networks and systems. QUIC adds streams, loss recovery, congestion control and TLS 1.3 on top, with each stream recovering its own losses and setup in one round trip.

### What does HTTP/2 change in a system design?

One connection per client instead of about six: fewer handshakes, fewer sockets on the load balancer, longer-lived connections. Domain sharding stops helping.
