## Why it exists

Rows need a stable id to be found, updated and linked. Keys give that id, and foreign keys stop links to rows that do not exist.

## How it works

  alt="Super keys are any unique column sets. The minimal ones are candidate keys. One candidate key is chosen as the primary key; the others are alternate keys. A foreign key in another table references the primary key."
  chart={`flowchart LR
  SK[Super keys: any unique set] --> CK[Candidate keys: minimal]
  CK --> PK[Primary key: the chosen one]
  CK --> AK[Alternate keys: the rest]

/>

- [Composite key](card:composite-key): columns unique only together, like `(student_id, course_id)`.
- [Surrogate](card:surrogate-key) (generated id) or [natural](card:natural-key) (email); generating ids is in [ID generation](card:id-generation).
- Delete rules are in [constraints](card:constraints); where the FK goes is in [relationships](card:relationships); FK indexes are in [indexes](card:indexes).

## Example

```sql
CREATE TABLE users (
  id    BIGINT PRIMARY KEY,
  email TEXT NOT NULL UNIQUE                 -- alternate key
);
CREATE TABLE orders (
  id      BIGINT PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users (id),
  amount  NUMERIC(10,2)
);
INSERT INTO orders VALUES (1, 99, 500);      -- fails if user 99 is missing
```

## Interview Qs

### Super key vs candidate key vs primary key?

A super key is any column set that is unique. A candidate key is a minimal super key: drop any column and it stops being unique. The primary key is the candidate you pick; the rest are alternate keys.

### Can a foreign key be NULL or repeated?

Yes to both. Many child rows can hold the same parent id, and a NULL FK means "no parent" and passes the check. Add NOT NULL when every child must have a parent.
