## Why it exists

Copies on several machines must agree, but networks fail. CAP names the one choice left when the copies cannot talk to each other.

- With no partition, a system can give both C and A; the choice applies only during the split.
- See [Strong vs Eventual](compare:strong-vs-eventual-consistency) for what an AP read may return.

## Interview Qs

### Why is "CA" not a real choice?

Dropping P works only if nodes can never lose contact, and no real network promises that. So the real question is what the system gives up, C or A, while a partition lasts.

### Is the C in CAP the same as the C in ACID?

No. CAP's C means every read returns the latest write, as if there were one copy. ACID's [consistency](card:acid) means a transaction keeps the database's rules and constraints valid.

### When would you choose AP over CP?

When an answer now beats a perfectly fresh one, like a shopping cart or a feed. Choose CP when a stale read costs money or safety, like an account balance or stock count.
