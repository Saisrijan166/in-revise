## What it is

The CAP theorem is a rule about databases that keep copies of data on several servers, called nodes. It says that when the network between nodes breaks, which is called a network partition, the system cannot give both consistency (every read returns the latest write) and availability (every request to a running node gets an answer). It must give up one of them until the network heals. P stands for partition tolerance: the system keeps working while nodes cannot reach each other.

## Why it exists

[Replication](card:replication) puts copies of the payments data on several machines, and the network between machines does fail. When node A has the new balance and node B cannot reach A, B must either answer with what it has, which may be old, or refuse. No design avoids this choice. CAP names it, so you decide it for each kind of data in advance instead of discovering it during an outage.

## How it works

1. A customer's balance is 1000 on both nodes. A payment changes it to 500 on node A.
2. The link between the nodes breaks before node B receives the change.
3. Another request reads the balance from node B.
4. A CP system makes node B refuse or time out, because it cannot confirm it has the latest value. An AP system makes node B answer 1000, the old value.
5. When the link heals, the nodes exchange changes and agree again.

So the key is: the choice exists only while the partition lasts. With a healthy network, a system can be both consistent and available.

## Example

The payment service makes the choice per kind of data, by asking what a stale read would cost:

| Data | What a stale read costs | Choice during a partition |
|---|---|---|
| Wallet balance checked before a refund | Money: the same refund could be paid twice | CP: refuse until the latest value is known |
| A customer's payment history page | A payment shows up a few seconds late | AP: answer now with what this node has |

What to notice:

- One system can make different choices for different data. CAP is a decision per operation, not a label for a whole product.
- The AP side is [eventual consistency](card:eventual-consistency): the copies agree again once updates stop flowing and the link is back.

## Rules and defaults

- **C means linearizable:** every operation looks as if it ran at one instant on one copy. ACID's C means a transaction keeps constraints valid. They are different properties.
- **P is not optional:** a system on several machines cannot promise the network never splits, so "CA" fits only a system whose network can never split, in practice a single node.
- **Examples (Abadi, 2012):** HBase is CP. Cassandra and Dynamo, in their default setup, are AP.
- **PACELC:** if there is a Partition, choose Availability or Consistency; Else, choose Latency or Consistency. A read from an asynchronous replica is fast but may be stale; waiting for the primary is fresh but slower.
- **For SQL databases:** CAP matters once you read from replicas or run several nodes. A single PostgreSQL or MySQL server has no partition to tolerate.

## Not to be confused with

- **Strong consistency** means every read sees the latest write. **Eventual consistency** means copies may differ for a while but agree once updates stop. Rule: CP keeps strong consistency; AP accepts eventual consistency.
- **[ACID's consistency](card:acid)** means every transaction leaves the data valid under its rules and constraints. Rule: CAP's C is about copies agreeing; ACID's C is about rules holding.

## Interview Qs

### Why is "CA" not a real choice?

Giving up P works only if nodes can never lose contact, and no real network promises that. So the real question is what the system gives up, consistency or availability, while a partition lasts.

### Is the C in CAP the same as the C in ACID?

No. CAP's C means every read returns the latest write, as if there were one copy. ACID's [consistency](card:acid) means a transaction keeps the database's rules and constraints valid.

### When would you choose AP over CP?

When an answer now is worth more than a perfectly fresh one, as for a shopping cart, a feed or a like count. Choose CP when a stale read costs money or safety, as for an account balance or the last unit of stock.
