## Why it exists

GROUP BY gives one row per group, so you lose the detail rows. Ranking, running totals and "change since last month" need the group's numbers next to each row.

## How it works

<Compare id="group-by-vs-partition-by" />

- Only in SELECT and ORDER BY: [they run after WHERE and HAVING](card:query-order).
- Top N per group, running totals and streaks: see [the patterns](card:top-n-per-group).

## Example

```sql
SELECT name, salary,
       ROW_NUMBER() OVER w AS rn,
       RANK()       OVER w AS rnk,
       DENSE_RANK() OVER w AS drnk,
       LAG(salary)  OVER w AS prev
FROM employees
WINDOW w AS (ORDER BY salary DESC);
```

```text
salary  rn  rnk  drnk  prev
100     1   1    1     NULL
100     2   1    1     100
90      3   3    2     100
```

## Interview Qs

### ROW_NUMBER vs RANK vs DENSE_RANK?

All number rows in order. On ties, ROW_NUMBER still counts 1, 2, 3; RANK shares the rank and skips (1, 1, 3); DENSE_RANK shares it without gaps (1, 1, 2).

### Can you filter on a window function in WHERE?

No. WHERE runs before window functions. Compute it in a subquery or CTE, then filter outside: `WHERE rn = 1`.
