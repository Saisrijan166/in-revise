## What it is

A window function is a function with an `OVER (...)` clause that computes a value from a set of rows related to the current row, called its window. Unlike `GROUP BY`, it does not merge the rows: every input row stays in the result, with the computed value next to it. `PARTITION BY` inside `OVER` says which rows form the group, and `ORDER BY` inside `OVER` says their order.

## Why it exists

[GROUP BY](card:aggregates-group-by) gives one row per group, so the single rows are lost. "Show each payment with its customer's total" would need a grouped subquery joined back to the payments. Ranking, running totals and "change since the previous payment" are even harder that way, often needing a self-join. A window function puts the group's numbers right next to each row in one pass.

## How it works

<Compare id="group-by-vs-partition-by" />

1. `FROM`, `WHERE`, `GROUP BY` and `HAVING` run first and fix which rows exist, as in the [logical order](card:query-order).
2. For each window function, the rows are split by `PARTITION BY`; with no `PARTITION BY`, all rows form one partition.
3. Inside each partition, the rows are sorted by the `ORDER BY` written inside `OVER`.
4. For every row, the function looks at its window: the whole partition, the rows up to it, or the row just before it, and computes one value.
5. The value is added as a new column, and the outer `ORDER BY` then sorts the final rows.

## Example

Three PAID payments: Asha (customer 1) paid 500 and then 700; Ravi (customer 2) paid 700.

```sql
SELECT id, customer_id, amount,
       SUM(amount) OVER (PARTITION BY customer_id) AS customer_total,
       RANK()      OVER (ORDER BY amount DESC)     AS amount_rank,
       LAG(amount) OVER (PARTITION BY customer_id
                         ORDER BY created_at)      AS prev_amount
FROM payments
WHERE status = 'PAID'
ORDER BY id;
```

```text output
 id | customer_id | amount | customer_total | amount_rank | prev_amount
----+-------------+--------+----------------+-------------+-------------
  1 |           1 | 500.00 |        1200.00 |           3 |        NULL
  3 |           2 | 700.00 |         700.00 |           1 |        NULL
  4 |           1 | 700.00 |        1200.00 |           1 |      500.00
```

What to notice:

- All three payments stay, and each shows its customer's total. `GROUP BY customer_id` would return only two rows.
- Payments 3 and 4 tie at 700, so both get rank 1 and the next rank is 3.
- `LAG` is NULL for each customer's first payment, because `PARTITION BY` restarts at each customer. Payment 4's previous amount is Asha's 500.
- PostgreSQL 18 and MySQL 9.7 return the same rows.

## Rules and defaults

- **Where allowed:** only in the SELECT list and `ORDER BY`. To filter on one, compute it in a [subquery](card:subqueries) or CTE and filter outside.
- **Default frame:** with `ORDER BY` in `OVER`, an aggregate covers the partition start up to the current row and its ties (`RANGE`). Without `ORDER BY`, it covers the whole partition.
- **ROWS vs RANGE:** `ROWS` counts physical rows; `RANGE` treats rows tied in the sort as one step.
- **LAG and LEAD:** the offset is 1 and the default is NULL; `LAG(amount, 1, 0)` returns 0 instead.
- **Ties in ROW_NUMBER:** tied rows get numbers in no fixed order; add a unique column such as `id` to the `ORDER BY`.
- **Named windows:** `WINDOW w AS (ORDER BY amount DESC)` lets several functions share one `OVER w`.

## Interview Qs

### What is the difference between ROW_NUMBER, RANK and DENSE_RANK?

All three number rows in the window's order; they differ only on ties. ROW_NUMBER gives every row a different number, 1, 2, 3. RANK gives tied rows the same rank and then skips, 1, 1, 3. DENSE_RANK gives tied rows the same rank without a gap, 1, 1, 2. DENSE_RANK suits "Nth highest distinct value".

### Can you filter on a window function in WHERE?

No. WHERE runs before window functions are computed, and PostgreSQL rejects it with "window functions are not allowed in WHERE". Compute the value in a subquery or CTE, for example as `rn`, and write `WHERE rn = 1` in the outer query.

### How do you compare each row with the previous one?

Use `LAG(column) OVER (ORDER BY ...)`, adding `PARTITION BY` if the comparison should restart per group. It returns the previous row's value without a self-join, so `amount - LAG(amount) OVER (...)` gives the change. The first row gets NULL unless you pass a default.
