## What it is

Top N per group means picking the best N rows inside each group, such as the three highest-paid employees in each department. "Nth highest" is the one-group case: the second highest salary in the whole company. Both need a rank on every row, from a [window function](card:window-functions), because `GROUP BY` returns one value per group, not the rows behind it.

## Why it exists

`GROUP BY dept` with `MAX(salary)` tells you the top Eng salary is 100, but not who earns it, and two people might. `LIMIT 3` does not help either: it cuts the whole result, not each department. Ranking the rows inside each group and then keeping the wanted ranks answers both "who" and "how many per group".

## How it works

| Question | Use | Ties |
|---|---|---|
| Second highest value | `MAX(x) WHERE x < (SELECT MAX(x) …)` | Counts distinct values |
| Nth highest value | `DENSE_RANK() = N`, or `DISTINCT … LIMIT 1 OFFSET N-1` | Counts distinct values |
| Top N per group | `DENSE_RANK() <= N` | Every tied row kept |
| Exactly N per group | `ROW_NUMBER() <= N`, with `id` in ORDER BY | Broken by the tie-breaker |
| Latest per customer | `ROW_NUMBER() = 1`, ORDER BY time DESC, id DESC | Broken by `id` |

1. In a subquery, add a rank column: `DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC)`. `PARTITION BY` restarts the numbering in each department.
2. Choose the function by how ties should count. `DENSE_RANK` gives tied rows the same rank; `ROW_NUMBER` gives every row its own number, so add a unique tie-breaker.
3. In the outer query, keep the ranks you want: `WHERE rnk <= 3`. This filter must be outside, because `WHERE` runs before window functions.
4. For a single value over the whole table, a shorter form works: `MAX` below `MAX` for the second highest, or `DISTINCT … LIMIT 1 OFFSET N-1` for the Nth.

## Example

Top three salary levels in each department. Eng pays Asha 100, Ravi 100, Meena 90, Kiran 80 and Dev 70; Sales pays Kabir 60 and Neha 50.

```sql
SELECT dept, name, salary, rnk
FROM (
  SELECT e.*,
         DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rnk
  FROM employees e
) ranked
WHERE rnk <= 3
ORDER BY dept, rnk, name;
```

```text output
 dept  | name  | salary | rnk
-------+-------+--------+-----
 Eng   | Asha  |    100 |   1
 Eng   | Ravi  |    100 |   1
 Eng   | Meena |     90 |   2
 Eng   | Kiran |     80 |   3
 Sales | Kabir |     60 |   1
 Sales | Neha  |     50 |   2
```

What to notice:

- Eng returns 4 rows for 3 salary levels, because Asha and Ravi tie at 100. Dev (rank 4) is dropped.
- Sales has only two employees and returns both; a group smaller than N is not an error.
- Swap in `ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC, id)` and Eng returns exactly Asha, Ravi and Meena: Kiran is cut although he holds the third salary level.
- The alias `ranked` is required in MySQL 9.7 (error 1248 without it). PostgreSQL 18 allows leaving it out, but keep it so the query runs on both.

## Rules and defaults

- **NULL salaries:** PostgreSQL sorts NULLs first in `DESC` order and MySQL last ([NULL handling](card:null-handling)), so in PostgreSQL a NULL salary gets rank 1. Add `WHERE salary IS NOT NULL`.
- **A missing Nth value:** `SELECT (SELECT DISTINCT salary … ORDER BY salary DESC LIMIT 1 OFFSET N-1)` returns NULL when there is no Nth salary, instead of no row at all.
- **PostgreSQL shortcuts:** `DISTINCT ON (dept) … ORDER BY dept, salary DESC` keeps one row per group, and `FETCH FIRST 3 ROWS WITH TIES` adds rows tied with the third. MySQL 9.7 supports neither.

## Not to be confused with

`ROW_NUMBER` numbers rows 1, 2, 3 even when values tie. `RANK` gives tied rows the same rank and then skips (1, 1, 3). `DENSE_RANK` gives tied rows the same rank without a gap (1, 1, 2). Rule: `DENSE_RANK` for "top 3 salary levels", `ROW_NUMBER` for "exactly 3 people" or "the latest one".

## Interview Qs

### Find the Nth highest salary. What if there are fewer than N salaries?

`SELECT (SELECT DISTINCT salary FROM employees WHERE salary IS NOT NULL ORDER BY salary DESC LIMIT 1 OFFSET N-1)`. `DISTINCT` makes the offset count values, not rows. Wrapping it as a scalar subquery returns one row with NULL when no Nth value exists, instead of no row at all.

### Find each customer's latest payment.

Rank with `ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY created_at DESC, id DESC)` in a subquery and keep `rn = 1`. In PostgreSQL, `SELECT DISTINCT ON (customer_id) * FROM payments ORDER BY customer_id, created_at DESC, id DESC` does the same in one step.

### Why not GROUP BY dept with MAX(salary) for the top earner per department?

It returns the top salary, not the employee. Adding `name` to the SELECT list fails in PostgreSQL and in MySQL's default mode, because `name` is not grouped. It would also hide a tie. Ranking keeps the whole row and every tied employee.
