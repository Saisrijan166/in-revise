## Why it exists

GROUP BY returns one value per group, not the rows holding it, so "Nth highest" and "top N per group" need a rank.

## How it works

| Question | Use | Ties |
|---|---|---|
| Second highest value | `MAX(x) WHERE x < (SELECT MAX(x) …)` | Ignored: distinct values |
| Nth highest value | `DENSE_RANK() = N` | One value |
| Top N per group | `DENSE_RANK() <= N` | All tied rows kept |
| Exactly N per group | `ROW_NUMBER() <= N` | Broken by the tie-breaker |
| Latest per user | `ROW_NUMBER() = 1`, ORDER BY time DESC, id DESC | Broken by id |

- MySQL needs the subquery alias (`ranked`).
- PostgreSQL sorts NULLs first in DESC order, so a NULL salary ranks 1: filter it out.

## Example

```sql
-- Top 3 salary levels per department
SELECT dept_id, name, salary, rnk
FROM (
  SELECT e.*,
         DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rnk
  FROM employees e
) ranked
WHERE rnk <= 3;
```

```text
dept_id | name | salary | rnk
1       | A    | 100    | 1
1       | B    | 100    | 1     <- tie: 4 rows
1       | C    | 90     | 2
1       | D    | 80     | 3
```

## Interview Qs

### Nth highest salary: what if there are fewer than N salaries?

`SELECT (SELECT DISTINCT salary FROM employees WHERE salary IS NOT NULL ORDER BY salary DESC LIMIT 1 OFFSET 2);` gives the 3rd, or NULL if there is none.

### Latest order per user in PostgreSQL, the short way?

`SELECT DISTINCT ON (user_id) * FROM orders ORDER BY user_id, created_at DESC, id DESC;` keeps each user's first row. MySQL lacks it.
