## Why it exists

Reports ask per-group questions: orders per user, revenue per city. Aggregates turn many rows into one number; GROUP BY says which rows belong together.

## How it works

<Compare id="where-vs-having" />

- Total of nothing should be 0: write `COALESCE(SUM(amount), 0)`.

## Example

```sql
-- orders: user 1 paid 800 and 400; user 2 paid 900, refunded 500
SELECT user_id, COUNT(*) AS orders, SUM(amount) AS total
FROM orders
WHERE status = 'PAID'          -- rows first
GROUP BY user_id
HAVING SUM(amount) > 1000;     -- then groups
```

```text output
 user_id | orders | total
---------+--------+-------
       1 |      2 |  1200
```

Counting a column holding 10, 10, NULL:

```sql
SELECT COUNT(*) AS all_rows, COUNT(col) AS non_null,
       COUNT(DISTINCT col) AS distinct_values
FROM (SELECT 10 AS col UNION ALL SELECT 10 UNION ALL SELECT NULL) t;
```

```text output
 all_rows | non_null | distinct_values
----------+----------+-----------------
        3 |        2 |               1
```

## Interview Qs

### COUNT(*) vs COUNT(column)?

COUNT(*) counts every row. COUNT(column) counts rows where that column is not NULL. They differ exactly when the column has NULLs.

### Why does SELECT name, city, COUNT(*) FROM users GROUP BY city fail?

Each group has many names, so the database cannot pick one. PostgreSQL and MySQL reject it, unless `name` depends on the grouped key, such as when you group by the primary key.
