## Why it exists

Real data is linked: users place orders, students take courses. Each kind of link needs the foreign key in a different place, or data repeats or cannot be stored.

## How it works

- A junction table can carry facts about the link itself, such as `enrolled_on`.
- Walk a self-referencing tree (org chart) with a [recursive CTE](card:ctes).

## Example

```sql
CREATE TABLE enrolments (
  student_id  BIGINT REFERENCES students (id),
  course_id   BIGINT REFERENCES courses (id),
  enrolled_on DATE NOT NULL,
  PRIMARY KEY (student_id, course_id)
);
CREATE TABLE profiles (
  user_id BIGINT NOT NULL UNIQUE REFERENCES users (id),
  bio     TEXT
);
```

## Interview Qs

### How do you model a many-to-many relationship?

With a junction table holding a foreign key to each side, one row per link. Make the pair its primary key so a link cannot be stored twice.

### How do you store each employee's manager?

A nullable `manager_id` column that references `employees.id` in the same table. The top manager has NULL. Query the chain with a self join or a recursive CTE.
