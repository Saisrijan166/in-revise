## Why it exists

Imports and retried inserts without a unique key leave repeated rows. You must find them, keep exactly one of each, and stop new ones.

## How it works

<Steps label="Clean up duplicate emails">
  <Step title="Find">`GROUP BY email HAVING COUNT(*) > 1` lists each repeated email once.</Step>
  <Step title="Inspect">`COUNT(*) OVER (PARTITION BY email)` keeps every row with its count.</Step>
  <Step title="Delete extras">`ROW_NUMBER() OVER (PARTITION BY email ORDER BY id) > 1` keeps the lowest id.</Step>
  <Step title="Prevent">Add a [UNIQUE constraint](card:constraints) on email.</Step>
</Steps>

- Add `WHERE email IS NOT NULL`, or the NULL emails form one "duplicate" group.
- MySQL blocks a DELETE whose subquery reads the same table, unless that read is a materialised derived table, as below.

## Example

```sql
DELETE FROM users
WHERE id IN (
  SELECT id FROM (
    SELECT id, ROW_NUMBER() OVER (PARTITION BY email ORDER BY id) AS rn
    FROM users
    WHERE email IS NOT NULL
  ) ranked
  WHERE rn > 1
);
```

## Interview Qs

### Delete duplicate emails, keeping the lowest id, without a window function?

Self-join. PostgreSQL: `DELETE FROM users u USING users d WHERE u.email = d.email AND u.id > d.id;` MySQL: `DELETE u FROM users u JOIN users d ON u.email = d.email AND u.id > d.id;` NULL emails never match, so they stay.

### How do you stop duplicates coming back?

Add a UNIQUE constraint or unique index on the column, after the clean-up or it fails. For concurrent writers use an [upsert](card:upsert) rather than "check, then insert".
