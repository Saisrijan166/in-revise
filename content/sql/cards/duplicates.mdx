## What it is

A duplicate is two or more rows that hold the same value in a column that should be unique, such as two sign-ups with the same email. Handling duplicates has three parts: find them by grouping, delete the extra copies while keeping one, and add a [UNIQUE constraint](card:constraints) so they cannot come back. A duplicate can also be defined by several columns together, such as name and city.

## Why it exists

Duplicates come from an import that ran twice, or from app code that checks "does this email exist?" and then inserts, so two requests at the same moment both insert. They break reports and joins: one customer counted twice, one email sent twice. Deleting by hand misses copies, and a careless `DELETE` removes the original along with its copies.

## How it works

<Mermaid
  alt="Four steps from left to right: find repeated values with GROUP BY and HAVING, number the copies of each value with ROW_NUMBER, delete every row numbered above 1, then add a UNIQUE constraint."
  chart={`flowchart LR
  F[1. Find: GROUP BY + HAVING] --> N[2. Number copies: ROW_NUMBER]
  N --> D[3. Delete rn > 1] --> U[4. Add UNIQUE]`}
/>

1. Find the repeated values: `GROUP BY email HAVING COUNT(*) > 1` returns each repeated email once, with its count.
2. Number the copies of each value: `ROW_NUMBER() OVER (PARTITION BY email ORDER BY id)` gives the oldest row 1 and its copies 2, 3 and so on.
3. Delete every row whose number is above 1. The `ORDER BY` inside the window decides which copy survives: `ORDER BY id` keeps the oldest.
4. Add a `UNIQUE` constraint on the column, so the database rejects any new copy.

## Example

An import loaded `signups(id, name, email)` with Asha three times (ids 1, 3, 5); Kabir (4) and Neha (6) have no email. First find the copies, then delete all but the oldest.

```sql
SELECT email, COUNT(*) AS copies
FROM signups
WHERE email IS NOT NULL
GROUP BY email
HAVING COUNT(*) > 1;

DELETE FROM signups
WHERE id IN (
  SELECT id FROM (
    SELECT id, ROW_NUMBER() OVER (PARTITION BY email ORDER BY id) AS rn
    FROM signups WHERE email IS NOT NULL
  ) ranked
  WHERE rn > 1);
```

```text output
    email     | copies
--------------+--------
 asha@mail.in |      3
DELETE 2
```

What to notice:

- The delete removed ids 3 and 5 and kept 1, 2, 4 and 6: Asha's oldest row survives, and the two rows without an email are untouched.
- Without `WHERE email IS NOT NULL`, the find query also reports NULL with 2 copies, because `GROUP BY` puts both missing emails in one group.
- The extra derived table `ranked` is what lets MySQL run this delete; the same statement works unchanged in PostgreSQL 18.

## Rules and defaults

- **MySQL same-table rule:** MySQL 9.7 rejects a `DELETE` or `UPDATE` whose subquery reads the same table directly (error 1093). A derived table that MySQL materialises is allowed, and a window function inside it prevents merging, so it is materialised.
- **Several columns:** for duplicates on name and city, use `GROUP BY name, city` and `PARTITION BY name, city`.
- **UNIQUE after the clean-up:** adding the constraint fails while duplicates exist. By default it still allows many NULLs, in PostgreSQL 18 and MySQL 9.7.

## Not to be confused with

`SELECT DISTINCT email` removes repeated values from one query's result; the table still holds every copy. Deleting duplicates changes the table itself. Rule: `DISTINCT` hides duplicates in a result; `DELETE` with `ROW_NUMBER` removes them from the data.

## Interview Qs

### Delete duplicate emails, keeping the lowest id, without a window function.

Join the table to itself. PostgreSQL: `DELETE FROM signups s USING signups d WHERE s.email = d.email AND s.id > d.id;` MySQL: `DELETE s FROM signups s JOIN signups d ON s.email = d.email AND s.id > d.id;` Each copy finds an older row and is deleted. NULL emails never match, so they stay.

### How do you stop duplicates from coming back?

Add a `UNIQUE` constraint or unique index on the column after the clean-up. For two writers at the same moment, "check, then insert" in app code is not enough; let the constraint reject the second insert, or use an [upsert](card:upsert).
