## Why it exists

Some questions need one answer before another: "users who spent more than the average". A subquery computes the inner answer in place.

## How it works

| Kind | Returns | Example |
|---|---|---|
| Scalar | one value | `WHERE amount > (SELECT AVG(amount) FROM orders)` |
| IN | a list | `WHERE id IN (SELECT user_id FROM orders)` |
| EXISTS | true or false | `WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id)` |
| Derived table | a table | `FROM (SELECT user_id, SUM(amount) AS t FROM orders GROUP BY user_id) AS s` |

- The EXISTS row is correlated: `u.id` comes from the outer query.
- NOT IN with NULLs: see [NULL](card:null-handling).

## Example

```sql
-- users with at least one order over 5000
-- orders: Asha 7000, Ravi 3000
SELECT u.name
FROM users u
WHERE EXISTS (
  SELECT 1 FROM orders o
  WHERE o.user_id = u.id AND o.amount > 5000
);
```

```text output
 name
------
 Asha
```

## Interview Qs

### Correlated vs non-correlated subquery?

A non-correlated subquery stands alone and can run once. A correlated one refers to the outer row, so logically it runs for each outer row.

### What happens if a scalar subquery returns two rows?

The query fails at run time. Make it return one row with an aggregate, a unique key or LIMIT 1 with ORDER BY.
