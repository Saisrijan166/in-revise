## What it is

An anti-join returns the rows of one table that have no matching row in another, such as customers who never paid. Its opposite, a semi-join, returns the rows that have at least one match, each row once. SQL has no `ANTI JOIN` keyword: you write it with `NOT EXISTS`, or with a [LEFT JOIN](card:joins) that keeps only the unmatched rows.

## Why it exists

An inner join keeps only matches, so a customer with no payment silently disappears from the result. Questions with "never", "without any" or "not in the other table" ask for exactly those missing rows. The obvious tool, `NOT IN`, returns no rows at all when the subquery contains one NULL, so a NULL-safe pattern is needed.

## How it works

| Form | Returns | If the subquery column holds a NULL |
|---|---|---|
| `NOT EXISTS (… WHERE p.customer_id = c.id)` | Customers with no match | Still correct |
| `LEFT JOIN payments p ON … WHERE p.id IS NULL` | Customers with no match | Still correct |
| `c.id NOT IN (SELECT customer_id …)` | Customers with no match | No rows at all |
| `EXISTS (…)`, the semi-join | Customers with a match, once each | Still correct |

1. Start from the table whose rows you want back: `customers`.
2. Write the match condition, `p.customer_id = c.id`, plus any condition on the match itself, such as `p.status = 'PAID'`.
3. With `NOT EXISTS`, put both conditions inside the subquery. The customer is kept when the subquery finds no row.
4. With `LEFT JOIN`, put both conditions in `ON`, then keep the rows where the payment's key is NULL. Only unmatched rows have NULL there.

## Example

"Find customers who never had a successful payment." Meena has only a PENDING payment and Kabir has none. Both forms give the same answer.

```sql
SELECT c.id, c.name
FROM customers c
WHERE NOT EXISTS (
  SELECT 1 FROM payments p
  WHERE p.customer_id = c.id AND p.status = 'PAID'
);

SELECT c.id, c.name
FROM customers c
LEFT JOIN payments p ON p.customer_id = c.id AND p.status = 'PAID'
WHERE p.id IS NULL;
```

```text output
 id | name
----+-------
  3 | Meena
  4 | Kabir
```

What to notice:

- Meena is returned although she has a payment, because the status test is part of the match. Drop `p.status = 'PAID'` and only Kabir comes back.
- In the join form, moving `p.status = 'PAID'` from `ON` to `WHERE` returns no rows: an unmatched row has NULL in every payment column.
- Test `p.id`, the primary key, which is never NULL in a real match; a nullable column could be NULL in a matched row too.
- `SELECT 1` only says "a row exists"; the subquery's columns are never read.

## Rules and defaults

- **NOT IN and NULL:** `4 NOT IN (1, 2, NULL)` is NULL, not true, so the row is dropped ([NULL handling](card:null-handling)). If you must use `NOT IN`, add `WHERE customer_id IS NOT NULL` inside the subquery.
- **EXISTS for "at least one":** an inner join lists Asha once per PAID payment, three times; `EXISTS` lists her once.
## Not to be confused with

`NOT EXISTS` returns whole rows of the first table that have no match, such as each customer's id and name. `EXCEPT` subtracts one query's result from another's: `SELECT id FROM customers EXCEPT SELECT customer_id FROM payments WHERE status = 'PAID'` gives ids 3 and 4, but only the compared column, with duplicates removed (PostgreSQL 18 and MySQL 9.7). Rule: rows with no match = `NOT EXISTS`; a difference of two value lists = [EXCEPT](card:set-operations). How `IN` and `EXISTS` differ is in [Subqueries](card:subqueries).

## Interview Qs

### NOT EXISTS, LEFT JOIN … IS NULL or NOT IN: which is fastest?

It depends on the product and version, so check with [EXPLAIN](card:explain-query-plans). PostgreSQL and MySQL can both plan `NOT EXISTS` as an antijoin. Choose for correctness first: `NOT IN` changes the answer when NULLs exist, while `NOT EXISTS` stays correct.

### Find customers who made at least one payment, without repeating anyone.

`SELECT c.* FROM customers c WHERE EXISTS (SELECT 1 FROM payments p WHERE p.customer_id = c.id)`. An inner join would return a customer once per payment, and fixing that with `DISTINCT` does extra work.
