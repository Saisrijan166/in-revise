## What it is

A join combines rows from two tables into one result row whenever a condition is true. The condition comes after `ON` and usually says that a [foreign key](card:keys) equals a primary key: `p.customer_id = c.id` pairs each payment with its customer. An INNER JOIN keeps only the pairs that match. A LEFT JOIN also keeps every row of the left table, the one written first, and fills the right table's columns with NULL where nothing matched.

## Why it exists

A good design stores each fact once, as you saw in [relationships](card:relationships): names live in `customers`, amounts in `payments`. But a report needs "customer name and amount" in one row. Without a join you would load both tables into Java and match them by hand, or copy the name into every payment. A join matches them inside the database and returns the combined rows.

## How it works

| Join | Keeps | Unmatched rows |
|---|---|---|
| INNER | only matching pairs | dropped |
| LEFT | every left row | right columns are NULL |
| RIGHT | every right row | left columns are NULL |
| FULL OUTER | every row of both tables | NULL on the missing side |
| CROSS | every pairing, no ON: 4 × 6 = 24 rows | none: everything pairs |
| Self join | a table joined to itself, under two aliases | depends on the join used |

Follow `customers c LEFT JOIN payments p ON p.customer_id = c.id`:

1. The database takes a customer row from the left table.
2. It finds every payment row for which the ON condition is true.
3. It outputs one combined row per matching payment, so Asha, with two payments, appears twice.
4. If no payment matches, an INNER JOIN outputs nothing for that customer; a LEFT JOIN outputs her once, with NULL in every payment column.
5. Only after all rows are joined does WHERE filter them.

So the key is: ON decides what matches; WHERE filters what the join produced.

## Example

Every customer with their paid payments, if any. `c` and `p` are aliases, short names for the two tables inside this query. Asha has two paid payments, Ravi and Meena one each (plus a failed and a pending one), and Arjun has none.

```sql
SELECT c.name, p.id AS payment_id, p.amount
FROM customers c
LEFT JOIN payments p
       ON p.customer_id = c.id
      AND p.status = 'PAID'
ORDER BY c.id, p.id;
```

```text output
 name  | payment_id | amount
-------+------------+--------
 Asha  |        101 | 500.00
 Asha  |        102 | 800.00
 Ravi  |        104 | 900.00
 Meena |        106 | 800.00
 Arjun |       NULL |   NULL
(5 rows)
```

What to notice:

- Arjun stays, with NULLs, because this is a LEFT JOIN and the status test is inside ON.
- Move `p.status = 'PAID'` into a WHERE and Arjun disappears: his NULL status is not 'PAID', so the result has the same 4 rows as an INNER JOIN.
- Ravi's failed payment does not appear, but Ravi does, because his paid payment matched.
- PostgreSQL 18 and MySQL 9.7 return the same five rows.

## Rules and defaults

- **Plain JOIN:** means INNER JOIN in both databases; `LEFT JOIN` and `LEFT OUTER JOIN` are the same.
- **NULL keys never match:** a payment whose customer_id is NULL joins to no customer, because `NULL = 1` is UNKNOWN.
- **RIGHT JOIN:** a LEFT JOIN with the tables swapped. The MySQL 9.7 manual advises writing LEFT JOIN for portability.
- **Join conditions:** most joins test equality (an equi join); a non-equi join uses another test, such as `p.amount BETWEEN band.low AND band.high`.

## Not to be confused with

An INNER JOIN returns only rows that matched on both sides. A LEFT JOIN returns those same rows plus each unmatched left row once, filled with NULLs. Rule: if every row of the first table must appear, use LEFT JOIN, and keep right-table filters in ON.

## Interview Qs

### Why did my SUM get bigger after I added a join?

A join repeats a row once per match. Asha paid 1300 in total, but if payment 102 has two refunds, joining refunds makes payment 102 appear twice, and SUM(p.amount) shows 2100. Aggregate each many side first, for example the refunds per payment in a subquery, then join one row per key.

### How do you get a FULL OUTER JOIN in MySQL?

MySQL has no FULL JOIN. Take a LEFT JOIN of the two tables, then UNION ALL a RIGHT JOIN filtered to rows with no left match, `WHERE c.id IS NULL`. Plain UNION of a LEFT and a RIGHT JOIN also works, but it removes real duplicate rows as well as the overlap.

### How do you list each employee with their manager's name?

A self join: join `employees` to itself under two aliases. `FROM employees e LEFT JOIN employees m ON m.id = e.manager_id` puts each employee next to the row of their manager. LEFT JOIN keeps the top manager, whose manager_id is NULL, with a NULL manager name.
