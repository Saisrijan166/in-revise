## Why it exists

Normalised data lives in separate tables: users in one, orders in another. A join puts the related rows back side by side for one answer.

## How it works

| Join | Keeps | Unmatched rows |
|---|---|---|
| INNER | matching pairs only | dropped |
| LEFT | every left row | right columns are NULL |
| RIGHT | every right row | left columns are NULL |
| FULL OUTER | every row from both | NULL on the missing side |
| CROSS | every pairing: 3 × 4 = 12 rows | no condition at all |
| SELF | a table with itself, two aliases | as the join type used |

- "Users with no orders" is an anti-join: see [rows with no match](card:anti-join-pattern).

## Example

```sql
-- every user, with their PAID orders if any
-- users: Asha, Ravi; orders: Asha 500 PAID, Asha 200 REFUNDED
SELECT u.name, o.amount
FROM users u
LEFT JOIN orders o ON o.user_id = u.id AND o.status = 'PAID'
ORDER BY u.name;
```

```text output
 name | amount
------+--------
 Asha |    500
 Ravi |   NULL
```

```sql
-- each employee with their manager's name
-- employees: Asha (no manager); Ravi and Meena report to Asha
SELECT e.name, m.name AS manager
FROM employees e
LEFT JOIN employees m ON m.id = e.manager_id
ORDER BY e.id;
```

```text output
 name  | manager
-------+---------
 Asha  | NULL
 Ravi  | Asha
 Meena | Asha
```

## Interview Qs

### Why did my SUM double after adding a join?

The left row repeats once per match, so joining two one-to-many tables multiplies rows. Aggregate each many side in a subquery first, then join one row per key.

### How do you do a FULL OUTER JOIN in MySQL?

MySQL has no FULL JOIN. UNION a LEFT JOIN with a RIGHT JOIN of the same tables. UNION drops the matched rows that appear twice, but also real duplicate rows; to keep those, use UNION ALL and a RIGHT JOIN filtered to rows with no left match.
