## Why it exists

Most "why does this error?" questions in SQL come from reading a query top to bottom. Each clause can only use what the earlier steps produced.

## How it works

<Steps label="Logical order of one SELECT">
  <Step title="FROM / JOIN">Build the combined rows.</Step>
  <Step title="WHERE">Keep rows where the condition is true.</Step>
  <Step title="GROUP BY">Fold rows into groups; aggregates are computed.</Step>
  <Step title="HAVING">Keep groups where the condition is true.</Step>
  <Step title="SELECT">Compute output columns, aliases and window functions.</Step>
  <Step title="DISTINCT">Drop duplicate output rows.</Step>
  <Step title="ORDER BY">Sort the output.</Step>
  <Step title="LIMIT / OFFSET">Return one slice.</Step>
</Steps>

## Example

```sql
SELECT user_id, SUM(amount) AS total
FROM orders
WHERE total > 1000          -- error: total does not exist yet
GROUP BY user_id;

SELECT user_id, SUM(amount) AS total
FROM orders
GROUP BY user_id
HAVING SUM(amount) > 1000   -- portable
ORDER BY total DESC;        -- alias is fine here
```

## Interview Qs

### Why can't I use a SELECT alias in WHERE?

WHERE is evaluated before SELECT, so the alias has no value yet. Repeat the expression, or wrap the query in a subquery or CTE and filter outside.

### Where are window functions computed?

After WHERE, GROUP BY and HAVING, together with the SELECT list. So they cannot be filtered in WHERE; filter them in an outer query.
