## What it is

A function takes a value and returns a new one, such as `LOWER('PAID')`, which returns 'paid'. String functions work on text: change case, trim spaces, cut out a part, join pieces. Date functions work on dates and timestamps (a date plus a time of day): get today, pull out the year, add 7 days, or round down to the first day of the month. You can use them in the SELECT list and in WHERE, and they run once for each row.

## Why it exists

Stored values are rarely in the shape a question wants. A report needs the month of each payment, not its exact second; a reference number needs 'PAY-' in front of the id; a name typed as ' asha ' needs cleaning before it can be compared. Without functions you would load the rows into Java and reshape them there. Functions do it inside the query, so only the finished values travel.

## How it works

| Need | PostgreSQL 18 | MySQL 9.7 |
|---|---|---|
| Characters / bytes | `LENGTH`, `OCTET_LENGTH` | `CHAR_LENGTH`, `LENGTH` |
| Join text | `CONCAT(a, b)`, `a \|\| b` | `CONCAT(a, b)` |
| Case, trim, cut, replace | `UPPER`, `LOWER`, `TRIM`, `SUBSTRING(s, 1, 3)`, `REPLACE` | same |
| Today, now | `CURRENT_DATE`, `NOW()` | same |
| Year of a date | `EXTRACT(YEAR FROM d)` | same, or `YEAR(d)` |
| Add 7 days | `d + INTERVAL '7 days'` | `d + INTERVAL 7 DAY`, `DATE_ADD` |
| Days between two dates | `d2 - d1` | `DATEDIFF(d2, d1)` |
| First day of the month | `DATE_TRUNC('month', ts)` | `DATE_FORMAT(ts, '%Y-%m-01')` |
| Date part of a timestamp | `ts::date` | `DATE(ts)` |

1. WHERE keeps the rows first, using the bare column, so only the needed rows reach the functions.
2. For each kept row, the database calls the function with that row's value. In `UPPER(TRIM(name))` the inner call runs first: trim, then upper-case.
3. The returned value goes into the result column; the stored row does not change.
4. If an argument is NULL, most functions return NULL. PostgreSQL's `CONCAT` and both databases' `CONCAT_WS` are exceptions: they skip NULLs.

## Example

February payments with a reference, the status in lower case, the month and a follow-up date a week later, in PostgreSQL 18:

```sql
SELECT CONCAT('PAY-', id)                    AS ref,
       LOWER(status)                         AS status,
       DATE_TRUNC('month', created_at)::date AS month,
       created_at::date + 7                  AS follow_up
FROM payments
WHERE created_at >= DATE '2026-02-01'
  AND created_at <  DATE '2026-03-01'
ORDER BY id;
```

```text output
   ref   | status  |   month    | follow_up
---------+---------+------------+------------
 PAY-103 | failed  | 2026-02-01 | 2026-02-10
 PAY-104 | paid    | 2026-02-01 | 2026-02-17
 PAY-105 | pending | 2026-02-01 | 2026-02-22
 PAY-106 | paid    | 2026-02-01 | 2026-03-07
(4 rows)
```

What to notice:

- The WHERE uses a range on the bare `created_at`. Payment 106 at 20:10 on 28 February is included, because the end is "before 1 March".
- `created_at::date + 7` adds whole days to a date. Adding 7 to 28 February gives 7 March: the database handles month lengths.
- In MySQL 9.7 the same result comes from `DATE_FORMAT(created_at, '%Y-%m-01')` and `DATE(created_at) + INTERVAL 7 DAY`; `DATE_TRUNC` and `::date` do not exist there.

## Rules and defaults

- **NOW() is fixed:** PostgreSQL 18 returns the start time of the current transaction, so two calls in one transaction give the same value. MySQL 9.7 returns the start time of the current statement.
- **CONCAT_WS(', ', a, b):** joins with a separator and skips NULL parts, in both databases.
- **SUBSTRING forms:** both accept `SUBSTRING(s, 1, 3)`; PostgreSQL also accepts the standard `SUBSTRING(s FROM 1 FOR 3)`.

## Interview Qs

### LENGTH vs CHAR_LENGTH?

In MySQL, LENGTH counts bytes and CHAR_LENGTH counts characters: 'josé' in MySQL's utf8mb4 character set gives 5 and 4, because é takes two bytes. In PostgreSQL, LENGTH and CHAR_LENGTH both count characters, and OCTET_LENGTH gives bytes. Use character counts for validation rules such as "name at most 50 characters".

### How do you find payments from the last 7 days?

`WHERE created_at >= NOW() - INTERVAL '7 days'` in PostgreSQL, or `INTERVAL 7 DAY` in MySQL. The function is applied to NOW(), a single value, not to the column, so an index on created_at can still be used.

### Why did CONCAT return NULL?

In MySQL, any NULL argument makes CONCAT return NULL. Wrap the nullable column in COALESCE, or use CONCAT_WS, which skips NULLs. PostgreSQL's CONCAT already skips NULLs, but its `||` operator returns NULL when either side is NULL.
