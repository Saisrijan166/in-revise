## Why it exists

Questions rarely want raw columns: emails need cleaning, dates need a month. These functions shape values inside the query.

## How it works

| Need | PostgreSQL 18 | MySQL 9.7 |
|---|---|---|
| Characters / bytes | `LENGTH`, `OCTET_LENGTH` | `CHAR_LENGTH`, `LENGTH` |
| Join text | `a \|\| b`, `CONCAT(a, b)` | `CONCAT(a, b)` |
| Case, cut, clean, find | `UPPER`, `LOWER`, `SUBSTRING(s FROM 1 FOR 3)`, `TRIM`, `REPLACE`, `POSITION('a' IN s)` | same |
| Today, now | `CURRENT_DATE`, `NOW()` | same |
| Year of a date | `EXTRACT(YEAR FROM d)` | same, or `YEAR(d)` |
| Add 7 days | `d + INTERVAL '7 days'` | `d + INTERVAL 7 DAY`, `DATE_ADD` |
| Days between | `d2 - d1` (dates) | `DATEDIFF(d2, d1)` |
| Month bucket | `DATE_TRUNC('month', ts)` | `DATE_FORMAT(ts, '%Y-%m-01')` |
| Date of a timestamp | `ts::date` | `DATE(ts)` |

- `CONCAT_WS(', ', a, b)` skips NULLs in both.
- Filter a year as a range: [a function on the column hides it from an index](card:index-not-used).

## Example

```sql
-- PostgreSQL: users who signed up, per month of 2026
-- emails: ' Asha@x.in' 5 Jan, 'asha@x.in' 20 Jan, 'ravi@x.in' 3 Feb, 'dev@x.in' 30 Dec 2025
SELECT DATE_TRUNC('month', created_at) AS month,
       COUNT(DISTINCT LOWER(TRIM(email))) AS users
FROM users
WHERE created_at >= DATE '2026-01-01'
  AND created_at <  DATE '2027-01-01'
GROUP BY 1
ORDER BY 1;
```

```text output
         month          | users
------------------------+-------
 2026-01-01 00:00:00+00 |     1
 2026-02-01 00:00:00+00 |     1
```

## Interview Qs

### LENGTH vs CHAR_LENGTH?

MySQL LENGTH counts bytes, CHAR_LENGTH characters: 'josé' in utf8mb4 gives 5 and 4. In PostgreSQL both count characters; OCTET_LENGTH gives bytes.

### Orders from the last 7 days?

`WHERE created_at >= NOW() - INTERVAL '7 days'` (MySQL: `INTERVAL 7 DAY`). The column stays bare, so its index still works.

### Why did CONCAT return NULL?

In MySQL any NULL argument makes CONCAT NULL: use COALESCE or CONCAT_WS. PostgreSQL CONCAT ignores NULLs, but `||` returns NULL.
