## What it is

A set operation combines the full results of two `SELECT` queries into one result, by stacking rows rather than adding columns. `UNION` keeps rows found in either query, `INTERSECT` keeps rows found in both, and `EXCEPT` keeps rows of the first query that are not in the second. Both queries must return the same number of columns.

## Why it exists

Some answers come from two lists of the same shape. A statement may need PAID payments and refunds in one list, or a report may need customers who paid but never failed. A [join](card:joins) is the wrong tool here: it matches rows on a condition and puts their columns side by side. Without set operations you would run two queries and merge the lists in application code. A set operation does it in one statement.

## How it works

Take two lists of customer ids from the payments table: A has the ids with a PAID payment (1, 2, 1) and B has the ids with a FAILED payment (1).

| Query | Result | Why |
|---|---|---|
| `A UNION B` | 1, 2 | every id in either list, each once |
| `A UNION ALL B` | 1, 1, 1, 2 | every row of both lists, repeats kept |
| `A INTERSECT B` | 1 | ids in both lists |
| `A EXCEPT B` | 2 | ids in A that are not in B |

1. The database runs each `SELECT` on its own and gets two results.
2. It lines up their columns by position: first with first, second with second.
3. It combines the rows using the operator.
4. Unless you wrote `ALL`, it removes duplicate rows from the combined result.
5. A final `ORDER BY` or `LIMIT` sorts or cuts the combined result, not the last query.

## Example

One statement of money movements: PAID payments and refunds in one list. A row cannot be both, so nothing needs removing.

```sql
SELECT id, 'payment' AS kind, amount FROM payments WHERE status = 'PAID'
UNION ALL
SELECT id, 'refund', amount FROM refunds
ORDER BY kind, id;
```

```text output
 id |  kind   | amount
----+---------+--------
  1 | payment | 500.00
  3 | payment | 700.00
  4 | payment | 700.00
  1 | refund  | 700.00
```

What to notice:

- The column names `id`, `kind` and `amount` come from the first query; the second query's `'refund'` needs no alias.
- `UNION ALL` is right because the `kind` column makes every row different. Plain `UNION` would give the same rows after an unneeded duplicate check.
- `ORDER BY kind, id` sorts the whole combined list. It runs on PostgreSQL 18 and MySQL 9.7 with the same result.

## Rules and defaults

- **Shape:** same number of columns, and each position must have compatible types.
- **Names:** the result takes its column names from the first query.
- **Duplicates:** removed by default for all three operators; `UNION ALL`, `INTERSECT ALL` and `EXCEPT ALL` keep them.
- **Precedence:** `INTERSECT` binds tighter than `UNION` and `EXCEPT`, so `A UNION B INTERSECT C` means `A UNION (B INTERSECT C)`. Use brackets when you mix them.
- **Sort or limit one part:** put that query in brackets with its own `ORDER BY ... LIMIT`; without brackets they apply to the whole result.
- **Versions:** PostgreSQL has all three. MySQL added `INTERSECT` and `EXCEPT` in 8.0.31.

## Not to be confused with

A join adds columns: each output row joins a row of one table with a matching row of another. A set operation adds rows: each output row comes from one query or the other, with the same columns. Rule: more columns, join; more rows of the same shape, set operation.

## Common mistakes

- **"UNION matches columns by name."** It matches by position. Swap the order in one query and names land under the city column, with no error.

## Interview Qs

### What is the difference between UNION and UNION ALL?

UNION stacks the two results and then removes duplicate rows, which means comparing rows across the whole result. UNION ALL returns every row and skips that check, so it is cheaper. Use UNION ALL when the parts cannot overlap or repeats are wanted, and UNION only when duplicates must go.

### What is the difference between UNION and JOIN?

UNION combines rows from queries that return the same columns, so the result gets longer. JOIN combines columns from related tables, matched by a condition, so the result gets wider. For example, payments plus refunds in one list is UNION ALL; each payment with its customer's name is a JOIN.

### How would you find ids in one table but not in another?

Use EXCEPT on the id columns: `SELECT id FROM a EXCEPT SELECT id FROM b`. It also removes duplicates. NOT EXISTS gives the same answer and can return other columns of `a`; you will see it in [Find rows with no match](card:anti-join-pattern).
