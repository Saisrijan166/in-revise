## Why it exists

Some answers come from two queries of the same shape: customers from two regions, ids in one table but not another. Set operations combine them without a join.

## How it works

With A = {1, 2, 2, 3} and B = {2, 3, 4}:

| Operator | Result |
|---|---|
| `A UNION B` | 1, 2, 3, 4 |
| `A UNION ALL B` | 1, 2, 2, 3, 2, 3, 4 |
| `A INTERSECT B` | 2, 3 |
| `A EXCEPT B` | 1 |

- INTERSECT binds tighter than UNION and EXCEPT; use brackets when you mix them.

## Example

```sql
-- users: asha@example.in (Pune), ravi@example.in (Delhi), meena@example.in (Mumbai)
SELECT email FROM users WHERE city = 'Pune'
UNION ALL
SELECT email FROM users WHERE city = 'Delhi'
ORDER BY email;

-- users with a paid order and no refunded one
-- orders: user 1 PAID; user 2 PAID and REFUNDED
SELECT user_id FROM orders WHERE status = 'PAID'
EXCEPT
SELECT user_id FROM orders WHERE status = 'REFUNDED';
```

```text output
      email
-----------------
 asha@example.in
 ravi@example.in

 user_id
---------
       1
```

## Interview Qs

### UNION vs UNION ALL?

UNION removes duplicate rows, which costs extra work over the whole result. UNION ALL returns every row and skips that check. Use UNION ALL unless you need the duplicates removed.

### UNION vs JOIN?

UNION adds rows from queries with the same columns. JOIN adds columns from related tables, matched by a condition.
