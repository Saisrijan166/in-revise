## Why it exists

Most backend jobs use one of the two. Interviewers want the standard SQL answer first, then the product difference that changes behaviour.

## How it works

- Also in the tree: [extensions](card:postgresql-extension) and the [|| operator](card:mysql-double-pipe). Row versions: [MVCC](card:mvcc).

## Example

```sql
-- users has a row with name 'Asha'
SELECT count(*) FROM users WHERE name = 'ASHA';
-- MySQL 9.7 (utf8mb4_0900_ai_ci): 1    PostgreSQL 18: 0
```

## Interview Qs

### What are the main differences between PostgreSQL and MySQL?

Start with the defaults that change behaviour: isolation level, table storage and string case. Then the syntax (ids, upsert) and the features only PostgreSQL has, as in the table above.

### Which would you choose for a new service?

Either works for typical web apps. I would pick PostgreSQL when I need its extra SQL features or extensions, and MySQL when the team and tooling already run it. Then I would check the defaults that differ.
