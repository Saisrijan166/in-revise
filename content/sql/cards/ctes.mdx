## Why it exists

Nested subqueries read inside-out and hard to follow. A tree, such as managers and reports, cannot be walked to any depth with plain joins.

## How it works

<Steps label="WITH RECURSIVE">
  <Step title="Anchor">Run the first SELECT once: the starting rows, such as the CEO.</Step>
  <Step title="Step">Join the table to the rows found last time: their direct reports.</Step>
  <Step title="Repeat">Add the new rows and run the step again on just those.</Step>
  <Step title="Stop">When a step finds no new rows, return everything found.</Step>
</Steps>

## Example

```sql
-- Asha manages Ravi; Ravi manages Meena
WITH RECURSIVE team AS (
  SELECT id, name, 1 AS level
  FROM employees WHERE manager_id IS NULL      -- anchor
  UNION ALL
  SELECT e.id, e.name, t.level + 1
  FROM employees e
  JOIN team t ON e.manager_id = t.id           -- step
)
SELECT * FROM team ORDER BY level;
```

```text output
 id | name  | level
----+-------+-------
  1 | Asha  |     1
  2 | Ravi  |     2
  3 | Meena |     3
```

## Interview Qs

### How do you get every employee under a manager, at any depth?

A recursive CTE: the anchor selects the manager, the step joins employees whose manager_id is in the previous level, until no new rows appear.

### How do you stop a recursive CTE looping forever?

Track the path and skip ids already seen, add a depth limit in the step, or in PostgreSQL 14+ use the CYCLE clause. MySQL raises an error past cte_max_recursion_depth.
