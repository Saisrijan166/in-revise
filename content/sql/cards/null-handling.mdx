## Why it exists

Real data has gaps: no phone number, no end date yet. SQL marks a gap as NULL and will not guess, so a test against it is neither true nor false.

## How it works

| Expression | Result |
|---|---|
| `NULL = NULL` | UNKNOWN |
| `5 <> NULL` | UNKNOWN |
| `TRUE AND UNKNOWN` | UNKNOWN |
| `FALSE AND UNKNOWN` | FALSE |
| `TRUE OR UNKNOWN` | TRUE |
| `NULL IS NULL` | TRUE |

- `NOT IN (1, NULL)` means `<> 1 AND <> NULL`: never TRUE, so no rows.
- Counting and summing NULLs: see [Aggregates](card:aggregates-group-by).

## Example

```sql
-- users: Asha (Pune, no email), Ravi (no city, no email), Meena (has email)
SELECT name, COALESCE(city, 'Unknown') AS city
FROM users
WHERE email IS NULL;

SELECT NULLIF(10, 10) AS equal, NULLIF(10, 5) AS not_equal;
```

```text output
 name |  city
------+---------
 Asha | Pune
 Ravi | Unknown

 equal | not_equal
-------+-----------
  NULL |        10
```

## Interview Qs

### Why does WHERE city = NULL return nothing?

`city = NULL` is UNKNOWN for every row, never TRUE, so WHERE drops all of them. Write `city IS NULL`.

### NOT IN vs NOT EXISTS with NULLs?

If the subquery returns a NULL, NOT IN gives UNKNOWN for rows that do not match, so they vanish. NOT EXISTS only asks whether a matching row exists, so NULLs cannot hide results.
