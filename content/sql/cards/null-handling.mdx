## What it is

NULL is the marker SQL puts in a column when the value is missing or unknown: Meena is a customer, but her city is not known, so `city` is NULL. NULL is not a value like 0 or empty text. Because the database cannot know whether an unknown city equals 'Pune', any comparison with NULL gives a third result, UNKNOWN. So SQL conditions have three possible results, TRUE, FALSE and UNKNOWN; this is called three-valued logic.

## Why it exists

Without NULL you would store a fake value for "not known", such as '' or 0. Then a balance of 0 and an unknown balance look the same, and an average counts the fake 0 as a real number. NULL says "no value" clearly, and SQL refuses to guess about it. The price is that every filter on a nullable column must say what to do with NULL.

## How it works

| Expression | Result |
|---|---|
| `NULL = 'Pune'`, `NULL <> 'Pune'` | UNKNOWN |
| `NULL = NULL` | UNKNOWN |
| `TRUE AND UNKNOWN` | UNKNOWN |
| `FALSE AND UNKNOWN` | FALSE |
| `TRUE OR UNKNOWN` | TRUE |
| `NULL IS NULL` | TRUE |

Follow Meena's row through `WHERE city <> 'Pune'`:

1. The database compares her city with 'Pune': `NULL <> 'Pune'` is UNKNOWN.
2. WHERE keeps only rows where the condition is TRUE, so her row is dropped.
3. `WHERE city = 'Pune'` drops her too, for the same reason: she is in neither result.
4. Only `city IS NULL` is TRUE for her, because IS NULL asks "is it unknown?" instead of comparing values.

So the key is: a NULL row falls out of every ordinary comparison; ask for it with IS NULL.

## Example

Customers outside Pune, including those whose city is unknown. The `customers` table has Asha and Arjun in Pune, Ravi in Delhi and Meena with a NULL city.

```sql
SELECT name, COALESCE(city, 'Unknown') AS city
FROM customers
WHERE city <> 'Pune' OR city IS NULL
ORDER BY id;
```

```text output
 name  |  city
-------+---------
 Ravi  | Delhi
 Meena | Unknown
(2 rows)
```

What to notice:

- `OR city IS NULL` is what brings Meena back. Without it, only Ravi is returned.
- `COALESCE(city, 'Unknown')` changes only what the result shows. The stored city is still NULL.
- The query returns the same two rows in PostgreSQL 18 and MySQL 9.7.

## Rules and defaults

- **Arithmetic:** any arithmetic with NULL gives NULL: `NULL + 5` is NULL.
- **NULLIF(a, b):** returns NULL when `a` equals `b`, otherwise `a`. `total / NULLIF(count, 0)` avoids a division by zero error in PostgreSQL 18. In a SELECT, MySQL 9.7 returns NULL with a warning instead; an INSERT or UPDATE in its default strict mode fails.
- **NULL-safe equality:** `IS NOT DISTINCT FROM` works in PostgreSQL 18 but is a syntax error in MySQL 9.7, which uses `<=>`.
- **Sort order:** PostgreSQL 18 sorts NULLs as larger than any value: last in ASC, first in DESC, unless you write `NULLS FIRST` or `NULLS LAST`. MySQL 9.7 puts NULLs first in ASC and last in DESC, and has no NULLS FIRST syntax; sort by `city IS NULL` first to move them.

## Not to be confused with

- **NULL, '' and 0:** NULL means no value is known, '' is a text value of length zero, and 0 is a number. Rule: `IS NULL` finds only NULL; `= ''` finds only empty text.
- **NOT IN and NOT EXISTS:** NOT IN compares the value with every item of a list, so one NULL in the list makes the result UNKNOWN. NOT EXISTS only asks whether a matching row exists, so NULLs cannot hide results. Rule: for "has no match", use NOT EXISTS. You will meet both in [Subqueries](card:subqueries).

## Interview Qs

### Why does WHERE city = NULL return nothing?

`city = NULL` compares a value with an unknown, so it is UNKNOWN for every row, even for rows whose city is NULL. WHERE keeps only TRUE rows, so all of them are dropped. Write `city IS NULL`, which tests for the marker instead of comparing.

### Is NULL equal to NULL? How do you compare two nullable columns?

No: `NULL = NULL` is UNKNOWN, so a plain `a = b` never matches two NULLs. To treat two NULLs as equal, write `a IS NOT DISTINCT FROM b` in PostgreSQL, or `a <=> b` in MySQL. Both return TRUE or FALSE, never UNKNOWN.

### How do you show 0 instead of NULL in a result?

Use `COALESCE(column, 0)`, which returns the first argument that is not NULL. It changes only the output; the stored value stays NULL.
