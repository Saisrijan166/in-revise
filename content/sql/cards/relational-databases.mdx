## Why it exists

Plain files cannot find, check and safely share data among many users. A DBMS does that for you; the relational model adds tables, keys and SQL.

## How it works

<Mermaid
  alt="One database server holds several databases. In PostgreSQL a database holds schemas, and a schema holds tables. A table has rows, also called tuples, and typed columns, also called attributes."
  chart={`flowchart LR
  S[Server] --> D[(Database)]
  D --> SC[Schema]
  SC --> T[Table = relation]
  T --> R[Rows = tuples]
  T --> C[Columns = attributes]`}
/>

- By default PostgreSQL puts a table in the `public` schema when you name none.
- MySQL has no extra level: `CREATE SCHEMA` is a synonym for `CREATE DATABASE`.
- SQL is an ISO standard; each product speaks its own dialect of it.

## Example

```sql
CREATE TABLE users (
  id    BIGINT PRIMARY KEY,
  name  TEXT NOT NULL,
  email TEXT,
  city  TEXT
);
SELECT name FROM users WHERE city = 'Pune' ORDER BY name;
```

## Interview Qs

### What is the difference between a DBMS and an RDBMS?

A DBMS is any software that manages databases, including document or key-value stores. An RDBMS is a DBMS that stores data in related tables with keys and constraints, queried with SQL.

### What is a schema?

The structure of the data: tables, columns and types. In PostgreSQL it is also a named namespace inside a database, so `sales.orders` and `hr.orders` can coexist. In MySQL, schema and database mean the same thing.
