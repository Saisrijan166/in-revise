## What it is

A database is an organised collection of data that a program called a DBMS (database management system) stores and looks after. In a relational database the data sits in tables. A table holds one kind of thing, such as customers; each row is one customer, and each column is one fact about it, such as `name`, with a fixed type. You talk to the database in SQL, a standard language for asking for and changing data.

## Why it exists

Without a DBMS you would keep customers in a file and write code to search it, check it and update it. Two users saving at once could overwrite each other, nothing would stop a wrong value, and a crash in the middle of a write could leave the file half-changed. A DBMS does this work once for every app: it finds rows fast, rejects bad data, lets many users work at the same time and recovers after a crash.

## How it works

1. You create a table and give each column a name and a type. The formal name for a table is a relation, which is where "relational" comes from.
2. Your app connects to the DBMS server, picks a database such as `shop`, and sends SQL statements.
3. The DBMS checks each new row against the column types and rules, then stores it.
4. For a query, the DBMS works out how to find the matching rows and sends back a result, which is itself a small table.

So the key is: you describe what you want in SQL, and the DBMS decides how to store and find it.

## Example

The running example in this tech is a small payments system. Here is its first table, filled with three customers and queried:

```sql
CREATE TABLE customers (
  id   BIGINT PRIMARY KEY,
  name TEXT NOT NULL,
  city TEXT
);
INSERT INTO customers VALUES (1, 'Asha', 'Pune'), (2, 'Ravi', 'Delhi'), (3, 'Meena', 'Pune');
SELECT name, city FROM customers WHERE city = 'Pune' ORDER BY name;
```

```text output
 name  | city
-------+------
 Asha  | Pune
 Meena | Pune
(2 rows)
```

What to notice:

- `CREATE TABLE` fixes the shape: every row has the same three columns, each with a type. `PRIMARY KEY` gives every row a unique id (you will see it in [keys](card:keys)), and `NOT NULL` makes a name required.
- The query says what to fetch (Pune customers, sorted by name), not how to search. The answer is again a table, with two rows.
- Remove `ORDER BY name` and the two rows may come back in any order; SQL promises an order only when you ask for one.

## Rules and defaults

- **Schema in PostgreSQL 18:** a database contains schemas, and a schema contains tables. A table created without a schema name goes into `public`, so `sales.payments` and `hr.payments` can live side by side.
- **Schema in MySQL 9.7:** there is no extra level. `CREATE SCHEMA` is a synonym for `CREATE DATABASE`.
- **The standard:** SQL is ISO/IEC 9075 (latest revision SQL:2023). Products follow most of it and add their own syntax, so check the product before copying a query.

## Not to be confused with

A relational database stores data in tables with fixed columns and links them by keys. A [NoSQL](card:sql-and-nosql) store, such as MongoDB, keeps data in other shapes, such as one JSON-like document per order. Rule: tables and SQL = relational; documents, key-value pairs or graphs = NoSQL.

## Interview Qs

### What is the difference between a DBMS and an RDBMS?

A DBMS is any software that manages databases, including document and key-value stores such as MongoDB and Redis. An RDBMS is a DBMS that stores data in related tables, enforces keys and constraints, and is queried with SQL. PostgreSQL, MySQL, Oracle and SQL Server are RDBMSs.

### What is a schema?

In general it means the structure of the data: the tables, their columns and types. In PostgreSQL it is also a named folder inside a database, so two schemas can each have a `payments` table. In MySQL, schema and database mean the same thing.

### Why use a database instead of files?

A database lets many users read and write at the same time without overwriting each other, rejects data that breaks its rules, finds rows quickly, and recovers to a consistent state after a crash. With files, the app would have to build all of that itself.
