## Why it exists

SQL questions come as English. Most words map to one clause; most answers follow a few clause chains.

## How it works

| Words | SQL |
|---|---|
| show, unique | `SELECT`, `DISTINCT` |
| only, between, one of, starts with, missing | `WHERE`, `BETWEEN`, `IN`, `LIKE 'A%'`, `IS NULL` |
| how many, total, average, highest | `COUNT`, `SUM`, `AVG`, `MAX` |
| per · groups with more than | `GROUP BY` · `HAVING` |
| top 5 | `ORDER BY … DESC LIMIT 5` |
| has none · more than once | [NOT EXISTS](card:anti-join-pattern) · [GROUP BY + HAVING](card:duplicates) |
| label, custom sort, 0 if missing | `CASE`, `ORDER BY CASE`, `COALESCE(x, 0)` |
| Nth highest, top N in each, running | [a pattern](card:sql-problem-approach) |

| Shape | Clauses |
|---|---|
| Filter, sort, limit | `WHERE`, `ORDER BY … DESC`, `LIMIT n` |
| Group, count, filter groups | `GROUP BY`, `COUNT(*)`, `HAVING` |
| Group, sum, sort, top | `SUM`, `ORDER BY total DESC`, `LIMIT` |
| Join, group, count | parent `LEFT JOIN` child, `COUNT(child.id)`: [zeros kept](card:group-aggregation-patterns) |

## Example

```sql
-- Top 3 departments by staff paid over 50000, if over 5
SELECT d.name, COUNT(*) AS staff        -- by number → COUNT
FROM employees e
JOIN departments d ON d.id = e.dept_id  -- departments → JOIN
WHERE e.salary > 50000                  -- over → WHERE
GROUP BY d.id, d.name                   -- per department → GROUP BY
HAVING COUNT(*) > 5                     -- more than 5 → HAVING
ORDER BY staff DESC, d.id               -- top → DESC + tie-breaker
LIMIT 3;
```

## Interview Qs

### "Top 3 salaries": rows or values?

Ask. Rows: `ORDER BY salary DESC, id LIMIT 3`. Amounts: `SELECT DISTINCT salary … ORDER BY salary DESC LIMIT 3`. With ties they differ.

### Pune customers who spent over 1000 in total: WHERE or HAVING?

Both. City is per row: `WHERE city = 'Pune'`. "In total" is a sum: `GROUP BY customer_id HAVING SUM(amount) > 1000`.
