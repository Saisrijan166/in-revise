## Why it exists

Running totals, change from the previous period and streaks all depend on row order. [Window functions](card:window-functions) read neighbouring rows directly, with no self-join.

## How it works

| day | ROW_NUMBER() | day − rn | Run |
|---|---|---|---|
| 01-01 | 1 | 12-31 | A |
| 01-02 | 2 | 12-31 | A |
| 01-04 | 3 | 01-01 | B |

- Consecutive days rise by one, like rn, so day − rn stays fixed; a gap changes it. Group by it.
- ROWS counts rows. For "the last 7 days" order by a date and use `RANGE BETWEEN INTERVAL '6 days' PRECEDING AND CURRENT ROW` (MySQL: `INTERVAL 6 DAY`).

## Example

```sql
WITH days AS (
  SELECT DISTINCT user_id, created_at::date AS d FROM orders
), marked AS (
  SELECT user_id, d,
         d - ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY d)::int AS grp
  FROM days
)
SELECT user_id, MIN(d) AS first_day, MAX(d) AS last_day, COUNT(*) AS days
FROM marked
GROUP BY user_id, grp;
```

MySQL: `DATE(created_at)` and `DATE_SUB(d, INTERVAL ROW_NUMBER() OVER (…) DAY)`.

## Interview Qs

### Show a running total of spending per user.

`SUM(amount) OVER (PARTITION BY user_id ORDER BY created_at, id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)`. Every order row stays; GROUP BY would collapse them into one total.

### Find users who ordered on 3 or more consecutive days.

Build the runs as above, add `HAVING COUNT(*) >= 3`, and select DISTINCT user_id from them. For "the same value in 3 rows in a row", compare the value with `LAG(x, 1)` and `LAG(x, 2)`.
