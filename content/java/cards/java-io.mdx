## What it is

Java I/O (input and output) is the set of classes for moving data in and out of a program: files, network sockets and the console. Data moves as a stream, a flow of data read or written in order. This is not the [Stream API](card:streams); the name is older. Byte streams move raw bytes, and character streams move text. NIO ("new I/O") is the newer set of packages. Its file part, called NIO.2 (Java 7), has the `Path` and `Files` classes, the simplest way to work with files today.

## Why it exists

A file on disk is only bytes. An image must be copied byte for byte, but text needs a charset, the rule that turns bytes into characters, or Hindi and emoji come out broken. Java keeps the two apart, so you choose bytes or text explicitly. Reading byte by byte straight from the operating system is also slow, because every call costs time; buffering fixes that.

## How it works

| Need | Classic `java.io` | NIO.2 `java.nio.file` |
|---|---|---|
| Name a file | `File` | `Path.of("a.txt")` (Java 11) |
| Read bytes | `FileInputStream` | `Files.readAllBytes` |
| Read text line by line | `BufferedReader` over `FileReader` | `Files.lines`, `Files.newBufferedReader` |
| A whole small text file | a read loop | `Files.readString`, `Files.writeString` (Java 11) |

Reading a text file the classic way stacks wrappers, one per job, which is the [decorator](card:decorator-pattern) pattern:

1. `FileInputStream` opens the file and reads raw bytes.
2. `InputStreamReader` wraps it and turns those bytes into characters with a charset.
3. `BufferedReader` wraps that, fetches a large block at once, and serves later reads from memory.
4. Your code calls `readLine()` until it returns `null`, the end of the file.
5. try-with-resources closes the reader when the block ends, even after an exception.

`Files.newBufferedReader(path)` gives you the same kind of buffered, UTF-8 reader in one call.

## Example

The payment service writes a small CSV file, counts the failed payments, then prints each id.

```java
Path file = Path.of("payments.csv");
Files.writeString(file, "P1,50000,PAID\nP2,12000,FAILED\nP3,8000,PAID\n");   // UTF-8

try (Stream<String> lines = Files.lines(file)) {                 // opens the file
    System.out.println(lines.filter(l -> l.endsWith(",FAILED")).count());
}                                                                 // closes it here

try (BufferedReader in = Files.newBufferedReader(file)) {        // the classic loop
    String line;
    while ((line = in.readLine()) != null) {
        System.out.println(line.split(",")[0]);
    }
}
```

```text output
1
P1
P2
P3
```

What to notice:

- `Files.writeString` and `Files.newBufferedReader` use UTF-8 when you give no charset.
- `Files.lines` reads lazily, so it suits large files, but its stream holds the file open. The `try (...)` closes it.
- `readLine()` returns the line without the `\n`, and `null` at the end, which is why the loop tests `!= null`.

## Rules and defaults

- **Default charset:** UTF-8 for `FileReader`, `InputStreamReader` and the other `java.io` classes since Java 18 (JEP 400). Before that it came from the OS and locale.
- **`Files` methods with no charset:** always UTF-8 (Java SE 25 API).
- **Writing with a buffer:** `BufferedWriter` keeps data in memory until `flush()` or `close()`; forget both and the last part never reaches the file.
- **Large files:** `Files.readAllLines`, `readString` and `readAllBytes` read everything into memory; the API says they are not meant for large files.
- **Non-blocking I/O:** NIO also has channels, buffers and selectors, which let one thread serve many network connections. Interviews rarely go deeper than naming them.

## Interview Qs

### What is the difference between byte streams and character streams?

Byte streams, `InputStream` and `OutputStream`, move raw bytes, which is right for binary files such as images. Character streams, `Reader` and `Writer`, decode bytes into characters with a charset, which is right for text. `InputStreamReader` is the bridge from bytes to characters.

### Why wrap a FileReader in a BufferedReader?

Without a buffer, each read can become a call to the operating system, which is slow. `BufferedReader` reads a large block into memory at once and serves later reads from it. It also adds `readLine()`, which plain `FileReader` does not have.

### What is the difference between java.io and NIO?

`java.io` is stream-based and blocking: a read waits until data arrives. NIO adds buffers, channels and selectors for non-blocking I/O, where one thread watches many connections. NIO.2 (Java 7) adds `Path` and `Files` for simpler file work.
