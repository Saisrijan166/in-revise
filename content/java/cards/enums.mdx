## Why it exists

`int` or `String` constants accept any value. An enum limits a variable to the listed constants, and the compiler checks it.

## How it works

| Feature | Looks like |
|---|---|
| Fields and constructor | `SMALL(200)` passes 200 to the private constructor |
| Constant-specific body | `SMALL { ... }` overrides a method for one constant |
| switch | `case SMALL ->`; a switch expression must cover every constant |
| Singleton | `enum Registry { INSTANCE }`: see [design patterns](card:design-patterns) |

- `valueOf("small")` throws IllegalArgumentException: the name must match exactly.

## Example

```java
enum Cup {
    SMALL(200), LARGE(500);
    private final int ml;
    Cup(int ml) { this.ml = ml; }          // private, even without the keyword
    int ml() { return ml; }
}
String label(Cup c) {
    return switch (c) {                    // no default: every constant covered
        case SMALL -> "Small";
        case LARGE -> "Large";
    };
}
```

## Interview Qs

### Can an enum extend a class or implement an interface?

It cannot extend anything: every enum already extends `java.lang.Enum`. It can implement interfaces, and each constant can override methods in its own body.

### Why compare enums with == and not equals()?

Each constant exists exactly once, so == is correct. It is also null-safe and checked at compile time, while `status.equals(...)` throws if `status` is null.
