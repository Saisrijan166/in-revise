## What it is

An enum (enumeration) is a type whose values are a fixed list of named constants, such as `enum PaymentStatus { PENDING, PAID, FAILED }`. Each constant is a single object, created once when the enum is first used. An enum is a real class: it can have fields, a constructor and methods, and it can implement interfaces.

## Why it exists

Without enums, a payment status is a `String` or an `int`. Then `"PAYED"` or `7` compiles fine and fails only when the code runs, maybe in production. Nothing lists the allowed values, and a method taking `String status` accepts any text. An enum limits the variable to the listed constants, so a typo is a compile error, and the compiler can check that a switch handles every status.

## How it works

  alt="The enum PaymentStatus becomes a class with three constants. Each constant, PENDING, PAID and FAILED, is one object made once by the private constructor, with ordinal 0, 1 and 2."
  chart={`flowchart LR

  E --> F["FAILED: one object, ordinal 2"]`}

1. The compiler turns the enum into a class that extends `java.lang.Enum`. It is final, unless some constant has its own class body.
2. Each constant becomes a `public static final` field. When the enum is first used, each constant's object is created once by calling the private constructor with the values in brackets, such as `PAID(true)`.
3. `values()` returns all constants in declaration order, `valueOf("PAID")` finds one by its exact name, `name()` returns the name and `ordinal()` the position from 0.
4. Because there is exactly one object per constant, `==` compares them correctly.
5. In a switch expression, the compiler checks that every constant has a case, or that there is a `default`.

## Example

`PaymentStatus` from the running example, with a field and a method, used in a switch expression.

```java
enum PaymentStatus {
    PENDING(false), PAID(true), FAILED(true);
    private final boolean terminal;                                // a field
    PaymentStatus(boolean terminal) { this.terminal = terminal; }  // private, always
    boolean isTerminal() { return terminal; }
}
static String label(PaymentStatus s) {
    return switch (s) {                                            // no default needed
        case PENDING -> "Waiting";
        case PAID -> "Done";
        case FAILED -> "Retry";
    };
}
PaymentStatus s = PaymentStatus.valueOf("PAID");                 // found by exact name
System.out.println(label(s) + " " + s.isTerminal() + " " + s.ordinal());
```

```text output
Done true 1
```

What to notice:

- `PAID(true)` passes `true` to the constructor, so every status knows whether it is final. Adding `public` to the constructor is a compile error.
- The switch has no `default`, and it compiles because all three constants are covered. Remove the `FAILED` case and it stops compiling.
- `ordinal()` prints 1 because `PAID` is second. Insert `AUTHORISED` before it and the same constant prints 2.

## Rules and defaults

- **No extends:** an enum cannot extend a class, because it already extends `java.lang.Enum`. It can implement interfaces.
- **No new:** the constructor is private, and a `public` or `protected` constructor is a compile error.
- **valueOf:** the name must match exactly, including case, or it throws `IllegalArgumentException`.
- **ordinal():** the position from 0. The `Enum` API says most code has no use for it; it exists for structures like `EnumSet` and `EnumMap`.
- **Constant-specific bodies:** a constant can override a method in its own body, `PAID { ... }`. The enum is then implicitly [sealed](card:records-sealed) instead of final: only its own constant bodies may extend it.
- **EnumMap and EnumSet:** use them for maps and sets keyed by an enum; `EnumMap` does not allow null keys.
- **Singleton:** an enum with one constant is a simple, safe singleton; see [design patterns](card:design-patterns).

## Interview Qs

### Can an enum extend a class or implement an interface?

It cannot extend anything, because every enum already extends `java.lang.Enum`. It can implement interfaces, and each constant can override methods in its own body.

### Why compare enums with == and not equals()?

Each constant exists exactly once, so `==` is correct. It is also null-safe and checked at compile time: comparing with an unrelated type fails to compile, while `status.equals(...)` throws if `status` is null.

### Can an enum have a constructor? Can you call new on it?

It can have a constructor, which sets the fields of each constant, but the constructor is always private. Only the constants listed in the enum call it, once each; code outside cannot create new values.
