## What it is

Employee stream questions are a fixed family of interview tasks on one data set: a list of employees, each with a name, a department and a salary. In Java this is usually the `Emp` record from [stream patterns](card:stream-coding-patterns). The questions ask for one employee (the top earner), a list (names over a salary), or a number per department (count, total, average). Each answer is one stream pipeline.

## Why it exists

Interviewers reuse this data set because it tests filter, sort, max and grouping in a few minutes, and the answers are easy to check by eye. The follow-ups are where people slip: an `Optional` where a plain value was expected, `reversed()` in the wrong place, or a second highest salary that ignores repeats. Knowing the pipeline for each question shape removes the guesswork.

## How it works

| Question | Pipeline |
|---|---|
| Highest-paid employee | `max(comparingInt(Emp::salary))` |
| Names earning over 50,000 | `filter(e -> e.salary() > 50_000).map(Emp::name).toList()` |
| By salary, highest first, then name | `sorted(comparingInt(Emp::salary).reversed().thenComparing(Emp::name))` |
| Top 3 earners | `sorted(comparingInt(Emp::salary).reversed()).limit(3)` |
| Nth highest salary | `map(Emp::salary).distinct().sorted(reverseOrder()).skip(n - 1).findFirst()` |
| Count, total, average or names per department | `groupingBy(Emp::dept, ...)` with a [downstream collector](card:collectors) |
| Highest paid per department | `toMap(Emp::dept, e -> e, BinaryOperator.maxBy(comparingInt(Emp::salary)))` |
| Over and under 50,000 | `partitioningBy(e -> e.salary() > 50_000)` |
| Department with most people | count per department, then `entrySet().stream().max(Map.Entry.comparingByValue())` |

The table assumes static imports of `Comparator.*` and `Collectors.*`.

1. Decide the shape of the answer: one employee, a list, a single number, or a map from department to something.
2. One employee comes from `max` or `min` with a comparator, and is an `Optional`.
3. A list comes from `filter`, `sorted` and `map`, ending in `toList()`.
4. A map per department comes from `groupingBy(Emp::dept, downstream)`, or `toMap` when each department keeps one employee.
5. A question about the map itself, such as the busiest department, streams over its `entrySet()`.

## Example

Three common questions on one list: the top earner per department, the second highest salary and the busiest department.

```java
record Emp(String name, String dept, int salary) {}
List<Emp> emps = List.of(new Emp("Asha", "IT", 90_000), new Emp("Ravi", "IT", 70_000),
        new Emp("Meena", "IT", 70_000), new Emp("Neha", "HR", 60_000));
Map<String, Emp> topByDept = emps.stream().collect(Collectors.toMap(Emp::dept, e -> e,
        BinaryOperator.maxBy(Comparator.comparingInt(Emp::salary)), TreeMap::new));   // sorted keys
int secondSalary = emps.stream().map(Emp::salary).distinct()
        .sorted(Comparator.reverseOrder()).skip(1).findFirst().orElseThrow();
String busiest = emps.stream().collect(Collectors.groupingBy(Emp::dept, Collectors.counting()))
        .entrySet().stream().max(Map.Entry.comparingByValue())
        .map(Map.Entry::getKey).orElse("none");
System.out.println(topByDept);
System.out.println(secondSalary + " " + busiest);
```

```text output
{HR=Emp[name=Neha, dept=HR, salary=60000], IT=Emp[name=Asha, dept=IT, salary=90000]}
70000 IT
```

What to notice:

- In `toMap`, the third argument decides between two employees of one department: `BinaryOperator.maxBy` keeps the higher paid. Without it, the second IT employee throws `IllegalStateException`.
- `map(Emp::salary)` comes before `distinct()`, so Ravi and Meena's equal salaries count once.
- `busiest` runs a second stream over the count map; `max` returns an `Optional`, which `orElse("none")` unwraps.

## Interview Qs

### Highest salary in each department, without Optional in the map?

`groupingBy(Emp::dept, maxBy(...))` gives `Map<String, Optional<Emp>>`. Use `toMap(Emp::dept, e -> e, BinaryOperator.maxBy(...))`, or wrap it: `collectingAndThen(maxBy(...), Optional::get)`.

### How do you list the employee names in each department?

`groupingBy(Emp::dept, mapping(Emp::name, toList()))` gives a `Map<String, List<String>>`, such as `IT=[Asha, Ravi, Meena]`. Without `mapping`, each value is a `List<Emp>`. Pass `TreeMap::new` as the middle argument if the departments must print in order.

### How do you find the average salary per department?

`groupingBy(Emp::dept, averagingInt(Emp::salary))` gives a `Map<String, Double>`. For the average of the whole list, use `mapToInt(Emp::salary).average()`, which returns an `OptionalDouble` because the list may be empty.
