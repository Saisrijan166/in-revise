## What it is

An access modifier is a keyword in front of a class, field, method or constructor that decides which other code may use it. Java has three keywords, `private`, `protected` and `public`, plus a fourth level you get by writing none, called package-private. A package is a named group of related classes, declared at the top of a file with `package pay;`. It also gives each class a full name, such as `pay.Payment`.

## Why it exists

If any code can set `payment.amount = -500`, every class that holds a payment must be checked when a bug appears. Hiding the field behind `private` means only `Payment`'s own methods can change it, so the checks live in one place and the inside can change later without breaking callers. Packages keep large codebases organised and let two teams each have a class called `Payment` without a clash.

## How it works

| Modifier | Same class | Same package | Subclass, other package | Any other code |
|---|---|---|---|---|
| `private` | yes | no | no | no |
| no modifier | yes | yes | no | no |
| `protected` | yes | yes | yes, through its own type | no |
| `public` | yes | yes | yes | yes |

1. The compiler checks every use of a member against the table, using the package of the class that holds the code and the package of the member.
2. Same package: everything except `private` is allowed.
3. Different package: only `public` members, plus `protected` members when the code is in a subclass and the object is of that subclass's type.
4. Anything else is a compile error, so the mistake never reaches run time.

## Example

`Payment` in package `pay` has one member at each level; `CardPayment` in package `app` is a subclass of it.

```java
package pay;

public class Payment {
    private long amount;           // only code inside Payment
    long batchId;                  // package-private: any class in package pay
    protected String status;       // package pay, plus subclasses elsewhere
    public long getAmount() { return amount; }   // everyone
}
```

```java
package app;

import pay.Payment;

class CardPayment extends Payment {
    void test(Payment other, CardPayment same) {
        status = "PAID";            // ok: this object's own inherited field
        same.status = "PAID";       // ok: reference of my own type
        // other.status = "PAID";   // error: Payment reference from another package
        // batchId = 3;             // error: package-private, different package
        long a = other.getAmount(); // ok: public
    }
}
```

What to notice:

- `amount` is reachable from outside only through `getAmount()`, so `Payment` alone decides how it changes.
- `other.status` fails although `CardPayment` is a subclass: in another package, protected access works only through `CardPayment`'s own type.
- `import pay.Payment` lets the file write `Payment` instead of `pay.Payment`. Without it, the full name still works.

## Rules and defaults

- **Top-level classes:** only `public` or package-private. `private` and `protected` are allowed only on members, such as a class declared inside another class.
- **One public class per file:** javac requires a public top-level class to be in a file named after it, such as `Payment.java`.
- **private scope:** a private member is visible anywhere inside the top-level class that declares it, including classes nested inside it.
- **Automatic imports:** `java.lang` (`String`, `Math`, `System`) and the current package need no import.
- **Wildcards:** `import java.util.*;` imports the types of that package only, not subpackages such as `java.util.concurrent`.
- **Module imports (Java 25, JEP 511):** `import module java.base;` imports every package the module exports at once.

## Interview Qs

### Can a top-level class be private or protected?

No. A top-level class is either public or package-private. Only member classes, declared inside another class, may be private or protected, because those words describe access relative to an enclosing class.

### What is the difference between package-private and protected?

Package-private allows only classes in the same package. Protected allows the same package and also subclasses in other packages, but those subclasses may use the member only through their own type, not through any parent-type reference.

### Does import load classes or slow the program?

No. It only lets one source file use a short type name. Class files always store the full names, so `import java.util.*` costs nothing at run time; classes are loaded only when the program uses them.
