## Why it exists

Hiding details lets a class change its inside without breaking other code. Access modifiers decide who may use each class, field, method and constructor.

## How it works

| Modifier | Same class | Same package | Subclass, other package | Anywhere |
|---|---|---|---|---|
| `private` | yes | no | no | no |
| no modifier | yes | yes | no | no |
| `protected` | yes | yes | yes, via inheritance | no |
| `public` | yes | yes | yes | yes |

- A package is a named group of classes and a namespace: `com.shop.Order` differs from `com.bank.Order`.
- `import java.util.*` does not include subpackages such as `java.util.concurrent`.
- Since Java 25, `import module java.base;` imports every package that module exports (JEP 511).

## Example

```java
package shop;
public class Base { protected int stock; }

package app;
class Store extends shop.Base {
    void test(shop.Base other, Store same) {
        stock = 1;              // ok: this object
        same.stock = 2;         // ok: own type
        // other.stock = 3;     // compile error: Base reference
    }
}
```

## Interview Qs

### Can a top-level class be private or protected?

No. A top-level class is public or package-private. Only member classes, declared inside another class, may be private or protected.

### Does import load classes or slow the program?

No. It only lets this file use a short type name. Class files always store full names, so `import java.util.*` costs nothing at run time.
