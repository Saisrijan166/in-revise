## Why it exists

An object must start in a valid state. A constructor runs exactly once per new object, so every rule about the starting values lives in one place.

## How it works

<Steps label="new Child() when Child extends Parent">
  <Step title="Class init, once">Parent static fields and static blocks, then Child's, in source order.</Step>
  <Step title="Memory">Allocate the object; every field gets its default value (0, false, null).</Step>
  <Step title="Parent part">super(...) runs Parent's initialisers and constructor body first.</Step>
  <Step title="Child initialisers">Child field initialisers and instance blocks, in source order.</Step>
  <Step title="Child body">The rest of the Child constructor runs last.</Step>
</Steps>

- When a class is initialised the first time: [class loading](card:class-loading-jit).
- Since Java 25 (JEP 513), statements before `super(...)` run before step 3; they may set fields but not read `this`.

## Example

```java
class Parent {
    static { System.out.print("1 "); }
    Parent() { System.out.print("3 "); }
}
class Child extends Parent {
    static { System.out.print("2 "); }
    { System.out.print("4 "); }               // instance block
    Child() { System.out.print("5 "); }       // implicit super() first
}
new Child(); new Child();
```

```text output
1 2 3 4 5 3 4 5
```

## Interview Qs

### Can a constructor be private?

Yes. If every constructor is private, code outside the class cannot call new. Singletons, utility classes and static factory methods use this.

### Why can't a constructor be final, static or abstract?

It is never inherited, so final adds nothing. It always builds an object, so static makes no sense. An abstract constructor could never have a body to run.
