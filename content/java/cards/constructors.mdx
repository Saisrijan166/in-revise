## What it is

A constructor is a special block of code that runs once, automatically, each time `new` creates an object. It looks like a method with the class's name and no return type, and its job is to give the new object a valid starting state, for example a positive amount. Around it, Java also runs initialisers: field initialisers such as `long amount = 100;`, instance blocks written as `{ ... }`, and static blocks written as `static { ... }`, which run once for the whole class rather than once per object.

## Why it exists

Without constructors, every caller would write `new Payment()` and then set each field by hand, and one forgotten line leaves a payment with no amount. A constructor puts the setup and its checks in one place that cannot be skipped. Knowing the initialisation order matters too: interviewers ask "what does this print?" because static blocks, instance blocks and parent constructors run in a fixed order that surprises people.

## How it works

  chart={`flowchart LR

  I --> B["constructor body"]`}

1. Java initialises the class the first time code creates an object, calls a static method or uses a static field (other than a constant).
2. For each `new`, it creates the object and sets every field to its default value.
3. It runs the parent constructor first. Every class has a parent; a class that names none extends `Object`, as [inheritance](card:inheritance) will show.
4. It runs field initialisers and instance blocks in the order they appear in the source.
5. It runs the constructor body.

So the key is: static once per class, everything else once per object, parent before child.

## Example

This class prints a line at each stage, then creates two payments.

```java
class Payment {
    static { System.out.println("1. static block: once, when the class is first used"); }
    long amount = 100;                                   // field initialiser
    { System.out.println("2. instance block: amount = " + amount); }

    Payment(long paise) {
        System.out.println("3. constructor body: amount = " + paise);
        amount = paise;
    }
}
new Payment(500);
new Payment(700);
```

```text output
1. static block: once, when the class is first used
2. instance block: amount = 100
3. constructor body: amount = 500
2. instance block: amount = 100
3. constructor body: amount = 700
```

What to notice:

- The static block printed once, although two objects were created. Instance blocks and the body run for every object.
- The instance block saw `amount = 100`: the field initialiser above it had already run, but the constructor body had not.
- `Payment(long paise)` is the only constructor, so `new Payment()` would not compile here.

## Rules and defaults

- **Default constructor:** added only when the class declares no constructor. It takes no arguments, calls `super()`, and has the same access as the class (package access if the class has no modifier).
- **Overloading:** a class may declare several constructors with different parameter lists, and one may call another with `this(...)`; see [this and super](card:this-super).
- **Not allowed:** `static`, `final` or `abstract` on a constructor. Constructors are not members, so they are never inherited or overridden.
- **Code before super(...) (Java 25, JEP 513):** statements may come before `super(...)` or `this(...)`, for example to validate an argument and throw. They may not read fields or call methods of the object, but may assign its fields that have no initialiser.

## Common mistakes

- **"A constructor returns the object."** It has no return type at all; `new` creates the object and returns the reference. A "constructor" written with `void` is an ordinary method that `new` never calls.

## Interview Qs

### Can a constructor be private?

Yes. If every constructor is private, code outside the class cannot call `new`. Utility classes such as `Math` use this to stop instantiation, and singletons and static factory methods use it to control how objects are made.

### Why can't a constructor be final, static or abstract?

It is never inherited, so `final` would prevent nothing. It always works on a new object, so `static` makes no sense. An `abstract` constructor could never have a body to run.

### In what order do static blocks, instance blocks and constructors run?

Static blocks run once, when the class is first used, the parent class's before the child's. For each new object, the parent constructor runs first, then this class's field initialisers and instance blocks in source order, then the constructor body.
