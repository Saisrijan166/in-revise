## What it is

`java.time` is the date and time library added in Java 8. It has a separate class for each kind of time value: a calendar date (`LocalDate`), an exact moment (`Instant`), a date and time in a time zone (`ZonedDateTime`), and amounts of time (`Duration` and `Period`). Like [String](card:strings), every one of these classes is immutable: a method that seems to change a value returns a new object instead.

## Why it exists

Before Java 8 there was `java.util.Date`, whose value any code holding it could change, and `SimpleDateFormat`, which breaks when several threads share one. One `Date` class also had to stand for a birthday, a timestamp and a meeting time alike. `java.time` gives each meaning its own type, so a due date cannot be mixed up with the moment a payment happened, and immutability makes the values safe to share.

## How it works

| You need | Class | Looks like |
|---|---|---|
| A date, such as a due date | `LocalDate` | `2026-10-19` |
| A time, such as opening hours | `LocalTime` | `11:30` |
| Date and time, no zone | `LocalDateTime` | `2026-10-19T11:30` |
| Date, time and zone | `ZonedDateTime` | `2026-10-19T11:30+05:30[Asia/Kolkata]` |
| A machine timestamp | `Instant` | `2026-10-19T06:00:00Z` |
| An amount of time | `Duration`, `Period` | `PT1H30M`, `P1M` |

1. Pick the class by meaning: "which day" is a `LocalDate`, "when exactly" is an `Instant`.
2. Create a value with a factory method such as `LocalDate.parse(...)`, `LocalDate.of(2026, 10, 20)` or `Instant.now()`.
3. Do date maths with methods such as `plusMonths(1)`. Each returns a new object, so assign the result.
4. Measure the gap with `ChronoUnit.DAYS.between(a, b)`, `Period.between(a, b)` or `Duration.between(a, b)`.
5. Turn a value into text, or text into a value, with a `DateTimeFormatter`.

## Example

A payment created on 20-10-2026 is due one month later, and its paid-at moment is shown in Indian time:

```java
DateTimeFormatter fmt = DateTimeFormatter.ofPattern("dd-MM-uuuu");
LocalDate created = LocalDate.parse("20-10-2026", fmt);
LocalDate due = created.plusMonths(1);          // new object; created is unchanged
long days = ChronoUnit.DAYS.between(created, due);
Period gap = Period.between(created, due);
Duration timeout = Duration.ofMinutes(90);
Instant paidAt = Instant.parse("2026-10-20T06:00:00Z");
System.out.println(created + " " + due + " " + days + " " + gap + " " + timeout);
System.out.println(paidAt.atZone(ZoneId.of("Asia/Kolkata")));
```

```text output
2026-10-20 2026-11-20 31 P1M PT1H30M
2026-10-20T11:30+05:30[Asia/Kolkata]
```

What to notice:

- `created` still prints 2026-10-20 after `plusMonths`: the new date went into `due`. Write only `created.plusMonths(1);` and the result is lost.
- The same gap is 31 days or one month (`P1M`), depending on whether you count days or calendar units.
- `paidAt` is one moment in UTC (the `Z`); `atZone` only changes how it is shown, as 11:30 in India.

## Rules and defaults

- **Thread safety:** all the main `java.time` classes, and `DateTimeFormatter`, are immutable and thread-safe, so one formatter constant can serve every thread.
- **Daylight saving:** across a clock change, adding a `Period` of one day keeps the same clock time, while a `Duration` of one day adds exactly 24 hours.
- **Pattern letters:** `uuuu` is the year, `MM` the month and `dd` the day; lower-case `mm` means minutes.
- **Old code:** a `Date` can still be converted with `date.toInstant()` and `Date.from(instant)`.

## Interview Qs

### Why replace Date and SimpleDateFormat?

Any code holding a `Date` can change its value, which causes bugs when it is shared. `SimpleDateFormat` is not synchronised, so threads sharing one corrupt each other's results. `java.time` types are immutable and thread-safe, and they separate dates, moments and zones into different classes.

### LocalDateTime or Instant for the time an event happened?

`Instant`, because it marks one exact moment. A `LocalDateTime` has no zone, so the same value is a different moment in Mumbai and in London. Store the `Instant` and convert it to a `ZonedDateTime` only when you show it to a user.

### Duration vs Period?

`Duration` is an exact amount of seconds and nanoseconds, such as 90 minutes, and suits timeouts. `Period` is years, months and days, such as one month, and suits calendar maths. Across a daylight-saving change, one-day `Period` and 24-hour `Duration` can give different results.
