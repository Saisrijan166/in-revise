## Why it exists

One thread does one thing at a time. Several threads let a program wait for I/O and use many cores at once, sharing the same objects.

## How it works

<Mermaid
  alt="Thread states. start() moves NEW to RUNNABLE. RUNNABLE goes to BLOCKED to enter synchronized code, to WAITING on wait() or join(), to TIMED_WAITING on sleep(ms) or wait(ms); each returns to RUNNABLE. When run() ends the thread is TERMINATED."
  chart={`flowchart LR
  N([NEW]) -- "start()" --> R[RUNNABLE]
  R -- "enter synchronized" --> B[BLOCKED]
  B --> R
  R -- "wait(), join()" --> W[WAITING]
  W --> R
  R -- "sleep(ms), wait(ms)" --> T[TIMED_WAITING]
  T --> R
  R -- "run() ends" --> X([TERMINATED])`}
/>

- RUNNABLE means running or ready to run; Java has no separate RUNNING state.
- A woken `wait()` goes through BLOCKED: it must get the monitor back first.
- In real code, hand tasks to an [executor](card:executors) instead of creating threads yourself.

## Example

```java
Runnable task = () -> System.out.println(Thread.currentThread().getName());
Thread worker = new Thread(task, "worker");

worker.run();     // prints "main": a plain method call
worker.start();   // prints "worker": a new thread
worker.join();    // main waits until worker ends
worker.start();   // IllegalThreadStateException: started once already
```

## Interview Qs

### What is the difference between a process and a thread?

A process is a running program with its own memory space. Its threads share that heap and its open files: cheap to communicate, but shared data needs synchronisation.

### Why are wait() and notify() in Object, not in Thread?

They act on an object's monitor, and every object has one. A thread waits on the object it locked, and another thread notifies through that same object.

### Can you start a thread twice?

No, even after it ends: the second start() throws IllegalThreadStateException. Create a new Thread, or submit the task to a pool again.
