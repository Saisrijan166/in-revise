## What it is

A thread is one sequence of steps that the computer runs, one instruction after another. A running Java program is a process: the operating system gives it its own memory. Inside it, the JVM starts with one thread, called `main`, and you can start more. All threads of a process share the same objects, but each one runs its own sequence of method calls.

## Why it exists

With one thread, a program does one thing at a time. If the payment service waits two seconds for the bank to answer, it can do nothing else in those two seconds. With several threads, one thread waits for the bank while another sends a receipt, and on a machine with several CPU cores, threads can run at the same instant. The price is that threads share objects, which the next concepts make safe.

## How it works

1. You create a `Thread` and give it a task, a `Runnable`. The thread is NEW: it exists but runs nothing.
2. You call `start()`. The thread becomes RUNNABLE, and the operating system schedules it onto a CPU core when one is free.
3. While running, it may pause. It is BLOCKED while it waits for a lock that another thread holds (you will see locks in [synchronization](card:synchronization)), WAITING while it waits for another thread with no time limit, and TIMED_WAITING during `sleep(ms)`.
4. When the pause ends, it goes back to RUNNABLE.
5. When the task's `run()` method returns, the thread is TERMINATED and cannot run again.

So the key is that `start()` creates the new line of work; everything else is the thread moving between running and waiting.

## Example

The payment service sends a receipt on a separate thread. The program shows the difference between `run()` and `start()`.

```java
Runnable sendReceipt = () ->
        System.out.println("receipt sent by " + Thread.currentThread().getName());
Thread worker = new Thread(sendReceipt, "worker");   // state: NEW

worker.run();      // a plain method call: runs on main
worker.start();    // a new thread runs sendReceipt
worker.join();     // main waits until worker is TERMINATED
System.out.println(worker.getState());
```

```text output
receipt sent by main
receipt sent by worker
TERMINATED
```

What to notice:

- `Thread.currentThread().getName()` names the thread that runs the line, so the output proves where each call ran.
- `worker.run()` printed `main`: no new thread was created. Only `start()` gave the task its own thread.
- Without `join()`, `main` could print the state before `worker` had finished, and you might see `RUNNABLE` instead of `TERMINATED`.

## Rules and defaults

- **Start once:** `start()` on a thread that was already started throws `IllegalThreadStateException`, even after it has ended.
- **JVM exit:** the JVM begins to shut down when every started non-daemon thread has ended. Daemon threads do not keep it alive.
- **Daemon setting:** a new thread copies the daemon status of the thread that creates it. Change it with `setDaemon(true)` before `start()`; on a running thread it throws `IllegalThreadStateException`.
- **Interrupt:** `t.interrupt()` asks thread `t` to stop. If `t` is in `sleep()`, `wait()` or `join()`, it receives an `InterruptedException`; otherwise only its interrupt flag is set, and the task must check it.
- **In real code:** hand tasks to a thread pool instead of creating threads by hand; you will see this in [executors](card:executors).

## Not to be confused with

A process is a running program with its own memory; a thread is a line of work inside it that shares that memory. Concurrency means several tasks make progress in overlapping time, even on one core by taking turns. Parallelism means tasks run at the same instant on different cores. Rule: process = own memory, thread = shared memory; concurrency = overlapping, parallelism = simultaneous.

## Interview Qs

### What is the difference between a process and a thread?

A process is a running program with its own memory space. Its threads share that memory and its open files, so they communicate cheaply by sharing objects. That same sharing is the risk: two threads changing one object at the same time need synchronisation.

### Should you implement Runnable or extend Thread?

Implement `Runnable`, usually as a lambda. The task stays separate from the thread that runs it, so the same task can go to a thread pool, and your class is still free to extend another class. Extending `Thread` mixes the job with the worker and uses up Java's single inheritance.

### Can you start a thread twice?

No. A second `start()` throws `IllegalThreadStateException`, even after the thread has terminated. To repeat the work, create a new `Thread` with the same `Runnable`, or submit the task to an executor again.
