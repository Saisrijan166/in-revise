## What it is

`java.lang.Object` is the root of every class: a class with no `extends` extends `Object`, so every object inherits its methods. Two matter most. `equals(Object)` answers "do these two objects mean the same value?", and by default it returns true only for the very same object. `hashCode()` returns an int that hash-based collections, such as `HashSet` and `HashMap`, use to decide where to store an object and where to look for it.

## Why it exists

Load payment 42 twice and you get two objects with the same id and amount. `==` says they differ, because it compares references, as you saw in [strings](card:strings). A set of payments would then hold the payment twice, and looking one up with a fresh copy would fail. Overriding `equals()` lets the class define "same value". Overriding `hashCode()` makes equal objects land in the same place inside a hash collection, so they can be found.

## How it works

<Mermaid
  alt="A HashSet lookup: the set calls hashCode() on the key, uses the int to pick one bucket, then calls equals() only against the entries in that bucket to confirm a match."
  chart={`flowchart LR
  K[key] -- "1. hashCode()" --> H["int, e.g. 1302"]
  H -- "2. picks" --> B[one bucket]

  M -- yes --> F[found]
  M -- no --> N[not found]`}
/>

1. You call `set.contains(key)`. The set calls `key.hashCode()` and uses the int to pick one bucket, a small group of stored entries.
2. It compares the key only with the entries in that bucket, calling `equals()` on each.
3. If one `equals()` returns true, the key is found. Other buckets are never searched, which is why lookups are fast.
4. If `hashCode()` is not overridden, two equal payments usually get different hash codes, so step 1 picks the wrong bucket and step 2 never runs.

So the key is: `hashCode()` narrows the search, and `equals()` confirms it. The bucket details come back in [HashMap](card:map-hashmap).

## Example

`Payment` defines equality by id and amount, and a `HashSet` then treats two copies as one.

```java
final class Payment {
    private final long id;
    private final long amountPaise;
    Payment(long id, long amountPaise) { this.id = id; this.amountPaise = amountPaise; }
    @Override public boolean equals(Object o) {              // Object, not Payment
        return o instanceof Payment p && id == p.id && amountPaise == p.amountPaise;
    }
    @Override public int hashCode() { return Objects.hash(id, amountPaise); }
}
Payment a = new Payment(42, 10_000), b = new Payment(42, 10_000);
System.out.println(a == b);                                 // two objects
System.out.println(a.equals(b));                            // same value
System.out.println(new HashSet<>(List.of(a, b)).size());    // one entry
```

```text output
false
true
1
```

What to notice:

- `o instanceof Payment p` checks the type and gives a typed variable `p` in one step (Java 16; more in [records and pattern matching](card:records-sealed)). It is false for null, so `a.equals(null)` returns false.
- `hashCode()` uses the same fields as `equals()`. It may use fewer, never more: if `equals()` ignored `amountPaise` but `hashCode()` used it, two equal payments could get different hash codes.
- Delete the `hashCode()` override and the set size usually becomes 2.

## Rules and defaults

- **equals() contract:** reflexive (`x.equals(x)`), symmetric, transitive, consistent across calls, and `x.equals(null)` is false.
- **hashCode() contract:** the same object returns the same value while the fields used by `equals()` do not change. Equal objects return equal values. Unequal objects may collide.
- **Defaults in Object:** `equals()` is `==`. `hashCode()` tries to give distinct ints for distinct objects. `toString()` returns the class name, `@`, and the hash code in hex.
- **final in Object:** `getClass()`, `wait()`, `notify()` and `notifyAll()` cannot be overridden.
- **clone():** protected; it throws `CloneNotSupportedException` unless the class implements `Cloneable`, and by default it makes a shallow copy.

## Not to be confused with

`==` is an operator: for primitives it compares values, and for objects it asks whether both references point to one object. `equals()` is a method that compares meaning, as the class defines it. Rule: `==` for primitives, enums and identity; `equals()` or `Objects.equals(a, b)` for content.

## Common mistakes

- **"A mutable field is fine in hashCode()."** If that field changes while the object is a map key or set element, lookups search the wrong bucket. Prefer [immutable](card:immutability) keys, which you will build next.

## Interview Qs

### Why must equals() take Object, not Payment?

`equals(Payment p)` is an overload, not an override. HashSet and HashMap call `equals(Object)`, so they keep using Object's identity check. Putting `@Override` on it turns the mistake into a compile error.

### Why do we need hashCode() if equals() already exists?

Comparing a key with every stored entry through `equals()` would be slow. `hashCode()` sends the lookup to one bucket, and `equals()` then checks only the few entries there. That is why equal objects must share a hash code.

### What happens if you override equals() but not hashCode()?

Equal objects usually get different default hash codes from Object. A HashSet stores both copies, and `map.get(equalKey)` returns null, because the lookup searches a different bucket from the one the entry is in.
