## Why it exists

Collections and generics hold only objects, so `List<int>` is not allowed. A wrapper puts a primitive inside an object and adds helpers such as `Integer.parseInt`.

## How it works

<Compare id="primitive-vs-wrapper" />

- Boxing and unboxing happen in assignments, method calls and arithmetic, so a null can fail far from where it came from.
- `Integer == int` unboxes and compares values; `Integer == Integer` compares references.
- HotSpot can cache more values with `-XX:AutoBoxCacheMax`; only -128 to 127 is guaranteed.

## Example

```java
List<Integer> nums = new ArrayList<>();
nums.add(5);                      // autoboxing
int first = nums.get(0);          // unboxing
Integer a = 127, b = 127;
System.out.println(a == b);       // true: cached object
Integer c = 128, d = 128;
System.out.println(c == d);       // usually false: two objects
System.out.println(c.equals(d));  // true
Integer missing = null;
int n = missing;                  // NullPointerException
```

## Interview Qs

### Why do we need wrapper classes?

Collections and generics accept only objects, a field may need `null` to mean "no value", and wrappers hold helpers such as `Integer.parseInt` and `Integer.MAX_VALUE`.

### Why is 127 == 127 true but 128 == 128 false for Integer?

Boxing reuses cached objects for -128 to 127, so both variables point to one object. 128 is outside the guaranteed cache, so two objects are made and `==` compares references.

### When does autoboxing throw NullPointerException?

When a null wrapper is unboxed: assigning it to an `int`, doing arithmetic with it, or returning a null `Integer` from a method declared to return `int`.
