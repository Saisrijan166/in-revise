## What it is

`CompletableFuture` (Java 8) is a [Future](card:future-interface) you can build on. A plain `Future` from an [executor](card:executors) offers only one way to use the result: block on `get()` until it is ready. A `CompletableFuture` also lets you attach the next steps, such as "then transform it", "then call another service", "if it fails, use this value". Each step runs when the one before it finishes, and each one returns a new `CompletableFuture`, so the steps form a chain.

## Why it exists

Approving a payment takes several calls: load the payment, then ask a fraud service for a score, then decide. With plain `Future`s, a thread calls `get()` after each step and sits idle while it waits. Two independent calls are also easy to run one after the other by mistake. With a chain, no thread waits between steps, independent calls run at the same time, and one `exceptionally` step handles a failure from any step.

## How it works

1. `supplyAsync(task, executor)` starts the first task on a pool thread and returns a `CompletableFuture` at once.
2. Each `thenXxx` call only registers the next step; nothing waits yet.
3. When a step finishes, its result is passed to the next one. A step that returns a plain value uses `thenApply`; a step that starts another async call uses `thenCompose`.
4. If a step throws, the later steps are skipped and the failure travels down the chain until `exceptionally` or `handle` turns it into a value.
5. At the very end, if a thread needs the value, `join()` or `get()` waits for it.

So the key is that you describe the whole flow first, and the steps then run by themselves as results arrive.

## Example

The payment service decides on payment 42 without blocking between steps. `loadPayment` returns a `Payment`, and `fraudScoreAsync` returns a `CompletableFuture<Integer>`.

```java
CompletableFuture<String> decision = CompletableFuture
        .supplyAsync(() -> loadPayment(id), io)              // step 1 runs on the io pool
        .thenCompose(p -> fraudScoreAsync(p, io))            // returns CompletableFuture<Integer>
        .thenApply(score -> score < 50 ? "APPROVED" : "REVIEW")
        .orTimeout(2, TimeUnit.SECONDS)                      // Java 9+: fail if slower than 2 s
        .exceptionally(ex -> "RETRY LATER");                 // any failure above lands here

System.out.println(decision.join());
```

```text output
APPROVED
```

What to notice:

- `io` is the service's own `ExecutorService`. Without it, the tasks run on the common pool that the whole JVM shares.
- `thenCompose` is needed because `fraudScoreAsync` returns a future. With `thenApply`, the next step would receive a `CompletableFuture<Integer>` instead of an `Integer`.
- `orTimeout` fails the chain with a `TimeoutException` if no decision arrives within 2 seconds, and `exceptionally` turns that into `"RETRY LATER"` too.
- `join()` is the only blocking call, at the very end.

## Rules and defaults

- **Default executor:** async methods without an `Executor` use `ForkJoinPool.commonPool()`.
- **Use your own executor for blocking calls:** the common pool is shared by the whole JVM, so slow I/O there delays unrelated work, and the pool may not add threads when its tasks block.
- **Which thread runs a non-async step:** `thenApply` and the other non-async methods may run on the thread that completed the previous step, or on the thread that attached the step. Use the `...Async` variants to choose the executor.
- **Timeouts (Java 9+):** `orTimeout(t, unit)` fails with `TimeoutException`; `completeOnTimeout(value, t, unit)` completes with a fallback value instead.
- **Errors:** `exceptionally` runs only on failure; `handle` always runs and receives the result and the exception; `whenComplete` sees both but keeps the original outcome.

## Common mistakes

- **"allOf gives me all the results."** `allOf` returns `CompletableFuture<Void>`: it only says when all are done. Read each value afterwards with `join()` on the original futures, which no longer blocks.

## Interview Qs

### How is CompletableFuture different from Future?

A `Future` can only be checked, waited on with `get()` or cancelled. A `CompletableFuture` can also be chained, combined with other futures, given a timeout, recovered from errors, and completed by hand with `complete(value)`. It still implements `Future`, so old code that calls `get()` keeps working.

### Which thread runs the steps?

Async methods run on the executor you pass, or on `ForkJoinPool.commonPool()` if you pass none. Non-async steps such as `thenApply` run on whichever thread completed the previous stage, or on the caller if the stage was already done when the step was attached.

### How do you handle an exception in a chain?

Add `exceptionally(ex -> fallback)` to replace a failure with a value, or `handle((result, ex) -> ...)` to deal with success and failure in one place. Without either, `join()` throws a `CompletionException` and `get()` an `ExecutionException`, both with the original exception as the cause.
