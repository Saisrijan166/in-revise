## What it is

A lambda is a short way to write a piece of behaviour and pass it around like a value, for example `p -> p.status() == Status.PAID`. Inputs go on the left, the result on the right. Java accepts a lambda only where it expects a functional interface: an [interface](card:abstract-classes-interfaces) with exactly one abstract method, such as `Predicate<T>`, whose one method `test` returns a boolean. The lambda becomes the body of that method. A method reference, such as `Payment::amountPaise`, is an even shorter lambda that only calls one existing method.

## Why it exists

Before Java 8, passing "keep only paid payments" to another method meant writing an [anonymous class](card:inner-classes): a class header, `@Override`, a full method signature and braces, all for one line of logic. That noise hid what the code did. Java 8 added lambdas, so you write only the logic. They also made the Stream API, which comes next, and the `Comparator` builders short enough to use everywhere.

## How it works

The `java.util.function` package has ready-made functional interfaces for the common shapes, so you rarely write your own:

| Interface | Its one method | Shape | Example |
|---|---|---|---|
| `Predicate<T>` | `test` | T in, boolean out | `p -> p.amountPaise() > 0` |
| `Function<T, R>` | `apply` | T in, R out | `p -> p.id()` |
| `Consumer<T>` | `accept` | T in, nothing out | `p -> System.out.println(p)` |
| `Supplier<T>` | `get` | nothing in, T out | `() -> new ArrayList<>()` |
| `BiFunction<T, U, R>` | `apply` | T and U in, R out | `(a, b) -> a * b` |
| `UnaryOperator<T>`, `BinaryOperator<T>` | `apply` | inputs and output of one type | `s -> s.trim()` |

1. You write a lambda where an interface type is expected, such as a `Predicate<Payment>` variable or a method argument. This expected type is called the target type.
2. The compiler finds that interface's single abstract method (`test`) and checks that the lambda's inputs and result fit it. It works out the parameter types from the target type, so you usually leave them out.
3. If the lambda uses a local variable of the surrounding method, the compiler checks that the variable is effectively final: it is never assigned again after its first value.
4. At run time, evaluating the lambda gives an object that implements the interface. The body does not run yet; it runs each time someone calls `test(p)`.

## Example

Two rules for payments, written as lambdas, then combined. `Status` is the enum `PENDING, PAID, FAILED`, and `Payment` is the record `Payment(long id, long amountPaise, Status status)`.

```java
Predicate<Payment> isPaid = p -> p.status() == Status.PAID;   // the body of test()
Function<Payment, Long> amount = Payment::amountPaise;        // method reference
long minPaise = 50_000;                                       // effectively final
Predicate<Payment> isLarge = p -> p.amountPaise() >= minPaise;

List<Payment> payments = List.of(new Payment(1, 80_000, Status.PAID),
        new Payment(2, 20_000, Status.PAID), new Payment(3, 90_000, Status.FAILED));
for (Payment p : payments)
    if (isPaid.and(isLarge).test(p)) System.out.println(p.id() + " " + amount.apply(p));
// minPaise = 10_000;   // compile error: minPaise is used inside a lambda
```

```text output
1 80000
```

What to notice:

- `isPaid` and `isLarge` are ordinary objects of type `Predicate<Payment>`. Calling `test(p)` runs the lambda body for that payment.
- `and` is a default method of `Predicate`. It has a body, so `Predicate` still has only one abstract method and stays a functional interface.
- `Payment::amountPaise` means exactly `p -> p.amountPaise()`.
- `minPaise` is never assigned again, so the lambda may read it. Remove the `//` on the last line and the compiler rejects the `isLarge` lambda.

## Rules and defaults

- **Lambda forms:** `x -> x * 2` (one input), `(a, b) -> a + b` (several), `() -> 42` (none). A block body needs braces and `return`: `x -> { long y = x * 2; return y; }`.
- **What counts as abstract:** default and static methods do not count, and neither does an abstract method that matches a public `Object` method such as `equals`.
- **@FunctionalInterface:** optional. Any interface with one abstract method, including your own, works with lambdas; the annotation only makes the compiler check the rule.
- **Captured locals:** must be final or effectively final; fields are not restricted. The `i` of a classic `for` loop changes, so it cannot be captured; the variable of an enhanced `for` loop is new on each pass, so it can.
- **Primitive versions:** `IntPredicate`, `ToLongFunction<T>` and similar avoid boxing.
- **Checked exceptions:** a lambda body may throw a checked exception only if the interface's method declares it. `Function.apply` declares none, so `map(path -> Files.readString(path))` does not compile; catch the exception inside the lambda.

## Not to be confused with

An [anonymous class](card:inner-classes) is a full class without a name. It can implement an interface with several abstract methods, extend a class and keep its own fields, and inside it `this` means the anonymous object. A lambda can only implement a functional interface, keeps no state of its own, and inside it `this` means the object of the surrounding method.

Rule: one abstract method and no state of its own: lambda. Anything more: anonymous class.

## Interview Qs

### What is a functional interface? Are Runnable and Comparator functional interfaces?

An interface with exactly one abstract method, so a lambda or method reference can implement it. Both are: `Runnable` has `run`, and `Comparator` has `compare`; its `equals` matches an `Object` method and does not count. Both are older than Java 8, so lambdas worked with existing code at once.

### Why must captured local variables be effectively final?

The JLS explains that capturing a local variable that keeps changing would likely cause concurrency problems. A lambda can run later, even on another thread, after the method has returned. So Java allows only locals that never change after their first value; the lambda then sees one clear value.

### What are the four kinds of method reference?

A static method: `Integer::parseInt`. A method of one particular object: `System.out::println`. A method of any object of a type: `String::length`, where the first argument becomes the object the method is called on. A constructor: `ArrayList::new`, and for arrays `int[]::new`.
