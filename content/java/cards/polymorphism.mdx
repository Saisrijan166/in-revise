## Why it exists

One call should work for many types. Callers write `animal.sound()` once, and each subclass supplies its own behaviour.

## How it works

<Compare id="overloading-vs-overriding" />

- Dynamic dispatch: the JVM runs the method of the object's class, not of the variable's type.
- A static method with the same signature hides the parent's: see [static](card:static-keyword).

## Example

```java
class Animal { String sound() { return "..."; } Animal self() { return this; } }
class Dog extends Animal {
    @Override public String sound() { return "Woof"; }  // wider access: fine
    @Override Dog self() { return this; }               // covariant return
}
static void print(Object o) { System.out.println("Object"); }
static void print(String s) { System.out.println("String"); }

Animal a = new Dog();   // upcast: implicit
a.sound();              // "Woof": picked at run time
Object o = "hi";
print(o);               // "Object": overload picked at compile time
```

## Interview Qs

### Can we overload a method by changing only its return type?

No. Two methods with the same name and parameter types clash at compile time, whatever they return. The compiler picks an overload from the arguments, so the parameter lists must differ.

### What is upcasting, and why use it?

Treating a child as its parent type: `Animal a = new Dog()`. It is implicit and never fails. Code written against `Animal` then works for every subclass, and each object still runs its own override.

### Can an overriding method throw a new exception?

Any unchecked exception, yes. A checked exception only if it is the same as, or a subclass of, one the parent method declares; callers using the parent type would not expect anything else.
