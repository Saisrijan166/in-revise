## What it is

A functional interface program asks you to declare your own interface with one abstract method, then implement it in several ways. The ladder has four steps: a named class, an anonymous class (a class written inline, with no name), a [lambda](card:lambdas) and a method reference. Each step writes less code, but every step creates an object of the same interface. Default and static methods may sit next to the one abstract method.

## Why it exists

"Create a functional interface, implement it, now do it with a lambda" is a common follow-up after the lambda theory. It checks that you know what a lambda replaces: the boilerplate of a class, not the logic. It also exposes two compile errors people hit at the whiteboard: calling a static interface method on an object, and passing your own interface where the Stream API wants a `Predicate`.

## How it works

<Steps label="The same interface, four implementations">
  <Step title="Named class">`class Adder implements Calculator`: the most code.</Step>
  <Step title="Anonymous class">`new Calculator() { ... }`: no class name, still a body.</Step>
  <Step title="Lambda">`(a, b) -> a + b`: only the parameters and the result.</Step>
  <Step title="Method reference">`Integer::sum`: an existing method with the right shape.</Step>
</Steps>

1. Declare the interface with one abstract method, and mark it `@FunctionalInterface` so the compiler checks that.
2. Implement it with a named class that says `implements` and writes the method as `public`.
3. Replace the class with an anonymous class: the same method body, written where you use it.
4. Replace the anonymous class with a lambda: keep only the parameters and the expression.
5. If an existing method already takes the same parameters and returns the same type, use a method reference to it.

The built-in interfaces such as `Predicate` and `Function`, and the rule for captured variables, are in [lambdas](card:lambdas).

## Example

All four implementations of `Calculator` give the same answer.

```java
@FunctionalInterface
interface Calculator { int calculate(int a, int b); }      // one abstract method
class Adder implements Calculator {                         // 1. a named class
    public int calculate(int a, int b) { return a + b; }
}
Calculator c1 = new Adder();
Calculator c2 = new Calculator() {                          // 2. an anonymous class
    public int calculate(int a, int b) { return a + b; }
};
Calculator c3 = (a, b) -> a + b;                            // 3. a lambda
Calculator c4 = Integer::sum;                               // 4. a method reference
for (Calculator c : List.of(c1, c2, c3, c4)) System.out.print(c.calculate(2, 3) + " ");
```

```text output
5 5 5 5
```

What to notice: the loop treats all four as `Calculator` objects. In the lambda, the types of `a` and `b` come from the interface, so you do not write them.

Default and static methods do not count as the one abstract method.

```java
interface Greeter {
    String name();                                         // abstract: the lambda's body
    default String greet() { return "Hello " + name(); }   // default: comes for free
    static Greeter of(String n) { return () -> n; }        // static: call Greeter.of(...)
}
Greeter g = Greeter.of("Asha");
System.out.println(g.greet());
```

```text output
Hello Asha
```

What to notice: the lambda `() -> n` implements only `name()`, and the object still gets `greet()`. Writing `g.of("Ravi")` instead of `Greeter.of(...)` is a compile error ("illegal static interface method call"): a [static interface method](card:abstract-classes-interfaces) can be called only through the interface name.

Your own interface plugs into a stream through a method reference.

```java
@FunctionalInterface
interface Rule { boolean check(int n); }
Rule even = n -> n % 2 == 0;
List<Integer> result = List.of(1, 2, 3, 4).stream()
        .filter(even::check)              // filter wants a Predicate: adapt with ::
        .toList();
System.out.println(result);
```

```text output
[2, 4]
```

What to notice: `filter(even)` does not compile, because a `Rule` is not a `Predicate`. `even::check` creates a new `Predicate` that calls `check`.

## Rules and defaults

- **@FunctionalInterface:** optional; with it, the compiler reports an error unless the interface has exactly one abstract method.
- **What does not count:** default and static methods, private methods (Java 9), and abstract methods that match public methods of `Object`, such as `equals`.

## Interview Qs

### How can you call an interface method without writing a class that implements it?

You cannot skip the implementation, only the named class. An anonymous class, a lambda or a method reference supplies the body inline, and each gives an object of the interface.

### Can a functional interface have default and static methods?

Yes. Only abstract methods count, so it may add any number of default, static and private methods, like `Greeter` above. A lambda supplies the one abstract method and gets the default methods for free.
