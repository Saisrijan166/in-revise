## Why it exists

A loop mixes how to step through data with what to compute. A stream states only the what and lets the library run it, even in parallel.

## How it works

<Mermaid
  alt="The source list.stream() feeds lazy filter, map and sorted steps; nothing runs until the terminal collect or toList pulls elements through to the result."
  chart={`flowchart LR
  S["Source: list.stream()"] --> F["filter (lazy)"] --> M["map (lazy)"] --> O["sorted (lazy)"] --> T["Terminal: collect / toList"] --> R(["Result"])`}
/>

- Intermediate: `filter`, `map`, `flatMap`, `distinct`, `sorted`, `limit`, `skip`, `peek`. Terminal: `collect`, `toList`, `forEach`, `reduce`, `count` (a `long`), `min`, `max`, `findFirst`, `findAny`, `anyMatch`, `allMatch`, `noneMatch`.
- `reduce` folds elements into one new value, such as a sum; `collect` is a mutable reduction that adds each element into a container, such as a `List` or `StringBuilder`.
- Results: [Collectors](card:collectors) build lists, maps and strings; [number streams](card:primitive-streams) give sums and averages; [coding patterns](card:stream-coding-patterns) turn a question into a pipeline.
- `findFirst`, `anyMatch` and `limit` short-circuit, so they can finish even on an infinite stream.

## Example

```java
List<String> names = List.of("Ravi", "Asha", "Amit", "Neha");
String firstA = names.stream()
        .peek(n -> System.out.println("saw " + n))      // debugging aid
        .filter(n -> n.startsWith("A"))
        .map(String::toUpperCase)
        .findFirst()                                    // short-circuits
        .orElse("none");
System.out.println(firstA);                             // Amit and Neha are never read
```

```text output
saw Ravi
saw Asha
ASHA
```

## Interview Qs

### Why use a stream if a for loop already works?

A loop gives step-by-step control. A stream describes a filter-map-collect pipeline that reads more clearly and can run in parallel with one call. It is not automatically faster.

### What is lazy evaluation in streams?

Intermediate operations only build the pipeline. Nothing runs until the terminal operation, which pulls elements through one by one, so `findFirst` or `limit` can stop early.

### What goes wrong with parallelStream().forEach(list::add)?

Several threads change a non-thread-safe `ArrayList` at once, so the result is erratic, even with null entries. Let the stream build the result with `collect` or `toList()`.
