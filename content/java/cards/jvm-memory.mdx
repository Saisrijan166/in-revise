## Why it exists

Some data lives only for one method call, other data must outlive it and be shared. The JVM splits memory so each kind is stored and freed the cheapest way.

## How it works

<Compare id="stack-vs-heap" />

- Shared by all threads: the heap and the method area (class data; HotSpot keeps it in Metaspace).
- Per thread: a stack, a PC register and a native method stack.

## Example

```java
void order() {
    int qty = 2;                 // local: in this frame
    User u = new User("Asha");   // u: reference in the frame; the User: on the heap
    print(u);                    // pushes a new frame; popped on return
}

int depth(int n) {
    return depth(n + 1);         // no base case: StackOverflowError
}
```

## Interview Qs

### What is the difference between StackOverflowError and OutOfMemoryError?

StackOverflowError: one thread needs a deeper stack than allowed, for example recursion with no base case. OutOfMemoryError: the heap (or Metaspace, or native memory) cannot satisfy a request, even after GC.

### Why did Metaspace replace PermGen in Java 8?

PermGen was a part of the heap whose size had to be tuned. HotSpot now keeps class metadata in native memory, limited by what the machine has unless you set `-XX:MaxMetaspaceSize`.

### Where are static variables stored?

In HotSpot since Java 8, static fields are on the heap, not in Metaspace. Metaspace holds only class metadata.
