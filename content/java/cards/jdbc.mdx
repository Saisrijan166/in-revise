## Why it exists

Databases differ. JDBC gives Java one set of interfaces and each vendor's driver implements them, so the same code works with PostgreSQL, MySQL or Oracle.

## How it works

<Steps label="Running a query with JDBC">
  <Step title="Get a Connection">`dataSource.getConnection()`, or `DriverManager.getConnection(url, user, password)`.</Step>
  <Step title="Prepare the SQL">`con.prepareStatement("SELECT name FROM users WHERE id = ?")`, then `ps.setLong(1, id)`.</Step>
  <Step title="Execute">`executeQuery()` returns a ResultSet; `executeUpdate()` returns the changed row count.</Step>
  <Step title="Read rows">`while (rs.next()) rs.getString("name")`: the cursor starts before the first row.</Step>
  <Step title="Close">Open all three in [try-with-resources](card:try-catch-finally), so they close even on errors.</Step>
</Steps>

- Opening a connection is costly, so apps use a connection pool. `close()` returns a pooled connection to the pool.
## Example

```java
String sql = "UPDATE account SET balance = balance + ? WHERE id = ?";
try (Connection con = dataSource.getConnection();
     PreparedStatement ps = con.prepareStatement(sql)) {
    con.setAutoCommit(false);                      // one unit of work
    try {
        ps.setLong(1, -500); ps.setLong(2, 1); ps.executeUpdate();
        ps.setLong(1, 500);  ps.setLong(2, 2); ps.executeUpdate();
        con.commit();                              // both or neither
    } catch (SQLException e) {
        con.rollback(); throw e;
    }
}
```

## Interview Qs

### What are the steps to query a database with JDBC?

Get a Connection, create a PreparedStatement with ? placeholders, set the values, call executeQuery, loop with rs.next() and read columns, then close everything, best with try-with-resources.

### How do you run two updates as one transaction?

Call setAutoCommit(false), run both updates, then commit(). On any SQLException call rollback(), so neither change stays.

### Why use a connection pool?

Opening a database connection is slow. A pool keeps connections open and lends them out; closing a pooled connection returns it to the pool for the next request.
