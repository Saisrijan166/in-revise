## Why it exists

Loading every class at start-up wastes time, and interpreting bytecode forever is slow. So the JVM loads classes when needed and compiles only hot code.

## How it works

<Steps label="From .class file to fast machine code">
  <Step title="Load">A class loader finds the bytes and creates the class.</Step>
  <Step title="Verify">The bytecode is checked for a correct, safe structure.</Step>
  <Step title="Prepare">Static fields are created with default values (0, null).</Step>
  <Step title="Resolve">Symbolic names become real references, possibly later, on first use.</Step>
  <Step title="Initialise">Static initialisers run, superclass first, once.</Step>
  <Step title="Run">The interpreter runs bytecode; the JIT compiles hot methods.</Step>
</Steps>

- A class is identified by its name plus its defining loader, so two loaders can load two different `Config` classes.

## Example

```java
class Config {
    static final int MAX = 10;                   // a constant variable
    static { System.out.println("Config init"); }
    static void load() { }
}
class Main {
    public static void main(String[] args) {
        System.out.println(Config.MAX);  // a constant: Config not initialised
        Config.load();                   // first use: Config initialises now
        Config.load();                   // already initialised
    }
}
```

```text output
10
Config init
```

## Interview Qs

### What is parent delegation, and why is it used?

Each loader asks its parent before loading a class itself. So a class the parent can see is loaded once, by the parent, and core `java.*` classes always come from the JDK, never from application code.

### ClassNotFoundException vs NoClassDefFoundError?

ClassNotFoundException (checked): loading a class by name, as with `Class.forName`, finds nothing. NoClassDefFoundError (an Error): a class present at compile time is missing at run time.

### What does the JIT compiler do?

HotSpot first interprets bytecode and profiles it. Hot methods are compiled to native code, first by C1, then by C2, so the program speeds up after warm-up.
