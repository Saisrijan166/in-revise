## Why it exists

Large programs break when any code can change any data. OOP groups data with the methods that guard it, and lets new types reuse and replace behaviour safely.

## How it works

| Principle | Java tool | Details in |
|---|---|---|
| [Encapsulation](card:encapsulation) | `private` fields + getters and setters | here |
| [Abstraction](card:abstraction) | abstract classes, interfaces | [Abstract classes and interfaces](card:abstract-classes-interfaces) |
| Inheritance | `extends` | [Inheritance](card:inheritance) |
| Polymorphism | overriding, overloading | [Polymorphism](card:polymorphism) |

- Encapsulation lets you add a check or change the field later without breaking callers.
- Keep fields `private` unless there is a reason; public fields are fine only for constants.

## Example

```java
class Account {
    private long balance;                       // hidden state

    long getBalance() { return balance; }       // getter

    void deposit(long amount) {                 // the only way in
        if (amount <= 0) throw new IllegalArgumentException("amount");
        balance += amount;
    }
}
```

## Interview Qs

### Encapsulation vs abstraction?

Encapsulation is about data: keep fields private and allow change only through methods. Abstraction is about design: show a simple contract, such as an interface, and hide how it is done.

### Why use a setter instead of a public field?

A setter can validate the value, keep the object consistent, and let the inside change later without breaking callers. A public field allows any value from anywhere.
