## What it is

Generics let a class or method work with a type that its user chooses. In `class Box<T>`, `T` is a type parameter: a placeholder for a type. When you write `Box<Payment>`, `Payment` is the type argument that fills it. Every collection in Java is generic, so `List<Payment>` means "a list that holds only `Payment` objects".

## Why it exists

Before generics (Java 5), a `List` held plain `Object`. Every read needed a cast such as `(Payment) list.get(0)`, and nothing stopped someone adding a `String` to a list of payments. The mistake showed up only at run time, as a `ClassCastException` far from the line that caused it. With generics the compiler knows what the list holds, so a wrong `add` does not compile and reads need no cast.

## How it works

| You write | It means | Use it to |
|---|---|---|
| `class Box<T>` | a class with a type parameter T | reuse one class for any type |
| `static <T> T first(List<T> l)` | a generic method; `<T>` goes before the return type | reuse one method for any type |
| `<T extends Number>` | T must be Number or a subtype | call Number methods on T |
| `List<? extends Number>` | a list of some unknown subtype of Number | read Numbers out of it |
| `List<? super Integer>` | a list of Integer or a supertype of it | add Integers into it |
| `List<?>` | a list of some unknown type | read elements as Object only |

1. You declare a type parameter, such as `T`, on a class or a method.
2. Each user supplies a type argument, such as `List<Payment>`. With the diamond, `new ArrayList<>()` (Java 7), the compiler works out the argument from the variable's type.
3. The compiler checks every call: `add` accepts only a `Payment`, and `get` returns a `Payment`.
4. Then it erases the type arguments. `T` becomes its bound (or `Object`), and the compiler inserts the casts you no longer write.
5. At run time a `List<Payment>` is just a `List`; the JVM never sees `Payment` in it.

So the key is: generics are a compile-time check, and they cost nothing at run time.

## Example

The examples in this topic use one small record, `record Payment(String id, long amount, Status status)`, with the amount in paise and `Status` an enum of `PENDING`, `PAID` and `FAILED`. Here a generic method returns the caller's own type, and a wildcard lets one method accept lists of different number types.

```java
static <T> T firstOrNull(List<T> items) {           // T is chosen by each caller
    return items.isEmpty() ? null : items.get(0);
}
static double sum(List<? extends Number> nums) {    // List<Integer>, List<Double>, ...
    double total = 0;
    for (Number n : nums) total += n.doubleValue();
    return total;
}

List<Payment> payments = List.of(new Payment("p1", 500, Status.PAID));
Payment first = firstOrNull(payments);               // no cast needed
// payments.add("p2");                               // compile error: a String is not a Payment
System.out.println(first.id() + " " + sum(List.of(1, 2)) + " " + sum(List.of(1.5, 2.5)));
```

```text output
p1 3.0 4.0
```

What to notice:

- `firstOrNull(payments)` returns a `Payment`, because T became `Payment` for this call. With a `List<String>` it would return a `String`.
- `sum` accepts any list of numbers, such as a `List<Integer>` or a `List<Double>` variable. With the parameter `List<Number>`, passing a `List<Integer>` variable would not compile. (A direct `List.of(1, 2)` would still compile, because the compiler would then build a `List<Number>`.)
- Inside `sum`, `nums.add(3)` would not compile: the list might be a `List<Double>`, so the compiler allows no adds into `? extends`.

## Rules and defaults

- **Reference types only:** a type argument must be a class type, so `List<int>` is not allowed. Use `List<Integer>`; [autoboxing](card:wrapper-classes) converts the values.
- **Invariance:** `Box<Integer>` is not a `Box<Number>`. If it were, code could put a `Double` into your box of Integers.
- **`? extends T`:** you can read elements as T, but you cannot add anything except `null`.
- **`? super T`:** you can add T values; elements you read come back as `Object`.
- **Bounds:** `<T extends Number & Comparable<T>>` adds several bounds with `&`; a class bound must come first.
- **Erasure limits:** no `new T()`, no `new T[]`, no `instanceof List<String>`, no static field of type T, and no two overloads that differ only in type arguments.
- **Raw types:** a generic type used with no argument, like plain `List`, still compiles but gives unchecked warnings and no type check. Avoid it.

## Not to be confused with

A bounded type parameter `<T extends Number>` names the type, so you can use T twice, for example to say a method returns the same type it received. A wildcard `? extends Number` names no type; it only widens what a parameter accepts. Rule: use T when two places must share one type; use `?` when you only need to read.

## Interview Qs

### What is type erasure, and what does it stop you doing?

The compiler checks the type arguments, then removes them and inserts casts. With no T at run time, you cannot write `new T()`, test whether an object is a `List<String>`, use a primitive as a type argument, or overload two methods that differ only by type argument.

### What is PECS?

Producer extends, consumer super. If a parameter produces values for you to read, type it `? extends T`. If it consumes values you write into it, type it `? super T`. If it does both, use plain T. `Collections.copy(List<? super T> dest, List<? extends T> src)` follows this rule.

### What is the difference between `List<?>` and `List<Object>`?

`List<?>` accepts a list of any type, such as `List<String>` or `List<Integer>`, but you can add only `null` to it. `List<Object>` accepts only a `List<Object>`, and you can add any object to it. Use `List<?>` for a method that only reads or prints.
