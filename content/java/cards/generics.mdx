## Why it exists

Without generics, collections hold `Object`. Every read needs a cast, and a wrong type fails only at run time with `ClassCastException`.

## How it works

| You write | It means | Use it to |
|---|---|---|
| `class Box<T>`, `<T> T first(List<T> l)` | a type the caller picks | reuse code for any type |
| `<T extends Number>` | T is Number or below | call Number methods on T |
| `List<? extends Number>` | some unknown subtype | read Numbers out (producer) |
| `List<? super Integer>` | Integer or a supertype | add Integers in (consumer) |
| `List<?>` | any type | use only Object methods |

- Erasure replaces T with its bound (or Object) and inserts casts, so generics cost nothing at run time.
- A raw `List` (no type argument) compiles with unchecked warnings. Avoid it.

## Example

```java
static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (T item : src) dest.add(item);   // read from src, write into dest
}

List<Number> nums = new ArrayList<>();
copy(nums, List.of(1, 2, 3));            // Integers into a List<Number>: fine
// List<Number> bad = new ArrayList<Integer>();   // compile error
```

## Interview Qs

### What is type erasure, and what does it stop you doing?

The compiler checks types, then removes the type arguments. With no `T` at run time, you cannot write `new T()`, test `instanceof List<String>`, or overload two methods that differ only by type argument.

### What is PECS?

Producer extends, consumer super. If a parameter gives you values, type it `? extends T`. If it takes your values, type it `? super T`. If it does both, use plain `T`.

### Why can a type argument not be a primitive such as int?

Type arguments must be reference types. Use `List<Integer>`; [autoboxing](card:wrapper-classes) converts the values.
