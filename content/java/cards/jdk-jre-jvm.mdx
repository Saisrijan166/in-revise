## Why it exists

Machine code runs on one kind of CPU and OS only. Java compiles once to bytecode and lets a JVM on each machine run it.

## How it works

<Mermaid
  alt="Hello.java is compiled by javac into Hello.class, which holds bytecode. The same Hello.class file then runs on a JVM for Windows, a JVM for Linux and a JVM for macOS."
  chart={`flowchart LR
  S[Hello.java] -- javac --> B[Hello.class: bytecode]
  B --> W[JVM on Windows]
  B --> L[JVM on Linux]
  B --> M[JVM on macOS]`}
/>

- Nesting: the JDK contains a JRE, and the JRE contains the JVM.
- The JVM runs bytecode and compiles hot code to machine code with the [JIT](card:class-loading-jit).
- Entry point: `public static void main(String[] args)`; since Java 25 a plain `void main()` also works.

## Example

```java
// javac Hello.java  ->  Hello.class  ->  java Hello
public class Hello {
    public static void main(String[] args) {     // classic entry point
        System.out.println("Hello " + args.length);
    }
}

// Java 25+ (JEP 512): a compact source file can be just this
void main() {
    IO.println("Hello");
}
```

## Interview Qs

### Why is main static?

The launcher calls it before any object exists. Since Java 25 an instance `void main()` is also allowed: the launcher first creates an object with the no-argument constructor.

### Is Java compiled or interpreted?

Both. javac compiles source to bytecode ahead of time. At run time the JVM interprets bytecode and JIT-compiles hot methods to machine code.

### Do you still need a JRE to run Java?

Not from Oracle: since JDK 11 it offers only the JDK; `jlink` can build a small custom runtime for one app.
