## What it is

Java is a programming language whose programs run on a JVM (Java Virtual Machine) instead of directly on the computer. You write source code in a `.java` file. A compiler called `javac` turns it into bytecode, a set of instructions stored in a `.class` file, and the JVM reads and runs that bytecode. The JRE (Java Runtime Environment) is the JVM plus Java's standard libraries, and the JDK (Java Development Kit) adds the tools you need to write programs, such as `javac`.

## Why it exists

A C program is compiled into machine code for one kind of CPU and one operating system. To ship it to Windows, Linux and macOS you build it three times, and each build can behave a little differently. Java compiles once, to bytecode that belongs to no real machine. Each machine gets its own JVM, and every JVM runs the same `.class` file. That is the idea behind "write once, run anywhere".

## How it works

1. You write `Hello.java`. Its code sits inside a class, a named block that holds methods; a method is a named group of steps. Classes come properly in [Classes, Objects and Methods](card:classes-objects).
2. `javac Hello.java` checks the code and writes `Hello.class`. A mistake such as a missing semicolon stops here, before anything runs.
3. `java Hello` starts a JVM. It loads `Hello.class` and the library classes it uses, then calls the `main` method, the program's starting point.
4. The JVM first interprets the bytecode, one instruction at a time. Code that runs often is compiled to fast machine code by its JIT compiler, which you will see in [class loading and JIT](card:class-loading-jit).

So the key is two steps: compile once with `javac`, then run anywhere with `java`.

## Example

A first program for the payment service: it prints how many payment ids were passed on the command line.

```java
// Hello.java    compile: javac Hello.java    run: java Hello p1 p2
public class Hello {
    public static void main(String[] args) {
        System.out.println("Payments to check: " + args.length);
    }
}
```

```text output
Payments to check: 2
```

What to notice:

- The file name must match the public class: `Hello.java` holds `public class Hello`.
- `main` is where the JVM starts. `args` holds the words typed after the class name, here `p1` and `p2`, so `args.length` is 2.
- `static` lets the JVM call `main` without first creating anything; `void` means it returns nothing. `System.out.println` prints one line.
- Since Java 11 (JEP 330), `java Hello.java p1` compiles the file in memory and runs it in one step, which is handy for small programs.

## Rules and defaults

- **Classic entry point:** `public static void main(String[] args)`. It is still valid in every version.
- **Java 25 entry point (JEP 512):** `main` may also be non-static, non-public and take no parameters. If it is not static, the launcher first creates an object with the class's non-private no-argument constructor.
- **Compact source file (Java 25):** a file may hold just `void main() { IO.println("Hi"); }`. The compiler wraps it in a class you cannot name, and `IO` (in `java.lang`) prints lines.
- **Getting Java:** Oracle has offered only the JDK since JDK 11. Some other vendors, such as Eclipse Temurin, still ship JRE packages, and `jlink` builds a small custom runtime for one app.

## Not to be confused with

The JDK is what you install to develop: tools plus a runtime. The JRE is the part that runs programs: the JVM plus the libraries. The JVM is the engine inside that loads and runs bytecode. Rule: JDK contains JRE, JRE contains JVM; you compile with the JDK and run on a JVM. The JIT and the garbage collector are parts of the JVM, compared below.

## Interview Qs

### Why is main static?

The launcher calls `main` before any object of the class exists, and a static method can be called without one. Since Java 25 an instance `void main()` is also allowed: the launcher creates an object with the non-private no-argument constructor first, then calls `main` on it.

### Is Java compiled or interpreted?

Both. `javac` compiles source to bytecode ahead of time. At run time the JVM interprets the bytecode and its JIT compiler turns frequently run methods into machine code, so long-running programs get fast after a warm-up.

### Do you still need a JRE to run Java?

You need a runtime, but not necessarily a separate JRE. Oracle has offered only the JDK since JDK 11, which includes one. For deployment, `jlink` can build a small runtime holding only the modules your app uses, and some vendors still publish JRE builds.

### What makes Java platform independent?

The bytecode. It is the same on every machine, while each operating system and CPU has its own JVM that turns that bytecode into native instructions. The JVM itself is platform specific.
