## What it is

A `String` is an object that holds a piece of text, such as a payment status `"PAID"`. It is immutable: once created, its text can never change, so a method like `toUpperCase()` returns a new `String`. Java keeps a string pool, an area where each distinct string literal (text written in quotes in your code) is stored once and shared. `StringBuilder` is a separate class whose text you can change, made for building text step by step.

## Why it exists

Strings are everywhere: map keys, URLs, file names, payment ids. If a shared string could change, every piece of code holding it would suddenly see different text, and a key could move inside a map. Because a `String` never changes, Java can share one object safely, between variables and between threads. The cost is that editing makes copies, which is why `StringBuilder` exists.

## How it works

1. Java keeps one pooled object for each distinct literal such as `"PAID"`. Every variable assigned that literal gets a reference to the same pooled object.
2. `new String("PAID")` always creates a new object outside the pool, even though the text is equal.
3. `==` compares references, so it is true only for the same object. `equals` compares the characters.
4. A method that "changes" a string, such as `concat` or `replace`, builds a new `String` and returns it. The old one is untouched.
5. `StringBuilder` keeps one growing buffer: `append` adds to it in place, and `toString()` makes the final `String` once.

## Example

The same status text, made in different ways, then a builder:

```java
String a = "PAID";
String b = "PAID";
String c = new String("PAID");
System.out.println(a == b);           // true: one pooled object
System.out.println(a == c);           // false: c is a separate object
System.out.println(a.equals(c));      // true: same text
System.out.println(a == c.intern());  // true: intern() returns the pooled one
String s = "paid";
s.toUpperCase();                      // result thrown away
System.out.println(s);                // still paid
System.out.println(1 + 2 + "J" + 1 + 2);   // + runs left to right
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 3; i++) sb.append(i);
System.out.println(sb.reverse());
```

```text output
true
false
true
true
paid
3J12
210
```

What to notice:

- `a == b` is true only because both are literals. Read `b` from a file or a request and `==` would be false, while `equals` stays true.
- `s.toUpperCase()` on its own line does nothing useful: the new `String` is dropped. Assign it back to keep it.
- `1 + 2` is added as numbers to give 3 before the first `String` appears; after that, every `+` joins text.
- `sb.reverse()` changed the builder itself; there is still only one `StringBuilder` object.

## Rules and defaults

- **Compile-time constants:** `"Ja" + "va"` is joined by the compiler and pooled. Text joined at run time, such as `s1 + s2`, is a new object.
- **intern():** returns the pooled copy, so `s.intern() == t.intern()` is true exactly when `s.equals(t)`.
- **Hash code cache:** OpenJDK's `String` computes its hash code once and stores it, which makes strings fast map keys.
- **substring(begin, end):** the end index is not included: `"hello".substring(1, 4)` is `"ell"`.
- **Length, three ways:** `s.length()` for a `String`, `arr.length` (a field, no brackets) for an array, `list.size()` for a list.

## Not to be confused with

`==` checks whether two variables point to the very same object, and `equals` checks whether two strings hold the same characters. Separately, `String` is fixed text, `StringBuilder` is a changeable buffer for one thread, and `StringBuffer` is a changeable buffer whose methods are synchronised, that is, locked so that only one thread uses it at a time. Rule: compare with `equals`; build with `StringBuilder`.

## Interview Qs

### Why is String immutable?

So one object can be shared safely. Literals can be pooled without one user changing another's text, the hash code can be cached for map keys, threads can share strings without locks, and a file name or URL cannot change after it was checked.

### How many objects does new String("Java") create?

At least one: a new `String` object every time it runs. The literal `"Java"` also needs a pooled object, but it is created only if no equal literal was pooled before. That is why `new String(...)` is almost never needed.

### Why use StringBuilder instead of += in a loop?

Each `+=` creates a new `String` and copies all the text so far, so building n pieces costs O(n²) copying. `StringBuilder` appends into one buffer that grows as needed, and you call `toString()` once at the end.
