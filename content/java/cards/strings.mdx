## Why it exists

Strings are map keys, URLs and file names. If a shared string could change, every holder would see it. Immutability makes sharing and pooling safe.

## How it works

<Mermaid
  alt="Two literals, a and b, with the text Java both point to one object in the string pool, so a == b is true. c = new String of Java creates a separate object, so a == c is false. c.intern() returns the pooled object."
  chart={`flowchart LR
  A[a = literal Java] --> P((Java in the pool))
  B[b = literal Java] --> P
  C["c = new String(...)"] --> N((separate Java object))
  N -. "c.intern()" .-> P`}
/>

- Constant expressions such as `"Ja" + "va"` are joined at compile time and pooled; run-time joins are not.

## Example

```java
String a = "Java";
String b = "Java";
String c = new String("Java");
System.out.println(a == b);           // true: one pooled object
System.out.println(a == c);           // false: c is a new object
System.out.println(a.equals(c));      // true: same text
System.out.println(a == c.intern());  // true
System.out.println(1 + 2 + "J");      // 3J: + runs left to right
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 3; i++) sb.append(i);
System.out.println(sb.reverse());     // 210
```

## Interview Qs

### Why is String immutable?

So one object can be shared safely: literals are pooled, the hash code can be cached for HashMap keys, threads need no locks, and no code can change a string after it was checked.

### How many objects does new String("Java") create?

One new String every time, plus the pooled literal `"Java"` if no equal literal was pooled before. That is why `new String(...)` is almost never needed.
