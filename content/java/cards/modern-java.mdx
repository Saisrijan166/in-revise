## What it is

Modern Java means the features added to the language and libraries since Java 8, and the release model that delivers them. Since Java 10 a new feature release ships every six months. Some releases are long-term support (LTS) releases: vendors such as Oracle keep fixing them for years, so most companies run one of them. The LTS releases are 8, 11, 17, 21 and 25.

## Why it exists

Code that uses a feature compiles only on a release that has it: a record does not compile on Java 11. So you need to know which version each feature needs, and interviewers ask exactly that, often as "what did Java 17 or 21 add?". The six-month model exists so that a finished feature ships within months, instead of waiting years for one large release.

## How it works

| LTS | Headline features (the release where they became final, if earlier) |
|---|---|
| 8 | [lambdas](card:lambdas), [Stream API](card:streams), [Optional](card:optional), [default methods](card:abstract-classes-interfaces), [java.time](card:date-time) |
| 11 | modules (9), [`List.of`](card:collections-framework) (9), [`var`](card:data-types) (10), HttpClient, run one `.java` file directly |
| 17 | [switch expressions](card:operators-control-flow) (14), text blocks (15), [records, instanceof patterns](card:records-sealed) (16), sealed classes |
| 21 | [virtual threads](card:virtual-threads), pattern matching for switch, record patterns, sequenced collections |
| 25 | [compact source files and instance main](card:jdk-jre-jvm), [flexible constructor bodies](card:constructors), module import declarations |

A language feature usually travels through releases like this:

1. It is proposed as a JEP, a JDK Enhancement Proposal, and built in the OpenJDK project.
2. It often ships first as a preview: fully specified and built, but not permanent. It works only when you pass `--enable-preview`.
3. After feedback over one or more releases, it becomes final and permanent. Records, for example, were a preview in Java 14 and 15 and became final in 16.
4. Every six months, in March and September, a feature release ships with whatever is finished.
5. Every two years, one of those releases is an LTS release.

So the key is: learn the release in which a feature became final, and the LTS that first contains it.

## Example

One small Java 25 program uses features from many releases. Each comment names the release where that feature became final:

```java
sealed interface Result permits Paid, Failed {}            // sealed classes: Java 17
record Paid(long paise) implements Result {}               // records: Java 16
record Failed(String reason) implements Result {}

String describe(Result r) {
    return switch (r) {                                    // switch expression: Java 14
        case Paid p   -> "paid " + p.paise();              // pattern in switch: Java 21
        case Failed f -> "failed: " + f.reason();
    };
}

void main() {                                              // instance main method: Java 25
    var results = List.of(new Paid(500), new Failed("timeout"));   // var 10, List.of 9
    results.forEach(r -> IO.println(describe(r)));         // lambda 8, IO class 25
}
```

```text output
paid 500
failed: timeout
```

What to notice:

- There is no class around `main` and no import for `List`. This is a compact source file (Java 25): the class is implicit, and the file imports the whole `java.base` module automatically. Run it with `java Payments.java`.
- The switch has no `default`. Because `Result` is sealed, the compiler knows `Paid` and `Failed` are the only cases; permit a third record without adding a case and the code stops compiling.
- On Java 21 the same file does not compile: javac reports that this kind of file is a preview feature there, disabled by default. That is why the release where a feature became final matters.

## Rules and defaults

- **Cadence:** a feature release every March and September since Java 10, numbered 10, 11, 12 and so on.
- **LTS:** Oracle's LTS releases are 8, 11, 17, 21 and 25, now two years apart; the next planned one is 29, in September 2027.
- **Non-LTS:** a full general-availability release, not a beta. Oracle treats it as superseded when the next release ships, six months later, and stops updating it.
- **Preview features:** compile with `javac --release N --enable-preview` and run with `java --enable-preview`, on that exact release N. A preview can change or be removed in the next release.
- **Newest release:** JDK 27, generally available since 15-09-2026; it is not an LTS.

## Interview Qs

### What is an LTS release, and which ones are LTS?

A release that keeps getting security and bug-fix updates for years, while a non-LTS release is replaced by the next one six months later. Oracle's LTS releases are 8, 11, 17, 21 and 25; the next planned one is 29, in September 2027.

### What is a preview feature?

A feature that is fully specified and built, but not yet permanent, shipped to get feedback from real users. It may change or be removed in a later release. You must turn it on with `javac --release N --enable-preview` and `java --enable-preview`, using that exact release N.

### What were the big changes in Java 8?

Lambdas and functional interfaces, which let you pass behaviour as a value; the Stream API for processing collections; `Optional`; default and static methods in interfaces; and the `java.time` date and time API. In HotSpot, Metaspace also replaced PermGen in Java 8.
