## What it is

Stream coding patterns are a translation table from the words of a question to [stream](card:streams) operations. "Which" or "only" means `filter`, "convert" or "get the names" means `map`, "unique" means `distinct`, "how many of each" means `groupingBy` with `counting`. You read the question, write one operation per phrase, and chain them in the order source, filter, sort, map, collect.

## Why it exists

A coding round leaves no time to recall whole programs, and there are too many variations to memorise. A few question words map to a few operations, so any new question becomes a short pipeline you build in a minute. Without the table, people reach for loops and temporary lists, or forget a step such as `distinct()` and return a wrong answer.

## How it works

| The question says | Write |
|---|---|
| which, only, where | `filter(...)` |
| convert, get the names | `map(...)`; nested lists: `flatMap(List::stream)` |
| unique | `distinct()` |
| sorted, highest first | `sorted(...)` with `Comparator.reverseOrder()` or `.reversed()` |
| top N, skip the first N | `sorted(...).limit(n)`, `skip(n)` |
| how many; highest, lowest | `count()`; `max(...)`, `min(...)` |
| total, average | `mapToInt(...).sum()`, `.average()` |
| is there any, do all, none | `anyMatch`, `allMatch`, `noneMatch` |
| how many of each, group by | `groupingBy(..., counting())` |
| split into two | `partitioningBy(...)` |
| combine into one value | `reduce(...)` |
| print each | `forEach(...)`: no result |

1. Name the source: `list.stream()`, `Arrays.stream(words)` for words, or `s.chars()` for characters.
2. Write one `filter` per condition in the question.
3. Sort while the elements still have the field you sort by.
4. Map to what the answer must contain, such as names or salaries.
5. End with the terminal step the answer's shape needs: a list, a count, one value or a map.

Each collector is explained in [Collectors](card:collectors), number streams in [IntStream](card:primitive-streams), and comparators in [Comparable and Comparator](card:comparable-comparator).

## Example

Each phrase of the question becomes one line. `Emp` is a record with a name, a department and a salary, used in the next concept too.

```java
record Emp(String name, String dept, int salary) {}
List<Emp> emps = List.of(new Emp("Asha", "IT", 90_000), new Emp("Ravi", "IT", 70_000),
        new Emp("Meena", "IT", 50_000), new Emp("Neha", "HR", 80_000));
// "Names of IT employees earning over 60,000, highest paid first"
List<String> names = emps.stream()
        .filter(e -> e.dept().equals("IT"))                        // IT            -> filter
        .filter(e -> e.salary() > 60_000)                          // over 60,000   -> filter
        .sorted(Comparator.comparingInt(Emp::salary).reversed())   // highest first -> sorted
        .map(Emp::name)                                            // names         -> map
        .toList();                                                 // list          -> collect
System.out.println(names);
```

```text output
[Asha, Ravi]
```

What to notice: Neha earns more than Ravi but is in HR, so the first filter drops her. `sorted` comes before `map`; swapped, the salary would be gone.

The same table solves the classic number questions on one list.

```java
List<Integer> nums = List.of(5, 9, 2, 9, 5, 7);
Map<Integer, Long> freq = nums.stream()                      // frequency, TreeMap: sorted keys
        .collect(Collectors.groupingBy(Function.identity(), TreeMap::new, Collectors.counting()));
List<Integer> dups = freq.entrySet().stream()                                // duplicates
        .filter(e -> e.getValue() > 1).map(Map.Entry::getKey).toList();
int second = nums.stream().distinct().sorted(Comparator.reverseOrder())      // 2nd highest
        .skip(1).findFirst().orElseThrow();
List<Integer> top3 = nums.stream().sorted(Comparator.reverseOrder()).limit(3).toList();
System.out.println(freq);
System.out.println(dups + " " + second + " " + top3);
```

```text output
{2=1, 5=2, 7=1, 9=2}
[5, 9] 7 [9, 9, 7]
```

What to notice:

- `Function.identity()` groups each number by itself, and `TreeMap::new` makes the keys print in order.
- `distinct()` turns the second highest into 7; without it, the answer would be 9 again.
- `top3` keeps repeats on purpose: the top three values are 9, 9 and 7. Add `distinct()` for the top three different values.

## Rules and defaults

- **distinct:** uses `equals`, and keeps the first of each repeat in an ordered stream.
- **Empty results:** `skip` past the end leaves an empty stream, so `findFirst`, `max` and `min` return an empty [Optional](card:optional). `orElseThrow()` (Java 10) then throws `NoSuchElementException`.

## Interview Qs

### How do you find duplicate elements with streams?

Count each value with `groupingBy(Function.identity(), counting())`, keep entries with a count above 1, and map to the key. `filter(x -> !seen.add(x))` with an outside Set also works, but it is a stateful lambda, which the Stream docs discourage.

### How do you find the first non-repeated character?

Count the characters into a `LinkedHashMap`, which keeps first-seen order: `groupingBy(Function.identity(), LinkedHashMap::new, counting())`. Then take the first entry with count 1. For "swiss" it is w.
