## Why it exists

Some data and behaviour belong to the class as a whole, like a count of all orders or Math.max. Creating an object just to reach them is waste.

## How it works

<Compare id="static-vs-instance" />

- Static nested classes: [nested classes](card:inner-classes). When static blocks run: [initialisation order](card:constructors).

## Example

```java
class Order {
    static int count;                   // one for all orders
    final int id;
    Order() { id = ++count; }           // instance code may use static
    static int total() { return count; }// no id here: no object
}
class A { static String hi() { return "A"; } }
class B extends A { static String hi() { return "B"; } }
A ref = new B();
ref.hi();                               // "A": hidden, not overridden
```

## Interview Qs

### Why is main static?

So the launcher can call it without creating an object first. Since Java 25 (JEP 512) main may also be an instance method; the launcher then creates the object with a no-argument constructor.

### Why do we need static if we already have objects?

For state or behaviour that is not tied to one object: shared counters, constants, utility methods and factory methods. They are called on the class, with no object needed.
