## What it is

`static` is a keyword that makes a field, method, block or nested class belong to the class itself instead of to each object. Members without `static` are instance members: every object has its own copy of an instance field, and an instance method runs on one object. A static field has exactly one copy, however many objects exist, and a static method is called through the class name, such as `Math.max(3, 7)`, with no object needed.

## Why it exists

Some data belongs to all payments together, such as the next id to hand out. Stored in each object, every payment would hold its own counter and they would drift apart. Some behaviour needs no object at all, like `Math.max`; creating an object only to call it is waste. `static` gives such data and helpers a single home on the class.

## How it works

1. The first time the class is used, Java sets up its static fields and runs its static blocks, once.
2. Each `new Payment()` creates an object with its own instance fields, such as `id`.
3. The constructor reads the shared static field `nextId`, copies it into the object's `id`, and increases it, so the next object gets the next number.
4. Code calls a static method through the class name, `Payment.created()`. It runs without any object, so it has no `this`.

So the key is: instance members are per object, static members are per class.

## Example

Every new payment takes the next id from one shared counter.

```java
class Payment {
    static long nextId = 1;                // one copy, shared by all payments
    long id;                               // each payment has its own
    Payment() { id = nextId++; }           // instance code may use static members
    static long created() {                // no object needed to call it
        return nextId - 1;                 // using id here would not compile
    }
}
Payment p1 = new Payment();
Payment p2 = new Payment();
System.out.println(p1.id + " " + p2.id + " " + Payment.created());
```

```text output
1 2 2
```

What to notice:

- `p1` and `p2` have different ids, but both read and updated the same `nextId`.
- `created()` is called on the class. It cannot read `id`, because it has no object to read it from.
- If `nextId` were an instance field, every payment would get its own counter starting at 1, so both ids would be 1, and `created()` would no longer compile.

## Rules and defaults

- **Static to instance:** a static method may use instance members only through an object reference, such as `p1.id`. Instance code may use static members directly.
- **When static code runs:** once, when the class is initialised; [constructors](card:constructors) lists what triggers it.
- **Overloading:** static methods can be overloaded like any method. They cannot be overridden, only hidden.
- **Static nested classes:** a class declared `static` inside another class; you will see these in [nested classes](card:inner-classes).

## Not to be confused with

A static member belongs to the class: one copy, used through the class name. An instance member belongs to each object: its own copy, used through a reference. Rule: if the value or behaviour depends on one particular object, it is an instance member; otherwise it may be static.

## Interview Qs

### Can you override a static method?

No. A child's static method with the same signature hides the parent's, and the declared type of the variable picks which one runs. Putting `@Override` on it is a compile error ("static methods cannot be annotated with @Override"). Static methods can still be overloaded.

### Why do we need static if we already have objects?

For state or behaviour that is not tied to one object: shared counters, constants, utility methods such as `Math.max`, and factory methods. They live on the class, so there is one copy and no object is needed to use them.

### Can a static method use this or call an instance method?

Not directly. A static method runs without a current object, so `this` and `super` do not compile there. It can call an instance method only through an object reference, for example `new Payment().markPaid()`.
