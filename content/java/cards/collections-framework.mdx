## Why it exists

Arrays have a fixed length and no algorithms. The framework gives shared interfaces, ready classes and algorithms, so you can swap implementations without rewriting code.

## Example

| Class | Lookup | Add | Remove |
|---|---|---|---|
| ArrayList | `get(i)` O(1), `contains` O(n) | at end: amortised O(1) | middle: O(n) |
| LinkedList | `get(i)` O(n) | at ends: O(1) | at ends: O(1) |
| HashMap, HashSet | O(1) average | O(1) average | O(1) average |
| TreeMap, TreeSet | O(log n) | O(log n) | O(log n) |
| PriorityQueue | `peek` O(1) | O(log n) | `poll` O(log n) |

```java
List<Integer> nums = new ArrayList<>(List.of(1, 2, 3, 4));
// for (Integer n : nums) if (n % 2 == 0) nums.remove(n);  // ConcurrentModificationException
nums.removeIf(n -> n % 2 == 0);    // safe, Java 8+: [1, 3]

Iterator<Integer> it = nums.iterator();
while (it.hasNext()) if (it.next() == 1) it.remove();   // also safe: [3]
```

## Interview Qs

### Collection vs Collections?

`Collection` is the root interface of List, Set and Queue. `Collections` is a utility class of static methods such as `sort`, `binarySearch` and `unmodifiableList`.

### Why does Map not extend Collection?

A map holds key-to-value mappings, not single elements, so `add(E)` does not fit. It offers three collection views instead: `keySet()`, `values()` and `entrySet()`.

### Fail-fast vs fail-safe iterators?

Fail-fast iterators (ArrayList, HashMap) throw ConcurrentModificationException, best effort, after an outside change. [Concurrent collections](card:concurrent-collections) have weakly consistent iterators (the JDK term, not "fail-safe") that never throw it.
