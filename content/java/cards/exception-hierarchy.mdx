## Why it exists

Some failures, like a missing file, are normal and callers should plan for them. Others are bugs. Java marks the first kind so the compiler can check it.

## How it works

<Compare id="checked-vs-unchecked" />

- A catch for a class also catches its subclasses: `catch (Exception e)` catches every RuntimeException too.
- Where the two common Errors come from: [JVM memory](card:jvm-memory).

## Example

```java
void load() throws IOException {               // checked: declare it...
    Files.readString(Path.of("a.txt"));
}
void run() {
    try { load(); }                            // ...or catch it
    catch (IOException e) { System.out.println("missing file"); }
    int[] a = new int[2];
    a[5] = 1;      // unchecked: compiles, then throws ArrayIndexOutOfBoundsException
}
```

## Interview Qs

### Why have checked exceptions if unchecked ones exist?

They put expected failures, like a missing file, in the method's contract, so the compiler makes callers plan for them. Bugs can happen anywhere; declaring them on every method would only add noise.

### Should you catch Error or Throwable?

Normally no. An Error such as OutOfMemoryError signals a serious problem an application should not try to handle, and `catch (Throwable t)` would catch it too.

### What is an unreachable catch block error?

A compile error for a catch that can never run: it names a checked exception the try block cannot throw, or an earlier catch already covers its type. `Exception` and `Throwable` are exempt from the first rule.
