## Why it exists

A List accepts the same value twice, and `contains` scans every item. A Set stores each value once and answers "is it there?" quickly.

## How it works

<Compare id="hashset-vs-linkedhashset-vs-treeset" />

- Override [equals and hashCode](card:object-class-equals-hashcode) together, or a HashSet keeps two "equal" objects.
- TreeSet is a NavigableSet: `first`, `floor`, `ceiling` and `headSet` work on the sorted order.

## Example

```java
List<String> words = List.of("pear", "apple", "fig");
Set<String> hash = new HashSet<>(words);         // order not guaranteed
Set<String> linked = new LinkedHashSet<>(words); // [pear, apple, fig]
Set<String> tree = new TreeSet<>(words);         // [apple, fig, pear]
System.out.println(tree.add("fig"));             // false: already there
```

## Interview Qs

### Why HashSet when ArrayList already exists?

They answer different needs. ArrayList keeps order and duplicates, and `contains` is O(n). HashSet keeps unique items with O(1) average `contains`, but promises no order.

### How does HashSet stop duplicates?

In OpenJDK each element is a key in an internal HashMap. `add` finds the bucket by `hashCode`, then compares keys with `equals`. If one matches, `add` returns false.

### What if you change an element after adding it to a HashSet?

If the change affects equals or hashCode, the set's behaviour is not specified: `contains` may miss it and a second copy may get in. Use immutable elements.
