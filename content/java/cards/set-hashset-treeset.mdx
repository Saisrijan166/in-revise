## What it is

A `Set` is a collection that holds each item at most once. Adding an item that is already there does nothing, and `add` returns `false`. `HashSet` stores items in a hash table: it turns each item's `hashCode()` into a slot number, called a bucket. `LinkedHashSet` is a `HashSet` that also remembers the order of insertion. `TreeSet` keeps its items sorted, using the order from [Comparable or a Comparator](card:comparable-comparator).

## Why it exists

A `List` happily stores the same payment id twice, and `list.contains(id)` checks every item one by one, which is O(n). A payment gateway that repeats its callbacks would make you process the same payment twice. A Set refuses the repeat for you, and a `HashSet` answers "have I seen this id?" in O(1) on average, however many ids it holds.

## How it works

<Compare id="hashset-vs-linkedhashset-vs-treeset" />

What `set.add(item)` does in a `HashSet`:

1. It calls `item.hashCode()` and turns the number into a bucket index.
2. It looks only at the few items already in that bucket, not the whole set.
3. It compares the new item with each of them using `equals()`.
4. If one is equal, it returns `false` and stores nothing. Otherwise it stores the item and returns `true`.

A `TreeSet` skips hashing: it walks down its sorted tree, calling `compareTo` or the Comparator at each step, and stops if a comparison returns 0. How buckets work in detail is shown in [Map](card:map-hashmap).

## Example

The gateway sends some payment callbacks twice; a `HashSet` skips the repeats, and the other two sets show their orders.

```java
List<String> callbacks = List.of("p2", "p1", "p2", "p3", "p1");  // the gateway repeats some
Set<String> seen = new HashSet<>();
for (String id : callbacks) {
    if (!seen.add(id)) System.out.println("skip duplicate " + id);  // add returns false
}
System.out.println(seen.size());
System.out.println(new LinkedHashSet<>(callbacks));   // first-seen order
System.out.println(new TreeSet<>(callbacks));         // sorted
```

```text output
skip duplicate p2
skip duplicate p1
3
[p2, p1, p3]
[p1, p2, p3]
```

What to notice:

- `seen.add(id)` does the check and the insert in one call, so there is no separate `contains` step.
- The `LinkedHashSet` keeps `p2` first, because that is where it first appeared; adding it again does not move it.
- Printing `seen` itself could show any order; only `LinkedHashSet` and `TreeSet` promise one.

## Rules and defaults

- **Override both:** a class used in a `HashSet` must override [equals and hashCode](card:object-class-equals-hashcode) together, or two equal objects can both be stored.
- **Mutable items:** if you change an item in a way that changes `equals` or `hashCode` while it is in a set, the set's behaviour is not specified. Use immutable items, such as records or strings.
- **Inside (OpenJDK):** a `HashSet` is backed by a `HashMap`; your items are its keys. A `TreeSet` is backed by a `TreeMap`.
- **TreeSet extras:** it is a `NavigableSet`, so `first()`, `floor(x)`, `ceiling(x)` and `headSet(x)` work on the sorted order.
- **Thread safety:** none of the three is synchronised.

## Not to be confused with

A `HashSet` stores single values and answers one question: is this value present? A `HashMap` links each key to a value, such as a payment id to its payment, so you can look the value up. Rule: Set for "have I seen it?"; Map for "what belongs to this key?".

## Interview Qs

### Why HashSet if ArrayList already exists?

They solve different problems. `ArrayList` keeps order and duplicates and is indexed, but `contains` is O(n). `HashSet` keeps only unique items and `contains` is O(1) on average, but it promises no order and has no index.

### How do you remove duplicates from a list but keep the original order?

Copy it into a `LinkedHashSet`: `new ArrayList<>(new LinkedHashSet<>(list))`. The set drops repeats and keeps first-seen order, and the outer `ArrayList` turns it back into a list. A `HashSet` would lose the order, and a `TreeSet` would sort it.

### What if you change an item after adding it to a HashSet?

If the change affects `hashCode`, the item now sits in the wrong bucket. `contains` may return `false` for it, and `remove` may fail to find it. The Set Javadoc says the behaviour is not specified. Keep set items immutable.
