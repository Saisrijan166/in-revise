## What it is

An annotation is a label you attach to code, such as `@Override` on a method. It is metadata: information about the code that changes nothing by itself. Reflection is the API in `java.lang.reflect` that lets a running program look at a class it did not know when it was compiled: list its methods and fields, read their annotations, and call them. Each loaded class is described by a `Class` object, which is where reflection starts.

## Why it exists

A test tool such as JUnit must run your test methods, but it was compiled long before your classes existed, so it cannot call `testRefund()` by name. Without reflection, you would register every test by hand. With annotations and reflection, you mark the method `@Test`, and the tool lists the class's methods at run time, finds the label and calls the method. Dependency injection frameworks and JSON libraries work the same way.

## How it works

1. Get the `Class` object: `PaymentService.class`, `payment.getClass()`, or `Class.forName("app.PaymentService")`, which also initialises the class.
2. List its members. `getDeclaredMethods()` returns every method declared in that class, private ones included, but not inherited ones. `getMethods()` returns only public ones, inherited included.
3. Read each member's labels with `getAnnotation` or `isAnnotationPresent`. This works only for annotations kept until run time.
4. For a private member, call `setAccessible(true)` to skip the access check.
5. Call `invoke(target, args)` on a method, or `get` and `set` on a field.

## Example

A custom `@Audit` label marks the payment methods to log, and a small loop finds and runs them.

```java
@Retention(RetentionPolicy.RUNTIME) @Target(ElementType.METHOD)   // run time; methods only
@interface Audit { String value(); }
class PaymentService {
    @Audit("refund") private void refund() { System.out.println("refund done"); }
    public void pay() { System.out.println("pay done"); }
}

for (Method m : PaymentService.class.getDeclaredMethods()) {
    Audit audit = m.getAnnotation(Audit.class);      // null if absent
    if (audit != null) {
        System.out.println("audit: " + audit.value());
        m.setAccessible(true);                       // open the private method
        m.invoke(new PaymentService());
    }
}
```

```text output
audit: refund
refund done
```

What to notice:

- `pay()` never runs: it has no `@Audit` label, so the loop skips it.
- Delete `@Retention(RetentionPolicy.RUNTIME)` and the program prints nothing, because `getAnnotation` then returns `null`.
- `setAccessible(true)` works here because both classes are in the same module. For a private member of another module, its package must be opened to yours.

## Rules and defaults

- **Retention:** `SOURCE` is dropped by the compiler (`@Override`, `@SuppressWarnings`). `CLASS`, the default, is kept in the `.class` file but not at run time. `RUNTIME` is readable by reflection (`@Deprecated`, `@FunctionalInterface`, framework annotations).
- **Target:** `@Target` limits where the annotation may go. Without it, the annotation is allowed on any declaration.
- **Elements:** an annotation can have elements written like methods, with `default` values. An element named `value` can be set without its name: `@Audit("refund")`.
- **Modules (Java 9+):** deep access to another module's private members throws `InaccessibleObjectException` unless that package is opened. Since Java 17 (JEP 403), JDK internals are closed this way too.

## Common mistakes

- **"An annotation adds behaviour to a method."** `@Audit` on its own does nothing. Some code must read it, such as the loop above, a framework, or the compiler for `@Override`.

## Interview Qs

### What is reflection, and why avoid it in normal code?

Reflection inspects and uses classes, fields and methods at run time. The JVM cannot optimise reflective calls as well as direct ones, mistakes such as a wrong method name appear only at run time, and private access breaks encapsulation. Keep it for frameworks and tools.

### What are the three retention policies?

`SOURCE`: the compiler drops it, as with `@Override`. `CLASS`, the default: kept in the `.class` file, not visible at run time. `RUNTIME`: kept by the JVM and readable by reflection, as with `@Deprecated` and framework annotations.

### How do frameworks use annotations?

They scan your classes with reflection, look for their annotations, and act on them. A test runner calls each method marked `@Test`; a dependency injection framework creates classes marked as components and passes in their dependencies. The annotation is only the label; the framework's code does the work.
