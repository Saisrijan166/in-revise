## What it is

The coding method is a fixed order of questions you answer before you type a program. What data comes in? What must come out? Which loop or collection do you need? What state must you keep, meaning the few variables the loop updates as it goes? The answers give the method's signature (its name, parameter types and return type) and most of its body. The rest of this topic applies the method to number, array, string, collection, OOP and stream programs.

## Why it exists

In a coding round you write Java on the spot, often in a plain editor. Most people do not freeze for lack of syntax; they freeze because they start typing before they know the input, the output and what to keep track of. Then they write, delete and rewrite. Answering the questions first turns a new problem into a few small decisions you have already practised.

## How it works

| Ask | For "count the even numbers" |
|---|---|
| What data do I get? | `int[] nums` |
| What do I return? | an `int` count |
| Which loop or collection? | one for-each loop |
| What state do I keep? | `count`, raised when `n % 2 == 0` |
| What happens to each value? | 1 no, 2 yes, 3 no, 4 yes… |
| What is the final output? | `3` for 1 to 6 |

1. Say the input aloud. It becomes the parameter: `int[] nums`.
2. Say the output aloud. It becomes the return type, so now you can write the signature: `static int countEven(int[] nums)`.
3. Pick the loop or collection and declare the state before the loop: `int count = 0`.
4. Write the loop body, return the state at the end, and print the returned value in `main`.
5. Trace a small input by hand, including an empty or one-element input, and write the expected output before you run it.

To practise, repeat this loop for every program in this topic:

<Steps label="Practise one question">
  <Step title="Write">Hide the answer and write it from memory.</Step>
  <Step title="Predict">Write the expected output before running.</Step>
  <Step title="Run">Compile, fix the errors, compare with your prediction.</Step>
  <Step title="Rewrite">Delete it, change one detail of the question, write it again.</Step>

## Example

The first program is the table above as a whole file: `main` prints what `countEven` returns.

```java
import java.util.*;                             // Arrays, List, Map: most programs need it
public class Main {
    public static void main(String[] args) {
        System.out.println(countEven(new int[] {1, 2, 3, 4, 5, 6}));
    }
    static int countEven(int[] nums) {          // returns the count; main prints it
        int count = 0;
        for (int n : nums) if (n % 2 == 0) count++;
        return count;
    }
}
```

```text output
3
```

What to notice:

- `countEven` is `static`, so `main` can call it without creating an object.
- `count` is declared before the loop. Declared inside, it would restart at 0 for every value.

The second program starts from the questions written as a comment: a String in, a boolean out, and two indexes as the state.

```java
// Input: String. Output: boolean. Logic: compare both ends, move inwards
static boolean isPalindrome(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
        if (s.charAt(left++) != s.charAt(right--)) return false;
    }
    return true;
}
System.out.println(isPalindrome("madam") + " " + isPalindrome("java"));
```

```text output
true false
```

What to notice:

- `return false` stops at the first mismatch; there is no need to check the rest.
- The loop runs while `left < right`, so an empty string and a one-letter string skip it and return `true`.

To run a file from a terminal:

```bash
javac Main.java                   # compile: writes Main.class
java Main                         # run the class: no .java, no .class
java Main.java                    # JDK 11+: compile in memory and run, no .class file
rm -f *.class                     # delete compiled classes in this folder
find . -name "*.class" -delete    # ... and in every subfolder
```

What to notice: after `javac`, `java` takes a class name; in source-file mode it takes a file name. If you edit the file and run `java Main` without compiling again, the old `Main.class` runs, which is why cleaning up class files helps.

## Rules and defaults

- **Source-file mode:** `java Main.java` compiles the file in memory and runs its `main` (JDK 11, JEP 330). Since JDK 22 (JEP 458) it also compiles other `.java` files the program uses.
- **Entry point:** the classic `public static void main(String[] args)` works on every JDK; the shorter Java 25 form is in [JDK, JRE and JVM](card:jdk-jre-jvm). Interview platforms may run an older JDK, so write the classic one.
- **Return type:** a non-void method must return a value on every path, or it does not compile.

## Interview Qs

### How do you start a coding question you have not seen?

Say the input and output aloud, which gives the signature. Pick the loop or collection and the state to keep, write the method, then trace a small input, including an empty or one-element case.

### Why return the result instead of printing it inside the method?

A returned value can be printed, stored, compared in a test or passed to another method. A printed value only reaches the screen. Keeping printing in `main` also keeps the method free of input and output, so it is easy to test.

### What does java Main.java do?

Since JDK 11 the launcher, in [source-file mode](card:source-file-mode), compiles that file in memory and runs its main method, without writing a `.class` file. Since JDK 22 it also compiles other source files the program uses.
