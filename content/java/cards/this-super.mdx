## Why it exists

A parameter can hide a field with the same name, and an override can hide the parent's code. this and super name exactly which one you mean.

## How it works

| Use | this | super |
|---|---|---|
| Field | `this.name` (shadowed by a parameter) | `super.name` (hidden by a child field) |
| Method | `this.save()` (rarely needed) | `super.save()` (parent's version) |
| Constructor | `this(...)`: same class | `super(...)`: parent class |
| As a value | `return this;` or `list.add(this)` | not allowed |

- Chaining and order of constructor calls: [constructors](card:constructors).

## Example

```java
class Animal {
    String sound() { return "..."; }
}
class Dog extends Animal {
    private final String name;
    Dog(String name) { this.name = name; }          // field, not parameter
    Dog() { this("Rex"); }                         // chain to Dog(String)
    @Override String sound() {
        return super.sound() + " woof";             // parent's code first
    }
}
```

## Interview Qs

### Why use this if we can use the variable directly?

When a parameter or local has the same name as a field, the plain name means the parameter. this.name is the only way to reach the field.

### Why super if inheritance already gives us the parent's methods?

After an override, the plain call runs the child's version. super.method() reaches the parent's code, often to extend it, and super(...) passes values to the parent constructor.
