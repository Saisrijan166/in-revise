## What it is

`this` is a reference to the current object: the object whose method or constructor is running right now. `super` refers to the same object, but seen as its parent class. A parent class is the class that another class builds on with `extends`; `class CardPayment extends Payment` makes `CardPayment` a child of `Payment`, and [inheritance](card:inheritance) covers this fully. Both words also have a call form inside constructors: `this(...)` and `super(...)`.

## Why it exists

A constructor parameter is usually named like the field it fills, so inside the constructor `amount` means the parameter, and the field is hidden. Constructors that share setup would also repeat it. A child class that replaces a parent method (overriding, see [polymorphism](card:polymorphism)) would have no way to run the parent's code. `this` and `super` name exactly which one you mean.

## How it works

| Use | `this` | `super` |
|---|---|---|
| Field | `this.amount`: the field, when a parameter has the same name | `super.amount`: the parent's field, if a child field hides it |
| Method | `this.describe()`: same as `describe()` | `super.describe()`: the parent's version |
| Constructor call | `this(...)`: another constructor of this class | `super(...)`: a constructor of the parent class |
| As a value | `return this;` or `list.add(this)` | not allowed |

1. When `new CardPayment(...)` runs, its constructor calls `super(id, amount)`, so `Payment`'s constructor sets the parent's fields.
2. Back in `CardPayment`, `this.last4 = last4` copies the parameter into the field of the same name.
3. When code calls `describe()` on the object, the child's version runs.
4. The child's version calls `super.describe()`, which runs the parent's version on the same object, and then adds its own text.

## Example

`Payment` chains its constructors, and `CardPayment` builds on `Payment` with `super`.

```java
class Payment {
    long id, amount;
    Payment(long id, long amount) { this.id = id; this.amount = amount; }  // field = parameter
    Payment(long id) { this(id, 0); }                                     // chain: same class
    String describe() { return "Payment " + id + ": " + amount + " paise"; }
}
class CardPayment extends Payment {
    String last4;
    CardPayment(long id, long amount, String last4) { super(id, amount); this.last4 = last4; }
    @Override String describe() { return super.describe() + " by card " + last4; }
}
System.out.println(new CardPayment(7, 50000, "4242").describe());
System.out.println(new Payment(8).describe());
```

```text output
Payment 7: 50000 paise by card 4242
Payment 8: 0 paise
```

What to notice:

- `this(id, 0)` reuses the two-argument constructor, so the field assignments are written once.
- `super(id, amount)` lets `Payment` set its own fields. Remove it and the compiler inserts `super()`, which fails here because `Payment` has no no-argument constructor.
- `@Override` asks the compiler to check that `describe()` really replaces a parent method; a typo in the name would then be a compile error.
- `super.describe()` reuses the parent's text. Writing `describe()` there instead would call the child's method again and again until a `StackOverflowError`.

## Rules and defaults

- **Where they work:** in constructors, instance methods and instance blocks. Static methods have no current object, so `this` and `super` are compile errors there.
- **One call:** a constructor may make one `this(...)` or one `super(...)` call, not both. With neither, the compiler adds `super()`.
- **Position (Java 25):** statements may come before the call, but they may not use `this`; see [constructors](card:constructors).
- **Direct parent only:** `super` reaches the parent, never the grandparent; `super.super.describe()` does not compile.

## Interview Qs

### Why use this if we can use the variable directly?

When a parameter or local variable has the same name as a field, the plain name means the parameter. `this.amount` is the only way to reach the field. `this` is also needed to pass the current object to another method, or to return it for chained calls.

### Why do we need super if inheritance already gives us the parent's methods?

After a child overrides a method, a plain call runs the child's version. `super.method()` reaches the parent's code, usually to extend it rather than copy it. `super(...)` passes values to the parent's constructor, which the child cannot call any other way.

### Can a constructor call both this(...) and super(...)?

No. It may make only one of these calls. A constructor that calls `this(...)` hands the work to another constructor, and that one makes the `super(...)` call, explicitly or implicitly, so the parent is still set up exactly once.
