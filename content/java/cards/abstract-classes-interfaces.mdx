## Why it exists

Callers should depend on what an object can do, not on its class. An interface names that contract; an abstract class also shares code and state.

## How it works

<Compare id="abstract-class-vs-interface" />

- Interface methods are public unless private, so an implementing method must be `public`.
- A default method lets an interface gain a method without breaking old implementers.
- An interface with one abstract method is a [functional interface](card:lambdas).

## Example

```java
interface Payment {                                // the contract
    void pay(double amount);
    default void payAll(double... amounts) { for (double a : amounts) pay(a); }
}
abstract class BasePayment implements Payment {   // shared state
    protected final String account;
    BasePayment(String account) { this.account = account; }
}
class UpiPayment extends BasePayment {
    UpiPayment(String account) { super(account); }
    public void pay(double amount) { /* call the UPI gateway */ }  // must be public
}
```

## Interview Qs

### If abstract classes exist, why do we need interfaces?

A class can extend only one class but implement many interfaces. Interfaces let unrelated classes, like UPI and card payments, share a type without a common parent.

### Can an abstract class have a constructor?

Yes. You cannot call it with `new`, but every subclass constructor runs it through `super(...)`, so it initialises the shared fields.

### Why declare variables with the interface type?

`Payment p = new UpiPayment("a1")` ties the caller to the contract only. You can swap the implementation, or pass a test double, without changing that code.
