## What it is

An abstract class is a class marked `abstract` that you cannot create with `new`. It may declare abstract methods, which have no body, and every concrete (non-abstract) subclass must implement them. It can also hold fields, constructors and normal methods. An interface is a contract: a list of methods that a class promises to provide by writing `implements`. A class extends one class but can implement many interfaces.

## Why it exists

In [polymorphism](card:polymorphism), `PaymentMethod` was a normal class whose `fee()` returned a dummy 0. That dummy body is a warning sign: the parent has no sensible fee, and nothing forces a subclass to supply one. An interface removes the dummy and makes `fee()` mandatory. `PaymentService` then depends only on the contract, so a new payment kind needs no change to the service. An abstract class adds what an interface cannot hold: shared fields and a constructor, written once.

## How it works

  alt="PaymentService uses the PaymentMethod interface. The abstract class BaseMethod implements PaymentMethod and holds the shared account field. CardPayment and UpiPayment extend BaseMethod and each implement fee()."
  chart={`flowchart LR
  S[PaymentService] -- "calls fee()" --> I["interface PaymentMethod"]
  B["abstract BaseMethod: account field"] -- implements --> I
  C[CardPayment] -- extends --> B
  U[UpiPayment] -- extends --> B`}
/>

1. The interface declares `fee(long)` with no body. It is implicitly `public` and `abstract`.
2. The abstract class `BaseMethod` implements the interface but does not have to write `fee()`, because an abstract class may leave methods unimplemented. It adds the shared `account` field and a constructor.
3. `CardPayment` extends `BaseMethod`, passes the account up with `super(account)`, and implements `fee()`. If it forgets, it does not compile, unless it is declared abstract too.
4. The caller holds the object in an interface-type variable. Calls go to the object's own method through dynamic dispatch.
5. A `default` method in the interface, here `total()`, has a body and is inherited by every implementation, which may override it.

So the key is: the interface fixes what can be called, the abstract class shares how.

## Example

The running payment example, split into a contract, a shared base and one implementation.

```java
interface PaymentMethod {                              // the contract
    long fee(long paise);                              // implicitly public and abstract
    default long total(long paise) { return paise + fee(paise); }   // Java 8+
}
abstract class BaseMethod implements PaymentMethod {   // shared state, no fee() yet
    protected final String account;
    BaseMethod(String account) { this.account = account; }
}
class CardPayment extends BaseMethod {
    CardPayment(String account) { super(account); }
    public long fee(long paise) { return paise * 2 / 100; }  // must be public
}

PaymentMethod m = new CardPayment("acc-1");
System.out.println(m.total(10_000));
```

```text output
10200
```

What to notice:

- `total()` is written once, in the interface, yet it calls the card's `fee()`: 10,000 plus a 200 fee.
- `public` on `fee` is required. Remove it and the compiler reports that it tries to assign weaker access than the interface method.
- `BaseMethod` has a constructor although nobody can call `new BaseMethod(...)`. It runs through `super(account)` whenever a subclass object is built.
- The variable type is `PaymentMethod`, so swapping in a `UpiPayment` changes no calling code.

## Rules and defaults

- **Abstract class:** cannot be instantiated. A class that declares an abstract method must itself be declared `abstract`.
- **Abstract method:** has no body and cannot also be `private`, `static` or `final`, because each of those stops a subclass from implementing it.
- **Interface fields:** every field is implicitly `public static final`, so it is a constant.
- **Interface methods:** implicitly `public` unless `private`, and implicitly `abstract` unless `default`, `static` or `private`.
- **Versions:** `default` and `static` interface methods arrived in Java 8, `private` ones in Java 9.
- **Static interface methods:** they are not inherited. Call them through the interface name, `InterfaceName.method()`, not through an implementing class or object.
- **Extending:** an interface can extend several interfaces. If two inherited default methods clash, the class must override the method, as in [inheritance](card:inheritance).

## Not to be confused with

An abstract class is a common parent for closely related classes: it says what they are and shares their fields and code. An interface is a capability that unrelated classes can offer side by side: one card payment class can implement `PaymentMethod` and a `Refundable` interface at once. Rule: abstract class = shared state, one parent; interface = a contract, many at a time.

## Interview Qs

### If abstract classes exist, why do we need interfaces?

A class can extend only one class but implement many interfaces. Interfaces let unrelated classes, like UPI and card payments, share a type without wasting their one superclass on it. They also let callers depend on a contract alone, which keeps code loosely coupled.

### Can an abstract class have a constructor?

Yes. You cannot call it with `new`, but every subclass constructor runs it through `super(...)`, so it initialises the shared fields once for all subclasses.

### Why declare variables with the interface type?

`PaymentMethod m = new CardPayment("acc-1")` ties the caller to the contract only. You can swap the implementation, or pass a test double, without changing that code. This is called programming to an interface.
