## Why it exists

A caller needs to know what a method can change. Because every argument is copied, a method can use what your variables point to, but never rebind them.

## How it works

<Mermaid
  alt="The caller's variable user and the method's parameter u hold copies of the same reference, so both point to one User object. Changing a field through u is visible to the caller. Assigning a new User to u only redirects the method's copy."
  chart={`flowchart LR
  C["caller: user"] --> O((User object))
  M["method: u (a copy)"] --> O
  M -. "u = new User()" .-> N((another User))`}
/>

- Arrays are objects too: a method can change `arr[0]`, but not replace the caller's array.
- String and wrapper objects are immutable, so a method cannot change the caller's value at all.

## Example

```java
void rename(User u)  { u.name = "New"; }               // caller sees this
void replace(User u) { u = new User(); }               // caller does not
void swap(int a, int b) { int t = a; a = b; b = t; }   // no effect outside

User user = new User();
rename(user);    // user.name is now "New"
replace(user);   // user is still the same object
```

## Interview Qs

### Is Java pass-by-value or pass-by-reference?

Always pass-by-value. For objects the value copied is the reference, so changes to fields are visible to the caller, but reassigning the parameter is not.

### Why can't you write a swap(a, b) method in Java?

The method swaps its own copies; the caller's variables still hold the old values or references. Return the result, or swap inside an array or object instead.
