## What it is

Pass-by-value means that when you call a method, Java copies each argument into a new parameter variable inside the method. For a primitive, the copy is the number itself. For an object, recall from [data types](card:data-types) that the variable holds a reference, so the copy is that reference, and the parameter points to the same object as the caller's variable. Java never passes the variable itself; there is no pass-by-reference.

## Why it exists

A caller needs to know what a method can and cannot change. Because every argument is a copy, a method can never make your variable point somewhere else, or change your `int`. It can only change an object through the reference it received. Knowing this answers a whole family of output questions, and explains why a Java `swap(a, b)` method cannot work.

## How it works

1. The caller's variable `note` holds a reference to a `StringBuilder` object.
2. On the call, Java copies that reference into the method's parameter. Now two variables point to one object.
3. If the method calls `note.append(...)`, it changes the shared object, so the caller sees the new text.
4. If the method assigns `note = new StringBuilder(...)`, only its own copy now points to the new object. The caller's variable still points to the old one.
5. When the method returns, its parameter disappears; the caller's variable was never touched.

So the key is: change the object and the caller sees it; reassign the parameter and the caller does not.

## Example

Three helper methods of the payment service, called with a note and an amount:

```java
static void addMark(StringBuilder note) { note.append(" [checked]"); }        // caller sees this
static void replace(StringBuilder note) { note = new StringBuilder("new"); }  // caller does not
static void addTen(int amount) { amount = amount + 10; }                      // caller does not

public static void main(String[] args) {
    StringBuilder note = new StringBuilder("payment 42");
    int amount = 500;
    addMark(note);
    replace(note);
    addTen(amount);
    System.out.println(note + " / " + amount);
}
```

```text output
payment 42 [checked] / 500
```

What to notice:

- `addMark` changed the object both variables point to, so ` [checked]` shows up in the caller.
- `replace` built a new `StringBuilder`, but only its parameter points to it; the caller's `note` is unchanged.
- `addTen` added to its own copy of 500, so the caller's `amount` is still 500. To change it, return the result: `amount = addTen(amount);` with a method that returns `int`.

## Rules and defaults

- **Arrays are objects:** a method can change `arr[0]`, and the caller sees it, but it cannot replace the caller's array.
- **Immutable objects:** a `String` or a wrapper such as `Integer` cannot be changed, so a method cannot change the caller's value at all; it can only return a new one.
- **No swap:** a method cannot swap two caller variables. Return the result, or swap the contents inside an array or object.

## Interview Qs

### Is Java pass-by-value or pass-by-reference?

Always pass-by-value. For objects the value copied is the reference, so changes to the object are visible to the caller, but reassigning the parameter is not. With pass-by-reference, the method could make the caller's variable point to a different object; Java cannot.

### Why can't you write a swap(a, b) method in Java?

The method receives copies, so it swaps its own two parameters while the caller's variables still hold the old values or references. To swap, put the values in an array or object and swap its contents, or return the swapped result.

### If Java is pass-by-value, why does my list change after I pass it to a method?

Because the method received a copy of the reference to the same list object. Calling `list.add(...)` through that copy changes the one shared list, so the caller sees it. Writing `list = new ArrayList<>()` in the method would not affect the caller.
