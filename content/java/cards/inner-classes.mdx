## Why it exists

Some classes only make sense next to one other class, like a Builder or an iterator. Nesting keeps them together and lets them use the outer class's private members.

## How it works

| Kind | Declared | Needs an outer object? | Typical use |
|---|---|---|---|
| Static nested | `static class` in a class | no | Builder, Node, helpers |
| Inner (member) | `class` in a class | yes | iterator over outer data |
| Local | inside a method | yes, in instance methods | a one-method helper |
| Anonymous | `new Type() { ... }` | yes, in instance methods | a one-off implementation |

- A [lambda](card:lambdas) only implements a functional interface; an anonymous class may also extend a class and hold fields.

## Example

```java
class Outer {
    private int size = 3;
    static class Nested { }                   // no Outer needed
    class Inner { int twice() { return size * 2; } }   // uses Outer.this.size
    Runnable task() {
        return new Runnable() {               // anonymous class
            public void run() { System.out.println(size); }   // here this = the Runnable
        };
    }
}
Outer.Nested n = new Outer.Nested();
Outer.Inner i = new Outer().new Inner();
```

## Interview Qs

### Static nested class vs inner class?

A static nested class needs no outer object and behaves like a top-level class. An inner class belongs to one outer object, can read its fields, and keeps it reachable for the garbage collector.

### When would you still use an anonymous class over a lambda?

When the type is not a functional interface, for example an abstract class, or when you need fields or several methods.
