## What it is

A nested class is a class declared inside another class, called the outer class. There are four kinds. A static nested class is marked `static` and needs no outer object. An inner (member) class is not static: each of its objects belongs to one outer object and can read that object's fields, even private ones. A local class is declared inside a method, and an anonymous class has no name and is declared and created in a single `new` expression.

## Why it exists

Some classes only make sense next to one other class: a `Config` for a service, a `Node` for a list, a counter over the service's data. As top-level classes they clutter the package and cannot see the outer class's private fields. Nesting keeps the helper next to its user and gives it that access. An anonymous class lets you implement an [interface](card:abstract-classes-interfaces) once, where it is needed, without inventing a class name for one use.

## How it works

| Kind | Declared | Needs an outer object? | Typical use |
|---|---|---|---|
| Static nested | `static class` inside a class | no | Config, Builder, Node |
| Inner (member) | `class` inside a class | yes | a view or counter over outer data |
| Local | inside a method body | yes, in instance methods | a helper for one method |
| Anonymous | `new Type() { ... }` | yes, in instance methods | a one-off implementation |

1. `new PaymentService.Config()` creates a static nested object. Nothing else is needed; it behaves like a top-level class with a dotted name.
2. An inner object needs an outer object first: `service.new Counter()`. Inside the outer class's own instance methods, plain `new Counter()` uses `this` as the outer object.
3. The compiler gives the inner object a hidden reference to its outer object, written `PaymentService.this`. That is how `Counter` reads `processed`.
4. `new Runnable() { ... }` declares an unnamed class that implements `Runnable` and creates one object of it in the same step. Inside its body, `this` is that anonymous object.

## Example

`PaymentService` has a static nested config, an inner counter and an anonymous task.

```java
class PaymentService {
    private int processed = 0;
    static class Config { int retries = 3; }                  // static nested
    class Counter { int next() { return ++processed; } }      // inner: uses the service's field
    Runnable report() {
        return new Runnable() {                               // anonymous class
            public void run() { System.out.println("processed=" + processed); }
        };
    }
}
var service = new PaymentService();
PaymentService.Counter counter = service.new Counter();   // tied to this service
counter.next(); counter.next();
service.report().run();
System.out.println(new PaymentService.Config().retries); // no service needed
```

```text output
processed=2
3
```

What to notice:

- `Counter` changes the private field `processed` of the service it was created from. Two counters made from two services would count separately.
- `Config` is created without any service, because it is static. Remove `static` and `new PaymentService.Config()` stops compiling.
- The anonymous `Runnable` also reads `processed`: it is created inside an instance method, so it is tied to that service too.

## Rules and defaults

- **Static nested:** can use the outer class's static members, even private ones, but needs an object to reach instance fields.
- **Inner classes:** each object holds its outer object, so the outer object cannot be garbage-collected (freed from memory) while the inner one is reachable. Since JDK 18, javac leaves out this reference when the inner class never uses it.
- **Static members:** inner classes may declare static members since Java 16.
- **Anonymous classes:** they cannot declare a constructor, but arguments in `new Base(args) { ... }` go to the parent's constructor. One anonymous class extends one class or implements one interface, not both.
- **Captured local variables:** a local or anonymous class may read a method's local variables only if they are `final` or effectively final, meaning never changed after being set.

## Not to be confused with

A static nested class is a normal class that only lives inside another class's name. An inner class is tied to one outer object and carries a reference to it. Rule: static nested = no outer object; inner = one outer object per inner object. An anonymous class also differs from a lambda, which you will meet in [lambdas](card:lambdas): a lambda creates no new class scope, so `this` inside it is the enclosing object.

## Interview Qs

### Static nested class vs inner class?

A static nested class needs no outer object and behaves like a top-level class. An inner class belongs to one outer object, can read its fields, and keeps that object reachable for as long as the inner object lives.

### Why can an inner class cause a memory leak?

Each inner object holds its outer object. If a long-lived cache or listener list keeps an inner object, the large outer object it points to can never be garbage-collected. Making the nested class static removes the hidden reference.

### When would you still use an anonymous class over a lambda?

When the type is not a functional interface (an interface with exactly one abstract method), for example an abstract class or an interface with several abstract methods, or when you need fields or your own `this`. For a single-method interface, a lambda is shorter.
