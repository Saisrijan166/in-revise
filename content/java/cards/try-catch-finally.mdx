## Why it exists

Code must recover from failures and still release files, sockets and locks. catch handles the failure; finally and try-with-resources make sure cleanup is not skipped.

## How it works

<Steps label="What runs, in order">
<Step title="try">
The block runs until it ends or something is thrown.
</Step>
<Step title="Close resources">
try-with-resources only: resources close, last opened first.
</Step>
<Step title="catch">
Only the first catch whose type matches runs; the rest are skipped.
</Step>
<Step title="finally">
Runs on every exit. If no catch matched, the exception then moves up to the caller.
</Step>
</Steps>

- Since Java 9 an existing effectively final variable can be the resource: `try (in) { }`.

## Example

```java
int firstByte(String path) {
    try (var in = new FileInputStream(path)) {   // closed automatically
        return in.read();
    } catch (FileNotFoundException e) {          // subclass first
        return -1;
    } catch (IOException e) {                    // then its parent
        throw new UncheckedIOException(e);
    } finally {
        System.out.println("after close, even after return");
    }
}
```

## Interview Qs

### Does finally always run? Why not clean up in catch?

catch runs only when a matching exception occurs; finally runs on every exit, including return and break. It may not run if the JVM exits first, for example on System.exit or a crash.

### Why use try-with-resources when finally exists?

It is shorter and you cannot forget close(). It closes in reverse order, and if both the body and close() throw, the body's exception wins and the close() one is kept as suppressed.

### Can a try have no catch?

Yes: try-finally, or try-with-resources on its own. A try with neither catch, finally nor resources is a compile error.
