## What it is

A try-catch-finally statement is how you handle the [exceptions](card:exception-hierarchy) from the previous concept. The `try` block holds code that may throw. A `catch` block names an exception type and runs only when that type, or a subclass, is thrown. The `finally` block runs last, whatever happened. try-with-resources (Java 7) is a form of try that opens resources, such as files or database connections, in brackets and closes them for you.

## Why it exists

A payment service opens a receipt file, writes to it and must close it, whether the write works or fails. If the close call sits at the end of the try block, an exception skips it and the file stays open; enough of those and the process runs out of file handles. catch lets you recover from the failure, and finally or try-with-resources makes sure the cleanup always runs. try-with-resources also removes the long, easy-to-get-wrong finally code that closing by hand needs.

## How it works

<Mermaid
  alt="Flow of a try statement. The try block runs. If it is try-with-resources, its resources close first. If an exception was thrown, Java picks the first catch whose type matches and runs it.   chart={`flowchart TD
  T[try block runs] --> R[resources close, last opened first]
  R --> Q{exception thrown?}
  Q -- no --> F[finally runs]
  Q -- yes --> C{a catch type matches?}
  C -- yes --> H[that one catch runs] --> F
  C -- no --> F
  F --> E[method continues, or the unmatched exception goes to the caller]`}
/>

1. The try block runs from the top until it ends or something throws. The lines after the throwing line are skipped.
2. In try-with-resources, each resource is closed as soon as the try block ends, in reverse order of opening. This happens before any catch or finally.
3. If an exception was thrown, Java checks the catch blocks from top to bottom and runs only the first whose type matches. The others are skipped.
4. The finally block runs next, in every case: after a normal end, after a catch, and even after a `return` in try or catch.
5. If no catch matched, the exception continues up to the calling method once finally has run.

So the key is: catch is for recovering, and finally or try-with-resources is for cleanup that must not be skipped.

## Example

`Receipt` stands for any resource. It prints when it opens and closes, so the order is visible:

```java
class Receipt implements AutoCloseable {
    Receipt() { System.out.println("open receipt"); }
    void write(long paise) {
        if (paise <= 0) throw new IllegalArgumentException("amount " + paise);
        System.out.println("write " + paise);
    }
    @Override public void close() { System.out.println("close receipt"); }
}
```

`record` writes one amount and handles a bad one. It is called with 500 and then with 0:

```java
static void record(long paise) {
    try (var receipt = new Receipt()) {
        receipt.write(paise);
    } catch (IllegalArgumentException e) {
        System.out.println("caught " + e.getMessage());
    } finally {
        System.out.println("finally");
    }
}
```

```text output
open receipt
write 500
close receipt
finally
open receipt
close receipt
caught amount 0
finally
```

What to notice:

- There is no `receipt.close()` in the code. try-with-resources calls it on both runs, even when `write` throws.
- In the second run, `close receipt` prints before `caught amount 0`: the resource is closed before the catch block runs, so a catch must not try to use it.
- `finally` prints on both runs. With a plain try and no resources, you would need `receipt.close()` inside finally, with a null check, to get the same safety.

## Rules and defaults

- **Valid forms:** a try needs at least one catch, a finally, or resources. A bare `try { }` does not compile.
- **Catch order:** a catch for a subclass after a catch for its superclass is a compile error, for example `FileNotFoundException` after `IOException`, because it could never run.
- **Multi-catch (Java 7):** `catch (IOException | SQLException e)` handles both types in one block. The variable `e` is implicitly final.
- **Resources:** must implement `AutoCloseable`, an interface with one method, `close()`. Since Java 9 an existing final or effectively final variable can be the resource: `try (in) { }`.
- **Suppressed exceptions:** if the try block throws and `close()` also throws, the try block's exception is the one thrown. The close exception is attached to it; `getSuppressed()` returns it.
- **When finally does not run:** if the JVM stops first, for example on `System.exit` or a crash.

## Not to be confused with

`finally` is a block that runs on every exit from a try. `final` is a keyword that stops a variable from being reassigned, a method from being overridden, or a class from being extended; see [final](card:final-keyword). `finalize()` is an `Object` method the garbage collector might call before freeing an object; it is deprecated, and marked for removal since Java 18. Rule: finally = cleanup block, final = cannot change, finalize = do not use.

## Common mistakes

- **"I close the file at the end of the try block."** An exception earlier in the block skips that line, so the file stays open. Use try-with-resources.
- **"catch (Exception e) at the top, the specific ones below."** That does not compile, because the broad catch already covers the specific types. Specific first, broad last.

## Interview Qs

### Does finally always run? Why not clean up in catch?

catch runs only when a matching exception is thrown, so cleanup there is skipped on success and on other exception types. finally runs on every exit, including return and break. It is skipped only if the JVM stops first, for example on System.exit or a crash.

### Why use try-with-resources when finally exists?

It is shorter, and you cannot forget to close. It closes resources in reverse order, and if both the body and close() throw, it keeps the body's exception and attaches the close() one as suppressed. A hand-written finally that calls close() can throw and replace the original exception.

### Can a try have no catch?

Yes: try-finally, or try-with-resources on its own, which then only closes its resources and lets any exception continue to the caller. A try with no catch, no finally and no resources is a compile error.
