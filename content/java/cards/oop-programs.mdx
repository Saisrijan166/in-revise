## What it is

OOP programs are "design a class for…" questions, where you write object-oriented code instead of defining it. Five shapes cover most of them: a class that guards its fields, an abstract parent with a child, an interface with two implementations, a custom exception, and an immutable value class. Each shape applies one earlier concept; this page is the code you type.

## Why it exists

Many candidates can define encapsulation or polymorphism but stumble when asked to write them. Interviewers use these programs to check the details that only show in code: private fields, a constructor that validates, `super(...)` in the child, `@Override`, `throws` on a checked exception, and equals with hashCode. A missing `public` or a missing hashCode is a compile error or a wrong answer.

## How it works

| Asked to write | Must show | Theory |
|---|---|---|
| A class with a constructor | private fields, `this.x = x`, a validating setter | [encapsulation](card:oop-principles) |
| Inheritance with overriding | `extends`, `super(...)`, `@Override` | [polymorphism](card:polymorphism) |
| Abstract class vs interface | state in one, a contract in the other | [both](card:abstract-classes-interfaces) |
| A custom exception | `extends Exception`, `super(message)` | [custom exceptions](card:throw-throws-custom) |
| equals and hashCode, immutable | `final`, `private final`, a new object per change | [equals](card:object-class-equals-hashcode), [immutability](card:immutability) |

1. Find the nouns in the question: they become classes and fields.
2. Make every field `private`, and `final` when it never changes after construction.
3. Write the constructor and route every change through a method that checks the value.
4. Put shared state and code in an abstract parent, and a pure contract in an interface.
5. Mark every overriding method with `@Override`, so the compiler checks the signature.

## Example

An encapsulated class lets only a validating setter change its state.

```java
class Student {
    private final String name;
    private int marks;
    Student(String name, int marks) { this.name = name; setMarks(marks); }
    int getMarks() { return marks; }
    void setMarks(int marks) {                        // the only way to change it
        if (marks < 0 || marks > 100) throw new IllegalArgumentException("marks " + marks);
        this.marks = marks;
    }
    @Override public String toString() { return name + " (" + marks + ")"; }
}
System.out.println(new Student("Asha", 92));
```

```text output
Asha (92)
```

What to notice: the constructor calls `setMarks`, so a bad value is rejected at creation too. `name` is `final` and has no setter, so it never changes.

An abstract parent holds the state; the child supplies the missing method.

```java
abstract class Animal {                    // state and shared code; no new Animal()
    private final String name;
    Animal(String name) { this.name = name; }
    abstract String sound();               // every child must implement it
    void speak() { System.out.println(name + ": " + sound()); }
}
class Dog extends Animal {
    Dog(String name) { super(name); }
    @Override String sound() { return "Woof"; }
}
Animal a = new Dog("Rex");                 // upcast; overriding picks Dog.sound()
a.speak();
```

```text output
Rex: Woof
```

What to notice: `speak` lives in `Animal`, but the call to `sound()` runs `Dog`'s version because the object is a `Dog`. `Dog` must call `super(name)`, because `Animal` has no no-argument constructor for Java to call by default.

An interface is a contract that unrelated types implement.

```java
interface Shape { double area(); }              // a contract, no state
record Square(double side) implements Shape {
    public double area() { return side * side; }
}
record Circle(double r) implements Shape {
    public double area() { return Math.PI * r * r; }
}
for (Shape s : List.of(new Square(3), new Circle(1))) {
    System.out.printf("%s %.2f%n", s.getClass().getSimpleName(), s.area());
}
```

```text output
Square 9.00
Circle 3.14
```

What to notice: `area()` is `public` in both records. The loop works only with the `Shape` type, so a new shape needs no change to it.

A custom checked exception must be declared and caught.

```java
class InvalidAgeException extends Exception {             // checked
    InvalidAgeException(String message) { super(message); }
}
static void checkAge(int age) throws InvalidAgeException {
    if (age < 18) throw new InvalidAgeException("Age " + age + " is under 18");
}
try {
    checkAge(15);
} catch (InvalidAgeException e) {
    System.out.println("Caught: " + e.getMessage());
}
```

```text output
Caught: Age 15 is under 18
```

What to notice: `super(message)` stores the text that `getMessage()` returns. Remove `throws` from `checkAge` and the code no longer compiles.

An immutable value class returns a new object for every change.

```java
final class Money {                                        // no subclass can change it
    private final long paise;                              // private final, no setter
    Money(long paise) { this.paise = paise; }
    Money plus(Money m) { return new Money(paise + m.paise); }   // a change = a new object
    @Override public boolean equals(Object o) { return o instanceof Money m && paise == m.paise; }
    @Override public int hashCode() { return Long.hashCode(paise); }
}
Money a = new Money(100);
Money b = a.plus(new Money(50));
Set<Money> set = new HashSet<>(List.of(a, new Money(100)));
System.out.println(a.equals(new Money(100)) + " " + b.equals(new Money(150)) + " " + set.size());
```

```text output
true true 1
```

What to notice: `plus` leaves `a` at 100 paise. Because equals and hashCode agree, the HashSet treats the two 100-paise objects as one. `o instanceof Money m` is pattern matching (Java 16).

## Rules and defaults

- **Interface methods:** unless declared `private` (Java 9), they are `public` even without the keyword, and an implementation may not reduce access, so it must say `public`.
- **Abstract:** a class with an abstract method must itself be `abstract`, and cannot be created with `new`.
- **Checked exception:** a method that throws one must catch it or declare it with `throws`.

## Interview Qs

### Write a class with proper encapsulation.

Make the fields private, set them in a constructor, expose getters, and let only a validating setter change state. Leave out setters the caller does not need; final fields cannot change after construction.

### When would you write a record instead of a class?

For a plain data carrier: `record Money(long paise) {}` writes the final field, constructor, equals and hashCode of the class above for you, plus accessors and toString. Its limits are in [records](card:records-sealed).
