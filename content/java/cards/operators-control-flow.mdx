## What it is

Operators are the symbols that compute a value, such as `+`, `==`, `&&` and `++`. Control flow is the set of statements that decide which lines run and how often: `if`/`else`, the loops `for`, `while` and `do-while`, and `switch`, which picks one branch by a value. Together they are the moving parts of every method.

## Why it exists

Most operators work as you expect, so interviewers ask about the few that do not. Output questions turn on three questions. When does `++` change the variable? Which side of `&&` is skipped? Where does a `switch` stop? Get them wrong and a payment check can crash on `null` or a switch can run two branches. Java 14 added the arrow switch to remove the most common of these bugs.

## How it works

| | Classic `case X:` | Arrow `case X ->` (Java 14) |
|---|---|---|
| Runs into the next case | Yes, until `break` | Never |
| Gives a value in a switch expression | `yield value;` | `-> value`, or `yield` inside a `{ }` block |
| Several values in one case | `case 1, 7:` | `case 1, 7 ->` |

1. Java evaluates an expression from left to right, so in `i++ + ++i` the left part runs, and changes `i`, before the right part.
2. `i++` hands back the current value and then adds 1; `++i` adds 1 first and hands back the new value.
3. For `a && b`, Java evaluates `a` first. If `a` is false, the result is already false, so `b` never runs. `||` skips `b` when `a` is true.
4. A `switch` jumps to the matching case. With `case X:` it runs on, through the next cases, until a `break`. With `case X ->` it runs only that case.
5. Loops repeat a body: `for (int i = 0; i < n; i++)`, the for-each `for (int x : arr)`, `while (c)`, and `do { } while (c);`, which runs the body at least once.

## Example

A payment check that uses each rule once:

```java
int i = 5;
int a = i++;                      // a = 5, then i becomes 6
int b = ++i;                      // i becomes 7, then b = 7
String note = null;
if (note != null && note.length() > 0) { }   // right side skipped: no crash
short sh = 3;
sh += 4.6;                        // means sh = (short) (sh + 4.6), so 7
String status = "FAILED";
String action = switch (status) {
    case "PAID" -> "send receipt";
    case "FAILED", "TIMEOUT" -> "retry";
    default -> "wait";
};
System.out.println(a + " " + b + " " + sh + " " + action);
```

```text output
5 7 7 retry
```

What to notice:

- `a` keeps the old 5 because `i++` adds after handing back the value.
- `note.length()` never runs, because `note != null` is already false. With `&` instead of `&&`, this line throws `NullPointerException`.
- `sh = sh + 4.6;` would not compile (`double` to `short`), but `+=` inserts the cast for you and drops the fraction.
- The arrow switch returns a value. Remove `default` and it does not compile, because a `String` switch expression must cover every possible value.

## Rules and defaults

- **Exhaustive:** a switch expression must cover every possible value, usually with a `default` case.
- **yield:** inside a `{ }` block of a switch expression, `yield value;` gives the result. `return` is not allowed there.
- **null:** a switch whose value is `null` throws `NullPointerException`, unless it has a `case null` label (Java 21, JEP 441).
- **break and continue:** `break` leaves a loop or switch, `continue` starts the next pass of a loop, and `break outer;` leaves the loop labelled `outer:`, even from inside a nested loop.
- **& and | on integers:** they are bitwise AND and OR, not logical operators.

## Common mistakes

- **"`return` works inside a switch expression block."** It does not compile; use `yield` to give the block's value.
- **Using `&` or `|` for a null check.** They evaluate both sides, so the right side runs even when the left side has already found `null`.

## Interview Qs

### What is the difference between & and &&?

For booleans both mean AND, but `&&` short-circuits: if the left side is false, it skips the right side. `&` always evaluates both. That matters for guards such as `p != null && p.isPaid()`. On integers, `&` is bitwise AND.

### Switch statement vs switch expression?

A switch statement only runs code; with `case X:` labels it falls through unless you `break`. A switch expression (Java 14) produces a value, as in `String s = switch (x) { ... };`, uses arrows that never fall through, and must be exhaustive.

### What happens if the switch value is null?

It throws `NullPointerException` before any case runs, even with a `default`. Since Java 21 you can add a `case null` label, for example `case null -> "missing";`, to handle it inside the switch.
