## Why it exists

A few rules decide most output questions: when a side effect happens, which side is skipped, and where a switch stops.

## How it works

| | Classic `case X:` | Arrow `case X ->` (Java 14) |
|---|---|---|
| Falls through to the next case | Yes, until `break` | Never |
| Value in a switch expression | `yield value;` | `-> value`, or `yield` inside a block |

- A switch expression must be exhaustive: cover every value, usually with `default`.
- Loops: `for (int i = 0; i < n; i++)`, for-each `for (int x : arr)` over an array or any Iterable, `while (c)`, and `do { } while (c);`, which runs the body at least once.
- `break` leaves a loop or switch, `continue` starts the next pass, `break outer;` leaves a labelled loop.

## Example

```java
int i = 5;
int a = i++;                  // a = 5, then i = 6
int b = ++i;                  // i = 7, then b = 7
String s = null;
if (s != null && s.length() > 0) { }   // safe: right side skipped
short sh = 3;
sh += 4.6;                    // sh = (short) (sh + 4.6)
String day = switch (i) {
    case 1, 7 -> "Weekend";
    default -> { yield "Weekday"; }
};
System.out.println(a + " " + b + " " + sh + " " + day);
```

```text output
5 7 7 Weekend
```

## Interview Qs

### What is the difference between & and &&?

For booleans both mean AND, but `&&` skips the right side when the left is false, while `&` always evaluates both. On integers `&` is bitwise AND.

### Switch statement vs switch expression?

A switch expression (Java 14) produces a value and must cover every case. A statement only runs code; with `case X:` labels it falls through unless you `break`.

### What happens if the switch value is null?

It throws `NullPointerException`. Since Java 21 a `case null` label handles it.
