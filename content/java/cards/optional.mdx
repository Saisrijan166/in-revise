## Why it exists

A `null` return looks like any other value, so callers forget to check it and get a `NullPointerException` later, far from the cause.

## How it works

| Step | Methods |
|---|---|
| Create | `Optional.of(v)`, `Optional.ofNullable(v)`, `Optional.empty()` |
| Transform (skipped when empty) | `map`, `flatMap`, `filter` |
| Get the value out | `orElse`, `orElseGet`, `orElseThrow()` (Java 10+), `ifPresentOrElse` (Java 9+) |
| Test | `isPresent()`, `isEmpty()` (Java 11+) |

- Test with `isEmpty()`, not `== Optional.empty()`: the empty instance is not promised to be a singleton.
- `map` wraps the result; use `flatMap` when the function already returns an Optional.

## Example

```java
Optional<User> findUser(String id) {
    return Optional.ofNullable(users.get(id));         // empty, never null
}

String city = findUser("42")
        .map(User::address)
        .map(Address::city)
        .orElse("unknown");

User u = findUser("7").orElseThrow(() -> new IllegalArgumentException("no user 7"));
```

## Interview Qs

### Why Optional if null already exists?

Null can mean "absent" too, but nothing forces a check. Optional puts absence in the method's type, so the caller has to decide what happens when there is no value.

### What is the difference between orElse and orElseGet?

`orElse` takes a value that is always computed; `orElseGet` takes a supplier that runs only when empty. See [orElse vs orElseGet](compare:orelse-vs-orelseget).

### Where should you not use Optional?

The API says it is mainly for return types. Avoid it as a field (it is not Serializable) or a parameter, and never return `null` from a method declared to return Optional.
