## What it is

`Optional<T>` is a small box that holds either one non-null value or nothing; a box with nothing is called empty. A method returns `Optional<Payment>` instead of `Payment` when it may have no result, such as `findById` for an id that does not exist. The return type then tells every caller "handle the empty case". Optional's methods take [lambdas](card:lambdas), so callers handle both cases without writing `if (x != null)`. You met it already: `findFirst` on a [stream](card:streams) returns one.

## Why it exists

When `findById` returns `null` for a missing payment, its signature looks exactly like one that never returns `null`. Callers forget to check, and a `NullPointerException` appears later, far from the cause. With `Optional<Payment>` the caller cannot call payment methods directly; they must unwrap the box and say what an empty result means: a default value, an exception, or nothing. Java 8 added Optional mainly for this purpose, as a method return type.

## How it works

<Mermaid
  alt="findById returns an Optional. If it holds a payment, map transforms the value and orElse returns it. If it is empty, map is skipped and orElse returns the fallback value."
  chart={`flowchart LR
  F["findById(id)"] --> O{"Optional"}
  O -- "has a payment" --> M["map(p -> ...)"] --> V(["the mapped value"])
  O -- "empty" --> E["map skipped"] --> D(["orElse fallback"])`}
/>

1. The method creates the Optional. `Optional.ofNullable(v)` gives an empty Optional when `v` is null; `Optional.of(v)` requires a non-null value; `Optional.empty()` says "no result" directly.
2. The caller transforms the value with `map`, `filter` or `flatMap`. Each one runs its lambda only when a value is present; on an empty Optional it returns empty and skips the lambda.
3. The caller ends the chain by deciding what empty means: `orElse(default)`, `orElseGet(supplier)`, `orElseThrow(...)` or `ifPresentOrElse(action, emptyAction)`.
4. Only at that last step does a plain value, or an exception, come out of the box.

## Example

A small payment store and a lookup that may find nothing.

```java
static Map<Long, Payment> store = Map.of(1L, new Payment(1, 80_000, Status.PAID));

static Optional<Payment> findById(long id) {
    return Optional.ofNullable(store.get(id));           // empty, never null
}

String s1 = findById(1).map(p -> p.status().name()).orElse("UNKNOWN");
String s2 = findById(9).map(p -> p.status().name()).orElse("UNKNOWN");
System.out.println(s1 + " " + s2);
findById(9).ifPresentOrElse(p -> System.out.println("found " + p.id()),
        () -> System.out.println("no payment 9"));
```

```text output
PAID UNKNOWN
no payment 9
```

What to notice:

- `store.get(9L)` returns null, and `ofNullable` turns that into an empty Optional, so `findById` never returns null.
- For id 9 the `map` lambda never runs; the empty Optional passes through and `orElse` supplies `"UNKNOWN"`.
- Replace `ofNullable` with `Optional.of` and `findById(9)` throws `NullPointerException`, because `of` does not accept null.
- When a missing payment is an error, `findById(9).orElseThrow(() -> new IllegalArgumentException("no payment 9"))` reports it at the right place.

## Rules and defaults

- **Versions:** `of`, `ofNullable`, `map`, `orElse`, `orElseGet` and `isPresent` came in Java 8; `ifPresentOrElse`, `or` and `stream()` in Java 9; `orElseThrow()` with no arguments in Java 10; `isEmpty()` in Java 11.
- **get():** returns the value or throws `NoSuchElementException`. The API names `orElseThrow()` as the preferred alternative: same behaviour, clearer name.
- **map returning null:** if the `map` function returns null, the result is an empty Optional, not an error.
- **Testing for empty:** use `isEmpty()` or `isPresent()`. Do not compare with `== Optional.empty()`, because the empty instance is not promised to be a single shared object.
- **Primitive versions:** `OptionalInt`, `OptionalLong` and `OptionalDouble`, which [number streams](card:primitive-streams) return.

## Not to be confused with

`orElse(value)` takes a ready value, and Java computes that value before the call, even when the Optional is not empty. `orElseGet(supplier)` takes a lambda that runs only when the Optional is empty. `map` wraps its result in an Optional; `flatMap` is for a function that already returns an Optional.

Rule: a constant default: `orElse`; a costly default, such as a database call: `orElseGet`.

## Interview Qs

### Why Optional if null already exists?

`null` can mean "absent" too, but nothing in the method's type says it might be null, and nothing forces a check. Optional puts absence into the return type, so the caller has to decide what happens when there is no value. It does not remove every `NullPointerException`; it makes this one case explicit.

### Where should you not use Optional?

The API says it is mainly for return types. Avoid it as a field, since it is not Serializable, and as a method parameter, where callers would have to wrap every argument. Never return `null` from a method declared to return Optional.

### When do you use flatMap on an Optional?

When the function you apply itself returns an Optional. If `Payment.refund()` returns `Optional<Refund>`, `findById(id).map(Payment::refund)` gives `Optional<Optional<Refund>>`. `flatMap(Payment::refund)` gives a plain `Optional<Refund>`, which is empty if either step finds nothing.
