## What it is

A data type tells Java what kind of value a variable holds and how much memory it takes. Java has eight primitive types, such as `int` for whole numbers and `double` for decimals, and a primitive variable holds the value itself. Every other type, such as `String`, is a reference type. An object is a bundle of data created while the program runs, and a reference variable holds only a reference to it, like an address, or `null`, which means "no object".

## Why it exists

Java checks types when it compiles. If you try to put text into an `int` variable, `javac` refuses, so the mistake never reaches a running payment service. Fixed sizes also make numbers fast and predictable: an `int` is 32 bits on every JVM. The price is a few rules you must know, about which conversions happen by themselves and what happens when a number does not fit.

## How it works

| Type | Bits | Holds | Default as a field |
|---|---|---|---|
| `byte`, `short`, `int`, `long` | 8, 16, 32, 64 | Whole numbers, signed | `0` |
| `float`, `double` | 32, 64 | Decimal numbers | `0.0` |
| `char` | 16 | One UTF-16 code unit, such as `'A'` | `'\u0000'` |
| `boolean` | not defined | `true` or `false` | `false` |
| any reference type | | A reference to an object | `null` |

1. A number written as `42` is an `int`, and `1.5` is a `double`. Add `L` for a `long` (`42L`) and `f` for a `float` (`1.5f`).
2. In arithmetic, `byte`, `short` and `char` are first promoted to `int`, and if one side is `long` or `double`, the other side is widened to match.
3. The result is then stored. Small to big (widening) happens by itself; big to small (narrowing) needs a cast, written `(int) x`.
4. If an `int` or `long` result does not fit, it wraps around silently. `10 / 0` with integers throws `ArithmeticException`, while `10.0 / 0` gives `Infinity` and `0.0 / 0` gives `NaN`.

## Example

The payment service counts money in paise. These lines show where the type rules bite:

```java
int a = 5 / 2;                       // both int: the fraction is dropped
double b = 5 / 2.0;                  // one side is double: 2.5
int big = Integer.MAX_VALUE + 1;     // too big for int: wraps silently
long paise = 1999;                   // widening int to long: automatic
int rupees = (int) 19.99;            // narrowing: cast needed, .99 is lost
var count = 3;                       // var: the compiler makes it an int
System.out.println(a + " " + b + " " + big + " " + rupees);
```

```text output
2 2.5 -2147483648 19
```

What to notice:

- `5 / 2` is 2 because both sides are `int`. Change one side to `2.0` and the whole division happens in `double`.
- `Integer.MAX_VALUE + 1` becomes the smallest `int`, with no error. That is why money totals use `long`.
- Remove the `(int)` cast and the line does not compile, because `double` to `int` can lose data.
- `count` is an `int` for ever; `count = "three";` would not compile.

## Rules and defaults

- **Defaults:** fields and array elements start at `0`, `0.0`, `false`, `'\u0000'` or `null`. Local variables, declared inside a method, get no default and must be assigned before use.
- **Widening can still lose digits:** `int` or `long` to `float`, and `long` to `double`, keep the size but may round the value.
- **var (Java 10):** allowed for local variables with an initial value, loop variables and, since Java 11, lambda parameters. `var x;` and `var x = null;` do not compile, and fields or method parameters cannot use it.
- **Overflow check:** `Math.addExact(a, b)` throws `ArithmeticException` instead of wrapping.
- **Casting objects:** converting between classes (upcasting and downcasting) is part of [polymorphism](card:polymorphism), later.

## Not to be confused with

A primitive such as `int` holds a plain number and can never be `null`. A wrapper such as `Integer` is an object that holds an `int` inside, so it can be `null` and can go into collections; you will meet it in [wrapper classes](card:wrapper-classes). Rule: primitive = the value itself; wrapper = an object around the value.

## Interview Qs

### What are the default values of variables in Java?

Fields and array elements get a default: `0` for whole numbers, `0.0` for decimals, `false`, `'\u0000'` or `null`. Local variables get none, and the compiler rejects any read before an assignment. This catches "forgot to initialise" bugs at compile time.

### Can you use var for fields or method parameters?

No. `var` works only where the compiler can see the value at once: local variables with an initial value, for-loop variables and, since Java 11, lambda parameters. It is a contextual keyword, not a reserved one, so a variable named `var` still compiles, and the type it infers never changes.

### What happens on integer overflow?

The value wraps silently: `Integer.MAX_VALUE + 1` is `Integer.MIN_VALUE`. Java throws no exception for normal arithmetic. Use a bigger type such as `long`, or `Math.addExact`, which throws `ArithmeticException` when the result does not fit.
