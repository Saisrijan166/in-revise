## Why it exists

Code must report problems it finds, and callers must know what may go wrong. Platform exceptions cannot name every business failure, so you write your own.

## How it works

<Compare id="throw-vs-throws" />

- An uncaught exception moves up the call stack to the nearest matching catch.
- The stack trace prints each wrapped cause as a `Caused by:` line.

## Example

```java
class PaymentException extends Exception {                    // checked
    PaymentException(String msg, Throwable cause) {
        super(msg, cause);                                    // keep the cause
    }
}
void pay(long amount) throws PaymentException {
    try { ledger.debit(amount); }
    catch (SQLException e) {
        throw new PaymentException("debit failed", e);         // chain it
    }
}
```

## Interview Qs

### Why do we need both throw and throws?

They do different jobs. throw is the action that raises one exception. throws is part of the method's contract, listing what may escape so callers can handle it; the compiler requires it for checked exceptions.

### When should you write a custom exception?

When no platform exception fits, or when callers need to tell your failures apart from others. Otherwise reuse standard ones such as IllegalArgumentException.

### What is exception chaining?

Wrapping a low-level exception as the cause of a higher-level one, through a constructor or initCause(). getCause() returns the original, so its stack trace is kept.
