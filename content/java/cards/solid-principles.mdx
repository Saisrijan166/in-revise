## Why it exists

Code that does many jobs, or depends on concrete classes, breaks in many places for one change. SOLID names five habits that keep changes local.

## How it works

| Letter | Rule | Smell it prevents (Java) |
|---|---|---|
| S | One reason to change | `UserService` that also builds emails and writes CSV |
| O | Add new code, do not edit old | a growing `switch (type)` in `PaymentService` |
| L | A subtype works where the parent is expected | an override that throws `UnsupportedOperationException` |
| I | Small, focused interfaces | `Worker` forcing `RobotWorker` to implement `eat()` |
| D | Depend on abstractions | `new MySqlRepo()` inside business code |

- O and D usually use the same tool: an interface plus [dependency injection](card:dependency-injection).
- SRP test: one reason to change = one group of people asking for changes.

## Example

```java
interface Notifier { void send(String msg); }       // D: the abstraction
class EmailNotifier implements Notifier { public void send(String m) { } }
class SmsNotifier implements Notifier { public void send(String m) { } }   // O: new class

class OrderService {                                 // S: only order logic
    private final Notifier notifier;
    OrderService(Notifier notifier) { this.notifier = notifier; }          // D: injected
    void place(String id) { notifier.send("Order " + id + " placed"); }
}
```

## Interview Qs

### Explain SOLID with one Java example.

An `OrderService` handles only orders (S). It talks to a `Notifier` interface (D). Adding SMS means a new `SmsNotifier` class, not editing `OrderService` (O). Any `Notifier` must behave like one (L), and `Notifier` has one method (I).

### Give a Liskov violation.

`Square extends Rectangle`: `setWidth` must also change the height, so code that sets width 5 and height 4 expects area 20 but gets 16. Fix: no inheritance between them, or make both immutable shapes.

### How do open-closed and dependency inversion relate?

Depending on an interface (D) gives open-closed (O): new behaviour is a new implementation passed in, with no edit to the caller.
