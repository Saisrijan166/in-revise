## Why it exists

Sorting and sorted collections must know which of two objects comes first. One class often needs several orders: students by roll number, by name, by marks.

## How it works

<Compare id="comparable-vs-comparator" />

- `Collections.sort(list)` and `new TreeSet<>()` use the natural order; pass a Comparator to choose another.
- BigDecimal breaks the equals rule: `compareTo` treats 4.0 and 4.00 as equal, `equals` does not.

## Example

```java
record Student(String name, int marks) implements Comparable<Student> {
    public int compareTo(Student o) { return Integer.compare(marks, o.marks); }
}

List<Student> list = new ArrayList<>(List.of(new Student("Ravi", 80), new Student("Asha", 92)));
Collections.sort(list);                                  // natural order: by marks
list.sort(Comparator.comparing(Student::name));          // custom: by name
list.sort(Comparator.comparingInt(Student::marks).reversed()
        .thenComparing(Student::name));                  // marks high to low, then name
```

## Interview Qs

### Why do we need both Comparable and Comparator?

A class has one `compareTo`, but you may need many orders, or need to sort a class you cannot edit. Comparable gives the default order; Comparators give the rest.

### What does "consistent with equals" mean?

`compareTo` returns 0 exactly when `equals` returns true. If not, a TreeSet or TreeMap breaks the Set or Map contract, for example by treating two unequal items as duplicates.

### How do you sort by two fields?

Chain them: `Comparator.comparing(Employee::dept).thenComparing(Employee::salary)`. Add `.reversed()` for descending order.
