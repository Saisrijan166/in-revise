## What it is

A `Queue` holds items waiting to be processed and hands them out in a fixed order. The front is called the head and the back the tail. Most queues are FIFO, first in, first out, like a ticket line. A `Deque` (double-ended queue, said "deck") lets you add and remove at both ends, so it can also act as a stack, which is LIFO, last in, first out. `PriorityQueue` is a queue whose head is always the smallest item.

## Why it exists

Much work must happen in a set order. Failed payments should be retried in the order they failed; an "undo" button must undo the latest action first; an urgent refund should jump ahead of small ones. With a plain `List` you would track positions by hand, and `list.remove(0)` on an `ArrayList` shifts every item. Queue classes make each of these orders a single method call.

## How it works

| Action | Throws an exception on failure | Returns false or null on failure |
|---|---|---|
| Add at the tail | `add(e)` | `offer(e)` |
| Remove the head | `remove()` | `poll()` |
| Look at the head | `element()` | `peek()` |

A retry queue of failed payments, step by step:

1. `offer("p1")`, then `offer("p2")`, add both at the tail; p1 is now the head.
2. `peek()` returns p1 but leaves it in the queue.
3. `poll()` removes p1 and returns it; p2 becomes the head.
4. When the queue is empty, `poll()` and `peek()` return `null`, while `remove()` and `element()` throw `NoSuchElementException`.

As a stack, a Deque's `push(e)`, `pop()` and `peek()` all work on the front, so the item pushed last comes out first. A `PriorityQueue` keeps a heap: a tree stored in an array where each parent is no larger than its children, so the smallest item is always at the top.

## Example

One `ArrayDeque` works as a retry queue, another as an undo stack, and a `PriorityQueue` with a Comparator serves the largest payment first.

```java
Queue<String> retries = new ArrayDeque<>();      // FIFO: first failed, first retried
retries.offer("p1");
retries.offer("p2");
System.out.println(retries.poll() + " " + retries.peek());   // p1 leaves; p2 is the head

Deque<String> undo = new ArrayDeque<>();         // used as a stack: LIFO
undo.push("create p3");
undo.push("refund p3");
System.out.println(undo.pop());                  // the last action pushed comes out first

Queue<Payment> biggest = new PriorityQueue<>(Comparator.comparingLong(Payment::amount).reversed());
biggest.offer(new Payment("p4", 300, Status.PENDING));
biggest.offer(new Payment("p5", 900, Status.PENDING));
System.out.println(biggest.poll().id());         // largest amount first
```

```text output
p1 p2
refund p3
p5
```

What to notice:

- The same class, `ArrayDeque`, gives FIFO through the `Queue` methods and LIFO through `push` and `pop`. The variable's type shows which way you use it.
- Without the Comparator, the `PriorityQueue` would need `Payment` to be `Comparable`, and it would return the smallest item first.
- `.reversed()` flips "smallest first" into "largest first", so this queue is a max-heap.

## Rules and defaults

- **null:** `ArrayDeque` and `PriorityQueue` reject `null` with `NullPointerException`. `LinkedList`, which is also a `Deque`, accepts it, but then `poll()` returning `null` becomes ambiguous.
- **Ties:** if several items in a `PriorityQueue` are equally small, which one comes out first is not defined.
- **Ordered view:** to see a `PriorityQueue` in order without emptying it, sort a copy, for example `Arrays.sort(pq.toArray())`.
- **Speed:** the Javadoc says `ArrayDeque` is likely faster than `Stack` as a stack and faster than `LinkedList` as a queue.
- **Threads:** none of these classes is thread-safe. Queues shared between threads are `BlockingQueue` types, covered in [concurrent collections](card:concurrent-collections).

## Not to be confused with

A queue gives back the oldest item first (FIFO); a stack gives back the newest item first (LIFO). `peek()` only looks at the next item; `poll()` and `pop()` also remove it. `push` adds at the front of a Deque; `offer` adds at the back. Rule: line of people = queue with `offer` and `poll`; pile of plates = stack with `push` and `pop`.

## Interview Qs

### Why ArrayDeque if Stack already exists?

`Stack` is a legacy class from Java 1.0 that extends `Vector`. Every call pays for synchronisation, and it inherits list methods such as `get(i)` and `add(i, e)` that let code break the LIFO rule. The `Deque` Javadoc recommends using a Deque instead, and `ArrayDeque` is likely faster.

### offer() vs add()?

Both insert at the tail. On a queue with a capacity limit that is full, `add` throws `IllegalStateException` while `offer` returns `false`. On queues with no limit, such as `ArrayDeque` and `PriorityQueue`, they behave the same.

### PriorityQueue vs TreeSet?

Both order items. `PriorityQueue` keeps duplicates and only promises cheap access to the smallest item. `TreeSet` drops items that compare as equal, keeps everything sorted and lets you iterate in order. Use `PriorityQueue` for "what is next?", `TreeSet` for a sorted set of unique items.
