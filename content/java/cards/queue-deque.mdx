## Why it exists

Many tasks need a set order of work: first come, first served (jobs, BFS), last in, first out (undo, bracket matching), or most urgent first (schedulers).

## How it works

| Queue method | Throws an exception | Returns false or null |
|---|---|---|
| Insert at tail | `add(e)` | `offer(e)` |
| Remove head | `remove()` | `poll()` |
| Look at head | `element()` | `peek()` |

- As a stack, a Deque's `push`, `pop` and `peek` act on the front, like `addFirst`, `removeFirst`, `peekFirst`.
- For a max-heap, pass a comparator: `new PriorityQueue<>(Comparator.reverseOrder())`.
- Queues shared by threads are [BlockingQueue](card:concurrent-collections) types.

## Example

```java
Deque<Character> stack = new ArrayDeque<>();
stack.push('(');
stack.push('[');
System.out.println(stack.pop());     // last in, first out

Queue<Integer> pq = new PriorityQueue<>(List.of(5, 1, 3));
System.out.println(pq.poll());       // smallest first
Queue<Integer> maxFirst = new PriorityQueue<>(Comparator.reverseOrder());
```

```text output
[
1
```

## Interview Qs

### Why ArrayDeque when Stack already exists?

Stack extends Vector, so it pays for synchronisation and inherits index methods like `get(i)` that ignore LIFO. The Deque docs recommend Deque instead, and ArrayDeque is likely faster as a stack.

### offer() vs add()?

Both insert. On a full capacity-limited queue, `add` throws IllegalStateException and `offer` returns false. For unbounded queues like ArrayDeque they behave the same.

### PriorityQueue vs TreeSet?

PriorityQueue keeps duplicates and only promises cheap access to the head. TreeSet drops duplicates and iterates in sorted order. Use PriorityQueue for "next most urgent", TreeSet for a sorted unique set.
