## What it is

Collection programs are coding questions where the hard part is choosing where to keep the state. A Map counts how often each item appears. A Deque used as a stack remembers the last thing opened. A `PriorityQueue` is a heap: whatever you add, it always hands back the smallest element first. A Comparator sets the order for sorting. Each collection was introduced earlier; here you use them to solve problems.

## Why it exists

Once loops are easy, the question becomes which collection holds the state, and picking it fast is half the answer. The wrong choice costs time or correctness. Counting with two nested loops is O(n²) where a Map is O(n). Sorting everything to find the top 3 does more work than a small heap. A HashMap prints keys in no fixed order when the question wants them sorted.

## How it works

| Problem | Collection and trick |
|---|---|
| List CRUD | `add`, `get(i)`, `set(i, v)`, `remove(i)`: see [List](card:list-arraylist) |
| Unique values, duplicates | a Set: see [array duplicates](card:array-programs) |
| How many of each | a Map: key = item, value = count |
| Sorted unique values, sorted keys | `TreeSet`, `TreeMap` |
| First in, first out | `Queue` with `offer`, `poll`, `peek`: see [Queue](card:queue-deque) |
| Last in, first out | `ArrayDeque` with `push`, `pop` |
| Top k, kth largest | `PriorityQueue` |

1. Say the question type in plain words: "how many of each", "the last one opened closes first", "the k biggest".
2. Pick the collection from the table.
3. Declare it with the interface type on the left: `Map<Character, Integer> freq = new TreeMap<>();`.
4. Update it once per element in a single loop.
5. Read the answer at the end: loop over `entrySet()`, check `isEmpty()`, or `peek()` at the head.

## Example

The frequency map is the most reused pattern in coding rounds.

```java
String s = "banana";
Map<Character, Integer> freq = new TreeMap<>();       // sorted keys
for (char c : s.toCharArray()) {
    freq.put(c, freq.getOrDefault(c, 0) + 1);         // or freq.merge(c, 1, Integer::sum)
}
for (Map.Entry<Character, Integer> e : freq.entrySet()) {
    System.out.println(e.getKey() + "=" + e.getValue());
}
```

```text output
a=3
b=1
n=2
```

What to notice: `getOrDefault(c, 0)` gives 0 for a char seen for the first time. The TreeMap is what makes the output order a, b, n; a HashMap promises no order.

A Comparator sorts by one rule, then breaks ties with another.

```java
List<String> names = new ArrayList<>(List.of("Ravi", "Bob", "Asha", "Al"));
names.sort(Comparator.comparingInt(String::length)
        .thenComparing(Comparator.naturalOrder()));      // by length, then A to Z
System.out.println(names);
names.sort(Comparator.reverseOrder());                    // Z to A
System.out.println(names);
```

```text output
[Al, Bob, Asha, Ravi]
[Ravi, Bob, Asha, Al]
```

What to notice: Asha and Ravi both have 4 letters, so `thenComparing` decides. The list is copied into an `ArrayList` because `List.of` cannot be sorted in place.

Balanced brackets use a Deque as a stack.

```java
static boolean balanced(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if ("([{".indexOf(c) >= 0) stack.push(c);              // opener: push
        else if (stack.isEmpty()
                || "([{".indexOf(stack.pop()) != ")]}".indexOf(c)) return false;
    }
    return stack.isEmpty();                                    // nothing left open
}
System.out.println(balanced("{[()]}") + " " + balanced("([)]") + " " + balanced("(("));
```

```text output
true false false
```

What to notice: an opener and its closer sit at the same position in `"([{"` and `")]}"`, so equal indexes mean a match. The `isEmpty()` check before `pop` handles a closer with nothing open.

A min-heap of size 3 keeps the three largest values.

```java
int[] nums = {5, 1, 9, 3, 7};
PriorityQueue<Integer> heap = new PriorityQueue<>();   // min-heap of the 3 largest
for (int n : nums) {
    heap.offer(n);
    if (heap.size() > 3) heap.poll();                  // drop the smallest
}
System.out.println(heap.peek() + " " + new TreeSet<>(heap));
```

```text output
5 [5, 7, 9]
```

What to notice: each `poll` removes the smallest of the four, so the three largest stay. The head, 5, is the 3rd largest. The heap is copied into a TreeSet only to print it sorted.

## Rules and defaults

- **Missing key:** `get` returns `null`; `getOrDefault` and `merge` (both Java 8) avoid it.
- **PriorityQueue order:** the head is the smallest element by natural order; pass `Comparator.reverseOrder()` for a max-heap. Printing it does not show sorted order; see [Queue, Deque and Stack](card:queue-deque).
- **Stack:** use `ArrayDeque` through the `Deque` interface; why not the old `Stack` class is in [Queue, Deque and Stack](card:queue-deque).

## Interview Qs

### How do you find the most frequent element?

Build the frequency map, then take the entry with the largest value: `Collections.max(freq.entrySet(), Map.Entry.comparingByValue()).getKey()`. One pass to count, one to find the maximum: O(n).

### How do you find the kth largest element?

Keep a min-heap of size k: offer each value, and poll when the size passes k. The head is the kth largest. That takes O(n log k) time, less than sorting everything in O(n log n).
