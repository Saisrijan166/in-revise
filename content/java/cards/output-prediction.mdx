## What it is

Output prediction questions show a short piece of code and ask "what does this print?". You answer by tracing: running the code in your head one line at a time while keeping a table with one column per variable. Each question is built around a rule taught earlier, such as `x++`, pass-by-value or `==` on wrapper objects, and the code is written so that a quick guess gives the wrong answer.

## Why it exists

Interviewers use these questions to check that you know how Java really evaluates code, not how it looks at a glance. A few traps come back again and again, and each one fools a fast reader. Tracing slowly, with every value written down, turns a guess into a short calculation and lets you explain each line aloud, which is what the interviewer wants to hear.

## How it works

| Trap | Rule lives in |
|---|---|
| `x++` or `++x` inside an expression | [operators](card:operators-control-flow) |
| A method changes its parameters | [pass-by-value](card:pass-by-value) |
| `null`, `"Java".equals(name)` | [strings](card:strings), [NullPointerException](term:null-pointer-exception) |
| `==` on `Integer`, autoboxing | [wrapper classes](card:wrapper-classes) |
| A stream pipeline | [streams](card:streams) |

1. Draw a table with one column per variable and fill in the starting values.
2. Read one line. Evaluate an expression from left to right, and note when `x++` or `++x` changes a variable.
3. Update the table, then write down anything the line prints.
4. At a method call, give the method copies of the values; follow an array or object through its reference.
5. For a stream, write the values left after each step, then apply the terminal step.

## Example

Increments: the order of reading and changing `x` decides the output.

```java
int x = 5;
if (x++ > 5) System.out.println("A");
else System.out.println("B");
System.out.println(x);
System.out.println(x++ + ++x);
System.out.println(x);
```

```text output
B
6
14
8
```

What to notice: the test compares the old value 5 with 5, so it prints B, and x is 6 afterwards. In `x++ + ++x` the left side yields 6 and makes x 7, then `++x` makes it 8.

Method calls: Java passes copies, but a copied reference still points to the same object.

```java
static void change(int n, int[] arr, StringBuilder sb, String s) {
    n = 99;
    arr[0] = 99;
    sb.append("!");
    s = s + "!";
}
int n = 1;
int[] arr = {1};
StringBuilder sb = new StringBuilder("hi");
String s = "hi";
change(n, arr, sb, s);
System.out.println(n + " " + arr[0] + " " + sb + " " + s);
```

```text output
1 99 hi! hi
```

What to notice: `arr[0] = 99` and `sb.append` change the objects the caller also sees. `n = 99` and `s = s + "!"` only change the method's own copies.

Null: a null reference can be compared and joined to text, but not used.

```java
String name = null;
System.out.println("Java".equals(name));
System.out.println(name + "!");
try {
    System.out.println(name.length());
} catch (NullPointerException e) {
    System.out.println("NullPointerException");
}
```

```text output
false
null!
NullPointerException
```

What to notice: `"Java".equals(name)` is safe because the method runs on the literal. `name.equals("Java")` would throw, like `name.length()`.

Wrappers: `==` and `equals` behave differently on boxed numbers.

```java
Integer a = 1000, b = 1000;
int c = 1000;
Long big = 1000L;
System.out.println(a == b);
System.out.println(a == c);
System.out.println(a.equals(c));
System.out.println(big.equals(1000));
```

```text output
false
true
true
false
```

What to notice: `a == b` compares two objects, while `a == c` unboxes `a` because `c` is an `int`. The last line boxes 1000 to an `Integer`, which a `Long` never equals; `big.equals(1000L)` is true.

Streams: write the values after each step.

```java
List<Integer> result = List.of(1, 2, 3, 4, 5).stream()
        .filter(n -> n % 2 != 0)        // 1 3 5
        .map(n -> n * 10)               // 10 30 50
        .filter(n -> n > 20)            // 30 50
        .toList();
System.out.println(result);
```

```text output
[30, 50]
```

What to notice: the comments are the trace table for a stream. Each line works on what the line above left.

## Rules and defaults

- **Evaluation order:** Java evaluates the left operand of an operator fully before the right one (JLS 15.7).
- **Assignment runs last:** in `x = x++`, the old value is stored back, so x does not change.

## Interview Qs

### Why does x++ + ++x give 14 when x is 6?

Operands are evaluated left to right. `x++` yields 6 and makes x 7; `++x` makes x 8 and yields 8. 6 + 8 is 14, and x ends at 8.

### Why does name + "!" print null! instead of throwing?

String concatenation converts a null reference to the text `"null"`. Only calling a method on it, like `name.length()`, throws NullPointerException.
