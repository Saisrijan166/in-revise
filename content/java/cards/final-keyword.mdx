## What it is

`final` is a keyword that forbids change after a certain point, and it means something slightly different in each place. On a variable or field, it allows only one assignment. On a method, it stops subclasses from replacing the method. On a class, it stops any class from extending it. The compiler enforces all three, so breaking the rule is a compile error, not a run-time surprise.

## Why it exists

A payment's id should never change after the payment is created, but a plain field can be reassigned by any method, by mistake. Some logic, such as a security check, must not be replaced by a subclass, and some classes, such as `String`, must not be extended at all. Without `final` these are only comments that someone can ignore; with it, the compiler refuses the code.

## How it works

| Where | What final stops | Typical use |
|---|---|---|
| Local variable or field | a second assignment | ids, constants, settings fixed at startup |
| Method | overriding in a subclass | logic a subclass must not change |
| Class | any subclass | value classes such as `String` |

1. When you declare `final long id;` without a value, the compiler checks that every constructor assigns `id` exactly once.
2. Any later assignment, such as `id = 2;`, is rejected at compile time.
3. For a final reference, only the variable is fixed. Calls that change the object it points to, such as `log.append(...)`, are allowed.
4. For a final method or class, the compiler rejects any subclass that tries to override the method or extend the class.

## Example

The payment's id and log are final, and a constant sets the maximum amount.

```java
class Payment {
    static final long MAX_PAISE = 10_000_000;     // constant: Rs 1 lakh
    final long id;                                // blank final: set once below
    final StringBuilder log = new StringBuilder();

    Payment(long id) { this.id = id; }            // the one assignment of id
    void markPaid() {
        log.append("PAID");                       // fine: the object changes
        // log = new StringBuilder();             // error: cannot assign final log
        // id = 2;                                // error: cannot assign final id
    }
}
Payment p = new Payment(1);
p.markPaid();
System.out.println(p.id + " " + p.log + " " + Payment.MAX_PAISE);
```

```text output
1 PAID 10000000
```

What to notice:

- `id` has no value in its declaration, so the constructor must set it. Add a second constructor that does not set it, and the class stops compiling.
- `log.append("PAID")` is allowed because it changes the `StringBuilder`, not the variable `log`.
- `MAX_PAISE` is `static final`: one copy for the class, and it never changes. Constants are written in capitals by convention.

## Rules and defaults

- **Blank final fields:** an instance field must be assigned by the end of every constructor (an instance block also counts); a static final field, in its declaration or a static block.
- **Final methods:** cannot be overridden, and a static final method cannot be hidden. Private methods and all methods of a final class behave as final already.
- **Effectively final:** a local variable that is never reassigned counts as effectively final even without the keyword; you will see why this matters in [lambdas](card:lambdas).
- **Parameters:** a parameter can be final too, which stops the method from reassigning it.

## Not to be confused with

`final` is a modifier that stops reassignment, overriding or subclassing. `finally` is a block after `try` that runs however the `try` ends; you will see it in [try-catch-finally](card:try-catch-finally). `finalize()` is an old `Object` method meant for clean-up before the JVM frees an unused object, deprecated for removal since Java 18. Rule: final restricts, finally cleans up, finalize is not used. Making a whole object unchangeable needs more than `final`: see [immutable classes](card:immutability).

## Interview Qs

### Can a final field be set in the constructor?

Yes. A final field declared without a value is a blank final. It must be assigned exactly once by the end of every constructor (an instance initialiser block also counts), or the code does not compile.

### Does final make an object immutable?

No. It fixes the reference, not the object. A `final List` cannot be pointed at another list, but you can still add to it. An immutable class needs private final fields, no setters, and copies of any mutable objects it holds.

### Why final if other languages have const?

Java reserves `const` as a keyword but never uses it. `final` covers three cases with one word: no reassignment, no overriding and no subclassing.
