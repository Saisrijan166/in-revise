## Why it exists

Some things must not change after they are set: a constant, a security check inside a method, or a class like String. final lets the compiler enforce that.

## How it works

| Where | Means | Typical use |
|---|---|---|
| Variable | one assignment only | constants, fixed settings |
| Method | no override | logic a subclass must not change |
| Class | no subclass | [immutable classes](card:immutability) such as String |

- Capturing locals in lambdas: [lambdas](card:lambdas).

## Example

```java
final List<String> names = new ArrayList<>();
names.add("Asha");             // fine: the list changes
// names = new ArrayList<>();  // compile error: reassignment

class Config {
    private final String url;  // blank final
    Config(String url) { this.url = url; }   // must be set here
}
final class Money { }          // class Cash extends Money: error
```

## Interview Qs

### Can a final field be set in the constructor?

Yes. A final field declared without a value is a blank final; every constructor must assign it exactly once, or the code does not compile.

### Why final if other languages have const?

Java reserves const but never uses it. final covers three cases with one word: no reassignment, no override and no subclass.
