## Why it exists

Related classes share code and one common type. Allowing a single parent keeps this simple; composition covers reuse when the link is not a true is-a.

## How it works

<Compare id="inheritance-vs-composition" />

- A method inherited from a superclass wins over an interface default with the same signature.
- JDK lesson: `Provider` inherits from `Hashtable`, so its data and checks sit in different classes; holding a map avoids that.

## Example

```java
interface Camera { default String name() { return "camera"; } }
interface Phone  { default String name() { return "phone"; } }

class SmartPhone implements Camera, Phone {
    @Override public String name() {      // required: two defaults clash
        return Phone.super.name();        // pick one parent's version
    }
}
class Car {                               // composition: Car has-a Engine
    private final Engine engine = new Engine();
    void start() { engine.start(); }      // delegate
}
```

## Interview Qs

### Why does Java not allow multiple class inheritance?

To avoid inheriting clashing fields and method bodies from two parents, the diamond problem. Interfaces carry no instance state, so a class may implement many; clashing default methods must be overridden.

### When do you prefer composition over inheritance?

When the link is has-a, or when you need behaviour from a class you do not control. Composition hides the helper behind your own methods, so its changes cannot leak into your API.

### Association vs aggregation vs composition?

All are has-a links. Association: objects use each other. Aggregation: a looser whole-part link whose parts are not deleted with the whole. Composition: the whole owns its parts, which are deleted with it.
