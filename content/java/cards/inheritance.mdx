## What it is

Inheritance means one class is built on another with `extends`: `class CardPayment extends Payment` makes `CardPayment` the child class (subclass) and `Payment` the parent class (superclass). The child gets the parent's fields and methods, can add its own, and can replace methods by overriding them. This is an is-a link: a card payment is a payment. Composition is the alternative, a has-a link: a class keeps another object in a field and calls its methods.

## Why it exists

Card, UPI and net-banking payments all have an id, an amount and a `describe()` method. Copying that code into three classes means fixing every bug three times. Inheritance writes it once in `Payment`, and each child adds only what is different. It also gives one common type, so a method that takes a `Payment` accepts all three. When the link is not a real is-a, such as a service that uses a gateway, composition reuses the code without tying the two classes together.

## How it works

1. You declare `class CardPayment extends Payment`. A class may name only one parent; one that names none extends `Object`.
2. When you create a `CardPayment`, its constructor first runs the parent's constructor through `super(...)`, as [this and super](card:this-super) showed.
3. A call such as `card.describe()` uses the child's own method if it has one, otherwise the method inherited from `Payment`.
4. With composition, `PaymentService` holds a `Gateway` in a private field and forwards work to it, so it uses only the gateway's public methods.

## Example

`CardPayment` inherits from `Payment`, and `PaymentService` uses a `Gateway` by composition.

```java
class Payment {
    protected long amount;
    Payment(long amount) { this.amount = amount; }
    String describe() { return amount + " paise"; }
}
class CardPayment extends Payment {          // is-a: a card payment is a payment
    CardPayment(long amount) { super(amount); }   // constructors are not inherited
}
class Gateway { String charge(String what) { return "charged " + what; } }
class PaymentService {                       // has-a: holds a gateway
    private final Gateway gateway = new Gateway();
    String pay(Payment p) { return gateway.charge(p.describe()); }   // delegate
}
System.out.println(new PaymentService().pay(new CardPayment(50000)));
```

```text output
charged 50000 paise
```

An interface lists methods a class promises to have and may give a default body ([abstract classes and interfaces](card:abstract-classes-interfaces) covers them). Two defaults with one signature clash:

```java
interface Refundable { default String info() { return "refundable"; } }
interface Trackable  { default String info() { return "trackable"; } }

class UpiPayment implements Refundable, Trackable {
    @Override public String info() {           // required: two defaults clash
        return Trackable.super.info();         // reuse one interface's version
    }
}
System.out.println(new UpiPayment().info());
```

```text output
trackable
```

What to notice:

- `CardPayment` has no `describe()` of its own, yet the call works: it inherited the method from `Payment`.
- `pay(Payment p)` accepted a `CardPayment`, because a child object can be used wherever its parent type is expected.
- Remove the `info()` override from `UpiPayment` and it does not compile: Java refuses to pick between two inherited defaults. This is the diamond problem.

## Rules and defaults

- **One parent class:** `extends` names exactly one class; `Object` is the default.
- **Class wins:** if a parent class and an interface both supply `info()`, the parent class's method is used and there is no clash.
- **Not inherited:** constructors and private members. Private fields still exist inside the child object, but only the parent's code can use them.
- **final classes:** a class declared `final`, such as `String`, cannot be extended, as [final](card:final-keyword) showed.

## Not to be confused with

Inheritance is an is-a link fixed in the code with `extends`: the child depends on the parent's inner workings. Composition is a has-a link through a field: the class depends only on the helper's public methods, and the helper can be swapped. Rule: extend only for a true is-a that you control; otherwise hold the object and delegate.

## Common mistakes

- **"Extending a library class is safe if I override the methods I care about."** The parent can add methods later. In JDK 1.2, `Hashtable` gained `entrySet()`; `java.security.Provider`, which extends it through `Properties`, did not override it, so callers could remove entries without the security checks in `Provider.remove`.

## Interview Qs

### Why does Java not allow multiple class inheritance?

To avoid inheriting clashing fields and method bodies from two parents, the diamond problem. Interfaces carry no instance fields, so a class may implement many; if two interfaces give the same default method, the class must override it and can pick one with `Name.super.method()`.

### When do you prefer composition over inheritance?

When the link is has-a, or when you need behaviour from a class you do not control. Composition hides the helper behind your own methods, so the helper's changes cannot leak into your API, and you can swap it for another implementation or a test fake.

### Association vs aggregation vs composition?

All are has-a links. Association: objects use each other, such as a teacher and a student. Aggregation: a looser whole-part link where the parts can exist alone, such as a department and its teachers. Composition: the whole owns its parts, which are deleted with it, such as a house and its rooms.
