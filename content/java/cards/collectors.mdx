## What it is

A collector is a recipe that tells `collect(...)` how to gather a [stream's](card:streams) elements into one result: a list, a set, a map or a String. The `Collectors` class holds ready-made recipes: `toList()`, `toSet()`, `toMap(...)`, `groupingBy(...)`, `partitioningBy(...)` and `joining(...)`. Some recipes take a second collector, called a downstream collector, which decides what each group keeps: the elements, a count, a total or one field.

## Why it exists

Without collectors, "count payments per status" means a new [HashMap](card:map-hashmap), a loop and a `merge` or `getOrDefault` call for each payment. It is easy to get wrong and hides the intent. `groupingBy(Payment::status, counting())` states the shape of the result in one line, and the library builds the map. Most stream answers in interviews end in exactly such a list, map or String.

## How it works

| I want | Write inside `collect(...)` | Result |
|---|---|---|
| A list or set | `toList()`, `toSet()` | `List<T>`, `Set<T>` |
| Unique, in first-seen order | `toCollection(LinkedHashSet::new)` | `LinkedHashSet<T>` |
| Key to value | `toMap(Payment::id, Payment::status)` | `Map<K, V>` |
| Groups | `groupingBy(Payment::status)` | `Map<K, List<T>>` |
| Count per group | `groupingBy(Payment::status, counting())` | `Map<K, Long>` |
| Total or average per group | `summingLong(...)`, `averagingLong(...)` as the second argument | `Map<K, Long>`, `Map<K, Double>` |
| One field per group | `groupingBy(Payment::status, mapping(Payment::id, toList()))` | `Map<K, List<Long>>` |
| Two groups by a test | `partitioningBy(p -> p.amountPaise() >= 50_000)` | `Map<Boolean, List<T>>` |
| One String | `joining(", ", "[", "]")` | `String` |

Follow `groupingBy(Payment::status, counting())`:

1. The terminal operation `collect` starts the stream and hands each payment to the collector.
2. `groupingBy` calls the key function, `Payment::status`, on the payment and gets its key, for example `PAID`.
3. It finds the group for that key, or creates it the first time the key appears.
4. The downstream collector, `counting()`, receives the payment as part of that group, so each group ends as a `Long` count instead of a list.
5. When the stream ends, `collect` returns the finished map, with `PAID` mapped to 2 and `FAILED` to 1.

## Example

Four common results from one list of payments.

```java
List<Payment> payments = List.of(new Payment(1, 80_000, Status.PAID),
        new Payment(2, 20_000, Status.PAID), new Payment(3, 90_000, Status.FAILED));
Map<Status, Long> countByStatus = payments.stream()
        .collect(Collectors.groupingBy(Payment::status, Collectors.counting()));
Map<Status, Long> totalByStatus = payments.stream().collect(Collectors.groupingBy(
        Payment::status, TreeMap::new, Collectors.summingLong(Payment::amountPaise)));
Map<Boolean, List<Long>> large = payments.stream().collect(Collectors.partitioningBy(
        p -> p.amountPaise() >= 50_000, Collectors.mapping(Payment::id, Collectors.toList())));
String ids = payments.stream().map(p -> "#" + p.id()).collect(Collectors.joining(", "));
System.out.println(countByStatus.get(Status.PAID) + " " + totalByStatus);
System.out.println(large + " " + ids);
```

```text output
2 {PAID=100000, FAILED=90000}
{false=[2], true=[1, 3]} #1, #2, #3
```

What to notice:

- `counting()` produces a `Long`, so the map is `Map<Status, Long>`, not `Map<Status, Integer>`.
- `TreeMap::new` is a map factory: the keys come out sorted, and enum keys sort in declaration order (`PENDING, PAID, FAILED`). Without it, the map type and order are not promised; the same plain `groupingBy` printed its keys in a different order on Java 21 and Java 25.
- `mapping(Payment::id, toList())` keeps only each payment's id in its group, not the whole payment.
- `joining` accepts only text, so `map` turns each payment into a String first.

## Rules and defaults

- **toMap with duplicates:** `toMap(key, value)` throws `IllegalStateException` when two elements give the same key. A third argument, the merge function, combines them: `(a, b) -> a` keeps the first, `Long::sum` adds. A fourth argument picks the map, such as `LinkedHashMap::new`.
- **No promises on the result:** plain `groupingBy`, `toMap` and `Collectors.toList()` promise nothing about the type, mutability or thread-safety of what they return. Ask for a type with a factory such as `TreeMap::new` or `toCollection(ArrayList::new)`.
- **Empty groups:** `groupingBy` has no entry for a key that never occurs. `partitioningBy` always has both keys, with an empty list or a zero count when nothing matches.
- **Empty input:** `counting()` and `summingLong` give 0, and `averagingInt` gives 0.0.
- **Nesting:** downstream collectors nest: `groupingBy(Payment::status, mapping(Payment::id, toList()))`.

## Not to be confused with

`groupingBy` makes one group for each key value that occurs. `partitioningBy` makes exactly two groups, true and false, from a test. `stream.toList()` (Java 16) returns an unmodifiable list; `collect(Collectors.toList())` (Java 8) promises nothing about whether you can change the list.

Rule: many keys: `groupingBy`; yes or no: `partitioningBy`. Read-only list: `toList()`; a list you will change: `toCollection(ArrayList::new)`.

## Interview Qs

### What happens when toMap meets a duplicate key?

It throws `IllegalStateException`, with a message naming the key. Pass a merge function as the third argument: `(a, b) -> a` keeps the first value, `Long::sum` adds them. If you need all the values per key, `groupingBy` with `mapping` is the right tool instead.

### What is a downstream collector?

The collector that `groupingBy` or `partitioningBy` runs on each group. Without one, each group is a list of its elements. With `counting()`, `summingLong`, `mapping` or `maxBy`, each group becomes a count, a total, a list of one field, or its top element.

### How do you keep the groups sorted by key?

Pass a map factory as the middle argument: `groupingBy(Payment::status, TreeMap::new, toList())`. The plain form promises nothing about the map's type or order, so the order you see in a test can change between JDK versions.
