## Why it exists

Most stream answers end in a collection, a map or a String. Collectors are ready-made recipes, so you never fill a map by hand.

## How it works

| I want | Write inside `collect(...)` | Result |
|---|---|---|
| A list or set | `toList()`, `toSet()` | `List<T>`, `Set<T>` |
| Unique, in first-seen order | `toCollection(LinkedHashSet::new)` | `LinkedHashSet<T>` |
| Key to value | `toMap(Emp::id, Emp::name)` | `Map<K, V>` |
| Groups | `groupingBy(Emp::dept)` | `Map<K, List<T>>` |
| Count per group | `groupingBy(Emp::dept, counting())` | `Map<K, Long>` |
| Total or average per group | `summingInt(Emp::salary)`, `averagingInt(...)` as the second argument | `Map<K, Integer>`, `Map<K, Double>` |
| One field per group | `groupingBy(Emp::dept, mapping(Emp::name, toList()))` | `Map<K, List<String>>` |
| Two groups by a test | `partitioningBy(e -> e.salary() > 50_000)` | `Map<Boolean, List<T>>` |
| One String | `joining(", ", "[", "]")` | `String` |

- The second argument of `groupingBy` and `partitioningBy` is a downstream collector, run on each group. They nest: `mapping(Emp::name, joining(", "))`.

## Example

```java
record Emp(String name, String dept, int salary) {}
List<Emp> emps = List.of(new Emp("Asha", "IT", 90), new Emp("Ravi", "IT", 70),
        new Emp("Neha", "HR", 60));
Map<String, Long> count = emps.stream()
        .collect(Collectors.groupingBy(Emp::dept, Collectors.counting()));
Map<String, String> names = emps.stream().collect(Collectors.groupingBy(Emp::dept,
        TreeMap::new, Collectors.mapping(Emp::name, Collectors.joining(", "))));
Map<Boolean, Long> above65 = emps.stream()
        .collect(Collectors.partitioningBy(e -> e.salary() > 65, Collectors.counting()));
System.out.println(count.get("IT") + " " + names + " " + above65);
```

```text output
2 {HR=Neha, IT=Asha, Ravi} {false=1, true=2}
```

## Interview Qs

### What happens when toMap meets a duplicate key?

It throws `IllegalStateException`. Add a merge function: `(a, b) -> a` keeps the first, `Integer::sum` adds. A fourth argument, `LinkedHashMap::new`, keeps the order.

### What is a downstream collector?

The collector `groupingBy` or `partitioningBy` runs on each group. Without one you get lists; with `counting()`, `summingInt`, `mapping` or `maxBy` you get a count, a total, one field or the top element.

### How do you keep the groups sorted by key?

Pass a map factory: `groupingBy(Emp::dept, TreeMap::new, toList())`. The plain form promises nothing about the map's type or order.
