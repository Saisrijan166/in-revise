## Why it exists

Data classes needed pages of boilerplate, and open class trees left every `instanceof` chain incomplete. Records, sealed types and patterns fix both.

## How it works

<Mermaid
  alt="A sealed interface Shape permits two records, Circle and Square. A switch with one case per permitted type is exhaustive, so it needs no default."
  chart={`flowchart LR
  S["sealed interface Shape"] --> C["record Circle"]
  S --> Q["record Square"]
  C --> W{"switch (shape)"}
  Q --> W
  W --> OK["exhaustive: no default"]`}
/>

- A compact constructor `Circle { ... }` validates the parameters; the fields are assigned after it runs.

## Example

```java
sealed interface Shape permits Circle, Square {}
record Circle(double r) implements Shape {
    Circle { if (r < 0) throw new IllegalArgumentException("r < 0"); }  // compact
}
record Square(double side) implements Shape {}

double area(Shape s) {                              // Java 21+
    return switch (s) {                             // exhaustive: no default
        case Circle c -> Math.PI * c.r() * c.r();   // type pattern
        case Square(double side) -> side * side;    // record pattern
    };
}
```

## Interview Qs

### When should you not use a record?

When the object must change, extend another class or hide its fields. Records suit DTOs, map keys and multi-value returns.

### What does `null instanceof String` return?

`false`. So `if (o instanceof String s)` never binds `s` to null and needs no separate null check.

### Why use sealed classes?

To state "these are all the subtypes". The compiler then checks that a switch covers each one, and every switch without a default stops compiling when a new subtype is added.
