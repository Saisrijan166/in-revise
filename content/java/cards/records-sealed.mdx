## What it is

These are three features that work together. A record (Java 16) is a class declared by its components, such as `record Paid(long id, long amountPaise) {}`; the compiler writes the fields, constructor, accessors, `equals()`, `hashCode()` and `toString()`. A sealed class or interface (Java 17) lists in `permits` the only types allowed to extend it. Pattern matching tests an object's type and gives you a typed variable in one step, in `instanceof` (Java 16) and in `switch` (Java 21).

## Why it exists

An immutable `Paid` class written by hand needs about 30 lines of fields, constructor, getters, [equals and hashCode](card:object-class-equals-hashcode), and adding a field means editing them all. A record is one line. Separately, a payment either succeeds or fails, but with an open interface any class could implement it, so an `instanceof` chain over the results might miss a case and nobody would know. Sealing fixes the list of subtypes, and the compiler can then check that a switch handles every one.

## How it works

1. For each record component, the compiler creates a `private final` field and an accessor with the same name, `amountPaise()`, not `getAmountPaise()`. It also creates the constructor and builds `equals()`, `hashCode()` and `toString()` from all components.
2. A compact constructor, written `Paid { ... }` with no parameter list, runs first with the parameters. Use it to validate or copy them; the fields are assigned after its body.
3. `sealed interface PaymentResult permits Paid, Failed` makes any other implementing class a compile error.
4. In a switch over a `PaymentResult`, each case is a pattern. `case Paid p` tests the type and binds `p`; `case Failed(long id, String reason)` is a record pattern that also takes the record apart into its components.
5. Because the compiler knows every permitted type, a switch without `default` compiles only if each one has a case.

## Example

The result of a payment, modelled as a sealed interface with two records.

```java
sealed interface PaymentResult permits Paid, Failed {}
record Paid(long id, long amountPaise) implements PaymentResult {
    Paid {                                                 // compact constructor
        if (amountPaise <= 0) throw new IllegalArgumentException("amount must be > 0");
    }
}
record Failed(long id, String reason) implements PaymentResult {}

static String describe(PaymentResult r) {                 // Java 21+
    return switch (r) {                                    // no default: every type covered
        case Paid p -> "paid " + p.amountPaise();          // type pattern
        case Failed(long id, String reason) -> id + " failed: " + reason;   // record pattern
    };
}
System.out.println(describe(new Paid(42, 10_000)));
```

```text output
paid 10000
```

What to notice:

- `p.amountPaise()` is the generated accessor. There is no `getAmountPaise()` and no setter.
- `new Paid(42, 0)` throws `IllegalArgumentException` from the compact constructor, so an invalid `Paid` can never exist.
- The switch has no `default`. Add a third permitted record and this method stops compiling until you add its case.
- The record pattern binds `id` and `reason` directly, so the `Failed` case needs no accessor calls.

## Rules and defaults

- **Records:** implicitly final and extend `java.lang.Record`, so they cannot extend another class. Instance fields and instance initialisers are not allowed in the body; static fields, methods and nested types are.
- **Shallow immutability:** a `List` component can still be changed through the list. Store `List.copyOf(...)` in the compact constructor, as in [immutable classes](card:immutability).
- **Sealed subtypes:** each permitted subtype must be `final`, `sealed` or `non-sealed`, and must be in the same module, or in the same package when there are no modules. `permits` may be left out when the subtypes are in the same source file.
- **instanceof patterns:** `null instanceof String s` is false, so the variable is never bound to null.
- **Null in a switch:** a switch with no `case null` throws `NullPointerException` when the value is null.
- **Enums:** an exhaustive switch over an [enum](card:enums) follows the same rule: no `default` needed when every constant is covered.

## Not to be confused with

An enum fixes a set of values: exactly one `PAID` object exists. A sealed type fixes a set of types: there can be any number of `Paid` objects, each with its own id and amount. A record is just a compact data class, and it may or may not belong to a sealed type. Rule: enum = fixed values; sealed = fixed subtypes; record = data carrier.

## Interview Qs

### When should you not use a record?

When the object must change after creation, must extend another class, or must hide its fields, since every component gets a public accessor. Records suit data transfer objects, map keys and returning several values from a method.

### What does `null instanceof String` return?

`false`. So `if (o instanceof String s)` never binds `s` to null and needs no separate null check.

### Why use sealed classes?

To state "these are all the subtypes". The compiler then checks that a switch covers each one, so adding a new subtype makes every switch without a default stop compiling and shows you each place to update. It also stops other code from adding subtypes you did not plan for.
