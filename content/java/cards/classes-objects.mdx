## Why it exists

Programs model many things of one kind, such as users or orders. A class describes the kind once; each object holds one thing's own data.

## How it works

<Mermaid
  alt="Car a = new Car(): the class Car is the blueprint, new creates a Car object on the heap, and the variable a holds a reference to it. Car b = a copies the reference, so a and b point to the same object."
  chart={`flowchart LR
  C[class Car] -- new Car --> O((Car object on heap))
  A[a] --> O
  B["b = a"] --> O`}
/>

- `new` allocates the object, sets fields to default values, then runs a [constructor](card:constructors).
- Where locals and objects live: [JVM memory](card:jvm-memory). Passing them to methods: [pass-by-value](card:pass-by-value).

## Example

```java
class Car {
    String color;                                // field: each Car has its own
    void paint(String c) { color = c; }          // instance method
    static int total(int... prices) {            // varargs: int[] inside
        int sum = 0; for (int p : prices) sum += p;
        return sum;
    }
}
Car a = new Car(); Car b = a;
b.paint("red");                                  // a.color is "red" too
int t = Car.total(5, 10, 20);                    // 35
```

## Interview Qs

### Is the return type part of the method signature?

No. The signature is the name plus the parameter types. That is why [overloading](card:polymorphism) needs a different parameter list, not just a different return type.

### What are the rules for varargs?

A method may have only one varargs parameter, and it must be the last one. Inside the method it is an array; callers may pass zero or more values.
