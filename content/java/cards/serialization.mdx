## Why it exists

Objects live only in memory. To save one to a file, cache it, or send it to another JVM, Java needs a byte form it can turn back into an object.

## How it works

<Mermaid
  alt="Serialisation flow. An object goes into ObjectOutputStream, which writes its non-transient, non-static fields as bytes to a file or the network. ObjectInputStream reads the bytes back and rebuilds the object without running its class's constructors; transient fields get default values."
  chart={`flowchart LR
  O([Object]) --> OOS[ObjectOutputStream.writeObject]
  OOS --> B[(Bytes: file or network)]
  B --> OIS[ObjectInputStream.readObject]
  OIS --> C([Copy: no constructor run, transient = default])`}
/>

- With no serialVersionUID, Java computes one from class details, so a small change breaks old data.
- [Records](card:records-sealed) are different: they are rebuilt through the canonical constructor (Java 16+).
- Untrusted input: the API docs say avoid it; if you must, set a [serialisation filter](card:serialization-filter).

## Example

```java
class User implements Serializable {
    private static final long serialVersionUID = 1L;
    String name = "Asha";
    transient String token = "secret";               // not written
}
try (var out = new ObjectOutputStream(new FileOutputStream("u.bin"))) {
    out.writeObject(new User());
}
try (var in = new ObjectInputStream(new FileInputStream("u.bin"))) {
    User copy = (User) in.readObject();
    System.out.println(copy.name + " " + copy.token);   // token was not written
}
```

```text output
Asha null
```

## Interview Qs

### What is serialVersionUID and why declare it?

It is the class's serial version. Reading data written by a different version fails with InvalidClassException. The computed default changes with small edits or compilers, so the API docs strongly recommend declaring it, ideally private.

### What is not serialised?

Static fields (they belong to the class) and transient fields. Fields of a non-serialisable superclass are also skipped; that superclass needs an accessible no-arg constructor, which runs on reading.

### Why is Java serialisation discouraged today?

It rebuilds objects outside normal constructors, so crafted bytes can break invariants or attack the app. Prefer an explicit format like JSON; if Java serialisation stays, use a filter.
