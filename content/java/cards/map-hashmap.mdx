## Why it exists

Finding a key in a list means scanning it. A hash table jumps straight to one bucket.

## How it works

<Steps label="map.put(key, value) in HashMap (OpenJDK 25)">
  <Step title="Hash">`h ^ (h >>> 16)` on `key.hashCode()` mixes in the high bits. A null key hashes to 0.</Step>
  <Step title="Bucket">Index = `(capacity - 1) & hash`; capacity is a power of two.</Step>
  <Step title="Match">A node with the same hash and `equals` true gets the new value.</Step>
  <Step title="Insert">No match: add a node. A bucket that already held 8 becomes a tree (under 64 buckets, the table resizes instead).</Step>
  <Step title="Resize">Past capacity × load factor: double the buckets.</Step>
</Steps>

- [LinkedHashMap](card:linkedhashmap) in access order, with `removeEldestEntry`, is an LRU cache.

## Example

```java
class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int max;
    LruCache(int max) { super(16, 0.75f, true); this.max = max; }  // true = access order
    @Override protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > max;                   // evict least recently used
    }
}
```

## Defaults

| What | Default | Where |
|---|---|---|
| Initial capacity, load factor | 16 buckets, 0.75 (resize after 12 entries) | HashMap, Java SE 25 |
| Bucket to tree | adding to a bucket of 8+ nodes, capacity 64+ | HashMap, OpenJDK 8 to 25 |

## Interview Qs

### Why HashMap when HashSet already exists?

HashSet only says whether a value is present. HashMap links each key to a value, like an id to a user; HashSet is built on one.

### HashMap vs Hashtable?

Hashtable is legacy (Java 1.0), synchronised, and rejects null keys and values. HashMap is unsynchronised and allows one null key. For high concurrency, use ConcurrentHashMap.

### Why LinkedHashMap or TreeMap when HashMap exists?

HashMap promises no order. LinkedHashMap keeps insertion or access order cheaply; TreeMap keeps keys sorted at O(log n).
