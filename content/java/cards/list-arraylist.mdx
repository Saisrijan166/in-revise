## What it is

A `List` is an ordered sequence: each item sits at a position, called its index, starting at 0, and the same value may appear more than once. `ArrayList` and `LinkedList` are its two main classes. `ArrayList` keeps the items in an internal array that it replaces with a bigger one when it fills up. `LinkedList` keeps each item in a small node object that points to the next node and the previous one.

## Why it exists

A Java array has a length fixed at creation: a `Payment[10]` cannot take an eleventh payment, and it has no `add`, `remove` or `contains`. You would have to create a bigger array and copy everything yourself. A `List` grows and shrinks for you and gives those methods, and the [framework](card:collections-framework) lets you pick the class whose costs match your use.

## How it works

<Compare id="arraylist-vs-linkedlist" />

Follow an `ArrayList` as payments are added:

1. `new ArrayList<>()` starts with no space; in OpenJDK the first `add` creates an internal array with room for 10 items.
2. Each `add(p)` puts the payment in the next free slot. That is O(1).
3. When the array is full, the next `add` creates an array about 1.5 times bigger and copies every item into it. That one copy is O(n), but it happens rarely, so on average each `add` is still O(1). This average is called amortised O(1).
4. `get(i)` reads slot i directly, which is O(1) whatever the size.
5. `add(0, p)` or `remove(0)` must shift every later item by one slot, which is O(n).

A `LinkedList` never copies or shifts, but to reach index i it walks node by node from the nearer end. So the key is: ArrayList is fast to read by position, and LinkedList is fast only where it already stands.

## Example

Payments are added to an `ArrayList`, one in front; then the classic `remove` overload trick on a `List<Integer>`.

```java
List<Payment> payments = new ArrayList<>();             // empty; grows as you add
payments.add(new Payment("p1", 500, Status.PAID));      // goes to index 0
payments.add(new Payment("p2", 900, Status.PENDING));   // index 1
payments.add(0, new Payment("p0", 100, Status.PAID));   // insert at 0: p1, p2 shift right
System.out.println(payments.get(1).id() + " " + payments.size());

List<Integer> codes = new ArrayList<>(List.of(10, 20, 1));
codes.remove(1);                    // remove(int index): removes 20, the item at index 1
codes.remove(Integer.valueOf(1));   // remove(Object): removes the value 1
System.out.println(codes);
```

```text output
p1 3
[10]
```

What to notice:

- After `add(0, ...)`, `p1` moved from index 0 to index 1. Every insert at the front shifts all items, so a loop of front inserts on a large `ArrayList` is slow.
- `codes.remove(1)` treats 1 as an index. Write `Integer.valueOf(1)` whenever you mean the value.
- `List.of(10, 20, 1)` cannot change, so it is wrapped in `new ArrayList<>(...)` to get a list you can remove from.

## Rules and defaults

- **Initial capacity:** `new ArrayList<>(n)` reserves room for n items up front, and `ensureCapacity(n)` does it later. Both avoid repeated copying when you know the size.
- **Size vs capacity:** `size()` is the number of items; capacity is the length of the internal array. `trimToSize()` shrinks the capacity to the size.
- **Thread safety:** `ArrayList` and `LinkedList` are not synchronised. Wrap with `Collections.synchronizedList(...)`, or use a [concurrent collection](card:concurrent-collections), if threads share the list.
- **Vector:** a legacy resizable array whose methods are synchronised. The docs recommend `ArrayList` when you do not need thread safety.
- **null:** both `ArrayList` and `LinkedList` accept `null` items.

## Not to be confused with

An array (`int[]`, `Payment[]`) has a fixed length, can hold primitives such as `int` directly, and you read its size with the `length` field. An `ArrayList` grows on its own, holds only objects (so `ArrayList<Integer>`, boxed through [wrapper classes](card:wrapper-classes)), and you read its size with `size()`. Rule: an array for fixed-size data, especially primitives; an `ArrayList` when the number of items changes.

## Interview Qs

### When would you pick LinkedList over ArrayList?

Rarely: when you add and remove mostly at the two ends, or remove items through an iterator as you walk. Even then, `ArrayDeque` is usually faster for a queue or stack. Only `ArrayList` gives O(1) `get(i)`.

### What happens inside ArrayList when it is full?

The next `add` creates a bigger array, about 1.5 times the old capacity in OpenJDK, copies all items into it and drops the old array. That copy is O(n), but it happens so rarely that adding at the end costs amortised O(1). The Javadoc promises only the amortised cost, not the growth factor.

### ArrayList vs Vector?

Both are resizable arrays. `Vector` is a legacy class (Java 1.0) whose methods are all synchronised, which costs time even in one thread. Use `ArrayList`, and add synchronisation or a concurrent collection only when threads share the list.
