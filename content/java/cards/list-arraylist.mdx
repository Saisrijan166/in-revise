## Why it exists

An array cannot change its length. A List grows and shrinks for you and adds methods such as `add`, `remove`, `contains` and `sort`.

## How it works

<Compare id="arraylist-vs-linkedlist" />

- Adding to a full ArrayList copies everything into a bigger array; `ensureCapacity(n)` cuts repeated copies.
- Inserting in the middle of either list costs O(n): ArrayList shifts items, LinkedList walks to the spot.

## Example

```java
List<Integer> list = new ArrayList<>(List.of(10, 20, 1));
list.remove(1);                    // index 1 -> [10, 1]
list.remove(Integer.valueOf(1));   // value 1
System.out.println(list);

int[] fixed = new int[3];          // primitives, length never changes
List<Integer> growing = new ArrayList<>();   // boxed Integer, grows
```

```text output
[10]
```

## Interview Qs

### When would you pick LinkedList over ArrayList?

Rarely: when you add and remove at both ends or through an iterator in place. For a queue or stack, ArrayDeque is likely faster, and only ArrayList gives O(1) get(i).

### Why use ArrayList when arrays already exist?

An array has a fixed length set at creation. ArrayList resizes itself and gives the List API, at the cost of boxing primitives. Use an array for fixed-size primitive data.

### ArrayList vs Vector?

Both are resizable arrays. Vector is a legacy class whose methods are synchronised; the docs recommend ArrayList when thread safety is not needed.
