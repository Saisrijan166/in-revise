## Why it exists

SearchBox and ProductList must agree on the same search text. If each keeps its own copy, they drift apart, so one component has to own it.

## How it works

  alt="ProductsPage owns the query state and passes query and onQueryChange to SearchBox and the filtered products to ProductList. Typing calls onQueryChange, which updates the state in ProductsPage."
  chart={`flowchart TD
  P["ProductsPage: owns query"] -- "query, onQueryChange" --> S[SearchBox]
  P -- "filtered products" --> L[ProductList]
  S -. "onQueryChange(text)" .-> P`}
/>

- Remove the state from the children, add it to the parent, pass it down with a setter callback.
- [Prop drilling](card:prop-drilling)? Pass JSX as `children` first; reach for [Context](card:context-api) later.
- Which tool fits which state: [the picker](card:global-state).

## Example

```jsx
import { useState } from 'react';

export default function ProductsPage({ products }) {
  const [query, setQuery] = useState('');      // lifted: both children need it
  const shown = products.filter((p) => p.name.toLowerCase().includes(query.toLowerCase()));
  return (
    <>
      <SearchBox query={query} onQueryChange={setQuery} />
      <ProductList products={shown} />
    </>
  );
}
```

## Interview Qs

### What is prop drilling and how do you avoid it?

Passing a prop through components that only forward it. First pass JSX as `children`, so the middle layers never see the prop. If many distant components need it, use [Context](card:context-api) or a [store](card:global-state).

### What is state colocation, and why is it faster?

Keeping state in the lowest component that uses it. An update then re-renders only that small subtree, not the whole page, so slow components that do not use the state are skipped.
