## What it is

Several rules can set the same property on the same element: the browser's own defaults, a UI library, and your CSS. The **cascade** is the fixed set of steps the browser runs to pick exactly one declaration to use. One of those steps is **specificity**: a score for how targeted a selector is, written as three numbers for how many ID, class and type selectors it has. Inline styles, `!important` and `@layer` (a [cascade layer](card:box-model-positioning) is a named group of rules) also take part, as earlier steps.

## Why it exists

If the last rule in the file always won, every small stylesheet change could silently break something far away, and a library's styles would override yours by accident just because they loaded later. The cascade is a predictable referee: given two rules that clash, you can work out which one applies and why. Specificity lets a precise rule (`#save-button`) beat a general one (`button`) without depending on file order.

## How it works

The browser compares two clashing declarations by running these steps in order and stopping at the first one that separates them.

<Steps label="How the cascade picks one declaration">
  <Step title="Origin and importance">Your CSS beats browser defaults. An !important declaration flips the order and beats normal declarations.</Step>
  <Step title="Inline style">A style="" attribute on the element beats any selector of the same importance.</Step>
  <Step title="Cascade layers">Unlayered rules beat layered ones, and a later @layer beats an earlier one.</Step>
  <Step title="Specificity">Compare the (ID, CLASS, TYPE) counts; the first column that differs decides it.</Step>
  <Step title="Source order">Still tied? The declaration written last in the CSS wins.</Step>
</Steps>

1. The browser gathers every declaration that targets the element for one property.
2. It sorts them by origin and `!important`, so your normal rules already beat browser defaults.
3. Among the survivors it compares specificity column by column, left to right.
4. If two still tie, the one that appears last in the source wins.

So the key is that each step is only reached when the previous one ties, which is why a single ID beats any pile of classes.

## Example

Each comment shows the specificity count and what actually wins.

```css
#dashboard .total   { color: green; } /* 1-1-0: wins, the ID column decides */
.panel .total       { color: blue; }  /* 0-2-0: loses on the ID column */
p.total:hover       { color: red; }   /* 0-2-1: applies only on hover */
:where(#dashboard) .total { color: grey; } /* 0-1-0: :where() counts the ID as 0 */
:is(#dashboard, .x) p     { color: black; } /* 1-0-1: takes its most specific argument */
```

What to notice:

- The first rule wins because it is the only one with an ID; the ID column (1 vs 0) settles it before classes are even compared.
- `:where(#dashboard)` wraps the ID but contributes 0 to the count, so wrapping a selector in `:where()` is a way to keep specificity low on purpose.
- `:is()` takes the specificity of its most specific argument, so `:is(#dashboard, .x)` counts as one ID even though one branch is a class.
- Remove the ID from the first rule and `.panel .total` (0-2-0) would then win, because the comparison would fall through to the class column.

## Rules and defaults

- **Specificity format:** three columns (ID, CLASS, TYPE). CLASS also covers attribute selectors and pseudo-classes; TYPE also covers pseudo-elements like `::before`.
- **Zero-weight selectors:** `*`, the combinators `>`, `+`, `~`, and `:where()` add nothing to any column.
- **Inheritance:** only `color`, `font` and a few other properties pass to children automatically; `margin`, `padding`, `border` and layout properties do not.
- **Cascade layers (@layer):** Baseline since 2022; layer order is checked before specificity, so an early layer always loses to an unlayered rule.

## Interview Qs

### How do you override an inline style from a stylesheet?

An inline `style=""` attribute beats any normal selector, so the only way a stylesheet can win is with `!important` on the declaration. That is a sign of trouble, though. The cleaner fix is to remove the inline style and set the property in CSS, or to change it in the same JavaScript that added it.

### What do inherit, initial and unset do?

`inherit` takes the parent's computed value for that property. `initial` sets the property to its own defined initial value, ignoring the parent. `unset` is a mix: it acts like `inherit` for inherited properties such as `color`, and like `initial` for everything else, which makes it handy for resetting a property to its natural behaviour.

### Why use cascade layers instead of !important?

Layer order is checked before specificity, so you can put a third-party stylesheet in an early layer and your own simple selectors will win without any `!important` or ID hacks. `!important` wins too, but it is hard to override later (only another `!important` beats it), so it tends to spread. Layers keep the override explicit and ordered.
