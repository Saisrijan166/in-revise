## Why it exists

Many rules can set the same property on one element: browser defaults, a library and your own CSS. The cascade is the fixed order that decides which one applies.

## How it works

<Steps label="How the cascade picks one declaration">
  <Step title="Origin and importance">Your CSS beats browser defaults. An !important declaration flips the order and beats normal ones.</Step>
  <Step title="Inline style">A style attribute beats any selector of the same importance.</Step>
  <Step title="Cascade layers">Unlayered rules beat layered ones; a later @layer beats an earlier one.</Step>
  <Step title="Specificity">Compare (ID, CLASS, TYPE) counts; the first bigger column wins.</Step>
  <Step title="Order of appearance">Still tied? The declaration written last wins.</Step>
</Steps>

- :is(), :not() and :has() take the weight of their most specific argument.
- Inheritance only fills properties that no rule set on the element.

## Example

```css
#cart .total         { color: green; } /* 1-1-0: wins */
.cart .total         { color: blue; }  /* 0-2-0 */
p.total:hover        { color: red; }   /* 0-2-1, but only on hover */
:where(#cart) .total { color: gray; }  /* 0-1-0: :where() adds 0 */
:is(#cart, .x) p     { color: black; } /* 1-0-1: its most specific argument */
```

## Interview Qs

### How do you override an inline style from a stylesheet?

Only an !important declaration in the stylesheet beats a normal inline style. Better: remove the inline style, or change it in the same code that set it.

### What do inherit, initial and unset do?

inherit takes the parent's computed value. initial sets the property's initial value. unset acts as inherit for inherited properties like color, and as initial for the rest.

### Why use cascade layers?

Layer order is checked before specificity. Put a third-party stylesheet in an early layer and your simple selectors win without !important. Baseline 2022.
