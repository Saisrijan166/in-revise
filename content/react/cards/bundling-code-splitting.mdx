## Why it exists

Browsers must download, parse and run JavaScript before the page responds. One big bundle makes the first visit slow for code the user may never open.

## How it works

<Steps label="From source to the browser">
  <Step title="Resolve">The [bundler](card:bundler) follows every `import` from the entry file.</Step>
  <Step title="Transform">JSX and TypeScript become plain JavaScript.</Step>
  <Step title="Shake and minify">Unused exports are dropped; names and spaces are shortened.</Step>
  <Step title="Split">Each `import()` starts a separate chunk, loaded on demand.</Step>
</Steps>

- To find what is heavy, check the Network tab or a bundle analyser; drop or lazy-load big libraries.

## Example

```jsx
import { lazy, Suspense, useState } from 'react';
const Checkout = lazy(() => import('./Checkout.jsx')); // outside the component: its own chunk

export default function Cart({ cart }) {
  const [paying, setPaying] = useState(false);
  if (!paying) return <button onClick={() => setPaying(true)}>Checkout</button>;
  return (
    <Suspense fallback={<p>Loading checkout…</p>}>
      <Checkout cart={cart} />
    </Suspense>
  );
}
```

## Interview Qs

### What is the difference between code splitting and lazy loading?

Code splitting is the build step that cuts the bundle into chunks. Lazy loading is fetching a chunk only when it is needed, for example `React.lazy` loading the Checkout page on first render.

### Why must lazy() be declared outside the component?

Inside, a new lazy component is created on every render, so React resets its state each time. Declare it at module level.

### Why does tree shaking need ES modules?

Static `import` and `export` let the bundler see which exports are used before running code, so it can drop the rest.
