## Why it exists

Every state change makes React call components again. Knowing what triggers that, and what it really costs, tells you when to leave it alone and when to fix it.

## How it works

<Mermaid
  alt="A trigger (own state change, parent re-render, or context value change) makes React call the component again. React compares the new output with the old. If nothing differs, the DOM is not touched. If something differs, only those DOM nodes are updated, then the browser paints."
  chart={`flowchart LR
  T1[Own state change] --> R[Render: call the component]
  T2[Parent re-render] --> R
  T3[Context value change] --> R
  R --> D{Output differs?}
  D -- no --> N[DOM untouched]
  D -- yes --> C[Commit: update only those nodes]`}
/>

- Find slow renders with the [Profiler](card:measuring-performance) before fixing anything.
- Fixes, cheapest first: [keep state low](card:lifting-state-up), pass slow parts as `children`, then [memo](card:memoization).
- Slow update you cannot avoid: mark it non-urgent with [useTransition](card:use-transition) or [useDeferredValue](card:use-deferred-value).

## Example

```jsx
import { useState } from 'react';
function Layout({ children }) {
  const [cartOpen, setCartOpen] = useState(false); // state lives here only
  return (
    <main>
      <button onClick={() => setCartOpen(!cartOpen)}>Cart</button>
      {cartOpen && <p>Cart: 2 items</p>}
      {children}
    </main>
  );
}
// <Layout><ProductList products={products} /></Layout>: toggling skips ProductList
```

## Interview Qs

### Is a re-render the same as a DOM update?

No. Rendering calls the component to compute JSX. In the commit step React changes only DOM nodes whose output differs. If nothing differs, the DOM is not touched.

### What makes a component re-render?

Its own state changing, its parent re-rendering, or a context it reads getting a new value. New props arrive only because the parent rendered.

### How do you stop a slow list re-rendering when a small toggle changes?

Move the toggle state into a small component, or pass the list as `children` so it is created outside. Use `memo` only if that is not enough.
