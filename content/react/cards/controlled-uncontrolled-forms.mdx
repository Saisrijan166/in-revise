## What it is

A form field in React is either controlled or uncontrolled, depending on who holds its current text. A **controlled input** keeps its value in React [state](card:use-state): you set the field's `value` from state and update that state on every `onChange`. An **uncontrolled input** lets the browser's DOM keep the text, like a plain HTML form; you set only a `defaultValue` and read the final value when the form is submitted.

## Why it exists

Different fields have different needs. A search box must react to every keystroke, so you want the current text in state to filter the list live. A coupon code only matters once, when the user submits, so holding it in state and re-rendering on each keystroke is wasted work. React supports both styles so you can match the field to its job: reach into state when the UI must respond as the user types, and let the DOM hold the value when you only need it at the end.

## How it works

The two styles differ in where the value lives and when you read it:

1. **Controlled:** you bind `value` to a state variable and add `onChange`. Each keystroke fires `onChange`, you call the setter, the component re-renders, and `value` shows the new state.
2. **Uncontrolled:** you give a `defaultValue` (the starting text) and no `value`. The user types freely and the DOM stores the text; React does not re-render on each keystroke.
3. **Reading uncontrolled:** on submit you read the field from the submit event's `FormData`, or from a [ref](card:use-ref) pointing at the DOM node.

A field must stay one style for its whole life; do not switch a field between `value` and `defaultValue`.

## Example

The search box is controlled; the coupon form is uncontrolled and read on submit.

```jsx
function SearchBox({ query, setQuery }) {          // controlled
  return <input value={query} onChange={e => setQuery(e.target.value)} />;
}

function CouponForm({ applyCoupon }) {             // uncontrolled
  return (
    <form action={formData => applyCoupon(formData.get('code'))}>
      <input name="code" defaultValue="" />
      <button type="submit">Apply</button>
    </form>
  );
}
```

What to notice:

- In `SearchBox`, `value={query}` ties the field to state and `onChange` updates it; remove `onChange` and the field freezes and React warns.
- In `CouponForm`, `defaultValue` only seeds the field; the DOM holds whatever the user types, and no state changes while typing.
- The React 19 `<form action={fn}>` passes the fields as `FormData`, so `formData.get('code')` reads the coupon at submit time without a ref.

## Rules and defaults

- **Controlled needs both:** a `value` without an `onChange` (or `readOnly`) makes the field read-only and triggers a React warning (React 19).
- **Keep `value` a string:** use `value={query ?? ''}`; passing `undefined` makes React treat the field as uncontrolled.
- **One style for life:** do not change a field from `value` to `defaultValue` or back; React warns about switching between controlled and uncontrolled.
- **Form Actions (React 19):** a `<form action={fn}>` receives the fields as [FormData](card:form-actions) and does not need `e.preventDefault()`.

## Not to be confused with

A **controlled input** stores its value in React state, so the component re-renders as the user types. An **uncontrolled input** leaves the value in the DOM and is read on submit. **defaultValue** seeds an uncontrolled field once, while **value** fixes a controlled field on every render. Rule: `value` + `onChange` means controlled; `defaultValue` means uncontrolled.

## Interview Qs

### What is the difference between controlled and uncontrolled components?

A controlled component stores the field's value in React state: `value` comes from state and `onChange` updates it, so state is the single source of truth. An uncontrolled component lets the DOM keep the value; you set a `defaultValue` and read the value only on submit, with `FormData` or a ref. Controlled re-renders on each keystroke; uncontrolled does not.

### When would you choose an uncontrolled input?

When you need the value only once, at submit, such as a coupon code or a simple contact form. The DOM holds the text, so there is no state update or re-render per keystroke, and the code is shorter. Choose controlled instead when the UI must respond while the user types, like live search or instant validation.

### How do you stop a form from reloading the page on submit?

In a traditional `onSubmit` handler, call [e.preventDefault()](card:dom-events), which stops the browser's default full-page form submission so you can handle it in JavaScript. With a React 19 `<form action={fn}>`, React handles this for you, so you do not need `preventDefault`.
