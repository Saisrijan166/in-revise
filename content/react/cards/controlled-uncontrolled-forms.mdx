## Why it exists

Some inputs must react to each keystroke, like a search box that filters products. Others only matter on submit, like a coupon code. React supports both.

## How it works

<Compare id="controlled-vs-uncontrolled" />

- An input must not switch between the two during its life.
- React 19 [form Actions](card:form-actions) receive the fields as FormData.

## Example

```jsx
function SearchBox({ query, setQuery }) {         // controlled
  return <input value={query} onChange={e => setQuery(e.target.value)} />;
}

function CouponForm({ applyCoupon }) {            // uncontrolled
  return (
    <form action={formData => applyCoupon(formData.get('code'))}>
      <input name="code" defaultValue="" />
      <button type="submit">Apply</button>
    </form>
  );
}
```

## Interview Qs

### What is the difference between controlled and uncontrolled components?

Controlled: React state holds the value and onChange updates it. Uncontrolled: the DOM holds the value; you give a defaultValue and read it on submit with FormData or a ref.

### When would you choose an uncontrolled input?

A simple form read once on submit, like a coupon code: less code, and no state set on every keystroke. Choose controlled when the UI must react while the user types.

### How do you stop a form from reloading the page?

In onSubmit, call [e.preventDefault()](card:dom-events). A React 19 `<form action={fn}>` does not need it.
