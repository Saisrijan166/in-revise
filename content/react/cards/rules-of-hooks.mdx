## Why it exists

Hooks give function components state, effects and other React features. Custom hooks let components reuse stateful logic without copying it.

## How it works

| Where you call a hook | Allowed? |
|---|---|
| Top level of a function component | Yes |
| Top level of a custom hook | Yes |
| Inside `if`, a loop, or after an early `return` | No |
| In an event handler, `try/catch`, or a class component | No |

- React has no names for hooks; it pairs each call with its stored state by position, so the order must never change.
- `eslint-plugin-react-hooks` catches breaks: `rules-of-hooks` and `exhaustive-deps` are in its recommended preset.
- Built-in: [useState](card:use-state), [useEffect](card:use-effect), [useRef](card:use-ref), [useContext](card:context-api), [useReducer](card:use-reducer), [useMemo](card:memoization).

## Example

```jsx
import { useState, useEffect } from 'react';

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => JSON.parse(localStorage.getItem(key)) ?? initial);
  useEffect(() => localStorage.setItem(key, JSON.stringify(value)), [key, value]);
  return [value, setValue];
}

function Cart() {
  const [cart] = useLocalStorage('cart', []);   // its own state, per call
  return <p>{cart.length} items in cart</p>;
}
```

## Interview Qs

### What are the rules of hooks, and why do they exist?

Top level only, and only from function components or custom hooks. React stores hook state in a list matched by call order, so a conditional call shifts every later hook.

### How is a custom hook different from a normal function?

Its name starts with `use` and it may call other hooks; a normal function cannot. Each caller gets its own state.

### What did hooks replace?

Earlier, logic was shared with higher-order components (a function that wraps a component) and render props (a function prop that returns UI). Both add wrapper layers; custom hooks do not.
