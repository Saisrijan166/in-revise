## What it is

A hook is a special function that lets a [function component](card:components-jsx-props) use a React feature such as state. Its name always starts with `use`, like [useState](card:use-state). The Rules of Hooks are two limits on where you may call one: only at the top level of the function, and only from a component or from another hook. A custom hook is your own `use`-function that calls built-in hooks to package some logic so several components can reuse it.

## Why it exists

React stores a component's hooks in a plain list and remembers nothing but their order. If you called a hook inside an `if` that is sometimes false, the list would be shorter on those renders, and React would hand the state of one hook to another. The result is state that jumps between variables with no error. The rules keep the call order identical on every render, so each hook always lines up with its own stored state.

## How it works

React keeps one list of hook states per component and walks it in order on each render.

| Where you call a hook | Allowed? |
|---|---|
| Top level of a function component | Yes |
| Top level of a custom hook | Yes |
| Inside an `if`, a loop, or after an early `return` | No |
| In an event handler, a `try/catch`, or a class component | No |

1. On the first render React runs the component top to bottom and, for each hook call in order, creates a slot of state.
2. On every later render it runs the same calls in the same order and reads slot 1, slot 2, slot 3 to match them.
3. If a call is skipped by an `if`, the slots shift by one, and every later hook reads a neighbour's state.

So the key is that React identifies a hook by its position, not its name.

## Example

A custom hook, `useLocalStorage`, bundles saving to the browser so any component can reuse it. Each component that calls it gets its own value.

```jsx
import { useState, useEffect } from 'react';

function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => JSON.parse(localStorage.getItem(key)) ?? initial);
  useEffect(() => localStorage.setItem(key, JSON.stringify(value)), [key, value]);
  return [value, setValue];
}

function PaymentDraft() {
  const [draft, setDraft] = useLocalStorage('draft', { amount: 0 });   // its own state, per call
  return <p>Amount: {draft.amount}</p>;
}
```

What to notice:

- The function name starts with `use`, which is what lets it call `useState` and `useEffect` inside.
- Both hooks are called at the top level, unconditionally, so the call order never changes.
- `useLocalStorage` returns `[value, setValue]`, so it is used exactly like `useState`; the saving is hidden.
- A second component calling `useLocalStorage('other', …)` runs these hooks again and gets a separate, independent value.

## Rules and defaults

- **Naming:** a function may call hooks only if its name starts with `use`; the `eslint-plugin-react-hooks` lint rule relies on this to know what a component or hook is.
- **Enforced by lint:** the plugin's recommended preset turns on `rules-of-hooks` (order) and `exhaustive-deps` (dependency arrays); breaking a rule is a lint error, not a runtime crash.
- **Built-in hooks you will use:** [useState](card:use-state), [useEffect](card:use-effect), [useRef](card:use-ref), [useContext](card:context-api), [useReducer](card:use-reducer) and [useMemo](card:memoization).

## Common mistakes

- **"I can guard a hook with a quick `if` for one render."** Any conditional call shifts the slot order; put the condition inside the hook's arguments or inside the effect, never around the call.
- **"My custom hook must start with `use` only by convention."** The name is how React and the linter detect a hook; a non-`use` function that calls hooks is flagged and may break.

## Interview Qs

### What are the rules of hooks, and why do they exist?

Call hooks only at the top level, and only from function components or custom hooks. React stores each component's hook state in an ordered list and matches calls to slots by position. A conditional or looped call changes the order, so a later hook would read another hook's state.

### How is a custom hook different from a normal function?

Its name starts with `use`, and it is allowed to call other hooks; a plain function is not. Each component that calls it runs those hooks freshly, so every caller gets its own state. The hook shares the logic, never a shared value.

### What did custom hooks replace?

Before hooks, shared stateful logic used higher-order components (a function that wraps a component) and render props (a function prop that returns UI). Both added wrapper layers to the tree. A custom hook reuses the logic with no extra component.
