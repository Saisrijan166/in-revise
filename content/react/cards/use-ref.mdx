## What it is

`useRef` is a hook that gives you one object, `{ current: ... }`, and hands you back the exact same object on every render. You store a value in `.current` and read it later. Two things make it different from [state](card:use-state): it survives re-renders like state, but changing it does not cause a re-render. It is used for two jobs: holding a reference to a real DOM node, and keeping a mutable value that the screen does not display, such as a timer id.

## Why it exists

Some values must outlive a single render but must not redraw the UI when they change. A timer id, or the DOM node you want to focus, are examples. If you kept these in state, every change would schedule a render for no visual reason, and some, like a DOM node, cannot be computed during render at all. A ref gives you a stable slot that persists across renders and stays out of React's render cycle, so you can read and change it freely.

## How it works

A ref has two common uses; in both, `.current` is where the value lives.

| Use | In the dashboard | What `.current` holds |
|---|---|---|
| Reach a DOM node | Focus the search box | The real `<input>` element, set by React |
| Keep a value between renders | A debounce timer id | Whatever you assign to it |

1. You call `useRef(initial)`, and React creates the box once and returns the same box on every later render.
2. For a value ref, you assign `myRef.current = x` in an event handler or Effect, and read it later; no render happens.
3. For a DOM ref, you pass the ref as the `ref` prop on a JSX tag.
4. After React commits that tag to the page, it sets `.current` to the DOM node, and back to `null` when the element is removed.

So the key is that a ref is React's escape hatch: it remembers a value without taking part in rendering.

## Example

The dashboard focuses its search box when a button is clicked. The parent creates the ref and passes it to the input, which in React 19 takes `ref` as a plain prop.

```jsx
import { useRef } from 'react';

function SearchInput({ ref }) {                 // React 19: ref is a normal prop
  return <input ref={ref} placeholder="Search payments" />;
}

export default function SearchBox() {
  const inputRef = useRef(null);
  const focusSearch = () => inputRef.current.focus();
  return <><SearchInput ref={inputRef} /><button onClick={focusSearch}>Search</button></>;
}
```

What to notice:

- `useRef(null)` starts the box empty; React fills `.current` with the `<input>` node once it is on the page.
- `SearchInput` reads `ref` straight from its props. Before React 19 you had to wrap it in `forwardRef` for this to work.
- Clicking the button calls `inputRef.current.focus()`, reaching the real DOM node directly.
- None of this is state, so focusing the input causes no re-render.

## Rules and defaults

- **Do not touch during render:** read or write `.current` in event handlers or Effects, not while rendering; the one allowed exception is lazy one-time setup.
- **Let React own its DOM:** you may read, focus or scroll a node React manages, but do not add or remove its children yourself.
- **Initial value:** `useRef(x)` sets `.current` to `x` on the first render only; after that React never resets it.

## Common mistakes

- **"A ref is a lighter useState."** No. State updates re-render; ref changes do not. Use a ref only when the value should not drive the UI.
- **Reading a DOM ref too early.** `.current` is `null` until after commit, so read it in an Effect or event handler, not during render.

## Interview Qs

### When do you use useRef instead of useState?

When a value must survive re-renders but is not shown on screen: a DOM node, a timer id, or any object the JSX does not read. Updating a ref is instant and causes no re-render, while updating state schedules one. If the value appears in the UI, use state.

### How does a parent get a child component's DOM node?

The parent creates a ref with `useRef(null)` and passes it as the `ref` prop; the child puts that ref on its `<input>`. Since React 19 a function component reads `ref` straight from its props. Older code wrapped the child in `forwardRef` to receive it.

### What is useImperativeHandle for?

It lets a child expose a small custom object through its ref instead of the raw DOM node, for example only a `focus()` method. The parent then calls just that. It is an advanced tool and rarely needed.
