## Why it exists

Some values must survive re-renders but never change what is drawn, like a timer id or an input to focus. State would cause useless re-renders.

## How it works

| Use | In the shop | What `.current` holds |
|---|---|---|
| Reach a DOM node | Focus the search box | The `<input>` node, set by React |
| Keep a value between renders | The debounce timer id | Whatever you assign |

- Refs are an escape hatch for browser APIs; most data still flows through props and state.
- Do not change DOM nodes React manages (adding or removing children); read them, focus them, scroll them.

## Example

```jsx
import { useRef } from 'react';

function SearchInput({ ref }) {                 // React 19: ref is a normal prop
  return <input ref={ref} placeholder="Search products" />;
}

export default function SearchBox() {
  const inputRef = useRef(null);
  const focusSearch = () => inputRef.current.focus();
  return <><SearchInput ref={inputRef} /><button onClick={focusSearch}>Search</button></>;
}
```

## Interview Qs

### When do you use useRef instead of useState?

When the value must survive re-renders but is not shown on screen: a DOM node, a timer id, or an object the JSX does not use. Updating a ref is instant and causes no re-render; updating state schedules one.

### How does a parent get a child component's DOM node?

Create a ref in the parent and pass it as the `ref` prop; the child puts it on its `<input>`. Since React 19 a function component reads `ref` as a prop; older code wrapped the child in `forwardRef`.

### What is useImperativeHandle for?

It lets a component expose a small custom object instead of its whole DOM node, such as only `focus()`. It is rarely needed.
