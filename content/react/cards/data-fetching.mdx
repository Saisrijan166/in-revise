## Why it exists

Responses are slow, can fail and can arrive out of order, so the screen may stay blank, break, or show an old search.

## Example

```jsx
import { useQuery } from '@tanstack/react-query';
// getProducts(query, signal): fetch('/api/products?q=' + query), throw if !res.ok

function ProductList({ query }) {
  const { data: products, isPending, isError } = useQuery({
    queryKey: ['products', query],                 // one cache entry per search
    queryFn: ({ signal }) => getProducts(query, signal),
  });
  if (isPending) return <p>Loading…</p>;
  if (isError) return <p>Could not load products.</p>;
  return <ul>{products.map((p) => <li key={p.id}>{p.name}: ₹{p.price}</li>)}</ul>;
}
```

## Defaults

| What | Default | Where |
|---|---|---|
| `staleTime` | 0: stale at once; refetch on mount, focus, reconnect | TanStack Query v5 |
| `gcTime` | 5 minutes for an unused query | TanStack Query v5 |
| `retry` | 3 on the client, with exponential backoff | TanStack Query v5 |

## Interview Qs

### What is a race condition in data fetching, and how do you fix it?

Requests for "mo" and "mouse" can return out of order, so the older result wins. The effect cleanup sets an ignore flag or calls `controller.abort()`.

### Why use TanStack Query instead of useEffect and fetch?

Effects refetch on every mount, cache nothing and need race handling by hand. TanStack Query caches by key, dedupes, retries and gives `isPending` and `isError`.
