## Why it exists

Thousands of DOM rows make renders and scrolling slow. Typing and scrolling fire many events a second; heavy work or an API call for each one is waste.

## How it works

<Compare id="debounce-vs-throttle" />

- Virtualize with [TanStack Virtual](card:tanstack-virtual) or [react-window](card:react-window), or load fewer rows with pagination.
- If the slow part is rendering, not a request, [useDeferredValue](card:use-deferred-value) keeps typing smooth without a delay.
- Debouncing saves calls; still [ignore stale responses](card:data-fetching).

## Example

```javascript
function debounce(fn, ms) {
  let timer;                                 // kept alive by the closure
  return (...args) => {
    clearTimeout(timer);                     // a new key press restarts the wait
    timer = setTimeout(() => fn(...args), ms);
  };
}
const search = debounce((q) => console.log(`GET /api/products?q=${q}`), 300);
['m', 'mo', 'mou', 'mous', 'mouse'].forEach((q, i) => setTimeout(() => search(q), i * 100));
```

```text output
GET /api/products?q=mouse
```

## Interview Qs

### How would you render 10,000 products?

Virtualize: render only the rows in the viewport plus a small overscan, and swap them as the user scrolls. Or paginate, or load more as the user nears the end.

### Write a debounce function.

Keep a timer in a closure. On each call, clear the old timer and start a new one; the function runs only when calls stop for the given delay.

### Debounce or useDeferredValue for a search box?

Debounce the network request. useDeferredValue suits slow rendering: it has no fixed delay and its background render can be interrupted. They can be combined.
