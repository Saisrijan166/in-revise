## Why it exists

A product list can have hundreds of buttons, and rows come and go. Bubbling lets one listener on the list serve every button, including ones added later.

## How it works

<Mermaid
  alt="A click on the Add to cart button. Capturing phase goes down from document to body to the product list to the button. Then the bubbling phase goes back up from the button to the list, body and document."
  chart={`flowchart LR
  D[document] -- capture --> B[body] -- capture --> U["product list"] -- capture --> T(["button: target"])
  T -- bubble --> U2["product list"] -- bubble --> B2[body] -- bubble --> D2[document]`}
/>

- React delegates too: since React 17 it attaches its listeners to the root container, not `document`. Handler naming: [components](card:components-jsx-props).

## Example

```javascript
const list = document.querySelector("#product-list");
list.addEventListener("click", (event) => {
  const button = event.target.closest("button[data-id]");
  if (!button) return;
  console.log("add", button.dataset.id, "| listener on", event.currentTarget.id);
});
document.body.addEventListener("click", () => console.log("body heard it too"));
document.querySelector('[data-id="cable"]').click();
```

```text output
add cable | listener on product-list
body heard it too
```

## Interview Qs

### What is event delegation, and why use it?

Attach one listener to a common parent and read `event.target` to see which child was hit. Fewer listeners, and new children work without extra wiring.

### What does passive: true do?

It promises the listener will not call `preventDefault`, so the browser can scroll at once instead of waiting for it. It is already true by default for `wheel`, `mousewheel`, `touchstart` and `touchmove` on `window`, `document`, `<html>` and `body`.
