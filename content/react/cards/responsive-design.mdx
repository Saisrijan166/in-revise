## Why it exists

One site must work from a phone to a wide monitor. Fixed pixel layouts overflow small screens.

## How it works

| Unit | Relative to | Good for |
|---|---|---|
| px | Nothing: a fixed CSS pixel | Borders, thin lines |
| % | The parent (a width % is of the parent's width) | Fluid widths |
| em | The element's font size (the parent's, for font-size) | Padding that grows with the text |
| rem | The root (html) font size | Font sizes and spacing |
| vw / vh | 1% of the viewport width / height | Full-screen sections |

- `clamp(1rem, 0.75rem + 1.5vw, 2rem)` gives fluid type within bounds; mixing in rem keeps it zoomable.
- Picking image sizes with srcset and sizes is in [measuring performance](card:measuring-performance).

## Example

```css
.products { display: grid; gap: 1rem; }               /* phone: one column */

@media (min-width: 40em) {
  .products { grid-template-columns: repeat(2, 1fr); } /* tablet */
}
@media (min-width: 64em) {
  .products { grid-template-columns: repeat(4, 1fr); } /* desktop */
}

.cart { container-type: inline-size; }
@container (min-width: 400px) { .cart-line { display: flex; } }
```

## Interview Qs

### Media queries vs container queries?

A media query checks the viewport. A container query checks an ancestor with container-type, so a ProductCard adapts in a sidebar or the main column.

### Why is 100vh too tall on mobile?

vh does not change as the address bar shows and hides; it can match the size with the bar hidden, so 100vh overflows when the bar shows. Use 100dvh, which follows the bar.
