## Why it exists

The shop must remember the cart and who is logged in across reloads. Each browser store fits a different job, and the wrong one leaks data.

## How it works

<Compare id="localstorage-vs-sessionstorage-vs-cookies" />

- A server sets a cookie with a header: `Set-Cookie: session=a3fWa; HttpOnly; Secure; SameSite=Lax; Max-Age=3600`.
- `Domain` and `Path` limit where the cookie is sent; `Max-Age=0` deletes it.
- Since the browser sends cookies by itself, cookie sessions need [CSRF defence](card:frontend-security).

## Example

```jsx
import { useEffect, useState } from 'react';

function useSavedCart() {
  const [cart, setCart] = useState(() => JSON.parse(localStorage.getItem('cart') ?? '[]'));

  useEffect(() => {
    localStorage.setItem('cart', JSON.stringify(cart));
  }, [cart]);

  return [cart, setCart];
}
```

## Defaults

| What | Default | Where |
|---|---|---|
| Cookie without `Max-Age` or `Expires` | Session cookie: deleted when the session ends | All browsers (MDN) |
| Cookie without `SameSite` | Treated as `Lax` by some browsers; set it explicitly | Varies by browser (MDN) |

## Interview Qs

### Where would you store a login token?

In an HttpOnly, Secure, SameSite cookie set by the server, so page scripts cannot read it. Then add CSRF protection, because the browser sends that cookie automatically.

### Is sessionStorage shared between tabs?

No. Each tab gets its own session storage, which survives reloads and is cleared when the tab closes. localStorage is shared by every tab of the same origin.

### Why not keep everything in cookies?

A cookie holds about 4 KB, browsers cap cookies per domain, and every matching request carries them. Use Web Storage or IndexedDB for data the server never needs.
