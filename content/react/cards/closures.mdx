## What it is

A **closure** is a function together with the variables it could see in the [scope](card:scope-hoisting) where it was written. When a function is created inside another function, it keeps a link to that outer scope, so it can still read and change those outer variables later, even after the outer function has returned. The captured variable is the real variable, not a copy, so when its value changes, the closure sees the new value.

## Why it exists

Functions often run later: as a click handler, a timer callback or an array method. By the time they run, the function that set them up has already finished. Without closures, that callback could no longer reach the data it was set up with, so you would have to keep that data in a global variable, where any code could change it. A closure lets the callback keep private access to exactly the variables it needs, with no globals.

## How it works

1. `createCart()` runs and creates a scope that holds the variable `count`.
2. Inside, two functions `add` and `size` are created; each keeps a link to that scope.
3. `createCart()` returns the two functions and finishes, but the scope is not thrown away, because the two functions still point to it.
4. Later calls to `add` and `size` read and change the same `count`, which stays private: no code outside can reach it.

So the key is: the inner functions keep the outer scope alive, and that scope is private to them.

## Example

`createCart` hides a counter and exposes only two functions to change and read it. Then a loop shows the `var` trap. Both outputs come from running the code with Node.

```javascript
function createCart() {
  let count = 0;
  return { add: () => ++count, size: () => count };
}
const cart = createCart();
cart.add();
cart.add();
console.log(cart.size(), cart.count);
```

```text output
2 undefined
```

```javascript
for (var i = 0; i < 3; i++) setTimeout(() => console.log("var", i));
for (let j = 0; j < 3; j++) setTimeout(() => console.log("let", j));
```

```text output
var 3
var 3
var 3
let 0
let 1
let 2
```

What to notice:

- `cart.size()` returns `2`, but `cart.count` is `undefined`: `count` lives only in the closure, not as a property, so outside code cannot touch it.
- The three `var` callbacks all print `3`: they share one `i`, which is already `3` when the timers run.
- The three `let` callbacks print `0, 1, 2`: `let` gives each loop iteration its own `j`, so each closure captures a different one.

## Rules and defaults

- **Formed on creation:** a closure forms whenever a function is defined inside another scope, whether or not it is returned.
- **Captures variables, not values:** the closure sees later changes to a captured variable, so timing matters.
- **`let` per iteration:** in a `for` loop, `let` creates a fresh loop variable each turn; `var` keeps one for the whole loop.
- **Memory:** a closure that is still reachable keeps its captured variables alive, so holding closures you no longer need keeps that memory in use.

## Interview Qs

### What is a closure? Give a real use.

A closure is a function bundled with references to the variables of the scope where it was created, so it can keep using them after that scope's function has returned. Real uses: a counter with private state, a factory such as `makeAdder(5)`, event handlers that read outer variables, and debounce helpers that hold a timer id.

### How do you fix the var-in-a-loop bug?

Declare the loop variable with `let` instead of `var`. `let` creates a new binding for each iteration, so each scheduled callback captures its own value. Older code wrapped the loop body in an immediately called function to give each turn its own scope, which has the same effect.
