## Why it exists

Functions often run later, as callbacks or event handlers. A closure lets them still reach the variables of the code that created them, without globals.

## How it works

<Mermaid
  alt="createCart runs and creates a scope holding count. It returns add and size. createCart finishes, but add and size still point to that scope, so count stays alive and private."
  chart={`flowchart LR
  F["createCart() runs"] --> S[("scope: count")]
  F --> R["returns add, size"]
  R -- "still point to" --> S`}
/>

- Scope is lexical: decided by where the function is written, see [scope](card:scope-hoisting).
- The captured variable stays reachable while the inner function does, so outside code cannot touch it.
- Debounce is a closure over a timer id: see [debounce](card:large-lists-and-frequent-events). Stale values inside hooks: see [useEffect](card:use-effect).

## Example

```javascript
function createCart() {
  let count = 0;
  return { add: () => ++count, size: () => count };
}
const cart = createCart();
cart.add();
cart.add();
console.log(cart.size(), cart.count);
```

```text output
2 undefined
```

```javascript
for (var i = 0; i < 3; i++) setTimeout(() => console.log("var", i));
for (let j = 0; j < 3; j++) setTimeout(() => console.log("let", j));
```

```text output
var 3
var 3
var 3
let 0
let 1
let 2
```

## Interview Qs

### What is a closure? Give a real use.

A function bundled with references to its surrounding scope. Real uses: a counter with private state, a factory like `makeAdder(5)`, event handlers that read outer variables, and debounce helpers.

### How do you fix the var-in-a-loop bug?

Declare the loop variable with `let`, which creates a new binding per iteration. Older code wrapped the callback in a function factory to give each one its own scope.
