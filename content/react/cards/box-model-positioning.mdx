## What it is

In CSS, the browser draws every element as a rectangular box. From the inside out that box has four layers: the **content** (the text or image), the **padding** (space inside the border), the **border**, and the **margin** (space outside the border, pushing other boxes away). This is the box model. Two more properties control the box: `display` sets how it joins the page flow, and `position` sets where it sits.

## Why it exists

Most layout bugs come down to two questions: how big is this box, and where does it sit. If you only had one way to size and place boxes, you could not make a label sit beside its value, or pin a status badge to a card corner, or keep a header on screen while the page scrolls. The box model gives a predictable size; `display` and `position` give you the placement choices to answer "where".

## How it works

The `position` value decides how an element is placed and what its `top`, `right`, `bottom` and `left` offsets measure from.

| position | Keeps its space in the flow? | Offsets (top, left) measure from | Dashboard example |
|---|---|---|---|
| static (default) | Yes | Not used; offsets and z-index do nothing | A normal paragraph |
| relative | Yes | Its own normal spot | Anchor for a badge inside a PaymentRow |
| absolute | No | The nearest positioned ancestor | A "Refunded" badge in the row corner |
| fixed | No | The viewport | A header that never scrolls away |
| sticky | Yes | Normal, then sticks inside its scroll box | A column heading that stays while rows scroll |

1. The browser lays out boxes top to bottom in normal flow; `static` and `relative` boxes keep their space.
2. An `absolute` or `fixed` box is lifted out of the flow, so other boxes close the gap it left.
3. For `absolute`, the browser looks up the ancestor chain for the first element that is itself positioned (anything but `static`) and measures the offsets from it.
4. For `fixed`, it measures from the viewport, so the box stays put while the page scrolls.

So the key is that offsets always need a reference, and for `absolute` that reference is the nearest positioned ancestor, not the direct parent.

## Example

This shows why `box-sizing` matters when you set a fixed width on a payment card.

```css
.payment-card { width: 200px; padding: 16px; border: 2px solid; margin: 8px; }
/* Default content-box: visible width = 200 + 2*16 + 2*2 = 236px */

.payment-card { box-sizing: border-box; }
/* border-box: visible width stays 200px; content shrinks to 164px */
```

What to notice:

- With the default `content-box`, `width: 200px` sizes only the content, and padding and border are added on top, so the box is wider than you asked for.
- With `border-box`, the 200px includes the padding and border, so the visible box is exactly 200px and the content area shrinks to fit.
- `margin: 8px` is never part of the width either way; it only pushes neighbouring boxes away.
- Most style resets set `box-sizing: border-box` on everything, because layouts are far easier when `width` means the visible box.

## Rules and defaults

- **Default box-sizing:** `content-box`, where `width` and `height` exclude padding and border. Teams usually override it to `border-box`.
- **fixed reference:** normally the viewport, but if any ancestor has `transform`, `filter` or `perspective` set, `fixed` measures from that ancestor instead.
- **sticky inset:** `sticky` needs an inset such as `top: 0`; without one it behaves like `relative` and never sticks.
- **z-index:** only works on a positioned element (or a flex or grid item); on a `static` box it does nothing.

## Interview Qs

### display: none versus visibility: hidden?

`display: none` removes the box and its children from layout, so nothing takes its space and it is not read by screen readers. `visibility: hidden` only makes it invisible; the box keeps its space in the flow. Use `display: none` to drop an element, `visibility: hidden` to hide it while holding its place.

### Why does z-index sometimes do nothing?

Either the element is not positioned (and is not a flex or grid item), so `z-index` is ignored, or it sits in a different stacking context. A parent with `opacity` below 1, a `transform`, or `position` plus `z-index` starts a new stacking context, and children inside it can only stack against each other, not against boxes outside it.

### What is margin collapsing?

When the bottom margin of one block touches the top margin of the next, they merge into the larger of the two: 20px then 30px gives 30px of gap, not 50px. It happens only for vertical margins of block boxes in normal flow, not for floats, absolutely positioned boxes, or items inside a flex or grid container.
