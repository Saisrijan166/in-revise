## Why it exists

Most layout bugs are about how big a box is and where it sits. The box model gives the size; display and position give the place.

## How it works

| position | Keeps its space in the flow? | Offsets (top, left) are from | Shop example |
|---|---|---|---|
| static (initial) | Yes | Not used; offsets and z-index do nothing | Normal text |
| relative | Yes | Its own normal spot | Anchor for a badge inside a ProductCard |
| absolute | No | The nearest positioned ancestor | "Sale" badge in the card corner |
| fixed | No | The viewport | A header that never scrolls |
| sticky | Yes | Scrolls normally, then sticks inside its scroll container | Cart total that stays visible |

- fixed uses the viewport unless an ancestor has transform, filter or perspective set.
- sticky needs an inset such as `top: 0`; without one it acts like relative.

## Example

```css
.card { width: 200px; padding: 16px; border: 2px solid; margin: 8px; }
/* content-box (initial): visible width = 200 + 2*16 + 2*2 = 236px */

.card { box-sizing: border-box; }
/* border-box: visible width = 200px; content shrinks to 164px */
```

## Interview Qs

### display: none vs visibility: hidden?

display: none removes the box from layout: no space, children hidden too. visibility: hidden only stops drawing it; the space stays.

### Why does z-index sometimes do nothing?

The element is not positioned (nor a flex or grid item), or it is in another stacking context: a parent with opacity below 1, a transform or its own z-index traps it.

### What is margin collapsing?

Touching vertical margins of blocks merge into the larger: 20px and 30px give 30px, not 50px. Not for floats, absolute boxes, or inside flex and grid containers.
