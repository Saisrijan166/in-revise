## Why it exists

When a list changes, React must know which old row matches which new row. Without a reliable name, it may reuse a row's state for a different item.

## How it works

| Key | Result when the list changes |
|---|---|
| `product.id` | Each row keeps its own state and DOM |
| Array index | Rows can swap state after an insert, delete or reorder |
| `Math.random()` | Every row remounts each render; typed input is lost |

- Put the key on the element returned by `map`, not inside the child.
- This is how keys fit into [reconciliation](card:what-is-react).

## Example

```jsx
function ProductList({ products, onAdd }) {
  return (
    <ul>
      {products.map(product => (
        <li key={product.id}>
          <ProductCard product={product} onAdd={onAdd} />
        </li>
      ))}
    </ul>
  );
}
```

## Interview Qs

### Why does React need keys in a list?

Keys let React match items between renders. With them it can move, add or remove the right rows and keep each row's state, instead of guessing by position.

### What goes wrong with the index as key?

Delete the first product and every index shifts. React keeps state by key, so the quantity typed for the old first row now shows on the next product.
