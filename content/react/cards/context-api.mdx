## Why it exists

Passing the same prop through many components that do not use it ([prop drilling](card:lifting-state-up)) is noisy and fragile. Context lets distant components read shared data directly.

## How it works

<Mermaid
  alt="App holds the cart in state and renders CartContext with value cart. Layout and Header sit in between and pass nothing. CartBadge and ProductCard, deep below, each call useContext(CartContext) and get the cart from the closest provider."
  chart={`flowchart TD
  A["App: cart state"] --> P["CartContext value={cart}"]

  H --> B["CartBadge: useContext"]
  L --> C["ProductCard: useContext"]`}
/>

- Middle components (Layout, Header) pass nothing; readers subscribe directly.
- Try plain props or passing JSX as `children` first; context hides where data comes from.

## Example

```jsx
import { createContext, useContext } from 'react';

const CartContext = createContext([]);         // default: used with no provider

function CartBadge() {
  const cart = useContext(CartContext);         // closest provider wins
  return <span>Cart ({cart.length})</span>;
}

export default function App({ cart }) {
  return <CartContext value={cart}><CartBadge /></CartContext>;
}
```

## Interview Qs

### When should you use context, and when not?

Use it for data many distant components need: theme, current user, language, cart. Do not use it just to skip two levels of props; props keep data flow visible. For a large, often-changing app store, compare [Context, Redux and Zustand](compare:context-vs-redux-vs-zustand).

### What does useContext return with no provider above?

The default passed to `createContext`. A provider with `value={undefined}` gives `undefined`, not the default.

### How do you cut re-renders caused by a context?

Wrap the value object in `useMemo` and its functions in `useCallback`, so it changes only when the data changes. Or put state and `dispatch` in separate contexts: `dispatch` never changes, so components that only dispatch skip those re-renders.
