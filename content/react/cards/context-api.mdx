## What it is

Context is a way to pass a value from a component down to any component inside it, no matter how many levels deep, without threading it through each one as a prop. You create a context with `createContext`, wrap part of the tree in its provider to set the value, and any component below reads that value with the `useContext` hook. It is React's built-in answer to prop drilling, where the same prop is forwarded through many components that do not use it themselves.

## Why it exists

A value like the signed-in user or the colour theme is needed in many places across the tree. Without context you pass it as a prop from the top, through every component on the way down, even the ones that only hand it onward. That clutters each component's props and breaks the moment you add a layer in between. Context removes the chain: the value is set once at the top and read directly wherever it is needed.

## How it works

The provider sits high in the tree; readers deep below subscribe to it directly, and the components in between pass nothing.

1. You call `createContext(defaultValue)` once, outside your components, to make the context object.
2. High in the tree you render `<CartContext value={cart}>`, which supplies the value to everything inside it.
3. Any component below calls `useContext(CartContext)` and receives the value from the nearest provider above it.
4. When that provider's value changes, React re-renders every component that read it.

So the key is that readers subscribe to the provider directly, and the layers in between are untouched.

## Example

The dashboard keeps the cart in `App` and lets a deep `CartBadge` read it with no prop passing.

```jsx
import { createContext, useContext } from 'react';

const CartContext = createContext([]);         // default: used where there is no provider

function CartBadge() {
  const cart = useContext(CartContext);         // reads the closest provider's value
  return <span>Cart ({cart.length})</span>;
}

export default function App({ cart }) {
  return <CartContext value={cart}><CartBadge /></CartContext>;
}
```

What to notice:

- `createContext([])` sets a default of `[]`, used only if a `CartBadge` is rendered with no provider above it.
- `<CartContext value={cart}>` is the React 19 provider form; `<CartContext.Provider value={cart}>` does the same.
- `CartBadge` reads the cart with one `useContext` call and never receives it as a prop.
- If `cart` changes, `CartBadge` re-renders, because it read this context.

## Rules and defaults

- **No provider above:** `useContext` returns the default passed to `createContext`. A provider with `value={undefined}` gives `undefined`, not the default.
- **Closest provider wins:** when providers for the same context are nested, a reader gets the value of the nearest one above it.
- **Try props first:** for passing a value down only a level or two, plain props or passing JSX as `children` keep the data flow visible; context hides where the value comes from.

## Not to be confused with

Context is a transport for a value; it is not a store and does nothing to optimise re-renders. A state manager like Redux or Zustand (see [Context vs Redux vs Zustand](compare:context-vs-redux-vs-zustand)) holds the state itself and lets a component read just the slice it needs. Rule: context moves a value down the tree; a store owns the state and controls who re-renders.

## Interview Qs

### When should you use context, and when not?

Use it for data many distant components need: theme, the current user, routing, or reducer state. Do not reach for it just to skip one or two levels of props, since props keep the data flow visible. For a large, frequently changing store, a dedicated state manager suits better.

### Why can context cause performance problems?

Every component that reads a context re-renders whenever the provider's value changes, and `React.memo` does not stop that. If the value is an object created inline, it is a new reference each render, so all readers re-render even when nothing really changed.

### How do you cut re-renders caused by a context?

Memoize the value with `useMemo` and its functions with `useCallback` so the reference stays stable. Or split state and `dispatch` into two contexts: `dispatch` is stable, so components reading only it are not re-rendered when the state changes.
