## Why it exists

Guessing wastes effort. Measuring shows which render, task or file is slow; Core Web Vitals show what real users feel.

## How it works

| Core Web Vital | Measures | Good (75th percentile) |
|---|---|---|
| [LCP](card:lcp) | Loading: largest image or text in view | ≤ 2.5 s |
| [INP](card:inp) | Response to clicks, taps and keys | ≤ 200 ms |
| [CLS](card:cls) | Visual stability: unexpected layout shifts | ≤ 0.1 |

- INP replaced FID as a Core Web Vital on 12-03-2024.
- Lighthouse cannot measure INP (no real user); it reports Total Blocking Time instead.
- Test with CPU throttling: your machine is faster than most users'.

## Example

```html
<img src="/img/mouse-400.webp" alt="Wireless Mouse"
     srcset="/img/mouse-400.webp 400w, /img/mouse-800.webp 800w"
     sizes="(max-width: 600px) 100vw, 400px"
     width="400" height="400" loading="lazy">
```

## Defaults

| What | Default | Where |
|---|---|---|
| `loading` | `eager` | HTML `<img>` |
| `loading` | `lazy` | `next/image`, Next.js 16 |
| `formats` | `['image/webp']` | `next/image`, Next.js 16 |
| `preload` | `false`; replaces `priority`, deprecated | `next/image`, Next.js 16 |

## Interview Qs

### How do you find why a React page is slow?

Record with the React DevTools Profiler to see which components render and how long they take, and use the browser Performance panel for long tasks. Fix the biggest cost first, then measure again.

### Which Core Web Vitals do you know?

LCP for loading, INP for responsiveness and CLS for visual stability. Good is LCP 2.5 s, INP 200 ms and CLS 0.1 or less at the 75th percentile.

### How do images hurt performance, and how do you fix it?

Large files slow LCP; missing sizes cause layout shift. Serve WebP or AVIF sized with srcset, set width and height, lazy-load below the fold, and load the LCP image eagerly.
