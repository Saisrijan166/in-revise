## Why it exists

JavaScript has one thread, yet it must wait for timers, network and clicks without freezing. The event loop runs waiting callbacks one at a time, in a fixed order.

## How it works

<Steps label="One turn of the browser event loop">
  <Step title="Run one task">The script, a timer callback or an event handler runs until the stack is empty.</Step>
  <Step title="Drain microtasks">Every queued microtask runs, including ones added meanwhile.</Step>
  <Step title="Render">The browser may update the screen.</Step>
  <Step title="Next task">Take the oldest task from a task queue and repeat.</Step>
</Steps>

<Compare id="microtask-vs-macrotask" />

- Long tasks hurt responsiveness, measured as [INP](card:measuring-performance).

## Example

```javascript
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
(async () => {
  console.log("D");
  await null;
  console.log("E");
})();
console.log("F");
```

```text output
A
D
F
C
E
B
```

## Interview Qs

### Why does D print before F?

An async function runs synchronously until its first `await`. Only the code after `await` is queued, as a microtask, so E waits.

### Can a microtask starve the page?

Yes. The loop drains microtasks until the queue is empty, so a microtask that keeps queueing more blocks timers, input and rendering.
