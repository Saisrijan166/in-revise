## What it is

An Effect is code that runs because a component is on screen, not because the user did something. You write it with the `useEffect` hook. It is meant for talking to systems outside React: starting a timer, opening a network connection, or subscribing to a browser event. React runs the Effect after the component has been drawn, and runs it again whenever a value it depends on changes.

## Why it exists

Rendering must stay pure: a component should only look at its props and state and return JSX, with no side effect. But a real app also has to connect to a chat server, poll for new data, or set a timer, and that work has to happen at some point tied to the component being shown. Without Effects you would have nowhere safe to put it. `useEffect` gives it a slot that runs after render and, through its cleanup, a matching slot to undo it.

## How it works

The dependency array is the control: it tells React which renders should run the Effect again.

| Dependency array | When the Effect runs |
|---|---|
| None given | After every render |
| `[]` (empty) | Once after mount; cleanup on unmount |
| `[productId]` | After mount, then whenever `productId` changes |

1. React renders the component and paints it to the screen.
2. It then runs the Effect's setup function.
3. Before the next run, and when the component is removed, React runs the cleanup function you returned.
4. On a re-render it compares each dependency with the last render using `Object.is`; if any changed, it runs cleanup then setup again.

So the key is that each Effect captures the values from its own render; a value you read but leave out of the array stays frozen at an old value (a stale closure).

## Example

In the payments dashboard, a stock badge polls an API every five seconds while it is shown, and stops cleanly when it is removed or the product changes.

```jsx
import { useEffect } from 'react';

function StockBadge({ productId }) {
  useEffect(() => {
    const id = setInterval(() => refreshStock(productId), 5000);
    return () => clearInterval(id);   // cleanup: before the next run and on unmount
  }, [productId]);                    // re-run only when productId changes
  return <span>Checking stock…</span>;
}
```

What to notice:

- The setup starts the interval; the returned function clears it, so the two always pair up.
- `productId` is listed because the Effect reads it; when it changes, React clears the old interval and starts one for the new product.
- Drop the cleanup and each product change would leave its interval running, so several timers would pile up.
- With Strict Mode in development React runs setup, cleanup, setup once on mount; the `clearInterval` cleanup makes that harmless.

## Rules and defaults

- **Timing:** by default an Effect runs after the browser paints. `useLayoutEffect` runs before paint, blocking it, for cases like measuring an element to avoid a flicker; prefer `useEffect`.
- **Dependencies:** `exhaustive-deps` (in `eslint-plugin-react-hooks`) warns when you read a value but leave it out of the array.
- **Non-reactive logic:** code inside an Effect that should read the latest value but not re-trigger it can move into `useEffectEvent` (an Effect Event, added in React 19.2).
- **Not for derived values:** compute them during render instead; not for user actions, which belong in event handlers.

## Common mistakes

- **"useEffect is where I fetch data."** It works, but raw fetches race and leak; prefer a framework loader or a library, and always handle the stale-response case (see [data fetching](card:data-fetching)).
- **Empty deps to "run once" while reading props.** `[]` freezes those props at their first value; list what you read, or you get a stale closure.

## Interview Qs

### When do you not need an Effect?

To compute a value from props or state: write `const total = price * quantity` during render, not `setTotal` in an Effect, which costs an extra render. And for user actions: run them in the event handler that fired, not in an Effect watching the result.

### What is a stale closure in an Effect, and how do you fix it?

An interval set up with `[]` that calls `setCount(count + 1)` keeps seeing the first `count`, because the Effect captured that render's value. Fix it by listing every value you read as a dependency, or by using the updater form `setCount(c => c + 1)`, which needs no dependency.

### Why does an Effect run twice on mount in development?

React Strict Mode intentionally runs setup, cleanup, then setup again to reveal missing cleanup. It happens only in development. If your cleanup correctly undoes the setup, the double run is invisible and production runs it once.
