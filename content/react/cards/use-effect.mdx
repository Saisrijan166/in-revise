## Why it exists

Some work must happen because a component is on screen, not because of a click: a timer, a subscription, a connection. Rendering must stay pure, so this work goes in an Effect.

## How it works

| Dependency array | When the effect runs |
|---|---|
| None | After every render (commit) |
| `[]` | Once after mount; cleanup on unmount |
| `[productId]` | After mount, then whenever `productId` changes |

- Each render's effect sees that render's values. A missing dependency leaves it reading old ones: a stale closure.
- Data fetching races (old responses arriving last) are handled in [data fetching](card:data-fetching).

## Example

```jsx
import { useEffect } from 'react';

function StockBadge({ productId }) {
  useEffect(() => {
    const id = setInterval(() => refreshStock(productId), 5000);
    return () => clearInterval(id);   // cleanup: before the next run and on unmount
  }, [productId]);                    // re-run only when productId changes
  return <span>Checking stock…</span>;
}
```

## Interview Qs

### When do you not need an Effect?

To compute a value from props or state: write `const total = price * quantity` during render, not `setTotal` in an Effect, which costs an extra render (see [derived state](card:use-state)). And for user actions: put them in the event handler.

### What is a stale closure in an effect, and how do you fix it?

An interval set up with `[]` that calls `setCount(count + 1)` keeps seeing the first `count`. List every value you read as a dependency, or use the updater form `setCount(c => c + 1)` so the effect needs no dependency.

### useEffect vs useLayoutEffect?

`useEffect` usually runs after the browser paints. `useLayoutEffect` runs before paint, blocking it, so you can measure layout (a tooltip's height) without a flicker. Prefer `useEffect`.
