## Why it exists

Nested callbacks for each async step become "callback hell", with error handling at every level. Promises chain the steps flat, and async / await reads like synchronous code.

## Example

```javascript
async function loadProducts(query) {
  const response = await fetch(`/api/products?q=${encodeURIComponent(query)}`);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

const [mouse, cable] = await Promise.all([loadProducts("mouse"), loadProducts("cable")]);
```

```javascript
const wait = (ms, v) => new Promise((ok) => setTimeout(() => ok(v), ms));
const found = Promise.resolve("Wireless Mouse");
const failed = Promise.reject(new Error("HTTP 404"));
const settled = await Promise.allSettled([found, failed]);
console.log(settled.map((r) => r.status));
try {
  await Promise.all([found, failed]);
} catch (e) {
  console.log("all rejected:", e.message);
}
console.log(await Promise.any([failed, found]));
console.log(await Promise.race([wait(50, "slow"), wait(10, "fast")]));
```

```text output
[ 'fulfilled', 'rejected' ]
all rejected: HTTP 404
Wireless Mouse
fast
```

## Interview Qs

### Why check response.ok after fetch?

The `fetch` promise rejects only when the request itself fails, such as a network error. A 404 or 500 still fulfils, so you must check `response.ok` or `response.status` and throw yourself.

### Promises vs callbacks?

Promises chain flat instead of nesting, send any error to one `catch`, and combine with `Promise.all`. A callback API makes you handle errors at every level.

### What does an async function return?

Always a promise. A returned value becomes the fulfilled value; a thrown error becomes the rejection.
