## What it is

A promise is an object that stands for a value not ready yet, such as a network request's result. It is in one of three states: pending while the work runs, then either fulfilled with a value or rejected with an error. It settles once and never changes. An [async function](term:async-function) always returns a promise, and `await` inside it pauses until a promise settles, then hands back its value. This builds on the [event loop](card:event-loop): the pause does not block the page; other work runs meanwhile.

## Why it exists

Before promises, each step that took time (load a payment, then load its customer, then its card) was a function you passed in, a callback. Chaining several meant nesting callbacks inside callbacks, with error handling repeated at every level, which was hard to read and easy to get wrong. Promises let you chain the steps as a flat list with one error handler, and async / await lets you write that chain as ordinary top-to-bottom code.

## How it works

1. You call something that returns a promise, such as `fetch`. The promise starts pending and your code keeps running.
2. When the work finishes, the promise settles: fulfilled with a value, or rejected with an error.
3. `await` makes the async function wait at that line until the promise settles, then continues with the value, or throws the error so a surrounding `try / catch` can handle it.
4. To run several independent calls together, you start them all first and then `await Promise.all([...])`, so they overlap instead of running one by one.

So the key is that `await` pauses only that one call; to go parallel you start the calls before you await them.

## Example

The payments dashboard loads two product lists. Doing them with `Promise.all` makes both requests at once instead of waiting for the first to finish.

```javascript
async function loadProducts(query) {
  const response = await fetch(`/api/products?q=${encodeURIComponent(query)}`);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

const [mice, cables] = await Promise.all([loadProducts("mouse"), loadProducts("cable")]);
```

What to notice:

- `await fetch(...)` pauses `loadProducts` until the response headers arrive; the page stays responsive meanwhile.
- `if (!response.ok) throw` is needed because fetch fulfils even on a 404 or 500. Without this line, a failed request looks like success.
- `Promise.all([a, b])` starts both calls, then waits for both; the two requests overlap. Writing `await loadProducts("mouse"); await loadProducts("cable");` instead would run them one after the other.

## Rules and defaults

- **Settles once:** a promise moves from pending to fulfilled or rejected one time; later resolve or reject calls are ignored.
- **async always returns a promise:** even `async () => 5` returns a promise that fulfils with `5`. Returning a promise does not wrap it twice.
- **fetch (browser):** its promise rejects only on a network error, a bad URL or an aborted request. HTTP error statuses (404, 500) fulfil, so you check `response.ok`.
- **Unhandled rejection:** a rejected promise with no `.catch` or surrounding `try / catch` triggers an `unhandledrejection` event and logs a warning.

## Interview Qs

### Why do you check response.ok after fetch?

The fetch promise rejects only when the request itself fails, such as a lost network or an aborted call. An HTTP 404 or 500 is still a completed response, so the promise fulfils. To treat those statuses as errors you must read `response.ok` or `response.status` and throw yourself.

### How do promises improve on callbacks?

Callbacks nest one level per async step, and you handle errors at every level, which is hard to follow. Promises chain the steps as a flat list, send any error to a single `catch`, and let you combine several with `Promise.all`. async / await then lets you write that chain as plain sequential code.

### What does an async function return, and what happens when it throws?

It always returns a promise. A value you return becomes the promise's fulfilled value; an error you throw becomes its rejection. So the caller handles both with `.then` / `.catch`, or with `await` inside a `try / catch`.
