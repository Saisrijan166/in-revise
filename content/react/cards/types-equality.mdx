## What it is

Every JavaScript value is either a primitive or an object. The seven [primitives](term:primitive-js) are string, number, bigint, boolean, undefined, symbol and null; they are plain values compared by their content. Everything else, including arrays and functions, is an object, compared by reference: two objects are equal only when they are the exact same object in memory. [Type coercion](term:type-coercion) is JavaScript quietly converting a value to another type, which it does in `==`, `+` and inside an `if`. `===` compares without any conversion; `==` converts first.

## Why it exists

JavaScript was built to be forgiving, so it converts types on its own rather than raising an error. That is why `"3" * 2` gives `6` and `if ([])` runs. These rules are not optional: they decide the outcome of nearly every "what does this print?" puzzle and cause real bugs, such as a quantity of `0` being treated as missing. Knowing which values are falsy and how `==` converts lets you predict the result and reach for `===` to avoid the surprises.

## How it works

<Compare id="loose-vs-strict-equality" />

1. With `===`, if the two values are different types the answer is immediately `false`; if the same type, it compares them directly (two objects only match when they are the same reference).
2. With `==`, JavaScript first converts the values toward a common type (for example a boolean or an array becomes a number) and then compares, which is why `0 == ""` is `true`.
3. In an `if`, or with `!`, the value is converted to a boolean. Only the [falsy](term:falsy) values become `false`; every object, even `[]`, becomes `true`.
4. `NaN` is never equal to anything, including itself, so you test it with `Number.isNaN(x)`, and `typeof null` returns `"object"`, so you test for null with `x === null`.

## Example

This logs a few comparisons so the coercion rules are visible instead of memorised.

```javascript
console.log(typeof null, typeof NaN, typeof function () {});
console.log(0 == "", null == undefined, null == 0);
console.log("1" + 2, "3" * 2, [] == false);
console.log(NaN === NaN, Number.isNaN(NaN), Object.is(NaN, NaN));
console.log([] === [], Boolean([]), Boolean(""));
```

```text output
object number function
true true false
12 6 true
false true true
false true false
```

What to notice:

- `typeof null` is `"object"` and `typeof NaN` is `"number"`: both are long-standing quirks, not what the name suggests.
- `0 == ""` is `true` but `null == 0` is `false`: `null` only loosely equals `null` and `undefined`, nothing else.
- `"1" + 2` is `"12"` because `+` with a string joins text, while `"3" * 2` is `6` because `*` forces numbers.
- `[] === []` is `false`: they are two different arrays. `Boolean([])` is `true`, so an empty array is truthy.

## Rules and defaults

- **Primitives by value, objects by reference:** `1 === 1` is true; two separate arrays with the same contents are never `===`.
- **The eight falsy values:** `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. Everything else is truthy.
- **`==` null check:** `x == null` is `true` for exactly `null` and `undefined`, which is the one broadly recommended use of `==`.
- **Testing NaN:** use `Number.isNaN(x)`. The global `isNaN` converts its argument first, so `isNaN("abc")` is `true`; `Object.is(NaN, NaN)` is also `true`.

## Not to be confused with

`undefined` and `null` both mean "no value", but differently: `undefined` is what you get from a variable that was never assigned or a missing property, while `null` is a value you set on purpose to mean "empty". Rule: `undefined` is the absence JavaScript gives you; `null` is the absence you choose.

## Interview Qs

### How do you reliably check for NaN?

Use `Number.isNaN(x)`. `NaN` is the only value not equal to itself, so `x === NaN` is always `false`. The older global `isNaN` first coerces its argument to a number, so `isNaN("abc")` wrongly returns `true`; `Number.isNaN` does no conversion.

### Why is typeof null "object", and how do you work around it?

It is a bug from the first version of JavaScript that could not be fixed without breaking existing code, so it stayed. To check for null specifically, use `x === null`; to allow both null and undefined, use `x == null`.

### When would you ever use == instead of ===?

Almost never, with one common exception: `x == null`. Because `==` treats `null` and `undefined` as equal to each other and nothing else, `x == null` is a short, safe way to catch both "no value" cases in one check.
