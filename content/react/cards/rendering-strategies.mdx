## Why it exists

A blank page waiting for JavaScript shows late and is harder for crawlers to read. Where and when HTML is built trades speed, freshness and server cost.

## How it works

<Compare id="csr-vs-ssr-vs-ssg-vs-isr" />

- [Hydration](card:hydration) attaches React to server HTML with `hydrateRoot`.
- [Streaming SSR](card:streaming-ssr) sends HTML in chunks, so the browser paints before the slowest data arrives.
- Server HTML speeds the first paint; heavy hydration JS can hurt INP. [Measure both](card:measuring-performance).

## Example

```jsx
// app/products/[id]/page.jsx (Next.js 16.4, Cache Components, plus a loading.jsx)
import { cacheLife } from 'next/cache';

async function getProduct(id) {
  'use cache';
  cacheLife('hours'); // ISR: after an hour, serve stale and refresh in the background
  return fetch(`https://shop.example/api/products/${id}`).then((r) => r.json());
}
export async function generateStaticParams() {
  return [{ id: '1' }, { id: '2' }]; // prerendered at build time; others on first visit
}
export default async function ProductPage({ params }) {
  const product = await getProduct((await params).id);
  return <h1>{product.name}: ₹{product.price}</h1>;
}
```

## Interview Qs

### What is hydration, and what causes a mismatch?

Hydration attaches React and its event handlers to server HTML. A mismatch happens when the first client render differs: `typeof window` checks, browser-only APIs, timestamps or different data. Fix it like a bug; show client-only values after an Effect.

### Which rendering would you pick for an online shop?

Product pages: ISR, fast and refreshed hourly. Search results: SSR, per query. Cart: CSR in a Client Component. Help pages: SSG.

### Is SSR always faster than CSR?

No. SSR usually paints sooner, but a render per request can raise TTFB, and clicks still wait for hydration. Static HTML from a CDN skips the render cost.
