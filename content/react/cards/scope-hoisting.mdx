## Why it exists

JavaScript must know which variable a name means and when it exists. The three keywords answer that differently, and interviewers test the difference with "what prints?" snippets.

## How it works

<Compare id="let-vs-const-vs-var" />

- A lookup walks the [scope chain](card:scope-chain) outward until it finds the name.
- Functions remember the scope they were created in: that is a [closure](card:closures).

## Example

```javascript
console.log(price);
var price = 799;
console.log(addToCart());
function addToCart() { return "added"; }
try { console.log(total); } catch (e) { console.log(`${e.name}: ${e.message}`); }
let total = 0;
const cart = [];
cart.push("Wireless Mouse");
console.log(cart);
```

```text output
undefined
added
ReferenceError: Cannot access 'total' before initialization
[ 'Wireless Mouse' ]
```

## Interview Qs

### What is hoisting?

Declarations are set up before the code runs. Function declarations are usable early; `var` reads `undefined`; `let`, `const` and `class` exist but throw ReferenceError until their line runs.

### Can you change a const array?

Yes. `const` fixes the binding, not the value: `push` works, `cart = []` throws TypeError. For a read-only object use `Object.freeze`, which is shallow.

### Why avoid var?

It ignores block scope, so a `var` in an `if` or loop leaks into the whole function, and it allows silent redeclaration.
