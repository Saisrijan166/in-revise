## What it is

A **scope** is the region of code where a name is visible. When you read a name, JavaScript looks for it in the current scope, then in the scope around that, and so on outward. **Hoisting** means the names declared in a scope are set up before the code in that scope runs, so a name can exist on a line above its own declaration. The three keywords `var`, `let` and `const` choose which scope a variable lives in and how it behaves before its line runs.

## Why it exists

A program needs clear rules for which variable a name refers to, and `var` had confusing ones: a `var` written inside an `if` or a loop was visible across the whole function, so loops and blocks leaked variables and caused bugs. ECMAScript 2015 added `let` and `const`, which live only inside their `{ }` block. This keeps each variable close to where it is used, and makes using a name too early an error instead of a silent `undefined`.

## How it works

The difference is clearest side by side.

<Compare id="let-vs-const-vs-var" />

1. Before a block runs, JavaScript reserves every name declared in it (this is hoisting).
2. A `var` name is reserved for the whole function and given the value `undefined` straight away, so reading it before its line gives `undefined`.
3. A `let` or `const` name is reserved for its block but left uninitialised. From the top of the block to its declaration line it is in the **temporal dead zone**, and reading it throws `ReferenceError`.
4. When a name is read, the lookup walks the [scope chain](card:scope-chain) outward until it finds the name.

So the key is: `var` fails quietly with `undefined`, while `let` and `const` fail loudly so you catch the mistake.

## Example

This prints how each keyword behaves before and after its line. The output comes from running it with Node.

```javascript
console.log(price);               // var, read before its line
var price = 799;
console.log(addToCart());         // function declaration, callable early
function addToCart() { return "added"; }
try { console.log(total); }       // let, read before its line
catch (e) { console.log(`${e.name}: ${e.message}`); }
let total = 0;
const cart = [];
cart.push("Wireless Mouse");      // changing the array is allowed
console.log(cart);
```

```text output
undefined
added
ReferenceError: Cannot access 'total' before initialization
[ 'Wireless Mouse' ]
```

What to notice:

- `price` is already reserved, so reading it before its line gives `undefined`, not an error.
- A function declaration is fully hoisted, so `addToCart()` runs before the line that defines it.
- `total` is in its temporal dead zone, so reading it throws `ReferenceError`.
- `cart.push(...)` works even though `cart` is `const`: `const` fixes the name, not the array it holds.

## Rules and defaults

- **Block scope:** `let` and `const` are visible only inside the nearest `{ }`; `var` is visible in the whole enclosing function.
- **Must initialise `const`:** a `const` declaration without a value is a `SyntaxError`; `let` and `var` may be declared without one.
- **Reassignment:** reassigning a `const` throws `TypeError`; `let` and `var` allow it.
- **Redeclaring:** declaring the same name twice with `let` or `const` in one scope is a `SyntaxError`; `var` allows it silently.
- **Global script:** at the top level of a classic script a `var` becomes a property of `globalThis`; `let` and `const` do not.

## Interview Qs

### What is hoisting?

Declarations are set up before the code in their scope runs. A function declaration is fully usable early. A `var` is reserved and set to `undefined`, so reading it early gives `undefined`. A `let`, `const` or `class` is reserved but left in the temporal dead zone, so reading it before its line throws `ReferenceError`.

### Can you change a const array?

Yes. `const` fixes the binding, so `cart = []` throws `TypeError`, but `cart.push(...)` changes the existing array and is allowed. To make the array itself read-only, use `Object.freeze`, which is shallow: it does not freeze nested objects.

### Why avoid var?

It ignores block scope, so a `var` inside an `if` or loop leaks into the whole function and can be read before its line as `undefined`. It also allows silent redeclaration of the same name, which hides bugs. `let` and `const` are block-scoped and fail loudly instead.
