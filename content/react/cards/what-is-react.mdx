## What it is

React is a JavaScript library for building user interfaces out of small, reusable pieces called components. You do not change the page by hand. Instead you describe, for the current data, what the UI should look like, and React makes the real [DOM](card:how-browsers-render) match that description. This way of working is called **declarative**: you write the result you want, not the step-by-step DOM instructions to reach it.

## Why it exists

Without React, you update the page by hand: find a node, set its text, add a row, remove another. As an app grows, you have many such edits, triggered in many orders, and keeping the screen correct for every combination becomes hard and buggy. React removes this: you describe the whole UI for the current state in one place, and React works out which DOM changes are needed. You stop tracking "what to change" and only say "what it should be".

## How it works

React keeps an in-memory tree of elements, the **virtual DOM**, describing the UI. When state changes, one update flows through these phases:

<Steps label="One update in React">
  <Step title="Trigger">The first render, or a state update in a component or one of its parents, starts the update.</Step>
  <Step title="Render">React calls your component functions and builds a new element tree for the current state.</Step>
  <Step title="Reconcile">React compares (diffs) the new tree against the previous one to find what changed.</Step>
  <Step title="Commit">React applies only the needed changes to the real DOM, and then the browser paints.</Step>
</Steps>

The diff follows two rules: if an element keeps the same type, React reuses its DOM node and updates only the changed attributes; if the type is different, React tears down that subtree and builds a new one, losing its state. So the key is that React always does the smallest DOM update that makes the page match your description.

## Example

Browsers cannot run [JSX](card:components-jsx-props) (the HTML-like syntax you will write in React), so a compiler turns each tag into a function call. This is the real output of the esbuild compiler for one button:

```jsx
<button className="add" onClick={addToCart}>Add to cart</button>
```

```text output
import { jsx } from "react/jsx-runtime";
/* @__PURE__ */ jsx("button", { className: "add", onClick: addToCart, children: "Add to cart" });
```

What to notice:

- The tag becomes a `jsx(...)` call that returns a plain JavaScript object describing the element. That object, not real HTML, is what React works with.
- The attributes (`className`, `onClick`) and the text become fields on that object. React reads them later to build or patch the real DOM node.
- Because an element is just an object, building and comparing a whole tree of them is ordinary JavaScript, which is how reconciliation can run before any DOM is touched.

## Rules and defaults

- **Element type decides reuse:** same type at the same position means the DOM node is reused; a different type means the subtree is rebuilt and its state is lost (React 19).
- **Re-render is not DOM rebuild:** a re-render re-runs your component and produces a new element tree; the real DOM changes only where the diff found a difference. See [re-renders](card:re-renders).
- **Diffing is roughly O(n):** React compares trees in one pass using the type-and-[key](card:lists-and-keys) heuristics, not a slow full tree comparison.

## Not to be confused with

The **virtual DOM** is React's in-memory tree of element objects. The **real DOM** is the browser's live tree of nodes that is actually on screen. **Reconciliation** is the diffing step that decides how to change the real DOM so it matches the virtual one. Rule: virtual DOM = description, reconciliation = the diff, real DOM = the result.

## Interview Qs

### What is the virtual DOM, and is it faster than the real DOM?

The virtual DOM is React's in-memory tree of element objects describing the UI. It is not inherently faster: React still makes the same real DOM changes, plus the cost of building and diffing trees. Its value is the declarative API, which replaces manual DOM edits with a minimal automatic patch.

### How does reconciliation work?

React diffs the new element tree against the previous one in roughly O(n) using two heuristics: an element of a different type means that subtree is rebuilt, and [keys](card:lists-and-keys) match list items between renders. It then commits only the DOM changes the diff found.

### What is JSX and how does it become JavaScript?

JSX is HTML-like syntax written inside JavaScript. A compiler such as Babel or esbuild turns each tag into a `jsx(...)` call that returns a plain element object describing the UI. The browser runs that JavaScript; React later turns the element objects into real DOM.
