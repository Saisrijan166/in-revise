## Why it exists

A page is easier to build and reuse as small pieces: ProductCard, ProductList, Cart. Props let one component work for every product.

## How it works

| JSX rule | Write | Not |
|---|---|---|
| One root | `<>...</>` or one wrapper | two siblings at the top |
| Close every tag | `<img />` | `<img>` |
| camelCase attributes | `className`, `strokeWidth`, `onClick` | `class`, `stroke-width`, `onclick` |
| JavaScript inside | `{product.name}` | `"product.name"` |

- `aria-*` and `data-*` attributes keep their dashes.
- A default like `{ qty = 1 }` applies only when the prop is missing or `undefined`, not `null`.
- `{cond ? <A /> : <B />}` picks one; `return null` renders nothing.

## Example

```jsx
function ProductCard({ product, onAdd }) {
  return (
    <div className="card">
      <h3>{product.name}</h3>
      <p>₹{product.price}</p>
      <button onClick={() => onAdd(product.id)}>Add to cart</button>
    </div>
  );
}

<ProductCard product={{ id: 1, name: 'Wireless Mouse', price: 799 }} onAdd={addToCart} />
```

## Interview Qs

### What is the difference between props and state?

Props come from the parent and are read-only. State is the component's own memory and changes with a setter. See [state vs props](compare:state-vs-props).

### How does a child send data to its parent?

The parent passes a function as a prop, such as `onAdd={addToCart}`. The child calls it with the data; the parent updates its state, and the new value flows back down as props.

### What are Fragments and why use them?

`<>...</>` groups several elements without adding a wrapper node to the DOM. Use `<Fragment key={id}>` when a list item needs a key.
