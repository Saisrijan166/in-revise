## What it is

`useState` is a React Hook that gives a component its own memory, called **state**. You call it with the starting value and it returns a pair: the current value and a **setter** function. Calling the setter is how you ask React to change that value. Unlike a plain variable, state survives between renders, and changing it tells React to render the component again.

## Why it exists

A plain local variable cannot do what a UI needs. It starts again from scratch on every render, so it forgets anything the user did, and assigning to it does not update the screen, because nothing tells React to re-render. State fixes both: React keeps the value between renders, and calling the setter both stores the new value and schedules a fresh render where that value is shown. Without state, a counter or a form could not remember or display its own data.

## How it works

The important idea is that the setter does not change the value in place; it queues a new render:

<Steps label="What happens after a click">
  <Step title="Set">The click handler calls setQty; React stores the requested value and marks the component to re-render.</Step>
  <Step title="Batch">React waits until the whole handler has finished before rendering, so several setter calls become one render.</Step>
  <Step title="Re-render">React calls the component function again, and this time useState returns the new value.</Step>
  <Step title="Commit">React updates the DOM, so the new quantity appears on screen.</Step>
</Steps>

So the key is that within one render the state value is a fixed snapshot. The variable you read holds the value from when this render started; the new value exists only in the next render.

## Example

The first handler reads the snapshot twice; the second uses the updater form so each call sees the latest value.

```jsx
const [qty, setQty] = useState(1);
const total = qty * product.price;      // derived from state, not stored as state

function addTwo() {
  setQty(qty + 1);
  setQty(qty + 1);                      // both read the snapshot qty = 1, so qty becomes 2
}
function addTwoSafely() {
  setQty(q => q + 1);
  setQty(q => q + 1);                   // each updater gets the latest value: 1 → 2 → 3
}
```

What to notice:

- `total` is computed during render from `qty`, not kept in its own state. Derived values should be recomputed, not stored, or the copy can drift out of date.
- In `addTwo`, both `setQty(qty + 1)` calls read the same snapshot `qty = 1`, so the final value is `2`, not `3`.
- In `addTwoSafely`, each `q => q + 1` receives the latest queued value, so two calls add two, giving `3`.
- Reach for the updater form whenever the next value depends on the previous one.

## Rules and defaults

- **Automatic batching:** multiple setter calls in one handler produce a single re-render; since React 18 this also applies inside timeouts, promises and native event handlers (before 18, only React event handlers were batched).
- **Change detection:** React compares the old and new value with `Object.is`; a mutated object or array keeps the same reference, so React may skip the render. Create a new one with spread, `map` or `filter`.
- **Lazy initial state:** `useState(() => expensiveInit())` runs the function only on the first render, not on every render.
- **Do not copy props into state:** a prop copied into state stops following the prop; read the prop directly instead.

## Not to be confused with

**State** is a component's own data that it can change with its setter. **Props** are inputs from the parent that the component only reads (see [state vs props](compare:state-vs-props)). **Derived values**, like a cart total, are computed from state during render and are not state themselves. Rule: store the smallest source of truth in state, and compute everything else from it.

## Interview Qs

### Why does console.log right after calling the setter print the old value?

Because state is a snapshot for the current render. The setter only queues the change and schedules a new render; it does not reassign the variable you are holding. The new value becomes visible when the component runs again on the next render, so a log in the same handler still shows the old value.

### What is automatic batching?

React groups several state updates into one re-render instead of rendering after each one. It waits until the event handler finishes, then applies all queued updates together. Since React 18 this batching also covers updates inside timeouts, promises and native event handlers, so you get one render where older versions did several.

### Why must you not mutate state directly?

React decides whether to re-render by comparing the old and new value with `Object.is`. If you mutate an object or array, the reference stays the same, so React sees no change and may skip the render, leaving the screen stale. Always pass a new object or array, built with spread, `map` or `filter`.
