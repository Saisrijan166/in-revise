## Why it exists

Each render creates new objects and functions and repeats every calculation. Memoization reuses the last result so a slow calculation or a slow child is skipped when nothing really changed.

## How it works

<Compare id="usememo-vs-usecallback-vs-memo" />

- Dependencies are compared one by one with `Object.is`; any change recomputes.
- With React Compiler on (Next.js 16: `reactCompiler: true`, off by default), keep manual hooks as escape hatches.

## Example

```javascript
const a = { name: 'Wireless Mouse', price: 799 };
const b = { name: 'Wireless Mouse', price: 799 };
console.log(a === b, Object.is(a, a));     // compared by reference
const makeHandler = () => () => {};        // a new function each call
console.log(makeHandler() === makeHandler());
```

```jsx
import { memo, useCallback, useMemo } from 'react';

const ProductCard = memo(function ProductCard({ product, onAdd }) {
  return <button onClick={() => onAdd(product)}>Add {product.name}</button>;
});

export function ProductList({ products, query, setCart }) {
  const visible = useMemo(() => products.filter((p) => p.name.includes(query)), [products, query]);
  const addToCart = useCallback((p) => setCart((c) => [...c, p]), [setCart]);
  return visible.map((p) => <ProductCard key={p.id} product={p} onAdd={addToCart} />);
}
```

## Interview Qs

### Why does my memo child still re-render?

A prop is a new object or function each render, so `Object.is` sees a change. Pass stable values with `useMemo` or `useCallback`, or pass plain values. Its own state or a context it reads also re-renders it.

### Does useCallback stop the function being created?

No. The function is still created each render; React just returns the cached one while dependencies are unchanged.

### Do you still need these hooks with React Compiler?

Mostly no: the compiler memoizes components and values at build time. Keep them where you need exact control, such as a value used as an effect dependency.
