## What it is

Memoization means keeping the result of some work and reusing it while the inputs are the same, instead of doing the work again. React has three tools for it. `useMemo` caches a value a component calculated. `useCallback` caches a function the component created. `React.memo` wraps a child so it skips its [re-render](card:re-renders) when its props have not changed. All three answer "did the input change?" the same way, which is the key to using them.

## Why it exists

Every time a component runs, it rebuilds its objects and functions and repeats its calculations. If a component filters a large payment list on each render, that filtering runs again even when the list and the filter did not change. And a child that re-renders with the same data still does its work. Memoization lets React skip the repeat: reuse the old filtered list, reuse the old handler, skip the unchanged child.

## How it works

The three tools differ in what they cache, but all compare their inputs with `Object.is`.

<Compare id="usememo-vs-usecallback-vs-memo" />

1. On each render, React compares this render's inputs with the last render's, one by one, using `Object.is`.
2. `Object.is` compares by reference for objects and functions: two objects with the same fields are still different values. So a new `{}` or `() => {}` created during render always counts as a change.
3. If every input is unchanged, React reuses the stored value, function or child output and does no new work.
4. If any input changed, it redoes the work and stores the new result.

So the key is keeping inputs stable: a `React.memo` child only skips if the props passed to it are the same references as last time.

## Example

Objects and functions are compared by reference, which is why a fresh one each render looks like a change.

```javascript
const a = { id: 1, status: 'failed' };
const b = { id: 1, status: 'failed' };
console.log(a === b, Object.is(a, a)); // same fields, but different objects
const makeHandler = () => () => {};    // builds a new function each call
console.log(makeHandler() === makeHandler());
```

```text output
false true
false
```

Now the payments dashboard keeps a memo row's props stable so the row can skip.

```jsx
import { memo, useCallback, useMemo } from 'react';

const PaymentRow = memo(function PaymentRow({ payment, onRefund }) {
  return <button onClick={() => onRefund(payment.id)}>Refund {payment.id}</button>;
});

export function PaymentList({ payments, status, refund }) {
  const visible = useMemo(() => payments.filter((p) => p.status === status), [payments, status]);
  const onRefund = useCallback((id) => refund(id), [refund]);
  return visible.map((p) => <PaymentRow key={p.id} payment={p} onRefund={onRefund} />);
}
```

What to notice:

- `a === b` is `false` because they are different objects, even with equal fields; `Object.is(a, a)` is `true` because it is the same reference. This is why memo compares references, not fields.
- `useMemo` recomputes `visible` only when `payments` or `status` changes, so typing elsewhere does not re-filter the list.
- `useCallback` gives every render the same `onRefund` reference. Without it, each render would pass a new function, so `Object.is` would see a changed prop and `PaymentRow` would re-render anyway.
- Remove the `memo` wrapper and every row re-renders whenever `PaymentList` does, stable props or not.

## Rules and defaults

- **Object.is comparison:** React.memo and the hooks compare inputs with `Object.is`. A new object or function reference each render counts as changed.
- **memo is an optimisation, not a guarantee:** a memo child still re-renders if its own state changes or a context it reads changes, even when props are stable.
- **React Compiler 1.0 (stable 07-10-2025):** it adds this memoization at build time, so most apps no longer write these hooks by hand. In Next.js 16 it is the top-level `reactCompiler` option, off by default; set it to `true` to enable. Keep manual hooks as escape hatches, for example a value used as an effect dependency.

## Not to be confused with

`useMemo` caches a computed value; `useCallback` caches a function reference; `React.memo` skips a child's re-render. Rule: useMemo = value, useCallback = function, React.memo = component. They are often used together, because a memo child only skips when useMemo and useCallback keep its object and function props stable.

## Interview Qs

### Why does my React.memo child still re-render?

A prop passed to it is a new object or function on each render, so `Object.is` sees a changed prop and memo cannot skip. Pass stable values with `useMemo` or `useCallback`, or pass plain strings and numbers. Its own state changing or a context it reads changing also re-renders it, regardless of props.

### Does useCallback stop a function being created each render?

No. The function is still created every render. `useCallback` just stores the first one and returns that same reference while its dependencies are unchanged. That stable reference is what lets a memo child skip, or stops an effect that depends on the function from re-running.

### Do you still need these hooks with React Compiler?

Mostly no. React Compiler 1.0 adds the memoization at build time, so hand-written `useMemo`, `useCallback` and `React.memo` are rarely needed. Keep them where you want exact control, such as a value used as an effect dependency, or in code the compiler is not enabled for.
