## Why it exists

When many event handlers update the same state in different ways, the logic spreads across the component. A reducer puts every update rule in one place.

## How it works

<Compare id="usestate-vs-usereducer" />

- In a component: `const [cart, dispatch] = useReducer(cartReducer, [])`, then `dispatch({ type: 'added', id })`.
- Reducers run during render, so they must be pure; Strict Mode calls them twice in development to catch slips.
- For a deep tree, pass state and `dispatch` down through [context](card:context-api). Redux applies the same idea app-wide ([global state](card:global-state)).

## Example

```javascript
function cartReducer(cart, action) {
  switch (action.type) {
    case 'added':   return [...cart, { id: action.id, qty: 1 }];
    case 'removed': return cart.filter((i) => i.id !== action.id);
    case 'qty':     return cart.map((i) => (i.id === action.id ? { ...i, qty: action.qty } : i));
    default:        throw new Error(`Unknown action: ${action.type}`);
  }
}
let cart = cartReducer([], { type: 'added', id: 'mouse' });
cart = cartReducer(cart, { type: 'qty', id: 'mouse', qty: 2 });
console.log(cart);
```

```text output
[ { id: 'mouse', qty: 2 } ]
```

## Interview Qs

### When would you pick useReducer over useState?

When state has several related fields, many handlers change it alike, or update bugs keep appearing. For simple values, `useState` is shorter.

### Why must a reducer be pure?

React calls it during rendering, possibly more than once. It must return the same next state for the same input and must not fetch, set timers or mutate state. That also makes it easy to unit test without a component.

### How do you share a reducer's state with deep children?

Call `useReducer` in a parent, then provide `cart` and `dispatch` through two contexts. Any child reads the cart or dispatches an action without prop drilling.
