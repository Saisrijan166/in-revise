## Why it exists

One function can serve many objects, so it needs a way to know which object called it. `this` is that link, and it is set at call time.

## How it works

| How it is called | this is |
|---|---|
| `shop.greet()` | `shop` |
| `greet()` in strict code | `undefined` |
| `new Product()` | the new object |
| `greet.call(obj)`, `apply`, `bind` | `obj` |
| An arrow function | the `this` around it |

<Compare id="call-vs-apply-vs-bind" />

- Modules and class bodies are always strict, so a detached method gets `undefined`.

## Example

```javascript
const shop = {
  name: "inShop",
  greet() { return `Hi from ${this.name}`; },
  arrow: () => typeof this,
};
console.log(shop.greet());
const greet = shop.greet;
try { greet(); } catch (e) { console.log(e.name); }
console.log(greet.call({ name: "Other" }));
console.log(shop.arrow());
```

```text output
Hi from inShop
TypeError
Hi from Other
undefined
```

## Interview Qs

### Arrow function vs regular function?

Arrows have no own `this`, `arguments` or `prototype`, and `new` throws on them. Use them for callbacks that need the outer `this`; avoid them as object methods.

### What is the prototype chain?

Every object links to a prototype. A missing property is looked up along these links until `null`. Classes use the same chain underneath.
