## What it is

`this` is a keyword inside a function that points to an object the function is working on. One function can be shared by many objects, so `this` is the link that tells the running function which object called it. Its value is not fixed when you write the function; it is chosen each time the function is called, from the way it is called. An **arrow function** is the exception: it has no `this` of its own and uses the `this` of the [scope](card:closures) where it was written.

## Why it exists

The same function often works on different objects. If every method were tied to one object, you could not share a method across many instances of a class, or reuse a helper on another object. `this` solves that by being filled in at call time: `payment.refund()` runs `refund` with `this` as `payment`, and `order.refund()` runs the same code with `this` as `order`. The cost is that a method pulled off its object loses the object, which is the usual source of bugs.

## How it works

The value of `this` depends only on the call. This table lists each form of call.

| How it is called | this is |
|---|---|
| `shop.greet()` | `shop` (the object before the dot) |
| `greet()` in strict code | `undefined` |
| `new Product()` | the newly created object |
| `greet.call(obj)`, `apply`, `bind` | `obj`, the object you pass |
| An arrow function | the `this` of the surrounding scope |

The three explicit setters differ only in how they take arguments and when they run.

<Compare id="call-vs-apply-vs-bind" />

1. Look at the call, not the definition, to find `this`.
2. If there is an object before the dot, `this` is that object.
3. If the function is called plainly, `this` is `undefined` in strict code (modules and class bodies are always strict).
4. An arrow function ignores all of this and keeps the `this` it was written in.

## Example

The same method behaves differently depending on how it is called. The output comes from running the code with Node.

```javascript
const shop = {
  name: "inShop",
  greet() { return `Hi from ${this.name}`; },
  arrow: () => typeof this,          // no own this
};
console.log(shop.greet());           // called on shop
const greet = shop.greet;            // method detached from shop
try { greet(); } catch (e) { console.log(e.name); }
console.log(greet.call({ name: "Other" }));  // this set explicitly
console.log(shop.arrow());
```

```text output
Hi from inShop
TypeError
Hi from Other
undefined
```

What to notice:

- `shop.greet()` has `shop` before the dot, so `this.name` is `"inShop"`.
- The detached `greet()` has no object, so `this` is `undefined` and reading `this.name` throws `TypeError`.
- `greet.call({ name: "Other" })` sets `this` by hand, so it works again.
- `shop.arrow` has no `this` of its own and borrows the module's `this`, which is `undefined`, so `typeof` is `"undefined"`.

## Rules and defaults

- **Call-time binding:** `this` is set when the function is called, from the call form, not when it is defined.
- **Strict default:** in modules and class bodies (always strict), a plain call gives `this === undefined`; in old sloppy scripts it gives `globalThis`.
- **Arrow functions:** have no own `this`, `arguments` or `prototype`, and cannot be called with `new`.
- **bind is permanent:** `bind` fixes `this` once; calling `bind` again on the result cannot change it, and `call`/`apply` on a bound function cannot either.

## Common mistakes

- **"Arrow functions are just shorter functions."** They also change `this`: an arrow method on an object does not get the object as `this`, so it is the wrong choice for object methods but the right choice for callbacks that need the outer `this`.

## Interview Qs

### Arrow function vs regular function?

An arrow function has no own `this`, `arguments` or `prototype`, and calling it with `new` throws. It takes `this` from the scope where it was written. Use arrows for callbacks that should keep the surrounding `this`, such as inside a method; avoid them as the methods of an object, which need their own `this`.

### What is the prototype chain?

Every object has a hidden link to another object, its prototype. When you read a property that the object does not have, JavaScript follows these links one by one until it finds the property or reaches `null`. Classes are built on this: methods live on the prototype, so all instances share one copy.
