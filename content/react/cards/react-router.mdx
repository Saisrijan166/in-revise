## Why it exists

A single-page app loads one document, yet users still expect real URLs: shareable links, a working Back button and pages like /products/42.

## How it works

  alt="Clicking a Link to /cart calls history.pushState: the URL changes but no document loads. The router matches /cart and renders Cart. Pressing Back fires popstate, and the router matches again."

- Three modes: declarative, data (adds loaders), framework (a Vite plugin). Code splitting per route: [bundling](card:bundling-code-splitting).
- Next.js routes by folders instead: [App Router](card:server-components).

## Example

```jsx
import { BrowserRouter, Routes, Route, Link } from 'react-router';

const App = () => (
  <BrowserRouter>
    <Link to="/cart">Cart</Link>
    <Routes>
      <Route path="/products" element={<ProductList />} />
      <Route path="/products/:id" element={<ProductPage />} /> {/* useParams().id */}
      <Route path="/cart" element={<Cart />} />
      <Route path="*" element={<NotFound />} />
    </Routes>
  </BrowserRouter>
);
```

## Interview Qs

### How do you build a protected route?

Check the user before showing the page. In data mode a loader can `throw redirect("/login")`; in declarative mode a wrapper renders the page or navigates to /login. This only hides UI: the API must still check access on the server.

### What are nested routes and Outlet?

Child routes sit inside a parent and add to its path. The parent renders the shared layout and an `<Outlet />` where the matched child appears.

### Why does refreshing /products/42 give a 404 after deploy?

The browser asks the server for /products/42, but only index.html exists. Configure the host to serve index.html for every path; the router then reads the URL and renders the page.
