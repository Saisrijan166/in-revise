## What it is

Client-side routing is how a single-page app shows different "pages" for different URLs without loading a new HTML document each time. A single-page app (SPA) sends one HTML file; after that, [JavaScript](card:scope-hoisting) swaps the visible [components](card:components-jsx-props) as the user moves around. React Router is the common library that does this for React: you declare which component belongs to which URL, and it renders the matching one.

## Why it exists

An SPA loads one document, but users still expect the web to work normally: links they can share, a Back button that goes back, and real addresses like `/payments/42`. If the app ignored the URL, everything would live at one address, so nothing could be bookmarked or shared and Back would leave the app. React Router restores all of that by syncing the URL with what is shown, while keeping the single-page speed of swapping components instead of reloading.

## How it works

1. The user clicks a `<Link to="/cart">`. React Router stops the browser's normal navigation.
2. It calls `history.pushState`, which changes the URL in the address bar without fetching anything.
3. It matches the new URL against your routes and renders the component for the one that matches.
4. When the user presses Back, the browser fires a `popstate` event; the router catches it, matches the previous URL and renders again.

So the key is: the URL changes and the view changes, but the document and the running app stay the same.

## Example

Routes map URL patterns to components. `<Link>` navigates on the client; `:id` is a parameter read with `useParams`.

```jsx
import { BrowserRouter, Routes, Route, Link } from 'react-router';

const App = () => (
  <BrowserRouter>
    <Link to="/payments">Payments</Link>
    <Routes>
      <Route path="/payments" element={<PaymentList />} />
      <Route path="/payments/:id" element={<PaymentPage />} /> {/* useParams().id */}
      <Route path="/cart" element={<Cart />} />
      <Route path="*" element={<NotFound />} />
    </Routes>
  </BrowserRouter>
);
```

What to notice:

- Imports come from `react-router`, not `react-router-dom`; that package was removed in React Router 8.
- `path="/payments/:id"` matches `/payments/42` and exposes `42` as `useParams().id` inside `PaymentPage`.
- `path="*"` is the catch-all, so any unmatched URL renders `NotFound` instead of a blank screen.
- Changing `<Link>` to `<a href="/payments">` would reload the whole document and reset the app's state; `<Link>` avoids that.

## Rules and defaults

- **Import from `react-router` (v8):** the separate `react-router-dom` package was removed; everything ships in `react-router`.
- **Three modes:** declarative (routes as JSX), data (adds route loaders and actions), and framework (a Vite plugin with file-based routes). Pick per app.
- **URL reading hooks:** `useParams` for `/payments/:id`, `useSearchParams` for `?status=paid`, and `useNavigate` to navigate from code.
- **Nested routes need an `<Outlet />`:** a parent route renders shared layout and places `<Outlet />` where the matched child appears.
- **Host fallback is required:** for deep links to survive a refresh, the server must return `index.html` for every path.

## Not to be confused with

Client-side routing swaps components in the browser with no server round-trip. Server-side routing means each URL is a separate request the server answers with its own HTML. Next.js's [App Router](card:server-components) routes by folders and renders on the server by default, which is server-side routing built into the framework; React Router's declarative mode runs entirely in the browser. Rule: React Router for a browser SPA, a framework router when you want server rendering per route.

## Interview Qs

### Why use Link instead of a plain anchor tag?

A plain `<a>` makes the browser load a new document, which resets all in-memory state and re-downloads the app. `<Link>` intercepts the click, changes the URL with the History API, and renders the matching component, so navigation is instant and the running app and its state survive.

### What are nested routes and what does `<Outlet />` do?

Nested routes let a child route sit inside a parent and extend its path, so the parent can render a shared layout once. The parent places `<Outlet />` at the spot where the matched child should appear, and React Router renders the child component there.

### Why does refreshing /payments/42 give a 404 after deploy, and how do you fix it?

On refresh the browser asks the server for `/payments/42`, but the build only produced `index.html`, so the server has no such file. Configure the host to serve `index.html` for every path; the app then loads, reads the URL in the browser, and React Router renders the right page.
