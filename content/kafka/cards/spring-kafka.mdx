## What it is

Spring for Apache Kafka (spring-kafka) is the Spring project that wraps the plain Kafka [producer and consumer](card:consumer-basics) clients. `KafkaTemplate` sends records. A method marked `@KafkaListener` receives them. Behind that method, a listener container, a Spring object that owns a consumer and its thread, runs the poll loop, commits offsets and handles errors. Spring Boot creates these objects for you from `spring.kafka.*` properties.

## Why it exists

With the plain clients you write the poll loop yourself, start one thread per consumer, decide when to [commit](card:offset-commits), catch exceptions, retry and park failed records. Every service repeats that code, and small mistakes lose or duplicate records. Spring puts it in one tested container. You write one method with business logic, and set the rest with properties and a few beans.

## How it works

1. At start-up Spring Boot creates a `KafkaTemplate` and a listener container factory from your `spring.kafka.*` properties.
2. For each `@KafkaListener` method, the factory builds a container with `concurrency` consumer threads, all in the method's group.
3. Each thread polls its partitions and calls your method once per record.
4. When your method returns, the container commits the offsets, by default after all records of one poll are done.
5. If the method throws, the error handler seeks back and redelivers the record. When the retries run out, a recoverer logs it or publishes it to a dead letter topic, then the container moves on.

## Example

The Notification service sends a receipt and commits each record only after the receipt is out:

```java
@Component
class PaymentNotificationListener {
    private final NotificationSender sender;
    PaymentNotificationListener(NotificationSender sender) { this.sender = sender; }

    @KafkaListener(topics = "payments", groupId = "notification",
                   concurrency = "3", ackMode = "MANUAL_IMMEDIATE")
    void onPayment(ConsumerRecord<String, String> rec, Acknowledgment ack) {
        sender.sendReceipt(rec.key(), rec.value());   // e-mail or SMS for this orderId
        ack.acknowledge();                            // commit only after the receipt is sent
    }
}
```

What to notice:

- `groupId = "notification"` puts these threads in their own group, so Analytics, in another group, still gets every payment too.
- `concurrency = "3"` starts three consumer threads, one per partition of a 3-partition topic.
- `ackMode = "MANUAL_IMMEDIATE"` (per listener since spring-kafka 4.1) plus `ack.acknowledge()` commits this record's offset right away. If `sendReceipt` throws, `acknowledge()` never runs and the record is redelivered.
- Without `ackMode`, the default BATCH mode commits after the whole poll, and the `Acknowledgment` parameter is not needed.

## Rules and defaults

| What | Default | Where |
|---|---|---|
| `enable.auto.commit` | set to `false` by Spring unless you set it | Spring for Apache Kafka 4.1 |
| AckMode | `BATCH`: commit after all records of one poll are processed | Spring for Apache Kafka 4.1 |
| DefaultErrorHandler | `FixedBackOff(0, 9)`: 10 deliveries, no delay, then log | Spring for Apache Kafka 4.1 |
| Dead letter topic | original topic plus `-dlt`, same partition number | DeadLetterPublishingRecoverer, 4.1 |

- **Starter:** add `spring-boot-starter-kafka`; Boot then auto-configures `KafkaTemplate` and the default listener container factory.
- **Error handler bean:** a `CommonErrorHandler` bean, such as a `DefaultErrorHandler`, is attached to the default factory automatically.
- **Fatal exceptions:** `DeserializationException`, `ClassCastException` and similar are not retried; the recoverer is called on the first failure.
- **Ack modes:** `RECORD` commits after each record; `MANUAL` and `MANUAL_IMMEDIATE` wait for `acknowledge()`.

## Not to be confused with

Kafka auto-commit is the client committing in the background every few seconds, whether or not you finished. Spring's container commit happens after your method returns. Rule: in Spring, offsets follow your processing, not the clock. Retrying in place blocks the partition; retry topics with `@RetryableTopic` keep it moving but lose order (see the comparison below).

## Interview Qs

### What happens when a @KafkaListener method throws?

The container hands the record to `DefaultErrorHandler`, which seeks back and redelivers it: 10 deliveries in all, no delay, by default. Then it calls the recoverer, which logs the record, or with `DeadLetterPublishingRecoverer` publishes it to `payments-dlt` with the exception in its headers.

### How do you commit offsets manually in Spring?

Set AckMode to `MANUAL` or `MANUAL_IMMEDIATE`, on the listener or with `spring.kafka.listener.ack-mode`. Add an `Acknowledgment` parameter to the method and call `acknowledge()` after the work is done. `MANUAL_IMMEDIATE` commits at once; `MANUAL` queues it for the batch commit.

### Why can extra concurrency not speed up a listener?

Each concurrent thread is a consumer in the same group, and a partition goes to only one consumer in a group. With 3 partitions, a fourth thread gets nothing. To go faster, add partitions or make the method faster.
