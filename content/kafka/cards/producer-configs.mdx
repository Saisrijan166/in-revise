## Why it exists

The producer has dozens of settings; interviews and real services need only a few. Knowing which one bounds what avoids lost or endless sends.

## How it works

| Config | Controls | Default (Kafka 4.3) |
|---|---|---|
| `bootstrap.servers` | Brokers to contact first; the client finds the rest | none (required) |
| `key.serializer`, `value.serializer` | Object to bytes: [producers](card:producer-basics) | none (required) |
| `client.id` | App name in broker logs | empty |
| `acks` | Who must have the record: [acks](card:producer-acks) | see the concept |
| `retries` | Resends on transient errors | 2147483647 |
| `delivery.timeout.ms` | Total time to report success or failure | 120000 (2 min) |
| `request.timeout.ms` | Wait for one broker reply | 30000 (30 s) |
| `max.block.ms` | How long `send()` may block on metadata or a full buffer | 60000 (1 min) |
| `batch.size`, `linger.ms`, `compression.type` | [Batching](card:batching-and-compression) | see the concept |
| `enable.idempotence` | No duplicates from retries: [idempotent producer](card:idempotent-producer) | see the concept |

- Keep `delivery.timeout.ms` at least `request.timeout.ms` + `linger.ms`.
- List more than one broker in `bootstrap.servers` in case one is down.
- All Spring settings: [Spring for Apache Kafka](card:spring-kafka).

## Example

```properties
bootstrap.servers=kafka-1:9092,kafka-2:9092,kafka-3:9092
client.id=payment-service
key.serializer=org.apache.kafka.common.serialization.StringSerializer
value.serializer=org.apache.kafka.common.serialization.StringSerializer
# leave retries unset; bound the time instead
delivery.timeout.ms=120000
```

## Interview Qs

### What is the difference between request.timeout.ms and delivery.timeout.ms?

`request.timeout.ms` is the wait for one broker reply before a retry. `delivery.timeout.ms` bounds the whole send, including batching, waiting and every retry. When it expires, the callback gets the error.

### When does send() block?

When it must fetch the topic's metadata first, or when the producer's buffer is full. It blocks up to `max.block.ms`; then the Future fails with a timeout.

### Which producer configs would you set for a payments service?

`bootstrap.servers` with several brokers, the serializers and a `client.id`. Keep the defaults `acks=all` and idempotence on, and tune `delivery.timeout.ms` for how long a payment event may keep retrying.
