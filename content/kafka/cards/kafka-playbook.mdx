## Why it exists

Most Kafka questions are a few rules in new words. Know them and the traps; answer in five steps.

## How it works

| Rule | Owner |
|---|---|
| Kafka: a distributed log to publish, store, process | [Kafka](card:what-is-kafka) |
| Broker: one Kafka server; controllers keep the metadata | [Brokers](card:kafka-architecture) |
| Topic: a stream of partitions, each an ordered log; order only inside one | [Topics](card:topics), [partitions](card:partitions) |
| Same key, same partition, so per-key order | [Keys](card:partition-keys) |
| Offset: a position in one partition; committed = progress | [Offsets](card:offsets) |
| A group gives each partition one consumer; every group reads all | [Groups](card:consumer-groups) |
| More partitions, more parallelism | [Scaling](card:ordering-and-scaling) |
| Reading never deletes; retention does, so replay works | [Replay](card:replay) |
| Replication: fault tolerance; durability = RF, acks=all, ISR, min.insync.replicas | [Replicas](card:replication), [ISR](card:isr-and-min-insync) |

## Interview Qs

### What are Kafka's main guarantees?

Order per partition; durability from replication, acks=all and min.insync.replicas; scale through partitions; replay, as records are kept; fan-out, as each group reads alone.

### Walk me through Kafka end to end.

The key picks a partition; its leader appends the record, followers copy it. Each group's consumers poll their partitions, process, then commit offsets.
