## What it is

Kafka code templates are the small, fixed pieces of code you write when an interviewer says "integrate Kafka in a Spring Boot service". There are four: the `application.yml` settings, a producer that uses `KafkaTemplate`, a consumer method marked `@KafkaListener`, and an error-handler bean. The console tools that ship with Kafka let you test a topic without writing any code. Why each piece works is explained in [Spring for Apache Kafka](card:spring-kafka).

## Why it exists

"How do you integrate Kafka?" usually means "write it on the board now". Candidates who know the theory still forget the group id, send without a key, or ignore what `send()` returns. A short, correct skeleton for each piece answers the question in two minutes and leaves time for the follow-ups: ordering, failures and duplicates.

## How it works

| Asked to write | Where |
|---|---|
| Spring Boot producer, consumer, error handler | the templates below |
| Plain Java producer with a callback | [producers](card:producer-basics) |
| Plain poll loop with commitSync | [consumer poll loop](card:consumer-basics) |
| Manual ack in Spring | [Spring for Apache Kafka](card:spring-kafka) |
| Read, process, write exactly once | [transactions](card:kafka-transactions) |
| Save offsets before a rebalance | [rebalancing](card:rebalancing) |

1. Add `spring-boot-starter-kafka` and set the broker address and group id in `application.yml`.
2. Inject `KafkaTemplate` into the Payment service and send each event with `orderId` as the key.
3. In the Notification service, put `@KafkaListener` on the method that handles one record.
4. Declare a `DefaultErrorHandler` bean, so records that keep failing go to `payments-dlt` instead of blocking the partition.
5. Test the topic from the command line with the console producer and consumer.

## Example

The Payment service publishes `PaymentCompleted`, and the Notification service consumes it:

```yaml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    consumer:
      group-id: notification
      auto-offset-reset: earliest   # a new group starts from the oldest record
```

```java
@Service
class PaymentEventProducer {
    private static final Logger log = LoggerFactory.getLogger(PaymentEventProducer.class);
    private final KafkaTemplate<String, String> kafka;
    PaymentEventProducer(KafkaTemplate<String, String> kafka) { this.kafka = kafka; }

    void publish(String orderId, String paymentJson) {
        kafka.send("payments", orderId, paymentJson).whenComplete((result, ex) -> {
            if (ex != null) log.error("payment event for {} not sent", orderId, ex);
            else log.info("order {} at offset {}", orderId, result.getRecordMetadata().offset());
        });
    }
}
```

```java
@Component
class NotificationConsumer {
    private static final Logger log = LoggerFactory.getLogger(NotificationConsumer.class);

    @KafkaListener(topics = "payments")   // group id comes from application.yml
    void onPayment(ConsumerRecord<String, String> rec) {
        if (rec.value().isBlank()) throw new IllegalArgumentException("empty payment event");
        log.info("receipt for order {} from partition {}", rec.key(), rec.partition());
    }
}
```

```java
@Configuration
class KafkaErrorConfig {
    @Bean   // a failed record: 3 tries 1 s apart, then payments-dlt
    DefaultErrorHandler errorHandler(KafkaTemplate<String, String> template) {
        var toDlt = new DeadLetterPublishingRecoverer(template);
        return new DefaultErrorHandler(toDlt, new FixedBackOff(1000L, 2L));
    }
}
```

```bash
kafka-topics.sh --bootstrap-server localhost:9092 --create --topic payments --partitions 3

echo "o-101:PaymentCompleted" | kafka-console-producer.sh --bootstrap-server localhost:9092 \
  --topic payments --reader-property parse.key=true --reader-property key.separator=:

kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic payments \
  --from-beginning --max-messages 1 --formatter-property print.key=true \
  --command-property group.protocol=consumer
```

```text output
Created topic payments.
o-101	PaymentCompleted
Processed a total of 1 messages
```

What to notice:

- `send("payments", orderId, paymentJson)` passes the key; drop `orderId` and one order's events can be read out of order. `whenComplete` runs when the broker answers, so a failed send is logged, not lost silently.
- The listener throws on a blank event. The error handler then delivers it 3 times, 1 second apart (`FixedBackOff(1000L, 2L)` means 2 retries), and publishes it to `payments-dlt`.
- `parse.key=true` with `key.separator=:` makes the console producer split `o-101:PaymentCompleted` into key and value; `print.key=true` prints both, separated by a tab.
- `group.protocol=consumer` uses the newer consumer group protocol; without it, the Kafka 4.3 console consumer prints a hint suggesting it.

## Rules and defaults

- **Group id is required:** a `@KafkaListener` on topics needs `spring.kafka.consumer.group-id`, `groupId` or `id`; otherwise start-up fails.
- **Error handler wiring:** Spring Boot attaches a `CommonErrorHandler` bean, such as `DefaultErrorHandler`, to the default listener container factory. You do not call a setter.
- **DLT partitions:** by default the recoverer writes to the same partition number in `payments-dlt`, so the DLT needs at least as many partitions as `payments`.
- **Console tool options:** since Kafka 4.2, `--property` is deprecated; use `--reader-property` (producer), `--formatter-property` (consumer) or `--command-property`.

## Interview Qs

### How do you integrate Kafka in a Spring Boot service?

Add `spring-boot-starter-kafka` and set `bootstrap-servers` and `group-id`. Inject `KafkaTemplate` and call `send(topic, key, value)`; put `@KafkaListener(topics = ...)` on a method. Boot creates the producer factory, the template and the listener containers.

### How do you send failed records to a dead letter topic?

Declare a `DefaultErrorHandler` bean with a `DeadLetterPublishingRecoverer` and a back-off; Boot attaches it to the listener factory. After the retries the record goes to `payments-dlt`, with the exception and the original topic, partition and offset in its headers.

### How do you test a topic without writing code?

`kafka-console-producer.sh` sends each input line as a record, and `kafka-console-consumer.sh` with `--from-beginning` prints the records already in the topic. Use `parse.key` and `print.key` to send and see keys.
