## What it is

A producer is the part of your service that writes records to Kafka. In Java it is a `KafkaProducer` object from the `kafka-clients` library. You give it a record: the topic, an optional key and the value, such as a `PaymentCompleted` event keyed by `orderId`. The producer does the rest: it turns the record into bytes, chooses the [partition](card:partition-keys), and sends it to the broker that leads that partition.

## Why it exists

Without a client library, each service would have to find the right broker for every partition, convert objects to bytes, group small writes, retry on errors and follow leaders when they move. Every team would write this differently, and most would get it wrong. The producer hides all of it behind one `send()` call, and does the network work on its own background thread so your request thread is not held up.

## How it works

1. Your code calls `send(record, callback)`. The call returns at once with a `Future`, an object that will hold the result later.
2. The `key.serializer` and `value.serializer` turn the key and value into bytes, because brokers store only bytes.
3. The producer picks the partition: from the key's hash, or the partition you set yourself ([partition keys](card:partition-keys)).
4. The record joins that partition's batch in memory. A background I/O thread sends the batch to the partition's leader broker ([batching](card:batching-and-compression)).
5. The broker replies with the partition and [offset](card:offsets), or an error. The producer completes the `Future` and runs your callback.

So the key is that sending and the result are separated in time: you learn about success or failure only in step 5.

## Example

The Payment service sends one `PaymentCompleted` event to the `payments` topic (3 partitions), keyed by `orderId`.

```java
var props = new Properties();
props.put("bootstrap.servers", "localhost:9092");
props.put("key.serializer", StringSerializer.class.getName());
props.put("value.serializer", StringSerializer.class.getName());
try (var producer = new KafkaProducer<String, String>(props)) {
    var event = "{\"type\":\"PaymentCompleted\",\"orderId\":\"o-101\",\"amountInr\":500}";
    producer.send(new ProducerRecord<>("payments", "o-101", event), (meta, ex) -> {
        if (ex != null) System.err.println("send failed: " + ex);
        else System.out.println("partition " + meta.partition() + ", offset " + meta.offset());
    });
    System.out.println("send() returned");
}
```

```text output
send() returned
partition 2, offset 0
```

What to notice:

- `send() returned` prints **first**: `send()` only queued the record, and the callback ran later, when the broker answered.
- The callback checks `ex` first. Remove that check and a rejected payment event disappears without a trace.
- The key `o-101` decided the partition (2 here). Every later event for order `o-101` goes to the same partition, so they stay in order.
- `try (...)` closes the producer at the end, and `close()` waits until buffered records are sent. Without it, the program could exit before the record leaves memory.

## Rules and defaults

- **Required settings:** `bootstrap.servers`, `key.serializer` and `value.serializer` have no default in Kafka 4.3; the producer will not start without them.
- **Thread safety:** one `KafkaProducer` can be shared by all threads, and the Kafka javadoc says that is generally faster than many instances.
- **Callback order:** callbacks for records sent to the same partition run in the order of the sends.
- **Keep callbacks short:** they run on the producer's I/O thread, so slow work there delays every other send. Hand heavy work to another thread.
- **Blocking cases:** `send()` can block when it must fetch topic metadata first or when the buffer is full; the limits are in [producer configs](card:producer-configs).

## Common mistakes

- **"One producer per request is safer."** It wastes connections and memory and kills batching. One shared producer is the documented pattern.
- **"JSON or Avro payloads need nothing special."** They need a matching serializer; formats and schemas are covered in [Schema Registry](card:schema-registry-and-serialization).

## Interview Qs

### What is a Kafka producer, and what does it do with a record?

It is the client that publishes records to topics. For each record it serialises the key and value, picks the partition (from the key's hash when there is a key), adds the record to that partition's batch, and a background thread sends the batch to the partition's leader broker.

### Is send() synchronous?

No. It puts the record in a buffer and returns a `Future<RecordMetadata>` at once. Call `get()` on it to block until the broker answers, which is simple but slow, or pass a callback that handles success or failure without blocking. With neither, a failed send goes unnoticed.

### Should each thread create its own KafkaProducer?

No. `KafkaProducer` is thread-safe, and one shared instance usually gives better throughput because records from all threads share batches. Close it on shutdown so buffered records are sent and its threads and connections are released.
