## What it is

Log storage is how a broker keeps a [partition](card:partitions) on disk. A partition is a folder, such as `payments-0`, holding segment files: each segment holds a run of events, and its file name is the [offset](card:offsets) of its first event. New events are only appended to the newest segment, called the active segment. A cleanup policy decides when old events leave: by age or size (delete), or by keeping the latest event per key (compact).

## Why it exists

Kafka keeps events after they are read, so that many groups can read them and read them again. Disks are finite, so old data must go by a clear rule, not by who has read it. One giant file per partition would make that hard: removing old data would mean rewriting the file. With segments, removing old data means deleting whole old files, which is cheap.

## How it works

1. The leader appends each new event to the end of the active segment.
2. When the active segment reaches `segment.bytes` (1 GiB) or `segment.ms` (7 days), Kafka closes it and starts a new one, named after the next offset.
3. With `cleanup.policy=delete`, a segment is deleted once its newest event is older than `retention.ms`, or when the partition is over `retention.bytes`, oldest segment first.
4. With `cleanup.policy=compact`, a background cleaner copies closed segments, keeping only the latest event for each key. Offsets do not change; the removed events leave gaps.

## Example

Make segments roll quickly on a test topic, write about 3 MB, then list the segment files of its only partition:

```bash
# Segments roll at 1 MiB, the smallest value Kafka 4.3 allows
bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic seg-demo \
  --partitions 1 --replication-factor 1 --config segment.bytes=1048576

# Write 3,000 records of 1,000 bytes each
bin/kafka-producer-perf-test.sh --topic seg-demo --num-records 3000 --record-size 1000 \
  --throughput -1 --command-property bootstrap.servers=localhost:9092 > /dev/null

# On the broker that stores the partition (its log directory is /tmp/kafka-logs)
ls /tmp/kafka-logs/seg-demo-0/*.log
```

```text output
Created topic seg-demo.
/tmp/kafka-logs/seg-demo-0/00000000000000000000.log
/tmp/kafka-logs/seg-demo-0/00000000000000001033.log
/tmp/kafka-logs/seg-demo-0/00000000000000002057.log
```

What to notice:

- About 3 MB became three segments of up to 1 MiB each. With the default 1 GiB, all of it would still sit in the first file.
- Each file is named after the offset of its first event: the second segment starts at offset 1033.
- The last file is the active segment, where new events go. Compaction never touches it; it works only on closed segments.

## Rules and defaults

- **cleanup.policy (Kafka 4.3):** `delete` by default. `compact` keeps the latest event per key; `delete,compact` applies both.
- **Broker-wide time limit (Kafka 4.3):** `log.retention.hours=168`, 7 days; a topic's `retention.ms` overrides it, and `-1` means no time limit.
- **retention.bytes:** per partition, so a topic can use about that value times its partition count, per copy.
- **Tombstone:** an event with a key and an empty (null) value tells compaction to delete that key; tombstones are kept for `delete.retention.ms`, 1 day by default.
- **Tiered storage:** since Kafka 3.9, closed segments can move to remote storage such as Amazon S3, keeping long history off the brokers' disks ([tiered storage](card:tiered-storage)).

## Not to be confused with

Retention (the delete policy) removes whole old segments once they pass a time or size limit, whatever keys they hold. Compaction removes older events only when a newer event with the same key exists, so the latest value of every key stays. Rule: delete for a history you keep for a while, such as payments; compact for the latest state per key, such as each customer's current address.

## Interview Qs

### When does Kafka delete old data?

When a segment's newest event is older than `retention.ms`, or when the partition is bigger than `retention.bytes`. Kafka drops whole segments, oldest first, whether or not anyone has read them. With the compact policy, it instead removes older events that have a newer event with the same key.

### What is log compaction, and when do you use it?

`cleanup.policy=compact` keeps at least the latest event per key and drops older ones in the background. Use it for latest-state topics, such as each customer's address, so a new reader can rebuild the current state from the topic. A tombstone deletes a key.

### Why does Kafka split a partition into segments?

So old data can be removed by deleting whole files instead of rewriting one huge file, and so the compaction cleaner can work on closed files while new events go to the active one.
