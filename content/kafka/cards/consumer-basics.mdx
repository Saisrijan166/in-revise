## Why it exists

Producers and consumers rarely run at the same speed. If brokers pushed records, a slow consumer would be flooded; pulling lets each consumer read when it is ready.

## How it works

<Steps label="The poll loop">
  <Step title="Subscribe">Join the group named by group.id, for example payment-service on payments ([consumer groups](card:consumer-groups)).</Step>
  <Step title="Poll">poll() returns a batch of records from the partitions this consumer owns.</Step>
  <Step title="Process">Handle each record, such as marking a ₹500 order as paid.</Step>
  <Step title="Commit">Save the next offset to read ([committing offsets](card:offset-commits)).</Step>
  <Step title="Repeat">Poll again in time, or the consumer leaves the group and a [rebalance](card:rebalancing) starts.</Step>
</Steps>

- Long poll: the broker holds a fetch until fetch.min.bytes arrive or fetch.max.wait.ms passes.
- Deserializers turn bytes back into objects; they must match the [producer's serializers](card:producer-basics).
- To stop the loop from another thread, call wakeup(); poll() then throws WakeupException.

## Example

```java
props.put("group.id", "payment-service");
props.put("enable.auto.commit", "false");
props.put("key.deserializer", StringDeserializer.class.getName());
props.put("value.deserializer", StringDeserializer.class.getName());
try (var consumer = new KafkaConsumer<String, String>(props)) {
    consumer.subscribe(List.of("payments"));
    while (running) {
        for (var rec : consumer.poll(Duration.ofMillis(500)))
            markPaid(rec.key(), rec.value());   // orderId -> PaymentCompleted
        consumer.commitSync();                  // only after processing
    }
}
```

## Interview Qs

### Why does Kafka use pull instead of push?

Pull lets each consumer read at its own rate, fetch large batches, and catch up after a slowdown. A push system can flood a slow consumer. Long polling stops an idle consumer from spinning.

### Can two threads share one KafkaConsumer?

No. KafkaConsumer is not thread-safe; only wakeup() may be called from another thread. Run one consumer per thread, or one polling thread that hands work to a pool and commits with care.

### subscribe() or assign()?

subscribe() joins a consumer group: Kafka spreads the partitions and rebalances them when members change. assign() takes fixed partitions with no group management, so failover is your job.
