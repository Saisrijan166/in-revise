## Why it exists

Some nodes are special: GPU nodes, a team's pool, the control plane. Labels can pull Pods to them but cannot keep other Pods off; taints can.

## How it works

<Compare id="taints-vs-node-affinity" />

- kubeadm taints control-plane nodes with `node-role.kubernetes.io/control-plane:NoSchedule`, so app Pods stay off them.
- DaemonSet Pods tolerate the `not-ready` and `unreachable` taints with no time limit, so they are never evicted for them.

## Example

```yaml
# kubectl taint nodes node-7 dedicated=payments:NoSchedule
# payment-service Pod template:
tolerations:
  - { key: dedicated, operator: Equal, value: payments, effect: NoSchedule }
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
        - matchExpressions:
            - { key: dedicated, operator: In, values: [payments] }
```

## Interview Qs

### Why do normal Pods not run on control-plane nodes?

kubeadm taints those nodes with `node-role.kubernetes.io/control-plane:NoSchedule`. Only Pods that tolerate it, usually system components, are placed there. Removing the taint lets any Pod in.

### What happens to Pods when a node becomes unreachable?

The control plane taints the node `node.kubernetes.io/unreachable` with NoExecute. Pods get an automatic 300-second toleration, so after 5 minutes they are evicted and their controllers recreate them elsewhere.
