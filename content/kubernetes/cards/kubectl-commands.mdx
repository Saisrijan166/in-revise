## Why it exists

Every change and every check goes through kubectl to the API server. A short, grouped list is quicker to recall in an interview than a long flat one.

## How it works

| Task | Command |
|---|---|
| Inspect | `get pods -o wide`, `describe pod P`, `explain deployment.spec`, `top pod` |
| Change | `apply -f app.yaml`, `diff -f app.yaml`, `delete -f app.yaml`, `delete pod P`: [manifests](card:kubectl-and-manifests) |
| Scale | `scale deployment/payment-service --replicas=5` |
| Release | `set image`, `rollout status`, `rollout history`, `rollout undo`, `rollout restart`: [rollouts](card:rolling-updates-rollbacks) |
| Debug | `logs P --previous`, `logs -f P`, `exec -it P -- sh`, `debug`, `port-forward`: [debugging](card:kubectl-debugging) |
| Context | `config get-contexts`, `config use-context C` |

- `top` needs metrics-server: [metrics](card:observability-in-k8s).
- Permissions check: `kubectl auth can-i`: [RBAC](card:rbac).

## Example

```bash
kubectl get pods -n payments -l app=payment-service -o wide -w   # where, and watch
kubectl get deployment payment-service -n payments -o yaml       # spec and status
kubectl set image -n payments deployment/payment-service payment-service=payment-service:1.4.1
kubectl get pods -A                                               # every namespace
```

## Interview Qs

### How do you switch the default namespace for kubectl?

`kubectl config set-context --current --namespace=payments` stores it in the current kubeconfig context. Commands without `-n` then use it.

### Why does `kubectl get all` not show my ConfigMap?

"all" is a category, not everything. Only kinds registered in it appear, such as Pods, Services, Deployments and ReplicaSets. List other kinds by name: `kubectl get configmaps,secrets`.
