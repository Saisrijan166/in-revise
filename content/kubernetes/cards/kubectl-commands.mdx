## What it is

kubectl is the command-line client that sends your requests to the Kubernetes API server, as you saw in [kubectl and manifests](card:kubectl-and-manifests). Almost every command has one shape: `kubectl VERB TYPE NAME flags`, such as `kubectl get pods payment-xyz -n payments`. The verb says what to do, the type and name say which objects, and flags narrow or format the result. This concept groups the everyday verbs by task.

## Why it exists

On call, and in interviews, you are asked to do things: list the Pods of one app, read a crashed container's logs, roll back a release. A flat list of fifty commands is hard to recall under pressure. Grouped by task, each command has a place, and the same flags work the same way on every verb, so you build a command instead of remembering it.

## How it works

| Task | Verbs |
|---|---|
| Inspect | `get`, `describe`, `explain`, `top`, `events` |
| Change | `apply -f`, `diff -f`, `delete -f`, `scale` |
| Release | `set image`, `rollout status`, `rollout history`, `rollout undo`, `rollout restart`: see [rollouts](card:rolling-updates-rollbacks) |
| Debug | `logs`, `exec`, `debug`, `port-forward`: see [debugging](card:kubectl-debugging) |
| Context | `config get-contexts`, `config use-context`, `config set-context --current` |

Build a command in this order:

1. **Pick the verb** for the task, such as `get` to list or `logs` to read output.
2. **Name the type**, in plural, singular or short form: `pods`, `pod` or `po`; `deployments` or `deploy`; `services` or `svc`.
3. **Pick the objects:** a name, or `-l app=payment-service` for every object with that label.
4. **Set the scope:** `-n payments` for one namespace, or `-A` for all of them.
5. **Choose the output:** `-o wide` for extra columns, `-o yaml` for the full object, `-w` to keep watching for changes.

So the key is: verb, type, which objects, which namespace, which format.

## Example

The trap in action: `get all` shows the app's workload objects, but not its ConfigMap, which you must ask for by kind.

```bash
kubectl get all -n payments
kubectl get configmaps -n payments
```

```text output
pod/payment-service-c5cf79fb-85jgv
pod/payment-service-c5cf79fb-n9nff
service/payment-service
deployment.apps/payment-service
replicaset.apps/payment-service-c5cf79fb
configmap/kube-root-ca.crt
configmap/payment-config
```

What to notice:

- `get all` printed the Pods, the Service, the Deployment and the ReplicaSet, and stopped there.
- The ConfigMap `payment-config` exists. Only asking for `configmaps` by kind shows it.
- `kube-root-ca.crt` was created by Kubernetes itself, not by you. It holds the certificates Pods use to check that they are talking to the real API server.

## Rules and defaults

- **Default namespace:** without `-n`, kubectl uses the namespace in the current context, and `default` if the context sets none. `kubectl config set-context --current --namespace=payments` changes it.
- **The all category:** `get all` lists only kinds registered in the `all` category. Ask for other kinds by name, several at once: `kubectl get configmaps,secrets,ingresses`.
- **explain:** `kubectl explain deployment.spec.strategy` prints the API's own description of a field, so you do not need to search the web for it.
- **top:** `kubectl top pods` needs metrics-server in the cluster (see [metrics](card:observability-in-k8s)).
- **Permissions:** `kubectl auth can-i delete pods -n payments` answers yes or no for your user (see [RBAC](card:rbac)).
- **diff:** `kubectl diff -f payment-service.yaml` shows what apply would change, without changing anything.

## Not to be confused with

`kubectl get` lists objects, one line each, or prints the stored object with `-o yaml`, which suits scripts and exact values. `kubectl describe` prints a readable summary of one object, including related events, which suits a person who is debugging. Rule: get for data, describe for diagnosis.

## Interview Qs

### How do you switch the default namespace for kubectl?

Run `kubectl config set-context --current --namespace=payments`. It stores the namespace in the current context in your kubeconfig, so later commands without `-n` use payments. `-n` on a single command still overrides it.

### Why does kubectl get all not show my ConfigMap?

"all" is a category, not every kind. Only kinds registered in it appear, such as Pods, Services, Deployments and ReplicaSets. List other kinds by name, for example `kubectl get configmaps,secrets -n payments`.

### How do you see the whole stored object, including its status?

`kubectl get deployment payment-service -n payments -o yaml`. It prints the spec you sent plus the status the cluster wrote, such as ready replicas and conditions. Use `-o jsonpath` to pull out one field.
