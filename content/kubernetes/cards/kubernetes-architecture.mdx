## Why it exists

Kubernetes separates deciding what should run (the control plane) from running it (worker nodes), so many machines can be managed as one cluster.

## How it works

<Compare id="control-plane-vs-worker-node" />

- Hub and spoke: components coordinate through the API server, not with each other.
- Add-ons, like cluster DNS, run as ordinary workloads in kube-system; DNS and network plugins: [Pod networking and DNS](card:cluster-networking-dns).
- Running the control plane on several machines, and etcd quorum: [high availability](card:high-availability).

## Interview Qs

### What does etcd store, and why protect it?

Every object: what you asked for and what the cluster reports. Lose it without a backup and the cluster forgets its state. Access to etcd equals root on the cluster, so only the API server should reach it.

### Is kube-proxy always needed?

No. It programs node rules so Service addresses reach Pods. Some network plugins do that forwarding themselves; then nodes do not run kube-proxy.

### What does the cloud-controller-manager do?

It links the cluster to a cloud API: checks whether a silent node was deleted, sets up routes, and creates load balancers for LoadBalancer Services. On-premises or local clusters do not have one.
