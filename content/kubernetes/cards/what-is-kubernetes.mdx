## Why it exists

Running containers on many machines by hand breaks down: a crashed container stays down and nobody spreads the load. Kubernetes automates placing, restarting and scaling them.

## How it works

<Mermaid
  alt="The reconciliation loop. The desired state says 3 payment-service Pods. A controller observes that only 2 are running, sees a difference of 1, and asks for 1 new Pod. It then observes again, for ever."
  chart={`flowchart LR
  D["Desired: 3 Pods"] --> O["Observe: 2 running"]
  O --> F{"Differ?"}
  F -- "yes" --> A["Act: create 1 Pod"]
  A --> O
  F -- "no" --> O`}
/>

- You write the end state in a manifest, not the steps: see [kubectl and manifests](card:kubectl-and-manifests).
- Many small control loops, not one script: each controller tracks at least one kind of object.
- Also built in: service discovery, rollouts and rollbacks, Secrets, batch jobs, scaling.

## Example

```bash
kubectl get pods -n payments           # 3 payment-service Pods
kubectl delete pod payment-service-7d9f8-abcde -n payments
kubectl get pods -n payments           # still 3: a new Pod took its place
```

## Interview Qs

### Why is it called K8s?

Kubernetes is Greek for helmsman or pilot. K8s counts the eight letters between the K and the s. Google open-sourced the project in 2014.

### What does Kubernetes not do?

It does not build your image or deploy source code (that is CI/CD), ships no built-in database or message bus, and dictates no logging or monitoring tool. It gives building blocks; you plug in the rest.

### What is container orchestration, and how does Kubernetes do it?

Automating where containers run, how many run, and what happens when they fail. Kubernetes runs no fixed "first A, then B" script: independent control loops keep moving the actual state toward the desired state.
