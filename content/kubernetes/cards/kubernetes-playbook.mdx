## Why it exists

Most questions ask which object fits a need, or what happens after apply.

## How it works

| You need | Use |
|---|---|
| A stateless app | [Deployment](card:deployments-and-replicasets) |
| A database with its own disk | [StatefulSet](card:statefulsets) + [PVC](card:persistent-storage) |
| One agent per node | [DaemonSet](card:daemonsets) |
| A task that ends; a nightly one | [Job; CronJob](card:jobs-and-cronjobs) |
| A stable name for Pods | [Service](card:services) |
| HTTP routes from outside | [Gateway API](card:ingress-and-gateway-api) |
| Settings; passwords | [ConfigMap; Secret](card:configmaps-and-secrets) |
| Traffic only to healthy Pods | [Probes](card:probes) |
| More Pods under load | [HPA](card:autoscaling) |
| Pods kept up during drains | [PodDisruptionBudget](card:high-availability) |
| API access; Pod-to-Pod traffic | [RBAC](card:rbac); [NetworkPolicy](card:network-policies) |

| Don't say | Say |
|---|---|
| Failed readiness restarts the Pod | [It stops traffic; liveness restarts](card:probes) |
| apply worked, so the app is up | [Check the rollout](card:kubectl-and-manifests) |
| Call the Pod by its IP | [Pod IPs change; call the Service](card:services) |
| The CPU request caps CPU | [The limit does](card:resource-requests-limits) |
| Secrets are encrypted | [Not in etcd by default](card:configmaps-and-secrets) |
| CrashLoopBackOff is the cause | [A symptom](card:pod-errors) |

## Example

<Steps label="kubectl apply -f payment-service.yaml">
  <Step title="Send">kubectl sends the Deployment to the API server.</Step>
  <Step title="Check">Authentication, authorisation, admission ([RBAC](card:rbac)).</Step>
  <Step title="Store">Saved in etcd ([architecture](card:kubernetes-architecture)).</Step>
  <Step title="Controllers">A ReplicaSet, then 3 Pods ([Deployments](card:deployments-and-replicasets)).</Step>
  <Step title="Schedule">A node per Pod ([scheduling](card:scheduling)).</Step>
  <Step title="Start">The kubelet has the runtime start payment-service:1.4.0.</Step>
  <Step title="Ready">Readiness passes ([probes](card:probes)).</Step>
  <Step title="Traffic">Ready Pods get Service traffic; ₹500 payments arrive ([Services](card:services)).</Step>
</Steps>

## Interview Qs

### What happens when you run kubectl apply on a Deployment?

It is checked (authentication, authorisation, admission) and stored in etcd. Controllers create a ReplicaSet and Pods, the scheduler binds each to a node, kubelets start them, ready Pods join the Service.

### How would you run a Spring Boot service on Kubernetes?

A Deployment (3 replicas), a ClusterIP Service, an HTTPRoute, a ConfigMap and Secret, Actuator probes, requests and limits, an HPA and a PodDisruptionBudget.
