## Why it exists

Pods are replaced all the time, and each new Pod gets a new IP. Callers need one address that keeps working.

## How it works

<Mermaid
  alt="order-service calls payment-service on port 80. The selector finds the Pods; the EndpointSlice lists their IPs and which are ready; each connection goes to one Pod on port 8080."
  chart={`flowchart LR
  C[order-service] -- "payment-service:80" --> S[Service ClusterIP]
  S -- "selector app=payment-service" --> E[EndpointSlice: Pod IPs + ready flag]
  E -- ":8080" --> P1[Pod 1]
  E -- ":8080" --> P2[Pod 2]
  E -- ":8080" --> P3[Pod 3]`}
/>

<Compare id="clusterip-vs-nodeport-vs-loadbalancer" />

- Only ready Pods get traffic. A failing [readiness probe](card:probes) takes a Pod out; with no ready Pods, calls fail.
- `sessionAffinity: ClientIP` sends one client IP to the same Pod each time.
- Callers use its [DNS name](card:cluster-networking-dns); outside HTTP comes via [Ingress or Gateway API](card:ingress-and-gateway-api).

## Example

```yaml
apiVersion: v1
kind: Service
metadata:
  name: payment-service
  namespace: payments
spec:
  type: ClusterIP          # the default; may be left out
  selector:
    app: payment-service   # must match the Pod labels
  ports:
    - port: 80             # callers use payment-service:80
      targetPort: 8080     # Spring Boot listens here
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Service type | ClusterIP | Kubernetes 1.37 |
| targetPort | same as port | Kubernetes 1.37 |
| ClientIP affinity timeout | 10800 s (3 hours) | Kubernetes 1.37 |

## Interview Qs

### A Service exists, but calls to it fail. What do you check first?

Its endpoints: `kubectl get endpointslices -n payments -l kubernetes.io/service-name=payment-service`. Empty means the selector matches no Pod labels or no Pod is ready. Then check targetPort. Full order: [debugging with kubectl](card:kubectl-debugging).

### What is the difference between port, targetPort and nodePort?

port is the Service's own port (80). targetPort is the container port it forwards to (8080). nodePort is the port opened on every node, only for NodePort and LoadBalancer Services.
