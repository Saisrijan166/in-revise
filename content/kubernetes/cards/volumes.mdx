## What it is

A volume is a directory that Kubernetes makes available to the containers of a [Pod](card:pods), at a path you choose in each container. Without one, a container sees only its image's files plus what it writes, and those writes vanish when the container restarts. The volume type decides where the files really live: on the node's disk, in memory, in a [ConfigMap or Secret](card:configmaps-and-secrets), or in network storage.

## Why it exists

The payment service writes logs to `/app/logs`, and a log-shipper [sidecar](card:multi-container-pods) in the same Pod must read them. Without a volume, two things go wrong. When the payment-service container crashes, the kubelet restarts it with a clean filesystem, so the logs are gone. And the sidecar cannot see the other container's files at all. A volume belongs to the Pod, not to one container, so it fixes both.

1. You list each volume once under the Pod's `spec.volumes`, with a name and a type, such as `emptyDir`.
2. Each container that needs it adds a `volumeMounts` entry with the same name and its own `mountPath`.
3. When the Pod is assigned to a node, the kubelet creates the volume (an empty folder for `emptyDir`) and mounts it into the containers as they start.
4. If a container crashes, the kubelet restarts it and mounts the same volume again, with its files intact.
5. When the Pod is removed from the node, ephemeral volumes such as `emptyDir` are deleted. Storage behind a `persistentVolumeClaim` volume stays.

So the key is: a volume lives at the Pod level, and its type decides what happens after the Pod.

## Example

The payment service and its log shipper share one emptyDir:

```yaml
# payment-service Pod template (part)
volumes:
  - name: logs
    emptyDir: { sizeLimit: 500Mi }
containers:
  - name: payment-service
    image: payment-service:1.4.0
    volumeMounts: [{ name: logs, mountPath: /app/logs }]
  - name: log-shipper
    image: log-shipper:1.0
    volumeMounts: [{ name: logs, mountPath: /logs, readOnly: true }]
```

What to notice:

- The volume is declared once, but each container mounts it at its own path: `/app/logs` and `/logs` show the same files.
- `readOnly: true` stops the shipper from changing or deleting the logs; the payment service can still write.
- `sizeLimit: 500Mi` caps the folder. The space comes from the node's ephemeral storage, so other users of that disk can fill it first.
- If you add `medium: Memory`, the folder is RAM-backed and fast, but the log files then count against the payment-service container's memory limit.

## Rules and defaults

- **Common types:** `emptyDir` (scratch space), `configMap` and `secret` (settings as files), `downwardAPI` (the Pod's own name, namespace and labels as files), `projected` (several of these in one folder), `persistentVolumeClaim` (durable storage).
- **emptyDir medium:** the node's disk by default; `medium: Memory` uses tmpfs. With no `sizeLimit`, a memory-backed emptyDir can grow to the node's allocatable memory.
- **configMap and secret volumes:** always mounted read-only.
- **subPath:** mounts one file or sub-folder of a volume instead of its root. A ConfigMap, Secret or downwardAPI volume mounted with `subPath` never receives updates.
- **hostPath:** mounts a path from the node. It can expose kubelet credentials or the container runtime socket, and Pod Security's Baseline level forbids it. Keep it for node agents.
- **No nesting:** a volume cannot be mounted inside another volume.

## Not to be confused with

A volume is a field of one Pod's spec: a folder made available to that Pod's containers. A [PersistentVolume](card:persistent-storage), which comes next, is a separate cluster object for real storage that exists without any Pod; a Pod reaches it through a `persistentVolumeClaim` volume. Rule: volume = how a Pod mounts a folder; PersistentVolume = storage that lives on its own.

## Interview Qs

### What happens to emptyDir data when a container crashes?

Nothing. A crash does not remove the Pod from the node; the kubelet restarts the container in the same Pod, and the files are still there. The data is deleted permanently when the Pod leaves the node, for example when it is deleted or evicted.

### Why is hostPath risky?

It gives the container access to the node's filesystem, which can hold kubelet credentials or the container runtime socket, a path to container escape. Pods from one template may also behave differently on different nodes. The [Pod Security](card:pod-security) Baseline level forbids it; keep it for node agents.

### How do two containers in a Pod share files?

Declare one volume, usually an emptyDir, under `spec.volumes` and mount it in both containers. Each container chooses its own `mountPath`, and both see the same files, as in the [sidecar](card:multi-container-pods) pattern.
