## Why it exists

A container's files vanish when it restarts, and two containers in one Pod cannot see each other's files. A volume fixes both.

## How it works

<Compare id="emptydir-vs-persistent-volume" />

- Ephemeral types (emptyDir, configMap, secret, downwardAPI, CSI ephemeral) are created and destroyed with the Pod.
- A `persistentVolumeClaim` volume mounts a [PersistentVolume](card:persistent-storage), which stays after the Pod is gone.

## Example

```yaml
# payment-service writes logs; a sidecar ships them
volumes:
  - name: logs
    emptyDir: { sizeLimit: 500Mi }
containers:
  - name: payment-service
    image: payment-service:1.4.0
    volumeMounts: [{ name: logs, mountPath: /app/logs }]
  - name: log-shipper
    image: log-shipper:1.0
    volumeMounts: [{ name: logs, mountPath: /logs, readOnly: true }]
```

## Interview Qs

### What happens to emptyDir data when a container crashes?

Nothing. The kubelet restarts the container in the same Pod and the files are still there. The data is deleted when the Pod leaves the node, for example when it is deleted or evicted.

### Why is hostPath risky?

It exposes the node's filesystem, which can hold kubelet credentials or the container runtime socket: a path to container escape. The [Pod Security](card:pod-security) Baseline level forbids it; keep it for node agents only.

### How do two containers in a Pod share files?

Mount the same volume, usually an emptyDir, in both, as in a [sidecar](card:multi-container-pods). Each container chooses its own `mountPath`.
