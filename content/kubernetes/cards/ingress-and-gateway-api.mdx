## Why it exists

A LoadBalancer Service exposes one Service and knows nothing about HTTP paths. One entry point should send `/api/payments` and `/api/orders` to different Services, with HTTPS handled once.

## How it works

<Mermaid
  alt="Gateway API roles: the infrastructure provider's GatewayClass names the controller; the platform team's Gateway listens on 443; the app team's HTTPRoute for /api/payments attaches to it and sends traffic to payment-service and its Pods."
  chart={`flowchart LR
  GC["GatewayClass (infra provider)"] --> G["Gateway :443 (platform team)"]
  R["HTTPRoute /api/payments (app team)"] -- attaches to --> G
  G --> S[Service payment-service]
  S --> P[Pods :8080]`}
/>

<Compare id="ingress-vs-gateway-api" />

- HTTPS is decrypted at the Gateway or Ingress; the certificate sits in a Secret.
- `backendRefs` weights split traffic 90/10 for a [canary](card:release-strategies).

## Example

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: payments-route
  namespace: payments
spec:
  parentRefs: [{ name: public-gateway, namespace: infra }] # Gateway must allow payments
  rules:
    - matches: [{ path: { type: PathPrefix, value: /api/payments } }]
      backendRefs: [{ name: payment-service, port: 80 }]
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Routes a Gateway accepts | only from its own namespace (`allowedRoutes`) | Gateway API v1.6 |
| Ingress without `ingressClassName` | the IngressClass marked default | Kubernetes 1.37 |

## Interview Qs

### Why use Ingress or a Gateway when a LoadBalancer Service already exposes the app?

A LoadBalancer gives one Service its own load balancer and sees only ports. Ingress or a Gateway puts many Services behind one address, routes by host and path, and terminates TLS once.

### Is Ingress deprecated?

No. Ingress is GA and stays, but it is frozen: no new features. New work should use Gateway API.

### Ingress NGINX is retired. What do you do?

It still runs but gets no security fixes after March 2026. Migrate to a Gateway API implementation, as Kubernetes suggests, or another maintained controller.
