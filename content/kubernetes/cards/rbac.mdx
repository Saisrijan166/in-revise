## Why it exists

Many people and programs call the same API server. Without rules, any of them could read Secrets or delete Deployments.

## How it works

<Steps label="One request to the API server">
  <Step title="Authenticate">Who is calling? Certificate, token or ServiceAccount token. No match: 401.</Step>
  <Step title="Authorise">RBAC checks the bindings. No rule allows it: 403.</Step>
  <Step title="Admission">Admission controllers may change or reject writes. One rejection is final.</Step>
  <Step title="Store">The object is validated and saved.</Step>
</Steps>

<Compare id="role-vs-clusterrole" />

- A RoleBinding may point to a ClusterRole: the common rules are reused, but rights stay in that namespace.
- Who the Pod is comes from its [ServiceAccount](card:service-accounts); RBAC decides what it may do.

## Example

payment-service may only read ConfigMaps in `payments`:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata: { name: config-reader, namespace: payments }
rules:
  - { apiGroups: [""], resources: [configmaps], verbs: [get, list, watch] }
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata: { name: payment-service-config-reader, namespace: payments }
subjects: [{ kind: ServiceAccount, name: payment-service, namespace: payments }]
roleRef: { apiGroup: rbac.authorization.k8s.io, kind: Role, name: config-reader }
```

## Interview Qs

### How do you check what a ServiceAccount is allowed to do?

Ask the API server: `kubectl auth can-i list configmaps -n payments --as=system:serviceaccount:payments:payment-service`. It answers yes or no. Add `--list` to see every allowed action in the namespace.

### How do you protect Secrets with RBAC?

Grant `get` on named Secrets only to the ServiceAccount that needs them. `list` and `watch` also reveal contents. Anyone who can create Pods in a namespace can mount its Secrets, so limit that too.

### Why use a ClusterRole in a RoleBinding?

To write a rule set once, like the built-in `view` or `edit`, and grant it namespace by namespace. The binding keeps the rights inside its own namespace.
