## Why it exists

Some agents must run on every machine, such as a log collector reading that node's files. A replica count cannot follow nodes as they come and go.

## How it works

<Mermaid
  alt="The log-agent DaemonSet runs one Pod on node 1 and one on node 2. When node 3 joins the cluster, the DaemonSet adds a log-agent Pod there too."
  chart={`flowchart LR
  DS[DaemonSet log-agent] --> A[Node 1: log-agent Pod]
  DS --> B[Node 2: log-agent Pod]
  DS -. "node 3 joins" .-> C[Node 3: Pod added]`}
/>

- Typical agents: log collectors, node monitoring, storage daemons; kubeadm runs kube-proxy as a DaemonSet.
- Tainted nodes, such as control-plane nodes, need a matching toleration: [Taints and Tolerations](card:taints-and-tolerations).

## Example

```yaml
apiVersion: apps/v1
kind: DaemonSet                    # no replicas field
metadata: { name: log-agent, namespace: logging }
spec:
  selector: { matchLabels: { app: log-agent } }
  template:
    metadata: { labels: { app: log-agent } }
    spec:
      containers:
        - name: agent
          image: log-agent:2.0
          volumeMounts: [{ name: varlog, mountPath: /var/log, readOnly: true }]
      volumes: [{ name: varlog, hostPath: { path: /var/log } }]
```

## Interview Qs

### When do you use a DaemonSet?

For an agent that must run on every node, or every node of a kind: log shipping, node metrics, network or storage plugins. It adds the Pod to new nodes and removes it from nodes that leave.

### How do you run a DaemonSet on only some nodes?

Set a nodeSelector or node affinity in the Pod template; the controller creates Pods only on matching nodes. To include tainted nodes, add matching tolerations.
