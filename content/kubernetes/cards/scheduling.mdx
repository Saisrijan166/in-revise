## Why it exists

A Pod needs a node with enough room, the right hardware and safe neighbours. Picking by hand does not scale, so the scheduler places every new Pod.

## How it works

<Steps label="How kube-scheduler places a Pod">
  <Step title="Watch">A new Pod has no node yet.</Step>
  <Step title="Filter">Drop nodes without room for its requests, matching labels or affinity, or with an untolerated taint.</Step>
  <Step title="Score">Rank the feasible nodes, for example by spread and preferred-affinity weights.</Step>
  <Step title="Bind">Tell the API server the winner; that node's kubelet starts the Pod.</Step>
</Steps>

- `IgnoredDuringExecution`: rules apply only at placement; a running Pod stays if node labels change.
- `nodeName` skips the scheduler; it is meant for custom schedulers.
- Keeping Pods off nodes: [taints](card:taints-and-tolerations). Why spreading matters: [high availability](card:high-availability).

## Example

```yaml
# payment-service Pod template: 3 replicas, one per zone
topologySpreadConstraints:
  - maxSkew: 1
    topologyKey: topology.kubernetes.io/zone
    whenUnsatisfiable: DoNotSchedule
    labelSelector:
      matchLabels: { app: payment-service }
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `whenUnsatisfiable` | `DoNotSchedule` | Kubernetes 1.37 |
| Built-in spreading | soft: maxSkew 3 per node, 5 per zone | kube-scheduler, Kubernetes 1.37 |

## Interview Qs

### Why is a Pod stuck in Pending?

No node passed the filter: too little free CPU or memory for its requests, no node with the required labels, or an untolerated taint. `kubectl describe pod` shows a FailedScheduling event with the reason.

### nodeSelector or node affinity?

nodeSelector is the simplest: the node needs all listed labels. Node affinity adds operators such as In and NotIn, and soft preferred rules with weights.

### Anti-affinity or topology spread for replicas?

Required anti-affinity allows at most one matching Pod per domain, so extra replicas stay Pending. Topology spread allows several per domain and keeps the counts even.
