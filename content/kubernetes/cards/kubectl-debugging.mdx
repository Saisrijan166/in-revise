## Why it exists

Kubernetes records why things fail in status, events and logs. Reading them in a fixed order beats guessing.

## How it works

<Steps label="Debug a Pod, outside in">
  <Step title="get">`kubectl get pods -o wide`: status, restarts, node.</Step>
  <Step title="describe">Container state, exit code and recent events; meanings in [Pod errors](card:pod-errors).</Step>
  <Step title="events">`kubectl get events --sort-by=.metadata.creationTimestamp` for the whole namespace.</Step>
  <Step title="logs">`kubectl logs` and `--previous`; add `-c` for one container.</Step>
  <Step title="exec">Run a command inside a running container, if it has a shell.</Step>
  <Step title="debug">`kubectl debug -it POD --image=busybox:1.28 --target=payment-service` when it has none.</Step>
</Steps>

- Events are kept only for a short time: [events and logs](card:observability-in-k8s).
- Rollout stuck? `kubectl rollout status`: [rollouts](card:rolling-updates-rollbacks).

## Example

Customers get errors on `/api/payments`. Check the Service path in order:

```bash
kubectl get pods -n payments -l app=payment-service   # READY 0/1? see probes
kubectl get endpointslices -n payments -l kubernetes.io/service-name=payment-service
kubectl get svc payment-service -n payments -o yaml   # selector, targetPort 8080
kubectl run tmp -n payments --rm -it --image=busybox:1.28 -- nslookup payment-service
kubectl get networkpolicy -n payments
```

Empty EndpointSlices mean the [selector](card:services) matches no Pods or no Pod is [ready](card:probes).

## Interview Qs

### A Service does not respond. How do you debug it?

Check that Pods are ready, the EndpointSlices list their IPs, the Service selector matches the Pod labels, targetPort matches the container port, DNS resolves the name, and no [NetworkPolicy](card:network-policies) blocks it.

### The image has no shell. How do you look inside?

`kubectl debug` adds an ephemeral container with your tools to the running Pod. `--target` shares the app container's process namespace. `--copy-to` debugs a copy instead.

### A node shows NotReady. What do you check?

`kubectl describe node`: the Ready condition and pressure conditions (memory, disk, PIDs), plus events. `kubectl debug node/NAME` opens a shell in a Pod on that node.
