## What it is

An LLM is not trained in one go; it is built in stages. Pre-training produces a [base model](card:what-is-an-llm) that can continue text but does not follow requests. Later stages turn that base model into a helpful assistant that follows instructions and gives answers people prefer. Each stage uses a different kind of [training data](card:machine-learning-types), from raw text at the start to human rankings at the end.

## Why it exists

Next-token prediction on its own gives a model that continues text but does not do what you ask: given "Write a refund email", a base model might just add more instructions instead of writing the email. The later stages fix this. They teach it to follow instructions and to prefer the kind of answer people actually want, which is what makes an API model usable without you shaping every reply by hand.

## How it works

Each stage takes the model from the one before and changes it with different data.

<Steps label="From raw text to a chat assistant">
  <Step title="Pre-training">The model predicts the next token over huge unlabelled text. No labels are written by hand; the text itself is the signal. The result is a base model that knows language.</Step>
  <Step title="Supervised fine-tuning">It is trained on prompt-and-good-answer pairs written as demonstrations. The result follows instructions.</Step>
  <Step title="Preference tuning">People rank competing answers. RLHF trains a reward model from those rankings and tunes the model to score well; DPO tunes directly on the rankings with no separate reward model.</Step>
  <Step title="Your fine-tune (optional)">An app team may further adapt tone, format or a narrow task, often with LoRA on an open-weight model.</Step>
</Steps>

So the key is that each stage adds a different ability: language, then instruction-following, then alignment with human preference.

## Example

An app team rarely does the first three stages; the realistic choice is whether to fine-tune at all, and LoRA makes it cheap when you do.

```text
Full fine-tune of a 175B model:  update all ~175,000,000,000 weights   (very costly)
LoRA fine-tune of the same model: base weights frozen; train small
                                   added matrices ~ 10,000x fewer params (Hu et al., 2021)
Result: a small adapter you load on top of the base model, one per task
```

What to notice:

- LoRA freezes the base model and trains only small added matrices, so it needs far less GPU memory and storage per task (Hu et al., 2021).
- The output is a small adapter, not a new full model, so you can keep one adapter per task.
- None of this adds live data: a model fine-tuned today still will not know tomorrow's refund statuses, which is why fresh facts come from tools or RAG.

## Rules and defaults

- **Pre-training is self-supervised:** the next-token labels come from the text itself, so no hand-labelling is needed (see [machine-learning-types](card:machine-learning-types)).
- **Fine-tune for behaviour, not changing facts:** use it for format, tone or a narrow task, or to make a smaller model good at one job.
- **Provider platforms change:** OpenAI's docs (21-10-2026) say its fine-tuning platform is winding down, so re-check availability before planning a fine-tune.
- **Which technique for a feature:** choose between RAG, fine-tuning and long context deliberately; see [rag-or-fine-tuning](card:rag-or-fine-tuning).

## Interview Qs

### What is RLHF?

Reinforcement learning from human feedback. People rank model answers, a reward model learns those preferences, and the model is tuned to score highly against that reward model. InstructGPT used RLHF after supervised fine-tuning to make the model more helpful and aligned.

### When would you fine-tune instead of prompting?

When prompts and examples cannot get a consistent format or tone, or when you want a smaller, cheaper model to do one narrow task reliably. You would not fine-tune to add facts that change, because fine-tuned facts go stale; fetch those with tools or RAG instead.

### What is LoRA, and why is it popular?

LoRA is a parameter-efficient fine-tuning method. It freezes the base model's weights and trains only small low-rank matrices added alongside them. That needs far less GPU memory and storage, and produces a small adapter per task instead of a full model copy.
