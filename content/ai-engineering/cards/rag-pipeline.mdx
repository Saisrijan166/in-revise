## What it is

The RAG pipeline is the set of steps that turn documents into grounded answers. It has two separate flows. Ingestion is the offline flow that prepares the documents: it loads them, splits them into [chunks](card:chunking), turns each chunk into an [embedding](card:embeddings), and stores the vectors with their metadata. Query is the online flow that runs for each question: it embeds the question, searches for the closest chunks, and hands them to the LLM. [What RAG is](card:what-is-rag) explains the idea; this concept is the plumbing behind it.

## Why it exists

If you read, chunked and embedded thousands of pages while a user waited for an answer, every question would take minutes and cost a fortune in embedding calls. Splitting the work fixes this. The heavy, slow part (preparing the documents) runs once, ahead of time, during ingestion. Each question then needs only one quick step: embed the short question and run a single vector search. So latency and cost per request stay small and do not grow with the size of the corpus.

## How it works

1. Offline, you load each document, clean it, and split it into chunks.
2. You embed every chunk and store the vectors, along with metadata such as tenant and document id, in the vector database.
3. Online, when a question arrives, you embed the question with the same embedding model.
4. You search the store for the top-K nearest chunks, then [filter](card:metadata-and-filtering) or [rerank](card:reranking) them.
5. You put the surviving chunks into the prompt and ask the LLM to answer from them, with citations.

So the key is that steps 1 and 2 happen once, while steps 3 to 5 happen on every request.

## Example

Spring AI gives you one object for each half. The example wires ingestion and query in a single service.

```java
@Service
class RefundHelp {
    private final VectorStore store;
    private final ChatClient chat;
    RefundHelp(ChatClient.Builder builder, VectorStore store) {
        this.store = store;
        this.chat = builder.defaultAdvisors(QuestionAnswerAdvisor.builder(store).build()).build();
    }
    void ingest(Resource policy) {   // offline: chunk, embed, store
        store.add(TokenTextSplitter.builder().build().apply(new TextReader(policy).get()));
    }
    String ask(String q) {           // online: retrieve + generate
        return chat.prompt().user(q).call().content();
    }
}
```

What to notice:

- `ingest` is the whole offline half in one line: `TextReader` loads, `TokenTextSplitter` chunks, and `store.add` embeds and stores. You call it once per document, not per question.
- `store.add` triggers the embedding; the vector store calls the `EmbeddingModel` for you, so the database only stores and searches vectors.
- `ask` looks like a plain chat call, but the `QuestionAnswerAdvisor` quietly embeds the question, searches the store, and injects the top chunks into the prompt before the model sees it.
- Remove the advisor and `ask` becomes an ordinary LLM call with no retrieval, so it would answer from the model's memory only.

## Rules and defaults

- **Ingestion runs once per document:** re-run it only when that document changes, not per request.
- **Same embedding model both sides:** the question and the chunks must be embedded by the same model, or their vectors are not comparable.
- **Freshness is your job:** nothing re-indexes automatically. When a file changes, delete its old chunks by `document_id` and add the new ones.
- **Spring AI 2.0 defaults:** `TokenTextSplitter` chunks at 800 tokens; `QuestionAnswerAdvisor` runs the retrieve-and-stuff flow, while `RetrievalAugmentationAdvisor` exposes the same steps modularly.

## Interview Qs

### Walk me through building a RAG system.

Ingestion: load, clean, chunk, embed and store the vectors with metadata. Query: embed the question, search the top-K chunks with any tenant filters, rerank them, and prompt the LLM to answer only from those chunks with citations. Then evaluate retrieval and answers, and tune.

### A refund policy document changed. What do you do, and what do you not do?

Re-ingest just that document: delete its old chunks by document id, then chunk and embed the new version. You do not retrain or fine-tune anything, because RAG reads documents at query time, so the next question automatically sees the new text.

### Which Spring AI pieces map to each stage?

Ingestion uses a `DocumentReader` to load, `TokenTextSplitter` to chunk, and `VectorStore` to embed and store. Query uses the `QuestionAnswerAdvisor` for the standard retrieve-and-answer flow, or `RetrievalAugmentationAdvisor` when you want to customise each step.
