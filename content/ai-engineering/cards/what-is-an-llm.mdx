## Why it exists

Hand-written rules cannot cover open-ended language. A model trained on huge text learns the patterns itself and can answer, summarise or write code from a plain request.

## How it works

<Steps label="One generation loop, for 'Where is my refund for order 42?'">
  <Step title="Split into tokens">The text becomes token ids; see [tokens](card:tokens).</Step>
  <Step title="Score every next token">The [transformer](card:transformer-and-attention) gives a probability to each token in its vocabulary.</Step>
  <Step title="Pick one">One token is chosen; how is set by [sampling settings](card:sampling-parameters).</Step>
  <Step title="Append and repeat">The token joins the input; the loop runs again.</Step>
  <Step title="Stop">At an end token or the output limit.</Step>
</Steps>

- Model families as dated examples (21-10-2026): GPT, Claude, Gemini, Llama, Mistral. No ranking.
- A reasoning model spends hidden reasoning tokens before the visible answer; they are billed as output.
- Everything it "knows" lives in its weights or in the request; see [LLM limits](card:llm-limits).

## Interview Qs

### What is an LLM, in one line?

A large neural network, usually a transformer, trained on huge text to predict the next token. Repeating that prediction produces whole answers, code or summaries.

### Why does the same prompt sometimes give a different answer?

Each step picks a token from a probability list. With sampling, a different pick early on leads to a different answer. Settings such as temperature control how random the pick is.

### Base model, chat model, reasoning model: what is the difference?

A base model only continues text. A chat model is tuned to follow instructions. A reasoning model also thinks in hidden tokens first, so it is slower and costs more. See [the comparison](compare:base-vs-instruct-vs-reasoning-model).
