## What it is

An LLM, a large language model, is a very large [neural network](card:neural-networks) trained to predict the next piece of text. "Large" means billions of learned weights, trained on a huge amount of text. Its one skill is this: given the text so far, it gives a probability to every possible next token (a token is a word or part of a word; the next concept covers them). It is the engine behind chat assistants, and it is what you call through an API when you build an AI feature.

## Why it exists

Open-ended language is too varied for hand-written rules: you cannot list every question a customer might ask or every way to phrase a reply. Instead of rules, an LLM learns the patterns of language itself from huge text during [training](card:how-models-learn). Then, at request time, it can answer, summarise, translate or write code from a plain instruction, with no code written for each case.

## How it works

The model does one small thing in a loop. The loop below runs for the question "Where is my refund for order 42?".

<Steps label="One generation loop">
  <Step title="Split into tokens">The input text is turned into [tokens](card:tokens), the small pieces the model reads.</Step>
  <Step title="Score every next token">The [transformer](card:transformer-and-attention) gives a probability to each possible next token.</Step>
  <Step title="Pick one">One token is chosen from that list; how random the choice is depends on the [sampling settings](card:sampling-parameters).</Step>
  <Step title="Append and repeat">The chosen token is added to the input, and the loop runs again on the longer text.</Step>
  <Step title="Stop">The loop ends at a special end-of-text token or when the output limit is reached.</Step>
</Steps>

So the key is that an LLM never plans the whole answer at once; it builds it one token at a time, and each token depends on everything before it.

## Example

The support assistant runs on top of an LLM. Calling it is one method call; the loop above happens inside the provider.

```java
// Spring AI: one call to the model that runs the whole generation loop internally
String reply = chatClient.prompt()
        .user("Where is my refund for order 42?")
        .call()
        .content();
// reply (example): "Your refund for order 42 was approved and should arrive in 3-5 business days."
```

What to notice:

- One `call()` hides the whole token-by-token loop; your code sees only the finished text.
- The reply is shown as an example, not a guaranteed output: the same call can produce different wording, and the "3-5 business days" fact is invented unless you supplied the real policy.
- To make the answer depend on real data, you must put that data into the request; the model has no other way to reach it.

## Rules and defaults

- **It only predicts text:** every answer, including JSON or code, is produced token by token by the same next-token step.
- **Model families (examples, 21-10-2026):** GPT, Claude, Gemini, Llama and Mistral are all LLMs built this way; this site does not rank them.
- **Reasoning models cost more:** a reasoning model first writes hidden reasoning tokens before the visible answer, and those tokens are billed as output.
- **Knowledge is fixed:** everything the model "knows" is in its weights or in the request you send; it cannot reach anything else on its own (see [llm-limits](card:llm-limits)).

## Not to be confused with

A database or a search engine returns stored data; an LLM writes new text that is only likely to be right. The base, instruction-tuned and reasoning kinds are all LLMs that differ in how they were trained, not in this core next-token job. Rule: LLM = generate text; database = return exact rows; search = rank existing documents.

## Interview Qs

### What is an LLM, in one line?

A large neural network, usually a transformer, trained on huge text to predict the next token. Repeating that one prediction, with each chosen token fed back in, produces whole answers, code or summaries.

### Why does the same prompt sometimes give a different answer?

Each step picks a token from a probability list, and the pick is usually not forced to the single most likely token. A different pick early on leads the whole sentence down a different path. Settings such as temperature control how random the pick is.

### What is the difference between a base, a chat and a reasoning model?

A base model only continues text. An instruction-tuned (chat) model is further trained to follow instructions. A reasoning model also writes reasoning tokens first, so it handles harder problems but is slower and costs more. See [the comparison](compare:base-vs-instruct-vs-reasoning-model).
