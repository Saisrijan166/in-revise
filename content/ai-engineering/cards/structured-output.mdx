## Why it exists

Backend code needs fields such as status and orderId, not a paragraph. Free text breaks parsers and turns every reply into a guess.

## How it works

<Compare id="json-mode-vs-structured-outputs" />

- OpenAI: `json_schema` format with strict mode. Anthropic: `output_config.format` (the old `output_format` is deprecated).
- Spring AI adds format instructions and parses the reply; it can also switch on the provider's native mode.
- Business-rule checks after parsing: [output validation](card:output-validation).

## Example

```java
record RefundStatus(String orderId, String status, String nextStep) {}

@Service
class RefundAssistant {
    private final ChatClient chat;
    RefundAssistant(ChatClient.Builder builder) { this.chat = builder.build(); }

    RefundStatus status(String order) {
        return chat.prompt()
            .user(u -> u.text("Give the refund status for: {order}").param("order", order))
            .call().entity(RefundStatus.class);
    }
}
```

Example response:

```json
{ "orderId": "42", "status": "REFUND_INITIATED", "nextStep": "₹500 is on its way to your UPI account" }
```

## Interview Qs

### What is the difference between JSON mode and structured outputs?

JSON mode only guarantees valid JSON. Structured outputs constrain the reply to your JSON Schema, so required fields and types are present. OpenAI recommends structured outputs over JSON mode where supported.

### Can structured output still fail?

Yes. A refusal, or a reply cut off by the token limit, may not match the schema. Check the refusal field or stop reason, retry or fall back, then validate the values.
