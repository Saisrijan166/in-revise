## What it is

Similarity search is the step that uses [embeddings](card:embeddings) to find related text. You embed the question into a query vector, then return the K stored vectors that are closest to it. "Closest" is defined by a **distance metric**, a formula that scores how near two vectors are. The common metric is cosine similarity, which scores two vectors by the angle between them.

## Why it exists

Once text is an embedding, "find related text" turns into "find the nearest vectors". But "nearest" is not obvious: you need one agreed rule for measuring how near two lists of numbers are. A distance metric is that rule. Without it you could store vectors but could not rank them, so you could not say which chunks to send to the LLM.

## How it works

Cosine, dot product and Euclidean are three ways to measure nearness; the table shows how they differ.

<Compare id="cosine-vs-dot-product-vs-euclidean" />

1. Embed the question with the same model used for the documents, giving one query vector.
2. Score the query vector against each stored vector using the chosen metric.
3. Sort by that score and keep the top K (for example the 5 nearest chunks).

Comparing against every stored vector is called [exact kNN](card:exact-knn). It is perfectly accurate but gets too slow at millions of vectors, which is why large stores use an approximate [index](card:vector-databases) instead.

## Example

Cosine similarity in plain Java, so you can see the two extreme scores. The score is 1 when two vectors point the same way, and 0 when they are at right angles.

```java
public class Cosine {
    static double cosine(double[] a, double[] b) {
        double dot = 0, na = 0, nb = 0;
        for (int i = 0; i < a.length; i++) { dot += a[i] * b[i]; na += a[i] * a[i]; nb += b[i] * b[i]; }
        return dot / (Math.sqrt(na) * Math.sqrt(nb));
    }
    public static void main(String[] args) {
        System.out.println(cosine(new double[]{1, 2, 3}, new double[]{2, 4, 6})); // same direction
        System.out.println(cosine(new double[]{1, 0}, new double[]{0, 1}));       // right angle
    }
}
```

```text output
1.0
0.0
```

What to notice:

- `{1,2,3}` and `{2,4,6}` point the same way (one is just twice the other), so the score is 1.0; cosine ignores length and looks only at direction.
- `{1,0}` and `{0,1}` are at right angles, so the score is 0.0, meaning unrelated.
- Replace cosine distance with cosine similarity in a query and you must flip the sort order, because bigger similarity means closer but smaller distance means closer.

## Rules and defaults

- **Metric follows the model:** use the distance the embedding model's docs recommend; OpenAI's embeddings are normalised, so cosine and dot product behave the same.
- **Similarity vs distance:** cosine similarity is bigger when closer; cosine distance is `1 − similarity`, so it is smaller when closer. pgvector's `<=>` returns distance.
- **Exact search as a baseline:** scoring every vector is exact but scales badly; switch to an approximate index once you have many vectors.

## Interview Qs

### What is cosine similarity?

It scores two vectors by the angle between them. Pointing the same way gives 1, at right angles gives 0, opposite gives -1. Vector length is ignored, so it compares direction only, which is where an embedding keeps meaning. That makes it a natural fit for comparing embeddings.

### Cosine similarity or dot product: which should you use?

Dot product also counts vector length, while cosine looks only at direction. For normalised (length-1) vectors the two give the same ranking, and dot product is slightly faster to compute. If vectors are not normalised, follow the embedding model's recommendation rather than switching on a hunch.

### What is the difference between similarity and distance?

Similarity is bigger when two vectors are closer; distance is smaller when they are closer. Cosine distance is `1 − cosine similarity`, so both give the same order, just reversed. The practical point: check whether your store returns distance or similarity before you sort, or you will rank results backwards.
