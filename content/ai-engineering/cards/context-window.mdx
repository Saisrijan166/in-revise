## Why it exists

A model can only attend to a limited number of tokens at once. The app must decide what goes in, because anything left out does not exist for the model.

## How it works

<Mermaid
  alt="One request to the support assistant fills the context window from top to bottom: system prompt, tool definitions, conversation history, retrieved refund-policy chunks, the user's question, and finally the model's output including any reasoning tokens. All of it must fit in the window."
  chart={`flowchart TD
  S[System prompt] --> T[Tool definitions]
  T --> H[Conversation history]
  H --> R[Retrieved policy chunks]
  R --> Q["Question: refund for order 42?"]
  Q --> O["Output + reasoning tokens"]
  O --> L{{"Must fit the window"}}`}
/>

- Every turn re-sends the history, so long chats grow the input; see [conversation memory](card:conversation-memory).
- Anthropic: input over the window returns a 400 error; a reply that reaches it stops early.
- OpenAI: a reply that hits the limit comes back with status `incomplete`.

## Interview Qs

### What happens when the conversation gets longer than the window?

The request fails or the reply is cut off. The app must trim or summarise old turns and send fewer, better chunks. Count tokens before sending to stay inside the limit.

### If a model has a huge window, do we still need RAG?

Yes, usually. Long prompts cost more, run slower and recall worse, especially in the middle. Retrieval sends only the relevant part; see [RAG](card:what-is-rag).

### Is the context window the model's memory?

Only for this one request. It is working space, separate from training data, and it is empty again on the next call unless the app re-sends the history.
