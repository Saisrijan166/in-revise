## What it is

These are two ways to prompt, told apart by how many examples you include. **Zero-shot** gives the model only the instructions and the input, with no examples. **Few-shot** adds a few worked examples, each an input paired with its correct output, before the real input. A single example is called **one-shot**. The model copies the pattern in the examples for that call. The word "shot" just means "example".

## Why it exists

Some outputs are hard to pin down in words: an exact label set, a specific format, a particular tone. Writing more and more rules to describe them is slow and often still vague. Showing the model two or three correct examples is quicker and usually more reliable, because the model copies what it sees rather than interpreting a description.

## How it works

<Compare id="zero-shot-vs-few-shot" />

1. Write the instructions and try zero-shot first, since it costs the fewest tokens.
2. If the output drifts in format or labels, add a few examples, each showing an input and its correct output.
3. Make the examples diverse and all in one consistent format, and wrap each in an `<example>` tag so the model sees where one ends.
4. Send the examples on every call, because they work only while they are in the prompt. The weights never change; this is [in-context learning](card:how-models-learn), not training.

So the key is that few-shot steers behaviour without any training, at the price of more input tokens on each call.

## Example

A zero-shot instruction would be just the first line. This is the few-shot version: three labelled examples teach the label set, then the real message comes last.

```text
Classify the message as refund-status, payment-failed or other.

<example>Message: My UPI payment failed but the money was debited.
Label: payment-failed</example>
<example>Message: When will I get the 500 rupees back for order 42?
Label: refund-status</example>
<example>Message: Can I change my delivery address?
Label: other</example>

Message: {message}
Label:
```

What to notice:

- The three examples fix the exact label set, so the model is far less likely to invent a new label like "complaint".
- Each example pairs an input with its output in the same shape, and ends with `Label:`, so the model continues the pattern for `{message}`.
- The examples are diverse: one per label. Three near-identical examples would teach less and cost the same tokens every call.
- Dropping all three examples turns this into a zero-shot prompt; it may still work, but labels can drift when wording is unusual.

## Rules and defaults

- **Try zero-shot first:** it is the cheapest and often enough; add examples only when output drifts.
- **Use 3 to 5 diverse examples:** Anthropic suggests this range for few-shot; diversity matters more than count.
- **Keep one consistent format:** mixed formats confuse the model; wrap examples in tags such as `<example>`.
- **Examples cost tokens every call:** they are part of the input, so they add cost and latency on each request.
- **Weights do not change:** few-shot is in-context learning; to change the model itself you would fine-tune, which is a separate, heavier process.

## Not to be confused with

**Few-shot prompting** puts examples in the prompt and changes nothing in the model. **Fine-tuning** retrains the model's weights on many examples so the behaviour is baked in and costs no prompt tokens later. Rule: few-shot teaches per call through the prompt; fine-tuning teaches once by changing the weights.

## Interview Qs

### When would you use few-shot over zero-shot?

When the output format is unusual, the labels follow specific rules, or replies must stay consistent across calls. Start zero-shot because it is cheapest; add a few diverse examples only if the results drift.

### Does few-shot prompting change the model?

No. The examples are part of the input for that one call. The model follows the pattern in context and its weights stay the same. This is in-context learning. Changing the weights is fine-tuning, a separate and far more expensive process.

### How many examples should you give, and what is the cost?

Anthropic suggests 3 to 5 diverse examples. Each example is sent again on every call, so it adds input tokens, cost and latency each time. Too many near-identical examples waste tokens and can make the model overfit to that narrow pattern.
