## What it is

Hybrid search combines two ways of finding text. **Keyword search** ranks documents by how well they match the query's exact words; BM25 is the standard scoring formula for it. **Semantic search** is the [similarity search](card:similarity-search) over [embeddings](card:embeddings) you have already met: it ranks by meaning. Hybrid search runs both for the same query and fuses their two ranked lists into one, so a single result list carries both strengths.

## Why it exists

A support user might type "ORD-42 refund" or "my money is not back yet", often in the same session. Keyword search nails the first but fumbles the paraphrase; semantic search nails the paraphrase but can bury an exact order id, because an embedding treats a rare code as roughly "some number". Running only one method fails half the queries. Hybrid search keeps both so neither kind of query is left behind.

## How it works

1. Send the query to keyword search (BM25) and get one ranked list.
2. Send the same query to vector search and get a second ranked list.
3. Fuse the lists with [reciprocal rank fusion](card:rrf): each list contributes `1 / (k + rank)` for every document it ranks.
4. Sum each document's contributions across both lists and sort by the total; a [reranker](card:reranking) can then reorder the fused shortlist.

So the key is that fusion uses each document's **rank** in each list, not its raw score, so two very different score scales never have to be compared. (A [weighted score blend](card:weighted-score-blend) is the alternative, which normalises and mixes raw scores.) In PostgreSQL, [full-text search](card:postgres-full-text) plus pgvector gives both sides in one database.

## Example

RRF with k = 60, for a chunk ranked 1st by keyword search and 3rd by vector search.

```text
keyword list   rank 1  ->  1 / (60 + 1) = 0.0164
vector list    rank 3  ->  1 / (60 + 3) = 0.0159
fused RRF score                         = 0.0323
```

What to notice:

- Only the rank goes into the formula, so the keyword and vector scores, which are on different scales, are never compared directly.
- A smaller rank (nearer the top) gives a larger term, so being high in either list helps; being high in both wins.
- The constant k = 60 softens the gap between ranks 1 and 2; a larger k makes rank matter less, a smaller k makes the top rank dominate.

## Rules and defaults

- **BM25 is keyword ranking:** PostgreSQL's built-in `ts_rank` full-text search is not BM25; a BM25 engine or extension is needed for true BM25 scoring.
- **Dense vs sparse vectors:** an embedding is a dense vector (every value is set); keyword search uses a sparse vector (mostly zeros, one weight per matched term).
- **RRF default k:** 60 (Elasticsearch `rank_constant`); it needs no score tuning because it uses ranks only.

## Interview Qs

### What is hybrid search and why use it?

It runs keyword search (such as BM25) and vector search for the same query and merges the two results. You get exact-token matches (order ids, error codes) from keywords and meaning matches (paraphrases, synonyms) from vectors, so a mixed stream of real user queries is served well by one result list.

### How do you merge two ranked lists whose scores are on different scales?

Use reciprocal rank fusion: each list adds `1 / (k + rank)` for a document, and you sort by the sum. Because it uses ranks and not raw scores, the different scales never need to be compared. Weighted blending is the alternative, but it first has to normalise the scores.

### When does keyword search beat semantic search?

On exact tokens: order ids, transaction references, error codes and product names. An embedding of "ERR_TIMEOUT" sits near text about timeouts in general, so semantic search may return related text but miss the exact code. Keyword search matches the literal token, which is what the user wanted.
