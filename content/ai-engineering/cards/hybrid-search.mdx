## Why it exists

A customer types "ORD-42 refund" or "my money is not back". No single search method handles both exact ids and loose wording well.

## How it works

<Compare id="keyword-vs-semantic-search" />

- Fuse with [RRF](card:rrf) (ranks only, no tuning) or [weighted score blending](card:weighted-score-blend).
- In PostgreSQL, [full-text search](card:postgres-full-text) plus pgvector gives hybrid search in one database.
- Then a [reranker](card:reranking) can reorder the fused shortlist.

## Example

RRF with k = 60; a chunk ranked 1st by keywords and 3rd by vectors:

```text
keyword list  rank 1  ->  1 / (60 + 1) = 0.0164
vector list   rank 3  ->  1 / (60 + 3) = 0.0159
RRF score              =                0.0323
```

## Interview Qs

### What is hybrid search?

Running keyword search (such as BM25) and vector search for the same query and merging the results, so you get both exact matches and matches by meaning.

### How do you merge two ranked lists with different scores?

Reciprocal rank fusion uses only ranks: each list adds 1 / (k + rank). Scores on different scales never need comparing. Weighted blending first normalises scores, then mixes them.

### When does keyword search beat semantic search?

On exact tokens: order ids, transaction references, error codes, product names. An embedding may find text about error codes in general but miss the exact code.
