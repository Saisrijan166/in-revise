## Why it exists

The model gives a probability to every possible next token. These settings decide how to pick from them and when to stop.

## How it works

<Compare id="temperature-vs-top-p" />

- Even at temperature 0, output is not fully deterministic (Anthropic docs).
- When the cap is hit, the reason field says so: OpenAI `max_output_tokens`, Anthropic `max_tokens`.
- Stop sequences end the reply early when a chosen string appears.

## Example

```properties
spring.ai.openai.api-key=${OPENAI_API_KEY}
spring.ai.openai.chat.temperature=0.2
spring.ai.openai.chat.max-tokens=300
```

## Defaults

| What | Default | Where |
|---|---|---|
| temperature | 1.0 (range 0 to 1) | Anthropic Messages API |
| spring.ai.openai.chat.temperature | 0.8 | Spring AI 2.0 OpenAI starter |

## Interview Qs

### What is the difference between temperature and top-p?

Temperature reshapes the whole probability spread: low sharpens it, high flattens it. Top-p keeps only the smallest set of tokens whose probabilities add up to p. OpenAI advises changing one, not both.

### What temperature would you use for SQL generation or extraction?

Low, so output stays focused and repeatable. Even at 0 it is not fully deterministic, so still validate the result.

### What happens when max output tokens is too low?

The reply stops mid-way and the API reports the limit as the stop reason, so JSON may be incomplete. Check the reason and retry with a higher limit.
