## Why it exists

A model receives one list of messages. Roles tell it which text is the app's rules, which is the user's request and which is only data.

## How it works

| Role | Written by | Carries | Authority |
|---|---|---|---|
| System / developer | Your app | Persona, rules, format | High |
| User | The end user | The request | Below developer |
| Assistant | The model | Earlier replies | None |
| Tool | Your code | Tool results | None |

- OpenAI's Model Spec ranks root, system, developer, then user; quoted text and tool output carry no authority.
- Anthropic takes a top-level `system` parameter, then alternating `user` and `assistant` turns.
- Instructions hidden in retrieved chunks are still only data: see [prompt injection](card:prompt-injection).

## Example

Example request (Anthropic Messages API shape):

```json
{
  "model": "<model-id>",
  "max_tokens": 300,
  "system": "You are the support assistant for shop.example. Answer only about orders and refunds.",
  "messages": [
    { "role": "user", "content": "Hi, I need help with a refund." },
    { "role": "assistant", "content": "Sure. Which order is it?" },
    { "role": "user", "content": "Where is my refund for order 42?" }
  ]
}
```

## Interview Qs

### What is the difference between a system prompt and a user prompt?

The system (or developer) prompt comes from the app: role, rules, limits, format. The user prompt is the end user's request. When they conflict, providers rank the app's instructions higher.

### Can a system prompt keep a secret or enforce access control?

No. It can be extracted or overridden by injection. Keep keys in the backend and check permissions in code before any data or tool call ([LLM security](card:llm-security)).
