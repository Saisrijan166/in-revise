## What it is

Retrieval tuning is the set of choices that decide which chunks actually reach the prompt in a [RAG pipeline](card:rag-pipeline). The main dials are **top-K** (how many chunks you fetch), a **similarity threshold** (the lowest match score you accept), **query rewriting** (turning the user's words into a good search query), and **context assembly** (ordering, de-duplicating and trimming the chunks to fit the window). Getting these right is often the difference between a vague answer and a correct one.

## Why it exists

The user's raw question is often a poor search query: a follow-up like "and order 43?" means nothing on its own, and a vague question matches many weak chunks. If you then stuff every match into the prompt, you pay for more tokens and the real answer gets buried among noise, which lowers accuracy. Tuning what goes in gives answers that are both better and cheaper.

## How it works

<Steps label="From question to context">
  <Step title="Rewrite">Turn the question into a standalone search query using the chat history; optionally expand it into several queries.</Step>
  <Step title="Retrieve">Search the store with top-K, the similarity threshold and the [tenant filter](card:metadata-and-filtering), getting a set of candidate chunks.</Step>
  <Step title="Trim">Drop duplicate chunks, then [rerank](card:reranking) the candidates and keep only the best few.</Step>
  <Step title="Assemble">Order the kept chunks by relevance, label each with its source id, and check the whole block fits the token budget.</Step>
</Steps>

So the key is to retrieve wide but send narrow: gather candidates generously, then cut down to a few strong, labelled chunks.

## Example

This shows how a follow-up question is rewritten, then turned into a small labelled context block.

```text
History:   "Where is my refund for order 42?" -> answered
Follow-up: "and order 43?"
Rewritten: "Where is the refund for order 43, and when will it arrive?"
Context:   [refund-policy#4] UPI refunds reach the customer in 5-7 working days.
           [payment-faq#2]   A refund shows as a credit on the UPI app.
```

What to notice:

- The rewritten line is self-contained, so its embedding matches the refund documents; the raw "and order 43?" would not.
- Each chunk carries a source id like `refund-policy#4`. These labels let the model cite sources and let your code verify them, covered in [grounding and citations](card:grounding-and-citations).
- Only two chunks are passed, not twenty. The chat history itself is kept by [conversation memory](card:conversation-memory); it is used to rewrite, not stuffed into the context.

## Rules and defaults

- **Top-K default:** Spring AI 2.0 `SearchRequest` uses `topK = 4`, so four chunks are fetched unless you change it.
- **Threshold default:** `similarityThreshold = 0.0` accepts every match; raise it to drop weak chunks, but then handle the case where nothing passes.
- **No match left:** when the threshold filters out all chunks, the right behaviour is to answer "I don't know", not to invent one.
- **You must tune with evals:** there is no universal best top-K or threshold; measure them on your own questions (see [evals](card:ai-evaluation)).

## Interview Qs

### How do you pick top-K?

Measure it, do not guess. Run real questions through retrieval and check whether the correct chunk appears within the top K and how much noise comes with it. A common pattern is a larger K for the first search, then a [reranker](card:reranking) that keeps only the few best chunks for the prompt.

### What is HyDE?

Hypothetical Document Embeddings (Gao et al. 2022). An LLM first writes a fake answer to the question, and that answer, not the short question, is embedded and searched. A full answer looks more like the real documents than a terse question does, so it often retrieves better matches.

### A follow-up question returns nothing useful. What is wrong?

The follow-up is not standalone, so its embedding carries no real meaning. Rewrite it together with the chat history into a complete query before searching. Spring AI's `CompressionQueryTransformer` performs exactly this rewrite, turning "and order 43?" into a full question.
