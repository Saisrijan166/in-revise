## Why it exists

Some tasks need steps nobody can list in advance. An agent lets the model choose those steps itself.

## How it works

  alt="Agent loop: from the goal, the model decides; it calls a tool, the app runs it and returns the result, and the model decides again until the goal is met or a limit hits."
  chart={`flowchart LR
  G([Goal]) --> D{Model decides}
  D -- call a tool --> T[App runs the tool]
  T -- result --> D
  D -- goal met or limit hit --> F([Answer])`}
/>

- Each tool result is ground truth for the next decision; ReAct interleaves reasoning steps with actions.
- Stop on goal met, step limit or budget, and log every step ([observability](card:ai-observability)).
- Too many tools or permissions is [excessive agency](card:llm-security); fixed-step patterns are in [prompt chaining](card:prompt-chaining).

## Example

```text
Goal: "Where is my refund for order 42?"   (limit: 5 steps)
Step 1  need the order  -> getOrderStatus(42)
        observe: delivered; refund ₹500 to UPI, status PROCESSING
Step 2  enough to answer -> finish
Answer: draft explaining the ₹500 UPI refund is in progress
refundPayment needs backend rules + human approval
```

## Interview Qs

### What is the difference between an AI agent and a workflow?

A workflow follows a path your code defines. An agent lets the LLM pick the next tool in a loop, based on each result.

### How do you stop an agent looping forever or doing harm?

Cap steps, tool calls and spend; expose few least-privilege tools; require human approval for refunds; validate arguments in the backend; log every step.

### When would you not use an agent?

When the steps are known: a single call or a workflow is cheaper, faster and easier to test. Add complexity only when it clearly helps.
