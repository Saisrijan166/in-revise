## Why it exists

One big prompt that classifies, extracts and writes at once is hard to get right and to debug. Small steps can each be tested and fixed alone.

## How it works

<Steps label="Refund email chain">
  <Step title="1. Classify">An LLM call labels the intent: refund-status, payment-failed or other.</Step>
  <Step title="2. Extract">An LLM call returns the order id as [structured output](card:structured-output).</Step>
  <Step title="3. Gate and fetch">Code checks the order belongs to this customer, then reads it from PostgreSQL. No LLM.</Step>
  <Step title="4. Draft">An LLM call writes the reply from the fetched order data.</Step>
</Steps>

- Anthropic also names routing, parallelisation, orchestrator-workers and evaluator-optimiser workflows.
- When the steps cannot be known in advance, an [agent](card:ai-agents) fits better.

## Interview Qs

### What is prompt chaining and when do you use it?

Breaking a task into a fixed sequence of LLM calls, each using the previous output. Use it when the task splits cleanly into subtasks and accuracy matters more than latency.

### What are the downsides?

More calls mean more latency, cost and places to fail. An early mistake flows into later steps, so check each step's output in code.

### How is a chain different from an agent?

A chain follows steps fixed in code. An agent lets the model decide the next step and which tools to call, in a loop, until the task is done.
