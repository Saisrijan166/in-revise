## What it is

A token is a small piece of text that a model reads and writes as one unit. It is often a whole word, but can be part of a longer word, a space followed by a word, or a single punctuation mark. Before an [LLM](card:what-is-an-llm) sees your text, a tokenizer splits it into these tokens; this splitting is called tokenisation. The model's whole input and output are just sequences of tokens.

## Why it exists

A model needs a fixed, finite list of units it can recognise, called its vocabulary. Using whole words would make that list huge and still leave new or rare words unknown. Using single letters would make every sentence very long and slow. Sub-word tokens sit in between: a common word is one token, a rare word splits into a few known pieces, so any text can be encoded with a vocabulary of a sensible size.

## How it works

A tokenizer such as byte-pair encoding (BPE) learns which character runs appear together often and merges them into single tokens. These examples use OpenAI's `o200k_base` tokenizer.

| Text | Tokens | Count |
|---|---|---|
| `Where is my refund?` | `Where` · ` is` · ` my` · ` refund` · `?` | 5 |
| `मेरा रिफंड कहाँ है?` (same question, Hindi) | `म` · `ेरा` · ` र` · `िफ` · `ंड` · ` कहाँ` · ` है` · `?` | 8 |
| `tokenization` | `token` · `ization` | 2 |

1. The tokenizer scans the text and matches the longest known pieces it can.
2. A common word becomes one token; inside a sentence its leading space is usually part of the token, so `refund` appears as ` refund`.
3. A rare or compound word splits into several tokens, like `tokenization` into `token` and `ization`.
4. Non-English scripts often split into more, smaller tokens, so the Hindi line is 8 tokens for the same question that is 5 in English.

So the key is that token count, not word count, is what the model, the limits and the bill actually work in.

## Example

A real tiktoken run shows the counts above and how input and output tokens add up for billing.

```text
Request to the model:   system prompt + history + question   = input tokens
Model's reply:          visible answer (+ hidden reasoning)  = output tokens
Bill and rate limits:   input tokens + output tokens
```

What to notice:

- The bill and the rate limit use the sum of input and output tokens, so a long answer costs as much as a long prompt, often more per token.
- Hidden reasoning tokens from a reasoning model count as output even though you never see them.
- You can measure input tokens before you call, so you can trim the prompt or cap the output to stay within a budget and the [context window](card:context-window).

## Rules and defaults

- **English rule of thumb:** about 1 token per 4 characters, or 0.75 words (OpenAI docs); use it only for rough estimates.
- **Count exactly before sending:** OpenAI's `tiktoken` library for OpenAI models, or Anthropic's token-counting endpoint for Claude.
- **Read the real count after:** the response's `usage` field reports the exact input and output tokens the call used.
- **Tokenizers are model-specific:** a count from one model's tokenizer does not transfer to another model.

## Interview Qs

### Why do tokens matter to a backend developer?

Tokens set the context limit, the price and the latency of each call. Longer prompts and longer answers cost more money and take more time. So you trim the input to what is relevant and cap the output with a max-tokens setting to keep cost and latency predictable.

### How do you find how many tokens a prompt uses?

Count with the provider's own tokenizer before sending: `tiktoken` for OpenAI models, the token-counting endpoint for Claude. The rough "4 characters per token" guide is fine for a quick estimate. After the call, read the exact numbers from the response's `usage` field.
