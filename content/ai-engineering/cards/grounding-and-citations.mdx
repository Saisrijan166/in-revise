## What it is

**Grounding** means the assistant builds its answer only from the text you put in the prompt, usually the chunks retrieved in a [RAG pipeline](card:rag-pipeline), and refuses when that text does not hold the answer. A **citation** is a label on each claim pointing to the chunk id or page it came from. Together they turn a fluent reply into one a reader, and your own code, can check against its sources.

## Why it exists

A model can write a confident, fluent answer that is simply invented; this is [hallucination](card:hallucination). In a support assistant, an invented refund date is worse than no answer. Grounding ties each statement to a supplied document so the model has less room to make things up, and citations let both the user and your code trace a claim back and reject anything that does not check out.

## How it works

<Steps label="Grounded answer with sources">
  <Step title="Instruct">Tell the model: answer only from the chunks below, cite each claim as [chunk id], and if the answer is not there, say so and offer a human agent.</Step>
  <Step title="Generate">The model returns the answer with chunk ids attached to its claims.</Step>
  <Step title="Verify">Your code rejects any id that was not retrieved; [output validation](card:output-validation) checks the remaining answer.</Step>
  <Step title="Show">The UI displays the answer with links to the source pages.</Step>
</Steps>

So the key is that grounding is enforced in two places: the prompt asks for it, and your code checks it; the prompt alone is not enough.

## Example

First, an example reply (shown as an example, not a real model run): the model returns an answer plus the chunk ids it used.

```json
{ "answer": "UPI refunds reach you in 5-7 working days.", "citations": ["refund-policy#4"] }
```

Then your code checks every cited id against the chunks you actually retrieved.

```java
import java.util.*; import java.util.regex.*;
public class CitationCheck {
    public static void main(String[] args) {
        Set<String> retrieved = Set.of("refund-policy#4", "payment-faq#2");
        String answer = "UPI refunds take 5-7 working days [refund-policy#4]. Cards: 3 days [card-faq#9].";
        Matcher m = Pattern.compile("\\[([^\\]]+)]").matcher(answer);
        while (m.find()) {
            String id = m.group(1);
            System.out.println(id + (retrieved.contains(id) ? " -> retrieved" : " -> NOT RETRIEVED, reject"));
        }
    }
}
```

```text output
refund-policy#4 -> retrieved
card-faq#9 -> NOT RETRIEVED, reject
```

What to notice:

- The code pulls every `[id]` out of the answer and checks it against the `retrieved` set.
- `card-faq#9` was never retrieved, so it is flagged for rejection; this catches a claim the model attached to a source you never gave it.
- If you removed this check, an answer citing an invented chunk would reach the user looking trustworthy. Verification in code, not just the prompt, is what makes the citation reliable.

## Interview Qs

### What is grounding?

Basing the answer on trusted text supplied in the prompt, such as retrieved policy chunks, instead of on the model's training memory, and refusing to answer when that text does not contain the answer. It is the main defence against a fluent but invented reply.

### How do you make citations trustworthy?

Label every chunk with an id, require the model to attach an id to each claim, and reject in code any id you did not actually retrieve. Use the provider's built-in citation feature where it exists. Then measure how often cited chunks truly support the claim as faithfulness in [evals](card:ai-evaluation).

### Does a citation mean the answer is correct?

No. A citation shows where the claim is supposed to come from, not that the chunk supports it or that the chunk is right. The model can misread a chunk, or the chunk can be out of date. Correctness is checked separately by measuring faithfulness against the sources.
