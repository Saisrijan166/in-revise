## Why it exists

A fluent answer can still be invented. Grounding ties it to your documents, and citations let the user and your code check where each claim came from.

## How it works

<Steps label="Grounded answer with sources">
  <Step title="Instruct">"Answer only from the chunks below. Cite each claim as [chunk id]. If the answer is not there, say so and offer a human agent."</Step>
  <Step title="Generate">The model returns the answer with chunk ids.</Step>
  <Step title="Verify">Code rejects ids that were not retrieved; [output validation](card:output-validation) checks the rest.</Step>
  <Step title="Show">The UI shows the answer with links to the source pages.</Step>
</Steps>

- With Anthropic citations enabled, the API returns the cited text and its location, always pointing into the documents you sent.
- Asking the model to quote the relevant text first, then answer from the quotes, also reduces invented facts.

## Example

Example response (a fictional policy):

```json
{ "answer": "UPI refunds reach you in 5-7 working days.", "citations": ["refund-policy#4"] }
```

```java
import java.util.*; import java.util.regex.*;
public class CitationCheck {
    public static void main(String[] args) {
        Set<String> retrieved = Set.of("refund-policy#4", "payment-faq#2");
        String answer = "UPI refunds take 5-7 working days [refund-policy#4]. Cards: 3 days [card-faq#9].";
        Matcher m = Pattern.compile("\\[([^\\]]+)]").matcher(answer);
        while (m.find()) {
            String id = m.group(1);
            System.out.println(id + (retrieved.contains(id) ? " -> retrieved" : " -> NOT RETRIEVED, reject"));
        }
    }
}
```

```text output
refund-policy#4 -> retrieved
card-faq#9 -> NOT RETRIEVED, reject
```

## Interview Qs

### What is grounding?

Basing the answer on trusted text supplied in the prompt, such as retrieved policy chunks, instead of the model's training memory, and refusing when that text does not contain the answer.

### How do you make citations trustworthy?

Label every chunk with an id, require an id per claim, reject ids you did not retrieve, and use the provider's citation feature where it exists. Measure faithfulness in [evals](card:ai-evaluation).
