## Why it exists

An LLM only writes text. It cannot read live order rows or start a refund. Tool calling lets it ask your backend for data or actions through code you control.

## How it works

<Mermaid
  alt="The app sends the question and tool definitions to the model. The model returns a call getOrderStatus(orderId=42). The app checks the user owns order 42, reads the database and sends the tool result back. The model writes the answer."
  chart={`sequenceDiagram
  participant A as App (Spring Boot)
  participant M as Model
  participant D as Database
  A->>M: question + tool definitions
  M-->>A: call getOrderStatus(orderId=42)
  A->>A: user owns order 42?
  A->>D: read order, payment, refund
  A->>M: tool result
  M-->>A: final answer`}
/>

- Validate every argument; identity comes from the session, not the model.
- Keep tools few and narrow, read-only first; confirm money-moving actions and make them [idempotent](card:calling-llm-apis).
- The model never touches the database: tool, then backend, then DB ([wiring](card:ai-and-databases)). Full risk list: [LLM security](card:llm-security).

## Example

Spring AI 2.0; the user id comes through `ToolContext`, which the model never sees:

```java
@Component
class OrderTools {
    private final OrderService orders;
    OrderTools(OrderService orders) { this.orders = orders; }

    @Tool(description = "Status, payment and refund of one order")
    OrderStatus getOrderStatus(long orderId, ToolContext ctx) {
        long userId = (long) ctx.getContext().get("userId"); // from the session
        return orders.statusFor(userId, orderId);            // checks ownership
    }
}
// chatClient.prompt(q).tools(orderTools).toolContext(Map.of("userId", id)).call().content();
```

## Interview Qs

### Does the LLM execute the function?

No. It returns the tool name and JSON arguments. Your application decides whether to run it, runs it, and sends the result back so the model can continue or answer.

### How do you stop the model refunding someone else's order?

Never let the model supply the user id; pass it from the session (Spring AI `ToolContext`). Check ownership and business rules in the backend, ask for confirmation, and use an idempotency key.
