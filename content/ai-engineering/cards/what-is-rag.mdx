## What it is

RAG stands for retrieval-augmented generation. It is a way to answer a question using your own documents without changing the model. When a question arrives, the app searches your documents for the few passages that are most relevant, puts those passages into the [prompt](card:prompt-design), and asks the [LLM](card:what-is-an-llm) to answer from them. The search reuses [embeddings](card:embeddings) and [similarity search](card:similarity-search): the question and the documents are compared by meaning, not by exact words.

## Why it exists

An LLM knows only what was in its training data. It knows nothing after its [knowledge cutoff](card:llm-limits), and nothing private such as your refund policy or a customer's payment history. Without RAG you would have to retrain or fine-tune the model every time a document changes, which is slow, costly and still mixes your facts into the weights where you cannot see them. RAG removes this: it hands the model the right text at request time, so the answer is grounded in a source you can point to, and updating a document is just replacing a file.

## How it works

<Compare id="rag-vs-plain-llm" />

1. The app turns the user's question into an embedding and searches the document store for the chunks whose meaning is closest.
2. It takes the top few chunks and places them in the prompt, above the question, as the context to answer from.
3. It tells the LLM to answer using only that context and to cite the chunk it used.
4. The LLM writes the answer from the supplied text, so a document edited yesterday is reflected today with no retraining.

So the key is that RAG works on the prompt, not on the model.

## Example

This shows one request to the payments support assistant. It is a trace of the three stages, not code.

```text
Question:  Where is my refund for order 42?
Retrieve:  refund-policy.pdf, chunk 4 (fictional example policy)
           "UPI refunds reach the customer in 5-7 working days."
Augment:   prompt = rules + that chunk + the question
Generate:  "UPI refunds usually arrive in 5-7 working days [refund-policy#4]."
```

What to notice:

- The policy text came from a document search, not from the model's memory, so a model with no knowledge of your refunds can still answer correctly.
- The answer carries `[refund-policy#4]`, a pointer back to the chunk it used, which is possible only because the chunk was in the prompt.
- If the search had returned the wrong chunk (say the card-refund paragraph), the model would confidently give the wrong number. The answer is only as good as retrieval.
- A live value such as whether order 42's refund has started is not in the policy; that needs a [tool call](card:tool-calling), not RAG.

## Rules and defaults

- **No training:** RAG never changes the model weights. It only changes the prompt for one request. Training the model itself is [fine-tuning](card:llm-training-stages).
- **Documents are fetched per request:** the model holds no memory of them between calls, so each answer reflects the documents as they are right now.
- **Grounding is instructed, not guaranteed:** you must tell the model to answer only from the context; it can still ignore the instruction, which is why you also check the output.
- **Good for text knowledge:** policies, FAQs, manuals. For a single current record, use a tool or a database query instead.

## Not to be confused with

Fine-tuning changes the model's weights so it learns a skill or style, and it is slow and offline. RAG leaves the weights alone and adds knowledge through the prompt at request time. Rule: fine-tuning teaches behaviour; RAG supplies knowledge. RAG is also not plain search: search returns a list of documents, while RAG reads those documents and writes an answer from them.

## Interview Qs

### What is RAG and why use it?

Retrieval-augmented generation: before the LLM answers, the app searches a knowledge base for the chunks relevant to the question and adds them to the prompt. It is used so the model can answer from private or recent information it never saw in training, and cite its source, without any retraining.

### Does RAG change the model?

No. The weights stay exactly the same. RAG only changes what goes into the prompt for each request. Teaching the model itself is [fine-tuning](card:llm-training-stages), which is a separate, offline process.

### When would you not use RAG?

When the answer is a single live record, such as an order's current status, call a tool or query the database instead. Also skip RAG when the whole knowledge base is small enough to send in every prompt; see [RAG, fine-tuning or long context](card:rag-or-fine-tuning).
