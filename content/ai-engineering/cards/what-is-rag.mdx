## Why it exists

An LLM knows only its training data: nothing after its [knowledge cutoff](card:llm-limits) and nothing private, such as your refund policy. RAG hands it the right text at request time.

## How it works

<Compare id="rag-vs-plain-llm" />

- Use RAG for documents (refund policy, payment FAQ); use [tool calling](card:tool-calling) for live rows such as order 42's status.
- The stages, offline and online, are in [the RAG pipeline](card:rag-pipeline).

## Example

```text
Question:  Where is my refund for order 42?
Retrieved: refund-policy.pdf, chunk 4 (fictional example policy)
           "UPI refunds reach the customer in 5-7 working days."
Tool:      getOrderStatus(42) -> refund ₹500 to UPI, started 18-10-2026
Prompt:    rules + retrieved chunk + tool result + question
Answer:    "Your ₹500 UPI refund started on 18-10-2026. UPI refunds
            usually arrive in 5-7 working days [refund-policy#4]."
```

## Interview Qs

### What is RAG?

Retrieval-augmented generation: before the LLM answers, the app searches a knowledge base for relevant chunks and adds them to the prompt. The LLM answers from that text, so it can use private, recent information and cite it.

### Does RAG change the model?

No. The weights stay the same. RAG only changes what goes into the prompt for each request. Changing the model itself is [fine-tuning](card:llm-training-stages).

### When would you not use RAG?

When the answer is a live record (call a tool or the database instead), or when the whole knowledge base is small enough to send every time: see [RAG, fine-tuning or long context](card:rag-or-fine-tuning).
