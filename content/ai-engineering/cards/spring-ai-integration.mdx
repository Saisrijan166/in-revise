## Why it exists

The model is a remote, paid service that must not hold secrets or make decisions. One backend layer keeps the key, checks the caller and controls what goes in and out.

## Example

```properties
# starter: spring-ai-starter-model-openai (Spring AI 2.0)
spring.ai.openai.api-key=${OPENAI_API_KEY}
```

```java
@Service
class SupportAssistant {
    private final ChatClient chatClient;

    SupportAssistant(ChatClient.Builder builder) { this.chatClient = builder.build(); }

    String ask(String question) {
        return chatClient.prompt()
                .system("You are the shop.example support assistant. Answer only about orders and payments.")
                .user(question)
                .call().content();
    }
}
```

## Interview Qs

### How do you integrate an LLM into a Spring Boot app?

Add a Spring AI model starter, supply the key from a secret, and inject `ChatClient.Builder` into an AI service that retrieves context, builds the prompt, calls the model and validates.

### Spring AI, a provider SDK, or plain RestClient?

Spring AI: one portable API with advisors, RAG and tools. Provider SDK: newest provider features first. RestClient or WebClient: full HTTP control, but you write parsing and retries.

### Where do you keep the API key?

Server-side only: a key management service or secrets manager, or an environment variable. Never in source code, Git, logs or the browser.
