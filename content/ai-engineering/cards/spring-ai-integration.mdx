## What it is

Integrating an LLM in Spring Boot means putting the model behind your own backend. The browser never talks to the model provider; it calls your Spring Boot API, and only the server calls the model. Between the controller and the model you add an **AI service**: an ordinary Spring bean that owns the prompt, the retrieval and the output checks. It reaches the model through [Spring AI](term:spring-ai)'s `ChatClient`, one interface that works across providers.

## Why it exists

The model is a remote, paid service reached with a secret API key. If the React app called it directly, that key would travel to every browser, and anyone could read it and spend your budget. There would also be no place to check who is asking, cap usage or validate the reply. Putting one backend layer in front keeps the key on the server and gives auth, limits and checks a single home.

1. The browser sends the user's question to a Spring Boot controller, which authenticates the caller and applies rate limits.
2. The controller stays thin and hands the question to the AI service.
3. The AI service retrieves any context it needs (for example pgvector chunks), builds the prompt and calls the model through `ChatClient`.
4. If the model asks to run a tool, the service runs it against the database only after its own check, then sends the result back to the model.
5. The service validates the final reply and returns it to the controller, which responds to the browser.

So the controller guards the door and the AI service does the model work; see [calling LLM APIs](card:calling-llm-apis) for streaming and retries and [tool calling](card:tool-calling) for tools.

## Example

The app key comes from an environment variable, and a `SupportAssistant` bean injects a ready-built `ChatClient`.

```properties
# starter: spring-ai-starter-model-openai (Spring AI 2.0)
spring.ai.openai.api-key=${OPENAI_API_KEY}
```

```java
@Service
class SupportAssistant {
    private final ChatClient chatClient;

    SupportAssistant(ChatClient.Builder builder) { this.chatClient = builder.build(); }

    String ask(String question) {
        return chatClient.prompt()
                .system("You are the shop.example support assistant. Answer only about orders and payments.")
                .user(question)
                .call().content();
    }
}
```

What to notice:

- `${OPENAI_API_KEY}` reads the key from the environment, so the secret never sits in source or Git.
- Spring AI's starter auto-configures a `ChatClient.Builder`, so the service only injects it and calls `build()`.
- `.system(...)` sets the fixed rules, `.user(question)` adds the caller's text, and `.call().content()` returns the reply as a `String`.
- Swap the starter and key for `spring-ai-starter-model-anthropic` and the same code calls a different provider, because `ChatClient` is portable.

## Rules and defaults

- **ChatClient auto-configured:** adding a Spring AI model starter and a key auto-configures a `ChatClient.Builder` bean (Spring AI 2.0).
- **Portability:** `ChatClient` targets a provider-neutral `ChatModel`; switching provider is a starter and key change, not a code change (Spring AI 2.0).
- **Key source:** load the key from a secrets manager or environment variable. Never in code, Git, logs or the browser.
- **Thin controllers:** keep prompts, model calls, tools and validation in the AI service, not in the controller.

## Not to be confused with

Three clients can reach the model. [Spring AI](term:spring-ai)'s `ChatClient` gives one portable API with advisors, RAG and tools built in. A [provider SDK](term:provider-sdk) (the official OpenAI or Anthropic Java library) exposes the newest provider features first. A plain [RestClient](term:restclient) or [WebClient](term:webclient) gives full HTTP control but leaves you to write parsing and retries. Rule: ChatClient by default; a provider SDK or RestClient only when you need something ChatClient does not offer.

## Interview Qs

### How do you integrate an LLM into a Spring Boot app?

Add a Spring AI model starter and supply the key from a secret. Inject `ChatClient.Builder` into an AI service that sits behind a thin controller. The service retrieves context, builds the prompt, calls the model and validates the reply. The controller handles auth and rate limiting. The browser never calls the provider.

### Spring AI, a provider SDK, or plain RestClient?

Spring AI gives one portable API with advisors, RAG and tools, and is the default. A provider SDK gives the newest provider features first, so use it when ChatClient lacks something. RestClient or WebClient gives full HTTP control, but you write the request, parsing and retries yourself.

### Where do you keep the API key?

Server-side only: a secrets manager or key management service, or an environment variable read at startup. Never in source code, in Git, in logs, or in anything sent to the browser, because the key is a paid secret and a leaked key lets anyone spend your budget.
