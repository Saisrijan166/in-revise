## Why it exists

LLM calls are slow, rate-limited and sometimes fail. Without streaming users stare at a spinner; without timeouts and limits, threads pile up and bills spike.

## How it works

<Compare id="streaming-vs-blocking-response" />

- Set a connect timeout and a request timeout; a stuck call otherwise holds a thread and a connection.
- Retry at one layer only, with capped attempts; after repeated failures, a circuit breaker fails fast and a fallback answers.
- Limit each user in front of the AI service; this also caps spend ([unbounded consumption](card:llm-security)).

## Example

Spring AI 2.0 streaming endpoint; it needs Reactor on the classpath, e.g. `spring-boot-starter-webflux`.

```java
@RestController
class AskStreamController {
    private final ChatClient chatClient;

    AskStreamController(ChatClient.Builder builder) { this.chatClient = builder.build(); }

    @GetMapping(value = "/api/ask/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    Flux<String> ask(@RequestParam String q) {
        return chatClient.prompt().user(q).stream().content();   // tokens as they arrive
    }
}
```

## Defaults

| What | Default | Where |
|---|---|---|
| OpenAI request timeout | 60 s | Spring AI 2.0, `spring.ai.openai.timeout` |
| OpenAI SDK retries | 3 | Spring AI 2.0, `spring.ai.openai.max-retries` (not `spring.ai.retry.*`) |

## Interview Qs

### Why stream LLM responses?

Generation is token by token, so long replies take seconds. Streaming shows the first words early; total time does not drop. Errors can arrive mid-stream after a 200, so handle them.

### Which errors do you retry, and how?

Timeouts, network errors, 429 and 5xx: capped exponential backoff with jitter and a max attempts, waiting at least Retry-After. Not 400, 401, 403 or billing and quota 429s: they keep failing.

### How do you stop one user from burning the AI budget?

A rate limiter in front of the AI service: requests per user per minute, tokens per user per day, and an output-token cap per call. Over the limit, return 429.
