## Why it exists

Output can be malformed, wrong or steered by [prompt injection](card:prompt-injection). Used unchecked, it causes XSS, SQL injection or bad refunds (OWASP LLM05, 2025).

## How it works

<Steps label="Checks between the model and any action">
  <Step title="Parse">Map the reply to a typed object; reject if the schema fails ([structured output](card:structured-output)).</Step>
  <Step title="Business rules">Compare with DB facts: order owner, refundable amount, status.</Step>
  <Step title="Safety and permission">Is this user allowed? Is the content safe to show?</Step>
  <Step title="Act or fall back">Act, show an error, retry once, or send to a human.</Step>
</Steps>

- Guardrails screen input before the call and output after it, e.g. a moderation API.

## Example

```java
record Suggestion(long orderId, int refundRupees) {}
record Order(long id, int totalRupees, int refundedRupees) {}
static String check(Suggestion s, Order o) {      // o comes from the DB
    int refundable = o.totalRupees() - o.refundedRupees();
    if (s.orderId() != o.id()) return "REJECT: not this order";
    if (s.refundRupees() <= 0 || s.refundRupees() > refundable)
        return "REJECT: refundable is " + refundable;
    return "OK: queue for approval";
}
// order 42: total 1499, already refunded 500
System.out.println(check(new Suggestion(42, 1000000), new Order(42, 1499, 500)));
System.out.println(check(new Suggestion(42, 999), new Order(42, 1499, 500)));
```

```text output
REJECT: refundable is 999
OK: queue for approval
```

## Interview Qs

### The model says "refund ₹10,00,000". What stops it?

The backend. It checks the amount against the refundable balance in the database and that the user owns the order, then refunds in a transaction. The model only suggests.

### What is improper output handling?

Passing model output to other systems without checks: unescaped HTML (XSS), generated SQL without parameters, file paths or shell commands. Treat the model as an untrusted user and encode output for where it goes.

### When do you add human review?

For high-impact or irreversible actions such as large refunds, and when automatic checks fail. The model drafts; a person approves.
