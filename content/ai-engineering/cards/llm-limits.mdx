## Why it exists

Teams wire an LLM in as if it were a smart database. Knowing its limits decides what the model does and what the backend must still own.

## How it works

<Compare id="llm-vs-database-vs-search-engine" />

| Can do well | Cannot be trusted to |
|---|---|
| Generate, summarise, translate, write code | Guarantee facts |
| Classify and extract fields | Enforce authorisation |
| Reason over the context you supply | Give the same output every time |
| Call [tools](card:tool-calling) you offer | Know private or current data |
| Fill a JSON schema when constrained | Run actions safely on its own |

- For today's order status, use [tools](card:tool-calling) or [RAG](card:what-is-rag); wiring: [AI and databases](card:ai-and-databases).
- History between calls: [conversation memory](card:conversation-memory).

## Interview Qs

### What is a knowledge cutoff, and how do you work around it?

The date the training data ends. The model knows nothing after it, nor your private data. Fetch current facts at request time with tools or RAG.

### Can the LLM decide whether a refund is allowed?

No. The rule and the check live in backend code against the database. The model may explain the decision, but the backend makes it and enforces it.

### Why does temperature 0 still give different answers sometimes?

Generation is not guaranteed to be deterministic; Anthropic's docs say results vary even at temperature 0.
