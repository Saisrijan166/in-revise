## Why it exists

A new model starts with untrained weights and predicts badly. Training finds good weights from examples; after that, the model is used as is to answer new inputs.

## How it works

<Steps label="The training loop">
  <Step title="Predict">The model makes a guess for each example in a batch.</Step>
  <Step title="Measure the loss">A loss function scores how wrong the guesses are.</Step>
  <Step title="Nudge the weights">Gradient descent moves each weight a small step that lowers the loss.</Step>
  <Step title="Repeat">Run over the training set for several epochs, until the loss stops falling.</Step>
</Steps>

- Tune against the validation set; use the test set once, at the end, on unseen data.
- Training loss falls while validation loss rises: overfitting. Underfitting: poor even on training data.
- An app sends history to fake memory: see [conversation memory](card:conversation-memory).

## Interview Qs

### What is the difference between training and inference?

Training learns the weights from data: many passes, heavy compute, done by the model maker. Inference uses the fixed weights to predict or generate for one input. Calling an LLM API is inference.

### What is overfitting and how do you spot it?

The model fits its training data so closely that it fails on new data. Spot it when validation loss rises while training loss keeps falling. Fix it with more varied data or regularisation.

### Why keep both a validation set and a test set?

You tune the model against the validation set many times, so it slowly fits that set too. The untouched test set gives an honest final check on unseen data.
