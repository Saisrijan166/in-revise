## What it is

A model's behaviour lives in its parameters: the weights and biases, a long list of numbers. Training is the process that finds good values for those numbers from example data. Inference is the opposite phase: the numbers are now fixed, and the model just runs an input through them to produce an answer. When you call an LLM API, you are doing inference on a model someone else already trained.

## Why it exists

A fresh model starts with random weights and predicts nonsense. You cannot write the right weights by hand; there are billions of them. Training exists to find those values automatically from examples, by repeatedly measuring how wrong the model is and adjusting. Once trained, you do not want to keep changing the weights on every request, because that would be slow and unpredictable, so inference keeps them frozen.

## How it works

<Steps label="The training loop">
  <Step title="Predict">The model makes a guess for each example in a batch of training data.</Step>
  <Step title="Measure the loss">A loss function turns how wrong those guesses are into one number.</Step>
  <Step title="Nudge the weights">Gradient descent moves each weight a small step in the direction that lowers the loss.</Step>
  <Step title="Repeat">Pass over the whole training set again and again (epochs) until the loss stops falling.</Step>
</Steps>

1. The data is split: most for training, a validation set to tune against, and a held-out test set used once at the end on unseen data.
2. If training loss keeps falling while validation loss rises, the model is overfitting (memorising the training set); if it does poorly even on training data, it is underfitting.
3. When training ends, the weights are frozen and the model moves to inference.

So training is the loop that sets the numbers; inference is a single pass through numbers that no longer change.

- A chatbot feels like it remembers because the app stores earlier turns and sends them again each call; you will see this built deliberately in [conversation memory](card:conversation-memory).
- As a backend developer you almost always do inference (API calls); you only train when you fine-tune a model.

## Interview Qs

### What is the difference between training and inference?

Training learns the weights from data: many passes over a large dataset, heavy compute, done once per model version. Inference uses the fixed weights to predict or generate for one input, on every request. Calling an LLM API is inference.

### What is overfitting and how do you spot it?

The model fits its training data so closely that it does worse on new data. You spot it when validation loss rises while training loss keeps falling: the gap means it is memorising, not generalising. Fix it with more varied data, early stopping or regularisation.

### Why keep both a validation set and a test set?

You tune the model against the validation set many times, so the model slowly ends up fitting that set too. The test set is touched only once, at the very end, so it gives an honest measure of how the model does on data it has never seen.
