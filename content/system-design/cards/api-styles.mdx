## Why it exists

Every client and service must agree on how to ask for data and actions. Each style trades something: REST is simple and cacheable, gRPC is fast and strictly typed, GraphQL is flexible for many different clients.

## How it works

<Compare id="rest-vs-grpc-vs-graphql" />

- **REST** comes from Roy Fielding's 2000 dissertation: stateless requests, cacheable responses, one uniform interface. The status code tells the result: 2xx success, 4xx client error, 5xx server error.
- **gRPC** generates client and server code from a `.proto` contract, so a remote call looks like a local one.
- **GraphQL** checks every query against a typed schema. Long lists come back in pages; cursors stay stable when new rows arrive.

## Example

One screen needs a user's name and their order totals.

**REST:** two round trips, and each returns the whole object.

```text
GET /users/42
GET /users/42/orders
```

**GraphQL:** one request to one URL; only the asked-for fields come back.

```text
POST /graphql
{ "query": "{ user(id: 42) { name orders { total } } }" }
```

**gRPC:** typed methods from the shared `.proto` contract; `stream` means many replies.

```proto
service UserService {
  rpc GetUser (UserId) returns (User);
  rpc WatchOrders (UserId) returns (stream Order);
}
```

## Interview Qs

### REST, gRPC or GraphQL: how do you choose?

REST for public APIs and simple CRUD: every client speaks HTTP, and GETs can be cached. gRPC for internal calls that need speed, strict contracts or streaming. GraphQL when web and mobile clients need different fields from the same data.

### What makes an API RESTful?

Resources with their own URLs, a uniform interface (standard methods and status codes), stateless requests that carry everything needed, and responses marked cacheable or not. These constraints come from Roy Fielding's 2000 dissertation.

### Why can't a browser call gRPC directly?

Browsers give no API with enough control over HTTP/2 requests, and gRPC needs it. Use gRPC-Web through a proxy such as Envoy. Today it supports unary and server-streaming calls only.

### What is the N+1 problem in GraphQL?

Asking for 10 users and their orders can run 1 query for the users, then 1 per user: 11 calls. Batch them: DataLoader collects the keys and loads them in one call.
