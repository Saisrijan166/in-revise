## Why it exists

With many services, clients would need every address, and every service would repeat auth, TLS and rate limiting. A gateway gives clients one endpoint and does those shared jobs once.

## How it works

<Mermaid
  alt="A mobile or web client calls the API gateway, which checks auth, applies rate limits and logs the call. It routes /users to the users service and /orders to the orders service. For /home it calls an aggregator service, which calls both services and returns one combined reply."

  C([Mobile or web client]) --> G["API gateway: auth, rate limit, logs"]

  G -- "/orders" --> O[Orders service]
  G -- "/home" --> A[Aggregator]
  A --> U
  A --> O`}

- Azure names three gateway patterns: **routing** (one endpoint, layer 7 rules), **offloading** (shared jobs) and **aggregation** (one call, many services).
- Azure suggests a separate aggregator service behind the gateway, so heavy fan-out does not slow routing.

## Example

A mobile home screen needs profile, orders and offers.

- **No gateway:** the phone makes 3 calls over a slow mobile network, and each one can fail.
- **With aggregation:** the phone makes 1 call. The gateway calls the 3 services over the fast internal network and returns one reply.

| Over the limit | `429 Too Many Requests` | AWS API Gateway |
| Backend (integration) timeout | 50 ms to 29 s; Regional and private APIs can ask for more | AWS API Gateway REST APIs |
| Largest payload | 10 MB | AWS API Gateway REST APIs |

## Interview Qs

### API gateway vs load balancer?

A load balancer spreads traffic across copies of one service. A gateway manages APIs: it routes to different services and adds auth, rate limits and logging. They often work together, with a load balancer in front of several gateway instances.

### What are the downsides of an API gateway?

An extra hop on every request, a possible bottleneck and single point of failure, and one more thing to run. Run several instances, load-test it, and keep business logic out, or it becomes a shared monolith every team must change.

### What is the Backend for Frontend (BFF) pattern?

A separate backend layer for each client type, such as mobile and web, shaped to that client's needs. It suits clients with very different needs; the cost is more services and some duplicated code.

### Where should authentication happen: gateway or service?

Validate the token once at the gateway. Each service still decides what that caller may do, using a trusted identity, never an unverified header. Make services reachable only through the gateway, so nobody can bypass its checks.
