## Why it exists

People search text by words, in any form and order, and want the best matches first. Scanning every row with `LIKE '%word%'` is slow and cannot rank.

## How it works

- The query goes through the same analysis, so "Shoes" matches "shoes".
- Elasticsearch splits each index into shards, so search scales out across nodes.
- The database stays the source of truth. Changes reach the index a little later, often through change data capture, so search is near real-time.

## Example

PostgreSQL 18 full-text search, with no extra system:

```sql
-- A stored tsvector column, plus a GIN (inverted) index on it
ALTER TABLE products ADD COLUMN search tsvector
  GENERATED ALWAYS AS (to_tsvector('english', coalesce(name, ''))) STORED;
CREATE INDEX products_search_idx ON products USING GIN (search);

-- The 'english' config stems words, so "Running Shoes" matches
SELECT id, name, ts_rank(search, q) AS rank
FROM products, to_tsquery('english', 'run & shoe') AS q
WHERE search @@ q
ORDER BY rank DESC LIMIT 10;
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Relevance score | BM25, with k1 = 1.2 and b = 0.75 | Elasticsearch 9.x |
| Text analyzer | `standard`: split on word boundaries, lowercase, keep stop words | Elasticsearch 9.x |
| New documents searchable | After a refresh, every 1 s, for indices searched in the last 30 s | Elasticsearch 9.x |
| Index for full-text search | GIN preferred; GiST also works | PostgreSQL 18 |

## Interview Qs

### What is an inverted index?

A map from each term to the documents that contain it: the reverse of a document listing its words. A search looks up each query term and combines the lists, so it never scans every document.

### Why not LIKE '%term%'?

A B-tree serves only patterns anchored at the start, like `LIKE 'term%'`. A leading wildcard reads every row, and LIKE has no stemming or ranking. If you only need substring matching, PostgreSQL's pg_trgm extension can index `LIKE '%term%'`.

### How do you keep Elasticsearch in sync with the database?

Keep the database as the source of truth. Capture its changes with CDC, for example Debezium reading the WAL or binlog into Kafka, and index them asynchronously. Expect a short lag, and rebuild the index from the database if it drifts.

### How are results ranked?

By a relevance score. Elasticsearch uses BM25 by default: a term counts more when it is rare across documents and frequent in this one, repeats give diminishing returns, and matches in shorter fields count more.
