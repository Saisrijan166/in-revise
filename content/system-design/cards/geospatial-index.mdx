## Why it exists

"Find drivers within 3 km" needs closeness in two dimensions. A normal index sorts one value, so an index on `(lat, lng)` narrows by latitude only and still scans a strip around the globe.

## How it works

<Steps label="Nearby search with a geohash">
<Step title="Encode">
Store each place's geohash. Central Bengaluru is `tdr1v9q`; its first 6 characters name a cell of about 1.2 km by 0.6 km.
</Step>
<Step title="Add the neighbours">
Take the user's cell and the 8 cells around it, so places just across an edge are not missed.
</Step>
<Step title="Range-scan the index">
Fetch places whose geohash starts with one of those 9 prefixes, from a B-tree or a Redis sorted set.
</Step>
<Step title="Filter exactly">
Compute the real distance for each candidate, drop those outside the radius, and sort.
</Step>
</Steps>

<Compare id="geohash-vs-quadtree" />

- **Shapes** such as delivery zones need an R-tree of bounding boxes. PostGIS builds it on GiST: `USING GIST (geom)`.
- **Uber's H3** uses hexagons: a cell's centre is the same distance from all six neighbours.

## Example

Redis GEO (`GEOSEARCH` needs Redis 6.2+). Longitude comes first:

```text
GEOADD drivers 77.5946 12.9716 driver:17
GEOADD drivers 77.6100 12.9800 driver:8
GEOADD drivers 77.6245 12.9352 driver:42
GEOSEARCH drivers FROMLONLAT 77.6000 12.9700 BYRADIUS 3 km ASC
1) "driver:17"     # about 0.6 km away
2) "driver:8"      # about 1.6 km away; driver:42 (4.7 km) is outside
```

| What | Default or limit | Where |

| Index for `point` with SP-GiST | `quad_point_ops`, a quadtree | PostgreSQL 18 |

## Interview Qs

### Why can't a normal index find nearby places?

A B-tree sorts by one value. With an index on `(lat, lng)`, the latitude range limits the scan, but longitude is only checked inside it, so you read a strip around the globe. A geospatial index keeps nearby points close together.

### Geohash or quadtree?

Geohash: a fixed grid stored as plain keys in any database or Redis, with cheap updates for moving points. Quadtree: adapts to density by splitting busy areas finer, but is usually kept in memory and changes shape as points move.

### How do you find nearby drivers when locations change every few seconds?

Keep current locations in memory, for example Redis GEO: each update is one `GEOADD` that overwrites the old position, and `GEOSEARCH` returns drivers within a radius, nearest first.
