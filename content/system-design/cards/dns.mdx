## Why it exists

Computers connect by IP address, but people remember names. DNS maps names to addresses, and lets you change the address behind a name without telling any user.

## How it works

<Steps label="Looking up www.example.com">
<Step title="Ask the resolver">
The browser and OS check their own caches. On a miss, they ask a recursive resolver, usually run by the ISP or company network.
</Step>
<Step title="Root, then TLD">
The resolver asks a root server, which points to the .com servers. Those point to example.com's authoritative servers.
</Step>
<Step title="Get the record">
The authoritative server returns the record, for example A 192.0.2.10 with a TTL of 300 seconds.
</Step>
<Step title="Cache and connect">
The resolver caches the answer for the TTL, and the browser connects to the IP.
</Step>
</Steps>

- A cached answer at any step skips the rest of the walk.
- DNS can return different answers per user: by weight, location, latency or health.

## Example

A small zone. Each line is name, TTL in seconds, type, value.

```text
example.com.      3600  NS     ns1.example.net.
example.com.      300   A      192.0.2.10
example.com.      300   AAAA   2001:db8::10
www.example.com.  300   CNAME  example.com.
example.com.      3600  MX     10 mail.example.com.
```

Route 53 calls 60 or 120 seconds a common TTL for records you may fail over, and an hour to a day for NS and MX records that rarely change.

## Interview Qs

### What happens when you type a URL into the browser?

The browser resolves the name: its cache, the OS cache, then a recursive resolver that walks root, TLD and authoritative servers. With the IP, it opens a TCP connection, does the TLS handshake for HTTPS, and sends the HTTP request.

### What is a DNS TTL, and how do you pick it?

How long resolvers may cache a record, in seconds. Short TTLs mean changes spread fast but cause more queries; long TTLs are faster and cheaper but slow to change. Lower the TTL before a planned change.

### Can DNS do load balancing?

Yes, roughly: return several IPs, or use weighted, geo or latency routing with health checks. But caches delay changes and DNS cannot see each request, so put a real load balancer behind each answer.

### A record vs CNAME?

An A record maps a name to an IPv4 address (AAAA for IPv6). A CNAME maps a name to another name. A CNAME cannot sit at the zone apex or next to other records; Route 53 alias records work at the apex.
