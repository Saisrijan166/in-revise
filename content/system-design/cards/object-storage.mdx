## What it is

Object storage is a service that keeps files, called objects, in containers called buckets. Each object is one file plus its metadata (size, type, owner), and you reach it over HTTP by its bucket and key, like a path. Amazon S3 is the best-known example. Unlike a database row, you do not edit an object in place: you write the whole file or replace it. It is where large files belong, while the database keeps only the small record that points to them.

## Why it exists

Photos, videos and backups are too big to sit in database rows and too many to fit on one server's disk. If you push them through your API servers into a database, you bloat the database and its backups, and every byte flows through your own machines and memory. Object storage removes that: it holds any number of files durably behind a simple HTTP API, so your servers only handle the small metadata and the file traffic goes elsewhere.

## How it works

1. The client asks the app server for permission to upload a file.
2. The app checks the user and returns a presigned URL: a link that allows one upload to one key for a few minutes.
3. The client uploads the file straight to the bucket using that URL, so the bytes never pass through the app server. A big file is split into parts (multipart upload).
4. The client tells the app it finished; the app saves the key and metadata in the database and marks the file ready.

So the server signs and records, while the bucket does the heavy lifting and a [CDN](card:cdn) serves downloads close to users.

## Example

The app gives the client a URL that can PUT one file for ten minutes.

```java
String uploadUrl(S3Presigner presigner, String key) {
    PutObjectRequest put = PutObjectRequest.builder()
            .bucket("media").key(key).contentType("image/jpeg").build();
    PutObjectPresignRequest req = PutObjectPresignRequest.builder()
            .signatureDuration(Duration.ofMinutes(10))
            .putObjectRequest(put).build();
    return presigner.presignPutObject(req).url().toString();
}
```

```python
def upload_url(s3, key):  # s3 = boto3.client("s3")
    return s3.generate_presigned_url(
        "put_object",
        Params={"Bucket": "media", "Key": key, "ContentType": "image/jpeg"},
        ExpiresIn=600,  # seconds
    )
```

What to notice:

- The URL is signed for one bucket, one key and one operation (PUT), so it cannot be reused to upload anything else.
- The lifetime is short on purpose; after it expires the link is dead, which limits what a leaked URL can do.
- The client must send the same `Content-Type` it was signed with, `image/jpeg` here; a different one fails the signature check.
- The file bytes go client-to-bucket, never through the app server, which is the whole point of the pattern.

## Rules and defaults

| What | Default or limit | Where |
| --- | --- | --- |
| New bucket access | Private, with Block Public Access on | Amazon S3 |
| Storage class on upload | S3 Standard | Amazon S3 |
| One PUT (single upload) | Up to 5 GB | Amazon S3 |
| Multipart parts | 5 MiB to 5 GiB each, up to 10,000 parts | Amazon S3 |
| Largest object | 48.8 TiB (10,000 parts of 5 GiB) | Amazon S3 |
| Presigned URL lifetime | Up to 7 days (SDK, CLI); 12 hours (console) | Amazon S3, Signature V4 |

- **No shared transaction:** the bucket and the database are separate systems, so a step can fail between them. Clean up orphaned objects, and use a lifecycle rule to delete uploads that never finished.

## Not to be confused with

Block, file and object storage are different. Block storage is a raw disk volume a single server mounts, like Amazon EBS, used by databases and virtual machines. File storage is a shared folder many machines mount at once, like Amazon EFS. Object storage is whole files by key over HTTP, like S3. Rule: block for one machine's disk, file for a shared mount, object for lots of large unstructured files.

## Interview Qs

### Why not store images in the database?

Large files bloat the database, its backups and its memory, and every byte flows through your servers. Object storage holds any number of objects, is built for very high durability, and pairs with a CDN. Keep only the key and metadata (owner, size, status) in the database.

### How does a user upload a 2 GB video?

The app hands out a presigned URL, and the client uploads straight to the bucket with multipart upload: parts in parallel, resending only failed parts. Then the app marks the file ready, from the client's call or a bucket event. A lifecycle rule removes uploads that never completed.

### Is S3 eventually consistent?

Not since December 2020. After a successful PUT or DELETE, every later read and list sees the change (strong read-after-write). Two writes to the same key at the same time still end with the latest one winning, and there is no atomic update spanning several keys.
