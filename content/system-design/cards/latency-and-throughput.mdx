## Why it exists

A system can be fast for one user but slow under many, or handle huge volume while each user waits. You need both numbers to judge a design.

## How it works

| What | Latency | Throughput |
| --- | --- | --- |
| Question | How long does one request take? | How many requests finish per second? |
| Unit | ms, as p50, p95, p99 | requests/s or MB/s |
| Improve it | Do less, in parallel, closer to the user (cache, CDN) | Add servers; remove the bottleneck |
| Watch out | The slow tail, made worse by fan-out | Near full load, queues grow and latency rises |

- **Percentiles:** p50 is the typical request; p99 is the time within which 99% finish. Google's SRE book prefers them because the mean hides the slow tail.
- **Little's law** links the two: at 2,000 requests/s and 50 ms each, about 100 requests are in flight at once.

## Analogy

<Analogy title="A highway" limit="Cars do not time out, retry or split into 100 parallel trips; requests do.">
Latency is how long one car takes to cross. Throughput is how many cars cross per hour. A new lane carries more cars per hour, but no car drives faster. At rush hour, cars queue at the merge, so every trip gets longer.
</Analogy>

## Example

One server replies in 10 ms, but 1 reply in 100 takes 1 s.

- **Average:** (99 × 10 + 1 × 1,000) ÷ 100 ≈ 20 ms. No request actually took 20 ms.
- **One call:** 1 user in 100 waits a full second.
- **Fan-out to 100 such servers:** the page is fast only if all 100 replies are fast: 0.99^100 ≈ 0.37. So about 63% of pages take over 1 s (Dean and Barroso, 2013).

## Interview Qs

### Latency vs throughput?

Latency is how long one request takes; throughput is how many requests finish per unit of time. They are linked: as load nears capacity, queues build and latency rises. Aim for the most throughput you can get at an acceptable latency.

### Why use p99 instead of the average?

The average mixes many fast requests with a few very slow ones, so it can describe no real request. p99 shows the time within which 99% of requests finish, so you see what the slowest 1% feel. Set latency SLOs on percentiles.

### Every server is fast. Why is the page slow?

The page fans out to many servers and waits for the slowest. If each is slow 1% of the time, a page that calls 100 of them is slow about 63% of the time. Use timeouts, hedged requests, or fewer calls per page.

### Which latency numbers should you know?

Orders of magnitude from Jeff Dean's 2009 list: memory read 100 ns, round trip inside a datacentre 0.5 ms, spinning-disk seek 10 ms, California to the Netherlands and back 150 ms. Hardware has improved since, so remember the order, not the exact values.
