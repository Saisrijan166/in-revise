## Why it exists

If every server faces the internet, each one must handle TLS, compression and attacks, and clients must know every address. A reverse proxy does these jobs once, in front of the servers.

## How it works

<Mermaid
  alt="A client sends an HTTPS request to the reverse proxy. The proxy ends TLS, serves cached replies and static files itself, and forwards other requests to app servers on the private network. Clients never see the app servers."
  chart={`flowchart LR
  C([Client]) -- HTTPS --> P["Reverse proxy: TLS, cache, gzip"]
  P -- "/static" --> F[Static files]
  P -- "everything else" --> A[App servers, private]`}
/>

- It reads HTTP, so it can route by path: `/static` from disk, the rest to the app servers.
- nginx and HAProxy are reverse proxies that can also load-balance across several app servers.

## Example

nginx as a reverse proxy:

```nginx
server {
    listen 443 ssl;                              # TLS ends here
    ssl_certificate     /etc/nginx/site.crt;
    ssl_certificate_key /etc/nginx/site.key;
    gzip on;                                     # off by default
    gzip_types text/css application/javascript;  # text/html is always included
    location /static/ { root /var/www; }         # nginx serves these itself
    location / {
        proxy_pass http://app:8080;              # plain inside; https:// re-encrypts
        proxy_set_header Host $host;             # default is the upstream name
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Compression | Off (`gzip off`); when on, only `text/html` unless you add types | nginx 1.30 |
| Response cache | Off (`proxy_cache off`) | nginx 1.30 |
| Upstream response | Buffered (`proxy_buffering on`) | nginx 1.30 |
| Upstream timeouts | 60 s each for connect, send and read | nginx 1.30 |
| `Host` header sent upstream | The upstream's name (`$proxy_host`), not the client's | nginx 1.30 |

## Interview Qs

### Reverse proxy vs load balancer?

A load balancer spreads requests across many servers doing the same job. A reverse proxy is one front door that adds TLS, caching, compression and security, and is useful even with one server. Tools like nginx and HAProxy do both.

### Forward proxy vs reverse proxy?

A forward proxy sits in front of clients and sends their requests out to the internet. A reverse proxy sits in front of servers and takes requests from the internet for them. One hides the clients, the other hides the servers.

### What is TLS termination?

The proxy holds the certificate and decrypts HTTPS, so app servers skip that work and certificates live in one place. Traffic inside is plain unless the proxy re-encrypts it; Azure advises re-encrypting and trusting no network.

### Behind a proxy, how does the app see the client's real IP?

The proxy adds it to the `X-Forwarded-For` header; AWS ALB does this automatically, nginx with `proxy_set_header`. Trust that header only when it comes from your own proxy, since clients can fake it.
