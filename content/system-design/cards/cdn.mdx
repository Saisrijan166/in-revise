## What it is

A CDN (Content Delivery Network) is a large set of cache servers, spread around the world, that keep copies of your files close to users. Each of those cache servers sits at an edge location, near a group of users. The place where the real, original file lives, your own server or a storage bucket, is called the origin. When a user asks for a file, the CDN serves it from the nearest edge instead of from your origin.

## Why it exists

Every request to a far-away origin pays for the full round trip, and every request also adds load to that origin. A user in Chennai fetching a file from a server in Virginia waits for data to cross the planet, and your origin handles the load of all users everywhere. A CDN fixes both: the file is served from an edge near the user, so the round trip is short, and the origin only sees the first miss per edge, so its load drops sharply.

## How it works

DNS sends the user to a nearby edge, and the edge either already has the file or fetches it once.

1. DNS resolves your CDN name to the edge nearest the user.
2. The edge checks whether it already has the file. A hit is returned straight away.
3. On a miss, the edge fetches the file once from the origin, stores it for the time the origin's `Cache-Control` header allows, and returns it.
4. The next nearby user gets a hit, so the origin is never asked again until the cache time runs out.

## Example

These are the two cache headers the origin sends for a versioned asset and for the HTML, following the pattern MDN recommends.

```text
# app.3f9c2b.js: the file name changes whenever its content changes
Cache-Control: public, max-age=31536000, immutable

# index.html: store it, but recheck with the origin before each use
Cache-Control: no-cache
```

What to notice:

- The JavaScript file carries a one-year `max-age` because its name is content-hashed; a new build produces a new name, so the long cache time is safe.
- On deploy you upload `app.4a1d7e.js` and point `index.html` at it. Nobody requests the old name any more, so no purge is needed.
- `index.html` uses `no-cache`, so the edge always revalidates it with the origin, which is how users pick up the new asset name quickly.

## Rules and defaults

| What | Default | Where |
| --- | --- | --- |
| Cache time when the origin sends no `max-age` | 24 hours (86,400 s) | CloudFront default TTL |
| Longest cache time | 1 year (31,536,000 s) | CloudFront maximum TTL |
| Free invalidation paths | 1,000 a month, then paid per path (`/images/*` counts as one) | CloudFront |
| HTML and JSON | Not cached unless you add a rule | Cloudflare |

- **Changing a file early:** purge (invalidate) it, or better, publish it under a new name so every cache treats it as new.
- **Not everything is cacheable:** personalised or authorised responses must not be shared from one cached copy; mark them `no-store`.

## Not to be confused with

A CDN is a cache *near users*, which is different from an application [cache](card:caching-layers) near your backend. The application cache (for example Redis) saves a database query or computed result close to your services; a CDN saves finished files close to the user's city. You often use both: the CDN cuts network distance, the application cache cuts repeated work.

## Common mistakes

- **"A CDN caches every response automatically."** It only caches what the cache rules and headers allow. API responses, authorised content and personalised pages are not cached unless you explicitly make them cacheable.
- **"Purging is how you update files."** Purging works but is slow and metered, and it does not touch browser caches. Versioned file names update everywhere instantly, so keep purging for emergencies.

## Interview Qs

### How does a CDN work?

DNS sends the user to a nearby edge. On a hit the edge returns the file at once. On a miss it fetches the file from the origin, returns it, and caches it for its cache time, so the next nearby user gets a hit. The origin's load drops because it only serves misses.

### How do you update a file that the CDN has cached?

Prefer versioned file names: a new name is a new cache entry everywhere, including browsers, so the change is instant. A purge clears the CDN only, not browser caches, and CloudFront charges per path after 1,000 a month, so keep purging for emergencies.

### Many edges miss the same file at once. How do you protect the origin?

Add a mid-tier cache such as CloudFront Origin Shield. Edges ask it first, and it collapses identical misses into as few as one request to the origin, so a sudden surge of misses does not hammer your backend.
