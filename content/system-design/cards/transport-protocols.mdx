## Why it exists

Networks can lose, delay or reorder packets. Some data must arrive whole and in order, like a payment; some is useless if it comes late, like a video frame. TCP and UDP serve these two needs.

## How it works

<Compare id="tcp-vs-udp" />

- **TCP** numbers every byte, waits for acknowledgements and resends what is lost. Data behind a lost packet must wait: head-of-line blocking.
- **UDP** adds little more than ports and a checksum to IP. Apps that need some reliability build it themselves.
- **QUIC** does exactly that: reliable, encrypted streams over UDP. HTTP/3 runs on QUIC.

## Analogy

<Analogy title="A phone call vs postcards" limit="A call holds a line open just for you; TCP shares the network with everyone else. And apps can add their own checks on top of UDP.">
TCP is a phone call: you connect first, and if a word is lost you say "pardon?" and hear it again. UDP is a stack of postcards: each one travels alone, some get lost, and they may arrive in any order.
</Analogy>

## Example

Setup cost of a new connection when one round trip takes 100 ms:

| Setup | Round trips before the first request | Wait |
| --- | --- | --- |
| TCP + TLS 1.3 | 2: TCP handshake, then TLS | about 200 ms |
| QUIC (HTTP/3) | 1: both handshakes in one | about 100 ms |
| QUIC, repeat visit (0-RTT) | 0: the request rides in the first flight | about 0 ms |
| UDP, such as a DNS lookup | 0: the first datagram is the question | about 0 ms |

## Interview Qs

### TCP or UDP: when do you use each?

TCP when every byte must arrive in order: web APIs, payments, file transfers, database connections. UDP when fresh data matters more than complete data: live voice and video, online games, most DNS lookups. In a design interview, TCP is the default unless you say why not.

### Why do video calls and games prefer UDP?

With TCP, one lost packet holds up all newer data until it is resent. For live media an old frame is useless, so it is better to skip it and play the next one. UDP lets the app make that choice.

### What is QUIC, and why does HTTP/3 use it?

QUIC is a transport on top of UDP with reliable, encrypted streams. It merges the connection and TLS handshakes, so setup takes one round trip, and a lost packet stalls only its own stream. HTTP/3 is HTTP over QUIC.

### Does DNS use TCP or UDP?

Both. Most lookups use UDP: one small question, one small answer, no setup. If the answer is too big and comes back truncated, the client asks again over TCP. Full zone transfers (AXFR) between DNS servers always use TCP.
