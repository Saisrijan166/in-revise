## What it is

`chmod` ("change mode") is the command that sets a file's [permission bits](card:file-permissions), the read, write and execute flags for owner, group and others. It does not change who owns the file, only what each class is allowed to do. You give the new permissions either as octal numbers or as symbolic letters.

## Why it exists

When you create a file, make a script, or copy data onto a server, the default permissions are often wrong: a script is not runnable, or a secret is readable by everyone. You need a quick way to set exactly who can read, write and run it. `chmod` is that tool, and its two notations suit two needs: numbers to set everything at once, letters to flip one bit.

## How it works

Numeric mode uses one octal digit per class, where read is 4, write is 2 and execute is 1, added together:

<Compare id="chmod-vs-chown" />

1. **Numeric:** write three digits, owner then group then others. `chmod 755 run.sh` gives `rwxr-xr-x` (7 = 4+2+1, 5 = 4+1).
2. **Symbolic:** name a class (`u`, `g`, `o`, or `a` for all), an operator (`+` add, `-` remove, `=` set exactly), and the letters. `chmod g-w file` removes write from the group.
3. `=` replaces the class's bits; `+` and `-` only touch the bits you name and leave the rest alone.

## Example

```bash
chmod 640 app.conf
chmod u+x deploy.sh
ls -l app.conf deploy.sh
```

```text output
-rw-r----- 1 srijan dev   88 Nov  2 10:10 app.conf
-rwxr--r-- 1 srijan dev  512 Nov  2 10:10 deploy.sh
```

What to notice:

- `640` set `app.conf` to `rw-r-----`: owner read/write, group read, others nothing. One number set all three classes.
- `u+x` added just the owner's execute bit to `deploy.sh`; the group and others bits were left untouched.

## Rules and defaults

| Mode | Result | Typical use |
|---|---|---|
| `755` | `rwxr-xr-x` | scripts and directories everyone may run or enter |
| `644` | `rw-r--r--` | data files everyone may read |
| `600` | `rw-------` | private keys, secrets, owner only |
| `400` | `r--------` | read-only secret, even the owner cannot write |

- **A leading 4th digit** sets special bits: setuid, setgid or the sticky bit (see [special permissions](card:special-permissions)).
- **`-R`** applies the mode to a whole tree; use `X` (capital) to add execute only to directories and already-executable files.
- **You must own the file** (or be root) to change its mode.

## Common mistakes

- **Running `chmod 777`.** It gives everyone full access, including write and execute. It is almost never the right fix and is a common security hole.
- **Giving fewer than three digits.** `chmod 7 file` means `007`, rights for others only, not for everyone. Always write all three.
- **Using `chmod` to change the owner.** That is [chown](card:ownership); `chmod` only changes what each class may do.

## Interview Qs

### What does chmod 755 mean?

Owner gets read, write and execute (7 = 4+2+1); group and others get read and execute (5 = 4+1), so `rwxr-xr-x`. It is the usual mode for scripts and directories that everyone may run or enter but only the owner may change.

### What is the difference between numeric and symbolic chmod?

Numeric (`chmod 644`) sets all three classes at once using octal digits where r=4, w=2, x=1. Symbolic (`chmod u+x`) names a class and adds, removes or sets specific bits, leaving the others unchanged. Numeric is absolute; symbolic is relative.

### How do you make a file readable and writable only by its owner?

`chmod 600 file`: owner rw- (6), group and others get 0 (no access). For a read-only owner-only file, use `chmod 400`.
