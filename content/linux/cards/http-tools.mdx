## What it is

`curl` and `wget` both fetch things over HTTP from the command line, but with different jobs. `curl` sends one request and prints the response, so you use it to call and test an API. `wget` is a downloader: it saves files, and can follow links to fetch many files or a whole site. Both are the standard way to talk to a web service from a shell or a script, with no browser.

## Why it exists

On a server there is no browser, yet you still need to check an API, download a build, or confirm a service answers. Writing a small program each time is slow. `curl` and `wget` give you that in one line: `curl` to send a request and read exactly what came back (status, headers, body), `wget` to pull files down reliably, even resuming or mirroring.

## How it works

| Task | curl | wget |
|---|---|---|
| Show the response | prints it to the screen | saves it to a file |
| Headers only | `curl -I` | `wget --server-response --spider` |
| Set the method | `curl -X POST` | mainly GET |
| Send a body | `curl -d 'data'` | limited |
| Save to a file | `curl -o name` / `-O` | `wget -O name` (default: remote name) |
| Download many / mirror | not its job | `wget -r` |

1. Pick the tool by intent: `curl` to inspect a response, `wget` to download files.
2. Add flags for the method, body, headers or output file.
3. Read the result: `curl` shows it; `wget` writes it and logs progress.

## Example

```bash
curl -I https://example.com
```

```text output
HTTP/2 200
content-type: text/html; charset=UTF-8
content-length: 1256
```

What to notice: `-I` sends an HTTP HEAD, so the server returns only the status line and headers, not the page body. The `200` confirms the service is up and the `content-type` shows what it would serve. This is the fastest way to check an endpoint is alive.

## Rules and defaults

- **curl prints to the screen** by default; add `-o file` (chosen name) or `-O` (remote name) to save.
- **wget saves to a file** by default, under the remote filename; `-O file` picks the name.
- **Headers:** use `curl -I` (or `--head`) for a HEAD request, not `-X HEAD`.
- **Recursive download:** only `wget -r` follows links to fetch a tree of files; curl fetches the URLs you give it.

## Not to be confused with

`curl` is for making and inspecting a request, so it suits API testing and scripting. `wget` is for downloading, so it suits grabbing a file or mirroring a site. Rule: if you want to see the response, reach for curl; if you want to keep the file, reach for wget.

## Common mistakes

- **Using `-X HEAD` for headers.** Use `curl -I`. `-X` only changes the method word and can make curl wait for a body that never comes.
- **Forgetting curl does not save by default.** Without `-o` or `-O`, a binary download is dumped to the terminal. Always name an output file for files.

## Interview Qs

### What is the difference between curl and wget?

`curl` sends a request and prints the response, so it is used to call and test APIs, with full control over method, headers and body. `wget` is a downloader that saves files and can mirror a site recursively with `-r`. curl shows; wget saves.

### How do you test an API endpoint from the command line?

With `curl`. For example `curl -i -X POST -H 'Content-Type: application/json' -d '{...}' URL` sends a POST with a JSON body and prints the status and headers. `curl -I URL` is the quick check that an endpoint is up.

### How do you download a file and keep its name?

`wget URL` saves it under the remote filename automatically. With curl, use `curl -O URL` (capital O) to keep the remote name, or `curl -o myname URL` to choose a different one.
