## What it is

When you type a command, the shell splits the line into parts: the command name (like ls), its options or flags (like -l), and its arguments (like /etc, the thing to act on). Options change how the command behaves; arguments say what it works on. After the command finishes, the shell stores its exit code in the special variable $?, which tells you whether it succeeded.

## Why it exists

You need one simple, consistent way to tell the computer what to do and to know whether it worked. The command, options and arguments shape means every tool is learned the same way. The exit code exists so that scripts and other commands can react automatically: a backup script must know if the copy failed, and it checks the exit code rather than guessing from the text on screen.

## How it works

<Steps>
<Step title="Type the line">Write the command, then options, then arguments: ls -l /etc.</Step>
<Step title="Shell runs it">The shell finds the command, passes it the options and arguments, and runs it.</Step>
<Step title="Read the result">Output appears in the terminal; the exit code is saved in $?.</Step>
<Step title="Get help">man ls or ls --help lists every option.</Step>
</Steps>

1. Short options use one dash (-l); long options use two (--all); many short ones combine (-la).
2. 0 means success; any other number means a specific failure.

## Example

```bash
ls -l /etc/hostname
echo $?
```

```text output
-rw-r--r-- 1 root root 10 Nov  2 09:14 /etc/hostname
0
```

What to notice:

- `ls` is the command, `-l` the option (long listing), and `/etc/hostname` the argument.
- `$?` printed `0`, so `ls` succeeded. List a missing file instead and `$?` becomes `2`, a failure code, even though an error line was printed.

## Rules and defaults

| What | Default | Where |
|---|---|---|
| Exit code of success | 0 | shell convention ($?) |
| Exit code of failure | non-zero (1 to 255) | per command |
| Help for a command | `man <cmd>` or `<cmd> --help` | man-pages, GNU tools |

- Quick info commands: `whoami` (your username), `hostname` (machine name), `uname -a` (kernel and system), `date` (current date and time), `clear` (clear the screen), `history` (past commands).
- Options usually come before arguments, though many commands accept either order.

## Not to be confused with

An option changes how a command runs (ls -l); an argument is what it runs on (ls /etc). Rule: flags start with - or --, while arguments are plain names like files and directories.

## Common mistakes

- Reading the output and assuming success; always check $?, because a command can print text and still exit non-zero.
- Confusing -l (an option) with a file called l; options start with a dash.

## Interview Qs

### What are the parts of a Linux command?

The command name, its options (flags like -l or --all that change behaviour), and its arguments (what it acts on, like a file or directory). For example, in `ls -l /etc`, ls is the command, -l the option and /etc the argument.

### How do you check if a command succeeded?

Read its exit code from $?. Zero means success; any non-zero value means failure. Scripts test $? (or use the command in an if) rather than relying on the printed output, because commands often print text even when they fail.

### How do you find out what a command does?

Use `man <command>` for the full manual page, or `<command> --help` for a quick summary of options, for example `man ls` or `ls --help`. The `whatis` and `apropos` commands also help you find the right command.
