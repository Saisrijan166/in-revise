## What it is

A listening [socket](term:socket) is a service waiting on a port for connections. `ss` ("socket statistics") lists them. The usual form is `ss -tulnp`: show TCP (`-t`) and UDP (`-u`) sockets that are listening (`-l`), with numeric ports (`-n`) and the owning process (`-p`). It answers two everyday questions: what is running on this machine, and which process holds a given port. `netstat` is the older command that did the same.

## Why it exists

Services bind to ports, but you cannot see them by looking at files. When a port is taken, an app refuses to start; when a service seems dead, you need to know if it is even listening. `ss` reads the kernel's socket table directly and shows the port, its state and the process behind it, so you can confirm a service is up or find and stop whatever is squatting on a port.

## How it works

| Port | Service |
|---|---|
| 22 | SSH |
| 53 | DNS |
| 80 | HTTP |
| 443 | HTTPS |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 6379 | Redis |
| 8080 | Alternative HTTP / app |

1. Run `ss -tulnp` to list every listening TCP and UDP socket with its port and process.
2. Read the `Local Address:Port` column to see which ports are open, and the process column for the pid and program.
3. To check one port, pipe through `grep`, for example `ss -tulnp | grep :5432`.

## Example

```bash
ss -tulnp | grep :8080
```

```text output
tcp   LISTEN 0  511  0.0.0.0:8080  0.0.0.0:*  users:(("java",pid=8412,fd=24))
```

What to notice: port 8080 is in `LISTEN` state, bound on `0.0.0.0` (all interfaces), and the `users:(...)` field names the process: a `java` program with pid 8412. If your app will not start on 8080, this is the process to stop. `0.0.0.0` means it accepts connections from any interface, not just localhost.

## Rules and defaults

- **`-p` needs privilege** to show processes you do not own; run `ss` with `sudo` to see every owner.
- **Default without `-l`:** `ss` shows established connections; add `-l` for listening sockets, or `-a` for both.
- **Ports 0-1023 are privileged** (IANA System Ports): binding one needs root, which is why apps default to 8080 instead of 80.
- **ss replaces netstat:** both read the same kernel data; `ss` is faster and installed by default on modern distros.

## Not to be confused with

`ss` lists sockets on your own machine, including their owning process. `ping` tests whether a remote host answers over ICMP. Rule: use `ss` to ask "is this service listening here?" and `ping` to ask "does that host reply at all?".

## Common mistakes

- **Reading 'Address already in use' as a remote conflict.** It is a local process already on that port. Find it with `ss -tulnp` and stop it or change your port.
- **Forgetting `sudo` and seeing blank process names.** Without privilege, `ss -p` cannot show processes owned by others, so the owner column looks empty.

## Interview Qs

### How do you find which process is using a port?

`ss -tulnp` lists listening sockets with the owning process; filter with `grep`, for example `ss -tulnp | grep :8080`. The process column shows the pid and program name. Run it with `sudo` to see processes owned by other users.

### What do the flags in ss -tulnp mean?

`-t` TCP sockets, `-u` UDP sockets, `-l` only listening sockets, `-n` numeric ports (no name lookup), `-p` the process using each socket. Together they list every listening TCP and UDP port with its owner.

### Which common ports should you know?

22 SSH, 53 DNS, 80 HTTP, 443 HTTPS, 3306 MySQL, 5432 PostgreSQL, 6379 Redis, and 8080 as a common alternative HTTP or application port. Ports below 1024 are privileged and need root to open.
