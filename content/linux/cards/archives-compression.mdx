## What it is

Archiving and compression are two different jobs. Archiving joins many files and folders into one file so they move or store as a single unit. Compression shrinks data so it takes less space. `tar` is the archiver: it bundles files but does not shrink them. `gzip` is a compressor: it shrinks one file and is "not an archiver". A `.tar.gz` file is a tar archive that has been run through gzip, so it is both bundled and small.

## Why it exists

A backup or a release is usually many files in nested folders. Copying or uploading them one by one is slow and easy to get wrong, and they take more space and bandwidth than needed. `tar` packs the whole tree into one file so it travels as a unit, and `gzip` (via the `-z` flag) squeezes that file down. Together they turn a folder into a single, smaller `.tar.gz` you can move, store or download in one step.

## How it works

| Flag | Meaning |
|---|---|
| `-c` | create a new archive |
| `-x` | extract files from an archive |
| `-t` | list what is inside, without extracting |
| `-v` | verbose: print each file as it is processed |
| `-f` | the next word is the archive file name |
| `-z` | filter the archive through gzip |

1. `tar -c` reads the named files and writes one archive; add `-z` to gzip it as it writes.
2. `-f name` must point at the archive file; it is why `-f` comes last, just before the name.
3. `tar -x` reverses it: it reads the archive (with `-z`, un-gzips first) and recreates the files and folders.

## Example

```bash
tar -czvf logs.tar.gz logs/   # bundle + gzip the folder
tar -tzf logs.tar.gz          # list what is inside
```

```text output
logs/
logs/app.log
logs/error.log
```

What to notice: `-c` created the archive and `-z` gzipped it into the `.gz`. `-t` lists the contents without unpacking, and the folder structure is kept. To unpack it, swap `-c` for `-x`: `tar -xzvf logs.tar.gz` recreates `logs/` where you run it.

## Rules and defaults

- **tar needs `-z` to compress:** plain `tar -cf out.tar dir/` bundles at the same size; `-z` adds gzip and makes it a `.tar.gz`.
- **gzip replaces its input:** `gzip big.log` leaves `big.log.gz` and removes `big.log` (keeping the same permissions and timestamps); `gunzip big.log.gz` reverses it.
- **gzip is one file at a time:** it cannot bundle a folder. For that, tar it first, then gzip (which `-z` does in one go).
- **zip does both:** `zip -r out.zip dir/` recurses into the folder, bundling and compressing; `unzip out.zip` extracts it. zip is common when sharing with Windows users.

## Not to be confused with

`tar` bundles files into one archive; `gzip` shrinks a single file. Rule: a `.tar.gz` means tar bundled first and gzip shrank the bundle second — two tools, two steps.

## Common mistakes

- **Thinking tar compresses.** Without `-z` (or another filter) the archive is the same total size as the files.
- **Wrong flag order with `-f`.** `-f` names the archive, so it comes last among the bundled letters: `tar -czvf name.tar.gz dir/`, not `tar -cfzv`.
- **Expecting gzip to bundle a folder.** gzip works on one file; use tar (or `zip -r`) for a folder.

## Interview Qs

### What is the difference between tar and gzip?

`tar` bundles many files and folders into one archive but does not shrink them. `gzip` compresses a single file to make it smaller and is not an archiver. A `.tar.gz` is a tar archive that has then been gzip-compressed, which is why the `-z` flag is involved.

### How do you create and extract a .tar.gz?

Create: `tar -czvf app.tar.gz app/` — `-c` create, `-z` gzip, `-v` verbose, `-f` the file name. Extract: `tar -xzvf app.tar.gz` — the same flags with `-x` instead of `-c`. Use `-tzf` to list the contents without extracting.

### What do the tar flags c, x, t, v, f and z mean?

`-c` creates an archive, `-x` extracts one, `-t` lists its contents, `-v` is verbose output, `-f` says the next word is the archive file name, and `-z` filters the archive through gzip to compress or decompress it.
