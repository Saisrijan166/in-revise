## What it is

`find` is a command that searches a directory tree for files. You give it a place to start and a set of tests, and it looks at every file and folder under that place, keeping the ones that pass every test. Tests include `-name` (the file name), `-type` (file or directory), `-size` and `-mtime` (how long ago it changed). For each match it can print the path, or run a command with `-exec`, or remove it with `-delete`.

## Why it exists

You often know something about a file but not where it is: its name, that it is large, or that it has not changed in weeks. `ls` only lists one folder. find searches a whole tree in one command and can then act on every match at once, for example delete all old log files. Without it you would open folders by hand or write a loop. find turns "which files are like this, and do X to them" into a single line.

## How it works

<Steps label="How find runs">
<Step title="Start point">find begins at the path you give, for example `.` for the current directory. If you give none, it uses `.`.</Step>
<Step title="Walk the tree">It visits every file and directory under that start point, going into subfolders.</Step>
<Step title="Apply tests">For each entry it checks the tests you listed, such as `-name '*.log'` and `-type f`. All tests must pass (they are AND by default).</Step>
<Step title="Take an action">It prints each match. With `-exec cmd {} +` it runs a command on the matches; with `-delete` it removes them.</Step>
</Steps>

## Example

Find Java files larger than 1 mebibyte under the current folder:

```bash
find . -name "*.java" -type f -size +1M
```

```text output
./service/src/BigGenerated.java
./legacy/Dump.java
```

What to notice:

- `-name "*.java"` is quoted, so the shell passes `*.java` to find instead of expanding it first.
- `-type f` keeps only regular files, dropping any directory that happens to end in `.java`.
- `-size +1M` means strictly larger than 1 MiB; `M` is mebibytes (1024 x 1024 bytes), and `+` means greater than.

## Rules and defaults

| Test | Meaning | Note |
|---|---|---|
| `-name PATTERN` | Match the file name | Quote patterns with `*` or `?` |
| `-type f` / `-type d` | Regular file / directory | |
| `-size +100M` | Larger than 100 MiB | `-100M` = smaller; `M` is mebibytes |
| `-mtime +7` | Changed more than 7 days ago | `-7` = within 7 days |
| `-exec cmd {} +` | Run cmd on matches | `{}` is the path; `+` batches like xargs |
| `-delete` | Remove matches | Deletes files; a directory only if empty; cannot undo |

- With no start path, find uses the current directory. With no tests, it prints everything under it.
- `-exec ... {} \;` runs once per file; `-exec ... {} +` batches many paths into one call and is faster.
- `-delete` has no confirmation. Run the find first without it to see what would go.

## Not to be confused with

`grep` searches the text *inside* files and prints matching lines; find searches *for* the files themselves by their attributes. If the question is "where is the file?", use find; if it is "which lines say this?", use [grep](card:grep). The two combine: `find . -name '*.java' -exec grep -l deprecated {} +` finds Java files that contain the word deprecated. See [find vs grep](compare:find-vs-grep).

## Common mistakes

- **Unquoted name pattern.** `find . -name *.log` lets the shell expand `*.log` first and then find fails or searches the wrong thing. Quote it: `-name '*.log'`.
- **Running -delete too soon.** Test the search without `-delete` first; the delete cannot be undone.
- **Confusing -mtime signs.** `+7` is older than 7 days, `-7` is within the last 7 days, `7` is exactly the 7th day back.

## Interview Qs

### How do you find all files of a type under a directory?

`find . -name "*.ext" -type f`. find walks the tree from `.`, keeps regular files whose name matches the quoted pattern, and prints their paths. Add `-size` or `-mtime` to also filter by size or age.

### How do you delete files older than 7 days?

`find /path -type f -mtime +7 -delete`. `-mtime +7` selects files changed more than 7 days ago and `-delete` removes each match. Run it once without `-delete` first to confirm the list, because the delete cannot be undone.

### What does -exec {} + do, and how is it different from {} ;?

`-exec cmd {} +` runs the command once with many matched paths on its command line, like xargs, so it is efficient. `-exec cmd {} \;` runs the command separately for each file, which is slower but needed when the command takes exactly one argument.
