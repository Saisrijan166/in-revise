## What it is

Ownership is the identity attached to every file: one owning user and one owning group. The [permission bits](card:file-permissions) decide what the owner, the group and others may do; ownership decides which user and which group those rules point at. `chown` changes the owning user, and optionally the group; `chgrp` changes only the group.

## Why it exists

Permission classes (owner, group, others) are only useful if each file is pinned to a real user and group. When a file lands with the wrong owner, for example root-owned files in a service's directory, the service running as its own user cannot touch them. You need a way to reassign a file to the user or team that should manage it. `chown` and `chgrp` do that.

## How it works

```bash
chown appuser file        # new owning user
chown appuser:app file    # new owning user and group
chown :app file           # group only (same as chgrp app file)
chgrp app file            # new owning group
chown -R appuser:app dir/ # whole directory tree
```

1. `chown USER file` sets the owning user; the group is left as it was.
2. `chown USER:GROUP file` sets both at once.
3. A leading colon, `chown :GROUP`, changes only the group; `chgrp` is the dedicated command for that.
4. `-R` recurses into a directory and changes every file and subdirectory under it.

## Example

```bash
sudo chown -R appuser:app /srv/app
ls -ld /srv/app
```

```text output
drwxr-x--- 5 appuser app 4096 Nov  2 10:15 /srv/app
```

What to notice:

- The owning user and group are now `appuser app`, shown in the two name columns of `ls -l`.
- It needed `sudo`: changing the owning user requires root. Without it you would get "Operation not permitted".

## Rules and defaults

- **Changing the user needs root** (the CAP_CHOWN capability). A normal user cannot give a file away.
- **Changing the group** can be done by the file's owner, but only to a group they are a member of; root can set any group.
- **`-R` with symlinks:** by default `chown -R` does not follow symbolic links into their targets (`-P` is the default); `-L` would.
- **Ownership is separate from permissions:** chown does not touch the `rwx` bits, and chmod does not touch the owner.

## Not to be confused with

`chmod` changes the permission bits, what the owner, group and others may do. `chown` changes who the owner and group are. Rule: use `chmod` for *what is allowed*, `chown` for *who it applies to*. The full side-by-side is in [chmod vs chown](compare:chmod-vs-chown).

## Common mistakes

- **Trying to chown without root.** A normal user cannot change the owning user, even on their own file; only the group, to one they belong to.
- **Forgetting `-R` on a directory.** `chown appuser dir/` changes only the directory itself, not the files inside it.
- **Mixing up `chown user:group` and `chown user.group`.** The colon is the portable form; the dot is an old GNU extension and can clash with usernames that contain a dot.

## Interview Qs

### What is the difference between chmod and chown?

`chmod` changes the permission bits (what the owner, group and others may read, write or execute). `chown` changes the ownership (which user and group the file belongs to). One sets what is allowed; the other sets who it applies to.

### Why does changing a file's owner usually need sudo?

Because the kernel only lets a privileged process (CAP_CHOWN, i.e. root) change a file's owning user. If any user could give files away, they could dodge disk quotas by dumping files onto other accounts, so the ability is restricted.

### How do you change the owner of a directory and everything in it?

`sudo chown -R user:group dir/`. The `-R` flag recurses into the directory and reassigns every file and subdirectory, not just the top folder.
