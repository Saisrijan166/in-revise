## What it is

These are the everyday commands that change files and folders. `touch` creates an empty file. `mkdir` makes a directory. `cp` copies, `mv` moves or renames, and `rm` deletes. `rmdir` removes an empty directory. A few options matter a lot: `-p` builds a whole path of folders, `-r` makes a command work on a folder and everything inside it, and `-f` forces an action without asking.

## Why it exists

Managing a project from the shell means creating, copying and removing files constantly, so each action has a short command. Options exist because the plain command refuses risky work by default: `cp` and `rm` will not touch a folder without `-r`, and `mkdir` will not build missing parents without `-p`. Knowing these keeps you from fighting the tool, and from the far worse mistake of deleting the wrong tree with `rm -rf`.

## How it works

<Steps label="A short file-wrangling session">
<Step title="mkdir -p app/src">Create the app folder and its src child in one step.</Step>
<Step title="touch app/src/Main.java">Make an empty file inside it.</Step>
<Step title="cp app/src/Main.java app/src/Backup.java">Copy the file to a new name.</Step>
<Step title="mv app/src/Backup.java app/src/Old.java">Rename the copy (same folder = rename).</Step>
<Step title="rm app/src/Old.java">Delete the file; gone immediately, no trash.</Step>
</Steps>

- `cp -r src dst` copies a folder; without `-r` it refuses.
- `mv` to a name in the same folder renames; `mv` to another folder moves.
- `rmdir` only removes an empty folder; `rm -r` removes a full one.

## Example

```bash
mkdir -p logs/2026
touch logs/2026/app.log
cp -r logs backup
rm -r backup
```

What to notice:

- `mkdir -p` made both `logs` and `logs/2026` in one go; without `-p` it would error because `logs` did not exist yet.
- Successful file commands print nothing (no news is good news). `cp -r` copied the whole `logs` tree, and `rm -r` removed the copy without any confirmation prompt.

## Rules and defaults

| Command | Default behaviour |
|---|---|
| `mkdir dir` | Fails if a parent is missing; `-p` creates the parents |
| `cp a b` | Copies a file; refuses a folder unless `-r` |
| `mv a b` | Moves, or renames if `b` is in the same directory |
| `rm f` | Deletes a file; needs `-r` for a folder; `-f` skips prompts |
| `rmdir d` | Removes only an empty directory |

- **No trash:** `rm` unlinks immediately; there is no built-in undo.
- **`rm -rf` is the dangerous one:** recursive plus forced, no prompt. A wrong path can wipe a lot.
- **Overwrites are silent:** `cp` and `mv` replace an existing target without asking unless you add `-i`.

## Common mistakes

- **`rm -rf` with a typo or a stray space,** like `rm -rf / home` instead of `/home`. Check the path first.
- **Copying a folder without `-r`** and seeing "omitting directory". Add `-r`.
- **Expecting a rename command.** Use `mv old new` in the same folder.

## Interview Qs

### What is the difference between rm, rm -r and rm -rf?

`rm` deletes files. `rm -r` deletes a folder and everything inside it (recursive). `rm -rf` adds `-f`, which forces the delete and skips all prompts and missing-file warnings. There is no trash, so a wrong `rm -rf` cannot be undone.

### How do you rename a file in Linux?

With `mv oldname newname`. There is no separate rename command: when the destination is in the same directory, `mv` renames the file; when it is another directory, `mv` moves it.

### What does mkdir -p do?

It creates a directory and any missing parent directories in the path. `mkdir -p a/b/c` makes `a`, then `a/b`, then `a/b/c`, and it does not error if some of them already exist.
