## What it is

A signal is a short, predefined message the kernel delivers to a process to tell it something happened or to ask it to act, such as "please stop". Each signal has a name like SIGTERM and a number like 15. Most signals end the process by default, but a program can install a handler to catch many of them, except SIGKILL and SIGSTOP, which it can never catch or ignore.

## Why it exists

You need a standard way to control a running process from outside it: stop it, pause it, or tell it to reload. Signals are that channel. SIGTERM lets a well-behaved app flush files and close connections before exiting, which plain destroying would skip. SIGKILL exists as a last resort the process cannot refuse, so a hung program can always be removed.

## How it works

<Compare id="sigterm-vs-sigkill" />

1. You run `kill PID` (or a program calls the `kill()` system call); the kernel queues the signal for that process.
2. For a catchable signal, the process runs its handler, for example a JVM shutdown hook, then usually exits.
3. For SIGKILL or SIGSTOP there is no handler: the kernel acts directly, ending or pausing the process.
4. `kill -NUMBER` or `kill -NAME` picks the signal: `kill -9`, `kill -SIGKILL` and `kill -KILL` are the same.

## Rules and defaults

| Signal | Number | Default action | Catchable? |
|---|---|---|---|
| SIGHUP | 1 | end process | yes |
| SIGINT | 2 | end process | yes |
| SIGKILL | 9 | end process | no |
| SIGTERM | 15 | end process | yes |
| SIGSTOP | 19 | pause process | no |

- `kill PID` with no signal sends SIGTERM (15), not SIGKILL.
- These numbers hold on x86 and ARM; a few architectures differ, so prefer names in scripts.
- Ctrl+C sends SIGINT; Ctrl+Z sends SIGTSTP (a catchable terminal-stop), not SIGSTOP.

## Not to be confused with

Ctrl+C (SIGINT) and kill's SIGTERM both ask a program to stop and both can be handled, but SIGINT comes from the keyboard to the foreground program while SIGTERM is sent by PID to any process. Rule: same idea, different source.

## Common mistakes

- Reaching for `kill -9` first; it skips cleanup and can corrupt files. Try SIGTERM, then SIGKILL.
- Thinking a process can be written to ignore SIGKILL; it cannot — only the kernel decides.
- Confusing SIGSTOP (uncatchable, number 19) with Ctrl+Z's SIGTSTP, which a program can handle.

## Interview Qs

### What is the difference between SIGTERM and SIGKILL?

SIGTERM (15) is kill's default: it asks the process to stop and lets it clean up, and the process can catch or ignore it. SIGKILL (9) cannot be caught or ignored; the kernel ends the process at once with no cleanup.

### What does the default kill command send?

`kill PID` sends SIGTERM (15), a polite request to terminate, not SIGKILL. The process can run a handler first. You send SIGKILL with `kill -9` only when SIGTERM does not work.

### Which signals cannot be caught or ignored?

SIGKILL (9) and SIGSTOP (19). Every other signal can be caught by a handler, blocked, or ignored. That is why SIGKILL is the reliable last resort for a process that ignores SIGTERM.
