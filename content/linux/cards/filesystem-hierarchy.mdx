## What it is

Linux arranges all files in one tree that starts at the root directory, written `/`. There are no drive letters: a second disk or a USB stick is attached ("mounted") onto a folder inside this one tree. Each top-level folder has a job fixed by the Filesystem Hierarchy Standard (FHS), so config, logs, user files and programs always live in the same kinds of places.

## Why it exists

Without an agreed layout, every program would drop its settings and logs wherever it liked, and you would relearn the map on each machine. The FHS gives one predictable structure: an administrator or a script knows that configuration is under `/etc`, logs under `/var/log`, and user data under `/home`, on Ubuntu, Debian or Fedora alike. Tools, backups and package managers all rely on this.

## How it works

| Folder | Holds |
|---|---|
| `/etc` | System configuration files (one machine's settings) |
| `/var`, `/var/log` | Data that changes while running; logs in `/var/log` |
| `/home` | Normal users' home directories (`/home/anita`) |
| `/root` | The root user's own home directory |
| `/usr`, `/bin`, `/sbin` | Programs: everyday commands, plus `/sbin` for admin tools |
| `/tmp` | Temporary files, deleted without notice (often at boot) |
| `/proc`, `/sys` | Virtual files the kernel builds in memory |
| `/dev` | Device files that stand for hardware (disks, terminals) |
| `/opt` | Optional add-on third-party software |

1. Everything hangs off `/`; you reach a file by its path down the tree, like `/var/log/syslog`.
2. `/proc` and `/sys` are not on any disk. Reading `/proc/cpuinfo` asks the kernel for live information.
3. Extra disks are mounted onto an empty folder (say `/mnt/data`) and appear as part of the same tree.

## Analogy

<Analogy title="A well-run office building" limit="Real systems bend the rules: some logs sit elsewhere, and /usr today holds most programs, not /bin.">

## Example

```bash
ls /
cat /proc/loadavg
```

```text output
bin  boot  dev  etc  home  lib  opt  proc  root  sbin  sys  tmp  usr  var
0.12 0.08 0.05 1/312 48217
```

What to notice:

- `ls /` shows the top-level folders; the names are the same on almost every Linux system.
- `/proc/loadavg` is a virtual file. It holds no bytes on disk; the kernel produces the three [load averages](term:load-average) the moment you read it.

## Rules and defaults

- **One tree, no drive letters:** all storage is reached through `/`; mounting attaches a disk onto a folder.
- **Fixed by convention:** `/etc` config, `/var/log` logs, `/home` users, `/bin` and `/usr/bin` programs. A distro may add folders but keeps these.
- **`/proc` and `/sys` are virtual:** they vanish on shutdown and reflect the live kernel; do not treat them as normal files to back up.
- **`/tmp` is not safe storage:** anything there can be removed at any time.

## Interview Qs

### Where are configuration files and logs on Linux?

Configuration files live under `/etc`, and logs under `/var/log`. Changing application data is under `/var`. This layout is set by the Filesystem Hierarchy Standard, so it is the same across distributions like Ubuntu and Fedora.

### What is special about /proc and /sys?

They are virtual (pseudo) filesystems the kernel builds in memory, not files stored on a disk. Reading a file such as `/proc/cpuinfo` or `/proc/loadavg` returns live kernel and process information. They are empty when the system is off.

### Does Linux use drive letters like C: and D:?

No. Linux has one tree starting at `/`. Extra disks or USB drives are mounted onto a folder inside that tree, for example `/mnt/data`, so they appear as part of the same hierarchy rather than as separate lettered drives.
