## What it is

A process is a running program: the code plus its memory, open files and current state, which the kernel schedules on the CPU. Each process has a PID, a number that identifies it, and a PPID, the PID of the process that started it. Processes form a tree: PID 1 (the init system, usually systemd) is the first, and every other process descends from it. A process runs either in the foreground, holding your terminal, or in the background.

## Why it exists

A server runs many programs at once, and you often need to act on one: see if your app is alive, find why it eats CPU, or stop it. For that you need a way to name each running program and see its state. The PID is that name, and tools like ps and [top](card:monitoring-processes) list the processes so you can inspect the right one instead of guessing.

## How it works

<Steps>
<Step title="Start">You run a command; the kernel creates a process, gives it a PID and records its PPID.</Step>
<Step title="List">ps prints a snapshot of processes; ps aux covers every process on the system.</Step>
<Step title="Read the row">Each row shows the PID, owner, CPU and memory, state (STAT) and the command.</Step>
<Step title="Act">Use the PID to watch it with top or to send it a signal.</Step>
</Steps>

- Plain `ps` shows only processes with your user ID on your terminal; `ps aux` (BSD style) shows them all.
- STAT letters: `R` running, `S` sleeping, `Z` zombie, `T` stopped.

## Example

```bash
ps aux | grep '[j]ava'
```

```text output
deploy  4821  0.3  2.1 3812044 342112 ?  Sl  09:14  0:07 java -jar app.jar
```

What to notice:

- The columns are USER, PID (4821), %CPU, %MEM, memory sizes, STAT (`Sl`), START, TIME, then the command.
- The `[j]ava` pattern stops grep from matching its own grep process.
- PID 4821 is what you pass to top, kill or a [signal](card:signals).

## Rules and defaults

- Plain `ps` lists only your processes on your terminal; `ps -e` or `ps aux` lists every process.
- `ps` is a snapshot and then exits; for a live view use `top` or `htop`.
- The `%CPU` and `%MEM` in `ps aux` are averages over the process's whole life, not the current instant.
- Every process has exactly one parent (PPID); when a parent dies, its children are re-parented to PID 1.

## Not to be confused with

A program is the file on disk (like `/usr/bin/java`); a process is one running instance of it, so the same program can run as many processes. A job is the shell's name for a process it started, numbered `%1`, `%2`. Rule: the kernel tracks processes by PID; your shell tracks its own as jobs.

## Common mistakes

- Reading `ps aux` %CPU as the current CPU usage; it is a lifetime average, so use top for "now".
- Writing `ps -aux` and `ps aux` as if identical; the dash mixes two option styles (it usually works, but is not recommended).
- Forgetting that plain `ps` hides other users' and other terminals' processes.

## Interview Qs

### What is the difference between a process and a program?

A program is an executable file on disk. A process is a running instance of that program, with its own PID, memory and state. One program can run as many separate processes at the same time.

### What is PID 1?

PID 1 is the first process the kernel starts, the init system (usually systemd). Every other process descends from it. When any process's parent dies, PID 1 adopts the orphaned children and later reaps them.

### How do you list all running processes?

`ps aux` shows every process with its user, PID, CPU and memory. `ps -ef` is the equivalent in the other option style. For a live, refreshing view use `top` or `htop`.
