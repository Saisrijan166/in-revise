## What it is

A file permission says who may do what with a file. Linux tracks three actions, read (r), write (w) and execute (x), and keeps a separate set of them for three classes of user: the owner (also called the user), the file's group, and others (everyone else). That is nine bits in total. The same bits apply to directories, but their meaning shifts, because a directory is a special file that lists other files.

## Why it exists

Many users share one machine, and files hold private data and runnable programs. The system needs a simple, fast rule for every open, write or run: is this user allowed? Three actions times three classes gives a compact answer that fits in a few bits on every file, so the kernel can check access on each operation without a separate database.

## How it works

An `ls -l` line starts with ten characters that encode the permissions:

| Position | 1 | 2-4 | 5-7 | 8-10 |
|---|---|---|---|---|
| Means | file type | owner | group | others |
| Example `-rwxr-xr--` | `-` file | `rwx` | `r-x` | `r--` |

1. The first character is the type: `-` a regular file, `d` a directory, `l` a [symbolic link](term:symbolic-link).
2. The next three are the owner's rights, then the group's, then everyone else's.
3. A letter means the action is allowed; a `-` means it is not.
4. The kernel checks the class that matches you: owner first, else group, else others, and uses only that set.

## Example

```bash
ls -l script.sh report/
```

```text output
-rwxr-xr-- 1 srijan dev  214 Nov  2 10:04 script.sh
drwxr-x--- 2 srijan dev 4096 Nov  2 10:05 report
```

What to notice:

- `script.sh` is `-rwxr-xr--`: the owner can read, write and run it; the group can read and run; others can only read.
- `report` starts with `d`, a directory. Its `r-x` for the group lets group members enter and list it; others get `---`, so they cannot even see inside.

## Rules and defaults

- **Owner wins first:** if you own the file, only the owner bits apply to you, even if the group bits are wider.
- **Directory execute is traverse:** you need `x` on a directory to `cd` into it or reach any file below it.
- **Directory write is dangerous:** write on a directory lets you delete a file inside it even if you cannot write the file itself, because deleting changes the directory, not the file. The [sticky bit](card:special-permissions) limits this.
- **New files** are created at `644` and directories at `755` by default: the system asks for `666`/`777` and the umask (usually `022`) removes the group and others write bits. Change them with [chmod](card:chmod).

## Common mistakes

- **"Read on a directory lets me open files inside."** Read only lists names. You need execute to traverse into it.
- **"The widest matching class applies."** Only the first matching class is used. If others has `rwx` but you are the owner with `r--`, you get `r--`.
- **Confusing the group bits with your own.** You get group rights only when you are not the owner but are in the file's group.

## Interview Qs

### What do read, write and execute mean on a directory?

Read lists the entry names, write lets you create, delete or rename entries inside it, and execute lets you enter (`cd`) and traverse the directory to reach files below. You usually need read and execute together to work in a directory.

### How do you read an `ls -l` permission string like -rwxr-xr--?

The first character is the file type (`-` file, `d` directory). The next nine are three groups of `rwx`: owner, group, others. Here the owner has read, write, execute; the group read and execute; others read only.

### If a file's others bits are rwx but you are the owner with only r--, what can you do?

Only read. The kernel checks the owner class first because you own the file, and uses just that set. The wider others bits never apply to the owner.
