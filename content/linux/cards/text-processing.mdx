## What it is

Linux ships several small tools that each do one thing to text, meant to be joined by [pipes](card:pipes-and-redirection). `sort` orders lines, `uniq` collapses repeated lines, `wc` counts lines, words or bytes, and `cut` picks columns out of each line. `sed` is a stream editor that changes text by a rule, such as replace this with that. `awk` splits each line into fields and lets you work on them, like "print the third field". Chained together they answer questions about logs and data files.

## Why it exists

Developers constantly ask small questions of text: how many errors today, which IP hit us most, what are the unique user IDs. Writing a program for each is slow. These tools, built in the Unix spirit of "do one thing well", let you compose an answer in one line. Because each reads stdin and writes stdout, a pipe strings them into a pipeline. The whole toolkit exists so that counting, sorting and filtering text needs no code.

## How it works

<Steps label="A counting pipeline">
<Step title="Extract">`cut` or `awk` pulls out the column you care about, one value per line.</Step>
<Step title="Sort">`sort` puts equal values next to each other, which uniq needs.</Step>
<Step title="Count">`uniq -c` collapses each run of equal lines into one line prefixed with its count.</Step>
<Step title="Rank">`sort -rn` orders those lines by the count, largest first; `head` keeps the top few.</Step>
</Steps>

## Example

Find the most common status codes in a space-separated access log (the code is field 9):

```bash
awk '{print $9}' access.log | sort | uniq -c | sort -rn | head -3
```

```text output
   1423 200
    318 404
     57 500
```

What to notice:

- `awk '{print $9}'` prints the 9th field of each line; awk splits on spaces by itself.
- `sort` groups equal codes so that `uniq -c` can count each run and print the count in front.
- `sort -rn` sorts by that number in reverse, so the busiest code is first; `head -3` keeps the top three.

## Rules and defaults

| Tool | Does | Key options |
|---|---|---|
| `sort` | Order lines | `-n` numeric, `-r` reverse, `-k` by column |
| `uniq` | Collapse adjacent equal lines | `-c` count, `-d` only duplicates |
| `wc` | Count | `-l` lines, `-w` words, `-c` bytes |
| `cut` | Pick columns | `-d` delimiter, `-f` field numbers |
| `sed` | Edit a stream by rule | `s/old/new/` substitute |
| `awk` | Work on fields | `$1`, `$2` are fields; `{print ...}` |

- `uniq` compares only neighbouring lines, so sort before it.
- `cut -d` sets the field separator; without `-d` it defaults to the tab character.
- `sort` compares as text by default; use `-n` so `10` sorts after `9`, not before it.

## Common mistakes

- **uniq without sort.** Scattered duplicates survive. Always `sort | uniq`.
- **Text sort on numbers.** Plain `sort` puts `100` before `9`. Use `sort -n` for numbers.
- **Using cut on single-space columns that vary.** `cut` splits on one delimiter; for whitespace-separated fields `awk '{print $N}'` is safer.

## Interview Qs

### Why do you usually sort before uniq?

uniq only removes duplicate lines that are next to each other; it compares each line with the previous one. Sorting brings all equal lines together first, so `sort file | uniq` removes every duplicate and `sort file | uniq -c` counts each value.

### How would you find the top 5 most frequent lines in a file?

`sort file | uniq -c | sort -rn | head -5`. sort groups equal lines, `uniq -c` counts each group, `sort -rn` orders by the count from highest, and `head -5` keeps the top five.

### What is the difference between sed and awk?

sed is a stream editor: it transforms text by rules, most often substitution with `s/old/new/`. awk splits each line into fields (`$1`, `$2`, ...) and runs small programs on them, so it is better for column-based data, calculations and conditional printing.
