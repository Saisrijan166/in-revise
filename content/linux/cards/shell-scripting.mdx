## What it is

A shell script is a plain text file holding the same commands you would type at the prompt, run top to bottom. Its first line is the shebang, `#!/bin/bash`, which names the interpreter the kernel should use to run the file. Inside, you set variables (`name=value`), read them (`$name`), use the arguments passed in (`$1`, `$2`, ...), and add `if` and `for` to make decisions and repeat work.

## Why it exists

A real task is often several commands in a fixed order: pull the build, stop the service, copy files, restart, check the log. Typing them by hand every time is slow and easy to get wrong, and only you know the steps. A script records the sequence once, so anyone can run it the same way every time, schedule it with [cron](card:cron-scheduling), and change the recipe in one file instead of in their memory.

## How it works

<Steps>
<Step title="Write the file">The first line is #!/bin/bash; the rest are commands.</Step>
<Step title="Make it executable">chmod +x script.sh adds the execute permission.</Step>
<Step title="Run it">./script.sh asks the kernel to run the file; it reads the shebang and starts bash on it.</Step>
<Step title="Pass arguments">Words after the name arrive as $1, $2, ...; $# is how many, $@ is all of them.</Step>
</Steps>

1. Without the execute bit, `./script.sh` fails; `chmod +x` fixes it. (You can also run it as `bash script.sh`, which needs no execute bit.)
2. The kernel reads the `#!` line and runs the named interpreter with the script as its argument.
3. `$?` holds the exit code of the last command: 0 means success, non-zero means a failure.

## Example

```bash
#!/bin/bash
name=$1                       # first argument
if [ -z "$name" ]; then       # is it empty?
  echo "usage: greet.sh NAME"
  exit 1                       # non-zero = error
fi
echo "Hello, $name"
```

```text output
$ ./greet.sh
usage: greet.sh NAME
$ ./greet.sh Ayush
Hello, Ayush
```

What to notice: `name=$1` reads the first argument with no spaces around `=`. `[ -z "$name" ]` tests whether it is empty; the quotes keep an empty value from breaking the test. `exit 1` ends the script with a non-zero code so a caller knows it failed.

## Rules and defaults

- **No spaces in assignment:** `name=value`, not `name = value`.
- **`./` is needed:** typing just `script.sh` searches `PATH`, which usually excludes the current folder, so run `./script.sh`.
- **Exit codes:** every command sets `$?`; `0` is success, anything else is failure. `exit n` ends the script with code `n`.
- **`[ ]` is the test command:** `if [ "$x" = y ]; then ...; fi` compares strings or files; the spaces inside `[ ]` are required.
- **Quote your variables:** write `"$name"` so an empty or spaced value does not split into several words.

## Not to be confused with

Running `bash script.sh` hands the file to bash explicitly and ignores the shebang and the execute bit. Running `./script.sh` executes the file directly, so it needs both the execute bit and a correct shebang. Rule: `./` needs `chmod +x`; `bash file` does not.

## Common mistakes

- **Spaces around `=`.** `name = value` runs `name` as a command. Remove the spaces.
- **Forgetting `chmod +x`.** `./script.sh` then says "Permission denied"; add the execute bit or run it as `bash script.sh`.
- **Unquoted variables.** An empty `$1` in `[ $1 = x ]` breaks the test; always quote: `[ "$1" = x ]`.

## Interview Qs

### What is a shebang and why is the first line important?

The shebang is the `#!/bin/bash` on line 1. When you run the file directly with `./script.sh`, the kernel reads this line and starts the named interpreter with the script as its argument. Without it, the file may be run by the wrong shell.

### How do you access arguments passed to a script?

Positional parameters: `$1` is the first argument, `$2` the second, up to `$9` (and `${10}` beyond). `$#` is the number of arguments and `$@` expands to all of them, which is handy for looping over every argument.

### Why do you run a script as ./script.sh and not just script.sh?

A bare name is searched for on `PATH`, which normally does not include the current directory, so the script is not found. `./script.sh` gives an explicit path to the file in the current folder, which also requires the execute bit set by `chmod +x`.
