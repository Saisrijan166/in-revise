## What it is

These commands show a file's contents without changing it. `cat` prints the whole file. `less` opens it one screen at a time so you can scroll and search. `head` shows the first lines and `tail` the last lines. `tail -f` ("follow") keeps the file open and prints new lines as a program writes them, which is how you watch a live log. `wc` counts lines, words and bytes.

## Why it exists

Files range from a five-line config to a multi-gigabyte log. One tool cannot handle both well, so there is a small family. `cat` is quick for short files but floods the screen on a big one. `less` pages through any size. `head` and `tail` answer "what is at the start / end" without reading the middle. `tail -f` exists because developers constantly need to see new log lines the moment they appear, during a deploy or an incident.

## How it works

<Steps label="Reading a log the right way">
<Step title="cat small files">cat config.yaml prints a short file in full.</Step>
<Step title="less for big files">less app.log opens a pager; use arrows, /word to search, q to quit.</Step>
<Step title="head / tail for the ends">head -n 20 app.log shows the top; tail -n 50 app.log shows the recent end.</Step>
<Step title="tail -f for live logs">tail -f app.log streams new lines until you press Ctrl+C.</Step>
</Steps>

- `head` and `tail` default to 10 lines; `-n N` sets the count.
- `less` loads only what it shows, so it opens a huge file instantly.
- `tail -f` does not exit on its own; it waits for more data.

## Example

```bash
tail -n 3 app.log
wc -l app.log
```

```text output
10:15:02 INFO  started
10:15:04 WARN  slow query 1.2s
10:15:05 ERROR payment failed id=42
   317 app.log
```

What to notice:

- `tail -n 3` showed only the recent end of the log, which is usually where the latest error is.
- `wc -l` reported 317 lines. Running `tail -f app.log` instead would print those last lines and then keep streaming each new line the service writes.

## Rules and defaults

- **`head` / `tail` default to 10 lines;** change it with `-n N`.
- **`cat` reads the whole file** into the pipeline; avoid it on very large files, use `less`.
- **`less` is a pager,** not a dump: `q` quits, `/` searches, `G` jumps to the end.
- **`tail -f` keeps running** until interrupted with Ctrl+C; good for watching logs during a deploy.

## Not to be confused with

`cat` prints the whole file and returns to the prompt; `less` opens the file in a scrollable pager you quit with `q`. Rule: `cat` for small files or to feed a [pipe](term:pipe), `less` to read a large file comfortably.

## Common mistakes

- **`cat` on a huge log** that scrolls past uselessly; use `less` or `tail`.
- **Forgetting `tail -f` does not stop.** Press Ctrl+C to get your prompt back.
- **Using `less` to read a live log once** and missing new lines; `tail -f` streams them.

## Interview Qs

### How do you watch a log file in real time?

With `tail -f logfile`. It prints the last lines and then keeps streaming each new line the program writes, so you see errors as they happen. Stop it with Ctrl+C. `tail -F` also handles the file being rotated.

### What is the difference between cat and less?

`cat` prints the entire file to the screen at once and exits, which is fine for small files. `less` opens the file in a scrollable pager so you can move, search with `/`, and quit with `q`; it is the right choice for large files.

### How do you see the first or last few lines of a file?

`head` shows the first 10 lines and `tail` the last 10. Use `-n N` to change the count, for example `head -n 5 file` or `tail -n 50 file`.
