## What it is

Linux runs code in two separated worlds. Kernel space is privileged: the kernel runs there and can reach all memory and the hardware. User space is where ordinary programs run; they cannot touch hardware or another program's memory directly. A system call is the controlled request a user-space program makes to ask the kernel to do privileged work on its behalf.

## Why it exists

If every program could touch any memory or device, one bug could overwrite another program or crash the whole machine, and any program could read your private data. Splitting kernel space from user space puts a hardware-enforced wall between them. Programs get things done only by asking the kernel through system calls, so the kernel stays the single, checked gatekeeper for everything dangerous.

## How it works

<Steps>
<Step title="Program needs the kernel">Your code calls something like read(); the C library issues the matching system call.</Step>
<Step title="Switch to kernel mode">The CPU switches from user mode to kernel mode and jumps to the kernel's handler.</Step>
<Step title="Kernel does the work">The kernel checks the request, drives the hardware, and prepares the result.</Step>
<Step title="Switch back">The CPU returns to user mode and your program continues with the result.</Step>
</Steps>

1. The mode switch is what makes a system call different from a normal function call.
2. The kernel validates every request, so a bad argument fails safely instead of crashing the system.

## Rules and defaults

- User-space programs cannot run privileged CPU instructions or address hardware; attempting it is blocked.
- Every file, network and memory operation ultimately goes through a system call.
- A system call costs more than a plain function call because of the mode switch; heavy syscall use can slow a program.

## Not to be confused with

A library function such as printf runs inside your own program in user space; a system call such as write crosses into the kernel. Rule: library calls may stay in user space, but anything touching hardware or the OS ends in a system call.

## Common mistakes

- Believing open() or read() are plain functions; they wrap a system call and a mode switch.
- Thinking user programs can reach hardware if written cleverly; the CPU blocks it regardless.

## Interview Qs

### What is the difference between kernel space and user space?

Kernel space is privileged and can access hardware and all memory; the kernel runs there. User space is restricted, where normal programs run without hardware access. The split isolates programs so one cannot crash the system or read another's memory.

### What is a system call?

A system call is how a user-space program asks the kernel to do privileged work, such as reading a file or sending network data. It switches the CPU into kernel mode, runs kernel code, and returns. Examples are open, read, write and fork.

### Why is a system call slower than a normal function call?

Because it switches the CPU from user mode to kernel mode and back, and the kernel validates the request. A normal function call stays inside your program with no mode switch, so it is much cheaper.
