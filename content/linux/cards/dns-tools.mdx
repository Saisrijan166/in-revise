## What it is

[DNS](term:dns) turns a name like example.com into an IP address. `dig` and `nslookup` are the two commands that ask DNS directly and print the answer, so you can see what a name resolves to and which record it comes from. `/etc/hosts` is a small local file that maps names to IPs on this one machine. Because the system checks `/etc/hosts` before DNS, any name listed there is resolved locally, without a DNS query.

## Why it exists

Before any connection, a name must become an IP. When a site is unreachable or points to the wrong server, you need to know whether the name resolves at all and to what. `dig` and `nslookup` let you ask that question on its own, separating a DNS problem from a routing or service problem. `/etc/hosts` lets you override a name locally, for testing or for machines without DNS entries.

## How it works

<Steps>
<Step title="Check the local file first">
The resolver reads `/etc/hosts`. If the name is there, it uses that IP and stops.
</Step>
<Step title="Ask DNS">
If not, it queries the DNS servers in `/etc/resolv.conf` and gets back the record.
</Step>
<Step title="Inspect with dig">
`dig name` shows the answer, the record type (A for IPv4, AAAA for IPv6) and the TTL.
</Step>
</Steps>

1. The order of sources comes from `nsswitch.conf`; the default `hosts: files dns` means files (hosts) first, then DNS.
2. `/etc/hosts` wins for the names it lists, so it silently overrides DNS for them.
3. `dig +short` prints just the IP; the full output shows the record and how long it may be cached.

## Example

```bash
dig +short example.com
```

```text output
93.184.215.14
```

What to notice: `+short` strips the output down to the resolved IP, which is what you usually want. Without it, `dig` prints the full answer section, including the `A` record and its TTL (how many seconds resolvers may cache it). If this returns nothing, DNS resolution itself is failing.

## Rules and defaults

- **Lookup order:** `nsswitch.conf` sets it; the default `hosts: files dns` checks `/etc/hosts` before DNS.
- **/etc/hosts format:** one line per entry, `IP  name  [aliases]`; no server or network is involved.
- **dig vs nslookup:** `dig` gives detailed, scriptable output (`+short` for just the IP); `nslookup` is simpler and interactive.
- **Record types:** `A` maps a name to IPv4, `AAAA` to IPv6, `CNAME` is an alias to another name.

## Common mistakes

- **Forgetting /etc/hosts is checked first.** A leftover test entry overrides correct DNS and sends a name to the wrong IP, with no DNS error to hint at it.
- **Concluding the service is down when dig returns an IP.** A successful lookup proves only that the name resolves; the failure is then in routing, a firewall, or the service.

## Interview Qs

### How do you check what a domain name resolves to?

`dig +short example.com` prints the IP; the full `dig example.com` shows the record type and TTL. `nslookup example.com` does the same more simply. If the lookup returns nothing, DNS resolution itself is the problem.

### What is /etc/hosts and when does it win over DNS?

A local file mapping names to IPs on one machine. The default lookup order `hosts: files dns` checks it before DNS, so any name listed there is resolved locally and overrides the DNS record. It is handy for testing but a common cause of stale resolutions.

### A name resolves to the wrong IP. Where do you look first?

`/etc/hosts`, because it is checked before DNS and silently overrides it. A forgotten test entry there is a frequent cause. If hosts is clean, use `dig` to see what the DNS server actually returns.
