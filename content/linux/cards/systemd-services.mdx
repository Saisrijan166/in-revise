## What it is

A service is a background program ([daemon](term:daemon)) like a web server or a database. On most Linux systems these are managed by [systemd](term:systemd), the system and service manager. The kernel starts systemd first, as process number 1 ([PID](term:pid) 1), and systemd starts and supervises everything else. You control services with the `systemctl` command. Each service is described by a small text file called a `.service` unit.

## Why it exists

A daemon needs to be started at boot, restarted if it dies, stopped cleanly, and have its status checked, in the same way every time. Doing that with hand-written startup scripts was inconsistent across machines. systemd gives one tool, `systemctl`, and one file format, the unit, for every service, so starting nginx and starting a database look identical and behave predictably.

## How it works

<Compare id="start-vs-enable" />

1. The kernel boots and starts systemd as PID 1.
2. systemd reads unit files (for example `/usr/lib/systemd/system/nginx.service`) that say how to run each service.
3. `systemctl start <svc>` runs the service now; `stop` stops it; `restart` stops then starts it.
4. `systemctl enable <svc>` creates a symlink so systemd starts the service at the next boot; `disable` removes it. Neither changes the running state right now.
5. `systemctl status <svc>` reports whether it is running, whether it is enabled, and its last few log lines.

## Example

Enable and start nginx in one step, then check it:

```bash
sudo systemctl enable --now nginx
systemctl status nginx
```

```text output
Created symlink /etc/systemd/system/multi-user.target.wants/nginx.service → /usr/lib/systemd/system/nginx.service.
● nginx.service - A high performance web server and a reverse proxy server
     Loaded: loaded (/usr/lib/systemd/system/nginx.service; enabled; preset: enabled)
     Active: active (running) since Mon 2026-11-02 09:15:04 UTC; 2s ago
```

What to notice:

- `enable --now` did two things: it created the boot symlink (so it starts at boot) and started the service now.
- In `status`, `enabled` is the boot setting and `active (running)` is the live state. The two are separate, which is exactly why `start` alone does not survive a reboot.

## Rules and defaults

| Command | Acts now | Changes boot behaviour |
|---|---|---|
| `systemctl start` / `stop` | Yes | No |
| `systemctl restart` | Yes (stop then start) | No |
| `systemctl enable` / `disable` | No | Yes |
| `systemctl enable --now` | Yes (starts it) | Yes |
| `systemctl status` | Reads only | Reads only |

- **sudo:** start, stop, enable and disable change the system, so they need [sudo](term:sudo). `status` is read-only and does not.
- **reload:** `systemctl reload <svc>` asks a service to re-read its config without a full restart, if the service supports it.

## Not to be confused with

`restart` versus `reload`: `restart` stops the service and starts it again, dropping current connections for a moment; `reload` asks it to re-read its configuration while still running, if it supports that. Rule: use `reload` for a config change when you can, and `restart` when the service cannot reload or must truly restart.

## Common mistakes

- **Using `start` and expecting it to persist.** Boot startup needs `enable`.
- **Running `status` with sudo to "make it work".** `status` is read-only; it needs no privileges.
- **Thinking `disable` stops a running service.** It only changes the boot setting; use `stop` (or `disable --now`) to stop it now.

## Interview Qs

### What is systemd?

systemd is the system and service manager on most modern Linux distributions. The kernel starts it first, as PID 1, and it then starts and supervises all other services, which are described by unit files. You manage those services with the `systemctl` command.

### What is the difference between systemctl start and systemctl enable?

`start` runs the service now, in the current system, and has no effect after a reboot. `enable` sets the service to start automatically at every boot but does not start it now. A server service usually needs both, which `enable --now` does in one step.

### How do you check if a service is running and set to start at boot?

`systemctl status <service>`. Its output shows `active (running)` if it is running now, and `enabled` or `disabled` for whether it starts at boot, along with the last few log lines from the journal.
