## What it is

A link gives a file more than one name. Every file's real data is tracked by an [inode](term:inode), a number the filesystem uses internally. A hard link is a second directory name pointing at the very same inode, so both names are equal and open the same data. A symbolic link (symlink) is instead a small separate file whose only content is a path to another file, like a shortcut that says "go look over there".

## Why it exists

Sometimes you want one file reachable under two names or in two places without copying it, which wastes space and drifts out of sync. Links solve this. Hard links were the original way, but they cannot span disks or point at folders. Symbolic links were added to lift those limits: they can cross filesystems and point to directories, which is why deployments use a `current` symlink that you flip to the new release folder.

## How it works

<Compare id="hard-vs-symbolic-link" />

1. `ln target name` makes a hard link: `name` now points at the same inode as `target`. The file's link count rises by one.
2. The data is freed only when the link count reaches zero, that is, when the last name is removed.
3. `ln -s target name` makes a symlink: `name` is a tiny file storing the text path `target`.
4. Reading the symlink follows that path. If `target` is moved or deleted, the path no longer resolves and the symlink "dangles".

## Analogy

<Analogy title="Two kinds of address" limit="A real person can move house; file data does not, so a hard link never goes stale the way a forwarding note can.">
A hard link is like two people legally sharing one house, both full owners. A symlink is like a sticky note on a door saying "they live at number 12". Move the house and the note is wrong, but a co-owner still owns wherever the house is.
</Analogy>

## Example

```bash
echo hi > data.txt
ln data.txt hardname        # second name, same inode
ln -s data.txt softlink     # a path pointer
ls -li data.txt hardname softlink
```

```text output
1310721 -rw-r--r-- 2 anita anita 3 Nov  2 data.txt
1310721 -rw-r--r-- 2 anita anita 3 Nov  2 hardname
1310999 lrwxrwxrwx 1 anita anita 8 Nov  2 softlink -> data.txt
```

What to notice:

- `data.txt` and `hardname` share inode `1310721` and show link count `2`: they are the same data. Deleting `data.txt` leaves `hardname` working.
- `softlink` has its own inode and type `l`, and `-> data.txt` shows the path it stores. Delete `data.txt` and `softlink` breaks.

## Rules and defaults

- **Hard link limits:** cannot cross filesystems and cannot link a directory.
- **Symlink strengths:** can cross filesystems and point at directories.
- **Symlink weakness:** stores a path, so it breaks if the target is moved or deleted (a "dangling" link).
- **Create with:** `ln target name` for hard, `ln -s target name` for symbolic.

## Common mistakes

- **Thinking removing the target kills a hard link.** The data survives until the last hard link is gone.
- **Making a hard link across disks or to a folder.** Not allowed; use a symlink.
- **Using a relative symlink then moving it.** The stored path is read from the symlink's own location, so it can break.

## Interview Qs

### What is the difference between a hard link and a symbolic link?

A hard link is another name for the same inode (the real data), so the data lives until the last link is removed, but it cannot cross filesystems or link directories. A symbolic link is a small file holding a path to a target; it can cross filesystems and point to directories, but breaks if the target moves.

### What happens to a symlink if you delete its target?

The symlink becomes a dangling (broken) link. It still exists and still stores the old path, but following it fails with "No such file or directory", because the target it pointed to is gone.
