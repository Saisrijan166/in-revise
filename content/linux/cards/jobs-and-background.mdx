## What it is

A job is the shell's handle for a command or pipeline it started, numbered `%1`, `%2` and so on. Running a command with `&` at the end starts it in the background, so the shell returns your prompt instead of waiting. Ctrl+Z suspends the job in the foreground. The shell keeps a job table, and jobs, bg and fg let you list and move jobs between foreground, background and suspended.

## Why it exists

You often want to start a long task and keep using the same terminal: build in the background while you edit, or run a server and get the prompt back. Job control gives you that without a second terminal. And when you log out, the shell sends its children SIGHUP, which would stop them; nohup and disown exist so an important job can keep running after you leave.

## How it works

<Compare id="background-vs-nohup" />

1. `command &` starts the command in the background; the shell prints its job number and PID and returns the prompt.
2. On a foreground command, Ctrl+Z sends SIGTSTP, which suspends (stops) it; `jobs` then shows it as Stopped.
3. `bg %1` resumes job 1 in the background; `fg %1` brings it to the foreground.
4. On logout the shell sends SIGHUP to its jobs; `nohup command &` ignores SIGHUP and logs to nohup.out, and `disown` drops the job from the table so no SIGHUP is sent.

## Example

```bash
sleep 300 &
jobs
```

```text output
[1] 5123
[1]+  Running                 sleep 300 &
```

What to notice:

- `[1]` is the job number and 5123 is the PID; `&` returned the prompt immediately.
- `jobs` lists the job as Running in the background; after Ctrl+Z it would read Stopped.
- `fg %1` would bring it to the foreground, where Ctrl+C could stop it.

## Rules and defaults

| Action | Command | Effect |
|---|---|---|
| Background a command | `cmd &` | runs in background, prompt returns |
| Suspend foreground | Ctrl+Z | sends SIGTSTP; job becomes Stopped |
| Resume in background | `bg %1` | continues job 1 without the terminal |
| Bring to foreground | `fg %1` | job 1 takes over the terminal |
| Survive logout | `nohup cmd &` | ignores SIGHUP; output to nohup.out |

- A background job still shares the terminal's output unless you redirect it.
- nohup writes to nohup.out only when output is a terminal and you did not redirect it yourself.
- For anything long-lived, a [systemd service](card:systemd-services) is better than nohup or disown.

## Not to be confused with

Ctrl+Z suspends the foreground job (SIGTSTP) so you can resume it later with fg or bg; Ctrl+C interrupts it (SIGINT), which usually ends it. Rule: Ctrl+Z pauses, Ctrl+C stops.

## Common mistakes

- Assuming `&` alone detaches a job from the shell; it does not — logout can SIGHUP it.
- Forgetting to redirect output, so a background job keeps printing over your prompt.
- Using nohup and `&` for a production service instead of a systemd unit that restarts and logs properly.

## Interview Qs

### What does & do, and does the job survive logout?

`&` runs the command in the background and returns the prompt, but the job stays a child of the shell. On logout the shell sends SIGHUP, which usually stops it. Use nohup, disown, or systemd to keep it running.

### What is the difference between Ctrl+Z and Ctrl+C?

Ctrl+Z sends SIGTSTP and suspends the foreground job, which you can resume with fg or bg. Ctrl+C sends SIGINT and usually stops the job. One pauses, the other interrupts.

### How do you move jobs between foreground and background?

Start with `cmd &`, or suspend a running one with Ctrl+Z. `jobs` lists them with numbers. `bg %1` resumes job 1 in the background; `fg %1` brings it to the foreground.
