## What it is

cron is the service that runs commands automatically at set times. Each user has a crontab, a file of scheduled jobs, which you edit with `crontab -e` and list with `crontab -l`. A crontab line has five time fields followed by the command: minute, hour, day of month, month, and day of week. cron checks the time every minute and runs any line whose five fields match.

## Why it exists

Some work must happen on a clock with nobody watching: a nightly database backup, a log rotation at midnight, a report at 9 AM. Sitting at the terminal to run these by hand is unreliable and does not work while you sleep or are away. cron lets you describe "when" once, and the service runs the command at exactly those times, every time, for as long as the machine is up.

## How it works

| Position | Field | Values |
|---|---|---|
| 1 | minute | 0-59 |
| 2 | hour | 0-23 |
| 3 | day of month | 1-31 |
| 4 | month | 1-12 |
| 5 | day of week | 0-7 (0 and 7 are Sunday) |
| 6 | command | the rest of the line |

1. You add a line with `crontab -e`; it is saved as your personal crontab.
2. Every minute, cron compares the current time against each line's five fields.
3. When all five match, cron runs the command. A `*` in a field matches every value, so it always matches.

## Example

```text
# min hour dom mon dow   command
*    *    *   *   *      echo tick >> /tmp/tick.log
0    9    *   *   *      /home/app/backup.sh
0    2    *   *   1      /home/app/weekly.sh
```

What to notice: the first line has all stars, so it runs every minute. The second runs at 09:00 every day (minute 0, hour 9). The third runs at 02:00 every Monday (day-of-week 1). You add these with `crontab -e` and confirm them with `crontab -l`.

## Rules and defaults

- **A bare number is exact:** `9` in the hour field means 09:00, not "every 9 hours". Use `*/9` for a step.
- **Sunday is 0 or 7:** both values in the day-of-week field mean Sunday.
- **Day-of-month and day-of-week:** if you restrict both (neither is `*`), the job runs when either matches, not only when both do.
- **User vs system crontab:** `crontab -e` edits your own jobs. The system crontab (`/etc/crontab`) adds a username field between the time fields and the command, saying which user to run as.
- **Not for "while logged out" one-offs:** cron is for recurring jobs; for a single long task that must survive logout, use `nohup` or a background job.

## Not to be confused with

cron is the classic time-based scheduler driven by the five-field crontab. systemd timer units (`.timer`) do a similar job the modern, systemd way, with calendar expressions and tie-ins to services and logs. Rule: edit a crontab for quick, portable jobs; reach for a systemd timer when the task is already a systemd service.

## Common mistakes

- **Reading a fixed field as an interval.** `0 */6 * * *` is every 6 hours; `0 6 * * *` is once a day at 06:00.
- **Forgetting cron's limited environment.** cron runs with a minimal `PATH` and no login profile, so use full paths to commands and files.
- **Expecting output on screen.** cron has no terminal; redirect output to a file (`>> job.log 2>&1`) or it is mailed, not shown.

## Interview Qs

### What do the five fields in a cron line mean?

In order: minute (0-59), hour (0-23), day of month (1-31), month (1-12) and day of week (0-7, where 0 and 7 are Sunday). They are followed by the command. A field set to `*` matches every value for that field.

### How do you edit and view your cron jobs?

`crontab -e` opens your crontab in an editor and installs it when you save. `crontab -l` prints your current jobs. Each user has their own crontab, so these act on the jobs of whoever runs the command.

### What is a modern alternative to cron?

systemd timer units (`.timer` files). They schedule the activation of a service using calendar expressions or intervals, and integrate with systemd's service control and journald logs. They are common on current Linux systems alongside, or instead of, cron.
