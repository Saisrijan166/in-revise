## What it is

These four commands answer the first networking questions: what are my addresses, where does my traffic go, is a host reachable, and what lies in between. `ip addr` and `ip route` come from the `ip` tool and read your own machine's setup. `ping` and `traceroute` reach out across the network. They are the starting point for almost every "the service is not reachable" problem.

## Why it exists

When something cannot connect, you need to narrow down where it breaks: your own interface, your route out, the path across the internet, or the remote service. Guessing wastes time. These commands split the problem into layers, so you check each one in order and find the first layer that fails instead of changing things at random.

## How it works

<Steps>
<Step title="See your own setup">
`ip addr` lists interfaces and their IPs; `ip route` shows the routing table and the default gateway.
</Step>
<Step title="Test reachability">
`ping host` sends ICMP echo requests; steady replies mean the host is up and the path works.
</Step>
<Step title="Trace the path">
`traceroute host` shows each router (hop) along the way, so you see where packets stop.
</Step>
</Steps>

1. Start local with `ip addr` and `ip route` to confirm you have an IP and a way out.
2. Use `ping` to check the destination answers at all.
3. If it does not, `traceroute` shows the last hop reached, pointing at where the path breaks.

## Example

```bash
ping -c 3 1.1.1.1
```

```text output
PING 1.1.1.1 (1.1.1.1) 56(84) bytes of data.
64 bytes from 1.1.1.1: icmp_seq=1 ttl=57 time=12.3 ms
64 bytes from 1.1.1.1: icmp_seq=2 ttl=57 time=11.9 ms
3 packets transmitted, 3 received, 0% packet loss
```

What to notice: `-c 3` sends three packets and stops (otherwise `ping` runs until you press Ctrl+C). `0% packet loss` means every echo request got a reply, so the host is reachable over ICMP. The `time` values are the round trip in milliseconds.

## Rules and defaults

- **ping runs forever by default** on Linux; use `-c N` to send a fixed number, or Ctrl+C to stop.
- **ping uses ICMP, not TCP:** it does not test whether a specific service or port is open.
- **traceroute works by TTL:** it sends packets with a rising time-to-live, so each hop in turn reports back; some hops reply `* * *` when they drop the probes.
- **ip replaces ifconfig/route:** the older `ifconfig` and `route` from net-tools are deprecated on modern distros.

## Common mistakes

- **Treating a failed ping as proof the host is down.** ICMP is often blocked by firewalls while the real service is fine. Confirm with the service's actual port.
- **Reading `* * *` in traceroute as a failure.** A hop that hides itself still forwards traffic; only a stall at the final destination is meaningful.

## Interview Qs

### The host does not respond to ping. Is the service down?

Not necessarily. ping tests only ICMP reachability, and many hosts block ICMP at the firewall while still serving traffic. Check the actual service port (for example with `curl` or `ss`) before concluding the host or service is down.

### How do you check your machine's IP address and default gateway?

`ip addr` lists the interfaces and their IP addresses. `ip route` shows the routing table; the `default via <gateway>` line is the gateway used for any traffic leaving the local network.

### What does traceroute show?

Each router (hop) on the path from you to a destination, in order, with the round-trip time to each. It works by sending packets with an increasing time-to-live, so every hop reports back. It helps locate where a connection stalls.
