## What it is

A package manager installs, updates and removes software for you, so you do not build each program from source or hunt for files by hand. A [repository](term:package-manager) is a server that holds ready-made packages. On Debian and Ubuntu the tool is `apt`; on Fedora and RHEL it is `dnf`. You name a package, and the manager downloads it and every other package it depends on.

## Why it exists

Real software needs other software: a web server needs libraries, which need more libraries. Installing all of that by hand means tracking down each piece and the right version, and removing it cleanly later is worse. A package manager keeps a list of what is available, resolves these dependencies automatically, and records what it installed so it can upgrade or remove it as one unit.

## How it works

<Compare id="apt-update-vs-upgrade" />

1. `sudo apt update` contacts the configured repositories and refreshes the local index of what packages and versions exist. It installs nothing.
2. `sudo apt install <pkg>` reads that index, works out the dependencies, and downloads and installs the package and the dependencies together.
3. `sudo apt upgrade` installs newer versions of packages you already have, using the refreshed index.
4. `sudo apt remove <pkg>` deletes the package files but keeps its config; `purge` deletes the config too.
5. `sudo apt autoremove` deletes dependencies that were pulled in automatically and are no longer needed by anything.

## Example

Refresh the index, then install nginx; its dependencies come along automatically:

```bash
sudo apt update
sudo apt install nginx
```

```text output
Hit:1 http://archive.ubuntu.com/ubuntu noble InRelease
Fetched 128 kB in 1s
12 packages can be upgraded. Run 'apt list --upgradable' to see them.
The following additional packages will be installed:
  nginx-common nginx-core libnginx-mod-http-geoip2
0 upgraded, 4 newly installed, 0 to remove.
```

What to notice:

- `update` only reported "12 packages can be upgraded"; it changed nothing installed.
- `install nginx` pulled in three extra packages on its own. That is dependency resolution: you asked for one package, apt worked out the rest.

## Rules and defaults

| Command | What it does | Touches installed software |
|---|---|---|
| `apt update` | Refresh the list of available packages | No |
| `apt upgrade` | Install newer versions of installed packages | Yes |
| `apt install <pkg>` | Install a package and its dependencies | Yes |
| `apt remove <pkg>` | Delete the package, keep its config files | Yes |
| `apt purge <pkg>` | Delete the package and its system config | Yes |
| `apt autoremove` | Delete unneeded auto-installed dependencies | Yes |

- **sudo:** every command that changes installed software needs root, so it is run with [sudo](term:sudo). `apt update` also needs root to write the index cache.
- **Fedora / RHEL:** `dnf install`, `dnf remove`, `dnf upgrade` do the same on RPM-based systems. `dnf` refreshes metadata on its own, so there is no separate `update` step.

## Not to be confused with

`apt remove` versus `apt purge`: both delete the package, but `remove` leaves its edited config files in `/etc` so you can recover, while `purge` deletes those too. Rule: use `purge` when you want the package gone with no trace of its system config.

## Common mistakes

- **Running `apt upgrade` without `apt update` first.** Upgrade uses the local index; if it is stale, upgrade cannot see the newest versions.
- **Expecting `remove` to clean up config.** It does not; use `purge` for that.
- **Forgetting `autoremove`.** Over time, orphaned dependencies pile up until you clear them.

## Interview Qs

### What is the difference between apt update and apt upgrade?

`apt update` refreshes the local list of available packages and versions from the repositories; it installs nothing. `apt upgrade` then installs the newer versions of packages you already have. You run `update` first so `upgrade` knows what is actually new.

### What is the difference between apt remove and apt purge?

Both remove the installed package. `remove` leaves its modified system config files behind so you can recover from an accidental removal. `purge` deletes those config files as well, leaving no system configuration for the package.

### How do packages get their dependencies on Linux?

The package manager resolves them. When you `apt install` a package, apt reads the dependency list from the index, then downloads and installs the package together with every other package it needs, so you never chase libraries by hand.
