## What it is

When a process finishes, it does not vanish at once: it becomes a zombie (shown as `<defunct>`, STAT `Z`) that keeps only its exit status in the process table until its parent reads it with the wait() system call, which is called reaping. An orphan is the opposite: a process still running whose parent has already ended. A daemon is a long-running background service with no controlling terminal, such as sshd.

## Why it exists

The parent of a process usually wants to know how its child ended, its exit code. So the kernel keeps a finished child as a zombie, holding just the exit status, until the parent collects it. This is by design, not a leak. The catch is a parent that never collects: its zombies pile up and can fill the process table. Orphans and init's adoption exist so a child is never left unreaped when its parent dies first.

## How it works

<Compare id="zombie-vs-orphan" />

1. A child process exits; the kernel keeps a small entry with its exit status and marks it a zombie.
2. The parent calls wait() (or waitpid()), reads the status, and the entry is removed — the zombie is gone.
3. If the parent dies first, the still-running child becomes an orphan and is re-parented to init (PID 1).
4. init automatically calls wait() for the orphans it adopts, so their zombies are always reaped.

## Rules and defaults

- A zombie (STAT `Z`, `<defunct>`) uses no CPU or memory, only a process-table slot; you cannot kill it with a signal.
- The fix for zombies is the parent: make it reap (handle SIGCHLD and call wait()), or restart or end the parent so init adopts its children.
- Orphans are normal and harmless; PID 1 always reaps them.
- A daemon's name conventionally ends in `d` (sshd, crond, systemd); it detaches from the terminal and today usually runs under systemd.

## Not to be confused with

A daemon is a process that detached from any terminal and runs as a system service, usually started by systemd; a background [job](card:jobs-and-background) (`cmd &`) is still attached to your shell and can end when you log out. Rule: a daemon has no terminal; a background job still has one.

## Common mistakes

- Trying to `kill -9` a zombie; it is already dead, so the signal does nothing. Act on the parent instead.
- Thinking zombies consume CPU or memory; they only occupy a process-table entry.
- Treating orphans as a problem; they are normal, and init reaps them.

## Interview Qs

### What is a zombie process and how do you remove it?

A zombie is a finished process whose parent has not yet read its exit status with wait(). It holds a process-table slot but uses no CPU or memory. You cannot kill it; make the parent reap it, or restart or end the parent so init reaps its children.

### What is an orphan process?

An orphan is a process still running after its parent has died. The kernel re-parents it to init (PID 1), which later calls wait() to reap it. Orphans are normal and harmless, unlike a build-up of zombies.

### What is a daemon?

A daemon is a background service that runs without a controlling terminal, usually started at boot and managed by systemd. Its name often ends in `d`, like sshd or crond. It keeps running independently of any user session.
