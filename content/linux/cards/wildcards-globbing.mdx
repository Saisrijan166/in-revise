## What it is

Globbing is the shell's way of matching filenames with short patterns. `*` stands for any run of characters, `?` for exactly one, and `[...]` for one character from a set or range. Brace expansion `{...}` is a related feature that produces a list of strings. The key point is that your [shell](term:shell) (bash) does this matching and replaces the pattern with the real filenames, before the command you typed ever runs.

## Why it exists

Acting on many files by typing each name is tedious and error-prone. Wildcards let you say "every `.log` file" or "files 1 to 9" compactly. Putting the expansion in the shell, not in each command, means every command gets this power for free: `ls *.txt`, `rm *.tmp` and `cp img?.png backup/` all work the same way, because by the time the command runs it simply receives a list of filenames.

## How it works

<Steps label="What happens when you press Enter">
<Step title="You type a pattern">rm *.tmp</Step>
<Step title="The shell expands it">It looks in the current directory and finds a.tmp and b.tmp.</Step>
<Step title="The command runs on the result">rm a.tmp b.tmp actually executes; rm never saw the star.</Step>
</Steps>

- `*` matches any characters but not a leading dot and not `/`, so hidden files and sub-folders are not swept in by accident.
- `?` is one character; `report?.txt` matches `report1.txt` but not `report10.txt`.
- `[a-f]*` matches names starting with `a` to `f`. `{txt,bak}` expands to a list even if no such file exists.

## Example

```bash
ls
echo *.log
echo '*.log'
```

```text output
a.log  b.log  notes.txt
a.log b.log
*.log
```

What to notice:

- `echo *.log` printed `a.log b.log`: the shell expanded the pattern into the matching filenames before `echo` ran.
- `echo '*.log'` printed `*.log` unchanged, because quoting stops expansion. This is why patterns meant for `find` must be quoted, so the pattern reaches the command instead of the shell eating it.

## Rules and defaults

| Pattern | Matches |
|---|---|
| `*` | Any run of characters, including none (not a leading `.`) |
| `?` | Exactly one character |
| `[abc]`, `[a-f]` | One character from the set or range; `[!a]` means "not a" |
| `{txt,bak}` | Brace expansion: a list of strings, not a file match |

- **The shell expands, not the command:** by run time the command sees filenames.
- **No match, bash default:** the pattern is left unchanged and passed literally, which can surprise a command.
- **Quoting disables it:** `'*.log'` or `\*` is kept literal; use this to send a pattern to `find` or `grep`.
- **Braces are different:** `{a,b}` is a plain list and does not need matching files to exist.

## Common mistakes

- **Not quoting a pattern meant for `find`.** The shell expands it first; quote it as `'*.java'`.
- **Expecting `*` to include hidden files.** It skips names starting with `.`; match them explicitly.
- **Confusing `{a,b}` with `[ab]`.** Braces build a list of words; brackets match one character.

## Interview Qs

### Who expands wildcards, the shell or the command?

The shell. It replaces a pattern like `*.log` with the list of matching filenames before the command runs, so commands such as `ls`, `rm` and `cp` only ever receive filenames. This is why quoting a pattern passes it through unexpanded.

### What is the difference between *, ? and [...] in globbing?

`*` matches any run of characters (including none), `?` matches exactly one character, and `[...]` matches one character from a set or range, such as `[0-9]` or `[a-f]`. None of them match a `/` or a leading dot by default.
