## What it is

These are the words every networking question starts from. An IP address is the number that identifies a network interface, so it tells the network which machine to reach. A port is a number that identifies one service on that machine. A socket is the two put together: one IP address plus one port. DNS is the system that turns a name, like example.com, into an IP address. localhost is a name for your own machine.

## Why it exists

One machine runs many services at once: a web server, a database, a cache. They all share the same IP address, so the IP alone cannot say which one you want. Ports solve this by giving each service its own number. And people cannot remember IP addresses, so DNS lets you type a name and have it resolved to the current IP. Without these, every connection would need a raw number and could reach only one service per machine.

## How it works

| Term | What it identifies | Example |
|---|---|---|
| IP address | A machine (network interface) | `192.168.1.10` |
| Port | One service on that machine | `80` (web), `5432` (Postgres) |
| Socket | One endpoint: IP + port | `192.168.1.10:80` |
| DNS | Name turned into an IP | `example.com` -> `93.184.x.x` |
| localhost | Your own machine | `127.0.0.1` |

1. You type a name, so DNS resolves it to an IP address.
2. You pick a port, usually the service's standard one (80 for HTTP).
3. The IP and port form a socket; a connection links your socket to the server's socket.

## Example

```bash
getent hosts localhost
```

```text output
127.0.0.1       localhost
```

What to notice: `localhost` is just a name that resolves to the loopback address `127.0.0.1`, which always means "this machine". Traffic to it never leaves your computer, so a server bound only to localhost cannot be reached from another machine.

## Rules and defaults

- **Ports 0-1023 are privileged** (IANA System Ports): opening a listener on them needs root. Ports 1024-49151 are user ports anyone can use.
- **localhost = 127.0.0.1** for IPv4 (and `::1` for IPv6); this is fixed by the protocol and should not be changed.
- **A socket is unique per connection:** the four values source IP, source port, destination IP and destination port together identify one connection.

## Common mistakes

- **Thinking the IP alone reaches a service.** You also need the port. The IP finds the machine; the port picks the service.
- **Binding to localhost and expecting remote access.** A service bound to `127.0.0.1` is reachable only from the same machine; bind to `0.0.0.0` to accept outside connections.

## Interview Qs

### What is the difference between an IP address and a port?

An IP address identifies a machine (network interface) on the network. A port identifies one service on that machine. The IP gets you to the right computer; the port picks which of its many services you talk to.

### What is a socket?

A socket is one communication endpoint: an IP address plus a port, like `192.168.1.10:80`. A connection joins two sockets, one on each side. The combination of both sockets uniquely identifies a single connection.

### What does localhost mean?

localhost is a name for your own machine. It resolves to the loopback address `127.0.0.1` (or `::1` for IPv6). Traffic to it stays on the same computer and never touches the network.
