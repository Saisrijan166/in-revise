## What it is

`grep` is a command that searches text for a pattern. You give it a pattern and one or more files; it reads each line and prints the lines that match. The pattern is a [regular expression](term:regex) (regex), a small language for describing text: plain words match themselves, while characters like `.`, `*` and `[ ]` have special meaning. grep is the main way to find something inside logs and source files from the command line.

## Why it exists

Log files and source trees are too big to read by eye. When a service fails, you need the three lines that say `ERROR` out of a million lines, and you need them in a second. Opening the file in an editor and scrolling does not scale. grep answers one question fast: which lines match this pattern? It also reads from a [pipe](card:pipes-and-redirection), so you can filter the output of any other command.

## How it works

<Compare id="find-vs-grep" />

1. grep takes a pattern and some input: file names you list, or text piped into it.
2. It reads the input one line at a time.
3. For each line it tests the pattern. By default the pattern is a basic regular expression and the test is case-sensitive.
4. It prints the lines that match. With `-v` it prints the lines that do not match.
5. The exit status is `0` if any line matched, `1` if none matched, `2` on an error, which lets scripts test "was it found?".

## Example

Find error lines in a log, ignoring case and showing line numbers:

```bash
grep -in "error" app.log
```

```text output
12:2026-11-02 Payment ERROR: card declined
87:2026-11-02 error: retry limit reached
```

What to notice:

- `-i` made lowercase `error` match the uppercase `ERROR` on line 12.
- `-n` added the line number before each match, so you can jump straight to it.
- Searching a whole project instead of one file is `grep -rn "error" .`; the `.` means the current directory and `-r` walks into every subfolder.

## Rules and defaults

| What | Default | Note |
|---|---|---|
| Case | Case-sensitive | `-i` ignores case |
| Pattern type | Basic regex (BRE) | `-E` switches to extended regex (`+ ? |` work plainly) |
| Scope | The files you name | `-r` searches a directory tree |
| Exit status | 0 found, 1 not found, 2 error | used in scripts and `if` |

- A pattern with special characters should be in single quotes so the shell does not change it first: `grep 'ab.*cd' file`.
- `-r` follows only the directories; `-l` prints just the file names, `-c` prints a count per file.
- grep reads piped input, so `ps aux | grep java` filters another command's output.

## Common mistakes

- **Forgetting case.** `grep error` misses `ERROR`. Use `-i` when case does not matter.
- **Leaving a regex unquoted.** `grep *.log file` lets the shell expand `*.log` first; quote the pattern.
- **Expecting grep to find files by name.** That is `find`. grep looks inside files.

## Interview Qs

### What does grep do and where does the name come from?

grep searches input line by line and prints the lines matching a pattern or regular expression. The name comes from the old `ed` editor command `g/re/p`: globally search for a regular expression and print the matching lines.

### How do you search every file in a project for a word, case-insensitively, with line numbers?

`grep -rin "word" .` The `-r` walks the directory tree from the current folder, `-i` ignores case, and `-n` prints the line number before each match. Add `-l` instead if you only want the file names.

### What is the difference between grep and find?

grep searches the text inside files and prints matching lines; find searches for files themselves by name, type, size or time. They pair well: `find` locates the files and `grep` searches their contents.
