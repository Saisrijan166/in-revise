## What it is

A path is the address of a file in the [filesystem tree](card:filesystem-hierarchy). An absolute path starts at the root `/` and spells out the full route, so it names the same file from any directory. A relative path starts from your current directory. Four symbols help: `.` means the current directory, `..` the parent, `~` your home directory, and `-` (with `cd`) the directory you were in before.

## Why it exists

Typing the full path every time is slow when you are already deep in a folder, so relative paths and shortcuts save effort. But short paths are fragile: their meaning depends on where you are standing. Knowing both lets you type quickly by hand yet write robust scripts. A script or [cron](term:cron) job runs from a directory you did not choose, so it needs absolute paths to find its files reliably.

## How it works

<Compare id="absolute-vs-relative-path" />

1. An absolute path begins with `/`. The shell follows it from the root, so `/var/log/syslog` is the same file everywhere.
2. A relative path has no leading `/`. The shell joins it to your current directory. From `/home/anita`, `projects/app` means `/home/anita/projects/app`.
3. `.` is here and `..` is up one level, so `../shared/data` leaves the current folder and enters a sibling.
4. `~` expands to your home directory, and `cd -` returns to the previous directory (and prints it).

## Example

```bash
pwd
cd /var/log      # absolute: works from anywhere
cd ..            # relative: go up to /var
cd -             # jump back to /var/log
```

```text output
/home/anita
/var/log
```

What to notice:

- `cd /var/log` uses an absolute path, so it lands there no matter where you started.
- `cd ..` is relative: from `/var/log` it goes to `/var`. `cd -` then returns to `/var/log` and prints that directory, which is handy for hopping between two places.

## Rules and defaults

- **Leading `/` decides it:** a path that starts with `/` is absolute; anything else is relative to the current directory.
- **`~` is home:** `~` and a bare `cd` both go to your home directory; `~anita` is another user's home.
- **`cd -` uses `$OLDPWD`:** it switches to the directory you were last in and prints its name.
- **Scripts and cron:** prefer absolute paths, because the working directory there is not the one you tested in.

## Common mistakes

- **Using a relative path in cron or a systemd unit.** It resolves from the wrong directory and fails; use the absolute path.
- **Thinking `~` works everywhere.** The shell expands `~`; inside single quotes or some config files it stays a literal tilde.

## Interview Qs

### What is the difference between an absolute and a relative path?

An absolute path starts from the root `/` and names the same file from any directory, like `/etc/hosts`. A relative path starts from your current directory, like `../logs/app.log`, so its meaning changes as you move around with `cd`.

### What do . .. ~ and - mean in a path?

`.` is the current directory, `..` is the parent directory, `~` is your home directory, and `-` with `cd` is the directory you were in before. So `cd ..` goes up one level and `cd -` jumps back to the previous one.
