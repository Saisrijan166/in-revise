## What it is

A user is an account the system recognises, identified by a numeric user ID (UID). A group is a named bundle of users, identified by a group ID (GID), used so several users can share access to files. Linux checks file [permissions](card:file-permissions) against your UID and your group memberships. Accounts and groups are defined in a few plain-text files under `/etc`.

## Why it exists

One machine serves many people and services, and each needs its own private space and its own level of trust. Numbers, not names, make this cheap: the kernel compares UIDs and GIDs on every access. Groups solve a second problem, sharing: instead of granting a file to ten users one by one, you put them in a group and grant the group. The `/etc` files give commands and admins one place to look up these identities.

## How it works

| File | Holds | Who can read |
|---|---|---|
| `/etc/passwd` | one line per account: name, UID, GID, comment, home, shell | everyone |
| `/etc/shadow` | hashed passwords and aging rules | root only |
| `/etc/group` | group name, GID, extra members | everyone |

1. Your login name maps to a UID and a primary GID in `/etc/passwd`.
2. The password field in `/etc/passwd` is just `x`; the real hash lives in `/etc/shadow`, which only root can read.
3. `/etc/group` adds you to supplementary groups beyond your primary one.
4. `id` prints your UID, primary GID and all groups; `whoami` prints just your name.

## Example

```bash
whoami
id
```

```text output
srijan
uid=1001(srijan) gid=1001(srijan) groups=1001(srijan),27(sudo)
```

What to notice:

- `whoami` gives the login name; `id` gives the numbers behind it.
- srijan's primary group is `srijan` (GID 1001) and they are also a supplementary member of `sudo` (GID 27), which is what lets them run [sudo](card:sudo-and-root).

## Rules and defaults

- **Create accounts with root:** `sudo adduser srijan` (Debian/Ubuntu friendly wrapper) or the lower-level `useradd`; set a password with `passwd`.
- **UID 0 is special:** the user with UID 0 is root, the administrator.
- **System vs human users:** many UIDs below 1000 belong to services (like `www-data`), not people.
- **Groups give shared access:** add a user to a group so they inherit the group's file permissions; the change takes effect on their next login.

## Common mistakes

- **Thinking /etc/passwd stores passwords.** It stores account details; the hashes are in the root-only /etc/shadow.
- **Editing these files by hand.** Prefer `adduser`, `usermod` and `passwd`, which keep the files consistent and locked while writing.
- **Confusing primary and supplementary groups.** New files you create get your primary group; supplementary groups only grant access to files already owned by them.

## Interview Qs

### What is the difference between /etc/passwd and /etc/shadow?

`/etc/passwd` holds account details (name, UID, GID, home, shell) and is readable by everyone, because tools need to map UIDs to names. `/etc/shadow` holds the hashed passwords and aging data and is readable only by root, so hashes stay protected.

### What is the difference between a user's primary and supplementary groups?

The primary group (from `/etc/passwd`) is the group given to new files the user creates. Supplementary groups (from `/etc/group`) are extra memberships that grant access to files owned by those groups. A user has exactly one primary group and any number of supplementary ones.

### How do you see which groups you belong to?

Run `id`, which prints your UID, primary GID and every group you are in, or `groups` for just the names. `whoami` prints only your username.
