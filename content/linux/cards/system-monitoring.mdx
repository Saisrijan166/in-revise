## What it is

System monitoring commands answer "is the box healthy?" from the terminal, without any extra tools. The core four are `free` for memory, `df` for disk space per filesystem, `du` for the size of a folder, and `uptime` for how busy the system is. `top` adds a live, refreshing view of processes, and `lsblk` lists the disks. Each reads values the kernel already keeps.

## Why it exists

When a server slows down or a deploy fails, you need to know fast whether it is out of memory, out of disk, or overloaded. Guessing wastes time. These commands read the kernel's own counters and print a plain answer in one line, so you can tell within seconds which resource is the problem and where to look next.

## How it works

<Compare id="df-vs-du" />

1. `free -h` reads memory figures from the kernel and prints total, used, free and available RAM and swap in human units.
2. `df -h` lists each mounted filesystem with its size, used, available and use%, so you see which disk is full.
3. `du -sh <dir>` walks a folder, adds up the file sizes, and prints one human-readable total.
4. `uptime` prints how long the system has run and the load average for the last 1, 5 and 15 minutes.
5. `top` refreshes a few times a second to show the busiest processes; `lsblk` shows the disks and partitions as a tree.

## Example

Check memory, disk and load in three quick commands:

```bash
free -h
df -h /
uptime
```

```text output
               total        used        free      shared  buff/cache   available
Mem:            15Gi       6.2Gi       1.1Gi       0.3Gi       8.0Gi       8.4Gi
Filesystem      Size  Used Avail Use% Mounted on
/dev/nvme0n1p2  457G  180G  254G  42% /
 09:15:04 up 12 days,  3:22,  2 users,  load average: 0.84, 0.63, 0.55
```

What to notice:

- In `free -h`, read the **available** column, not **free**: available (8.4Gi) counts cache the system can reclaim, so it is the true headroom for new programs. `free` (1.1Gi) looks alarmingly low but is normal, because Linux uses spare RAM as cache.
- `df -h /` shows the root filesystem 42% used, so disk is fine here.
- The three load numbers (0.84, 0.63, 0.55) are the 1, 5 and 15-minute averages. They are falling, so the load spike is easing.

## Rules and defaults

| Command | Shows | Common form |
|---|---|---|
| `free` | Memory and swap used / available | `free -h` |
| `df` | Disk space per filesystem | `df -h` |
| `du` | Size of a folder or files | `du -sh <dir>` |
| `uptime` | Uptime and 1/5/15-min load | `uptime` |
| `top` | Live processes, CPU, memory | `top` (q to quit) |
| `lsblk` | Block devices as a tree | `lsblk` |

- **`-h` everywhere:** `free`, `df` and `du` all take `-h` to print human-readable units (Ki, Mi, Gi) instead of raw blocks.
- **Load average is a count:** it is the number of processes running or waiting (for CPU or I/O), averaged over the three windows. Read it against the number of CPU cores, not as a percentage.
- **free's `available`:** this is the estimate of memory available for new programs, which is more useful than the `free` column because Linux deliberately fills spare RAM with cache.

## Not to be confused with

Load average versus CPU usage: `top` shows CPU usage as a percentage of capacity right now, while `uptime`'s load average is a count of processes running or waiting, averaged over 1, 5 and 15 minutes. Rule: compare load to the core count (load 4 on 4 cores is full), and use the percentage from `top` for an instant snapshot.

## Common mistakes

- **Panicking at a low `free` value.** Linux uses free RAM as cache; the `available` column is the real headroom.
- **Reading load average as a percentage.** It is a process count; 2.0 on a 4-core machine means the box is half busy, not overloaded.
- **Running `du` on `/` to find free space.** `du` walks every file and is slow; use `df` for free space and `du` only on a suspect folder.

## Interview Qs

### What is the difference between df and du?

`df` reports free and used space per mounted filesystem, so it tells you whether a disk is full. `du` adds up the size of files under a path, so it tells you what is using the space. You run `df` first to spot the full disk, then `du` to find the big folder.

### What does the load average mean?

It is the number of processes running or waiting (for CPU or for I/O), averaged over the last 1, 5 and 15 minutes, shown by `uptime` and `top`. It is a count, not a percentage, so you compare it to the number of CPU cores: load 4 on a 4-core machine means fully busy.

### How do you check available memory on Linux?

`free -h`. Read the `available` column, not `free`: `available` estimates the memory that is usable for new programs, counting cache that the kernel can reclaim. A low `free` value is normal because Linux uses spare RAM as cache.
