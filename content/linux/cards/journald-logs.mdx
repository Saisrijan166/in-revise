## What it is

On a [systemd](card:systemd-services) system, services do not each write their own log file. They send their output to the journal, a central log store managed by `systemd-journald`. `journalctl` is the command that reads that store back. It can show every service's logs together, or filter down to one service, the last few lines, a time window, or a live feed.

## Why it exists

With old init systems, each service wrote to its own file somewhere in `/var/log`, so you had to know every file name and format to find anything. The journal collects all service output in one place, with structured fields like the unit name, the time and the priority. That lets one tool, `journalctl`, filter by service or time instead of guessing which file to tail.

## How it works

<Steps label="Reading service logs">
  <Step title="Services log to the journal">systemd-journald collects stdout, stderr and syslog from every unit into one indexed store.</Step>
  <Step title="Pick a service with -u">journalctl -u nginx shows only that unit's entries, newest at the bottom.</Step>
  <Step title="Limit with -n or --since">-n 50 shows the last 50 lines; --since "1 hour ago" shows only the recent window.</Step>
  <Step title="Follow with -f">-f keeps the view open and prints new entries as they arrive, until you press Ctrl-C.</Step>
</Steps>

## Example

Show the last 20 lines for nginx in the past hour, then follow it live:

```bash
journalctl -u nginx -n 20 --since "1 hour ago"
journalctl -u nginx -f
```

```text output
Nov 02 09:14:58 web-01 nginx[812]: 127.0.0.1 - GET /health 200
Nov 02 09:15:03 web-01 nginx[812]: 10.0.0.4 - GET /api/pay 500
Nov 02 09:15:03 web-01 nginx[812]: upstream timed out (110: Connection timed out)
-- No more entries --
```

What to notice:

- `-u nginx` filtered the whole journal down to one service, so unrelated services do not clutter the output.
- `--since "1 hour ago"` accepts plain English times as well as full dates like `"2026-11-02 09:00"`.
- The second command, `-f`, does not stop; it keeps printing new lines as they arrive, which is how you watch a live problem.

## Rules and defaults

| Option | Meaning |
|---|---|
| `-u <unit>` | Logs for one service (repeatable for several) |
| `-n [N]` | Last N entries; default 10 if N is omitted |
| `-f` | Follow: keep printing new entries live |
| `--since` / `--until` | Earliest / latest time to show |
| `-p err` | Only entries at priority error or worse |

- **Permissions:** a normal user sees their own and public logs. Full system logs need [sudo](term:sudo) or membership of the `systemd-journal` group.
- **Persistence:** whether logs survive a reboot depends on configuration; with the default on many systems the journal can be volatile, so do not assume old logs are always there.

## Not to be confused with

`journalctl -u <service>` versus `tail -f /var/log/<service>.log`: both can follow a log live, but they read different places. A systemd service logs to the journal, read with `journalctl`; many such services write no plain file in `/var/log` at all. Rule: for a systemd service use `journalctl -u`, and keep `tail -f` for programs that write their own log file.

## Common mistakes

- **Tailing a file that does not exist.** For a systemd service, the logs are in the journal, not a per-service file.
- **Forgetting `-u`.** Without it, `journalctl` shows every service mixed together.
- **Assuming logs are permanent.** On a volatile journal they are cleared on reboot unless persistent storage is configured.

## Interview Qs

### How do you view the logs of a systemd service?

Use `journalctl -u <service>`. It filters the journal to that one service. Add `-n 50` for the last 50 lines, `-f` to follow live, and `--since "1 hour ago"` to limit it to a recent time window.

### What is the difference between journalctl and tail -f on a log file?

`journalctl` reads systemd's central journal and can filter by service, time or priority. `tail -f` follows a single plain text file. A systemd service logs to the journal and often has no `/var/log` file, so `journalctl -u` is the right tool for it.

### How do you follow a service's logs in real time?

`journalctl -u <service> -f`. The `-f` flag keeps the command running and prints new log entries as they are written, like `tail -f`, until you stop it with Ctrl-C.
