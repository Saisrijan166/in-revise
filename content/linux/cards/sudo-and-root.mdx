## What it is

root is the superuser: the account with [UID](card:users-and-groups) 0 that administers the machine. Ordinary permission checks do not stop it, so it can read, change or delete any file and manage every process. `sudo` ("superuser do") lets a permitted normal user run a single command as root (or another user), authenticating with their own password. `su` ("switch user") instead starts a shell as another user, using that user's password.

## Why it exists

Most work does not need full power, and a mistake made as root can wipe a system. You still need a way to do the few tasks that require it, like installing packages or restarting a system service. Logging in as root for everything is risky and anonymous. `sudo` narrows the risk: it grants root for one command, ties it to a named person through their own password, records it, and avoids handing out the shared root password.

## How it works

<Compare id="su-vs-sudo" />

1. You type `sudo <command>`. sudo checks `/etc/sudoers` to see if you are allowed to run it.
2. If so, sudo asks for *your* password (cached for a few minutes), not root's.
3. sudo runs that one command with root's privileges, then control returns to your normal user.
4. The command and your identity are written to the system log, so the action is auditable.

## Example

```bash
systemctl restart nginx
sudo systemctl restart nginx
```

```text output
Failed to restart nginx.service: Access denied
[sudo] password for srijan:
```

What to notice:

- The first command fails: restarting a service needs root, and your normal user is not allowed.
- `sudo` prompts for `password for srijan`, your own password, not root's, and then runs the restart. The event is logged against srijan.

## Rules and defaults

- **The sudo group:** on Debian/Ubuntu, members of the `sudo` group may run any command as root (on RHEL/Fedora the group is `wheel`).
- **Password caching:** after one successful sudo, your password is remembered for about 15 minutes in that terminal.
- **`sudo -i` / `su -`:** both can give you a root shell; `sudo -i` uses your password and sudoers, `su -` needs root's password.
- **root is not magic for everything:** it bypasses file permission checks, but not kernel features like read-only mounts or SELinux denials.

## Common mistakes

- **Thinking sudo wants the root password.** It wants your own; `su` wants the target user's.
- **Running everyday commands with sudo.** Files you create under sudo end up owned by root and then your normal user cannot edit them.
- **Editing /etc/sudoers with a plain editor.** Use `visudo`, which checks the syntax; a broken sudoers file can lock everyone out of sudo.

## Interview Qs

### What is the difference between sudo and su?

`sudo` runs a single command with elevated rights using your own password, only if `/etc/sudoers` permits, and logs it. `su` switches your whole session to another user's shell using that user's password. sudo is per-command and audited; su is a full shell.

### What makes the root user special?

root has UID 0 and is the system administrator. File permission checks do not restrict it, so it can read, modify and delete any file and manage any process. Because of that power, you avoid using it directly and prefer sudo for individual tasks.

### Why prefer sudo over logging in as root?

sudo grants root for one command, tied to a named user through their own password, and logs it, so actions are attributable and revocable. Logging in as root (or sharing its password) is anonymous, unlogged, and makes a single mistake far more dangerous.
