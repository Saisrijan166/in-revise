## What it is

top and htop show a live, repeatedly refreshing list of processes, sorted by how much CPU or memory they use, plus a summary of system load. pgrep finds processes by name and prints their PIDs, and pkill sends them a signal by name. Together they let you watch what is busy and act on it without copying PIDs by hand.

## Why it exists

ps gives a one-time snapshot, so you cannot watch a CPU spike as it happens or see which process is climbing. top refreshes every few seconds, so you can spot the heavy process live. And typing a PID by hand is slow and error-prone when you just want "the java one", so pgrep and pkill work by name instead.

## How it works

<Steps>
<Step title="Watch">Run top (or htop); the list refreshes every few seconds, heaviest first.</Step>
<Step title="Read the header">The top line shows uptime and the load average over 1, 5 and 15 minutes.</Step>
<Step title="Find by name">pgrep java prints the PIDs of processes named java.</Step>
<Step title="Signal by name">pkill java sends them SIGTERM; add -9 for SIGKILL.</Step>
</Steps>

- htop adds colour, mouse and scrolling, but is usually not installed by default.
- Compare the load average to the CPU core count, not to 100.

## Example

```bash
pgrep -a java
pkill -f app.jar
```

```text output
4821 java -jar app.jar
```

What to notice:

- `pgrep -a java` lists the PID and full command of each java process.
- `pkill -f app.jar` matches the whole command line (`-f`), not just the 15-character name, so it reaches `java -jar app.jar`.
- Without `-f`, pgrep and pkill match only the short process name `java`.

## Rules and defaults

| What | Default | Note |
|---|---|---|
| pkill signal | SIGTERM (15) | add `-9` to force |
| pgrep/pkill match | process name only | name limited to 15 chars |
| `-f` option | matches full command line | needed for `java -jar app.jar` |
| top sort | by %CPU, refreshing | press M to sort by memory |

- top keeps running until you press `q`; htop is an add-on package (`apt install htop`).
- top's %CPU can exceed 100% for a multi-threaded process spread across several cores.

## Not to be confused with

pgrep lists matching PIDs; pkill signals them — same matching, different action. And `pkill java` matches the process name, while `pkill -f java` matches the full command line, so leaving out `-f` can miss a JVM whose name is only `java`. Rule: read with pgrep first, then pkill the same pattern.

## Common mistakes

- Reading load average as a percentage instead of a task count compared to cores.
- `pkill java` missing a process because the real name is truncated or differs; use `pkill -f` on the command line.
- Expecting htop to exist everywhere; it must be installed first.

## Interview Qs

### What is load average?

It is the average number of processes running or waiting (for CPU or for I/O) over the last 1, 5 and 15 minutes. Compare it to the CPU core count: on 4 cores, a load of 4 means fully busy, not overloaded.

### How do you find and kill a process by name?

`pgrep -a java` lists matching PIDs and commands; `pkill java` signals them, sending SIGTERM by default. For a process matched by its arguments, like `java -jar app.jar`, use `pkill -f` to match the full command line.

### What is the difference between ps and top?

ps prints a one-time snapshot and exits. top shows a live view that refreshes every few seconds, so you can watch CPU and memory change and see which process is climbing right now.
