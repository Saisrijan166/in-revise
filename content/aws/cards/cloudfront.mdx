## Why it exists

Far-away users wait for every byte, and each request loads the origin. A nearby cache fixes both.

## How it works

<Mermaid
  alt="A user reaches the nearest edge, which answers hits. On a miss, /static/* goes to a private S3 bucket via OAC and /api/* to the payment API load balancer."
  chart={`flowchart LR
  U[User] --> E[Edge location]
  E -- hit --> U
  E -- "miss: /static/*" --> S3[(S3 bucket, via OAC)]
  E -- "/api/*" --> ALB[Load balancer]
  ALB --> API[Payment API]`}
/>

- [AWS WAF](card:edge-security) attaches to the distribution to filter requests at the edge.

## Example

```json
{
  "Effect": "Allow",
  "Principal": { "Service": "cloudfront.amazonaws.com" },
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::payments-static/*",
  "Condition": { "StringEquals": {
    "AWS:SourceArn": "arn:aws:cloudfront::111122223333:distribution/EDFDVBD6EXAMPLE"
  } }
}
```

## Defaults

| What | Default | Where |
|---|---|---|
| Default TTL (no Cache-Control from origin) | 86,400 s (1 day) | CloudFront, as of 20-10-2026 |
| Maximum TTL | 31,536,000 s (1 year) | CloudFront |
| Free invalidation paths | 1,000 per month per account | CloudFront pricing |

## Interview Qs

### How do you serve private S3 files through CloudFront?

Keep the bucket private, add an OAC to the distribution and allow only that distribution in the bucket policy. For per-user access, add signed URLs or signed cookies.

### You deployed new JavaScript but users still get the old file. What do you do?

Invalidate the path, such as /static/*. Better: put a version or hash in the file name, so each deploy gets a new URL and needs no invalidation.

### Signed URL or signed cookie?

A signed URL protects one file and suits clients without cookies. A signed cookie covers many files, like a video's segments, with unchanged URLs.
