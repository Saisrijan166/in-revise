## What it is

Amazon CloudFront is AWS's content delivery network (CDN): a worldwide set of [edge locations](card:regions-and-azs) that keep cached copies of your content close to users. You create a distribution, which has its own domain name and lists your origins, the places that hold the real content, such as an S3 bucket or a load balancer. A user's request goes to the nearest edge location, which answers from its cache when it can.

## Why it exists

The payment app's JavaScript and the receipts live in Mumbai (`ap-south-1`). A user in London waits for every byte to cross the world, and every request lands on the bucket or the load balancer. With CloudFront, the London edge keeps a copy after the first request, so later London users get it from nearby and the origin serves only the misses. The edge also ends HTTPS, and it is where [AWS WAF](card:edge-security) can filter requests.

## How it works

  U[User] --> E[Nearest edge location]

  E -- "/api/*" --> ALB[Load balancer]
  ALB --> API[Payment API]`}

1. Route 53 points `pay.example.com` at the distribution, so the user's request reaches the nearest edge location.
2. The edge picks a cache behaviour: it compares the path with each behaviour's path pattern, in order, and the first match wins. The default behaviour, `*`, is checked last.
3. The edge looks up the cache key, which by default is the distribution's domain name plus the URL path. On a hit, it answers at once.
4. On a miss, it fetches from that behaviour's origin: `/static/*` from the private S3 bucket, signed with OAC, and `/api/*` from the load balancer.
5. It caches the response for its TTL: the origin's `Cache-Control: max-age` if there is one, otherwise the default TTL. Then it answers the user.

## Example

To keep the static bucket private, its bucket policy allows reads only by the CloudFront service, and only on behalf of one distribution:

```json
{
  "Effect": "Allow",
  "Principal": { "Service": "cloudfront.amazonaws.com" },
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::payments-static/*",
  "Condition": { "StringEquals": {
    "AWS:SourceArn": "arn:aws:cloudfront::111122223333:distribution/EDFDVBD6EXAMPLE"
  } }
}
```

What to notice:

- The `Principal` is the CloudFront service, not a user. OAC makes CloudFront sign each request it sends to the bucket.
- The `AWS:SourceArn` condition allows the read only when CloudFront acts for this one distribution. Without it, the statement would trust CloudFront acting for any distribution, not only yours.
- Only `s3:GetObject` is allowed, so CloudFront can read files but cannot list or change the bucket.
- Users never reach the bucket directly: Block Public Access stays on, and the S3 URL returns Access Denied.

## Rules and defaults

- **TTL settings:** the default TTL of 86,400 s (1 day) applies only when the origin sends no `Cache-Control` or `Expires` header. The maximum TTL, 31,536,000 s (1 year) by default, caps the origin's value. A minimum TTL above 0 keeps files cached even if the origin says `no-cache`.
- **What is cached:** CloudFront always caches responses to GET and HEAD, optionally OPTIONS, and never responses to POST, PUT or DELETE.
- **Certificate Region:** an ACM certificate for your own domain must be created in `us-east-1` (N. Virginia), wherever your origin runs.
- **Invalidation cost:** the first 1,000 invalidation paths each month are free per account, and a wildcard path such as `/static/*` counts as one path (at the time of writing).
- **Behaviour order:** the first matching behaviour decides everything, including whether signed URLs are required.

## Not to be confused with

An S3 pre-signed URL is signed with the AWS credentials of an IAM role or user and goes straight to the bucket. A CloudFront signed URL is signed with a private key whose public key sits in a trusted key group on the distribution, and it goes through the edge cache. Rule: S3 pre-signed URL = straight to the bucket with IAM rights; CloudFront signed URL = through the CDN with your own key pair.

## Interview Qs

### How do you serve private S3 files through CloudFront?

Keep the bucket private with Block Public Access on. Add an Origin Access Control to the distribution, and write a bucket policy that allows `s3:GetObject` only for that distribution. If each user may see only their own files, also require signed URLs or signed cookies on that cache behaviour.

### Signed URL or signed cookie?

A signed URL protects one file and suits clients that cannot use cookies, such as a download link in an email. A signed cookie covers many files at once, such as all segments of a video, and keeps the file URLs unchanged.

### Which TTL does CloudFront use for a file?

If the origin sends `Cache-Control: max-age` or `s-maxage`, or an `Expires` header, CloudFront uses that value, kept between the behaviour's minimum and maximum TTL. If the origin sends none, it uses the default TTL, one day unless you change it.
