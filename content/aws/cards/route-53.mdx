## What it is

Amazon Route 53 is AWS's managed DNS service: it turns a name a user types, like `pay.example.com`, into the address their browser should connect to. Your records live in a hosted zone, which is a container named after your domain. A record can use one of eight routing policies, which decide how Route 53 picks an answer when a resource has more than one possible address or location. The name comes from port 53, the standard DNS port.

## Why it exists

Users type a name, not an IP address, and the IP of a load balancer can change over time. DNS has to turn the name into a current address, but plain DNS only returns a fixed answer. Route 53 adds routing policies and health checks on top, so it can send users to the nearest [Region](card:regions-and-azs), split traffic for a canary release, or steer everyone away from an endpoint that has failed, none of which basic DNS can do.

1. The browser asks a DNS resolver for `pay.example.com`; the resolver may still hold a cached answer from a previous query, for as long as the TTL.
2. If the cache has expired, the resolver asks the Route 53 hosted zone that owns the domain.
3. Route 53 looks at the record's routing policy and any health check, and chooses an answer, for example the healthy primary ALB.
4. If a later health check marks the primary unhealthy, Route 53 starts answering with the standby instead.

So the health check is what turns a plain name into automatic failover.

## Example

A pair of failover alias records points one name at two load balancers, with the health check deciding.

```text
Name            Type   Alias target          Failover   Health check
pay.example.com A      alb-mumbai (ALB)      PRIMARY     hc-mumbai
pay.example.com A      alb-singapore (ALB)   SECONDARY   (none needed)
```

What to notice:

- Both records are type `A` alias records, not CNAMEs, so they can sit at the apex-style name and follow each ALB's changing IPs.
- The primary record carries a health check; while it passes, Route 53 answers only with Mumbai.
- When the health check fails, Route 53 switches to the secondary record, so users move to Singapore without any manual edit.
- Alias records to AWS targets are not charged per query, unlike CNAME records.

## Rules and defaults

- **Alias at the apex:** an alias record can sit at the bare domain (zone apex); a CNAME cannot (Amazon Route 53).
- **Alias TTL:** you cannot set it; Route 53 uses the target's TTL (Amazon Route 53).
- **Query charges:** alias queries to AWS resources are free; CNAME queries are billed.
- **Hosted zone types:** a public hosted zone answers internet queries; a private hosted zone answers only inside the VPCs you associate with it.
- **Changing a live record:** lower the TTL first (for example to 300 s), apply the change, then raise it again, so resolvers pick up the change quickly.

## Interview Qs

### Why an alias record instead of a CNAME for the load balancer?

A CNAME cannot be used at the zone apex, so `example.com` itself cannot be a CNAME, and CNAME queries are charged. An alias record works at the apex, is free for AWS targets, and automatically tracks the load balancer's changing IP addresses.

### Which routing policy would you pick for a canary release?

Weighted routing. You give the old and new stacks weights, for example 90 and 10, so Route 53 sends about 10 percent of traffic to the new version. You then raise the new weight gradually as it proves healthy.

### A record change has not reached some users. What is happening?

Resolvers cache the previous answer until its TTL expires, so they keep returning the old value. Lowering the TTL before the change, then raising it afterwards, limits how long stale answers can persist.
