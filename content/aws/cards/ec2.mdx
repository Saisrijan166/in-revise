## What it is

Amazon EC2 (Elastic Compute Cloud) rents you virtual servers, called instances, by the second. An instance boots from an AMI (Amazon Machine Image), a saved disk image with an operating system and software. Its instance type decides how much CPU, memory and network it gets. You launch it into a [subnet of your VPC](card:vpc-and-subnets) with a [security group](card:security-groups-and-nacls), and from then on the OS, Java and your app are yours to run.

## Why it exists

Before the cloud, running the payment service meant buying a server, waiting weeks for it, and paying for it even when it sat idle. EC2 gives you a server in minutes and stops charging for compute when you stop it. You still get a whole machine: your own OS, root access and long-running processes, which some software needs. The price of that control is that patching the OS and installing the runtime stay your job, as the [shared responsibility model](card:shared-responsibility-model) says.

1. You choose an AMI, for example Amazon Linux 2023, and an instance type such as `m7g.large`.
2. You choose the subnet, which fixes the Availability Zone, and the security groups that filter its traffic.
3. EC2 boots the instance. On the first boot it runs your user data script as root, which can install Java and start the app.
4. While the instance is running you pay per second. Your code can read facts about the instance, such as its ID and role credentials, from the instance metadata service.
5. When you stop it, compute billing ends and the EBS volumes stay. When you terminate it, the instance is gone for good.

So the AMI and the instance type are the two choices that define every instance.

## Example

The payment service's instance installs Java 25 and runs the jar as a service at first boot:

```bash
#!/bin/bash
# EC2 user data (Amazon Linux 2023): runs once, as root, at first boot
yum install -y java-25-amazon-corretto-headless
aws s3 cp s3://payments-artifacts/payment-service.jar /opt/payment-service.jar
cat > /etc/systemd/system/payment.service <<'UNIT'
[Unit]
Description=Payment service
[Service]
ExecStart=/usr/bin/java -jar /opt/payment-service.jar --server.port=8080
Restart=always
[Install]
WantedBy=multi-user.target
UNIT
systemctl enable --now payment.service
```

What to notice:

- The script runs as root, so there is no `sudo`, and `-y` is needed because nobody is there to answer prompts.
- `aws s3 cp` works only if the instance has an IAM role attached (an instance profile); without one the copy fails with a credentials error. You will see roles in [IAM basics](card:iam-basics).
- The systemd unit makes the OS start the app on every boot and restart it if it crashes. Starting it with `nohup` instead would run it only until the next reboot, because user data does not run again.
- If the app never comes up, `/var/log/cloud-init-output.log` on the instance shows what the script printed.

## Rules and defaults

- **Reading an instance type:** `m7g.large` is family m (general purpose), generation 7, option g (Graviton, AWS's Arm processor) and size large. Other families: C for compute, R and X for memory, I and D for local storage, P and G for GPUs.
- **User data:** runs as root at the first boot only, by default; at most 16 KB before base64 encoding (EC2, at the time of writing).
- **Billing:** per second with a one-minute minimum while running; a stopped instance is not billed for compute, but its EBS volumes and Elastic IPs are.
- **Changing the instance type:** only while the instance is stopped.
- **Terminate:** deletes the root EBS volume by default and keeps other EBS volumes (`DeleteOnTermination`).
- **IMDS:** by default an instance accepts both IMDSv1 and IMDSv2; set the token to required so only IMDSv2 works.

## Not to be confused with

Instance store is a disk attached to the physical host: fast and included in the price, but erased on stop, hibernate or terminate. An [EBS volume](card:ebs-and-efs) is a network disk that survives stop and start. Rule: anything you must keep, such as data or logs not yet shipped, goes on EBS or off the instance.

## Common mistakes

- **"I will put access keys in the AMI or the user data."** Anyone who can read the AMI or the instance attributes can read them. Attach an IAM role; the SDK then gets short-lived keys from instance metadata.

## Interview Qs

### What is the difference between stopping and terminating an instance?

Stop shuts it down so you can start it again: EBS volumes and the private IP stay, compute billing ends, and you still pay for EBS. Terminate deletes the instance for good, and its root EBS volume is deleted too by default. Both erase instance store data.

### How does code on EC2 get AWS credentials without stored keys?

Attach an IAM role to the instance through an instance profile. The AWS SDK reads temporary keys for that role from the instance metadata service at 169.254.169.254, and AWS replaces them before they expire. Requiring IMDSv2 adds a session token, which defends against SSRF attacks that try to read those keys.

### How do you choose an instance type for a Spring Boot API?

Start with a general-purpose type, M family, and pick C if the work is CPU-heavy or R if it holds a lot in memory. AWS positions Graviton types (g) as its best price-performance option if your software runs on Arm. Watch CPU and memory in CloudWatch, then resize: stop, change the type, start.
