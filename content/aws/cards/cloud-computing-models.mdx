## What it is

Cloud computing is renting IT resources, such as servers, storage and databases, from a provider like Amazon Web Services (AWS) over the internet. You ask for a server, get it within minutes and pay only while it runs. That server is usually a virtual server: a software computer that shares a physical machine with others. The service models say how much the provider runs for you: IaaS rents you virtual servers, PaaS runs your code, and SaaS gives you a finished application.

## Why it exists

Before the cloud, a company bought its own servers. They took weeks to arrive and had to be sized for the busiest day of the year, so most of them sat idle; if the guess was too low, the site slowed down on that busy day. In the cloud you stop guessing. You run what today's load needs, add servers in minutes when it grows, and hand them back when it falls. A large upfront purchase becomes a bill that follows usage.

## How it works

1. You ask AWS for a server of a chosen size, through its web console or an API call. AWS starts a virtual server on its own hardware within minutes. On AWS this is an EC2 instance, one running virtual server; you will see it in [EC2](card:ec2).
2. AWS meters the server from the moment it runs and bills you for that time. This is pay-as-you-go.
3. When load grows, you either give the server more CPU and memory (vertical scaling) or add more servers and spread the requests across them with a load balancer (horizontal scaling).
4. When load falls, you release the extra servers and their cost stops. Growing and shrinking with load, ideally automatically, is called elasticity. [Auto Scaling groups](card:auto-scaling-groups) do this for you later.

So the key is: capacity follows the load, and the bill follows the capacity.

## Example

The payment service is one Spring Boot JAR. Here is what running it looks like under each service model.

| Model | What you do | What AWS or the vendor does |
|---|---|---|
| IaaS: Amazon EC2 | Choose a virtual server, install Java, patch Linux, copy the JAR and start it | Runs the hardware, network and virtualisation |
| PaaS: AWS Elastic Beanstalk | Upload the JAR | All of the above, plus it creates the EC2 instances, load balancer, scaling and health checks |
| SaaS: a hosted email service | Only use it, for example to answer customer mail | Runs everything, including the application |

What to notice:

- The JAR is the same in the IaaS and PaaS rows. Only the work around it moves from your team to AWS.
- With IaaS, a missed Linux security patch is your team's problem. Who does what is the subject of the [shared responsibility model](card:shared-responsibility-model).
- SaaS is not a way to run your own code. It is software someone else built and runs.

## Rules and defaults

- **Resizing an EC2 instance:** you must stop the instance before you change its instance type, so vertical scaling means downtime for that server.
- **Prefer horizontal:** AWS's reliability advice is to replace one large resource with several small ones, so a single failure takes out only part of the capacity.
- **Stateless servers:** horizontal scaling works only if no request depends on data kept in one server's memory or disk. Keep sessions in a shared store, such as ElastiCache or a database.

## Not to be confused with

Scalability means a system can handle more load when you add resources. Elasticity means resources are added and released as the load changes, ideally without a person doing it. Rule: scalability = can grow; elasticity = grows and shrinks with the load, so you pay only for what it needs.

A service model (IaaS, PaaS, SaaS) says how much the provider runs. A deployment model says where the application runs: all in the cloud, hybrid (cloud connected to your own data centre), or on-premises. Rule: service model = who runs what; deployment model = where it runs.

## Interview Qs

### What is the difference between IaaS, PaaS and SaaS? Give AWS examples.

They differ in how much you manage. IaaS, such as Amazon EC2, rents you virtual servers, and you run the operating system, runtime and app. PaaS, such as AWS Elastic Beanstalk, takes your code and runs the servers, load balancing and scaling. SaaS is a finished application; you manage only your data and users.

### Why would a company move its servers to the cloud?

It pays for what it uses instead of buying hardware up front, and it stops guessing capacity: servers are added in minutes and released when load drops. New resources are ready in minutes, not weeks, the team stops running data centres, and the app can be deployed to other parts of the world quickly.

### Vertical or horizontal scaling: which do you prefer on AWS?

Horizontal, for most web services. A bigger EC2 instance must be stopped to resize, and it is still one machine with a size limit. Several instances behind a load balancer share the load and survive one failure. It needs stateless servers, with sessions in ElastiCache or a database.
