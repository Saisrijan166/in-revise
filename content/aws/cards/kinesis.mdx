## Why it exists

A queue gives each message to one worker, then deletes it. Fraud scoring and dashboards must each read every payment event, in order, sometimes twice.

## How it works

<Compare id="kinesis-data-streams-vs-firehose" />

- The family as of 20-10-2026: Kinesis Data Streams, Amazon Data Firehose (renamed on 09-02-2024) and Managed Service for Apache Flink.
- Consumers: your own app using the Kinesis Client Library, or a Firehose stream.

## Interview Qs

### Kinesis or SQS?

SQS gives each message to one worker, which deletes it. In Kinesis, records stay for the retention period, and many apps read the same stream in shard order and can replay it. Pick Kinesis for event streams and analytics.

### How do you scale a stream?

On-demand mode splits shards for you as traffic grows. In provisioned mode you change the shard count yourself. Either way, pick partition keys with many values so no shard runs hot.
