## What it is

A VPC (Virtual Private Cloud) is your own private network inside one AWS [Region](card:regions-and-azs), kept separate from every other customer's network. You give it an address range in CIDR notation, such as `10.0.0.0/16`, which is the set of private IP addresses your resources can use. A subnet is a smaller slice of that range, and it lives in exactly one [Availability Zone](card:regions-and-azs). A route table is the list of rules that says where traffic leaving a subnet is allowed to go.

## Why it exists

If AWS dropped your servers onto one shared network, anyone's instance could try to reach yours, and you could not control the layout. A VPC gives you a private, isolated network where you choose the address range, split it into public and internal parts, and decide every path. Without this you could not, for example, keep a database unreachable from the internet while still letting your app reach it.

1. You create the VPC with a CIDR block, for example `10.0.0.0/16`, which reserves those addresses for your network.
2. You carve out subnets, one per AZ per tier, each with a smaller range like `10.0.1.0/24`, so one subnet never spans two AZs.
3. You attach a route table to each subnet. A public subnet's table has a route to the internet gateway; a private subnet's table does not.
4. Every route table also has a local route, added automatically, so all subnets in the VPC can already reach each other.

So the route table, not the subnet's name, is what makes a subnet public or private.

## Rules and defaults

- **Subnet is zonal:** each subnet resides entirely in one AZ and cannot span zones (Amazon VPC).
- **CIDR sizes:** a VPC IPv4 block is between `/16` and `/28`; a subnet block is also between `/16` and `/28`. AWS recommends private ranges from RFC 1918.
- **Reserved addresses:** AWS reserves the first four and the last IP in every subnet, so a `/24` has 251 usable, not 256 (Amazon VPC).
- **One route table per subnet:** a subnet uses exactly one route table at a time, but one route table can serve many subnets. A subnet with no explicit table uses the VPC's main route table.
- **Local route:** present in every route table and cannot be deleted.

## Not to be confused with

An isolated subnet has no routes to anywhere outside the VPC, so it cannot reach the internet at all; the database belongs here. A private subnet has no route to an internet gateway but can still reach out through a [NAT gateway](card:internet-and-nat-gateways). Rule: public = route to internet gateway; private = no such route but can go out via NAT; isolated = no route out of the VPC.

## Interview Qs

### What exactly makes a subnet public?

Its route table has a route, usually `0.0.0.0/0`, to an internet gateway. The resource in it also needs a public IP address and security group rules that allow the traffic. Remove the internet gateway route and the same subnet becomes private.

### Why spread subnets across two AZs?

A subnet lives in one AZ and fails with it. Giving each tier a subnet in two or more AZs, behind a load balancer, means one AZ failing does not take the whole application down. This is the core of a highly available design on AWS.

### VPC peering or Transit Gateway?

Peering is a one-to-one link between two VPCs; it is not transitive, and the two CIDR blocks must not overlap. For many VPCs, or to connect on-premises networks, a Transit Gateway acts as a single Regional hub so you do not build a mesh of peerings.
