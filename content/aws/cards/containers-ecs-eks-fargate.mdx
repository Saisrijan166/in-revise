## Why it exists

A container image runs the same everywhere, but someone must place containers, restart failed ones and scale them. ECS and EKS do that on AWS.

## How it works

<Compare id="ecs-vs-eks" />

- ECS pieces: a cluster runs services, a service keeps tasks running, each task starts from a task definition.
- Each task has two roles: [task role vs execution role](compare:task-role-vs-task-execution-role).
- Rolling, blue/green and canary releases: [deployments on AWS](card:deployments-on-aws).

## Interview Qs

### ECS or EKS: which would you pick?

ECS for AWS-only teams: AWS's own API, no control-plane fee, fewer parts. EKS when the team uses Kubernetes: certified Kubernetes with its community tools and plugins, but a per-cluster hourly fee and more to operate.

### What is the difference between a task and a service in ECS?

A task is one running copy of a task definition; it can do a job and stop. A service keeps a desired number of tasks running and replaces failed ones, so it suits a long-running API.
