## Why it exists

Clients need one stable address while servers start, stop and fail. A load balancer hides them and sends traffic only to healthy ones.

## How it works

<Compare id="alb-vs-nlb-vs-gwlb" />

- A request goes listener, rule, target group, healthy target. An ALB needs at least two AZs.
- Cross-zone load balancing spreads traffic over targets in every AZ: on for ALB (a target group can opt out), off by default for NLB.

## Defaults

| What | Default | Where |
|---|---|---|
| Health check | Every 30 s, 5 s timeout, path /, success code 200 | ALB target group, 20-10-2026 |
| Thresholds | 5 passes to become healthy, 2 failures to become unhealthy | ALB target group, 20-10-2026 |
| Deregistration delay | 300 seconds | ALB and NLB target groups, 20-10-2026 |

## Interview Qs

### ALB or NLB for a Spring Boot REST API?

ALB. It works at layer 7, so it can send /payments and /refunds to different target groups, end HTTPS and check an HTTP health path. Pick NLB for raw TCP or UDP, very high throughput, or a fixed IP per AZ.

### Targets keep failing health checks, but the app looks fine. Why?

The check must reach the port and path and get the success code within the timeout. Common causes: the target's security group blocks the load balancer, the path does not exist, or the connection times out.
