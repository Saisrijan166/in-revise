## Why it exists

Scenario questions test quick need-to-service matching. Each row links the concept that explains it.

## How it works

| Need | Pick |
|---|---|
| Traffic spikes | [Auto Scaling](card:auto-scaling-groups) behind a [load balancer](card:elastic-load-balancing) |
| Survive an AZ failure | Every layer in two or more [AZs](card:regions-and-azs) |
| Run the service; code on an event | [ECS, EKS or EC2](card:compute-choice); [Lambda](card:lambda) |
| Images and PDFs; static files near users | [S3](card:s3); [CloudFront](card:cloudfront) |
| Relational data or key lookups | [RDS, Aurora or DynamoDB](card:choosing-a-database) |
| Fast short-lived lookups | [ElastiCache](card:elasticache) |
| Background work; one event to many | [SQS, SNS or EventBridge](compare:sqs-vs-sns-vs-eventbridge-vs-kinesis) |
| A multi-step workflow | [Step Functions](card:step-functions) |
| Secrets; encryption keys | [Secrets Manager](card:secrets-and-parameters); [KMS](card:kms-and-encryption) |
| Reach AWS APIs from private subnets | [VPC endpoints](card:vpc-endpoints-privatelink) |
| Health and alarms; API audit | [CloudWatch](card:cloudwatch); [CloudTrail](card:cloudtrail) |
| Survive losing a Region | [A DR strategy](card:disaster-recovery) |

## Interview Qs

### Traffic jumps tenfold during a sale. What do you do?

Scale tasks on request count per target, cache merchant config in ElastiCache, move slow work to SQS, and watch database connections.

### Which services would you use for a serverless payment API?

[API Gateway](card:api-gateway) in front of Lambda, DynamoDB for payments by id, SQS for receipt jobs, Step Functions for multi-step flows, and CloudWatch with X-Ray to watch it.
