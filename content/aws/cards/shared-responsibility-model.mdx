## Why it exists

In the cloud, AWS runs part of the stack and you run the rest. Without a clear line, each side assumes the other patched or locked it down.

## How it works

| Who does it | EC2 | RDS | Lambda, S3 |
|---|---|---|---|
| Data centre, hardware, host | AWS | AWS | AWS |
| Guest OS patches | You | AWS | AWS |
| Database engine or runtime | You install and patch | AWS patches; you pick version and window | AWS |
| Network and access rules | You: security groups | You: security groups | You: IAM, bucket policies |
| Data, IAM, encryption choices | You | You | You |

- Your tools: [IAM](card:iam-basics), [KMS encryption](card:kms-and-encryption), [security groups](card:security-groups-and-nacls).

## Interview Qs

### Explain the shared responsibility model.

AWS is responsible for security of the cloud: the facilities, hardware, software and network that run its services. The customer secures what is in the cloud: data, IAM, encryption settings, firewall rules and, on EC2, the guest OS and apps.

### Who patches what on EC2, RDS and Lambda?

EC2: you patch the guest OS and software. RDS: AWS supplies OS and engine updates and applies required ones in your maintenance window. Lambda: AWS updates managed runtimes automatically by default; container images you rebuild yourself.
