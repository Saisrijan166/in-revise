## Why it exists

When a bucket policy disappears or a security group opens to the world, you need proof of who did it. Metrics cannot tell you that.

## How it works

<Compare id="cloudwatch-vs-cloudtrail" />

- Two event types matter most: [management](card:ct-management-events) and [data](card:ct-data-events) events.
- "What did this resource look like last week?" is [AWS Config](card:aws-config-recorder), not CloudTrail.

## Example

```bash
# Who deleted the receipts bucket policy?
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=DeleteBucketPolicy
# Read userIdentity, eventTime and sourceIPAddress in each event
```

## Interview Qs

### Someone deleted a bucket policy in production. How do you find out who?

Search CloudTrail event history (or the trail in S3) for the DeleteBucketPolicy event. Its userIdentity, eventTime and sourceIPAddress show who, when and from where.

### CloudTrail vs AWS Config?

CloudTrail records the API calls. AWS Config records how each resource's configuration changed over time and checks it against rules. Use both together.
