## Why it exists

The payment service must put receipt PDFs in S3 and send SQS messages. The SDK signs each request, retries, pools connections and finds credentials, so the code never holds access keys.

## How it works

<Steps label="Default credentials chain: the first source that has credentials wins">
  <Step title="Java system properties">aws.accessKeyId and aws.secretAccessKey</Step>
  <Step title="Environment variables">AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY</Step>
  <Step title="Web identity token">Assumes a role with a token file, as on EKS</Step>
  <Step title="Profile files">~/.aws/credentials and ~/.aws/config, including SSO</Step>
  <Step title="Container credentials">The ECS task role, through the ECS credentials endpoint</Step>
  <Step title="Instance profile">The EC2 instance role, from the instance metadata service</Step>
</Steps>

- Which role each compute type uses: [temporary credentials](card:sts-and-temporary-credentials).

## Example

```java
S3Client s3 = S3Client.builder()                        // build once, reuse everywhere
    .region(Region.AP_SOUTH_1)
    .overrideConfiguration(o -> o
        .apiCallTimeout(Duration.ofSeconds(10))         // whole call, all retries
        .apiCallAttemptTimeout(Duration.ofSeconds(3)))  // one HTTP attempt
    .build();                                           // credentials: default chain

s3.putObject(PutObjectRequest.builder()
        .bucket("payment-receipts").key("receipts/" + paymentId + ".pdf")
        .contentType("application/pdf").build(),
    RequestBody.fromBytes(pdfBytes));
```

## Interview Qs

### How does the app get AWS credentials on ECS without access keys?

The default chain reaches the container credentials provider. ECS sets AWS_CONTAINER_CREDENTIALS_RELATIVE_URI, and the SDK fetches the task role's temporary credentials from that endpoint. No keys live in the image or config.

### How do you test AWS code without a real account?

Run LocalStack in Testcontainers. Spring Cloud AWS's testcontainers module points the clients at it through @ServiceConnection.
