## Why it exists

Each compute service trades control for less operations work. Interviewers ask you to pick one for a workload and say why.

## How it works

<Compare id="ec2-vs-lambda-vs-fargate" />

- Start from the workload: how long one run takes, how traffic arrives, team skills, and how much of the OS you must control.
- The services: [EC2](card:ec2), [Lambda](card:lambda), [ECS, EKS and Fargate](card:containers-ecs-eks-fargate).
- Elastic Beanstalk deploys an app onto EC2 or EKS for you; App Runner is closed to new customers.

## Interview Qs

### How would you deploy a Spring Boot backend on AWS?

Build a Docker image and push it to ECR. Run it as an ECS service on Fargate across two AZs, behind an ALB with health checks, and scale the task count on CPU or requests per target. One good answer, not the only one.

### When would you choose Lambda over containers?

For short, event-driven or spiky work: a payment webhook, a file-upload trigger, a nightly job under 15 minutes. A steady API with many endpoints usually fits a container service.

### When is EC2 still the right choice?

When you need control of the OS, special instance types such as GPUs, or software that must be installed and tuned on the host itself.
