## Why it exists

Clicking resources together in the console cannot be reviewed, repeated or rebuilt after a disaster. Code can be versioned, tested and run again in a new Region.

## How it works

<Compare id="cloudformation-vs-cdk-vs-terraform" />

- CDK constructs: [L1, L2 and L3](card:cdk-constructs). `cdk synth` writes the template; `cdk deploy` runs it.
- Rebuilding a Region from code is part of [disaster recovery](card:disaster-recovery).

## Example

```java
public class ReceiptsStack extends Stack {
    public ReceiptsStack(Construct scope, String id) {
        super(scope, id);
        Bucket.Builder.create(this, "Receipts")              // L2 construct
            .versioned(true)
            .encryption(BucketEncryption.S3_MANAGED)
            .blockPublicAccess(BlockPublicAccess.BLOCK_ALL)
            .enforceSSL(true)
            .removalPolicy(RemovalPolicy.RETAIN)              // keep receipts if the stack is deleted
            .build();
    }
}
```

## Interview Qs

### What is infrastructure as code, and why use it?

Defining servers, networks and databases in versioned files that a tool applies. Changes get code review, environments stay identical, and you can rebuild everything quickly.

### Why create a change set before updating a stack?

It previews the update without running it, including any resource CloudFormation would delete or replace, such as the payments database. Nothing changes until you execute it.
