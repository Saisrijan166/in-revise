## What it is

A VPC endpoint is a private doorway from your [VPC](card:vpc-and-subnets) to an AWS service, so traffic goes over the AWS network instead of out to the internet. There are two kinds. A gateway endpoint works only for S3 and DynamoDB and is a route entry in your route table. An interface endpoint works for most services and is a network interface with a private IP inside your subnet, built on AWS PrivateLink. PrivateLink is the technology that exposes a service as a private IP in your network.

## Why it exists

Private tasks still need to call S3, SQS, and Secrets Manager. Sending those calls through a [NAT gateway](card:internet-and-nat-gateways) costs per GB and needs an internet path you may not want for sensitive traffic. A VPC endpoint removes both problems: the traffic reaches the service over a private AWS path, so there is no NAT fee for it and no exposure to the internet.

## How it works

| | Gateway endpoint | Interface endpoint |
| --- | --- | --- |
| Services | S3, DynamoDB only | most AWS services, plus partner and your own services |
| How it works | a route to a prefix list in your route tables | a network interface with a private IP, via PrivateLink |
| Cost | no charge | per hour per AZ, plus per GB processed |
| From on-premises or another Region | no | yes, over VPN, Direct Connect or peering |

1. For S3 or DynamoDB, you create a gateway endpoint and AWS adds a route for the service's prefix list to the route tables you choose.
2. Traffic to that service now matches the endpoint route and goes over the AWS network, not the internet.
3. For a service like SQS, you create an interface endpoint, and AWS places a network interface with a private IP in each subnet you pick.
4. With private DNS enabled, the normal service hostname resolves to that private IP, so your application code does not change.

## Example

Private DNS is why the SDK needs no change. The same client call resolves to a private endpoint IP.

```text
Without endpoint:  secretsmanager.ap-south-1.amazonaws.com -> public IP -> NAT -> internet
With interface endpoint + private DNS:
                   secretsmanager.ap-south-1.amazonaws.com -> 10.0.1.47 (endpoint ENI in your subnet)
```

What to notice:

- The hostname your code calls is identical in both cases; only the resolved IP changes.
- The private IP `10.0.1.47` sits in your subnet, so the traffic never leaves the AWS network and needs no NAT or internet gateway.
- If private DNS were off, you would have to call an endpoint-specific DNS name by hand; turning it on is what keeps the SDK call unchanged.

## Rules and defaults

- **Gateway endpoint reach:** works only from inside the VPC that holds it; it cannot be used from on-premises, a peered VPC, or a transit gateway (AWS PrivateLink).
- **Interface endpoint security group:** you must attach one that allows inbound 443 from your resources, or the calls fail.
- **Private DNS prerequisite:** the VPC must have DNS hostnames and DNS resolution enabled for private DNS to work.
- **Endpoint policy:** optional; the default allows full access. It never replaces IAM or a bucket policy; all applicable policies must still allow the call (AWS PrivateLink).

## Not to be confused with

A gateway endpoint is a free route entry for S3 and DynamoDB and does not use PrivateLink. An interface endpoint is a paid network interface, built on PrivateLink, for most other services. Rule: S3 and DynamoDB from inside the VPC go through a gateway endpoint; everything else, or access from on-premises, goes through an interface endpoint.

## Interview Qs

### Gateway or interface endpoint for S3?

Use a gateway endpoint when the traffic comes from inside the VPC: it is free and needs only a route. Use an interface endpoint when you also need access from on-premises or another Region, accepting the per-hour and per-GB cost. Both keep traffic on the AWS network.

### How do private tasks read secrets without any internet access?

Create an interface endpoint for Secrets Manager in each AZ's private subnet, enable private DNS, and let the endpoint's security group allow 443 from the tasks. The SDK call stays the same, and no NAT gateway or internet gateway is required.

### Does an endpoint policy replace IAM?

No. An endpoint policy is an extra filter on the endpoint; the IAM identity policy and any resource policy must still allow the call. The default endpoint policy allows everything, so on its own it restricts nothing.
