## Why it exists

A payment webhook or receipt worker does not justify a server running all day. Lambda runs code only when an event arrives.

## How it works

## Example

```java
// libraries: aws-lambda-java-core, aws-lambda-java-events, AWS SDK s3
public class ReceiptHandler implements RequestHandler<SQSEvent, Void> {
    private static final S3Client S3 = S3Client.create(); // init once, reused

    @Override
    public Void handleRequest(SQSEvent event, Context context) {
        for (SQSEvent.SQSMessage msg : event.getRecords()) {
            S3.putObject(b -> b.bucket("payment-receipts").key(msg.getMessageId() + ".txt"),
                    RequestBody.fromString(msg.getBody()));
        }
        return null;
    }
}
```

## Interview Qs

### What is a cold start, and how do you reduce it for Java?

Lambda must create an environment, load code, start the JVM and run static init before the handler. Use SnapStart, keep init light, or provisioned concurrency for strict latency.

### Reserved or provisioned concurrency: what is the difference?

Reserved sets aside, and caps, one function's share of the Region's concurrency, free. Provisioned keeps environments initialised, removing cold starts, at extra cost.
