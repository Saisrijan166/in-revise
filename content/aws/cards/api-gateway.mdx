## Why it exists

Every API needs authentication, rate limits, versions and routing. API Gateway runs these as a managed service, so a Lambda-based payment API needs no web server at all.

## How it works

<Compare id="rest-api-vs-http-api" />

- Both REST and HTTP APIs can set CORS for browser clients.
- Private backends are reached through a [VPC link](card:vpc-link).

## Example

```text
POST /prod/payments  {"amount": 500, "currency": "INR", "method": "UPI"}
  1. JWT authorizer checks the bearer token
  2. throttling: over the limit → 429 Too Many Requests
  3. Lambda proxy integration passes the whole request to the handler
← 201 Created  {"paymentId": "pay_123", "status": "PENDING"}
```

## Interview Qs

### REST API or HTTP API?

HTTP API by default: lower price, JWT authorizers. REST API when you need API keys and usage plans, AWS WAF, caching, request validation or a private endpoint.

### Clients get 429 errors. What is happening?

Requests passed the throttle: the account limit per Region, or a stage, method or usage-plan limit. Retry with backoff, raise the quota, or cut calls with caching.
