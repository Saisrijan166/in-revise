## Why it exists

A VPC has no internet path by default. Load balancers must be reachable from outside; app servers must fetch updates and call payment partners without being reachable.

## How it works

<Compare id="internet-gateway-vs-nat-gateway" />

- Traffic to S3, SQS or Secrets Manager can skip the NAT fee: use [VPC endpoints](card:vpc-endpoints-privatelink).
- IPv6 outbound only: an egress-only internet gateway.

## Example

```text
Public subnet route table      Private subnet a route table
10.0.0.0/16  local             10.0.0.0/16  local
0.0.0.0/0    igw-0abc          0.0.0.0/0    nat-0aaa  (NAT in public subnet a)
```

## Interview Qs

### How does an instance in a private subnet download patches?

Its route table sends 0.0.0.0/0 to a NAT gateway in a public subnet. The NAT gateway uses its Elastic IP and the internet gateway. Nobody outside can open a connection to the instance.

### Can internet users reach a server through the NAT gateway?

No. Connections must start inside the VPC; only replies come back. For inbound traffic, put a load balancer in the public subnets.

### How do you make NAT highly available?

Create a zonal NAT gateway in each AZ and point each private subnet at its own AZ's gateway, or use one regional NAT gateway.
