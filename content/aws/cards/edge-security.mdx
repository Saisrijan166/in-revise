## What it is

Edge security is the set of controls at the front door of a public application, before traffic reaches the app. Three AWS services cover it. AWS WAF (Web Application Firewall) checks each HTTP(S) request against rules and blocks the bad ones. AWS Shield defends against DDoS, floods of traffic meant to overwhelm the service. ACM (AWS Certificate Manager) issues and renews the TLS certificates that make the site HTTPS. They attach to the public entry points: [CloudFront](card:cloudfront), the [load balancer](card:elastic-load-balancing) and [API Gateway](card:api-gateway).

## Why it exists

A public payment API is reached by anyone on the internet, including bots probing for SQL injection and clients flooding it with requests. [Security groups](card:security-groups-and-nacls) only decide which ports and source IPs are open; they never look inside the HTTP request, so they cannot see an injection attempt or count requests. Blocking that traffic at the edge keeps it away from the app, and TLS needs certificates that do not silently expire and take the site down.

## How it works

| Service | Works at | Stops or gives | Charge |
|---|---|---|---|
| AWS WAF | HTTP(S) requests | Injection, bad inputs, per-IP floods | Per web ACL, rule and request |
| Shield Standard | Network and transport layers | Common DDoS attacks | None; automatic |
| Shield Advanced | Those, plus the application layer | Larger DDoS, with cost protection | Paid, 1-year commitment |
| ACM | TLS | Public certificates, renewed for you | Free on integrated services |

<Steps label="Putting WAF in front of the payment API">
  <Step title="Attach">You create a web ACL and attach it to the ALB or CloudFront distribution.</Step>
  <Step title="Add managed rules">You add AWS managed rule groups, such as the core rule set, to block common bad inputs.</Step>
  <Step title="Add a rate limit">You add a rate-based rule so one IP cannot exceed your request limit in the window.</Step>
  <Step title="Filter">Every request is checked against the rules before it reaches the app; blocked ones get HTTP 403.</Step>
</Steps>

- The ALB or CloudFront ends TLS with the ACM certificate, so the app does not handle certificates itself.
- On your own servers, such as EC2, ACM public certificates are not free to export; use ACM's exportable certificates or managed renewal differently.

## Rules and defaults

- **WAF attach points:** CloudFront, Application Load Balancer, API Gateway REST APIs, AppSync, Cognito user pools and more. It cannot attach to a Network Load Balancer.
- **Rate-based rule:** the evaluation window is 60, 120, 300 or 600 seconds, and 300 (5 minutes) is the default; the lowest rate limit is 10. By default it aggregates by source IP.
- **Shield Standard:** on for every AWS account automatically, at no extra charge, against common network and transport (layer 3 and 4) DDoS.
- **Shield Advanced:** a paid subscription with a 1-year commitment; it adds application-layer mitigation, the Shield Response Team, DDoS cost protection, and it covers the standard WAF fees for the resources it protects.
- **ACM validity:** public certificates issued or renewed since 18-02-2026 are valid for 198 days (down from 395); AWS renews them before they expire, so the shorter life needs no action from you.

## Interview Qs

### What is the difference between AWS WAF and AWS Shield?

AWS WAF checks HTTP(S) requests against your rules: SQL injection, bad inputs, per-IP rate limits. AWS Shield fights DDoS. Shield Standard covers common network and transport attacks for free and automatically; Shield Advanced adds application-layer mitigation, the response team and DDoS cost protection for a paid, one-year subscription.

### How do you stop one client from flooding the payment API?

Add a rate-based rule to an AWS WAF web ACL on the ALB, CloudFront or an API Gateway stage. It counts each IP's requests over the window, 300 seconds by default, and blocks the IPs above the limit while others pass. [API Gateway throttling](card:api-gateway) can add a second, overall limit.

### Why can't a security group block SQL injection?

A security group is a stateful filter on ports and source or destination IPs; it decides whether a packet may arrive, not what it contains. SQL injection lives in the HTTP request body, which only a layer-7 tool like AWS WAF inspects. The two work together: the security group opens 443, WAF reads the request.
