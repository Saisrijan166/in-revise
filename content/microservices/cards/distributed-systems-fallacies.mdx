## Why it exists

Splitting a monolith turns method calls into network calls. Code written as if the network were perfect hangs, double-charges or leaks data when it is not.

## How it works

| The false belief | What it means for a service |
|---|---|
| The network is reliable | Set [timeouts and bounded retries](card:timeouts-and-retries) |
| Latency is zero | Avoid chatty calls; batch or cache |
| Bandwidth is infinite | Paginate; send only the fields needed |
| The network is secure | Encrypt and authenticate every call ([security](card:microservices-security)) |
| Topology doesn't change | Find instances by [service discovery](card:service-discovery), not fixed IPs |
| There is one administrator | Many teams own parts; [observe](card:observability) across them |
| Transport cost is zero | Serialising and moving data costs time and money |
| The network is homogeneous | Use standard protocols and contracts ([REST](card:rest-apis), [gRPC](card:grpc)) |

- A timeout is an unknown outcome, so a repeated call must be [idempotent](card:idempotency).

## Interview Qs

### What happens if one service goes down?

Callers see errors or timeouts, and waiting threads can pile up and spread the failure. Use timeouts, bounded retries, [circuit breakers](card:circuit-breaker) and a [fallback](card:fallback-and-degradation) where it is safe. Not every failure can be hidden from the user.

### A payment call timed out. Was the customer charged?

You cannot know: the request may have been lost, or processed with the reply lost. Retry with the same idempotency key, or ask the Payment service for the status, before charging again.

### What are the fallacies of distributed computing?

Eight false beliefs: the network is reliable, latency is zero, bandwidth is infinite, the network is secure, topology does not change, there is one administrator, transport cost is zero, and the network is homogeneous.
