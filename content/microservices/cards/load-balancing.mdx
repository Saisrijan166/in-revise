## Why it exists

One instance has a limit. Several instances only help if each request goes to one that is alive and not too busy.

## How it works

<Mermaid
  alt="Order Service calls a load balancer. The balancer sends calls in turn to Payment instance 1 and Payment instance 2. Payment instance 3 failed its health check, so it gets no traffic."
  chart={`flowchart LR
  C[Order Service] --> LB{Load balancer}
  LB -- "calls 1, 3, 5" --> P1[Payment 1]
  LB -- "calls 2, 4, 6" --> P2[Payment 2]
  LB -.->|"failed health check, no traffic"| P3[Payment 3]`}
/>

- Least-connections trap: an instance that fails fast looks idle and draws more traffic. Count recent errors as load.
- Sticky sessions block even spreading: keep [services stateless](card:scaling-services).

## Example

```nginx
upstream payment_service {
    least_conn;                       # without it: round robin
    server payment-1:8080 weight=2;   # gets twice the share
    server payment-2:8080;            # weight defaults to 1
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| Algorithm | round robin | NGINX upstream |
| Server weight | 1 | NGINX upstream |

## Interview Qs

### Round robin or least connections?

Round robin when requests cost about the same. Least connections when costs vary widely, like slow reports beside quick reads, because busy instances get fewer new calls.

### What is the difference between layer 4 and layer 7 load balancing?

Layer 4 sees only IPs and ports and forwards TCP or UDP traffic, so it is fast and protocol-agnostic. Layer 7 reads each HTTP request, so it can route by its headers.
