## Why it exists

Many services need the same order events, in order, and some join later. Kafka keeps events in a replicated log that each reader walks at its own pace.

- Each partition has a leader and followers; three copies is a common production setting.
- Need queue-style reading with more consumers than partitions? Kafka 4.3 has share groups.
- When to commit the offset decides loss or duplicates: [delivery guarantees](card:delivery-guarantees).

## Interview Qs

### How does Kafka keep order?

Only inside a partition. The producer sends records with the same key to the same partition, and one consumer in a group reads that partition in order. There is no order across partitions.

### You add consumers but throughput does not grow. Why?

A consumer group gives each partition to one consumer, so consumers beyond the partition count sit idle. Add partitions, or use a share group if order does not matter.

### What is consumer lag?

How far a consumer is behind: the log-end offset minus its current offset, per partition. Growing lag means consumers cannot keep up.
