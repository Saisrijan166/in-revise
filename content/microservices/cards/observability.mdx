## Why it exists

One checkout touches five services on many machines. Without shared signals you cannot tell which one failed or why it was slow.

## How it works

<Compare id="logs-vs-metrics-vs-traces" />

- Each instance writes logs to stdout; an agent ships them to one central, searchable store.
- Spring Boot 4.1 writes JSON logs with `logging.structured.format.console=ecs` (or `logstash`, `gelf`).
- How traces join up: [Distributed Tracing](card:distributed-tracing). What to alert on: [Metrics and SLOs](card:metrics-and-slos).

## Example

```json
{
  "timestamp": "2026-10-20T10:15:02.114Z",
  "level": "WARN",
  "service": "payment-service",
  "traceId": "0af7651916cd43dd8448eb211c80319c",
  "orderId": "1001",
  "message": "PaymentFailed: card declined, amount ₹2,499"
}
```

## Interview Qs

### How do you debug one request across many services?

Take the trace ID from the error, open the trace to see which span failed or was slow, then search the central logs by that ID. Metrics show whether it is one request or a trend.

### Correlation ID vs trace ID?

Both tie together the records of one call chain. A trace ID follows the W3C standard and also links spans. With Micrometer Tracing, Spring Boot adds traceId and spanId to every log line by default.
