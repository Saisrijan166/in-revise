## Why it exists

Without it, every client must know every service's address and repeat TLS, login checks and throttling. A single entry point hides the split and does those jobs once.

- Services still check the caller themselves: see [Securing Microservices](card:microservices-security).
- Lock services so clients cannot bypass the gateway; re-encrypt traffic from the gateway to them.
- In Spring: Spring Cloud Gateway, in [the Spring Cloud stack](card:spring-cloud-stack).

## Interview Qs

### Why use a gateway if services already have APIs?

Clients get one address and an API shaped for them. It hides how services are split, cuts round trips by aggregating calls, and applies TLS, authentication and throttling in one place.

### When would you use Backend for Frontend?

When web, mobile and partner clients need very different data. Each client type gets its own gateway with an API made for it, instead of one gateway full of client-specific code.

### Can the gateway become a bottleneck?

Yes: every request passes through it. Size it for peak traffic, run several instances, and keep it thin, with no business logic.
