## What it is

An array is a fixed number of slots of the same type, stored one after another in one block of memory. Each slot has a number called its index, starting at 0. In `int[] nums = {2, 7, 11, 15}`, `nums[0]` is 2 and `nums[3]` is 15. The number of slots is the array's length, and it is decided when the array is created.

## Why it exists

Many problems need a sequence of values that you can reach by position: the marks of 30 students, the pixels of an image, the cells of a board. Thirty separate variables cannot be looped over. An array gives all of them one name and a number each, so a loop can visit them, and any one of them can be read at once without walking past the others.

## How it works

| Operation on `nums` | Cost | Why |
|---|---|---|
| Read or write `nums[i]` | O(1) | the slot's address is computed from `i` |
| Find the index of a value | O(n) | without sorting, there is no shortcut: check one by one |
| Insert or delete at position `i` | O(n) | every item after `i` must move one slot |
| Add when the array is full | O(n) | create a bigger array and copy everything |

1. When you write `new int[4]`, Java reserves four slots of the same size next to each other and fills them with 0.
2. To read `nums[i]`, it computes start address + i × slot size and goes there directly. That is why the cost does not depend on how big the array is.
3. To find a value, nothing tells you where it is, so a loop checks `nums[0]`, `nums[1]` and so on until it matches.
4. To insert in the middle, the items from that position onwards move one slot right. If no slot is free, a new array must be made first.

So the key is: position is cheap, value and change are not.

## Example

Using the running example `nums = [2, 7, 11, 15]`, this code reads by index, searches by value and "grows" the array:

```java
int[] nums = {2, 7, 11, 15};
System.out.println(nums[2]);                // O(1): jump straight to index 2
int at = -1;
for (int i = 0; i < nums.length; i++) {     // O(n): check items one by one
    if (nums[i] == 15) { at = i; break; }
}
System.out.println(at);
int[] bigger = Arrays.copyOf(nums, 6);      // "growing" = copying into a new array
System.out.println(Arrays.toString(bigger));
int[][] grid = new int[2][3];               // 2 rows, 3 columns, all 0
System.out.println(grid.length + " x " + grid[0].length);
```

```text output
11
3
[2, 7, 11, 15, 0, 0]
2 x 3
```

What to notice:

- `nums[2]` takes one step, but finding 15 took four comparisons. With a million items the first stays one step and the second can take a million.
- `nums.length` has no brackets: it is a field, not a method like `String.length()`.
- `Arrays.copyOf` makes a new array; `nums` itself still has length 4. The two empty slots hold 0, the default for `int`.
- Writing `nums[4]` would compile but throw `ArrayIndexOutOfBoundsException`, because the last index is `length - 1 = 3`.

## Rules and defaults

- **Default values (Java SE 25):** a new array is filled with `0` for numbers, `false` for `boolean`, `'\u0000'` for `char` and `null` for objects.
- **Length:** fixed once the array is created. Read it with `nums.length`.
- **Index range:** 0 to `length - 1`. Any other index throws `ArrayIndexOutOfBoundsException` at run time.
- **2D arrays:** an `int[][]` is an array of row arrays. `grid.length` is the number of rows and `grid[0].length` the columns of row 0. Rows may have different lengths (a jagged array), for example `new int[3][]` and then each row created separately.

## Not to be confused with

An array has a fixed length and can hold primitives such as `int`. An [ArrayList](card:dynamic-array), the next concept, grows by itself but holds only objects such as `Integer`. A [linked list](card:linked-list), which you will see later, stores items in separate nodes joined by links, so it cannot jump to index i. Rule: array = fixed slots; ArrayList = an array that grows; linked list = a chain you walk.

## Interview Qs

### Why is array access O(1)?

The items have the same size and sit next to each other, so the address of item i is the start address plus i times the item size. The computer goes straight there. The cost is the same for index 3 and index 3 million.

### Why is inserting in the middle of an array slow?

Every item after the insert point must move one slot right to make room, which is O(n) in the worst case. If the array has no free slot, a bigger array must be created and all items copied, also O(n).

### Why are arrays fast to loop over, beyond Big-O?

Neighbouring items sit next to each other in memory, and the CPU loads memory in blocks into its cache. One load brings in the next few items too, so a loop over an array gets many cache hits. A linked list's nodes are scattered, so the same loop is slower.
