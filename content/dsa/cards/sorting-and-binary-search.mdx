## Why it exists

Order lets one comparison eliminate a large part of the search. Sorting can create that order; binary search then uses it efficiently.

## How it works

- Decide whether `left` and `right` are inclusive before coding.
- State the answer condition: found value, first true, or last true.
- Change a boundary every iteration; otherwise the loop can stall.

## Example

```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;
```

## Interview Qs

### What makes binary search valid?

The comparison must let you discard half the candidates safely. That comes from sorted values or a monotonic predicate where answers change from false to true, or the reverse, only once.

### Why avoid `(left + right) / 2`?

`left + right` can overflow for large integer bounds. `left + (right - left) / 2` produces the same midpoint without that addition risk.
