## Why it exists

Tasks and the next vertices in [BFS](card:bfs) must be handled in arrival order. A queue keeps that order; a deque also works at the back.

## How it works

<Compare id="stack-vs-queue" />

- An array queue that shifts everything on each dequeue costs O(n).
- A [circular queue](card:circular-queue) avoids the shift: head and tail indices wrap with `% capacity`.
- A `PriorityQueue` is also a `Queue`, but it serves by [priority](card:heap-priority-queue).

## Example

```java
Queue<Integer> q = new ArrayDeque<>();
q.offer(1); q.offer(2);            // [1, 2]
q.peek();                          // 1, stays in
q.poll();                          // 1, removed: [2]
q.poll(); q.poll();                // 2, then null (empty)
// q.remove() on empty: NoSuchElementException

Deque<Integer> d = new ArrayDeque<>();
d.offerFirst(1); d.offerLast(2);   // [1, 2]
d.pollLast();                      // 2
```

## Interview Qs

### Stack vs queue?

A stack is LIFO, one end; a queue is FIFO, add at the tail and remove at the head. DFS uses a stack; BFS uses a queue.

### Why ArrayDeque over LinkedList for a queue?

The Java docs say `ArrayDeque` is likely faster than `LinkedList` as a queue. It also rejects null, so `poll()` returning null always means empty.
