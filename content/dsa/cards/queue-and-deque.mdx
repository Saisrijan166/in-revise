## What it is

A queue is an [ADT](card:data-structures) that serves items in the order they arrived, like a line at a ticket counter. You add at the back, called the tail, and remove from the front, called the head, so the first item in is the first out: FIFO. A deque, short for double-ended queue and said "deck", lets you add and remove at both ends, so it can act as a queue or as a [stack](card:stack). In Java both are interfaces, `Queue` and `Deque`, and `ArrayDeque` implements both.

## Why it exists

Print jobs, incoming requests and the next places to visit in [breadth-first search](card:bfs), which you will meet in Graphs, must be handled in the order they arrived. If you keep them in a plain array and remove the front item, every other item shifts one slot left: O(n) for each removal. A queue removes from the front in O(1) instead. A deque also lets you work at the back, which sliding-window problems need later.

## How it works

<Mermaid
  alt="A queue holding A, B and C. A is at the head and C is at the tail. offer adds a new item after C at the tail; poll removes A from the head and returns it."
  chart={`flowchart LR
  IN([offer D]) --> T["tail: C"] --> M[B] --> H["head: A"] --> OUT([poll returns A])`}
/>

1. `offer("A")`, `offer("B")`, `offer("C")`: each item joins at the tail, so A is at the head.
2. `peek()` returns A and leaves the queue unchanged.
3. `poll()` removes and returns A; B becomes the head.
4. When the queue is empty, `poll()` and `peek()` return `null`, while `remove()` and `element()` throw `NoSuchElementException`.
5. Inside a fixed array, a queue avoids shifting by keeping a head index that moves forward on each poll. The tail index wraps back to slot 0 with `% capacity`, so slots freed at the front are reused. This is called a circular queue.

So the key is: a queue only ever touches its two ends, which is why both operations are O(1).

## Example

The same `ArrayDeque` class serves as a queue and as a deque:

```java
Queue<String> line = new ArrayDeque<>();
line.offer("A"); line.offer("B"); line.offer("C");  // join at the tail
System.out.println(line.peek() + " " + line.poll()); // look, then serve the head
System.out.println(line);

Deque<String> d = new ArrayDeque<>();
d.offerFirst("B"); d.offerFirst("A"); d.offerLast("C");
System.out.println(d.pollLast() + " " + d);          // serve from the back

line.clear();
System.out.println(line.poll());                     // empty: null, no exception
```

```text output
A A
[B, C]
C [A, B]
null
```

What to notice:

- `peek()` and `poll()` both return A, but only `poll()` removes it, so the queue that prints next is `[B, C]`.
- The deque took items at both ends: `offerFirst("A")` went in front of B, and `pollLast()` served C from the back.
- On the empty queue `poll()` returned `null`. Replacing it with `remove()` would throw `NoSuchElementException` at that line.

## Rules and defaults

| Operation | Throws when it fails | Returns a value when it fails |
|---|---|---|
| Add at the tail | `add(e)` | `offer(e)` returns `false` |
| Remove the head | `remove()` | `poll()` returns `null` |
| Read the head | `element()` | `peek()` returns `null` |

- **Deque methods:** the same pairs exist for each end, such as `offerFirst` and `offerLast`, `pollFirst` and `pollLast`, `peekFirst` and `peekLast`.
- **`ArrayDeque`:** no capacity limit, as it grows when needed; no `null` items; not thread-safe. `new ArrayDeque<>()` starts with room for 16 items (Java SE 25).
- **`offer` vs `add`:** they differ only for queues with a fixed capacity, where `offer` returns `false` when full. An `ArrayDeque` is never full.

## Not to be confused with

- **Queue vs PriorityQueue:** a plain queue serves items in arrival order. A [PriorityQueue](card:heap-priority-queue) also implements `Queue`, but it always serves the smallest item first, whatever the arrival order. Rule: arrival order = `ArrayDeque`; smallest first = `PriorityQueue`.
- **Deque vs dequeue:** a deque (noun) is the double-ended structure. To dequeue (verb) is to remove the head of a queue, which Java calls `poll`.

## Interview Qs

### What is the difference between a stack and a queue?

A stack is LIFO: you add and remove at one end, the top, so the newest item leaves first. A queue is FIFO: you add at the tail and remove at the head, so the oldest item leaves first. Depth-first search uses a stack; breadth-first search uses a queue.

### Why use ArrayDeque rather than LinkedList for a queue?

The Java docs say `ArrayDeque` is likely to be faster than `LinkedList` when used as a queue. It also rejects `null`, so a `null` from `poll()` can only mean the queue is empty.

### How do you build a queue from two stacks?

Push new items onto stack `in`. To dequeue, pop from stack `out`; if `out` is empty, first pop every item from `in` and push it onto `out`, which reverses their order so the oldest is on top. Each item moves at most once, so each operation is amortised O(1).
