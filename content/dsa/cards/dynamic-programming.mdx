## Why it exists

Plain recursion solves the same subproblem again and again, often in exponential time. Storing each answer once removes the repeats.

## How it works

<Steps label="Write any DP">
  <Step title="State">Say dp[x] in words: fewest coins that make sum x.</Step>
  <Step title="Transition">dp[x] = 1 + min of dp[x - c] over every coin c.</Step>
  <Step title="Base case">dp[0] = 0; unreachable sums stay "impossible".</Step>
  <Step title="Order and answer">Fill x = 1 up to the amount; return dp[amount].</Step>
</Steps>

- Coin change: O(n k) for sum n and k coins.

## Example

```java
int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];            // dp[x] = fewest coins for x
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;                                 // base case
    for (int x = 1; x <= amount; x++)
        for (int c : coins)
            if (c <= x && dp[x - c] != Integer.MAX_VALUE)
                dp[x] = Math.min(dp[x], dp[x - c] + 1);   // transition
    return dp[amount] == Integer.MAX_VALUE ? -1 : dp[amount];
}
```

## Interview Qs

### How do you know a problem needs DP?

It asks to count, minimise or maximise, the answer builds from smaller versions of the problem, and those versions repeat.

### Memoisation or tabulation?

Both solve each state once. Memoisation is easier to write from the recursion; tabulation avoids recursion overhead and deep stacks.

### How do you cut the memory?

If row i only reads rows i - 1 and i - 2, keep just those. Climbing Stairs then needs two variables, and many 2D tables need two rows.
