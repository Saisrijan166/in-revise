## What it is

Top K is the pattern for questions about the k best items out of many: the k largest, the kth largest, the k most frequent. You scan the input once and keep only k candidates in a [heap](card:heap-priority-queue), whose top is always the weakest candidate. K-way merge uses the same idea to merge k sorted lists into one: the heap holds the front item of each list.

## Why it exists

The direct way sorts all n items and reads off k of them, which costs O(n log n) and needs every item in memory at once. When k is small, most of that sorting is wasted. A heap of size k keeps only the best k seen so far. Each new item costs O(log k), so the whole scan is O(n log k), and it works on a stream that never ends.

## How it works

Find the 2nd largest of [3, 2, 1, 5, 6, 4] with a min-heap of size 2:

| Item | Heap after offer | Size > 2? | Heap after |
|---|---|---|---|
| 3, 2 | [2, 3] | no | [2, 3] |
| 1 | [1, 2, 3] | yes, poll 1 | [2, 3] |
| 5 | [2, 3, 5] | yes, poll 2 | [3, 5] |
| 6 | [3, 5, 6] | yes, poll 3 | [5, 6] |
| 4 | [4, 5, 6] | yes, poll 4 | [5, 6] |

1. Create an empty min-heap.
2. For each item, offer it to the heap.
3. If the heap now holds k + 1 items, poll once. This removes the smallest, which cannot be in the top k.
4. After the scan the heap holds the k largest items, and its top (peek) is the kth largest: here 5.

For a k-way merge, the heap starts with the first item of each list. You poll the smallest, append it to the output, and push the next item from that same list.

## Example

The kth largest element, the classic interview version of the pattern:

```java
int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();  // min-heap: smallest on top
    for (int x : nums) {
        heap.offer(x);
        if (heap.size() > k) heap.poll();                 // drop the smallest of k + 1
    }
    return heap.peek();                                   // smallest of the k largest
}

System.out.println(findKthLargest(new int[] {3, 2, 1, 5, 6, 4}, 2));
```

```text output
5
```

What to notice:

- `new PriorityQueue<>()` with no comparator orders by natural ordering, so the head is the least element: a min-heap.
- The poll happens only when the size passes k, so the heap holds at most k + 1 items. That bound is why each step costs O(log k), not O(log n).
- `peek()` reads the top without removing it. The top is the smallest of the k kept items, which is the kth largest overall.

## Rules and defaults

- **Java default:** `PriorityQueue` is a min-heap; how to turn it into a max-heap is in [Heap and PriorityQueue](card:heap-priority-queue).
- **Which heap:** k largest needs a min-heap of size k; k smallest needs a max-heap of size k.
- **Top k frequent:** [count each value with a `HashMap`](card:frequency-counting) first, then keep a size-k min-heap ordered by count.
- **K-way merge:** for N items in total across k lists, every item enters and leaves the heap once, so O(N log k).
- **Running median:** a max-heap holds the lower half and a min-heap the upper half, with sizes equal or one apart. The median is read from the tops.

## Not to be confused with

Sorting puts all n items in order, at O(n log n); a size-k heap orders nothing except its top, at O(n log k). A [binary search tree](card:binary-search-tree) or `TreeMap` keeps every item in sorted order, so it can answer "next larger" questions a heap cannot. Rule: need only the k best, use a heap; need all items in order, sort or use a tree.

## Interview Qs

### Why a min-heap for the k largest?

The heap must throw away the item that is no longer in the top k, and that is always the smallest kept item. A min-heap keeps the smallest on top, so it is removed in O(log k). The total is O(n log k), better than an O(n log n) sort when k is much smaller than n.

### How do you merge k sorted lists?

Put the head of each list in a min-heap ordered by value. Poll the smallest node, append it to the output, and push that node's next node if there is one. The heap never holds more than k nodes, so N nodes in total cost O(N log k).

### How do you keep a running median of a stream?

Use two heaps: a max-heap for the lower half and a min-heap for the upper half. Insert each number into one of them, then move a top across so their sizes differ by at most one. The median is the top of the bigger heap, or the average of both tops. Insert is O(log n) and reading the median is O(1).
