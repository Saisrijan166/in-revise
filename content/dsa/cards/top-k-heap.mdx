## Why it exists

Sorting everything to read off k items wastes work. A heap of size k keeps only the best k so far, at O(log k) per item.

## How it works

| Problem | Heap holds | Answer |
|---|---|---|
| Kth largest | min-heap: k largest so far | the top |
| Top k frequent | min-heap of k values, by count | the whole heap |
| Merge k sorted lists | min-heap: one head per list | poll, push that list's next |
| Running median | max-heap low half, min-heap high half | the tops |

- For the k smallest, flip it: a max-heap of size k.

## Example

```java
int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();  // min-heap
    for (int x : nums) {
        heap.offer(x);
        if (heap.size() > k) heap.poll();                 // drop smallest
    }
    return heap.peek();                                   // kth largest
}
```

## Interview Qs

### Why a min-heap for the k largest?

The item to drop is the smallest of the top k, and a min-heap keeps it on top. O(n log k) in total, better than an O(n log n) sort when k is small.

### How do you merge k sorted lists?

Put each list's head in a min-heap. Poll the smallest, append it, push its next node. The heap holds at most k nodes: O(N log k).

### How do you keep a running median?

A max-heap for the lower half, a min-heap for the upper half, sizes equal or one apart. Insert is O(log n); the median is read from the tops in O(1).
