## Why it exists

Most programs need lists, sets, queues and maps. Java ships tested ones behind shared interfaces, so you can swap the class without rewriting callers.

## How it works

<Mermaid
  alt="Collection is the root of List (ArrayList, LinkedList), Set (HashSet, LinkedHashSet, TreeSet) and Queue (PriorityQueue); Deque (ArrayDeque, LinkedList) extends Queue. Map (HashMap, LinkedHashMap, TreeMap) stands alone."
  chart={`flowchart TD
  C[Collection] --> L["List: ArrayList, LinkedList"]
  C --> S["Set: HashSet, LinkedHashSet, TreeSet"]
  C --> Q["Queue: PriorityQueue"]
  Q --> D["Deque: ArrayDeque, LinkedList"]
  M["Map: HashMap, LinkedHashMap, TreeMap"]`}
/>

- LinkedList is both a List and a Deque.
- These classes are not synchronised; thread-safe ones live in `java.util.concurrent`.

## Example

```java
List<Integer> nums = new ArrayList<>(List.of(3, 1, 2)); // interface on the left
nums.add(5);                   // int 5 boxed to Integer
Collections.sort(nums);        // [1, 2, 3, 5]
int[] arr = {3, 1, 2};
Arrays.sort(arr);              // Arrays for arrays
Map<String, Integer> count = new HashMap<>(); // Map: not a Collection
```

## Interview Qs

### Why is Map not part of the Collection interface?

A Collection holds single elements; a Map holds key-value pairs with unique keys, so add(e) does not fit. It offers keySet(), values() and entrySet() as collection views.

### Why declare a variable as `List`, not `ArrayList`?

Code that depends only on List keeps working if you switch List classes, and it shows you need list behaviour, not ArrayList details.

### Why can you not write `List<int>`?

Type arguments must be reference types, so collections hold Integer, not int. Java boxes and unboxes for you; unboxing null throws NullPointerException.
