## What it is

The Java Collections Framework is the set of ready-made data structures in the `java.util` package. It is built from interfaces and classes. An interface such as `List` is an [ADT](card:data-structures): it names the operations, like `add` and `get`. A class such as `ArrayList` is a data structure that implements it. `Collection` is the root interface for groups of single items; `Map`, which stores key-value pairs, is a separate family.

## Why it exists

Almost every program needs a list, a set, a queue or a map. Without the framework you would write your own resizable array or hash table for each program, each with its own method names and bugs. The framework gives tested classes behind shared interfaces. Code written against `List` works with any list class, so you can switch from one class to another by changing a single line.

1. Choose the interface by the behaviour you need: `List` keeps items by position and allows duplicates, `Set` refuses duplicates, `Queue` and `Deque` hand items out in a processing order, and `Map` looks values up by key.
2. Declare the variable with that interface type, such as `List<Integer>`.
3. Create it with the class whose costs suit the job, such as `ArrayList` or `LinkedList`. Each class gets its own concept in this tech.
4. For common jobs, call the helper classes: `Collections` has static methods for collections, such as `sort`, and `Arrays` has them for arrays.
5. Put objects in, not primitives: Java converts an `int` to an `Integer` for you, which is called autoboxing.

`LinkedList` appears twice in the picture: it is both a `List` and a `Deque`.

## Example

The same few lines use a list, an array and a map:

```java
List<Integer> nums = new ArrayList<>(List.of(3, 1, 2)); // List type, ArrayList class
nums.add(5);                              // int 5 is boxed to Integer
Collections.sort(nums);                   // Collections: helpers for collections
int[] arr = {3, 1, 2};
Arrays.sort(arr);                         // Arrays: helpers for arrays
Map<String, Integer> count = new HashMap<>();
count.put("apple", 2);                    // a Map has put, not add
System.out.println(nums + " " + Arrays.toString(arr) + " " + count);
System.out.println(nums.getLast());       // Java 21+: List is a SequencedCollection
```

```text output
[1, 2, 3, 5] [1, 2, 3] {apple=2}
5
```

What to notice:

- The left side says `List`, the right side `ArrayList`. Only the right side names the storage, so only it changes if you switch classes.
- `new ArrayList<>(List.of(...))` copies the list from `List.of`, which cannot be changed, into one you can change. Calling `add` on the `List.of` list itself throws `UnsupportedOperationException` (more in [Java pitfalls](card:java-pitfalls), later).
- `Collections.sort` sorts a list, `Arrays.sort` sorts an array. Mixing them up does not compile.
- `count` has `put`, not `add`, because a `Map` is not a `Collection`.

## Rules and defaults

- **Type arguments are reference types:** `List<int>` does not compile; write `List<Integer>`. Unboxing a `null` `Integer` into an `int` throws `NullPointerException`.
- **Not thread-safe:** the general classes such as `ArrayList`, `HashMap` and `ArrayDeque` are not synchronised. For many threads, use the classes in `java.util.concurrent`, such as `ConcurrentHashMap`.
- **Sequenced collections (Java 21):** `List`, `Deque` and `LinkedHashSet` are `SequencedCollection`s, with `getFirst()`, `getLast()` and `reversed()`. `getFirst()` on an empty one throws `NoSuchElementException`.
- **Ordering:** `Collections.sort(list)` and a `TreeMap` use the class's natural order unless you pass a `Comparator`.

## Not to be confused with

- **Collection vs Collections:** `Collection` is the root interface that lists and sets implement. `Collections` is a class of static helper methods, such as `Collections.sort(list)`. Rule: singular = the interface, plural = the helpers.
- **Comparable vs Comparator:** `Comparable` is implemented by the class itself and gives its one natural order through `compareTo`. A `Comparator` is a separate object, often a lambda, that gives any other order. Rule: Comparable inside the class, Comparator passed in from outside.

## Interview Qs

### Why is Map not part of the Collection interface?

A `Collection` holds single items, so methods like `add(e)` make sense. A `Map` holds key-value pairs with unique keys, so `add(e)` does not fit; it needs `put(key, value)`. Instead, a map offers `keySet()`, `values()` and `entrySet()`, which are `Collection` views of its contents.

### Why declare a variable as List, not ArrayList?

Code that depends only on `List` keeps working if you switch to another list class, and it states that you need list behaviour, not `ArrayList` details. Method parameters typed as `List` also accept any list a caller has.

### Why can you not write `List<int>`?

Type arguments of a generic type must be reference types, so collections hold `Integer`, not `int`. Java boxes and unboxes for you, and unboxing a `null` throws `NullPointerException`.
