## Why it exists

[HashMap](card:hashmap-hashset) gives no order. Some answers need first-seen order, least-recently-used order, or sorted keys with "next smaller key" queries.

## Example

```java
class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int max;
    LruCache(int max) { super(16, 0.75f, true); this.max = max; } // access order
    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > max;                                    // drop the LRU entry
    }
}
TreeMap<Integer, String> slots = new TreeMap<>(Map.of(9, "a", 12, "b", 15, "c"));
slots.floorKey(13);    // 12
slots.ceilingKey(13);  // 15
```

## Interview Qs

### How do you build an LRU cache in Java?

Extend LinkedHashMap with `accessOrder = true`, so each get moves an entry to the end, and override `removeEldestEntry` to return true when size passes the limit.

### When would you choose TreeMap over HashMap?

When you need keys in sorted order, the smallest or largest key, or the nearest key to a value (floorKey, ceilingKey). You pay O(log n) per operation instead of O(1) average.
