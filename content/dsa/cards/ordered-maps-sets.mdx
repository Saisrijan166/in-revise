## What it is

These are the ordered versions of [HashMap and HashSet](card:hashmap-hashset). `LinkedHashMap` is a `HashMap` that also links its entries in a list, so it iterates in the order keys were inserted, or, if you ask, in the order they were last used. `TreeMap` stores keys in a red-black tree, a sorted tree that keeps itself balanced (you will see it in [balanced trees](card:balanced-trees)), so keys come out sorted. `LinkedHashSet` and `TreeSet` are the matching sets.

## Why it exists

A `HashMap` is fast but gives no usable order. Some answers need one: print words in the order they first appeared, evict the least recently used entry from a cache, or find the meeting that started just before 1 pm. Without these classes you would sort the keys every time, O(n log n), or keep a separate list in step with the map by hand. The ordered maps keep the order for you as you insert.

## How it works

<Compare id="hashmap-vs-linkedhashmap-vs-treemap" />

1. A `LinkedHashMap` stores each entry in hash buckets, like a `HashMap`, and also links it to the previous and next entries. A new key goes to the end of that list.
2. Putting an existing key again only changes its value; its place in insertion order stays the same.
3. In access order (the third constructor argument `true`), every `get` or `put` of a key moves its entry to the end, so the first entry is always the least recently used.
4. After each insert, `LinkedHashMap` calls `removeEldestEntry`. If you override it to return `true` when the map is too big, the first entry is removed.
5. A `TreeMap` places each key by comparing it with keys in the tree, smaller to the left and larger to the right. Because the tree stays balanced, every lookup walks about log n levels, and `floorKey` or `ceilingKey` follow the same path.

## Example

The same word list goes into ordered sets, a `TreeMap` answers a nearest-key question, and a `LinkedHashMap` acts as a two-entry LRU cache:

```java
List<String> words = List.of("pear", "apple", "fig", "apple");
System.out.println(new LinkedHashSet<>(words));  // first-seen order, duplicate dropped
System.out.println(new TreeSet<>(words));        // sorted order
TreeMap<Integer, String> slots = new TreeMap<>(Map.of(9, "standup", 12, "lunch", 15, "review"));
System.out.println(slots.floorKey(13) + " " + slots.ceilingKey(13)); // nearest key below, above
Map<String, Integer> lru = new LinkedHashMap<>(16, 0.75f, true) {    // true = access order
    protected boolean removeEldestEntry(Map.Entry<String, Integer> e) { return size() > 2; }
};
lru.put("a", 1);
lru.put("b", 2);
lru.get("a");                // "a" becomes the most recently used
lru.put("c", 3);             // a third entry: the eldest, "b", is removed
System.out.println(lru.keySet());
```

```text output
[pear, apple, fig]
[apple, fig, pear]
12 15
[a, c]
```

What to notice:

- `LinkedHashSet` kept `pear, apple, fig` in arrival order and dropped the second `apple`; `TreeSet` sorted the same words.
- `floorKey(13)` is the largest key ≤ 13 and `ceilingKey(13)` the smallest key ≥ 13. Both return `null` when no such key exists.
- `get("a")` moved `a` behind `b`, so `b` became the eldest and was evicted when `c` arrived. With `false` as the third argument, the map would keep insertion order and evict `a` instead.

## Rules and defaults

- **Costs (Java SE 25 API):** `LinkedHashMap` is O(1) on average, slightly slower than `HashMap` because it also updates the list. `TreeMap` guarantees O(log n) for `get`, `put`, `containsKey` and `remove`.
- **Iteration:** a `LinkedHashMap` iterates in time proportional to its size; a `HashMap` iterates over all its buckets, including empty ones.
- **Nulls:** `LinkedHashMap` and `LinkedHashSet` allow null. `TreeMap` and `TreeSet` throw `NullPointerException` for a null key with natural ordering, or with a comparator that does not accept null.
- **More TreeMap queries:** `firstKey`, `lastKey`, `lowerKey` (strictly less), `higherKey` (strictly greater), `headMap(k)` (keys below k) and `tailMap(k)` (keys from k up).
- **Sets mirror maps:** `TreeSet` is built on a `TreeMap`, and offers `floor`, `ceiling`, `first`, `last` and `pollFirst`.

## Common mistakes

- **"A TreeSet with a custom comparator still uses equals to spot duplicates."** It uses only the comparator: two items that compare as 0 count as one item. A comparator on length alone keeps only one word of each length.

## Interview Qs

### How do you build an LRU cache in Java?

Extend `LinkedHashMap` with access order on, `new LinkedHashMap<>(capacity, 0.75f, true)`, so each `get` or `put` moves the entry to the end. Override `removeEldestEntry` to return `true` when `size()` exceeds the limit; the map then drops the least recently used entry after each insert. Both `get` and `put` stay O(1) on average.

### When would you choose TreeMap over HashMap?

When you need keys in sorted order, the smallest or largest key, a range of keys, or the nearest key to a value with `floorKey` or `ceilingKey`. You pay O(log n) per operation instead of O(1) on average, so for plain lookups `HashMap` is the better choice.

### HashMap vs LinkedHashMap vs TreeMap?

All three map unique keys to values. `HashMap` is the fastest and keeps no order. `LinkedHashMap` adds a linked list, so it keeps insertion or access order at almost the same speed. `TreeMap` keeps keys sorted in a red-black tree, at O(log n), and adds nearest-key and range queries.
