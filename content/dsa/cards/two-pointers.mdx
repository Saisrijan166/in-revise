## What it is

Two pointers is a pattern that walks an array with two indices at once. A pointer here is an `int` index, not a memory address. The best-known shape starts one index at each end of a sorted array and moves them toward each other, so it can find a pair with a given sum in one pass. Other shapes move both indices in the same direction.

## Why it exists

To find two values that add up to a target, the brute force checks every pair with two nested loops: O(n²). For 100,000 items that is about 5 billion pairs. In a sorted array you do not need to check them all: comparing the current sum with the target tells you which value can never be part of the answer, and you drop it. One pass, O(n).

## How it works

Pair with sum 9 in the sorted `nums = [2, 7, 11, 15]`:

| Step | left | right | Sum | Too small or too big? | Move |
|---|---|---|---|---|---|
| 1 | 0 (2) | 3 (15) | 17 | too big | right-- |
| 2 | 0 (2) | 2 (11) | 13 | too big | right-- |
| 3 | 0 (2) | 1 (7) | 9 | equal | found: indices 0 and 1 |

1. Put `left` at index 0 (the smallest value) and `right` at the last index (the largest).
2. Add the two values and compare the sum with the target.
3. If the sum is too big, `nums[right]` is too big even with the smallest value left, so move `right` back by one.
4. If the sum is too small, `nums[left]` is too small even with the largest value left, so move `left` forward by one.
5. Stop when the sum equals the target, or when `left` meets `right` (no pair).

So the key is that each comparison throws away one value for good. The pointers never move back, so there are at most n steps.

The same idea has two other shapes:

| Shape | Start | Move | Classic problems |
|---|---|---|---|
| [Opposite ends](card:opposite-ends-pointers) | `0` and `n - 1` | inward, by comparing | Two Sum II, Valid Palindrome, Container With Most Water |
| [Read and write](card:read-write-pointers) | both at `0` | read every item; write only the ones you keep | Remove Duplicates, Move Zeroes |
| [One per array](card:one-pointer-per-array) | `0` in each array | advance the one with the smaller value | Merge Sorted Array |

## Example

This returns the indices of the pair, for the trace above.

```java
int[] pairWithSum(int[] nums, int target) {    // nums must be sorted
    int left = 0, right = nums.length - 1;
    while (left < right) {
        int sum = nums[left] + nums[right];
        if (sum == target) return new int[] {left, right};
        if (sum < target) left++;               // need a bigger sum
        else right--;                           // need a smaller sum
    }
    return new int[0];                          // no pair
}

System.out.println(Arrays.toString(pairWithSum(new int[] {2, 7, 11, 15}, 9)));
```

```text output
[0, 1]
```

What to notice:

- `left < right`, not `<=`: a pair needs two different positions, so one value is never paired with itself.
- Only one pointer moves per step, and only in one direction. That is why the loop runs at most n - 1 times.
- With target 100 the loop ends with `left == right` and returns an empty array, after only three steps.

## Rules and defaults

- **Sorted data:** the opposite-ends shape needs it. The read-and-write shape and the palindrome check do not.
- **Cost:** O(n) time and O(1) extra space. If you must sort first, the total is O(n log n).
- **Inside a bigger loop:** the pair search can be the inner loop of [3Sum](card:three-sum), giving O(n²) instead of O(n³); the steps are in the Interview Qs below.

## Not to be confused with

Two pointers is the general idea of two indices moving by a rule, toward each other or the same way. A [sliding window](card:sliding-window), the concept after next, is the special case where both move the same way and everything between them, the window, is what you measure. Rule: a pair or an in-place rewrite is two pointers; the best contiguous range is a sliding window.

## Interview Qs

### Why does moving the left pointer never miss the answer?

If `nums[left] + nums[right]` is too small, `nums[right]` is the largest value still in play, so `nums[left]` cannot reach the target with any remaining value. Dropping it loses no pair. The same reasoning drops `right` when the sum is too big.

### How do you solve 3Sum?

Sort the array. For each index i, run opposite-end pointers on the part to its right, looking for `-nums[i]`. Skip equal neighbours to avoid duplicate triples. That is O(n²) time instead of the O(n³) of three nested loops.

### How do you check whether a string is a palindrome without extra space?

Put one pointer at each end and compare the characters. If they differ, it is not a palindrome; if they match, move both inward. Stop when they meet. O(n) time and O(1) space, and no sorting is needed.
