## Why it exists

A plain BST's height depends on insertion order, so sorted input makes it O(n). Balanced trees guarantee O(log n) whatever the order.

## Interview Qs

### What is a balanced tree, and why do we need it?

A tree whose height stays O(log n) as keys are added and removed. Without balance, a BST built from sorted keys is a chain and search becomes O(n).

### What does a rotation do?

It relinks a parent and child (a constant number of pointers) so one side gets shorter. The inorder order stays the same, so it is still a valid BST.

### AVL or red-black?

AVL is more strictly balanced, so lookups touch slightly fewer nodes. Red-black needs fewer rotations per update; Java's TreeMap uses one.
