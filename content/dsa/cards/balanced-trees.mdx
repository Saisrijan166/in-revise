## What it is

A balanced tree is a [binary search tree](card:binary-search-tree) whose height stays O(log n), so it never turns into a long chain. A self-balancing tree keeps this promise on its own: after every insert or delete it checks a balance rule and repairs the shape if needed. The repair tool is a rotation, a small relinking of a parent and a child. AVL trees and red-black trees are the two classic self-balancing BSTs.

## Why it exists

A plain BST's height depends on the order of inserts. Sorted keys, such as ids or timestamps that only grow, make every new key a right child, so the tree becomes a chain and search costs O(n). You cannot control the input order in real use. A self-balancing tree fixes the shape as it goes, so every operation stays O(log n) whatever the order.

Follow an insert into an AVL tree:

1. Insert the key as in a plain BST, as a new leaf.
2. Walk back up the path from the new leaf to the root. At each node, update its stored height.
3. Find the lowest node whose two subtree heights now differ by 2. Only nodes on this path can be out of balance.
4. Fix that node with one rotation, or two when the new key went into the inner side, such as the left child's right subtree. The taller side gets one level shorter.
5. Keep walking up and fix any other unbalanced node the same way. A delete can need fixes at several levels.

So the key is that rotations change the shape but never the sorted order of the keys.

## Example

The same seven keys give very different trees depending on insert order; `insert` and `height` are the methods from the earlier concepts.

```java
TreeNode sorted = null, mixed = null;
for (int key : new int[] {1, 2, 3, 4, 5, 6, 7}) sorted = insert(sorted, key);
for (int key : new int[] {4, 2, 6, 1, 3, 5, 7}) mixed = insert(mixed, key);
System.out.println(height(sorted) + " " + height(mixed));
```

```text output
6 2
```

What to notice:

- Sorted input gives height 6: a chain where finding 7 visits all seven nodes.
- The middle-first order gives height 2, the flattest possible shape for seven keys. A self-balancing tree reaches a shape like this on its own, whatever the input order.
- At one million sorted keys, the plain BST has height 999,999, while a red-black tree's height is at most 2 lg(n + 1), about 40.

## Rules and defaults

- **AVL rule:** at every node, the heights of the two subtrees differ by at most 1, counting an empty subtree as height -1. Each node stores its height.
- **Red-black rules:** every node is red or black; the root is black; a red node has no red child; and every path from a node down to a missing child passes the same number of black nodes. Together these keep the height at most 2 lg(n + 1).
- **Repair cost:** an insert into a red-black tree needs at most 2 rotations, plus colour changes. Rotations relink a constant number of links, so each repair stays O(log n) in total.
- **Java:** `TreeMap` is a red-black tree with guaranteed log(n) time for `containsKey`, `get`, `put` and `remove`. `TreeSet` is built on a `TreeMap`.
- **Interviews:** expect "what is it and why"; writing rotation code from memory is rarely asked.

## Not to be confused with

An AVL tree keeps a strict height rule, so it is flatter and lookups touch slightly fewer nodes. A red-black tree uses looser colour rules, so updates need fewer rotations, and it stores one colour bit per node instead of a height. Rule: both are O(log n) worst case; AVL for read-heavy data, red-black when inserts and deletes are frequent, as in Java's `TreeMap`.

## Interview Qs

### What is a balanced tree, and why do we need it?

A BST whose height stays O(log n) as keys are added and removed. Without balancing, sorted inserts build a chain, and search, insert and delete all become O(n). Balancing makes the O(log n) cost a worst-case guarantee instead of a hope about the input order.

### What does a rotation do?

It relinks a parent and one child, a constant number of links, so that the child moves up and the parent moves down on the other side. One subtree gets one level shorter. The inorder order of the keys does not change, so the tree is still a valid BST.

### Which tree does Java's TreeMap use, and what does that give you?

A red-black tree. Because its height is at most 2 lg(n + 1), `get`, `put`, `remove` and `containsKey` are guaranteed O(log n), and keys come out in sorted order. That is why TreeMap is the choice when you need floor, ceiling or a sorted walk.
