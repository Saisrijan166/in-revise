## Why it exists

Some questions want every valid answer. Building answers step by step, and undoing each step, visits them all with one shared path.

## How it works

<Mermaid
  alt="Subsets of [1, 2] as a tree of choices. The empty path branches to [1] and [2]. The path [1] branches to [1, 2]. Every node is saved, giving four subsets."
  chart={`flowchart TD
  E["[ ]"] --> A["[1]"]
  E --> B["[2]"]
  A --> AB["[1, 2]"]`}
/>

- Subsets save every node; combinations save at size k; permutations save at size n.

## Example

```java
List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    backtrack(nums, 0, new ArrayList<>(), result);
    return result;
}
void backtrack(int[] nums, int start, List<Integer> path, List<List<Integer>> result) {
    result.add(new ArrayList<>(path));          // save a copy
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);                      // choose
        backtrack(nums, i + 1, path, result);   // explore
        path.remove(path.size() - 1);           // un-choose
    }
}
```

## Interview Qs

### How do subsets, combinations and permutations differ in code?

Subsets and combinations loop from `start` so order does not repeat; combinations save only at size k. Permutations loop from 0 with a `used[]` array and save at size n.

### How do you avoid duplicate subsets when the input repeats?

Sort first, then in the loop skip `nums[i]` when `i > start` and it equals `nums[i - 1]`. Equal values then start a branch only once per level.

### Why is it exponential, and what helps?

There are 2^n subsets and n! permutations, so the output alone is that big. Pruning, such as stopping when a sum passes the target, cuts dead branches early.
