## What it is

Backtracking is a way to list every possible answer by building each one step by step. At each step you choose one option, add it to the current partial answer (the path), and [recurse](card:recursion) to make the next choice. When that branch is finished, you undo the choice and try the next option. It is a [DFS](card:dfs) over a tree of choices, where each node is a partial answer.

## Why it exists

Questions such as "list all subsets" or "place 8 queens so none attack" want every valid answer, not one number. Writing nested loops does not work, because the number of loops depends on the input size. Backtracking handles any size with one recursive function and one shared path. Undoing each choice lets that one path be reused for every answer, and pruning stops branches that cannot succeed.

## How it works

1. Start with an empty path. If the current path is a valid answer, save a copy of it.
2. Loop over the options that are still allowed from here, for subsets the values after the last one chosen.
3. Choose: add the option to the path.
4. Explore: recurse, so the deeper call makes the next choice.
5. Un-choose: remove the option from the path, so the loop's next option starts from the same path as before.

So the key is that every add has a matching remove, which returns the path to its earlier state.

## Example

All subsets of [1, 2, 3], following the tree above:

```java
List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    backtrack(nums, 0, new ArrayList<>(), result);
    return result;
}
void backtrack(int[] nums, int start, List<Integer> path, List<List<Integer>> result) {
    result.add(new ArrayList<>(path));          // save a copy of the current path
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);                      // choose
        backtrack(nums, i + 1, path, result);   // explore
        path.remove(path.size() - 1);           // un-choose
    }
}
System.out.println(subsets(new int[] {1, 2, 3}));
```

```text output
[[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
```

What to notice:

- Every node of the tree is a subset, so the copy is saved at the top of each call, before the loop. For combinations of size k, save only when `path.size() == k`.
- The loop starts at `start` and recurses with `i + 1`, so a value never comes before an earlier one. That stops [2, 1] from appearing next to [1, 2].
- `path.remove(path.size() - 1)` calls `remove(int index)` and removes the last item. On a `List<Integer>`, `path.remove(value)` with an `int` would also remove by index, not by value.
- Change `new ArrayList<>(path)` to `path` and the output becomes eight empty lists.

## Rules and defaults

- **Subsets and combinations:** loop from `start`, so each set appears in one order only.
- **Permutations:** loop from 0 every time and keep a `boolean[] used`, so each value is used once per answer. Save when the path has n items.
- **Repeated input values:** sort first, then skip `nums[i]` when `i > start` and it equals `nums[i - 1]`. Equal values then start only one branch per level.
- **Cost:** n items give 2^n subsets and n! permutations, and copying each one costs O(n). Backtracking only works for small inputs; pruning cuts the work but not the worst case.

## Interview Qs

### How do subsets, combinations and permutations differ in code?

Subsets and combinations loop from `start` and recurse with `i + 1`, so the same set never appears in a second order. Subsets save at every call; combinations save only at size k. Permutations loop from 0 every time, skip values already marked in a `used[]` array, and save when the path has n items.

### How do you avoid duplicate subsets when the input has repeated values?

Sort the input so equal values sit together. In the loop, skip `nums[i]` when `i > start` and `nums[i] == nums[i - 1]`. The first copy of a value still starts a branch, so subsets that use it twice are kept, but a second branch starting with the same value at the same level is never opened.

### Why is backtracking exponential, and what helps?

The number of answers is itself exponential: 2^n subsets and n! permutations, so listing them all cannot be faster. Pruning helps on search problems, such as N-Queens or Combination Sum, by returning from a branch as soon as it breaks a rule. It skips whole subtrees but does not change the worst case.
