## What it is

A graph is a set of vertices (the things) joined by edges (the links between pairs of them). A [tree](card:tree-basics) is a special graph: connected, no cycles, one parent per node. A general graph drops those rules. Any vertex may link to any other, links may form loops, and some vertices may not be reachable at all. In code you usually store it as adjacency lists: for each vertex, the list of its neighbours.

## Why it exists

Roads between cities, friendships and "task A must finish before task B" are links in every direction. An array holds a sequence and a tree allows one parent per node, so neither can say "city 1 links to cities 0, 2 and 3, and city 3 links back to 1". A graph can. Once a problem is drawn as a graph, the same few algorithms in this topic answer fewest steps, reachability, task order, cheapest routes and cheapest wiring.

## How it works

The running example for this topic is six cities, 0 to 5, joined by seven roads. The numbers on the roads are travel times; they matter from [Shortest Paths](card:shortest-paths) onwards.

1. Number the vertices 0 to V - 1, so each vertex can be an index into an array or list. V is the number of vertices and E the number of edges.
2. Decide the kind of graph: directed or undirected, weighted or unweighted.
3. Read the input. Interviews often give an edge list, such as `{{0, 1}, {0, 2}}`, or a grid; you build the graph yourself.
4. Create one empty list per vertex. For each edge u-v, add v to u's list; for an undirected graph, also add u to v's list.
5. An algorithm then visits u's neighbours with `for (int v : graph.get(u))`. Over all vertices this touches every list entry once, so a full walk costs O(V + E).

## Example

This builds the city graph from its edge list, ignoring travel times for now.

```java
int n = 6;                                          // cities 0 to 5
int[][] roads = {{0, 1}, {0, 2}, {1, 2}, {1, 3}, {2, 4}, {3, 4}, {3, 5}};
List<List<Integer>> graph = new ArrayList<>();
for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
for (int[] r : roads) {
    graph.get(r[0]).add(r[1]);
    graph.get(r[1]).add(r[0]);                      // undirected: store both ways
}
System.out.println(graph);
```

```text output
[[1, 2], [0, 2, 3], [0, 1, 4], [1, 4, 5], [2, 3], [3]]
```

What to notice:

- City 1's list is `[0, 2, 3]`: its three roads. City 5 has one road, so its list is `[3]`.
- Each road appears twice, 14 entries for 7 roads, because the graph is undirected. Delete the second `add` line and the graph becomes directed: city 1's list shrinks to `[2, 3]`.
- Space is O(V + E): 6 lists and 14 entries. A matrix would need 6 × 6 = 36 cells, most of them empty.

## Rules and defaults

- **Default choice:** adjacency lists. Road, friendship and dependency graphs are usually sparse, meaning they have far fewer than V² edges, and lists store only the edges that exist.
- **Dense graphs:** a graph with close to V² edges wastes little space in a matrix, and the matrix answers "is u linked to v?" in O(1).
- **Weighted edges:** store pairs instead of plain neighbours, such as `int[] {v, w}` in a `List<List<int[]>>`.
- **Names instead of numbers:** map each name to its neighbours with a `Map<String, List<String>>`, or give each name a number first.
- **Disconnected graphs:** a graph can split into several connected components, groups of vertices that reach each other but not the rest. An algorithm that starts only at vertex 0 then misses vertices.

## Not to be confused with

An adjacency list gives each vertex a list of the neighbours it really has. An adjacency matrix gives every pair of vertices a cell, linked or not. Rule: lists by default; a matrix only when the graph is dense or edge checks dominate. Every tree is a graph, but most graphs are not trees, because they can contain cycles.

## Common mistakes

- **"Each edge goes into one list."** Only in a directed graph. In an undirected graph, forgetting the second `add` makes some vertices look unreachable.
- **"One traversal from vertex 0 covers the graph."** Not if the graph is disconnected. Loop over all vertices and start again from each one not yet visited.

## Interview Qs

### Adjacency list or adjacency matrix: which do you choose and why?

Adjacency lists in most cases: O(V + E) space, and looping over a vertex's neighbours touches only real edges, so BFS and DFS run in O(V + E). A matrix needs O(V²) space and O(V) per neighbour loop. Choose it only for a dense graph, or when you check "is u linked to v?" far more often than you list neighbours.

### What changes in your code if the graph is directed or weighted?

For a directed graph, add each edge only to its source vertex's list, not both. For a weighted graph, store a pair per entry, such as `{neighbour, weight}`, so an algorithm can read the cost of each edge. The rest of the building loop stays the same.

### What is a connected component, and how do you find them?

In an undirected graph, it is a largest group of vertices that can all reach each other. A disconnected graph has several. Start a traversal from each vertex not yet visited; each start finds one component. [DFS](card:dfs) or [union-find](card:union-find) both do this, as later concepts show.
