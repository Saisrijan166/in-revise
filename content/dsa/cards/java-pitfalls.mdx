## Why it exists

These bugs compile, pass the example, then fail bigger tests.

## How it works

| Pitfall | What happens | Fix |
| --- | --- | --- |
| Big int sum | wraps silently | `long`, or `Math.addExact` to throw |
| `Integer == Integer` | compares objects | `equals`, or unbox |
| `-7 / 2` | -3: rounds toward 0 | `Math.floorDiv` for -4 |
| `'a' + 1` | an `int` (98) | cast `(char)`; `c - 'a'` is an index |
| `(a, b) -> a - b` | overflow flips the order | `Integer.compare(a, b)` |
| `Math.abs(Integer.MIN_VALUE)` | still negative | use `long` |
| `list.remove(1)` on `List<Integer>` | removes index 1 | `remove(Integer.valueOf(1))` |
| Remove in for-each | `ConcurrentModificationException` | `removeIf`, `Iterator.remove` |
| `Arrays.asList`, `List.of` | add throws | `new ArrayList<>(...)` |

- See also [strings](card:strings) and [binary search](card:binary-search).

## Example

```java
int big = Integer.MAX_VALUE;
System.out.println(big + 1);               // overflow wraps around
long safe = (long) big + 1;                // 2147483648
Integer x = 1000, y = 1000;
System.out.println(x == y);                // two objects: cache covers -128..127 by default
System.out.println(x.equals(y));
List<Integer> nums = new ArrayList<>(List.of(1, 2, 3));
nums.removeIf(n -> n % 2 == 0);            // [1, 3], no exception
```

```text output
-2147483648
false
true
```

## Interview Qs

### Why can x == y be false for two Integer objects that hold 1000?

`==` compares references. Java shares boxed objects only for -128 to 127; 1000 may be boxed twice. Use `equals`.

### How do you remove items from a list while looping?

Use `removeIf` or an `Iterator` with `it.remove()`. `list.remove` inside a for-each usually throws `ConcurrentModificationException`; the check is best-effort, so never rely on it.
