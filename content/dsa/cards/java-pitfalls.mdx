## What it is

A Java pitfall is code that compiles and runs but quietly does the wrong thing. In coding rounds the usual ones are number limits, boxed numbers and collection rules. Boxing is Java wrapping an `int` in an `Integer` object so it can go into a collection; an `Integer` is an object, so comparing two of them with `==` checks whether they are the same object. Overflow is a result too big for its type, which wraps around instead of failing.

## Why it exists

These bugs pass the small example in the problem statement, so you believe the solution is done. They fail only on the hidden tests, with large values or many items, where you cannot see what went wrong. An `int` sum near 3 × 10^9, a count of 500 compared with `==`, a comparator fed large numbers: each gives a wrong answer with no exception. Knowing the list lets you avoid them while writing, not while debugging.

## How it works

| Pitfall | What happens | Fix |
| --- | --- | --- |
| Large `int` sum or product | wraps around silently | `long`, or `Math.addExact` to throw |
| `Integer == Integer` | compares objects | `equals`, or unbox to `int` |
| `-7 / 2` | -3: rounds toward 0 | `Math.floorDiv(-7, 2)` for -4 |
| `'a' + 1` | an `int` (98), not a char | cast `(char)`; `c - 'a'` is an index |
| `(a, b) -> a - b` | overflow flips the order | `Integer.compare(a, b)` |
| `Math.abs(Integer.MIN_VALUE)` | still negative | use `long` |
| `list.remove(1)` on `List<Integer>` | removes index 1, not value 1 | `remove(Integer.valueOf(1))` |
| Remove in for-each | `ConcurrentModificationException` | `removeIf`, `Iterator.remove` |
| `Arrays.asList`, `List.of` | `add` throws | copy: `new ArrayList<>(...)` |

1. Before writing a sum or product, check the [value range](card:constraints-to-complexity); if the result can pass about 2.1 × 10^9, declare it `long`.
2. When you compare values taken out of a collection, use `equals` or unbox them to `int` first.
3. When you write a comparator, use `Integer.compare` or `Comparator.comparingInt`, never subtraction.
4. When you remove while looping, use `removeIf`, or an explicit `Iterator` and its `remove`.
5. When a method gets a list from `Arrays.asList` or `List.of` and must change it, copy it into a new `ArrayList` first.

## Example

Four pitfalls and their fixes, run on Java 25.

```java
int big = Integer.MAX_VALUE;
System.out.println(big + 1);                    // wraps to the smallest int
long safe = (long) big + 1;                     // cast first, then add
Integer x = 1000, y = 1000;
System.out.println(x == y);                     // compares two objects
System.out.println(x.equals(y));                // compares the values
System.out.println(-7 / 2 + " " + Math.floorDiv(-7, 2));
List<Integer> nums = new ArrayList<>(List.of(1, 2, 3));
nums.removeIf(n -> n % 2 == 0);                 // safe removal while looping
System.out.println(nums + " " + safe);
```

```text output
-2147483648
false
true
-3 -4
[1, 3] 2147483648
```

What to notice:

- `big + 1` prints the most negative `int` with no error. `(long) big + 1` works because the cast happens before the addition; `(long) (big + 1)` would cast the already wrong result.
- `x == y` is false although both hold 1000, because 1000 was boxed into two objects. With 127 it would print true, which is why small tests hide this bug.
- `-7 / 2` drops the fraction toward zero; `floorDiv` rounds down, which is what you want for negative coordinates or buckets.
- `removeIf` removes the even number safely. Calling `nums.remove(...)` inside a for-each over `nums` would usually throw instead.

## Rules and defaults

- **Overflow:** `int` and `long` arithmetic that passes the type's limit wraps around with no exception. Only `Math.addExact`, `multiplyExact` and their siblings throw `ArithmeticException` instead.
- **Boxing cache:** Java must reuse the same `Integer` object for values from -128 to 127; outside that range, two boxings may give two objects.
- **Fail-fast is best-effort:** `ConcurrentModificationException` is thrown when the iterator notices the change, but this is not guaranteed, so never rely on it.
- **Fixed lists:** `Arrays.asList` allows `set` but not `add` or `remove`; `List.of` allows no changes and throws on `null` elements.

## Common mistakes

- **"Removing inside a for-each always throws, so I would notice."** Not always. In `[1, 2, 3]`, removing 2 inside the loop ends the loop early with no exception and silently skips 3.
- **"Casting the result to long fixes overflow."** The multiplication already happened in `int`. Make one operand `long` before the operation: `1_000_000L * 3_000`.

## Interview Qs

### Why can x == y be false for two Integer objects that both hold 1000?

`==` on objects compares references, not values. Java must share boxed objects only for -128 to 127, so 1000 may be boxed into two separate objects. Use `equals`, or unbox to `int` before comparing. The bug hides in small tests, where counts stay below 128.

### How do you remove items from a list while looping over it?

Use `list.removeIf(condition)`, or loop with an explicit `Iterator` and call `it.remove()`. Calling `list.remove` inside a for-each usually throws `ConcurrentModificationException`, but the check is best-effort, so the loop can also skip items silently.

### Why is (a, b) -> a - b a risky comparator?

For values far apart, such as 2 × 10^9 and -2 × 10^9, the subtraction overflows and wraps to the wrong sign, so the comparator reports the wrong order and the sort is wrong. `Integer.compare(a, b)` compares without subtracting, so it is always correct.
