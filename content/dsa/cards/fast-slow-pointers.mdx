## What it is

Fast and slow pointers is a [two pointers](card:two-pointers) pattern for [linked lists](card:linked-list). Both pointers start at the head; each turn, slow moves one node and fast moves two. A cycle is a loop: some node's `next` points back to an earlier node, so the list never ends. If there is a cycle, fast eventually lands on the same node as slow. This method is called Floyd's cycle detection.

## Why it exists

A linked list has no indices and no length you can read, so you cannot "look ahead" to see whether it loops. The obvious fix is to store every visited node in a HashSet and stop when one repeats, but that costs O(n) extra memory. Two pointers at different speeds detect the loop, find where it starts and find the middle, all with O(1) extra memory.

## How it works

1. Put slow and fast at the head.
2. Each turn, move slow one node and fast two nodes.
3. If fast or `fast.next` becomes null, the list has an end, so there is no cycle.
4. If slow and fast land on the same node, there is a cycle. Inside the loop, fast gains one node on slow every turn, so it cannot jump over it.
5. To find the start of the cycle, move one pointer back to the head and leave the other at the meeting node. Move both one node per turn; they meet at the first node of the cycle.

So the key is the speed difference of one node per turn: once both are in the cycle, the gap between them shrinks by one each turn until it is zero.

## Example

This returns the first node of the cycle, or null when there is none. Here it runs on the list in the picture, 1 to 6 with 6 linking back to 4.

```java
ListNode cycleStart(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;                    // one step
        fast = fast.next.next;               // two steps
        if (slow == fast) {                  // they met inside the cycle
            slow = head;                     // phase 2: restart one pointer
            while (slow != fast) { slow = slow.next; fast = fast.next; }
            return slow;                     // the first node of the cycle
        }
    }
    return null;                             // fast fell off the end: no cycle
}

System.out.println(cycleStart(head).val);    // head is node 1
```

```text output
4
```

What to notice:

- `fast != null && fast.next != null` comes before `fast.next.next`. Remove the second check and a list with an odd number of nodes throws a NullPointerException, because fast lands on the last node, where `fast.next` is null, so `fast.next.next` fails.
- `slow == fast` compares node references, not values. Two different nodes can hold the same value.
- If node 6 linked to null instead, the method would return null after three turns.

## Rules and defaults

- **Middle node:** run the same loop with no meeting check. When fast stops, slow is at the middle; for an even number of nodes this loop leaves slow on the second of the two middle nodes ([Middle of the Linked List](card:middle-of-linked-list)).
- **Not only lists:** any sequence where each value decides the next one can loop. [Happy Number](card:happy-number) repeats "sum of the squares of the digits" and uses the same two speeds to spot the loop.
- **Cost:** O(n) time and O(1) extra space for detection, the start and the middle.

## Interview Qs

### Why must the pointers meet if there is a cycle?

Once both are inside the cycle, fast gains exactly one node on slow per turn. So the distance between them goes down by one each turn and reaches zero within one lap; fast cannot skip past slow.

### How do you find where the cycle starts?

After the first meeting, put one pointer back at the head and keep the other at the meeting node. Move both one node per turn. The distance from the head to the start equals the distance from the meeting node forward to the start, plus some whole laps of the cycle, so they meet exactly at the start.

### How do you find the middle of a linked list in one pass?

Move slow one node and fast two nodes per turn. When fast reaches the end, slow has covered half the distance, so it is at the middle. No length count is needed.
