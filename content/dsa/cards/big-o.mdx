## Why it exists

Exact times depend on the machine. Big-O compares solutions by how work grows with input, before you code.

## How it works

| Big-O | Name | Typical shape |
|---|---|---|
| O(1) | constant | a direct formula, no loop |
| O(log n) | logarithmic | halve the input each step |
| O(n) | linear | one pass, or a fixed number of passes |
| O(n log n) | linearithmic | sort, or n steps of O(log n) |
| O(n²) | quadratic | all pairs (two nested loops) |
| O(n³) | cubic | all triplets |
| O(2ⁿ) | exponential | try every subset |
| O(n!) | factorial | try every ordering |

- log₂ n = how many halvings take n to 1: about 20 for a million.
- Every pending [recursive](card:recursion) call holds stack space.

## Example

```java
int count = 0;
for (int x : nums) count++;                 // O(n)
for (int i = 0; i < n; i++)                 // O(n²): all pairs
    for (int j = i + 1; j < n; j++) count++;
for (int s = n; s > 1; s /= 2) count++;     // O(log n): halves
// total O(n²): the slowest phase wins; extra space O(1)
```

## Interview Qs

### Why do we drop constants in Big-O?

Big-O describes growth, not exact time: 5n and n grow alike, and the real constant depends on the machine. Constants still matter between answers of the same order.

### What is the difference between space complexity and auxiliary space?

Space complexity usually counts all memory, input included. Auxiliary space is only what the algorithm adds, like a HashMap or the recursion stack. Say which you mean.
