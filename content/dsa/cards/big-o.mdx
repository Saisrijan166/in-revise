## What it is

Big-O notation describes how the cost of an algorithm grows as its input grows. The input size is called n, for example the length of an array. Cost means time, counted as the number of basic steps, or space, the extra memory used. O(n) means the steps grow in proportion to n; O(n²) means they grow with n times n. Big-O is an upper bound: the cost grows no faster than that.

## Why it exists

Timing a program in seconds depends on the machine, the language and the input, so two people get different numbers. You also want to judge an idea before you code it. Big-O counts steps as a function of n instead. With n = 100,000 an O(n²) solution needs about 10 billion steps, which is far too slow, while an O(n log n) one needs about 1.7 million. That comparison tells you which idea to build.

## How it works

| Big-O | Name | Typical shape in code |
|---|---|---|
| O(1) | constant | a formula or one array access, no loop |
| O(log n) | logarithmic | halve the input each step |
| O(n) | linear | one pass, or a fixed number of passes |
| O(n log n) | linearithmic | a good sort, or n steps that each cost O(log n) |
| O(n²) | quadratic | all pairs: a loop inside a loop |
| O(2ⁿ) | exponential | try every subset |
| O(n!) | factorial | try every ordering |

To find the Big-O of a piece of code:

1. Name the input size: n for one array; n and m for two independent inputs.
2. Count how often each part runs: a loop over the array runs n times; a loop that halves its counter runs about log₂ n times.
3. Combine the parts: add the costs of parts that run one after another, and multiply the costs of parts nested inside each other.
4. Keep the fastest-growing term and drop constant factors: 3n² + 5n + 2 becomes O(n²).
5. Do the same for memory: count the extra arrays and maps you create. A method that calls itself (you will see this in [recursion](card:recursion)) also holds some memory for each call that has not yet returned.

## Example

One method with three phases; each comment gives that phase's cost:

```java
static int work(int[] nums) {
    int n = nums.length, count = 0;
    for (int x : nums) count++;                 // n steps: O(n)
    for (int i = 0; i < n; i++)                 // all pairs: O(n²)
        for (int j = i + 1; j < n; j++) count++;
    for (int s = n; s > 1; s /= 2) count++;     // halving: O(log n)
    return count;                               // extra space: O(1)
}
System.out.println(work(new int[8]));      // 8 + 28 + 3
System.out.println(work(new int[1000]));   // 1000 + 499500 + 9
```

```text output
39
500509
```

What to notice:

- The phases run one after another, so the total is O(n + n² + log n), which simplifies to O(n²): the slowest phase decides.
- With n = 1,000 the pairs phase does 499,500 of the 500,509 steps. That is why the smaller terms are dropped.
- The method creates only two `int` variables, whatever n is, so its extra space is O(1).

## Rules and defaults

- **Constants are dropped:** 2n and n are both O(n). Constants still matter when you compare two answers of the same order.
- **Independent inputs keep their own letters:** O(n + m) for two arrays, O(V + E) for a graph's vertices and edges, O(L) for a word of length L.
- **Space complexity vs auxiliary space:** space complexity usually counts all memory, input included; auxiliary space counts only what the algorithm adds. Say which you mean.
- **Say which case you mean:** worst case is a limit no single call exceeds; average (expected) case is the typical cost; amortised cost is the average per operation over a long run, where one call may be slow (you will see it in [ArrayList](card:dynamic-array)).

## Not to be confused with

Big-O (O) is an upper bound: the cost grows at most this fast. Big-Omega (Ω) is a lower bound: it grows at least this fast. Big-Theta (Θ) is a tight bound: both at once. Interviews almost always ask for Big-O, so give the tightest upper bound you can. Rule: O = at most, Ω = at least, Θ = exactly this rate.

## Common mistakes

- **"Two nested loops are always O(n²)."** Only when both loop over n. An inner loop over a different input gives O(n·m), and an inner loop that halves gives O(n log n).
- **Forgetting the recursion stack.** A recursive method that goes n calls deep uses O(n) extra space, even if it creates no array.

## Interview Qs

### Why do we drop constants in Big-O?

Big-O describes how cost grows, not the exact time: 5n and n both double when n doubles, and the real constant depends on the machine and language. Constants still matter when two answers have the same Big-O, such as two O(n) solutions where one makes a single pass and the other makes three.

### What is the difference between space complexity and auxiliary space?

Space complexity usually counts all the memory used, including the input. Auxiliary space counts only the extra memory the algorithm adds, such as a HashMap or the recursion stack. Reversing an array in place has O(1) auxiliary space but O(n) space complexity, because the array itself holds n items.

### What is the time complexity of a loop that halves n each time?

O(log n). The loop runs as many times as n can be halved before it reaches 1, which is log₂ n times: about 20 for a million. Binary search has this shape.
