## What it is

Depth-first search (DFS) visits a graph by following one path as far as it can. When it reaches a vertex with no unvisited neighbour, it backs up to the last vertex that still has one and tries that branch. To remember the way back it needs a [stack](card:stack), a last-in-first-out pile, and usually that stack is the call stack of a [recursive](card:recursion) method. Like [BFS](card:bfs), it marks vertices visited so it never handles one twice.

## Why it exists

Many graph questions do not ask for the fewest steps, only whether things connect. Can city 0 reach city 5? How many separate groups are there? Is there a loop? In what order can tasks run? DFS answers all of these in O(V + E) with a few lines of recursion. Its two moments, entering a vertex and finishing it, are exactly what cycle checks and [topological sort](card:topological-sort) need.

## How it works

<Compare id="bfs-vs-dfs" />

1. Call `dfs(start)`. On entry, mark the vertex visited.
2. Loop over its neighbours. At the first unvisited one, call `dfs` on it at once, before looking at the remaining neighbours.
3. When a vertex has no unvisited neighbours left, its call returns. This return is the backtracking step: you are back at the vertex you came from, which continues its own loop.
4. To cover a graph that is not connected, loop over all vertices and start a new DFS from each one still unvisited. Each start explores one connected component.

So the key is: the recursion goes deeper before it goes wider.

## Example

DFS on the city graph from [Graphs and How to Store Them](card:graph-basics), recording the visit order and counting components.

```java
static void dfs(int u, List<List<Integer>> graph, boolean[] seen, List<Integer> order) {
    seen[u] = true;                                 // mark on entry
    order.add(u);
    for (int v : graph.get(u))
        if (!seen[v]) dfs(v, graph, seen, order);   // go deeper before the next neighbour
}

boolean[] seen = new boolean[n];
List<Integer> order = new ArrayList<>();
int components = 0;
for (int i = 0; i < n; i++)
    if (!seen[i]) { components++; dfs(i, graph, seen, order); }
System.out.println(order + " components=" + components);
```

```text output
[0, 1, 2, 4, 3, 5] components=1
```

What to notice:

- From 0 it goes to 1, from 1 to 2, from 2 to 4, and only then to 3 and 5. BFS finished both distance-1 cities, 1 and 2, before going further; DFS dives instead.
- DFS first reached city 4 by 0-1-2-4, three roads, although BFS showed it is two roads away by 0-2-4. DFS finds a path, not the shortest one.
- Remove the road `{3, 5}` and city 5 has no roads. The outer loop then starts a second DFS at 5 and prints `components=2`.

## Rules and defaults

- **Cycle, undirected graph:** reaching a visited neighbour that is not the vertex you came from (the parent) means a cycle.
- **Cycle, directed graph:** colour vertices white (not visited), grey (entered, still on the current path) and black (finished). An edge to a grey vertex is a cycle; an edge to a black one is not.
- **Deep graphs:** each recursive call uses a stack frame, so a very long path can throw `StackOverflowError`. Then use an explicit `ArrayDeque` as the stack; the Java docs call it likely faster than `Stack`.
- **Cost:** O(V + E) time with adjacency lists, O(V²) with a matrix; O(V) extra space for the marks and the stack.

## Not to be confused with

Preorder, inorder and postorder [tree traversals](card:tree-traversals) are DFS on a tree. A tree has no cycles and each node is reached from one parent, so those traversals need no visited mark. A graph can lead back to a vertex by many routes. Rule: tree DFS, no visited array; graph DFS, always a visited array.

## Common mistakes

- **"Reaching a visited vertex means a cycle."** True only in an undirected graph, and only when the visited vertex is not the parent. In a directed graph the vertex may already be finished; only an edge to a grey vertex is a cycle.

## Interview Qs

### BFS or DFS: how do you choose?

For fewest steps in an unweighted graph, BFS, because it reaches vertices in order of distance. For reachability, components, cycle checks, topological order or exploring every path, DFS, which is shorter to write with recursion. Both cost O(V + E). On a very deep graph, recursive DFS risks a stack overflow; on a very wide one, BFS's queue grows large.

### How do you detect a cycle in a directed graph?

Run DFS with three colours. Mark a vertex grey when you enter it and black when its call returns. If you meet an edge to a grey vertex, it leads back into the current path, so there is a cycle. An edge to a black vertex is safe, because that vertex's search is already finished.

### Why can recursive DFS crash in Java, and how do you avoid it?

Each call takes a frame on the thread's stack, which has a fixed size. A path through a very large graph, such as a long chain, needs one frame per vertex and can throw `StackOverflowError`. Replace the recursion with a loop and an explicit `ArrayDeque` stack, which lives on the heap.
