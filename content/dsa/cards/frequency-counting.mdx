## Why it exists

Searching the array again for each item is O(n²). Remembering what you have seen in a hash table answers "have I seen this?" in O(1) on average.

## How it works

<Steps label="Two Sum in one pass">
  <Step title="Read x">Work out `need = target - x`.</Step>
  <Step title="Look up">If `need` is in the map, return its index and the current one.</Step>
  <Step title="Record">Store `x → index`, then read the next item.</Step>
</Steps>

- Anagrams have the same letter counts. [Group them](card:group-anagrams) by a key: the sorted letters.
- Java idioms (`merge`, `getOrDefault`): see [HashMap and HashSet](card:hashmap-hashset).

## Example

```java
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // value -> index
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);     // look up first
        if (j != null) return new int[] {j, i};
        seen.put(nums[i], i);                       // then record
    }
    return new int[0];
}
```

## Interview Qs

### In Two Sum, why look up before storing?

So an item never pairs with itself: with target 6, a single 3 must not count. [3, 3] still works: the first 3 is stored when the second arrives.

### How do you check that two strings are anagrams?

Count letters in an `int[26]`: add for the first string, subtract for the second; all zeros means an anagram. O(n) time and O(1) space. Sorting both strings also works, in O(n log n).
