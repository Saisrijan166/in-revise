## What it is

Counting with a HashMap is a pattern where one pass over the input remembers what it has seen. A frequency map stores each value with the number of times it appeared, such as each word with its count. A "seen" map stores each value with where it appeared, its index. Both rely on a [HashMap](card:hashmap-hashset) answering "is this key here?" in O(1) on average.

## Why it exists

Without a map, "have I seen this before?" means scanning everything before the current item, so the whole job costs O(n²). For Two Sum on 100,000 numbers that is billions of comparisons. Storing each item in a map as you pass it turns every later check into one lookup. You pay with O(n) extra memory, which is usually a good trade.

## How it works

Two Sum on the unsorted `nums = [11, 15, 2, 7]` with target 9, storing value → index:

| i | x | Need 9 - x | In the map? | Map after |
|---|---|---|---|---|
| 0 | 11 | -2 | no | `{11: 0}` |
| 1 | 15 | -6 | no | `{11: 0, 15: 1}` |
| 2 | 2 | 7 | no | `{11: 0, 15: 1, 2: 2}` |
| 3 | 7 | 2 | yes, at index 2 | return [2, 3] |

1. Read the next item `x`.
2. Work out what you need from the past; here the partner `target - x`.
3. Look it up in the map. If it is there, you have the answer.
4. Only then record `x` in the map, for the items still to come.
5. Move to the next item.

So the key is the order: look up first, then record. For plain counting, step 3 disappears and step 4 becomes "add one to the count of x".

## Example

This is the trace above as code. The array is not sorted, which [two pointers](card:two-pointers) would need.

```java
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // value -> its index
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);     // 1. look up the partner
        if (j != null) return new int[] {j, i};
        seen.put(nums[i], i);                       // 2. then record this value
    }
    return new int[0];                              // no pair
}

System.out.println(Arrays.toString(twoSum(new int[] {11, 15, 2, 7}, 9)));
```

```text output
[2, 3]
```

What to notice:

- `j` is an `Integer`, not an `int`: `get` returns null for a missing key, and unboxing null into an `int` would throw a NullPointerException.
- Swap the two steps, recording before looking up, and `twoSum([3], 6)` pairs 3 with itself. In the given order, `[3, 3]` still returns `[0, 1]`.
- The map stores indices because Two Sum asks for positions. To count, store counts instead, with `merge(x, 1, Integer::sum)`.

## Rules and defaults

- **Use it when:** the question says count, duplicate, unique, anagram, most frequent, or "find a pair" in data that is not sorted.
- **Fixed small alphabet:** for lowercase letters use `int[26]` with `c - 'a'` as the index; for ASCII use `int[128]`. This is O(1) space.
- **Duplicates only:** a [HashSet](card:hashmap-hashset) is enough; `set.add(x)` returns false when x is already there (Contains Duplicate).
- **Grouping:** to group words that are anagrams, use a key that is the same for all of them, such as the sorted letters, and map key → list of words ([Group Anagrams](card:group-anagrams)).
- **Cost:** O(1) average per lookup, so O(n) average for the pass. It is not a worst-case guarantee.

## Interview Qs

### In Two Sum, why look up before storing?

So an item never pairs with itself. With target 6 and a single 3, storing first would find that same 3. With the lookup first, the map holds only earlier items, and `[3, 3]` still works because the first 3 is stored when the second one arrives.

### How do you check that two strings are anagrams?

If the lengths differ, they are not. Otherwise count letters in an `int[26]`: add one for each letter of the first string and subtract one for each letter of the second. All zeros means an anagram. O(n) time and O(1) space; sorting both strings also works, in O(n log n).

### HashMap gives O(n), sorting gives O(n log n). Why would you ever sort?

Sorting the input in place needs no map, so it uses far less extra memory, and it puts equal items next to each other for later steps. The HashMap is faster on average but uses O(n) memory. Say which one the interviewer's constraints favour.
