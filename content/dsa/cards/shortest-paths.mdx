## Why it exists

When edges have costs, the fewest edges is not always the cheapest route. These algorithms add up weights instead.

## How it works

<Mermaid
  alt="Choosing an algorithm: equal edge costs, BFS; every pair on a small graph, Floyd-Warshall; any negative weight, Bellman-Ford; otherwise Dijkstra."
  chart={`flowchart TD
  Q{All edges cost the same?} -- yes --> B[BFS]
  Q -- no --> P{Every pair, small graph?}
  P -- yes --> F[Floyd-Warshall]
  P -- no --> N{Any negative weight?}
  N -- yes --> BF[Bellman-Ford]
  N -- no --> D[Dijkstra]`}
/>

- **Relax** edge u → v: if `dist[u] + w < dist[v]`, lower `dist[v]`. Dijkstra, Bellman-Ford and Floyd-Warshall are built on this step.
- Java's `PriorityQueue` has no decrease-key: push a new entry, skip stale ones.

## Example

```java
// graph.get(u) holds {v, weight}; dist starts at MAX_VALUE, dist[src] = 0
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
pq.offer(new int[] {src, 0});
while (!pq.isEmpty()) {
    int[] top = pq.poll();
    int u = top[0];
    if (top[1] > dist[u]) continue;              // stale entry
    for (int[] e : graph.get(u)) {
        int v = e[0], nd = dist[u] + e[1];
        if (nd < dist[v]) { dist[v] = nd; pq.offer(new int[] {v, nd}); }
    }
}
```

## Interview Qs

### Why does Dijkstra fail with negative weights?

It treats a vertex as final once it leaves the heap. A negative edge found later could still make it cheaper.

### What is a negative cycle?

A cycle whose weights sum below zero. Each extra lap lowers the cost, so no shortest path exists. Bellman-Ford detects it.
