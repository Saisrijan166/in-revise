## What it is

A shortest path is the route between two vertices of a weighted graph whose edge weights add up to the least total, such as the fastest route between two cities. [BFS](card:bfs) already finds the fewest edges when every edge costs the same. When costs differ you need an algorithm that adds weights. Dijkstra's algorithm handles non-negative weights, Bellman-Ford allows negative ones, and Floyd-Warshall finds every pair at once.

## Why it exists

On the city graph, BFS says city 1 is one road from city 0, but that road takes 4 hours, while 0-2-1 takes 3. Counting roads gives the wrong answer as soon as roads differ, and trying every path takes exponential time. Dijkstra finds the cheapest time from one city to all others in O((V + E) log V), using a [min-heap](card:heap-priority-queue) to always pick the closest city next.

## How it works

Dijkstra, step by step:

1. Set `dist[start] = 0` and every other distance to "not reached". Put `{start, 0}` in a min-heap ordered by distance.
2. Poll the entry with the smallest distance. If it is larger than that vertex's current `dist`, it is an old entry left behind by an update; skip it.
3. Otherwise the vertex is settled. Every other route to it would pass through a vertex at least as far away, and with no negative weights that route cannot be cheaper.
4. Relax each edge u → v with weight w: if `dist[u] + w < dist[v]`, lower `dist[v]` and push `{v, dist[v]}`.
5. Repeat until the heap is empty.

So the key is: always expand the closest unsettled vertex next.

## Example

Dijkstra from city 0. Each road now has its travel time: 0-1 takes 4, 0-2 1, 1-2 2, 1-3 5, 2-4 8, 3-4 3 and 3-5 6. `graph.get(u)` holds `{neighbour, time}` pairs.

```java
int[] dist = new int[n];
Arrays.fill(dist, Integer.MAX_VALUE);               // not reached yet
dist[0] = 0;
PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> Integer.compare(x[1], y[1]));
pq.offer(new int[] {0, 0});                         // {city, time so far}
while (!pq.isEmpty()) {
    int[] top = pq.poll();
    int u = top[0];
    if (top[1] > dist[u]) continue;                 // stale entry: skip it
    for (int[] e : graph.get(u)) {                  // e = {neighbour, time}
        int v = e[0], nd = dist[u] + e[1];
        if (nd < dist[v]) { dist[v] = nd; pq.offer(new int[] {v, nd}); }
    }
}
System.out.println(Arrays.toString(dist));
```

```text output
[0, 3, 1, 8, 9, 14]
```

What to notice:

- `dist[1]` is 3, by 0-2-1, not 4 by the direct road. City 1 was pushed twice, first with 4 and then with 3; the `continue` line skips the old `{1, 4}` entry.
- `dist[4]` is 9, by 0-2-4, rather than 11 by 0-2-1-3-4.
- Java's `PriorityQueue` has no method to lower the priority of an entry already inside it (no decrease-key), so the code pushes a new entry and skips stale ones. Without the stale check the answer stays correct, but the run can slow down to O(V·E).

## Rules and defaults

- **Dijkstra:** non-negative weights only; O((V + E) log V) with a binary heap.
- **Bellman-Ford:** relax every edge in V - 1 rounds, O(V·E). If one more round still lowers a distance, a negative cycle is reachable from the start. It can stop early when a round changes nothing.
- **Floyd-Warshall:** every pair in O(V³). Negative edges are fine; negative cycles are not.
- **Weights only 0 or 1:** 0-1 BFS puts 0-weight edges at the front of a deque and 1-weight edges at the back, giving O(E).

## Not to be confused with

Dijkstra settles the closest vertex each time, which is fast but needs non-negative weights. Bellman-Ford relaxes every edge in rounds, which is slower but survives negative weights and reports negative cycles. Rule: no negative weight, Dijkstra; any negative weight, Bellman-Ford.

## Common mistakes

- **"Integer.MAX_VALUE is a safe infinity."** Adding a weight to it overflows to a negative number. Only relax from a vertex whose `dist` is finite; Dijkstra does this naturally, Bellman-Ford needs an explicit check.

## Interview Qs

### Why does Dijkstra fail with negative weights?

It treats a vertex as final once it leaves the heap. With edges A→B 2, A→C 3 and C→B -2, it settles B at 2 first, because B is the closest. The cheaper route A-C-B costs 1, but the classic algorithm never revisits a settled vertex, so it misses it.

### Why do we need Bellman-Ford if Dijkstra is faster?

Dijkstra's speed comes from assuming that the closest vertex can never get cheaper, which breaks with negative weights. Bellman-Ford makes no such assumption: it relaxes every edge V - 1 times, enough for any shortest path. It costs O(V·E), but it handles negative weights and can prove a negative cycle exists.

### What is a negative cycle, and why does it break shortest paths?

A cycle whose weights add up to less than zero. Each extra lap round it lowers the total, so the cost can fall forever and no shortest path exists. Bellman-Ford detects one: if any edge still relaxes after V - 1 rounds, a negative cycle is reachable from the start.
