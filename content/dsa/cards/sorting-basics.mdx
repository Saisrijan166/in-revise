## Why it exists

Sorted data enables binary search, duplicate checks and two-pointer scans. Interviews ask a sort's cost more than its code.

## How it works

| Sort | Best | Average | Worst | Extra space | Stable |
| --- | --- | --- | --- | --- | --- |
| [Bubble](card:bubble-sort) | O(n) | O(n²) | O(n²) | O(1) | Yes |
| [Selection](card:selection-sort) | O(n²) | O(n²) | O(n²) | O(1) | No |
| [Insertion](card:insertion-sort) | O(n) | O(n²) | O(n²) | O(1) | Yes |
| [Merge](card:merge-sort) | O(n log n) | O(n log n) | O(n log n) | O(n) | Yes |
| [Quick](card:quick-sort) | O(n log n) | O(n log n) | O(n²) | O(log n) avg | No |
| [Heap](card:heap-sort) | O(n log n) | O(n log n) | O(n log n) | O(1) | No |

- Bubble sort's O(n) best needs an early exit after a swap-free pass.
- Insertion sort is linear on nearly sorted input.

## Example

```java
record Student(String name, int marks) { }
List<Student> list = new ArrayList<>(List.of(
    new Student("Asha", 90), new Student("Ravi", 80), new Student("Meera", 90)));
list.sort(Comparator.comparingInt(Student::marks).reversed());
System.out.println(list.stream().map(Student::name).toList());
// Stable: Asha stays before Meera (both 90)
```

```text output
[Asha, Meera, Ravi]
```

## Interview Qs

### What is a stable sort, and when does it matter?

Equal keys keep their input order. Sort by name, then stably by marks, and equal marks stay in name order.

### Can any sort beat O(n log n)?

Not by comparing items. Counting sort runs in O(n + k) for integer keys in 0..k-1, because it uses keys as array indexes.
