## What it is

Sorting puts items in order by a key, the value you sort by, such as a student's marks. Two words describe how a sort behaves. A stable sort keeps items with equal keys in the order they had in the input. An in-place sort works inside the input array and needs only a little extra memory, O(1) or O(log n). Each sort is judged by its time, its extra space and whether it is stable.

## Why it exists

Many problems become easy once the data is sorted. [Binary search](card:binary-search) needs it, duplicates end up next to each other, and overlapping ranges line up. Interviewers rarely ask you to code bubble sort. They ask which sort fits, what it costs, whether it is stable and what Java's sort does. This table answers those questions, and the next two concepts show the two sorts asked about most.

## How it works

| Sort | Best | Average | Worst | Extra space | Stable |
| --- | --- | --- | --- | --- | --- |
| [Bubble](card:bubble-sort) | O(n) | O(n²) | O(n²) | O(1) | Yes |
| [Selection](card:selection-sort) | O(n²) | O(n²) | O(n²) | O(1) | No |
| [Insertion](card:insertion-sort) | O(n) | O(n²) | O(n²) | O(1) | Yes |
| [Merge](card:merge-sort) | O(n log n) | O(n log n) | O(n log n) | O(n) | Yes |
| [Quick](card:quick-sort) | O(n log n) | O(n log n) | O(n²) | O(log n) average | No |
| [Heap](card:heap-sort) | O(n log n) | O(n log n) | O(n log n) | O(1) | No |

1. The simple sorts fix one item per pass. Bubble sort swaps out-of-order neighbours, selection sort picks the smallest remaining item, and insertion sort slides each item left into the sorted part. Up to n passes of up to n steps give O(n²).
2. Insertion sort's slides are short when the input is nearly sorted, so its best case is O(n).
3. Merge, quick and heap sort split the work into about log n levels with O(n) work per level, so they reach O(n log n).
4. No sort that only compares pairs of items can beat about n log n compares in the worst case. Counting sort beats it only by using the values themselves as array indexes.

## Example

Sorting students by marks, highest first, then sorting an `int[]`.

```java
record Student(String name, int marks) { }

List<Student> list = new ArrayList<>(List.of(
    new Student("Asha", 90), new Student("Ravi", 80), new Student("Meera", 90)));
list.sort(Comparator.comparingInt(Student::marks).reversed());   // stable
System.out.println(list.stream().map(Student::name).toList());

int[] nums = {15, 2, 11, 7};
Arrays.sort(nums);                                                // ascending, in place
System.out.println(Arrays.toString(nums));
```

```text output
[Asha, Meera, Ravi]
[2, 7, 11, 15]
```

What to notice:

- Asha and Meera both have 90 and keep their input order, Asha first, because `List.sort` is guaranteed stable.
- `.reversed()` flips the comparison so high marks come first. It does not reverse the list afterwards, so equal marks still keep their input order.
- `Arrays.sort(nums)` changes the array itself and returns nothing. There is no comparator version for `int[]`, so a descending `int[]` needs another step.

## Rules and defaults

- **Primitive arrays (Java SE 25):** `Arrays.sort(int[])` uses Dual-Pivot Quicksort, which the API note says offers O(n log n) on all data sets. Stability does not matter here: two equal ints cannot be told apart.
- **Objects (Java SE 25):** `Arrays.sort(Object[])`, `List.sort` and `Collections.sort` are guaranteed stable. The implementation is an adaptive merge sort adapted from TimSort: about n compares on nearly sorted input, and up to n/2 extra references on random input.
- **Bubble sort's O(n) best case** needs an early exit after a pass with no swaps. Without it, bubble sort is O(n²) even on sorted input.
- **Counting sort:** sorts integers in 0..k-1 in O(n + k) and is stable. Radix sort repeats it digit by digit.

## Not to be confused with

A stable sort keeps equal keys in their input order; that is about the result. An in-place sort uses almost no extra memory; that is about cost. A sort can have one, both or neither. Rule: stable answers "is the order of ties kept?", in place answers "does it need a second array?".

## Interview Qs

### What is a stable sort, and when does it matter?

A stable sort keeps items with equal keys in their input order. It matters when you sort by a second key: sort by name first, then stably by marks, and students with equal marks stay in name order. With an unstable sort, the name order among ties can be lost.

### Can any sort beat O(n log n)?

Not by comparing pairs: a comparison sort needs about n log n compares in the worst case. Counting sort runs in O(n + k) for integer keys in 0..k-1, because it uses each key as an array index. It only pays off when k is not much larger than n.

### Which algorithm does Java's Arrays.sort use?

For primitive arrays, a Dual-Pivot Quicksort. For object arrays and `List.sort`, a stable, TimSort-based merge sort. Objects need stability, because two equal objects can still differ in other fields; the API requires the object sort to be stable. For primitives, equal values are identical, so stability adds nothing.
