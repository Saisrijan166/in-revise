## Why it exists

"Seen it before?" and "how many times?" become one pass with a HashMap or HashSet, not nested loops.

## How it works

<Steps label="map.put(key, value)">
  <Step title="Hash">Call `key.hashCode()` and turn it into a bucket index.</Step>
  <Step title="Compare">Check keys in that bucket with `equals`.</Step>
  <Step title="Store">Same key: replace the value. New key: add an entry.</Step>
  <Step title="Grow">Entries over capacity × 0.75: about double the buckets and rehash.</Step>
</Steps>

- OpenJDK (JDK 8+) turns a long bucket into a balanced tree: heavy collisions cost O(log n).

## Example

```java
Map<String, Integer> count = new HashMap<>();
for (String w : words) {
    count.merge(w, 1, Integer::sum);          // +1 per word
}
int n = count.getOrDefault("java", 0);
Map<Integer, List<String>> byLen = new HashMap<>();
for (String w : words) {
    byLen.computeIfAbsent(w.length(), k -> new ArrayList<>()).add(w);
}
Set<Integer> seen = new HashSet<>();
boolean isNew = seen.add(42);                 // false if already present
```

| What | Default | Where |

## Interview Qs

### What happens if you override equals but not hashCode?

Equal keys can get different hash codes and land in different buckets, so `get` misses them and a set can hold duplicates.

### HashMap vs HashSet?

HashMap stores a value per unique key; HashSet stores unique items only, as the keys of an inner HashMap.
