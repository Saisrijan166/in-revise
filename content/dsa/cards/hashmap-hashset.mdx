## What it is

`HashMap<K, V>` is Java's [hash table](card:hashing): it maps each unique key to one value, such as a word to its count. `HashSet<E>` stores unique items with no values; inside, it is a `HashMap` whose keys are the items. Both rely on two methods of the key: `hashCode()`, which returns the number used to choose a bucket, and `equals()`, which decides whether two keys are the same.

## Why it exists

Questions like "have I seen this number before?" or "how many times does each word appear?" need a lookup inside a loop. Scanning a list for every item makes the loop O(n²). A `HashSet` answers "seen?" and a `HashMap` answers "what is stored for this key?" in O(1) on average, so the whole task becomes one O(n) pass. You get the speed without writing a hash table yourself.

## How it works

<Steps label="map.put(key, value)">
  <Step title="Hash">`key.hashCode()` → bucket index.</Step>
  <Step title="Compare">`equals` against the keys in that bucket.</Step>
  <Step title="Store">Equal key: replace the value. None: add an entry.</Step>
  <Step title="Grow">Entries over capacity × 0.75: double the buckets.</Step>
</Steps>

1. `put(key, value)` computes `key.hashCode()` and reduces it to a bucket index.
2. It compares the key with the entries in that bucket using `equals`: the hash code only narrows the search.
3. If an equal key exists, its value is replaced and the old value is returned. Otherwise a new entry is added and `put` returns `null`.
4. `get(key)` repeats steps 1 and 2 and returns the value, or `null` if no equal key is in the bucket.
5. `HashSet.add(x)` does the same with `x` as a key of its inner map.

So the key is: a correct `hashCode` sends equal keys to the same bucket, and `equals` picks the right one there.

## Example

A record is used as a key, because records get `equals` and `hashCode` from their fields (Java 16+):

```java
record Cell(int row, int col) {}                     // a record gets equals and hashCode
Map<Cell, String> board = new HashMap<>();
board.put(new Cell(0, 1), "X");
System.out.println(board.get(new Cell(0, 1)));      // an equal key finds the entry
System.out.println(board.put(new Cell(0, 1), "O")); // same key: returns the old value
System.out.println(board.get(new Cell(2, 2)));      // missing key: null
Map<String, Integer> count = new HashMap<>();
for (String w : List.of("go", "java", "go")) count.merge(w, 1, Integer::sum);
System.out.println(count.getOrDefault("go", 0) + " " + count.getOrDefault("rust", 0));
Set<Integer> seen = new HashSet<>();
System.out.println(seen.add(7) + " " + seen.add(7)); // second add: 7 is already there
```

```text output
X
X
null
2 0
true false
```

What to notice:

- `get(new Cell(0, 1))` finds the entry although it is a different object, because the record's `equals` and `hashCode` compare the fields. A plain class with only `equals` printed `null` in the same test.
- The second `put` replaced `X` with `O` and returned the old `X`. A map never holds the same key twice.
- `merge(w, 1, Integer::sum)` stores 1 for a new word and adds 1 otherwise. `count.put(w, count.get(w) + 1)` would throw `NullPointerException` for a new word, because `get` returns `null`.
- `seen.add(7)` returned `true`, then `false`: one call both checks and records. You will use this in [counting with a HashMap](card:frequency-counting).

## Rules and defaults

| What | Default | Where |
|---|---|---|
| Initial capacity | 16 buckets | Java SE 25 API, `HashMap` and `HashSet` |
| Load factor | 0.75: grow when entries exceed capacity × 0.75 | Java SE 25 API, `HashMap` and `HashSet` |

- **Contract:** if `a.equals(b)`, then `a.hashCode() == b.hashCode()`. Unequal keys may share a hash code; that only slows lookups.
- **Mutable keys:** if a key's fields change while it is in the map, the map's behaviour is not specified; usually the key cannot be found again. Use keys that do not change, such as `String`, `Integer` or records.
- **null from get:** it can mean "no such key" or "the key maps to null"; `containsKey` tells them apart.
- **Collisions in OpenJDK (JDK 8+):** a bucket that grows past 8 entries becomes a balanced tree if the table has at least 64 buckets (a smaller table doubles instead), so heavy collisions on `Comparable` keys cost O(log n), not O(n).
- **Set algebra changes the set:** `a.addAll(b)` is union, `a.retainAll(b)` intersection, `a.removeAll(b)` difference, all in place on `a`. Copy `a` first to keep it.
- **Handy methods (Java 8+):** `getOrDefault`, `merge` and `computeIfAbsent(key, k -> new ArrayList<>())`, which creates a list the first time a key is seen.

## Not to be confused with

- **HashMap vs HashSet:** a `HashMap` stores a value for each key; a `HashSet` stores only the items. Rule: need a count or an index per key → `HashMap`; need only "seen or not" → `HashSet`.
- **Hashtable:** an old synchronised map that rejects null keys and values. The Java docs recommend `HashMap` for one thread and `ConcurrentHashMap` for many.
- **Ordered maps:** iteration order of a `HashMap` can look sorted for small integer keys, but it is not defined. `LinkedHashMap` and `TreeMap` add a real order; see the [next concept](card:ordered-maps-sets).

## Interview Qs

### How does HashMap work internally?

It keeps an array of buckets. `put` computes the key's `hashCode`, turns it into a bucket index, then compares the keys in that bucket with `equals`: an equal key gets its value replaced, otherwise a new entry is added. When entries exceed capacity × load factor (16 × 0.75 by default), the array doubles and every entry is re-placed.

### What happens if you override equals but not hashCode?

Two equal keys usually get different hash codes, so they land in different buckets. `get` with an equal key looks in the wrong bucket and returns `null`, and a `HashSet` can hold two "equal" items. The `Object` contract says equal objects must have equal hash codes, so override both.

### Why should HashMap keys be immutable?

The bucket is chosen from the key's hash code when you `put` it. If the key's fields change afterwards, its hash code changes, and a later `get` searches a different bucket and misses the entry, although it is still in the map. Strings, wrapper types and records with immutable fields avoid this.
