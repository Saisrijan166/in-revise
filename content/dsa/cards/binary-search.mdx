## Why it exists

A scan of a million items needs a million checks. On sorted data each middle check drops half, so about 20 are enough.

## How it works

| lo..hi | mid | nums[mid] | Next |
| --- | --- | --- | --- |
| 0..6 | 3 | 12 < 23 | lo = 4 |
| 4..6 | 5 | 23 = 23 | found |

Searching `[2, 5, 8, 12, 16, 23, 38]` for 23.

- If the target exists, it lies between `lo` and `hi`. Stop when `lo > hi`.
- For duplicates, use the [lower bound](card:lower-bound): on a match, keep searching left.

## Example

```java
int search(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

## Interview Qs

### Why mid = lo + (hi - lo) / 2 and not (lo + hi) / 2?

On huge arrays lo + hi can pass the int maximum and turn negative, giving a bad index. lo + (hi - lo) / 2 cannot overflow; `(lo + hi) >>> 1` also works.

### How do you find the first occurrence of a value?

Lower bound: when `nums[mid] >= target`, record mid and set `hi = mid - 1`; else `lo = mid + 1`. The last recorded index is the answer, if it holds the target.
