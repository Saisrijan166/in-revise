## What it is

Binary search finds a value in a sorted array by looking at the middle item and throwing away the half that cannot contain the value. Sorted means every item is less than or equal to the next one, and that order is what tells you which half to drop. The search keeps two indexes, `lo` and `hi`, around the part still to be searched, and each step halves that part.

## Why it exists

Without it you check items one by one from the start, which is linear search: up to n checks, so a million items can take a million checks. Binary search on a million sorted items needs about 20 checks, because halving a million 20 times leaves one item. The price is that the data must be sorted first, and an [array](card:arrays) must stay sorted when you add to it.

## How it works

Searching `nums = [2, 7, 11, 15, 20, 26, 31]` for 26:

| Step | lo..hi | mid | nums[mid] | Decision |
| --- | --- | --- | --- | --- |
| 1 | 0..6 | 3 | 15 < 26 | 26 can only be right: lo = 4 |
| 2 | 4..6 | 5 | 26 = 26 | found at index 5 |

1. Set `lo = 0` and `hi = 6`, the first and last index. If 26 is in the array, it lies between them.
2. Compute `mid = lo + (hi - lo) / 2 = 3`. `nums[3]` is 15, smaller than 26, so everything from index 0 to 3 is too small: set `lo = mid + 1 = 4`.
3. Compute `mid = 5`. `nums[5]` is 26, so return 5.
4. If the target is missing, the range keeps shrinking until `lo` passes `hi`; then the loop stops and reports "not found". Searching for 9 ends with `lo = 2`, the index where 9 would go.

So the key is the rule kept at every step: if the target is in the array, it is between `lo` and `hi`.

## Example

A loop version of the search, checked against Java's built-in `Arrays.binarySearch`.

```java
static int search(int[] nums, int target) {
    int lo = 0, hi = nums.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;          // no int overflow
        if (nums[mid] == target) return mid;
        if (nums[mid] < target) lo = mid + 1;  // drop the left half
        else hi = mid - 1;                     // drop the right half
    }
    return -1;                                 // lo passed hi: not found
}

int[] nums = {2, 7, 11, 15, 20, 26, 31};
System.out.println(search(nums, 26) + " " + search(nums, 9));
System.out.println(Arrays.binarySearch(nums, 9));
```

```text output
5 -1
-3
```

What to notice:

- `lo <= hi`, not `lo < hi`: with `<`, a range of one item is never checked, so a target in the last remaining slot is missed.
- `mid + 1` and `mid - 1` skip the item just checked. Writing `lo = mid` can loop forever when `lo` and `hi` are neighbours, because `mid` then equals `lo`.
- `(lo + hi) / 2` breaks when `lo + hi` passes `Integer.MAX_VALUE`, about 2.1 billion: the sum turns negative. `lo + (hi - lo) / 2` never exceeds `hi`.
- `Arrays.binarySearch` returns -3 for 9, not -1: 9 would go at index 2, and the result is -(2) - 1.

## Rules and defaults

- **Sorted input:** if the array is not sorted, the result of `Arrays.binarySearch` is undefined (Java SE 25 API). It does not check.
- **Return value:** the index if found, else -(insertion point) - 1. The insertion point is the index of the first item greater than the key, or the length if there is none. So the result is 0 or more exactly when the key was found.
- **Duplicates:** with several equal items, Java gives no guarantee which index it returns.
- **Lower and upper bound:** lower bound is the first index whose value is at least the target; upper bound is the first index whose value is greater. Together they mark all copies of the target.
- **Lists:** `Collections.binarySearch` runs in O(log n) on a random-access list such as `ArrayList`. On a large `LinkedList` it makes O(n) link steps, because reaching the middle means walking to it.

## Not to be confused with

Linear search checks items one by one and works on any data, sorted or not, in O(n). Binary search checks the middle of a sorted range and drops half each time, in O(log n). Rule: one search in unsorted data, scan it; many searches in data that rarely changes, sort once and then use binary search.

## Common mistakes

- **"Binary search works on any array."** On unsorted data, comparing with the middle item says nothing about where the target is, so the search can drop the half that holds it. Sort first, or use a scan or a `HashSet`.

## Interview Qs

### Why mid = lo + (hi - lo) / 2 and not (lo + hi) / 2?

When both indexes are large, `lo + hi` can pass the largest int and turn negative, giving an invalid index. `lo + (hi - lo) / 2` only adds half the gap to `lo`, so it stays in range. `(lo + hi) >>> 1` also works. This bug sat in the JDK's own binary search for years.

### How do you find the first occurrence of a value with duplicates?

Use lower bound. When `nums[mid] >= target`, record `mid` and set `hi = mid - 1` to look further left; otherwise set `lo = mid + 1`. At the end, the last recorded index is the first position whose value is at least the target; check that it holds the target.

### Can you use binary search when there is no sorted array?

Yes, if you can ask a yes/no question whose answer switches from no to yes only once as a number grows, such as "can we finish in x hours?". Binary search then finds the smallest x that says yes. You will see this in [binary search on the answer](card:binary-search-on-answer).
