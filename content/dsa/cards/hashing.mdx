## What it is

A hash table stores keys, often with a value for each, in an [array](card:arrays) of slots called buckets. A hash function is a calculation that turns a key into a number; the table reduces that number to a bucket index. The same key always gives the same index, so finding a key means computing its index and looking in that one bucket. A collision is when two different keys get the same index.

## Why it exists

To check whether 15 is in an unsorted array, you scan every item, which is O(n). Sorting helps, but then each insert must keep the order. A hash table answers "is this key here, and what is its value?" by jumping straight to the right bucket, so the work does not grow with the number of keys. It pays for that speed with extra memory, some empty buckets, and with no useful order.

## How it works

1. To insert a key, compute its hash and reduce it to a bucket index, here `key % 8`.
2. If the bucket already holds other keys, that is a collision. With separate chaining, the bucket keeps a small list and the new key joins it; with open addressing, the table probes other slots for a free one.
3. To look a key up, compute the same index, go to that bucket and compare the key with the few keys there.
4. When the load factor, keys divided by buckets, passes a limit, the table creates more buckets (Java's `HashMap` about twice as many) and places every key again. This is rehashing, and it keeps buckets short.

So the key is: a good hash spreads keys so each bucket holds only a few, which makes every operation O(1) on average.

## Example

A tiny chaining table with 8 buckets stores the running example `nums = [2, 7, 11, 15]`:

```java
int[] nums = {2, 7, 11, 15};
List<List<Integer>> buckets = new ArrayList<>();
for (int i = 0; i < 8; i++) buckets.add(new ArrayList<>());   // 8 empty buckets
for (int x : nums) {
    int index = x % 8;                       // hash function: key mod bucket count
    buckets.get(index).add(x);               // chaining: each bucket keeps a list
}
System.out.println(buckets);
int key = 15;
List<Integer> bucket = buckets.get(key % 8); // jump to one bucket
System.out.println(bucket.contains(key));    // scan only that bucket's list
```

```text output
[[], [], [2], [11], [], [], [], [7, 15]]
true
```

What to notice:

- 7 and 15 share bucket 7: a collision. The lookup of 15 compared two keys, not all four.
- The load factor here is 4 keys ÷ 8 buckets = 0.5, so most buckets are empty. Fewer buckets would mean longer lists.
- The buckets print in index order, not insertion order: a hash table keeps no order of its own.
- A negative key would give a negative index with `%`. Real tables always make the index non-negative; OpenJDK's `HashMap` takes the low bits of the hash with `(n - 1) & hash`.

## Rules and defaults

- **Equal keys, equal hash:** a hash function must give the same number for keys that are equal, or a lookup would search the wrong bucket. Different keys may share a hash.
- **Average O(1) needs a good spread:** the hash should scatter typical keys evenly across buckets. The cost is O(1) on average, and O(n) when most keys collide.
- **Load factor limit:** chaining can work above 1, because a bucket holds a list. Open addressing needs it below 1, because each slot holds one key. Java's `HashMap` resizes at 0.75 (see [HashMap and HashSet](card:hashmap-hashset)).
- **Rehashing costs O(n):** every key moves to a new bucket. It is rare, so inserts stay O(1) amortised, like [ArrayList growth](card:dynamic-array).

## Not to be confused with

The hash code is the number a key's hash function returns, for example `"java".hashCode()`. The bucket index is that number reduced to the table size, such as `hash % 8`. Two different keys can have different hash codes and still land in the same bucket. Rule: equal hash codes are possible for different keys; equal keys must have equal hash codes.

## Interview Qs

### What is hashing?

A hash function turns a key into a number, and the hash table reduces that number to a bucket index. Equal keys always get the same index, so insert and lookup go straight to one bucket instead of scanning all keys. That gives O(1) average time.

### What is a collision, and how is it handled?

A collision is when two different keys map to the same bucket. Separate chaining keeps a list in each bucket and adds the new key to it. Open addressing keeps one key per slot and probes other slots, for example the next one, until it finds a free slot.

### Why is the worst case O(n)?

If the hash function is poor, or the keys are chosen to share hash codes, most keys land in one bucket and every lookup compares them one by one. Such keys are easy to build: in Java, `"Aa"` and `"BB"` have the same `hashCode()`, 2112.

### Why does a hash table resize?

As keys are added, buckets fill and collisions get more common, so lookups slow down. When the load factor passes its limit, the table makes more buckets and re-places every key, which shortens the buckets again. One resize is O(n), but it is rare.
