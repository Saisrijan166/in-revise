## Why it exists

Searching an unsorted array takes O(n). Hashing jumps straight to the slot where a key should be, trading extra memory for speed.

- Two fixes for collisions: [chaining or open addressing](compare:chaining-vs-open-addressing).
- When the load factor passes a limit, the table grows and every key is placed again (rehash).

## Interview Qs

### What is hashing?

A hash function turns a key into an array index. Equal keys always get the same index, so a lookup goes straight to one bucket.

### What is a collision, and how is it handled?

Two different keys map to the same index. Separate chaining keeps a list per bucket; open addressing probes for another empty slot, for example the next one (linear probing).

### Why is the worst case O(n)?

If the hash function is poor, or the keys share hash codes (such strings are easy to build), all keys land in one bucket and each lookup scans them all.
