## What it is

A pattern is a known technique that solves a whole family of problems. Two pointers, sliding window and prefix sums are patterns; each one has a short template you can reuse. Spotting the pattern means reading a new problem for clues that tell you which template fits. This topic teaches the patterns one by one, and the table below is the map you can come back to.

## Why it exists

Without patterns, every problem looks new, and you fall back to the brute force: try every pair or every subarray with nested loops. That is O(n²) or worse and usually too slow. Interview problems come from a small number of families, so if you recognise the family from its clues, you start from a template that is already fast and only adapt it.

## How it works

| Clue in the problem | Pattern | Its idea in a few words |
|---|---|---|
| Sorted array, find a pair or triple | [Two pointers](card:two-pointers) | Two indices move toward each other |
| Cycle or middle of a linked list | [Fast and slow pointers](card:fast-slow-pointers) | One pointer moves twice as fast |
| Longest or shortest contiguous subarray | [Sliding window](card:sliding-window) | Grow the right edge, shrink the left |
| Many range sums, or subarray sum with negatives | [Prefix sum](card:prefix-sum) | Store running totals, subtract two |
| Count, duplicate, seen before, unsorted pair | [Counting with a HashMap](card:frequency-counting) | Remember what you have seen |
| Next greater or smaller element | [Monotonic stack](card:monotonic-stack) | A stack of items still waiting |
| Smallest value that still works, answer in a range | [Binary search on the answer](card:binary-search-on-answer) | Halve the range of possible answers |
| Top k, kth largest, merge k sorted lists | [Top K with a heap](card:top-k-heap) | Keep only k items in a heap |
| Overlapping ranges, meetings | [Intervals](card:merge-intervals) | Sort by start, then sweep |
| Grid, islands, connected cells | [Grid BFS and DFS](card:grid-traversal) | Treat cells as graph nodes |
| All subsets, permutations, combinations | [Backtracking](card:backtracking) | Choose, explore, undo |
| Count ways or minimum cost, subproblems repeat | [Dynamic programming](card:dynamic-programming) | Solve each subproblem once |
| A local best choice that is provably safe | [Greedy](card:greedy) | Take the best step now |

1. Look at the input's shape: is it sorted, a linked list, a grid, a list of ranges?
2. Underline the question words: longest, contiguous, kth, how many ways, all.
3. Read the constraints: the input size tells you how fast the answer must be (you will see this in [Read the Constraints](card:constraints-to-complexity)).
4. Match the clues to a row of the table and start from that pattern's template.
5. If no row matches, write the brute force, find the work it repeats, and pick the pattern that removes it.

## Example

The same array, `nums = [2, 7, 11, 15]`, with three different questions, gives three different patterns.

- **"Return two indices whose values add up to 9; the array is sorted."** Sorted plus a pair: two pointers, O(n) time and O(1) extra space. The answer is indices 0 and 1.
- **"Same question, but the array is not sorted."** Unsorted pair: a HashMap of the values seen so far, O(n) average time.
- **"How many contiguous subarrays add up to 9?"** Contiguous plus a sum: prefix sums with a HashMap. Only `[2, 7]` works, so the answer is 1.

What to notice:

- The data did not change; the question words did. Always read the whole question before choosing.
- "Sorted" alone did not decide the pattern. It is the pair plus sorted that points to two pointers.

## Common mistakes

- **"I should memorise hundreds of problems."** Problems repeat in families. Learning about a dozen patterns, with their clues, covers far more new problems than memorised solutions.
- **"If no pattern fits, I am stuck."** The brute force is always a valid start. Say it with its cost, then look for the step it repeats; that step usually names the pattern.

## Interview Qs

### How do you approach a problem you have not seen before?

I clarify the input, work a small example by hand and state the brute force with its cost. Then I look for clues in the input, the question words and the constraints, and match them to a pattern that removes the work the brute force repeats.

### The array is sorted. Two pointers or binary search?

It depends on what is asked. Finding a pair with a target sum is two pointers, O(n). Finding one value is binary search, O(log n). A pair can also be found with a binary search for each element, but that costs O(n log n), so two pointers is better.
