## Why it exists

Checking every subarray is O(n²) or worse. Neighbouring windows share almost all their items, so update the answer as the edges move instead of recounting.

## How it works

<Compare id="two-pointers-vs-sliding-window" />

- [Fixed size k](card:fixed-size-window): add `nums[i]`, remove `nums[i - k]`, update the best. Window maximum: a [monotonic deque](card:monotonic-queue).
- [Variable size](card:variable-size-window): shrink in a `while` loop until the window is valid again.

## Example

```java
int longestUnique(String s) {                 // Longest Substring Without Repeating
    int[] count = new int[128];               // ASCII counts inside the window
    int best = 0;
    for (int left = 0, right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        count[c]++;
        while (count[c] > 1) count[s.charAt(left++)]--;   // shrink until valid
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

## Interview Qs

### There is a loop inside a loop. Why is it O(n)?

`left` only moves forward, so across the whole run it moves at most n times. Each index is added once and removed at most once: O(n) in total, not O(n²).

### When does a sliding window not work?

When shrinking may not fix the window, as with sums over negative numbers. Then use [prefix sums with a HashMap](card:subarray-sum-equals-k).
