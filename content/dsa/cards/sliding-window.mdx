## What it is

A sliding window is a [two pointers](card:two-pointers) pattern where both indices move in the same direction. Everything between `left` and `right` is the window, a contiguous subarray or substring. You keep a small summary of the window, such as its sum or a count of each letter, and update it as the edges move. The window grows on the right and shrinks on the left, so it slides along the input.

## Why it exists

The brute force for "longest substring without a repeated letter" checks every start and every end: O(n²) substrings, and checking each one costs more. But two neighbouring windows share almost all their items. Adding one item on the right and removing one on the left changes the summary by a small step, so you update it instead of recounting, and finish in one pass.

## How it works

Longest substring without a repeated letter in `"abcabcbb"`:

| right reads | Window breaks the rule? | Shrink to | Window | Best |
|---|---|---|---|---|
| a, b, c | no | none | abc | 3 |
| a | yes, two a | drop a | bca | 3 |
| b | yes, two b | drop b | cab | 3 |
| c | yes, two c | drop c | abc | 3 |
| b | yes, two b | drop a, b | cb | 3 |
| b | yes, two b | drop c, b | b | 3 |

1. Start with an empty window: `left = 0`, and the summary is empty.
2. Move `right` forward one item and add that item to the summary.
3. While the window breaks the rule, remove the item at `left` from the summary and move `left` forward.
4. The window is valid now, so compare its size or value with the best so far.
5. Repeat until `right` reaches the end.

So the key is that both edges only move forward. For a [fixed-size window](card:fixed-size-window) of size k, step 3 becomes "remove the item k places back", so the size stays k.

## Example

This is the trace above as code, with an array of letter counts as the summary.

```java
int longestUnique(String s) {          // Longest Substring Without Repeating Characters
    int[] count = new int[128];        // how often each ASCII char is in the window
    int best = 0;
    for (int left = 0, right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        count[c]++;                    // 1. grow: add the new char
        while (count[c] > 1)           // 2. invalid: c appears twice
            count[s.charAt(left++)]--; //    shrink from the left
        best = Math.max(best, right - left + 1);   // 3. record the valid window
    }
    return best;
}

System.out.println(longestUnique("abcabcbb"));
```

```text output
3
```

What to notice:

- `count` is the window's summary. `count[c] > 1` is the rule check, and it costs O(1) instead of rescanning the window.
- `right - left + 1` is the window's length, because both ends are included.
- `left++` happens inside the indexing: the item at the old `left` is removed, then `left` moves on. For `"bbbbb"` the method returns 1.

## Rules and defaults

- **Use it when:** the question says contiguous (subarray or substring) and asks for the longest, the shortest, the best, or every window of size k.
- **One-way rule:** shrinking must always move the window toward valid. Letter counts and sums of non-negative numbers have this; sums with negative numbers do not, so use [prefix sums with a HashMap](card:subarray-sum-equals-k).
- **Variable or fixed:** a [variable-size window](card:variable-size-window) shrinks in a while loop; a fixed-size one removes exactly one item each step.
- **Window maximum:** for the largest value in every window of size k, keep a [monotonic deque](card:monotonic-queue), shown with the monotonic stack.

## Not to be confused with

Two pointers is the broader pattern: two indices that move by a rule, often from both ends toward each other, to find a pair. A sliding window is the same-direction case where the range between the indices is the answer. Rule: a pair or an in-place rewrite is two pointers; the best contiguous range is a sliding window.

## Interview Qs

### There is a loop inside a loop. Why is it O(n)?

`left` only moves forward, so across the whole run it moves at most n times in total, not n times per `right`. Each index is added once and removed at most once: about 2n steps, which is O(n).

### When does a sliding window not work?

When shrinking does not always fix the window, as with sums that include negative numbers: removing a negative item raises the sum. Then use [prefix sums with a HashMap](card:subarray-sum-equals-k), which do not depend on the sign.

### How would you find the shortest substring that contains every letter of a pattern?

That is Minimum Window Substring. Count the pattern's letters, grow the window until it contains all of them, then shrink from the left while it still does, recording the shortest. Each index enters and leaves once, so it is O(n + m) for a string of length n and a pattern of length m.
