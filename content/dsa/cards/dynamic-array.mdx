## Why it exists

Plain [arrays](card:arrays) cannot grow, but most of the time you do not know the final count. A dynamic array grows for you.

## How it works

<Steps label="add(x) on a full ArrayList">
  <Step title="Check">Size equals capacity: no free slot.</Step>
  <Step title="Allocate">Create a larger array.</Step>
  <Step title="Copy">Move all n items across: O(n).</Step>
  <Step title="Add">Put x in the next free slot and increase size.</Step>
</Steps>

- Because capacity grows by a multiple, n adds cost O(n) in total: amortised O(1) each.
- `ensureCapacity(n)` or `new ArrayList<>(n)` avoids repeated resizes when n is known.

## Example

```java
List<Integer> nums = new ArrayList<>(); // capacity 10, size 0
for (int i = 0; i < 100; i++) {
    nums.add(i);                        // amortised O(1)
}
nums.get(50);                           // O(1)
nums.add(0, -1);                        // O(n): shifts 100 items
nums.remove(Integer.valueOf(7));        // removes value 7, O(n)
nums.remove(7);                         // removes index 7
```

## Interview Qs

### What does amortised O(1) mean for ArrayList add?

One add can cost O(n) when it resizes, but resizes are rare because capacity grows by a multiple. Over n adds the total work is O(n), so each add averages O(1).

### Why use ArrayList over an array?

It grows by itself and has a full List API, with the same O(1) index access. Use a plain array when the size is fixed or you need primitives without boxing.
