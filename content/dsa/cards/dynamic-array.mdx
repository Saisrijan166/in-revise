## What it is

An `ArrayList` is Java's dynamic array: a list that keeps its items in an ordinary [array](card:arrays) inside it and makes that array bigger when needed. It has a size, the number of items you stored, and a capacity, the number of slots in the inner array. The capacity is always at least the size, so there are usually a few free slots at the end. It implements the `List` interface from the [collections framework](card:java-collections).

## Why it exists

A plain array needs its length up front, but usually you do not know how many items will come: lines of a file, users who sign up, results of a search. You could create a new, bigger array by hand each time it fills up and copy everything, but that code is easy to get wrong and slow if you grow by one slot at a time. `ArrayList` does the growing for you, and grows by a large step, so adding stays cheap on average.

## How it works

<Steps label="list.add(x) at the end">
  <Step title="Check">Is size less than capacity? Then a free slot exists.</Step>
  <Step title="Grow if full">If not, create a larger array and copy all n items into it: O(n).</Step>
  <Step title="Store">Put x in slot number size, then add 1 to size.</Step>
</Steps>

1. `new ArrayList<>()` starts empty. The Java SE 25 API gives it an initial capacity of ten; OpenJDK creates those ten slots at the first `add`.
2. Each `add(x)` writes into the next free slot, which is O(1).
3. The 11th add finds no free slot. OpenJDK creates an array of 15 (half as big again), copies the 10 items, then stores the new one.
4. Growth continues 15 → 22 → 33 → 49 → 73 → 109. For 100 adds, the copies move 202 items in total, about 2 per add.
5. Because each new array is a fixed fraction bigger, copies get rarer as the list grows, so n adds cost O(n) in total. That average of O(1) per add is called amortised O(1).

So the key is: an occasional expensive add is paid for by many cheap ones.

## Example

The running example `[2, 7, 11, 15]` goes into an `ArrayList`, then items are inserted and removed:

```java
List<Integer> list = new ArrayList<>();       // size 0
for (int x : new int[] {2, 7, 11, 15}) {
    list.add(x);                              // add at the end: amortised O(1)
}
System.out.println(list.get(2));              // O(1), like nums[2]
list.add(0, 1);                               // insert at index 0: 4 items shift right
System.out.println(list);
list.remove(1);                               // int argument: removes INDEX 1
System.out.println(list);
list.remove(Integer.valueOf(1));              // Integer argument: removes the VALUE 1
System.out.println(list + " size " + list.size());
```

```text output
11
[1, 2, 7, 11, 15]
[1, 7, 11, 15]
[7, 11, 15] size 3
```

What to notice:

- `list.get(2)` works like `nums[2]`: one step, because the items still sit in an array.
- `add(0, 1)` had to move all four items one slot right. On a list of a million items that is a million moves.
- `remove(1)` removed the 2 at index 1, not the value 1. Java picks `remove(int index)` for an `int` argument; only `Integer.valueOf(1)` selects `remove(Object)`.
- The list holds `Integer` objects, not `int`. Each `add(x)` boxes the `int` into an `Integer`.

## Rules and defaults

- **Initial capacity:** ten for `new ArrayList<>()` (Java SE 25 API). Pass a number, `new ArrayList<>(n)`, when you know the count.
- **Growth policy:** the API only promises amortised constant time for `add`. The 1.5× growth is an OpenJDK detail, not a guarantee.
- **Avoid resizes:** `ensureCapacity(n)` makes room for at least n items in one step; `trimToSize()` shrinks the capacity to the current size.
- **Threads:** `ArrayList` is not synchronised. If several threads change one list, you must add the locking yourself.
- **Changing while looping:** adding or removing items during a for-each loop over the list is a bug, which the iterator usually, but not always, reports with `ConcurrentModificationException`. [Java pitfalls](card:java-pitfalls), later, shows the safe ways.

## Not to be confused with

A plain [array](card:arrays) has a fixed length and can hold `int` directly. An `ArrayList` grows by itself, offers methods such as `add` and `remove`, and holds only objects. `LinkedList`, which you will meet in [linked lists](card:linked-list), is also a `List` but stores nodes joined by links, so `get(i)` is O(n). Rule: count known and primitives wanted → array; count changes → `ArrayList`.

## Interview Qs

### What does amortised O(1) mean for ArrayList add?

One add can cost O(n), when it copies everything into a bigger array. But the capacity grows by a multiple, so such adds are rare: for n adds the total copying is O(n). Spread over the n adds, each one costs O(1) on average. Amortised means averaged over a sequence, not a guarantee for every single call.

### Why does ArrayList grow by a multiple and not by a fixed number of slots?

If it grew by, say, 10 slots each time, every 10th add would copy the whole list. Over n adds that is about n²/20 copies, so O(n²) in total. Growing by a fraction of the current size makes resizes rarer as the list grows, which keeps the total O(n).

### Why use ArrayList over an array?

It grows by itself and has the full `List` API, with the same O(1) access by index. Use a plain array when the size is fixed, or when you want primitives such as `int[]` without boxing each value into an object.
