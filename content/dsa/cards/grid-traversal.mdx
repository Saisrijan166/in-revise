## What it is

Grid traversal means walking a 2D grid, such as a map of land and water, as if it were a [graph](card:graph-basics). Each cell (r, c) is a node, and it is joined to its neighbours: usually the 4 cells above, below, left and right. With that view, the [DFS](card:dfs) and [BFS](card:bfs) you already know solve islands, mazes and spreading problems, with no edge list to build.

## Why it exists

Many interview problems hide a graph in a grid: count the islands, find the shortest way out of a maze, find how long a fire takes to spread. Writing special code for each problem leads to missed edges and repeated visits. Seeing cells as nodes turns every one of them into the same two moves, flood fill with DFS or level-by-level BFS, each visiting a cell once.

## How it works

<Mermaid
  alt="Cell (r, c) in the middle is joined to four neighbours: (r-1, c) above, (r+1, c) below, (r, c-1) on the left and (r, c+1) on the right."
  chart={`flowchart TD
  U["(r-1, c)"] --- C(("(r, c)"))
  C --- D["(r+1, c)"]
  L["(r, c-1)"] --- C
  C --- R["(r, c+1)"]`}
/>

1. Write the 4 moves as two direction arrays, so one loop visits all neighbours: `dr[d]` changes the row and `dc[d]` the column.
2. For each neighbour, check that the row and column are inside the grid before reading the cell.
3. Skip the neighbour if it is blocked (water, a wall) or already visited.
4. Mark it visited as soon as you reach it, by a `boolean[][]` grid or by overwriting the cell if the input may change.
5. Continue with DFS to cover a whole region, or put the neighbour in a queue for BFS, where each queue level is one more step from the start.

So the key is one loop over offsets, one bounds check and one visited mark per cell.

## Example

Number of Islands: count the groups of connected land cells ('1') in this 4 × 5 grid.

```java
static final int[] DR = {-1, 1, 0, 0}, DC = {0, 0, -1, 1};    // up, down, left, right
int numIslands(char[][] grid) {
    int count = 0;
    for (int r = 0; r < grid.length; r++)
        for (int c = 0; c < grid[0].length; c++)
            if (grid[r][c] == '1') { count++; sink(grid, r, c); } // new island found
    return count;
}
void sink(char[][] grid, int r, int c) {
    if (r < 0 || c < 0 || r >= grid.length || c >= grid[0].length) return; // bounds first
    if (grid[r][c] != '1') return;                    // water, or already visited
    grid[r][c] = '0';                                 // mark visited
    for (int d = 0; d < 4; d++) sink(grid, r + DR[d], c + DC[d]);
}
System.out.println(numIslands(new char[][] {"11000".toCharArray(), "11000".toCharArray(), "00100".toCharArray(), "00011".toCharArray()}));
```

```text output
3
```

What to notice:

- Each time the scan finds land that is still '1', it is the first cell of a new island. `sink` then floods the whole island, so its other cells are never counted again.
- The bounds check comes before `grid[r][c]`. Swap the two `if` lines and the first call that steps off an edge throws `ArrayIndexOutOfBoundsException`.
- Setting the cell to '0' is the visited mark. Without it, two neighbouring cells call each other forever and the stack overflows.
- Every cell is visited at most once, so the cost is O(rows × cols).

## Rules and defaults

- **Diagonals:** if diagonal moves are allowed, use 8 offsets instead of 4. Read the problem statement for which moves count.
- **Mark when reached:** in BFS, mark a cell visited when you add it to the queue, not when you take it out, or the same cell can enter the queue several times.
- **Deep recursion:** recursive DFS on a large grid that is all land can go one call deep per cell and overflow the call stack (see [recursion](card:recursion)). Use BFS, or DFS with your own stack, for large grids.
- **Fewest steps:** only BFS gives it, and only while every move costs the same.

## Not to be confused with

Flood fill visits every cell connected to a start cell; DFS or BFS both work, and the order does not matter. Shortest path in a grid needs the cells in order of distance, which only BFS gives. Rule: count or mark regions with either; fewest steps with BFS.

## Interview Qs

### Walk me through Number of Islands.

Scan every cell. When you find land that is not yet visited, add one to the count and flood fill from it with DFS or BFS, marking every cell of that island as visited. The count is the number of flood fills started. Each cell is visited once, so it is O(rows × cols) time.

### Why does BFS give the fewest steps in a grid, and DFS does not?

BFS processes cells level by level: first all cells 1 step away, then all cells 2 steps away. So the first time it reaches a cell, no shorter path exists. DFS follows one path as deep as it can, so the first path it finds to the exit can be long.

### When would you choose BFS over DFS for counting regions?

Both give the same count. On a very large grid, though, recursive DFS can go as deep as the number of cells in one region and overflow the call stack. BFS keeps its work in a queue on the heap, so it is safer there.
