## What it is

Union-find, also called disjoint set union (DSU), keeps items in groups that never overlap and only ever merge. It has two operations: `find(x)` returns the name of x's group, and `union(a, b)` merges the groups of a and b. Each group is stored as a small [tree](card:tree-basics) in a parent array. Every item points to its parent, and the root, which points to itself, names the group.

## Why it exists

Suppose roads between cities open one at a time, and after each one you must answer "are city 0 and city 5 connected now?". Re-running [DFS](card:dfs) after every road costs O(V + E) each time. Union-find answers each find or union in almost constant time, so a stream of E roads costs about O(E). It also spots a road whose two ends are already connected: that road closes a loop.

## How it works

<Mermaid
  alt="Two groups as trees: items 1 and 2 point to root 0; item 4 points to root 3. union(2, 4) finds roots 0 and 3 and hangs root 3 under root 0, making one group."
  chart={`flowchart BT

1. Start with every item alone: `parent[i] = i` and `size[i] = 1`.
2. `find(x)` follows parent links until it reaches an item that points to itself. That root names the group. On the way back it points every item it passed straight at the root; this is path compression.
3. `union(a, b)` finds both roots. If they are equal, a and b are already in one group, so a new edge between them closes a loop.
4. Otherwise it hangs the smaller tree's root under the larger one's (union by size) and adds the sizes, which keeps every tree shallow.

So the key is: a group is named by its root, and both tricks keep the path to the root short.

## Example

The two operations, with path compression and union by size:

```java
static int[] parent = new int[6], size = new int[6];
static int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);   // path compression
    return parent[x];
}
static boolean union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;                         // already one group
    if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
    parent[rb] = ra;                                    // smaller tree under larger
    size[ra] += size[rb];
    return true;
}
```

Now open the seven city roads from [Graphs and How to Store Them](card:graph-basics) one by one:

```java
for (int i = 0; i < 6; i++) { parent[i] = i; size[i] = 1; }   // each city alone
int groups = 6;
for (int[] r : roads) {
    if (union(r[0], r[1])) groups--;
    else System.out.println("road " + r[0] + "-" + r[1] + " closes a loop");
}
System.out.println("groups: " + groups);
```

```text output
road 1-2 closes a loop
road 3-4 closes a loop
groups: 1
```

What to notice:

- When road 1-2 opens, cities 1 and 2 are already joined through city 0, so their roots are equal and `union` returns false. Road 3-4 is rejected the same way: cities 3 and 4 are already joined through 1, 0 and 2.
- `groups` starts at 6 and drops by one for each successful union; five successes leave one group, so all cities are connected.
- Drop path compression (`if (parent[x] != x) return find(parent[x]); return x;`) and every answer stays the same. Only the speed changes: each find can then take up to O(log n) steps.

## Rules and defaults

- **Both speed-ups:** O(α(n)) amortised per call, where α is the inverse Ackermann function, at most 4 for any realistic n.
- **Only one speed-up:** union by size alone gives O(log n) per call; path compression alone gives O(log n) on average.
- **Merges only:** union-find has no operation to split a group or remove an edge.
- **Items that are not numbers:** give each item a number first, or keep the parents in a `HashMap`.
- **Cycles:** an edge with equal roots closes a cycle in an undirected graph only.

## Not to be confused with

DFS counts the components of a graph you know fully, in one O(V + E) pass. Union-find handles edges that arrive one at a time and answers "connected?" at any moment. Rule: a fixed graph and one question, DFS; edges arriving and many questions, union-find.

## Common mistakes

- **"Same parent means same group."** Two items in one group can have different parents. Compare `find(a) == find(b)`, never `parent[a] == parent[b]`.
- **"union sets parent[a] = b."** That moves only item a and can cut it off from its old group. Always link the two roots.

## Interview Qs

### What is union-find, and when do you use it?

A structure for groups that only merge, with `find` to name an item's group and `union` to merge two groups. Use it for connectivity while edges arrive, counting components, checking whether an edge closes a cycle in an undirected graph, and Kruskal's minimum spanning tree.

### How does union-find solve Graph Valid Tree?

A tree on n vertices has exactly n - 1 edges and no cycle. First check the edge count. Then union the ends of each edge; if any union finds equal roots, that edge closes a cycle, so the answer is no. With n - 1 edges and no cycle, the graph is also connected, so it is a tree.

### What does α(n) mean in its cost?

α is the inverse Ackermann function. It grows so slowly that it stays at most 4 for any input size you could ever store, so with path compression and union by size each operation is effectively constant time. Amortised means the bound holds on average over a long sequence of calls.
