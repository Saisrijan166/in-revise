## Why it exists

Some problems keep merging groups and asking "are these two in one group?". Re-running DFS after each merge is slow; union-find answers in almost constant time.

## How it works

<Mermaid
  alt="Two groups as trees: 1 and 2 point to root 0; 4 points to root 3. union(2, 4) hangs root 3 under root 0, making one group."
  chart={`flowchart BT
  n1((1)) --> n0((0 root))
  n2((2)) --> n0
  n4((4)) --> n3((3 root))
  n3 -. "union(2, 4)" .-> n0`}
/>

- **Path compression:** during find, point every visited vertex straight at the root.
- **Union by rank or size:** hang the smaller tree under the larger, so trees stay shallow.

## Example

```java
int[] parent, size;          // start: parent[i] = i, size[i] = 1
int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);   // path compression
    return parent[x];
}
boolean union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;                         // same group: edge closes a cycle
    if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
    parent[rb] = ra;  size[ra] += size[rb];             // smaller under larger
    return true;
}
```

## Interview Qs

### What is union-find and when do you use it?

A structure for groups that only merge. Use it for counting components as edges arrive, spotting an edge that closes a cycle (Graph Valid Tree), and Kruskal's minimum spanning tree.

### What is α(n) in its cost?

The inverse Ackermann function. It grows so slowly that it stays below 5 for any input size seen in practice, so each operation is effectively constant time.
