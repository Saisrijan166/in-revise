## What it is

A tree is a data structure that stores items in nodes connected by parent-to-child links. One node, the root, sits at the top and has no parent. Every other node has exactly one parent, and a node with no children is a leaf. A binary tree is a tree in which each node has at most two children, called left and right.

## Why it exists

Arrays and lists are flat: every item has one item before it and one after it. Many things are hierarchies instead, such as folders inside folders or an org chart, and squeezing them into a list loses who belongs under whom. A tree stores those parent-child links directly. It also allows fast search: if each step down the tree rules out a whole branch, you reach any item by walking a single path instead of checking all n items.

1. Each node is an object that holds a value and a link to each child. In Java a missing child is `null`.
2. Your code keeps a link to the root only. It reaches every other node by following child links down.
3. To find a node's depth, count the edges on the way down from the root to it. The root has depth 0.
4. To find a node's height, take the longest path from it down to a leaf and count its edges. A leaf has height 0, and a node's height is 1 + the larger height of its children.
5. Every node except the root has one edge up to its parent, so a tree with n nodes has n - 1 edges.

So the key is that a tree is reached from the root, one edge at a time, and its height decides how long the longest walk is.

## Example

This builds the small tree from the picture, which later concepts reuse, and computes heights with [recursion](card:recursion).

```java
class TreeNode {
    int val;
    TreeNode left, right;               // null means "no child here"
    TreeNode(int val) { this.val = val; }
}
int height(TreeNode node) {             // counted in edges
    if (node == null) return -1;        // empty tree: -1, so a leaf gets 0
    return 1 + Math.max(height(node.left), height(node.right));
}
TreeNode root = new TreeNode(8);
root.left = new TreeNode(3);  root.right = new TreeNode(10);
root.left.left = new TreeNode(1);  root.left.right = new TreeNode(6);
root.right.right = new TreeNode(14);
System.out.println(height(root) + " " + height(root.left.left) + " " + height(null));
```

```text output
2 0 -1
```

What to notice:

- `TreeNode` holds a value and two links. This class is the standard shape of a binary tree node in coding rounds.
- The root has height 2, leaf 1 has height 0, and the empty tree has -1. Returning -1 for `null` is what makes a leaf come out as 0.
- If the base case returned 0 instead, every height would be one larger: the function would count nodes on the path, not edges.
- `height` asks both children first and then combines their answers, so it visits every node once: O(n) time.

## Rules and defaults

- **Edges or nodes:** this site counts depth and height in edges. Some problems count nodes instead: LeetCode 104 "Maximum Depth" calls this tree's depth 3. Read the definition in the problem before you answer.
- **Siblings and subtrees:** nodes with the same parent are siblings. A subtree is a node together with everything below it, and it is a tree on its own.
- **Height limits:** a binary tree of height h has at most 2^(h+1) - 1 nodes. If every node has one child, the tree is a chain of n nodes, called skewed, with height n - 1.

## Not to be confused with

Depth looks up from a node to the root; height looks down from a node to its deepest leaf. Rule: depth = how far from the top, height = how far above the bottom. The shape words are separate again: a full binary tree has 0 or 2 children at every node, a complete one fills every level from the left with only the last level allowed gaps, and a perfect one has every level completely full.

## Interview Qs

### What is the difference between depth and height?

Depth counts edges from the root down to the node, so the root has depth 0. Height counts edges from the node down to its deepest leaf, so every leaf has height 0. The height of the whole tree equals the largest depth of any node.

### How many edges does a tree with n nodes have, and why?

Exactly n - 1. Each node except the root has exactly one edge to its parent, and those are all the edges. Adding one more edge creates a cycle; removing one splits the tree into two parts.

### Why does the height of a tree matter so much?

Most tree operations walk one path from the root down, so they cost O(height). A tree where every level is full has height about log n, so the walk is O(log n). A skewed tree is a chain with height n - 1, so the same walk costs O(n).
