## Why it exists

Nearly every tree problem is "visit every node and combine answers". The visit order decides what you know at each node: the parent's data, or the children's results.

## How it works

<Compare id="traversal-orders" />

- To get a node's answer from its children (height, size), use postorder.
- To print or decide per level (right side view), use level order.

## Example

```java
void inorder(TreeNode node, List<Integer> out) {
    if (node == null) return;        // base case
    inorder(node.left, out);
    out.add(node.val);               // move this line up: preorder; down: postorder
    inorder(node.right, out);
}
```

```text
Tree 1(2(4,5),3):  pre 1 2 4 5 3   in 4 2 5 1 3   post 4 5 2 3 1   level 1 | 2 3 | 4 5
```

## Interview Qs

### Which traversal gives sorted output for a BST, and why?

Inorder. Every key in the left subtree is smaller and every key in the right subtree is larger, so visiting left, node, right lists keys from smallest to largest.

### How do you do a level-order traversal?

Put the root in a queue. While it is not empty, read its size, poll that many nodes, record them as one level, and add their children.

### Can you rebuild a tree from its traversals?

With distinct keys, preorder plus inorder (or postorder plus inorder) gives one unique tree. Preorder plus postorder alone is not always enough.
