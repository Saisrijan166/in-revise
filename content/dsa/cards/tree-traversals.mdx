## What it is

A traversal is a fixed order for visiting every node of a [tree](card:tree-basics) exactly once. The three depth-first orders go as deep as possible before moving sideways, and differ only in when they handle the node itself. Preorder handles it before its two subtrees, inorder between them, and postorder after them. Level order instead visits the tree row by row from the root.

## Why it exists

Nearly every tree problem is "visit every node and combine what you find". The order decides what you already know when you reach a node. In preorder you know the path from the root, so you can pass information down. In postorder both children are already finished, so you can build an answer from theirs, such as a height. Picking the right order is often the whole solution.

## How it works

<Compare id="traversal-orders" />

1. A recursive traversal starts at the root. If the node is `null`, it returns at once; this is the base case.
2. Otherwise it makes two recursive calls, one for the left subtree and one for the right subtree.
3. Where you put the line that handles the node decides the order: before both calls is preorder, between them inorder, after both postorder.
4. Level order puts the root in a queue. While the queue is not empty, it reads the queue's size, polls that many nodes as one level, and adds each node's children to the back.

So the key is one recursive template with the "handle the node" line in three possible places, plus a queue for rows.

## Example

One recursive walk over the running tree fills all three depth-first lists at once:

```java
void dfs(TreeNode node, List<Integer> pre, List<Integer> in, List<Integer> post) {
    if (node == null) return;              // base case: empty subtree
    pre.add(node.val);                     // before both children
    dfs(node.left, pre, in, post);
    in.add(node.val);                      // between the children
    dfs(node.right, pre, in, post);
    post.add(node.val);                    // after both children
}
// root is the tree 8 (3 (1, 6), 10 (-, 14)) from Trees and Binary Trees
List<Integer> pre = new ArrayList<>(), in = new ArrayList<>(), post = new ArrayList<>();
dfs(root, pre, in, post);
System.out.println("pre  " + pre);
System.out.println("in   " + in);
System.out.println("post " + post);
```

```text output
pre  [8, 3, 1, 6, 10, 14]
in   [1, 3, 6, 8, 10, 14]
post [1, 6, 3, 14, 10, 8]
```

Level order needs a [queue](card:queue-and-deque) instead of recursion:

```java
Deque<TreeNode> queue = new ArrayDeque<>(List.of(root));
while (!queue.isEmpty()) {
    int size = queue.size();                  // nodes on this level
    List<Integer> level = new ArrayList<>();
    for (int i = 0; i < size; i++) {
        TreeNode node = queue.poll();
        level.add(node.val);
        if (node.left != null) queue.offer(node.left);
        if (node.right != null) queue.offer(node.right);
    }
    System.out.println(level);
}
```

```text output
[8]
[3, 10]
[1, 6, 14]
```

What to notice:

- The three `add` lines are the only difference between the orders. Preorder starts with the root 8; postorder ends with it.
- Inorder came out sorted because this tree happens to be a [binary search tree](card:binary-search-tree), the next concept. On another tree it would not be sorted.
- `size` is read before the loop starts. Without it, children added during the loop would be mixed into the current level.
- `ArrayDeque` does not accept `null`, so the code checks each child before `offer`.

## Rules and defaults

- **Time:** every order visits each node once: O(n).
- **Space:** the recursive orders keep one call per level of the current path, O(height): O(log n) for a balanced tree, O(n) for a skewed one. Level order holds one level in the queue, which can be about n/2 nodes on the last level of a perfect tree.
- **Without recursion:** preorder, inorder and postorder can use your own stack instead of the call stack, which avoids a `StackOverflowError` on a very deep tree.

## Not to be confused with

Depth-first orders (pre, in, post) follow one branch to the bottom before trying the next; level order is breadth-first and finishes a whole row before going deeper. Rule: recursion or a stack for depth-first, a queue for level order. You will see the same pair for graphs in [BFS](card:bfs) and [DFS](card:dfs).

## Interview Qs

### Which traversal gives sorted output for a BST, and why?

Inorder. In a BST every key in the left subtree is smaller than the node and every key in the right subtree is larger. Visiting left, then node, then right therefore lists the keys from smallest to largest.

### How do you do an inorder traversal without recursion?

Use a stack. Push nodes while going left from the current node. When you reach `null`, pop a node, handle it, and move to its right child. Repeat until the stack is empty and the current node is `null`. The stack holds the same path that recursion would keep.

### Can you rebuild a tree from its traversals?

With distinct keys, preorder plus inorder gives exactly one tree: the first preorder value is the root, and its position in the inorder list splits the left and right subtrees. Postorder plus inorder also works. Preorder plus postorder alone is not always enough.
