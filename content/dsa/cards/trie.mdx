## What it is

A trie, also called a prefix tree, is a tree that stores [strings](card:strings) letter by letter. Each edge from a node stands for one letter, so a word is a path from the root. Words that start with the same letters share the start of their path. Each node also has an end-of-word flag that says whether a stored word ends exactly there.

## Why it exists

A [HashSet](card:hashmap-hashset) answers "is cart stored?" in O(1) on average, but not "which stored words start with ca?". To answer that, it has to check every word. A trie answers prefix questions directly: walk the letters c, a from the root, and every word below that node starts with ca. This makes it the tool for autocomplete and for searching many words at once.

## How it works

  RR --> T2(("t *"))`}

A `*` marks a node whose end-of-word flag is true: car, cat and cart.

1. Insert starts at the root and reads the word one letter at a time.
2. For each letter it follows the child link for that letter, creating a new node if the link is missing.
3. After the last letter it sets the end-of-word flag on the node it reached.
4. Search and startsWith walk the same way but never create nodes. If a link is missing, the answer is false.
5. At the end of the walk, startsWith returns true; search returns the node's end-of-word flag.

So the key is that the work depends only on the length of the word, not on how many words are stored.

## Example

This trie uses a `HashMap` for each node's children; `walk` returns the node where a string ends, or `null`.

```java
class Trie {
    Map<Character, Trie> next = new HashMap<>();   // one child per next letter
    boolean isWord;                                // true only if a stored word ends here
    void insert(String word) {
        Trie node = this;
        for (char c : word.toCharArray()) node = node.next.computeIfAbsent(c, k -> new Trie());
        node.isWord = true;
    }
    Trie walk(String s) {                          // the node where s ends, or null
        Trie node = this;
        for (char c : s.toCharArray()) if ((node = node.next.get(c)) == null) return null;
        return node;
    }
}
```

The word list car, cart, cat goes in, and four queries come out:

```java
Trie trie = new Trie();
for (String w : List.of("car", "cart", "cat")) trie.insert(w);
Trie car = trie.walk("car"), ca = trie.walk("ca");
System.out.println("search car: " + (car != null && car.isWord));
System.out.println("search ca: " + (ca != null && ca.isWord));
System.out.println("startsWith ca: " + (ca != null));
System.out.println("startsWith do: " + (trie.walk("do") != null));
```

```text output
search car: true
search ca: false
startsWith ca: true
startsWith do: false
```

What to notice:

- `computeIfAbsent` returns the existing child, or creates and stores a new one, so insert never overwrites a shared prefix. car and cart share the nodes c, a, r.
- "ca" is a path but not a word: its flag is false, so search says false while startsWith says true.
- Remove the line `node.isWord = true` and every search returns false, because no node would ever be marked as a word end.
- "do" fails at the first letter: the root has no `d` child, so `walk` returns `null` after one step.

## Rules and defaults

- **Cost:** insert, search and startsWith are O(L) for a string of length L. Listing every word under a prefix also costs the size of what you collect.
- **Array children:** when the input is only lowercase a to z, a `Trie[26]` array indexed by `c - 'a'` is faster than a map, but every node keeps 26 links, used or not.
- **Map children:** a `HashMap` stores only the links that exist and accepts any character, at the cost of hashing on every step.

## Interview Qs

### What is a trie, and when do you use it?

A tree of letters where each word is a path and shared prefixes share nodes. Use it when the question is about prefixes: autocomplete, "does any word start with this?", longest common prefix, or searching a grid for many dictionary words at once (Word Search II).

### Trie or HashSet for a dictionary?

A HashSet if you only need exact lookups: it is simpler and needs no node per letter. A trie when you need startsWith, all words with a prefix, or to stop a search early as soon as no word can match the letters so far.

### How would you implement search and startsWith?

Both start at the root and follow one child link per letter, returning false as soon as a link is missing. At the end, startsWith returns true, because the prefix path exists. Search returns the end-of-word flag of the last node, because the path alone does not prove the word was inserted.
