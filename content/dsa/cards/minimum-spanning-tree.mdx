## What it is

A spanning tree of a connected, undirected graph is a set of its edges that links every vertex and has no cycle. With V vertices it always has V - 1 edges. A minimum spanning tree (MST) is the spanning tree whose edge weights add up to the least total. Two greedy algorithms build it: Kruskal's, with [union-find](card:union-find), and Prim's, with a [min-heap](card:heap-priority-queue). Greedy means each step takes the best choice available now and never undoes it; you will see this idea in [Greedy](card:greedy).

## Why it exists

You must lay fibre so that all six cities are connected, and you know what each road's cable costs. Cabling every road wastes money, and trying every subset of roads takes exponential time. Any loop in the network has one edge you could drop and stay connected, so the cheapest network is always a tree. Kruskal and Prim find that tree in about O(E log E).

## How it works

<Compare id="kruskal-vs-prim" />

Kruskal's algorithm, step by step:

1. Sort all edges by weight, cheapest first.
2. Put every vertex in its own union-find group.
3. Take the next edge. If its two ends are in different groups, add the edge to the tree and union the groups.
4. If both ends are already in one group, skip the edge: it would close a cycle.
5. Stop once the tree has V - 1 edges.

Prim's algorithm gets the same total another way. It starts from one vertex and keeps adding the cheapest edge from the tree to a vertex not yet in it, with candidate edges kept in a min-heap.

## Example

Kruskal on the six cities, using `parent`, `size` and `union` from [Union-Find](card:union-find). Each road is `{a, b, cost}`.

```java
int[][] roads = {{0,1,4}, {0,2,1}, {1,2,2}, {1,3,5}, {2,4,8}, {3,4,3}, {3,5,6}};  // {a, b, cost}
Arrays.sort(roads, (x, y) -> Integer.compare(x[2], y[2]));  // cheapest road first
for (int i = 0; i < 6; i++) { parent[i] = i; size[i] = 1; }
int total = 0;
List<String> picked = new ArrayList<>();
for (int[] r : roads) {
    if (union(r[0], r[1])) {                       // ends in different groups: no loop
        total += r[2];
        picked.add(r[0] + "-" + r[1]);
    }
}
System.out.println(picked + " total=" + total);
```

```text output
[0-2, 1-2, 3-4, 1-3, 3-5] total=17
```

What to notice:

- Road 0-1 (cost 4) is skipped: 0 and 1 are already connected by 0-2 and 1-2, which cost 3 together. Road 2-4 (cost 8) is skipped the same way.
- Five roads were picked for six cities, which is V - 1.
- An MST is not a shortest-path tree. Inside it, city 0 reaches city 4 by 0-2-1-3-4, a cost of 11, but [Dijkstra](card:shortest-paths) found 9 by 0-2-4.

## Rules and defaults

- **Input:** a connected, undirected, weighted graph. A disconnected graph has no spanning tree. Kruskal then gives one tree per component (a minimum spanning forest), and Prim covers only the start vertex's component.
- **Edge count:** exactly V - 1 edges. One fewer leaves a vertex out; one more always creates a cycle.
- **Uniqueness:** guaranteed when all weights differ. With equal weights there can be several MSTs, all with the same total.
- **Cost:** Kruskal O(E log E), mostly the sort. Prim O(E log V) with a binary heap, or O(V²) with an adjacency matrix, which suits dense graphs.

## Not to be confused with

Shortest-path algorithms minimise the cost from one start to each vertex, one traveller at a time. An MST minimises the total cost of one network that connects all vertices, with no regard for any single route. Rule: one traveller's route, Dijkstra; the cheapest wiring for everyone, an MST.

## Interview Qs

### Kruskal or Prim: which would you use?

Both are greedy and give an MST with the same total weight. Kruskal sorts the edge list and uses union-find to skip cycles, O(E log E), so it fits when the input is an edge list. Prim grows one tree from a start vertex with a min-heap, O(E log V), and fits adjacency lists or, in its O(V²) form, dense graphs.

### How many edges does a spanning tree have, and why?

Exactly V - 1. A tree on V vertices needs V - 1 edges to connect them all. With one fewer, some vertex is left out. With one more, the extra edge links two vertices that are already connected, so it always closes a cycle.

### Why does Kruskal skip an edge whose ends share a root?

Equal roots mean the two ends are already connected by edges taken earlier, so this edge would close a cycle, and a tree has none. Because edges come cheapest first, the path already connecting them uses edges no more expensive than this one, so skipping it never makes the total worse.
