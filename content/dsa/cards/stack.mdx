## Why it exists

Many problems must finish the newest thing first: close the last open bracket, return from the last call. A stack keeps that order.

## How it works

| Use | What sits on the stack |
|---|---|
| Method calls | one frame per call that has not returned |
| Bracket matching | each opening bracket not yet closed |
| Iterative DFS | vertices still to explore |
| Expression evaluation | operands and operators (Dijkstra's two stacks) |
| Browser back button | pages visited, newest on top |

- **Overflow:** recursion too deep for the call stack; Java throws `StackOverflowError`.
- **Underflow:** popping an empty stack.

## Example

Valid parentheses: push the expected closer; each closer must match the top.

```java
boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(') stack.push(')');
        else if (c == '[') stack.push(']');
        else if (c == '{') stack.push('}');
        else if (stack.isEmpty() || stack.pop() != c) return false;
    }
    return stack.isEmpty();
}
```

## Interview Qs

### What is a stack, and where is it used?

A LIFO collection: push, pop and peek work at the top in O(1). Used for method calls, bracket matching, DFS and expression evaluation.

### Stack overflow vs stack underflow?

Overflow: no room left, usually recursion too deep (`StackOverflowError`). Underflow: popping an empty stack (`EmptyStackException` from `Stack`, `NoSuchElementException` from `ArrayDeque`).
