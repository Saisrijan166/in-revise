## What it is

Recursion is when a method solves a problem by calling itself on a smaller version of the same problem. The calls stop at the base case: an input so small that the method returns the answer directly. Every other input goes to the recursive case, which calls the method again on a smaller input and uses the result. Each call that has not finished waits on the call stack, the [stack](card:stack) of method calls you met earlier.

## Why it exists

Some problems are made of smaller copies of themselves. The digit sum of 472 is 2 plus the digit sum of 47; a tree is a root with smaller trees under it. A loop handles the tree case awkwardly, because you must keep your own list of places still to visit. Recursion lets the code follow the shape of the problem, and the call stack remembers where each call has to continue. Merge sort, quick sort, tree traversals and DFS later in this tech are all written this way.

## How it works

  A -. "returns 2 + 11 = 13" .-> M([caller])`}
/>

1. `sumDigits(472)` is not small enough, so it calls `sumDigits(47)` and waits. Its frame, holding `n = 472`, stays on the call stack.
2. `sumDigits(47)` calls `sumDigits(4)` and waits too. Three frames are now on the stack.
3. `sumDigits(4)` reaches the base case (`n < 10`) and returns 4 without another call. Its frame is removed.
4. `sumDigits(47)` continues and returns 7 + 4 = 11; then `sumDigits(472)` returns 2 + 11 = 13.
5. To find the cost, count the calls for time and the longest chain of waiting calls for space. Here there are 3 calls and a depth of 3, one per digit.

So the key is: calls go down until the base case, and the answers come back up in reverse order.

## Example

The full method, with the base case checked before the recursive call.

```java
static int sumDigits(int n) {
    if (n < 10) return n;               // base case: one digit
    return n % 10 + sumDigits(n / 10);  // last digit + sum of the rest
}

System.out.println(sumDigits(472));
System.out.println(sumDigits(7));
```

```text output
13
7
```

What to notice:

- `if (n < 10) return n;` comes first. Remove it and `n` shrinks to 0 and stays 0, so the calls never end and the JVM throws `StackOverflowError`.
- `n / 10` drops the last digit, so each call has one digit fewer. That is the progress toward the base case.
- `sumDigits(7)` returns at once: the base case also answers the smallest inputs directly.
- Time and extra space are both O(number of digits): one call and one frame per digit.

## Rules and defaults

- **Base case first:** check it before the recursive call, or the method calls itself forever.
- **Progress:** each call must get a strictly smaller input. A call with the same input repeats forever.
- **One frame per call:** the JVM creates a new frame for every method call, even when the call is the method's last step (a tail call). So deep recursion can overflow in Java even when written in tail form.
- **Stack size:** each thread has a fixed stack; the default is 1024 KB on Linux/x64 (Java SE 25) and can be changed with `-Xss`. When the calls need more, the JVM throws `StackOverflowError`. A loop is the safer fix than a bigger stack.

## Not to be confused with

Recursion repeats work by calling the method again, and the call stack keeps track of where each call stopped. Iteration repeats work with a loop that updates variables, and keeps any list of pending work in your own stack or queue. Any recursion can be rewritten as a loop. Rule: recursion when the problem branches into smaller problems; a loop when it is a straight line, or when the depth could reach n.

## Common mistakes

- **"The result of the recursive call comes back on its own."** A call returns its answer to the caller only. If you write `sumDigits(n / 10);` without using or returning its value, the work is thrown away and the method returns the wrong answer.

## Interview Qs

### What does every recursive method need?

A base case that returns without calling again, and a recursive case that calls the method on a smaller input. Each call must make progress toward the base case; otherwise the calls never stop and the program ends with a `StackOverflowError`.

### What is the space cost of recursion?

O(maximum depth), because every call that has not returned keeps a stack frame. Walking a balanced tree goes about log n deep, so O(log n); walking a linked list or a skewed tree goes n deep, so O(n), even if the method allocates nothing.

### Why is naive recursive Fibonacci slow, and how do you fix it?

`fib(n)` calls `fib(n - 1)` and `fib(n - 2)`, and both recompute the same smaller values. Drawn as a recursion tree, `fib(5)` already makes 15 calls and computes `fib(2)` three times; the count grows exponentially. Storing each answer the first time makes it O(n); you will see this in [dynamic programming](card:dynamic-programming).

### When would you replace recursion with a loop?

When the depth can grow with n, like walking a long linked list, because Java gives every call a frame and a million frames overflow the stack. A loop uses O(1) extra space, or an explicit stack on the heap when you need to remember pending work.
