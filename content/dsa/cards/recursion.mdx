## Why it exists

Some problems hold smaller copies of themselves: a tree is made of subtrees. Recursion lets the code follow that shape.

## How it works

<Mermaid
  alt="fact(3) calls fact(2), which calls fact(1), the base case. Answers return in reverse: 1, then 2, then 6 to the caller."
  chart={`flowchart LR
  A["fact(3)"] -- calls --> B["fact(2)"]
  B -- calls --> C["fact(1): base case"]
  C -. returns 1 .-> B
  B -. returns 2 .-> A
  A -. returns 6 .-> M([caller])`}
/>

- Calls go down until the base case; answers come back up in reverse order.
- To count time, draw the recursion tree: total work is the sum over its nodes.

## Example

```java
int sumDigits(int n) {
    if (n < 10) return n;               // base case
    return n % 10 + sumDigits(n / 10);  // smaller input
}
// sumDigits(472) = 2 + sumDigits(47) = 2 + 7 + 4 = 13
```

## Interview Qs

### What does every recursive method need?

A base case that returns without calling again, and a recursive case that calls itself on a smaller input, so the calls always reach the base case.

### What is the space cost of recursion?

O(maximum depth), since each open call keeps a frame: O(log n) on a balanced tree, O(n) on a skewed tree or a list.

### Why is naive recursive Fibonacci slow, and how do you fix it?

It recomputes the same values again and again, so the number of calls grows exponentially. Store each answer once ([dynamic programming](card:dynamic-programming)) and it becomes O(n).
