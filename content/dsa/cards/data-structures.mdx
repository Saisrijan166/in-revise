## Why it exists

Data can be stored in many ways, each making some operations fast and others slow. Picking the layout is picking the costs.

## How it works

| Family | Shape | Examples |
|---|---|---|
| Linear | items in one sequence | array, linked list, stack, queue |
| Non-linear | one item links to many (branches) | tree, heap, graph |
| Hash-based | a hash of the key picks the slot | HashMap, HashSet |
| Specialised | built for one job | trie (prefixes), union-find (groups) |

- Some books file hash tables under non-linear; the costs matter more than the label.

## Example

```java
Queue<Integer> a = new ArrayDeque<>(); // array inside
Queue<Integer> b = new LinkedList<>(); // linked nodes inside
a.offer(1); b.offer(1);                // same ADT operations
a.poll();   b.poll();                  // same FIFO behaviour, different storage
```

## Interview Qs

### What is a data structure?

A way to organise data, with its operations, so the operations a program uses most are cheap: an array for index access, a HashMap for lookup by key.

### What is the difference between an ADT and a data structure?

An ADT lists the operations and their meaning, like a queue's offer and poll. A data structure is one way to store data that delivers them, at its own costs.

### Linear vs non-linear data structure?

Linear: items sit in one sequence (arrays, lists, stacks, queues). Non-linear: an item can link to several others (trees, graphs).
