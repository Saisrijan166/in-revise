## Why it exists

Several correct algorithms can solve the same problem. Complexity helps choose one that still finishes when the input grows.

## How it works

| Clue | First estimate |
| --- | --- |
| Touch every item once | O(n) |
| Cut a sorted range in half | O(log n) |
| Try every pair | O(n²) |

- Drop constants and smaller terms: O(3n + 8) becomes O(n).
- Count auxiliary arrays, maps, sets and recursive calls as extra space.

## Example

```java
int sum = 0;
for (int x : nums) sum += x; // O(n) time, O(1) extra space
```

## Interview Qs

### What does O(n) mean?

Work grows roughly in proportion to the input size. A scan through n array values is O(n), even when each iteration does a fixed number of operations.

### Is two loops always O(n²)?

No. Two separate loops are O(n + n), so O(n). A loop inside another loop that can each run n times is O(n²).
