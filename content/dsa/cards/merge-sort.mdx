## Why it exists

Simple sorts take O(n²). Merging two sorted lists is cheap, so merge sort turns sorting into cheap merges with a guaranteed O(n log n).

## How it works

<Compare id="merge-sort-vs-quick-sort" />

- The two halves are split at the middle, so the depth is always log n.
- The [merge step](card:merge-step) uses `<=` to take the left item on ties; that keeps it stable.

## Example

```java
void merge(int[] nums, int lo, int mid, int hi, int[] tmp) {
    for (int i = lo; i <= hi; i++) tmp[i] = nums[i];
    int left = lo, right = mid + 1;
    for (int k = lo; k <= hi; k++) {
        if (left > mid) nums[k] = tmp[right++];
        else if (right > hi) nums[k] = tmp[left++];
        else if (tmp[left] <= tmp[right]) nums[k] = tmp[left++];  // stable
        else nums[k] = tmp[right++];
    }
}
int[] a = {2, 5, 1, 4}; merge(a, 0, 1, 3, new int[4]);  // sorted halves
System.out.println(Arrays.toString(a));
```

```text output
[1, 2, 4, 5]
```

## Interview Qs

### Why is merge sort O(n log n)?

Halving gives log n levels of recursion. At each level, all merges together touch n items once. So the total is n work times log n levels.

### Why is merge sort a good choice for linked lists?

Merging lists only relinks nodes, so it needs no helper array, and it never needs random access. It stays O(n log n) on any input.

### How do you count inversions in an array?

Count pairs i < j with nums[i] > nums[j] during merge sort: when the right item is taken first, add the number of items left in the left half. O(n log n).
