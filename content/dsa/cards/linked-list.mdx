## What it is

A linked list stores values in separate objects called nodes. Each node holds one value and a reference to the next node; a reference is how Java points from one object to another, and `null` means it points nowhere. The list keeps only a reference to the first node, called the head. In a singly linked list each node links to the next one only; in a doubly linked list it also links back to the previous one.

## Why it exists

An [array](card:arrays) keeps its items side by side, so inserting at the front of 1,000,000 items shifts all of them one slot right. A linked list inserts at the front by creating one node and pointing it at the old head: no shifting, whatever the size. The price is access. Nodes can sit anywhere in memory, so there is no way to compute where the 500,000th node is; you follow 500,000 links to reach it.

## How it works

1. **Read the i-th value:** start at the head and follow `next` i times. This is O(n), because nothing lets you skip ahead.
2. **Insert at the head:** create a node, set its `next` to the current head, then make the new node the head. This is O(1).
3. **Insert after a node `p` you hold:** set `newNode.next = p.next`, then `p.next = newNode`. The relink is O(1); if you only know the position, walking there first is O(n).
4. **Delete the node after `p`:** set `p.next = p.next.next`, and the skipped node is gone. In a singly linked list you therefore need the node before the one to delete; a doubly linked node reaches it through its `prev` link.
5. **Search for a value:** walk from the head, comparing each value, until you find it or reach `null`. This is O(n).

So the change itself is one or two link updates; the cost is in getting to the right node.

## Example

Reversing a linked list is the classic interview task. It walks the list once and flips each `next` link:

```java
class ListNode {
    int val; ListNode next;
    ListNode(int val, ListNode next) { this.val = val; this.next = next; }
}

ListNode reverse(ListNode head) {
    ListNode prev = null, curr = head;
    while (curr != null) {
        ListNode next = curr.next;   // 1. save the rest of the list
        curr.next = prev;            // 2. flip this node's link
        prev = curr;                 // 3. move both one step on
        curr = next;
    }
    return prev;                     // 1 -> 2 -> 3 becomes 3 -> 2 -> 1
}
```

What to notice:

- `next` is saved before the link is flipped. Without that line, `curr.next = prev` would cut off the rest of the list and it would be lost.
- When the loop ends, `curr` is `null` and `prev` holds the old last node, which is the new head.
- It visits each node once and uses three references, whatever the length: O(n) time and O(1) extra space.

## Rules and defaults

- **Java `LinkedList`:** a doubly linked list that implements both `List` and `Deque`, and allows `null` items. It is not synchronised.
- **`get(i)` on a `LinkedList`:** it walks from the beginning or the end, whichever is closer to `i`, which is still O(n).
- **Edge cases to test:** an empty list (`head == null`), a single node, and two nodes. Ask the interviewer whether the list can contain a cycle.
- **Circular linked list:** the last node links back to the first, so no link is `null`; a loop must stop when it returns to its starting node.

## Not to be confused with

An [array](card:arrays) keeps items side by side in one block, so any index is O(1), but inserting in the middle shifts the rest. A linked list keeps nodes anywhere, joined by links, so relinking at a held node is O(1), but reaching index i is O(n). Rule: need indexes or fast scans, use an array or `ArrayList`; need many inserts and removes at nodes you already hold, use a linked list.

## Common mistakes

- **Writing special code for the head.** Inserting or deleting at the head often needs its own `if`. Put a dummy node, which holds no real value, before the head; then every real node has a node before it. Return `dummy.next` at the end.
- **Following a link without checking it.** `curr.next.next` throws `NullPointerException` when `curr.next` is `null`. Check each link before you follow it, especially near the end of the list.

## Interview Qs

### What is the difference between a singly and a doubly linked list?

A singly linked node has one link, to the next node, so you can only walk forwards. A doubly linked node also links to the previous node, so you can walk both ways and delete a node you hold in O(1). The price is one extra reference per node.

### Why is linked-list access O(n)?

Nodes are not side by side in memory, so the address of the i-th node cannot be computed from i, as it can in an array. The only way to reach it is to start at the head and follow i links.

### How do you reverse a linked list?

Walk the list once with three references, `prev`, `curr` and `next`. At each node, save `curr.next`, point `curr.next` back at `prev`, then move `prev` and `curr` one step forward. When `curr` becomes `null`, `prev` is the new head. It takes O(n) time and O(1) extra space.
