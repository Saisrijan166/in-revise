## What it is

A binary search tree (BST) is a [binary tree](card:tree-basics) that keeps its keys in order. For every node, all keys in its left subtree are smaller than the node's key, and all keys in its right subtree are larger. The rule holds for whole subtrees, not just for the two children. Searching it works like [binary search](card:binary-search): each comparison rules out one side.

## Why it exists

A sorted array lets you binary search in O(log n), but inserting a key means shifting every larger item one place: O(n). A hash table finds keys fast but keeps no order, so "the smallest key above 50" means checking them all. A BST keeps keys sorted and lets you insert without shifting, because a new key only needs a new leaf link.

## How it works

<Compare id="binary-tree-vs-bst" />

1. Search starts at the root and compares the key with the node's key.
2. If they are equal, the key is found. If the key is smaller, the search moves to the left child; if larger, to the right child.
3. If the search reaches `null`, the key is not in the tree.
4. Insert does the same walk and, at the `null` where the search stopped, attaches a new node with the key.
5. Each step goes one level down, so the work is at most the tree's height plus one comparisons.

So the key is that one comparison per level throws away a whole subtree.

## Example

This inserts the running keys and searches for two of them; the result is the same tree 8 (3 (1, 6), 10 (-, 14)) as before.

```java
TreeNode insert(TreeNode node, int key) {
    if (node == null) return new TreeNode(key);             // empty spot: put the key here
    if (key < node.val) node.left = insert(node.left, key);
    else if (key > node.val) node.right = insert(node.right, key);
    return node;                                            // equal key: ignored
}
boolean contains(TreeNode node, int key) {
    if (node == null) return false;                         // fell off the tree: not here
    if (key == node.val) return true;
    return contains(key < node.val ? node.left : node.right, key);  // drop the other side
}
TreeNode root = null;
for (int key : new int[] {8, 3, 10, 1, 6, 14}) root = insert(root, key);
System.out.println(contains(root, 6) + " " + contains(root, 7));
```

```text output
true false
```

What to notice:

- Searching for 6 visits 8, 3 and 6: three nodes, one per level, not all six.
- Searching for 7 goes 8, 3, 6, then to the right child of 6, which is `null`, so the answer is false. Insert would put 7 exactly there.
- `insert` returns the node so the parent can store the new link: `node.left = insert(...)`. Without that assignment the new node would be lost.
- Insert the same keys in the order 1, 3, 6, 8, 10, 14 and every key becomes a right child: a chain of height 5.

## Rules and defaults

- **Delete with no child:** remove the node.
- **Delete with one child:** link the parent straight to that child.
- **Delete with two children:** copy in the inorder successor, the smallest key in the right subtree, then delete that successor. It has no left child, so this second delete is one of the easy cases.
- **Equal keys:** decide a policy. This code ignores a repeated key; Java's `TreeMap.put` replaces the value stored for an existing key.
- **No balance by default:** a plain BST's shape depends on insert order. Guaranteeing O(log n) needs a [self-balancing tree](card:balanced-trees), the next concept.

## Not to be confused with

A binary tree only limits each node to two children; a BST adds the order rule on top. Rule: every BST is a binary tree, but a binary tree is a BST only if left < node < right holds for every subtree. A heap, which you will see in [Heap and PriorityQueue](card:heap-priority-queue), orders only parent against children.

## Interview Qs

### Why can a BST become O(n)?

Its shape depends on the order of inserts. Keys inserted in sorted order each become the right child of the previous key, giving a chain of n nodes. A search may then visit every node. Self-balancing trees such as AVL and red-black trees prevent this.

### How do you validate a BST?

Recurse with an allowed range. The root may hold any key. Going left, the node's key becomes the new upper bound; going right, it becomes the new lower bound. Every node must lie strictly inside its range. This catches a key deep in a subtree that breaks an ancestor's rule, which comparing children alone misses. Time O(n).

### How do you delete a node with two children?

Find its inorder successor, the smallest key in its right subtree, by going right once and then left until there is no left child. Copy that key into the node, then delete the successor from the right subtree. The successor has no left child, so removing it is easy.
