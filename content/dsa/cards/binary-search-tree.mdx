## Why it exists

A sorted array allows binary search, but each insert shifts items, O(n). A BST keeps keys in order with quick inserts.

## How it works

<Compare id="binary-tree-vs-bst" />

- Search: compare with the node, go left or right, stop at a match or `null`.
- Delete: a leaf goes; one child moves up; two children: copy the successor (smallest on the right), then delete it.
- Equal keys: decide a policy. Java `TreeMap.put` replaces the value.

## Example

```java
boolean isValid(TreeNode node, Integer min, Integer max) {
    if (node == null) return true;
    if (min != null && node.val <= min) return false;
    if (max != null && node.val >= max) return false;
    return isValid(node.left, min, node.val)
        && isValid(node.right, node.val, max);
}

TreeNode root = new TreeNode(5);
root.right = new TreeNode(7); root.right.left = new TreeNode(3);  // 3 < 5: invalid
System.out.println(isValid(root, null, null));
```

```text output
false
```

## Interview Qs

### Why can a BST become O(n)?

Its shape depends on insertion order. Sorted keys give each node one child: a chain of n nodes. Self-balancing trees prevent this.

### How do you delete a node with two children?

Copy in its inorder successor (the smallest key in its right subtree), then delete the successor, which has no left child.

### How do you find the kth smallest key?

Do an inorder walk and count visited nodes; stop at the kth. You can stop early instead of visiting all n nodes.
