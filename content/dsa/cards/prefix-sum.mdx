## Why it exists

Re-adding a range costs O(n) per query. Running totals stored once make every range sum O(1).

## How it works

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| nums[i] | 1 | 3 | 4 | 8 | 6 | 1 | 4 | 2 | |
| pre[i] | 0 | 1 | 4 | 8 | 16 | 22 | 23 | 27 | 29 |

- Sum of indices 3 to 6 = `pre[7] - pre[3]` = 27 - 8 = 19.
- [2D prefix sums](card:prefix-sum-2d) give any rectangle sum from four corners; a [difference array](card:difference-array) does range updates.

## Example

```java
int subarraySum(int[] nums, int k) {           // Subarray Sum Equals K
    Map<Integer, Integer> seen = new HashMap<>();
    seen.put(0, 1);                             // the empty prefix
    int sum = 0, count = 0;
    for (int x : nums) {
        sum += x;
        count += seen.getOrDefault(sum - k, 0); // earlier prefixes that leave k
        seen.merge(sum, 1, Integer::sum);
    }
    return count;
}
System.out.println(subarraySum(new int[] {1, 1, 1}, 2));
```

```text output
2
```

## Interview Qs

### Why give the prefix array n + 1 slots?

`pre[0] = 0` stands for the empty prefix, so a range that starts at index 0 needs no special case: `sum(0..b) = pre[b + 1] - pre[0]`.

### Count subarrays with sum k when numbers can be negative?

A [sliding window](card:sliding-window) fails here. Keep a running sum and a map of prefix-sum counts; add the count of `sum - k` at each step. O(n) average time, O(n) space.
