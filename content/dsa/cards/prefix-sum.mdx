## Why it exists

Many range questions repeatedly add almost the same values. Prefix totals let adjacent ranges share that work.

## How it works

- Create an array of length `n + 1` with `prefix[0] = 0`.
- Set `prefix[i + 1] = prefix[i] + nums[i]`.
- A range `left..right` is `prefix[right + 1] - prefix[left]`.

## Example

```java
int[] prefix = new int[nums.length + 1];
for (int i = 0; i < nums.length; i++) prefix[i + 1] = prefix[i] + nums[i];
int range = prefix[right + 1] - prefix[left];
```

## Interview Qs

### Why is the prefix array length n + 1?

`prefix[i]` can mean the sum of elements before i. The extra zero at index 0 makes ranges beginning at index 0 use the same subtraction formula.

### When do prefix sums beat a sliding window?

Use prefix sums for many arbitrary range sums and for sum conditions with negative values. A variable sliding window normally relies on a condition that responds predictably as values are added or removed.
