## What it is

Binary search on the answer is [binary search](card:binary-search) run over the range of possible answers instead of over an array. You write a check that takes one candidate value and answers yes or no: "can Koko eat all the bananas at speed 4?" If the answers are all no up to some point and all yes after it, binary search finds the first yes. Such a check is called monotonic.

## Why it exists

Many problems ask for the smallest speed, capacity or time that still works. The direct way tries every value from 1 upwards and checks each one. With values up to a billion and an O(n) check, that is far too slow. Because the answers flip only once, each check at the middle rules out half of the remaining values, so about 30 checks cover a billion values.

## How it works

Koko has piles of 3, 6, 7 and 11 bananas and 8 hours. At speed s she eats up to s bananas from one pile per hour, so a pile of p takes p / s hours, rounded up.

| Speed | 1 to 3 | 4 | 5 to 11 |
|---|---|---|---|
| Hours needed | 27, 15, 10 | 8 | 8 or fewer |
| Finishes in 8 hours? | no | **yes, the first** | yes |

1. Set lo to the smallest sensible answer (speed 1) and hi to the largest one needed (11, the biggest pile, which finishes any pile in one hour).
2. Take mid between lo and hi and run the check on it.
3. If mid works, the answer is mid or something smaller, so set hi = mid.
4. If mid does not work, every smaller value fails too, so set lo = mid + 1.
5. Stop when lo equals hi. That value is the first one that works.

So the key is a check that can be computed for one value, and that flips from no to yes only once.

## Example

The same Koko problem in code: the answer is the slowest speed that finishes in 8 hours.

```java
int minSpeed(int[] piles, int h) {                        // Koko Eating Bananas
    int lo = 1, hi = Arrays.stream(piles).max().getAsInt(); // range of possible speeds
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (canFinish(piles, h, mid)) hi = mid;            // works: try slower
        else lo = mid + 1;                                 // too slow: go faster
    }
    return lo;                                             // the first speed that works
}
boolean canFinish(int[] piles, int h, int speed) {         // the yes/no check, O(n)
    long hours = 0;
    for (int p : piles) hours += (p + speed - 1) / speed;  // ceil(p / speed)
    return hours <= h;
}
System.out.println(minSpeed(new int[] {3, 6, 7, 11}, 8));
```

```text output
4
```

What to notice:

- `hi = mid`, not `mid - 1`, because mid itself may be the answer. Writing `mid - 1` there can skip it.
- `(p + speed - 1) / speed` rounds the division up with integers only: a pile of 7 at speed 4 takes 2 hours.
- `hours` is a `long`. With large piles and speed 1, the total can pass the `int` limit and wrap to a negative number, which would make the check say yes wrongly.
- There are n piles and 11 possible speeds, so the cost is O(n log 11), not one check per speed.

## Rules and defaults

- **Bounds:** lo and hi must contain the true answer. If hi is too small, the loop returns hi even though it fails the check.
- **Monotonic or nothing:** if the check can go yes, no, yes, binary search gives wrong answers. Prove the flip-once property before coding.
- **Smallest vs largest:** for the smallest value that works, the check goes no then yes, and you keep the first yes. For the largest value, it goes yes then no; find the first no and step back one.
- **Cost:** the number of checks is about log2(hi - lo + 1); multiply by the cost of one check.

## Not to be confused with

Plain [binary search](card:binary-search) looks for a value stored in a sorted array, comparing the target with `nums[mid]`. Binary search on the answer stores nothing: mid is a candidate answer, and the check decides which half to keep. Rule: array binary search compares with a stored value; answer binary search runs a check.

## Interview Qs

### How do you spot binary search on the answer?

The problem asks for the minimum or maximum value that meets a rule, such as the least capacity or the largest minimum distance. One candidate is easy to check, usually in O(n). And once one value works, every larger one works too (or every smaller one, for a maximum).

### Koko Eating Bananas: what are the bounds and the cost?

lo is 1, the slowest possible speed. hi is the largest pile, because at that speed every pile takes one hour, so any faster speed is never needed. Each check sums hours over n piles in O(n), and there are O(log max pile) checks, so O(n log max pile) in total.

### How do you find the largest valid X instead?

The check now goes yes, yes, then no. Binary search for the first no, then return one less. Or flip the update: when mid works, set lo = mid and take the upper middle, lo + (hi - lo + 1) / 2, so the loop cannot get stuck.
