## Why it exists

Trying every answer is slow when the range is huge. If all the yeses come after all the noes, halving finds the boundary fast.

## How it works

| Speed x | 1 … 4 | 5 | 6 … max |
|---|---|---|---|
| canFinish(x) | no | **yes, first** | yes |

- lo and hi: the smallest and largest sensible answers.
- mid passes: answer is mid or smaller; fails: go bigger.

## Example

```java
int minSpeed(int[] piles, int h) {                 // Koko Eating Bananas
    int left = 1, right = Arrays.stream(piles).max().getAsInt();
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (canFinish(piles, h, mid)) right = mid; // fits: try smaller
        else left = mid + 1;                       // too slow: go faster
    }
    return left;
}
boolean canFinish(int[] piles, int h, int speed) {
    long hours = 0;
    for (int p : piles) hours += (p + speed - 1) / speed;  // ceiling
    return hours <= h;
}
```

## Interview Qs

### How do you spot binary search on the answer?

It asks for the minimum or maximum value that meets a rule, one candidate is easy to check, and once one works, every larger one works.

### Koko Eating Bananas: what are the bounds and the cost?

From 1 up to the largest pile, which finishes every pile in one hour. Each check is O(n), so O(n log max pile) in total.

### How do you find the largest valid X instead?

Mirror it: the check goes true, true, then false. Find the first false and step back one.
