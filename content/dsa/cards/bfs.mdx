## What it is

Breadth-first search (BFS) visits every vertex reachable from a start vertex in order of distance. First the start, then all vertices one edge away, then all vertices two edges away, and so on. It keeps the vertices it has found but not yet explored in a [queue](card:queue-and-deque), first in, first out, and a visited mark stops it from handling a vertex twice. Level-order traversal of a [tree](card:tree-traversals) is BFS on a tree.

## Why it exists

Many questions ask for the fewest steps: fewest roads between two cities, fewest moves in a maze, fewest friends linking two people. Trying every path and keeping the shortest can take exponential time. BFS finds the fewest-edges distance from the start to every vertex in one pass, O(V + E), because the queue never lets a far vertex be handled before a nearer one.

## How it works

1. Mark the start as visited with distance 0, and add it to the queue.
2. Remove the vertex at the front of the queue; call it u.
3. For each neighbour v of u that is not visited yet, mark it now, set `dist[v] = dist[u] + 1`, and add it to the back of the queue.
4. Repeat from step 2 until the queue is empty. Any vertex still unmarked cannot be reached from the start.

So the key is: the FIFO queue makes every distance-k vertex leave before any distance-(k + 1) vertex.

## Example

BFS from city 0 on the city graph built in [Graphs and How to Store Them](card:graph-basics), with `n` and `graph` from there.

```java
int[] dist = new int[n];
Arrays.fill(dist, -1);                              // -1 = not reached yet
Deque<Integer> queue = new ArrayDeque<>();
dist[0] = 0;                                        // start at city 0
queue.offer(0);
while (!queue.isEmpty()) {
    int u = queue.poll();
    for (int v : graph.get(u)) {
        if (dist[v] == -1) {                        // first time seen: mark it now
            dist[v] = dist[u] + 1;
            queue.offer(v);
        }
    }
}
System.out.println(Arrays.toString(dist));
```

```text output
[0, 1, 1, 2, 2, 3]
```

What to notice:

- `dist` doubles as the visited mark: -1 means not reached. City 5 is three roads from city 0, by 0-1-3-5.
- The mark is set when a city is added, not when it is removed. City 2 is a neighbour of both 0 and 1, and city 4 of both 2 and 3; marking on removal would put each of them in the queue twice.
- Every city enters the queue once and every list is scanned once, so the run is O(V + E) time and O(V) extra space.

## Rules and defaults

- **Equal costs only:** BFS distances count edges. With different edge weights, use Dijkstra, which you will see in [Shortest Paths](card:shortest-paths).
- **The path itself:** store `parent[v] = u` when you mark v, then walk the parents back from the target to the start.
- **Early stop:** to find one target, stop when you first mark it; its distance is already final.
- **Several starts:** put every start in the queue at distance 0 before the loop. This is multi-source BFS, used for spreading problems on grids.
- **Matrix input:** with an adjacency matrix the neighbour loop scans a whole row, so BFS costs O(V²).

## Not to be confused with

BFS explores level by level with a queue and gives fewest-edges distances. [DFS](card:dfs), the next concept, follows one path as deep as it can with a stack, and the first path it finds can be long. Rule: fewest steps, BFS; reachability, components or cycles, either one, and DFS is usually shorter to write.

## Common mistakes

- **"A visited check is optional."** In a graph with cycles, city 0 adds 1, city 1 adds 0 again, and the queue never empties. Every graph BFS needs the mark; only a tree can skip it.

## Interview Qs

### Why does BFS give the shortest path in an unweighted graph?

The queue removes vertices in order of distance: every vertex one edge away before any vertex two edges away. So the first time BFS reaches a vertex, it has come by a path with the fewest edges, and no shorter path can appear later. That is why `dist[v] = dist[u] + 1` is final when it is set.

### When does BFS not give the shortest path, and what do you use instead?

When edges have different weights. Two cheap roads can take less time than one slow road, but BFS prefers the single road because it counts edges. Use Dijkstra for non-negative weights, or 0-1 BFS when every weight is 0 or 1.

### How do you get the path, not just the distance?

Keep a `parent` array. When you mark v while exploring u, set `parent[v] = u`. After BFS, start at the target and follow `parent` back to the start, then reverse the list. This adds O(V) space and no extra time.
