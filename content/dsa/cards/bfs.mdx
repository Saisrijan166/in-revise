## Why it exists

Many questions ask for the fewest steps: fewest hops, moves or friends between two points. BFS answers this by exploring nearest vertices first.

## How it works

<Steps label="BFS from a start vertex">
  <Step title="Start">Mark the start as visited and put it in the queue.</Step>
  <Step title="Take">Remove the vertex at the front of the queue.</Step>
  <Step title="Spread">Mark each unvisited neighbour and add it to the back.</Step>
  <Step title="Repeat">Continue until the queue is empty.</Step>
</Steps>

- Mark a vertex when you add it, not when you remove it; otherwise it can enter the queue many times.
- Keep a `dist` array to know each vertex's level.

## Example

```java
int[] dist = new int[n];
Arrays.fill(dist, -1);                 // -1 = not visited yet
Deque<Integer> queue = new ArrayDeque<>();
dist[start] = 0;
queue.offer(start);
while (!queue.isEmpty()) {
    int u = queue.poll();
    for (int v : graph.get(u))
        if (dist[v] == -1) { dist[v] = dist[u] + 1; queue.offer(v); }
}
// dist[v] = fewest edges from start to v
```

## Interview Qs

### Why does BFS give the shortest path in an unweighted graph?

It removes vertices in order of distance: every vertex one edge away before any two edges away. So the first time it reaches a vertex, no path with fewer edges exists.

### When does BFS fail to give the shortest path?

When edges have different weights. Three cheap edges can cost less than one expensive edge. Use [Dijkstra](card:dijkstra) for non-negative weights.
