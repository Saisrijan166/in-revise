## What it is

A heap is a [complete binary tree](card:complete-binary-tree) with one ordering rule, the heap property. In a min-heap every parent is less than or equal to its children, so the smallest item is at the root; a max-heap is the mirror image. Because the tree is complete, it is stored in a plain array with no links. A priority queue is a [queue](card:queue-and-deque) that always serves the most important item next, and a heap is the usual way to build one, as in Java's `PriorityQueue`.

## Why it exists

Many tasks need the next smallest or largest item again and again while new items keep arriving: the next job to run, the closest unvisited city. Sorting the list after each arrival costs O(n log n) every time. Scanning for the minimum costs O(n) every time. A heap only keeps the minimum at the top and the rest loosely ordered, so both adding an item and removing the top cost O(log n).

## How it works

1. The items sit in an array, level by level: index 0 is the root, and the children of index i are at 2i + 1 and 2i + 2.
2. To add an item (offer), put it at the end of the array, then swap it with its parent while it is smaller than the parent. This is called sift up.
3. To remove the top (poll), take the root, move the last item into its place, then swap it with its smaller child while it is larger than that child. This is sift down.
4. Each sift moves at most one level per swap, and a complete tree has height about log n, so offer and poll are O(log n).

So the key is that only the path between the root and one leaf changes on each operation.

## Example

This adds five numbers to Java's `PriorityQueue`, prints it, then polls it empty.

```java
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
for (int x : new int[] {5, 1, 8, 3, 2}) minHeap.offer(x);
System.out.println(minHeap + " peek=" + minHeap.peek());
StringBuilder out = new StringBuilder();
while (!minHeap.isEmpty()) out.append(minHeap.poll()).append(' ');
System.out.println(out.toString().trim());
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
maxHeap.addAll(List.of(5, 1, 8, 3, 2));
System.out.println("max first: " + maxHeap.poll());
```

```text output
[1, 2, 8, 5, 3] peek=1
1 2 3 5 8
max first: 8
```

What to notice:

- Printing shows the internal array, the one in the picture: `[1, 2, 8, 5, 3]` is not sorted, but each parent is smaller than its children.
- `peek` reads the root without removing it. Only repeated `poll` calls give sorted output, 1 2 3 5 8.
- `Collections.reverseOrder()` flips the comparison, turning the same class into a max-heap.
- For objects, pass a comparator, such as `(a, b) -> Integer.compare(a[1], b[1])` to order `int[]` pairs by their second value.

## Rules and defaults

| What | Default | Where |
|---|---|---|
| Order | Natural order, smallest first: a min-heap | `PriorityQueue`, Java SE 25 |
| Initial capacity | 11, and the array grows as needed | `new PriorityQueue<>()`, Java SE 25 |

- **Costs (Java SE 25):** `offer`, `add`, `poll` and `remove()` are O(log n); `peek`, `element` and `size` are O(1); `contains` and `remove(Object)` are O(n).
- **Not allowed:** `null` elements. With natural ordering, items must be `Comparable`, or `offer` may throw `ClassCastException`.
- **Ties:** if several items are equal and smallest, the head is any one of them.
- **Threads:** `PriorityQueue` is not synchronized; use `PriorityBlockingQueue` when several threads share the queue.
- **Where it is used:** [Top K and K-way merge](card:top-k-heap), the running median, and [Dijkstra's shortest paths](card:shortest-paths), which you will see later.
- **Comparators:** use `Integer.compare(a, b)`, not `a - b`, which can overflow. You will see why in [Java pitfalls](card:java-pitfalls).

## Not to be confused with

A heap orders only each parent against its children, so it knows where the minimum is and nothing more. A [binary search tree](card:binary-search-tree) orders every left subtree against every right subtree, so it can search for any key and list all keys in order. Rule: only the next min or max, heap; search, ranges or sorted order, balanced BST such as `TreeMap`.

## Interview Qs

### How do you make a max-heap in Java?

Pass a reversed comparator: `new PriorityQueue<>(Collections.reverseOrder())`, or `(a, b) -> Integer.compare(b, a)`. Avoid `(a, b) -> b - a`, because the subtraction can overflow for large values and silently break the order.

### Why is building a heap from n items O(n), not O(n log n)?

Treat the array as a complete tree and sift down each parent, from the last parent back to the root. About half the nodes are leaves and never move, and most others are near the bottom and move only a level or two. Adding up these short moves gives O(n) in total.

### Why is a heap stored in an array and not with node links?

A complete tree has no gaps: its levels fill left to right. So the node at index i always has its children at 2i + 1 and 2i + 2 and its parent at (i - 1) / 2. No links are needed, which saves memory and keeps the items close together.
