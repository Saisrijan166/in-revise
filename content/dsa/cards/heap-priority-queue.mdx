## Why it exists

Some tasks need the next smallest or largest item again and again as items arrive. Re-sorting each time is slow.

## How it works

<Mermaid
  alt="A min-heap stored as the array 1, 3, 2, 7, 4. Root 1 at index 0 has children 3 and 2 at indexes 1 and 2; node 3 has children 7 and 4 at indexes 3 and 4."
  chart={`flowchart TD

- offer: add at the end; swap up while smaller than the parent.
- poll: move the last item to the root, swap down with the smaller child.

## Example

```java
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
PriorityQueue<int[]> byDist = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));

minHeap.offer(5); minHeap.offer(1); minHeap.offer(3);
minHeap.peek();   // 1, stays
minHeap.poll();   // 1, removed; top is now 3
```

## Defaults

| What | Default | Where |
|---|---|---|
| Order | Natural order, smallest first (min-heap) | `PriorityQueue`, Java SE 25 |
| Initial capacity | 11 (grows as needed) | `new PriorityQueue<>()`, Java SE 25 |

## Interview Qs

### How do you make a max-heap in Java?

Pass `Collections.reverseOrder()` or a comparator lambda; use `Integer.compare`, not `a - b` ([why](card:java-pitfalls)).

### Why is building a heap O(n), not O(n log n)?

Sift down each parent, last to first. Most nodes are near the bottom and move only a few levels, so the total is linear.
