## Why it exists

Merge sort needs an extra array. Quick sort works in place with a short inner loop, so it is usually fastest.

## How it works

<Steps label="quickSort(nums, lo, hi)">
  <Step title="Pick a pivot">Ideally a random item.</Step>
  <Step title="Partition">Smaller left, larger right; Lomuto leaves the pivot in its final place.</Step>
  <Step title="Recurse">Sort both sides; stop at size 0 or 1.</Step>
</Steps>

- Even splits give log n levels; a min or max pivot each time gives n levels: O(n²).
- [Quickselect](card:quickselect) recurses into one side: k-th smallest in average O(n).

## Example

```java
int partition(int[] nums, int lo, int hi) {     // Lomuto: pivot = last item
    int pivot = nums[hi], i = lo;
    for (int j = lo; j < hi; j++) {
        if (nums[j] < pivot) swap(nums, i++, j);
    }
    swap(nums, i, hi); return i;
}
void quickSort(int[] nums, int lo, int hi) {
    if (lo >= hi) return;
    int p = partition(nums, lo, hi);
    quickSort(nums, lo, p - 1); quickSort(nums, p + 1, hi);
}
void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
```

## Interview Qs

### When does quick sort become O(n²), and how do you avoid it?

When every pivot is the smallest or largest item (last item of sorted input): each partition removes only one item. Use a random pivot or shuffle first.

### Why is quick sort often faster than merge sort?

It sorts in place with a short inner loop and no helper array. Merge sort wins for stability or a firm worst case.
