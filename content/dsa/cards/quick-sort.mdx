## What it is

Quick sort is a divide-and-conquer sort that picks one item, the pivot, and rearranges the range so smaller items come before the pivot and the rest after it. This rearranging is called partitioning, and afterwards the pivot sits at its final sorted position. Quick sort then sorts the part before the pivot and the part after it the same way. Unlike [merge sort](card:merge-sort), it does its work before the recursive calls and needs no helper array.

## Why it exists

Merge sort needs a second array of n items. Quick sort sorts inside the array itself, and its inner loop only compares and swaps, so it is usually faster in practice. The cost of that speed is a risk: if the pivots split the range badly, the work grows to O(n²). Choosing the pivot at random removes that risk for practical purposes.

## How it works

Partitioning `[15, 2, 11, 7]` with the last item, 7, as pivot. `i` marks where the next smaller item goes:

| j | nums[j] | Smaller than 7? | Array after | i |
| --- | --- | --- | --- | --- |
| 0 | 15 | no | [15, 2, 11, 7] | 0 |
| 1 | 2 | yes: swap with index 0 | [2, 15, 11, 7] | 1 |
| 2 | 11 | no | [2, 15, 11, 7] | 1 |
| end | 7 | swap pivot into index 1 | [2, 7, 11, 15] | 1 |

1. Pick the pivot. This partition, called Lomuto, uses the last item; the code below first swaps a random item into that place.
2. Scan the range from left to right. Each item smaller than the pivot is swapped to index `i`, and `i` moves one step right.
3. Swap the pivot into index `i`. Now 7 is at index 1, its final place: everything before it is smaller, everything after it is not.
4. Sort the part before the pivot (`[2]`, done) and the part after it (`[11, 15]`) the same way.
5. Count the cost. Even splits give about log n levels of O(n) partitions: O(n log n). A pivot that is always the smallest or largest removes one item per level: n levels, O(n²).

## Example

Quick sort with a random pivot and the Lomuto partition.

```java
static void quickSort(int[] nums, int lo, int hi) {
    if (lo >= hi) return;                              // 0 or 1 item: sorted
    int p = partition(nums, lo, hi);                   // pivot is now at index p
    quickSort(nums, lo, p - 1);                        // items before the pivot
    quickSort(nums, p + 1, hi);                        // items after the pivot
}
static int partition(int[] nums, int lo, int hi) {     // Lomuto partition
    swap(nums, ThreadLocalRandom.current().nextInt(lo, hi + 1), hi);  // random pivot to the end
    int pivot = nums[hi], i = lo;                      // nums[lo..i-1] < pivot
    for (int j = lo; j < hi; j++)
        if (nums[j] < pivot) swap(nums, i++, j);
    swap(nums, i, hi);                                 // pivot into its final place
    return i;
}
static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
```

What to notice:

- The `ThreadLocalRandom` line moves a random item to the end to act as pivot. Remove it and a sorted array of a million items puts all other items on one side every time: O(n²) work and a million-deep recursion.
- After `swap(nums, i, hi)` the pivot never moves again, so the recursive calls skip it with `p - 1` and `p + 1`.
- Items equal to the pivot all go after it. With many duplicates the splits become uneven; a 3-way partition that groups `<`, `=` and `>` fixes that.
- Called as `quickSort(nums, 0, nums.length - 1)` on `[15, 2, 11, 7]`, it leaves `[2, 7, 11, 15]`.

## Rules and defaults

- **Cost:** O(n log n) time on average with O(log n) stack. The worst case is O(n²) time, and the recursion can then reach n frames.
- **Pivot choice:** the first or last item as pivot gives the worst case on sorted or reversed input. A random pivot, or shuffling the array first, makes it very unlikely.
- **Partition schemes:** Lomuto uses the last item and one left-to-right scan. Hoare scans from both ends and swaps each pair of items that sit on the wrong sides, and it is usually the faster of the two.
- **Stability:** not stable, because partition swaps items across long distances.
- **In Java:** `Arrays.sort(int[])` already uses a quick sort variant (see [sorting basics](card:sorting-basics)), so in a coding round you only write quick sort when asked to.

## Not to be confused with

Merge sort splits by position, at the middle index, and does its work when it merges after the recursive calls. Quick sort splits by value, around the pivot, and does its work when it partitions before the recursive calls. Rule: merge sort splits for free and combines with work; quick sort splits with work and combines for free.

## Interview Qs

### When does quick sort become O(n²), and how do you avoid it?

When every pivot is the smallest or largest item in its range, for example the last item of an already sorted array. Each partition then removes only one item, giving n levels of O(n) work. Pick the pivot at random or shuffle first, and the bad case becomes very unlikely.

### Why is quick sort often faster than merge sort in practice?

It sorts in place, so it never copies items into a helper array and back, and its inner loop only compares and swaps. Merge sort is still the better choice when you need a stable sort or a guaranteed O(n log n) worst case.

### Why is quick sort not stable?

Partition swaps an item with one far away. In `[(A, 5), (B, 5), (C, 1)]` with pivot `(C, 1)`, the final swap moves `(A, 5)` to the end, behind `(B, 5)`. The two items with key 5 have changed their input order.

### How do you find the k-th smallest item without sorting everything?

Use quickselect. Partition once; the pivot lands at its final index p. If p equals k, you are done; otherwise continue only into the side that holds index k. Average O(n), worst O(n²), so choose the pivot at random.
