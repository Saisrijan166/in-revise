## What it is

A greedy algorithm builds an answer one step at a time and, at each step, takes the choice that looks best right now. It never goes back to change a choice. Many greedy solutions start by [sorting](card:sorting-basics) the input, so the best next choice is always the next item. Greedy is correct only when the local best choice is always part of some best overall answer, which you must argue, not assume.

## Why it exists

Trying every combination of choices is exponential, and even [DP](card:dynamic-programming) has to compare every option at every state. For some problems that work is not needed: one choice can be proven safe, so the other options never have to be compared. Then a sort and one pass give the answer, in O(n log n) time.

## How it works

1. Sort the events by end time, earliest first.
2. Take the first event, because it ends first and leaves the most time for the rest.
3. Walk the remaining events in order. Take an event if it starts at or after the end of the last one taken; otherwise skip it.
4. Never undo a choice. The number of events taken is the answer.

So the key is choosing the right sort key and being able to say why the first choice is safe.

## Example

Activity selection in Java, on the events from the picture:

```java
int maxEvents(int[][] events) {                 // each event: [start, end]
    Arrays.sort(events, (a, b) -> Integer.compare(a[1], b[1]));   // earliest end first
    int count = 0, lastEnd = Integer.MIN_VALUE;
    for (int[] e : events) {
        if (e[0] >= lastEnd) {                   // starts at or after the last end
            count++;
            lastEnd = e[1];                      // commit: never undone
        }
    }
    return count;
}
System.out.println(maxEvents(new int[][] {{1, 10}, {2, 3}, {4, 5}}));
```

```text output
2
```

What to notice:

- The sort key is `a[1]`, the end time. Sort by start instead and the code takes [1, 10] first and returns 1.
- `e[0] >= lastEnd` lets an event start at the moment the last one ends. Use `>` if touching events clash.
- `lastEnd` starts at `Integer.MIN_VALUE`, so the first event is always taken.
- After the sort there is one pass with no going back, so the cost is O(n log n).

## Rules and defaults

- **Prove it or drop it:** the usual argument is an exchange: take any best answer, swap in the greedy choice, and show the answer is no worse.
- **Look for a counterexample:** before coding, try two or three tiny inputs where another choice might win.
- **Classic greedy problems:** activity selection (sort by end), Jump Game II (track the farthest reach), Gas Station, and the fewest intervals to remove, which is n minus the activity selection count.
- **Coin change:** greedy is optimal for some coin sets, such as the euro coins, but not for every set.

## Not to be confused with

[Dynamic programming](card:dynamic-programming) compares every option at every state and keeps the best, so it is correct whenever the recurrence is right. Greedy keeps only one option per step, so it is faster but needs a proof. Rule: greedy when one choice is provably safe; DP when you must compare options.

## Interview Qs

### How do you know a greedy choice is correct?

Show that some best answer starts with your choice. The usual argument is an exchange: take any best answer, replace its first choice with the greedy one, and show the answer is still valid and no worse. If you cannot argue it, try small inputs for a counterexample before writing any code.

### Why sort events by end time, not by start time or by length?

The event that ends first leaves the most time for all the others, and swapping it into any best answer never removes an event. Earliest start fails on [1, 10], [2, 3], [4, 5]: it takes the long event and gets 1. Shortest first fails on [1, 5], [4, 7], [6, 10]: it also gets 1 instead of 2.

### Does greedy ever work for coin change?

Yes, for some coin sets, such as the euro coins, where taking the largest coin that fits is proven optimal. For an arbitrary set it can fail: with {1, 3, 4} and amount 6, greedy uses three coins and the best is two. Then use the DP for coin change.
