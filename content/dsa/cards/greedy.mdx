## Why it exists

Trying every combination is slow. When the best local step is always part of a best answer, one sorted pass is enough.

## Example

```java
int maxEvents(int[][] events) {                  // each event: [start, end]
    Arrays.sort(events, (a, b) -> Integer.compare(a[1], b[1]));  // by end
    int count = 0, lastEnd = Integer.MIN_VALUE;
    for (int[] e : events) {
        if (e[0] >= lastEnd) {                   // fits after the last pick
            count++;
            lastEnd = e[1];
        }
    }
    return count;
}
System.out.println(maxEvents(new int[][] {{1, 3}, {2, 4}, {3, 5}}));
```

```text output
2
```

## Interview Qs

### How do you know a greedy choice is correct?

Show the greedy choice property: some best answer starts with your choice, since swapping it in never makes things worse. If you cannot, try small inputs for a counterexample before coding.

### Why sort events by end time, not start time or length?

The event that ends first leaves the most room for the rest. Earliest start and shortest event both have counterexamples.

### Does greedy ever work for coin change?

Yes, for some coin systems such as the euro coins, where it is proven optimal. For an arbitrary set of coins, it can fail, so use DP.
