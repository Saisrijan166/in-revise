## What it is

A `String` is a sequence of characters, such as `"java"`, read by index like an [array](card:arrays): `s.charAt(0)` is `'j'`. A Java String is immutable: once created, its characters can never change. Methods that seem to change it, such as `toUpperCase()` or `replace()`, return a new String. A `StringBuilder` is the changeable partner: a text buffer you can append to, insert into or reverse in place, then turn into a String with `toString()`.

## Why it exists

Text is everywhere in coding rounds: palindromes, anagrams, reversing words, building an answer. Because a String never changes, Java can share one String object safely between variables and threads, and it is a safe key for a map, which needs keys that do not change. The price is that every "change" makes a copy. If you build a long result with `+=` in a loop, each step copies all the text so far. `StringBuilder` exists so that building text costs one copy per character instead.

## How it works

| You write | What happens | Cost to build n characters |
|---|---|---|
| `s += word` in a loop | a new String each step, all old text copied | O(n²) |
| `sb.append(word)` in a loop | text added to one buffer that grows when full | O(n) |
| `s == t` | compares the two references | O(1) |
| `s.equals(t)` | compares the characters one by one | O(length) |

1. `String s = "go";` points `s` at a String object holding `go`.
2. `s += "lang";` creates a third String, `golang`, copies both parts into it and points `s` at it. The old `go` is unchanged.
3. In a loop of n steps, step k copies about k characters, so the total is 1 + 2 + … + n, which is O(n²).
4. A `StringBuilder` keeps spare room, like an [ArrayList](card:dynamic-array). `append` writes into the free space, and only a rare resize copies, so n characters cost O(n) in total.
5. `toString()` copies the finished buffer once into a new, immutable String.

## Example

This code shows the `==` trap, immutability, a StringBuilder and counting letters:

```java
String a = "java";
String b = new StringBuilder("ja").append("va").toString(); // same text, new object
System.out.println(a == b);                 // compares references
System.out.println(a.equals(b));            // compares characters
String up = a.toUpperCase();                // returns a new String
System.out.println(a + " " + up);
StringBuilder sb = new StringBuilder();
for (String w : List.of("go", "java", "rust")) {
    sb.append(w.charAt(0));                 // adds to one buffer, no copy of old text
}
System.out.println(sb.reverse());           // changes the builder in place
int[] count = new int[26];
for (char c : "java".toCharArray()) count[c - 'a']++;  // 'a' -> 0, 'j' -> 9
System.out.println(count[0] + " " + count['j' - 'a']);
```

```text output
false
true
java JAVA
rjg
2 1
```

What to notice:

- `a == b` is false although both hold `java`: `b` was built at run time, so it is a separate object. Only `equals` answers "same text?".
- After `toUpperCase()`, `a` still prints `java`. If you write `a.toUpperCase();` without keeping the result, nothing changes.
- `sb.reverse()` changed the builder itself and returned it; a String has no such method.
- A `char` is a small number, so `c - 'a'` gives 0 for `'a'` and 9 for `'j'`. An `int[26]` then counts each letter without a map.

## Rules and defaults

- **Indexes:** `charAt(i)` accepts 0 to `length() - 1`; any other index throws `IndexOutOfBoundsException`.
- **substring(a, b):** includes index `a` and excludes index `b`, so the result has length `b - a`. `"hamburger".substring(4, 8)` is `"urge"`. In OpenJDK it copies, so it costs O(b - a).
- **Regex methods:** `split` and `replaceAll` read their first argument as a regular expression; `replace` is literal. `split` also drops empty strings at the end of the result.
- **Literals:** identical string literals, and constant expressions such as `"ja" + "va"`, refer to one shared object (Java SE 25). Text built at run time is a new object.
- **StringBuilder:** not synchronised. `StringBuffer` has the same methods with synchronisation; the Java docs recommend `StringBuilder` where one thread uses the buffer.
- **StringBuilder equality:** it does not override `equals`, so two builders with the same text are not equal. Compare `sb1.toString().equals(sb2.toString())`.

## Not to be confused with

A `String` is fixed text, safe to share and to use as a map key. A `StringBuilder` is changeable text for building a result inside one method. `StringBuffer` is the older, synchronised version of `StringBuilder`, needed only when several threads append to the same buffer. Rule: build with `StringBuilder`, keep and compare as `String`.

## Common mistakes

- **"s.length is the length of a string."** That is the array syntax. For a String, call the method `s.length()`; for a `List`, `list.size()`.
- **"Strings are compared with compareTo for equality."** `compareTo` gives the alphabetical order (negative, zero or positive). It returns 0 for equal text, but `equals` states the intent and also handles a non-String argument.

## Interview Qs

### Why is String immutable in Java, and what does it cost?

Because its value cannot change, one String object can be shared by many variables, including every identical literal in the program, passed between threads without locks and used safely as a `HashMap` key. The cost is that every change, such as concatenation or `replace`, creates a new String and copies the characters.

### Why is string concatenation in a loop slow?

Each `+=` creates a new String and copies all characters built so far into it. Over n steps that is 1 + 2 + … + n copies, which is O(n²). A `StringBuilder` appends into one growing buffer, so the whole loop is O(n), and `toString()` makes the final String once.

### String vs StringBuilder vs StringBuffer?

String is immutable. StringBuilder is mutable and not synchronised, so it is the fast choice for building text in one thread. StringBuffer is mutable and synchronised, which makes it safe to share between threads but slower; it is rarely needed today.
