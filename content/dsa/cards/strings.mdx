## Why it exists

Text problems are common in interviews. Knowing that Strings cannot change explains which operations are cheap and why StringBuilder exists.

## How it works

<Compare id="string-vs-stringbuilder" />

- `charAt(i)` is O(1); in OpenJDK `substring` copies, so it costs O(length of the result).
- `s.toCharArray()` then `new String(chars)` lets you edit characters as an array.

## Example

```java
StringBuilder sb = new StringBuilder();
for (char c : "hello".toCharArray()) {
    sb.append(Character.toUpperCase(c));
}
String up = sb.toString();             // "HELLO"
int[] count = new int[26];
for (char c : "banana".toCharArray()) {
    count[c - 'a']++;                  // a=3, b=1, n=2
}
boolean same = up.equals("HELLO");     // true
```

## Interview Qs

### Why is String immutable in Java, and what does it cost?

A String's value cannot change after it is created, so it can be shared and used safely as a map key. The cost: every change creates a new String and copies the text.

### Why is concatenation in a loop slow?

Each `+=` copies all characters built so far into a new String. Over n steps that is 1 + 2 + … + n copies, O(n²). StringBuilder appends into one growing buffer: O(n).
