## What it is

Choosing a data structure means picking where your solution keeps its data, based on what it does with that data most often. Every structure makes some operations cheap and others slow: a [HashMap](card:hashmap-hashset) finds a key quickly but has no order, a [TreeMap](card:ordered-maps-sets) keeps keys sorted, a [heap](card:heap-priority-queue) always knows its smallest item. This concept gathers the structures you have met into one decision table.

## Why it exists

The right structure is often the whole solution. Two Sum with a list needs a loop inside a loop to find each partner; with a HashMap the same idea is one pass. Picking by habit, usually an `ArrayList`, turns an O(n) idea into O(n²). Picking by the repeated operation makes the fast solution almost write itself.

## How it works

| You need, again and again | Structure | In Java |
| --- | --- | --- |
| Access by position | [Array](card:arrays) or [dynamic array](card:dynamic-array) | `int[]`, `ArrayList` |
| Value for a key | [Hash table](card:hashmap-hashset) | `HashMap` |
| "Seen before?", unique items | Hash set | `HashSet` |
| Sorted keys, nearest key | [Balanced BST](card:ordered-maps-sets) | `TreeMap`, `TreeSet` |
| The most recent item first (LIFO) | [Stack](card:stack) | `ArrayDeque` |
| The oldest item first (FIFO) | [Queue](card:queue-and-deque) | `ArrayDeque` |
| The smallest or largest item | [Heap](card:heap-priority-queue) | `PriorityQueue` |
| Words that share a prefix | [Trie](card:trie) | your own node class |
| Groups that merge | [Union-find](card:union-find) | `int[] parent` |
| Links between items | [Graph](card:graph-basics) | `List<List<Integer>>` |

1. Write the brute force and mark the operation inside its loop, such as "search the list for x".
2. Name that operation in plain words, such as "is x here?" or "give me the smallest".
3. Find the row in the table whose left column says the same thing, and use that structure.
4. If two operations repeat, such as "count each word" and "keep the top k", use one structure for each and keep them in step.

So the key is: you choose by operation, never by habit.

## Example

Three small problems, each decided by its repeated operation.

```text
Contains Duplicate:  "have I seen this value?"           -> HashSet
Valid Parentheses:   "does it match the latest open '('?" -> ArrayDeque as a stack
Meeting rooms:       "which room frees up first?"         -> PriorityQueue of end times
```

What to notice:

- Each line starts from a question the loop asks for every item, not from the shape of the input. The input is an array in all three.
- Valid Parentheses needs the most recent open bracket, which is exactly last in, first out, so a stack fits and a queue does not.
- In the meeting-rooms line only the earliest end time matters, so a full sort after each meeting would be wasted work; the heap keeps just that earliest one at its head.

## Rules and defaults

- **Stack and queue in Java:** use `ArrayDeque` for both; why it beats `Stack` and `LinkedList` is in [Queue and Deque](card:queue-and-deque).
- **Order:** `HashMap` and `HashSet` promise no iteration order. Need insertion order? `LinkedHashMap`. Need sorted keys? `TreeMap`.
- **Data that never changes:** if you only search after loading, sorting once and using [binary search](card:binary-search) is enough; a `TreeMap` pays off when items keep arriving.
- **Nearest key:** `TreeMap.floorKey` and `ceilingKey` (and `TreeSet.floor` and `ceiling`) return the closest key at or below, or at or above, a value; they return null when there is none.

## Not to be confused with

A `HashMap` stores key-value pairs for fast lookup and keeps no order. A `TreeMap` stores the same pairs sorted by key, at O(log n) per operation, so it can also answer "next larger key". Rule: need only lookup, HashMap; need order or neighbours, TreeMap.

## Interview Qs

### How do you choose a data structure for a problem?

List the operations the solution repeats and how often. Pick the structure that makes the most frequent one cheap, then check that the others are still acceptable. If two operations both matter, such as counting and finding the top k, combine two structures.

### The input describes friendships or course prerequisites. What do you use?

A graph, usually stored as an adjacency list, because the data is links between items. If you only need to merge groups and ask whether two items are in the same group, union-find is simpler and faster.

### You need a map but also the next larger key. Which map?

A `TreeMap`. It keeps keys sorted, so `ceilingKey(x)` returns the smallest key at or above x and `higherKey(x)` the smallest key strictly above it, each in O(log n). A `HashMap` has no order, so it would need a full scan.
