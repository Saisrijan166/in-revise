## Why it exists

The right structure often is the solution. The wrong one turns an O(n) idea into O(n²).

## How it works

| You need | Structure | Java |
| --- | --- | --- |
| Access by position | [Array](card:arrays) / [dynamic array](card:dynamic-array) | `int[]`, `ArrayList` |
| Value by key, fast | [Hash table](card:hashmap-hashset) | `HashMap` |
| Unique items, "seen before?" | Hash set | `HashSet` |
| Sorted keys, nearest key | [Balanced BST](card:ordered-maps-sets) | `TreeMap`, `TreeSet` |
| Last in, first out | [Stack](card:stack) | `ArrayDeque` |
| First in, first out | [Queue](card:queue-and-deque) | `ArrayDeque` |
| Smallest or largest, again and again | [Heap](card:heap-priority-queue) | `PriorityQueue` |
| Words by prefix | [Trie](card:trie) | your own node class |
| Groups that merge | [Union-find](card:union-find) | `int[] parent` |
| Links between items | [Graph](card:graph-basics) | `List<List<Integer>>` |

- Two needs at once? Combine, for example a HashMap plus a heap.

## Example

```text
"Return the k most frequent words"
count each word     → HashMap<String, Integer>
keep the top k      → PriorityQueue of size k
```

## Interview Qs

### How do you choose a data structure for a problem?

List the operations it repeats and how often. Pick the structure that makes the most frequent one cheap.

### The input describes friendships or course prerequisites. What do you use?

A graph, usually an adjacency list. If you only need to merge groups and ask whether two items are in the same group, union-find is simpler.

### You need a map but also the next larger key. Which map?

A TreeMap: sorted keys with `ceilingKey` and `floorKey`. A HashMap has no order.
