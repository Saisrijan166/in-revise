## What it is

A topological sort lists the vertices of a directed graph so that every edge u → v has u before v. Read each edge as "u must happen before v", and the list is a valid order to do all the tasks. It exists only for a DAG, a directed graph with no directed cycle, because on a cycle every task waits for another one. The usual method, Kahn's algorithm, works with each vertex's in-degree: the number of edges pointing into it.

## Why it exists

Courses have prerequisites, build modules depend on other modules, and a spreadsheet cell can depend on other cells. Without an algorithm you would guess an order, check every rule, and reshuffle each time one fails. Topological sort builds a valid order in O(V + E). If no order exists, it tells you so, which is exactly the classic Course Schedule question.

Kahn's algorithm, step by step:

1. Count each vertex's in-degree, which here means how many prerequisites it is still waiting for.
2. Put every vertex with in-degree 0 in a queue: these tasks can be done now.
3. Remove a vertex from the queue and add it to the output.
4. For each edge from it to v, lower v's in-degree by one. When v reaches 0, all its prerequisites are done, so add v to the queue.
5. When the queue is empty, count the output. Fewer than V vertices means the rest sit on a cycle or wait behind one.

The DFS method gives an order too: record each vertex when its DFS call finishes, then reverse that list.

## Example

Kahn's algorithm on the four courses. Edges are pairs `{before, after}`.

```java
int n = 4;                                          // 0 Java, 1 DSA, 2 SQL, 3 Spring Boot
int[][] prereq = {{0, 1}, {0, 2}, {1, 3}, {2, 3}};  // {before, after}
List<List<Integer>> graph = new ArrayList<>();
for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
int[] indegree = new int[n];
for (int[] p : prereq) { graph.get(p[0]).add(p[1]); indegree[p[1]]++; }
Deque<Integer> queue = new ArrayDeque<>();
for (int u = 0; u < n; u++) if (indegree[u] == 0) queue.offer(u);
List<Integer> order = new ArrayList<>();
while (!queue.isEmpty()) {
    int u = queue.poll();
    order.add(u);
    for (int v : graph.get(u)) if (--indegree[v] == 0) queue.offer(v);
}
System.out.println(order.size() == n ? order : "cycle, only " + order);
```

```text output
[0, 1, 2, 3]
```

What to notice:

- Only Java starts at in-degree 0. Spring Boot starts at 2, so it enters the queue only after both DSA and SQL have come out.
- Add the pair `{3, 1}`, so that DSA also needs Spring Boot, and it prints `cycle, only [0, 2]`. DSA and Spring Boot wait for each other and never reach in-degree 0.
- Each vertex enters the queue once and each edge lowers one counter once: O(V + E).

## Rules and defaults

- **Edge direction:** edges must point from the task that comes first to the task that waits. Check which way the input pairs point, and flip them if needed.
- **DAG only:** a directed cycle makes an order impossible. An undirected graph has no direction, so the question does not apply.
- **Many answers:** when several vertices sit in the queue at once, any of them may come next, so many orders can be valid.
- **Cost:** O(V + E) time and O(V) extra space, for both Kahn's algorithm and the DFS method.

## Not to be confused with

Kahn's algorithm uses a queue like [BFS](card:bfs), but the trigger differs. BFS adds a vertex the first time any edge reaches it. Kahn's algorithm adds it only when its last incoming edge has been removed. Rule: BFS queues a vertex when first seen; Kahn's queues it when its last prerequisite is done.

## Interview Qs

### Course Schedule: can you finish all courses?

Build edges from prerequisite to course and run Kahn's algorithm. If every course comes out, yes. If some never reach in-degree 0, they sit on a cycle or depend on one, so no. It runs in O(V + E), where V is the number of courses and E the number of prerequisite pairs.

### Kahn's algorithm or DFS: which would you use?

Both are O(V + E). Kahn's is iterative, so it cannot overflow the stack, and it detects a cycle with one count at the end. The DFS method records vertices in finish order and reverses them, but it needs grey and black colours to detect a cycle. I use Kahn's unless the code already has a DFS.

### Why does a topological order exist only for a DAG?

On a cycle a → b → c → a, a must come before b, b before c, and c before a. No list can satisfy all three, so no order exists. Without a cycle, some vertex always has in-degree 0, so Kahn's algorithm can always take a next step.
