## What it is

An edge case is an input at the boundary of what the problem allows: an empty array, a single item, all values equal, the largest possible number, a graph with two separate parts. Testing edge cases means stepping through your code with these inputs, by hand, before you call it finished. It is step 6 of the [problem-solving routine](card:problem-solving-steps).

## Why it exists

The example in a problem statement is chosen to explain the task, so it is usually the easy, typical case. Most bugs hide at the boundaries: a loop that reads `nums[0]` on an empty array, an `int` sum that overflows, a search that never visits a separate part of a graph. Interviewers watch whether you look for these yourself, because testing is one of the things they score.

## How it works

| Input type | Edge cases to try |
| --- | --- |
| Array or string | empty, 1 or 2 items, duplicates, all equal, sorted, reversed |
| Numbers | negatives, zero, `Integer.MAX_VALUE`, sums past the `int` limit |
| k or target | k = 0, k larger than n, no answer exists |
| Linked list | null head, one node, two nodes, a cycle |
| Tree | empty, one node, skewed like a list |
| Graph | one node, disconnected parts, cycles |
| Intervals | touching ends such as [1, 2] and [2, 3], one inside another |

1. Before coding, ask which boundaries the input can reach, such as "can the array be empty?".
2. After coding, pick the rows of the table that match your input type.
3. Dry-run the smallest input line by line, writing down each variable, to catch off-by-one errors in loop bounds.
4. Run one extreme input in your head to check overflow and deep recursion.
5. Fix what breaks, then say aloud which cases you checked.

So the key is: the boundaries, not the examples, are where you find the bugs.

## Example

Finding the largest value: the first version passes the usual example and fails on all-negative input.

```java
static int maxWrong(int[] nums) {
    int best = 0;                              // bug: assumes some value is >= 0
    for (int x : nums) best = Math.max(best, x);
    return best;
}

static int max(int[] nums) {
    if (nums.length == 0) throw new IllegalArgumentException("empty input");
    int best = nums[0];                        // start from a real value
    for (int x : nums) best = Math.max(best, x);
    return best;
}

System.out.println(maxWrong(new int[] {-3, -1}) + " " + max(new int[] {-3, -1}));
```

```text output
0 -1
```

What to notice:

- `maxWrong` returns 0, a value that is not in the array. With `[4, 9]` it would give the right answer, which is why the bug survives the given example.
- `max` starts from `nums[0]`, so the answer is always a real element. `Integer.MIN_VALUE` as the start works too.
- Reading `nums[0]` needs a non-empty array, so the empty case is handled first. Whether to throw or return a special value is a question to ask the interviewer.

## Rules and defaults

- **Running minimum and maximum:** start a minimum at `Integer.MAX_VALUE` and a maximum at `Integer.MIN_VALUE`, or both at the first element.
- **Deep recursion:** a skewed tree or a long linked list makes recursion about n calls deep, which can throw `StackOverflowError`.
- **Disconnected graphs:** a search from one start node reaches only its own part; loop over all nodes to cover the rest.
- **Ask, do not guess:** if the problem does not say what to return when no answer exists, ask.

## Interview Qs

### Which edge cases do you check for an array problem?

Empty, one element, two elements, duplicates or all values equal, already sorted or reversed, negative numbers and zero, and values large enough that a sum overflows an `int`. For problems with k or a target, also k = 0, k larger than n, and no valid answer.

### Why test a skewed tree?

A tree where every node has one child is really a linked list. Its height is about n, so code that assumed a short, balanced tree slows down, and recursion goes about n calls deep, which can overflow the call stack for large n.

### How do you find off-by-one errors quickly?

Dry-run the smallest inputs, such as one and two items, line by line, writing each index. Check that each loop's first and last index are the ones you meant, and that `<` and `<=` are right.
