## Why it exists

The examples you are given are simple on purpose. Most bugs hide in the boundaries, and interviewers watch whether you look for them yourself.

## How it works

| Input | Test these |
| --- | --- |
| Array or string | empty, 1 or 2 items, duplicates, all equal, sorted, reversed |
| Numbers | negatives, zero, `Integer.MAX_VALUE`, sums past int |
| k or target | k = 0, k > n, no answer exists |
| Linked list | null head, one node, two nodes, a cycle |
| Tree | empty, one node, skewed like a list |
| Graph | one node, disconnected parts, cycles |
| Intervals | touching ends like [1,2] and [2,3], one inside another |

- Dry-run the smallest input line by line; it finds off-by-one errors fast.

## Example

```java
int max(int[] nums) {
    int best = nums[0];          // not 0: [-3, -1] must return -1
    for (int x : nums) best = Math.max(best, x);
    return best;                 // empty input: ask, or throw
}
```

## Interview Qs

### Which edge cases do you check for an array problem?

Empty, one element, two elements, duplicates or all equal, already sorted or reversed, negative numbers, and values large enough to overflow a sum.

### Why test a skewed tree?

A tree where every node has one child behaves like a linked list. Its height grows to about n, so recursion goes about n calls deep and code that assumed a short tree slows down or overflows the stack.
