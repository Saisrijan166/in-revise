## What it is

A controller test checks the HTTP side of an endpoint: the mapping, the binding and validation, the status code and the JSON. `@WebMvcTest` is a Spring Boot test slice: it starts only the web part of the app. MockMvc then sends fake requests through real Spring MVC, without starting a server. The service is replaced by a mock, made with Mockito, a fake object whose answers the test sets.

## Why it exists

Starting the whole app with a database for every controller check is slow, and a failure could come from anywhere. Calling the controller as a plain Java method is fast, but it skips what usually breaks: wrong paths, a missing `@Valid`, wrong status codes and JSON field names. A web slice test runs the real Spring MVC handling, so those bugs show up in milliseconds, while the mock keeps the service's logic out of the test.

## How it works

<Compare id="webmvctest-vs-springboottest" />

1. `@WebMvcTest(PaymentController.class)` builds a small Spring context with that controller, the advice classes, the JSON converters and MockMvc, but no services or repositories.
2. `@MockitoBean` adds a mock `PaymentService` to that context, so the controller's constructor receives it.
3. The test tells the mock what to return, for example payment PAY101.
4. MockMvcTester sends a request through Spring MVC. Mapping, binding, validation, the controller and the advice all run, just as in the real app.
5. The test checks the status and the JSON of the response.

## Example

One test checks a good payment and a negative amount. It ran and passed on Spring Boot 4.0.3.

```java
@WebMvcTest(PaymentController.class)
class PaymentControllerTests {
    @Autowired MockMvcTester mvc;
    @MockitoBean PaymentService service;                     // the slice loads no services
    @Test void createsPaymentAndRejectsNegativeAmount() {
        when(service.create(any(), any())).thenReturn(new PaymentResponse("PAY101", "PENDING", new BigDecimal("500")));
        assertThat(pay(500)).hasStatus(HttpStatus.CREATED).bodyJson().extractingPath("$.paymentId").isEqualTo("PAY101");
        assertThat(pay(-500)).hasStatus(HttpStatus.BAD_REQUEST);           // @Positive fails
    }
    MockMvcTester.MockMvcRequestBuilder pay(int amount) {
        return mvc.post().uri("/api/payments").header("Idempotency-Key", "order-789-payment")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"amount\": %d, \"currency\": \"INR\", \"method\": \"UPI\"}".formatted(amount));
    }
}
```

What to notice:

- No server and no database start; the test exercises the real mapping, `@Valid` and the 201 from `ResponseEntity.created`.
- The mock answers `create`, so the test checks the controller, not the payment rules. The rules get their own unit tests.
- The −500 request never reaches the mock: validation rejects it with 400 first.
- Remove `@MockitoBean` and the context fails to start, because the controller needs a `PaymentService` and the slice has none.

## Rules and defaults

- **Mocks (Spring Boot 4.0+):** use `@MockitoBean` from Spring Framework (6.2+). `@MockBean` was deprecated in Spring Boot 3.4 and removed in 4.0.
- **Where it lives (Spring Boot 4):** `@WebMvcTest` is in the `spring-boot-webmvc-test` module, package `org.springframework.boot.webmvc.test.autoconfigure`.
- **@SpringBootTest:** the default web environment is `MOCK`, so no server starts. MockMvc is available there only with `@AutoConfigureMockMvc`.
- **Real HTTP:** `webEnvironment = RANDOM_PORT` starts a server on a free port; `@AutoConfigureRestTestClient` gives a `RestTestClient` (new in Spring Framework 7.0) that calls it.
- **Rollback:** with a real server, a test's `@Transactional` does not roll back what the server wrote, because the server runs on another thread.

## Not to be confused with

A unit test checks one class alone, created with plain `new` and given mocks, with no Spring at all. A `@WebMvcTest` is a slice: real Spring MVC, but only the web layer. Integration and contract tests, and which level suits which check, come in [API testing strategy](card:api-testing-strategy). Rule: business rules → unit test; HTTP behaviour → slice.

## Interview Qs

### @WebMvcTest or @SpringBootTest?

`@WebMvcTest` loads only the web layer, so it quickly checks mappings, validation, JSON and status codes, with services mocked. `@SpringBootTest` loads the whole app; I use a few of them for full flows, with RANDOM_PORT when I want real HTTP.

### Does MockMvc start a server?

No. It runs full Spring MVC request handling, mappings, validation and advice included, with mock request and response objects. For real HTTP, I use `@SpringBootTest` with RANDOM_PORT and `RestTestClient`.

### @MockBean or @MockitoBean?

`@MockitoBean`, from Spring Framework. Spring Boot 3.4 deprecated `@MockBean`, and Spring Boot 4.0 removed it, so old tests must switch when they upgrade.
