## Why it exists

Controller bugs are wrong mappings, status codes, JSON or validation. Sending a fake request through Spring MVC catches them in milliseconds, without starting the whole app.

## How it works

<Compare id="webmvctest-vs-springboottest" />

- A RANDOM_PORT test runs the server on another thread, so `@Transactional` on the test does not roll back its data.
- Which cases to test for POST /api/payments: [API testing strategy](card:api-testing-strategy).

## Example

```java
@WebMvcTest(PaymentController.class)
class PaymentControllerTests {
    @Autowired MockMvcTester mvc;
    @MockitoBean PaymentService service;                 // the slice does not load services
    @Test void createsPaymentAndRejectsNegativeAmount() {
        when(service.create(any())).thenReturn(new PaymentResponse("PAY101", "PENDING", new BigDecimal("500")));
        assertThat(pay(500)).hasStatus(HttpStatus.CREATED);
        assertThat(pay(-500)).hasStatus(HttpStatus.BAD_REQUEST);          // @Positive fails
    }
    MockMvcTester.MockMvcRequestBuilder pay(int amount) { return mvc.post().uri("/api/payments")
            .contentType(MediaType.APPLICATION_JSON).content("{\"amount\": %d, \"currency\": \"INR\", \"method\": \"UPI\"}".formatted(amount)); }
}
```

## Defaults

| What | Default | Where |
| --- | --- | --- |
| `@SpringBootTest` web environment | `MOCK`: no server starts | Spring Boot 4.1 |
| MockMvc in `@SpringBootTest` | only with `@AutoConfigureMockMvc` | Spring Boot 4.0+ |

## Interview Qs

### @WebMvcTest or @SpringBootTest?

@WebMvcTest loads only the web layer, so it quickly checks mappings, validation, JSON and status codes. @SpringBootTest loads the whole app; use a few of them for full flows.

### Does MockMvc start a server?

No. It runs full Spring MVC request handling, mappings, validation and advice included, with mock request and response objects. For real HTTP, use RANDOM_PORT with RestTestClient.

### @MockBean or @MockitoBean?

@MockitoBean, from Spring Framework. Spring Boot 3.4 deprecated @MockBean, and Spring Boot 4.0 removed it.
