## Why it exists

One ₹500 payment crosses the gateway, the payment service and the provider. Without a shared ID you cannot join their logs, so one failure takes hours to find.

## How it works

<Compare id="logs-vs-metrics-vs-traces" />

- At the edge, accept or create the ID; put it in every log line; forward it on every outgoing call.
- Spring Boot 4.1: Actuator with Micrometer Observation records `http.server.requests`; Micrometer Tracing adds traceId and spanId to logs.
- Write structured JSON logs so tools can search by traceId or paymentId.

## Example

```text
POST /api/payments HTTP/1.1
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01

# payment service calls the provider: same trace-id, its own span as parent-id
POST /v1/charges HTTP/1.1
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-b7ad6b7169203331-01

{"level":"ERROR","traceId":"4bf92f3577b34da6a3ce929d0e0e4736","paymentId":"PAY101","msg":"provider timeout"}
```

## Defaults

| What | Default | Where |
|---|---|---|
| Trace sampling | 10% of requests (0.1) | Spring Boot 4.1, `management.tracing.sampling.probability` |
| Propagation sent | W3C | Spring Boot 4.1, `management.tracing.propagation.produce` |
| Actuator endpoints over HTTP | `health` only | Spring Boot 4.1, `management.endpoints.web.exposure.include` |

## Interview Qs

### How do you follow one request across microservices?

Use distributed tracing: the first service starts a trace, each hop sends the W3C traceparent header, and each service adds its own span. Logs carry the same trace ID, so one search shows the whole path.

### Which metrics do you watch for an API?

RED per endpoint: request rate, error rate and duration. For duration use p95 and p99 percentiles from a histogram, not the average.

### What must never go into logs?

Access tokens, passwords, session IDs, encryption keys, card or bank data and personal data. Mask or drop them; log IDs such as paymentId and traceId instead.
