## What it is

An HTTP client is the code your service uses to call another API, such as the payment gateway. Spring's clients turn a Java object into an HTTP request, send it, and turn the JSON reply back into an object. `RestClient` is the main one for normal code: the calling thread waits for the reply, which is called blocking. `WebClient` is the reactive one: the thread does not wait, and the result arrives later as a `Mono` or `Flux`, reactive types for one value or many.

## Why it exists

Calling the gateway by hand means opening connections, writing headers, turning JSON into objects and checking status codes, in every place that calls out. A Spring client does that in one chain of calls, reuses Spring Boot's JSON setup, and throws a clear exception on 4xx or 5xx. It also gives you one place to set timeouts, so a slow gateway cannot hold your threads for as long as it likes, a risk [retries and timeouts](card:retries-and-timeouts) covered.

## How it works

<Compare id="resttemplate-vs-restclient-vs-webclient" />

1. Your class asks for a `RestClient.Builder` in its constructor. Spring Boot provides one that already has the JSON converters and the timeout settings.
2. It builds the client once, with the gateway's base URL, and keeps it in a field.
3. For each call it chains the HTTP method, the URI, headers and the body, then calls `retrieve()`.
4. `.body(Type.class)` sends the request and converts the JSON reply into that type.
5. If the reply is 4xx or 5xx, `retrieve()` throws unless an `onStatus` handler deals with that status first.

## Example

The payment service charges the customer through the gateway.

```java
@Service
class GatewayClient {
    private final RestClient http;
    GatewayClient(RestClient.Builder builder) {
        this.http = builder.baseUrl("https://gateway.example.com").build();
    }
    GatewayResult charge(ChargeRequest req, String idempotencyKey) {
        return http.post().uri("/charges")
                .header("Idempotency-Key", idempotencyKey)       // order-789-payment
                .body(req)                                       // written as JSON
                .retrieve()
                .onStatus(HttpStatusCode::is4xxClientError, (rq, rs) -> { throw new GatewayRejected(rs.getStatusCode()); })
                .body(GatewayResult.class);                      // JSON reply -> record
    }
}
```

What to notice:

- The builder comes from Spring Boot, so the client gets the same JSON settings and timeouts as the rest of the app. A client made with `RestClient.create()` would skip them.
- The `Idempotency-Key` header lets the gateway spot a retried charge and not charge twice, as in [idempotency keys](card:idempotency-keys).
- `onStatus` turns a 4xx into the service's own `GatewayRejected`. Without it, the caller gets Spring's `HttpClientErrorException`.
- The reply is read straight into the `GatewayResult` record; no JSON parsing code is written by hand.

## Rules and defaults

- **Builders you can inject (Spring Boot 4.1):** a prototype `RestClient.Builder`, so each class gets its own copy. There is no `RestTemplate` bean, only a `RestTemplateBuilder`.
- **Timeouts (Spring Boot 4.1):** `spring.http.clients.connect-timeout` and `spring.http.clients.read-timeout` apply to all auto-configured clients. A read timeout throws `ResourceAccessException`.
- **Which library sends the request:** Spring Boot picks Apache HttpClient if it is on the classpath, then Jetty, Reactor Netty, the JDK `HttpClient`, and finally `HttpURLConnection`.
- **Interface clients:** methods marked `@GetExchange` or `@PostExchange` on an interface; `@ImportHttpServices` registers them, and `spring.http.serviceclient.<group>.base-url` sets the URL.
- **RestTemplate:** still works in Spring Framework 7.0. `@Deprecated` is planned for 7.1 and removal for 8.0.

## Interview Qs

### RestTemplate vs RestClient vs WebClient?

RestTemplate is the old blocking client with template methods like `getForObject`; its removal is planned for Spring Framework 8.0. RestClient is also blocking, with a fluent API. WebClient is non-blocking and reactive. New blocking code uses RestClient; reactive code uses WebClient.

### What is an HTTP interface client?

A Java interface whose methods carry `@GetExchange` or `@PostExchange` with the path. Spring creates a proxy, an object that implements the interface by making the HTTP calls through RestClient or WebClient. The remote API is declared once, and callers use plain method calls.

### How do you handle a 4xx from the called API?

By default `retrieve()` throws a `RestClientException` subclass, such as `HttpClientErrorException` for 4xx. Add `onStatus` to map a status to your own exception, or use `exchange()` to read the response yourself.
