## Why it exists

"REST" is used loosely. The model gives a shared scale to say how far an API really follows REST, and what hypermedia adds.

## How it works

| Level | Adds | Payment example |
|---|---|---|
| 0 | One URI; every call is a POST (RPC over HTTP) | POST /api with an action inside |
| 1 | One URI per resource | /payments, /payments/PAY101 |
| 2 | HTTP verbs and status codes | GET /payments/PAY101 returns 200 |
| 3 | Hypermedia links in responses | PAY101 links to its refund and receipt |

- Fowler calls the model a learning aid, not a definition of REST.
- Classic SOAP services sit at level 0.

## Example

```json
{
  "paymentId": "PAY101",
  "status": "SUCCESS",
  "_links": {
    "self":    { "href": "/api/payments/PAY101" },
    "refund":  { "href": "/api/payments/PAY101/refunds" },
    "receipt": { "href": "/api/payments/PAY101/receipt" }
  }
}
```

## Interview Qs

### What is HATEOAS?

Hypermedia as the Engine of Application State: each response includes links to related resources and allowed next actions, so the client follows links instead of hard-coding URIs.

### Explain the Richardson Maturity Model.

Level 0 tunnels calls to one endpoint. Level 1 adds a URI per resource. Level 2 uses HTTP verbs and status codes properly. Level 3 adds hypermedia links.

### Is HATEOAS required?

By Fielding's definition, yes: without hypermedia it is not REST. In practice many APIs stop at level 2 and document their URIs instead.
