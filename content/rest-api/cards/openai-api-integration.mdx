## What it is

An LLM (large language model) is the kind of model behind ChatGPT, and OpenAI offers its models to programs as a REST API. Calling it from Java is an ordinary HTTPS POST: you send the model id and your input as JSON, prove who you are with a Bearer API key, and read the generated text from the JSON reply. ChatGPT is the chat app; your code calls the OpenAI API.

## Why it exists

Interviewers ask "how would you add an AI feature?" to see whether you treat it as an external dependency. It is one, so the rules for the payment gateway apply: keep the key secret, set timeouts, handle 429, cap retries, and parse the JSON properly. The same small shape also answers the wider "write integration code" question for Redis, Kafka and AWS.

1. The service builds a [RestClient](card:rest-clients) for `https://api.openai.com/v1` with the header `Authorization: Bearer <key>`, reading the key from an environment variable.
2. It POSTs to `/responses` a JSON body with `model`, `input` and `max_output_tokens`.
3. OpenAI replies 200 with an `output` array. Items of type `message` hold content parts of type `output_text`; other items, such as reasoning, may come first.
4. The code keeps the message items and joins their text parts.
5. On a rate-limit 429 it waits for `Retry-After`, retries a few times, then gives up.

The same "one client class, one main call" shape answers the other integration questions:

| Tech | Java or Spring class | Main call |
| --- | --- | --- |
| OpenAI | `RestClient` | `post().uri("/responses").body(...).retrieve()` |
| Redis | `StringRedisTemplate` | `opsForValue().set(key, value, ttl)`, `get(key)` |
| Kafka producer | `KafkaTemplate` | `send(topic, key, value)` |
| Kafka consumer | `@KafkaListener(topics = "...")` | the method runs for each record |
| AWS S3 | `S3Client` (SDK 2.x) | `putObject(PutObjectRequest, RequestBody)` |
| AWS SQS | `SqsClient` (SDK 2.x) | `sendMessage(SendMessageRequest)` |
| AWS RDS | `JdbcClient` or JPA, as for any SQL database | `sql(...).param(...).update()` |

## Example

The payment API writes a short summary of a customer's payments. The client class sends the request:

```java
@Service
class AiClient {
    private final RestClient http;
    private final String model;
    AiClient(RestClient.Builder builder, @Value("${openai.model}") String model) {
        this.model = model;
        this.http = builder.baseUrl("https://api.openai.com/v1")
                .defaultHeader("Authorization", "Bearer " + System.getenv("OPENAI_API_KEY")).build();
    }
    String ask(String prompt) {
        return http.post().uri("/responses")
                .body(Map.of("model", model, "input", prompt, "max_output_tokens", 500))
                .retrieve().body(Reply.class).text();
    }
}
```

Records read the reply:

```java
record Reply(List<Item> output) {
    String text() {                       // skip reasoning items, join the text parts
        return output.stream().filter(i -> "message".equals(i.type()))
                .flatMap(i -> i.content().stream())
                .filter(p -> "output_text".equals(p.type()))
                .map(Part::text).collect(Collectors.joining());
    }
}
record Item(String type, List<Part> content) {}
record Part(String type, String text) {}
```

What to notice:

- The key comes from `OPENAI_API_KEY` at runtime, so it is never in the code, in Git or in a browser.
- The model id comes from `openai.model` in configuration; switching models is a config change.
- `max_output_tokens` caps how much text the model may write, which caps the cost of one call.
- `text()` filters by `type` instead of taking `output[0]`, so a reasoning item at the start does not break it. Jackson ignores the reply fields the records do not declare.

## Rules and defaults

- **Responses or Chat Completions:** OpenAI recommends `POST /v1/responses` for new projects. `POST /v1/chat/completions` with `messages` is still supported.
- **Where the key lives:** on the server only, in an environment variable or a secret store.
- **429 handling:** for a rate limit, wait for `Retry-After`, or back off with jitter, and cap the attempts. The official SDKs already retry 429 and 5xx errors twice by default, so turn their retries off or do not wrap a second retry loop around them.
- **Tracing a call:** log the `x-request-id` response header; OpenAI support uses it to find a request.
- **Libraries:** the official [openai-java SDK](card:openai-java-sdk) and [Spring AI](card:spring-ai-chatclient) wrap the same HTTP call.

## Interview Qs

### How would you integrate the ChatGPT API in Spring Boot?

Code calls the OpenAI API, not ChatGPT. One service wraps a RestClient: POST `/v1/responses` with model and input as JSON and a Bearer key from the environment, never in code, Git or a browser. I map the reply to records, set timeouts and cap the output tokens.

### What do you do when OpenAI returns 429?

A rate-limit 429 is retryable: wait for `Retry-After`, else back off with jitter, and cap the attempts. Quota and spend-limit 429s need someone to act, not retries. The official SDKs already retry 429 and 5xx twice by default, so I do not stack a second loop on top.

### Is this small client production-ready?

No, it is the skeleton. Production adds timeouts, capped retries, the key in a secret store, logging of `x-request-id`, limits on input size and output tokens, and handling of failed or empty replies.
