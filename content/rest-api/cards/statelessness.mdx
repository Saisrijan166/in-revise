## Why it exists

If a server keeps each client's session, every call must reach a server that has it, and a crash can lose it. Stateless requests remove that tie.

## How it works

- The token proves who is calling on every request; see [JWT vs session cookie](compare:jwt-vs-session-cookie).
- A stateless request also tells a cache everything it needs to reuse a response.

## Interview Qs

### What makes a REST API stateless?

Each request carries everything needed to process it, such as credentials and ids. The server does not depend on session state stored from earlier requests.

### Why does statelessness help scaling?

No request needs a particular server, so a load balancer can send it to any instance. You add instances freely and survive one failing without sticky sessions.

### Can a stateless API store data in a database?

Yes. Stateless is about session state between requests. The payments themselves are resource state and live in the database.
