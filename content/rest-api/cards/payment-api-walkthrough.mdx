## Interview Qs

### Design a REST API for payments. Where do you start?

With the resource and its states: PAY101 goes PENDING to SUCCESS or FAILED. Walk the ten steps, then go deep on idempotency and timeouts, where money gets charged twice.

### The gateway charged ₹500 but your call timed out. What now?

Do not charge again. Treat it as [unknown and reconcile](card:unknown-outcomes), retrying only with the same idempotency key.

### Which tests prove the design?

The [six payment cases](card:api-testing-strategy): valid, invalid amount, no login, wrong account, duplicate key, gateway timeout.
