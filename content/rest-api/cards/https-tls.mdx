## What it is

TLS (Transport Layer Security) is a protocol that wraps a network connection in encryption. HTTPS is ordinary HTTP sent over a TLS connection, which is why the URL starts with `https://`. Before any request is sent, the server proves who it is with a certificate: a file, signed by a certificate authority that operating systems and browsers trust, that ties the server's name to a key only that server holds.

## Why it exists

On plain HTTP every byte, including the `Authorization` header, travels as readable text through Wi-Fi routers, internet providers and proxies. Anyone on that path could copy a bearer token or a Basic password and reuse it, or change ₹500 to ₹5,000. TLS encrypts the traffic, detects any change, and lets the client check it is talking to `api.shop.example` and not an impostor.

1. The client opens a connection and offers the TLS versions and ciphers (encryption methods) it supports; the server picks one, ideally TLS 1.3.
2. The server sends its certificate. The client checks that a trusted certificate authority signed it, that it has not expired, and that it names the host in the URL. If any check fails, the client stops before sending the request.
3. Both sides agree on fresh session keys. Every HTTP request and response after that is encrypted and checked for changes.
4. In production TLS often ends at the load balancer, which holds the certificate, decrypts, and forwards to the service, either re-encrypted or over mTLS (mutual TLS, where the client shows a certificate too).

So the key is: TLS protects data while it moves, not where it is stored.

## Example

This real run connects to a public API and prints what curl checked during the TLS handshake.

```bash
curl -sv -o /dev/null https://api.github.com/ 2>&1 | grep -E "SSL connection|subject:|issuer:|verify ok"
```

```text output
* SSL connection using TLSv1.3 / TLS_AES_128_GCM_SHA256 / X25519 / id-ecPublicKey
*  subject: CN=*.github.com
*  issuer: C=GB; O=Sectigo Limited; CN=Sectigo Public Server Authentication CA DV E36
*  SSL certificate verify ok.
```

What to notice:

- `TLSv1.3` is the negotiated version, and `TLS_AES_128_GCM_SHA256` is the cipher that encrypts the traffic and detects changes.
- `subject: CN=*.github.com` is the name in the certificate. It matches the host `api.github.com`, so curl knows it reached the real server. The `issuer` is the certificate authority that vouched for it.
- `verify ok` means every certificate check passed. With a wrong host name or an expired certificate, curl stops with an error instead. The `-k` flag skips these checks and must never be used in production.

## Rules and defaults

- **Versions:** TLS 1.3 is RFC 9846 (July 2026), which replaced RFC 8446. TLS 1.0 and 1.1 are deprecated by RFC 8996 (March 2021); disable them.
- **HSTS:** the `Strict-Transport-Security: max-age=<seconds>` response header makes browsers use only HTTPS for that host for that many seconds (RFC 6797). It helps browser apps; API clients should be configured with `https://` URLs and refuse plain `http://`.
- **Termination:** when the load balancer decrypts, traffic behind it is plain unless you re-encrypt it or use mTLS.
- **Not covered by TLS:** data at rest in the database, a token stolen from a device or a log, and bugs in your authorisation.

## Not to be confused with

SSL (Secure Sockets Layer) is the older protocol that TLS replaced. SSL 3.0 must not be used (RFC 7568), yet people still say "SSL certificate" for what is now a TLS certificate. Rule: say TLS; SSL is only the old name.

## Interview Qs

### What does TLS protect, and what does it not?

It protects data in transit: nobody on the path can read or change it, and the client knows it reached the real server. It does not protect stored data, a token stolen from a device, or a bug in your authorisation.

### What is mTLS and when do you use it?

Mutual TLS: both sides present certificates, so the server also knows which client is calling. Each microservice can then prove its identity to the others without passwords, so mTLS suits service-to-service calls inside a system.

### What is TLS termination?

The load balancer holds the certificate and decrypts incoming traffic, so the app servers skip that work and certificates are managed in one place. The trade-off: traffic behind it is plain unless you re-encrypt it or use mTLS.
