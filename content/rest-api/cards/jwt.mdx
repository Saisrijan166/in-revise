## Why it exists

Calling a login server on every request is slow. A JWT carries the caller's identity and rights in a signed token, so any API can check it by itself.

## How it works

<Steps label="How an API validates a JWT">
  <Step title="Split">Take the three Base64url parts from `Authorization: Bearer`.</Step>
  <Step title="Pick the algorithm">Use only the one you expect, such as RS256. Never trust `alg: none` from the header.</Step>
  <Step title="Verify the signature">Use the issuer's public key; reject on any mismatch.</Step>
  <Step title="Check the time">Reject if now is after `exp` or before `nbf`.</Step>
  <Step title="Check who">`iss` is your trusted issuer and `aud` names this API.</Step>
  <Step title="Authorise">Only now use `sub` and scopes to decide access.</Step>
</Steps>

- To log users out early, revoke the [refresh token](card:oauth2-and-oidc) or keep a denylist of `jti` values.

## Example

```json
{
  "iss": "https://auth.shop.example",
  "sub": "customer-42",
  "aud": "payments-api",
  "scope": "payments:write",
  "iat": 1792483200,
  "exp": 1792484100
}
```

## Interview Qs

### Can you decode a JWT without the key?

Yes. The header and payload are just Base64url JSON. The key is needed only to check, or create, the signature. That is why the payload must hold no secrets.

### How do you log out a user who has a JWT?

You cannot delete a self-contained token. Keep it short-lived, revoke the refresh token, and if you must stop it at once, deny its `jti` until it expires. A denylist brings back server state.

### What is the alg none attack?

An attacker changes the header to `alg: none` and drops the signature; a careless library accepts it. Fix: verify only with an allow-list of algorithms you chose.
