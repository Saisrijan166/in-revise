## Why it exists

REST is not the only way to call a service. Interviewers ask when you would leave it, and what each choice costs.

## How it works

<Compare id="rest-vs-soap-vs-graphql-vs-grpc" />

- **Over-fetching:** a response carries fields the screen ignores. **Under-fetching:** the screen needs extra calls. GraphQL asks once, for exactly those fields.
- gRPC calls: unary, server streaming, client streaming, bidirectional streaming.

## Example

```text
POST /graphql
{ payment(id: "PAY101") { status amount } }
```

## Interview Qs

### When would you choose gRPC over REST?

For internal service-to-service calls that need a strict contract, small binary messages or streaming. Keep REST at the edge for browsers and partners, since browsers need gRPC-Web and a proxy.

### What problem does GraphQL solve?

Over-fetching and under-fetching: different screens need different fields. The client sends one query naming the fields, to one endpoint, and gets just those back.
