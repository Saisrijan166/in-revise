JAVA

1. Java Basics

What is Java?

Java: A high-level, object-oriented, class-based programming language designed to be portable and platform-independent.

JDK: Java Development Kit; used to develop Java programs.

JRE: Java Runtime Environment; provides the environment needed to run Java programs.

JVM: Java Virtual Machine; executes Java bytecode.

Bytecode: Intermediate .class code generated by the Java compiler.

Platform independent: Java bytecode can run on different operating systems using their JVM.

WORA: "Write Once, Run Anywhere."

Java Flow

.java source code
      ↓
javac compiler
      ↓
.class bytecode
      ↓
JVM
      ↓
Machine code

JDK vs JRE vs JVM

JDK
 ├── JRE
 │    └── JVM
 └── Development tools

JDK: Develop + compile + run.

JRE: Run Java applications.

JVM: Actually executes bytecode.

Compilation vs Execution

Compilation: .java → .class.

Execution: JVM loads and executes .class.

Example

class Main {
    public static void main(String[] args) {
        System.out.println("Hello Java");
    }
}

main(): Starting point of a normal Java application.

public: JVM must be able to access it.

static: JVM can call it without creating an object.

void: Returns nothing.

String[] args: Receives command-line arguments.

5. Type Casting

Widening

Widening: Smaller compatible type → larger type.

Automatic: Usually no explicit cast required.

Narrowing

Narrowing: Larger type → smaller type.

Explicit cast required.

Can lose data.

Reference Casting

Upcasting: Child object referenced by parent type; automatic.

Downcasting: Parent reference converted to child type; explicit and can fail.

23. Diamond Problem

Diamond Problem

Happens when a class could inherit the same method through multiple paths.

Java Interface Solution

If two interfaces provide conflicting default methods, implementing class must resolve the conflict.

interface A {
    default void show() {}
}

interface B {
    default void show() {}
}

class C implements A, B {
    public void show() {
        A.super.show();
    }
}

1. Abstract Class vs Interface — Why Interface?
Question
If abstract class already exists, why do we need an interface?

Simple answer
Abstract class is mainly for sharing common state/behavior. Interface is mainly for defining a contract/capability that different, unrelated classes can implement.

Example:

abstract class Animal {
    String name;

    void eat() {
        System.out.println("Eating");
    }

    abstract void sound();
}

Good when classes are closely related:

Animal
 ├── Dog
 └── Cat
But suppose:

Payment
 ├── UPI
 ├── CreditCard
 ├── PayPal
 └── Wallet
These classes don't need to share a common parent class just to define pay().

interface Payment {
    void pay();
}

class UPI implements Payment {
    public void pay() {
        System.out.println("UPI payment");
    }
}

class CreditCard implements Payment {
    public void pay() {
        System.out.println("Card payment");
    }
}

The big reason
A Java class can:

class UPI implements Payment, Refundable, Trackable {
}

But it can extend only one class:

class UPI extends PaymentBase, OtherBase { } // ❌

Remember
Abstract class → "What you ARE + shared implementation/state"

Interface → "What you CAN DO / contract"
2. Why Interface if We Can Just Use a Normal Class?
Question
Why not create a normal Payment class instead of an interface?

Answer
Because an interface lets us depend on the contract, not a specific implementation.

Payment payment = new UPI();

Later:

Payment payment = new CreditCard();

The calling code can remain the same.

Remember
Interface → loose coupling
Implementation → can change
3. Why Abstract Class if Interface Exists?
Question
If interfaces can have methods with implementation, why use abstract classes?

Answer
Because an abstract class can provide shared instance state + constructors + common implementation.

    protected double amount;

    Payment(double amount) {
        this.amount = amount;
    }

    void printAmount() {
        System.out.println(amount);
    }

    abstract void pay();
}

Remember
Interface → contract/capability
Abstract class → common base + shared state/behavior

    }

If default methods conflict, C must resolve the conflict.

One class inheritance + multiple interface implementation.

Question → identify concept → remember syntax skeleton → write logic → mentally verify output

We should therefore practice Java as a coding language, not as a list of theoretical topics.

0. The Core Rule
For every question, think in this order:
1. What data do I have?
2. What do I need to return/print?
3. What loop / collection / method do I need?
4. What is the Java syntax?
5. What happens for each value?
6. What is the final output?

Example:
Count even numbers in an array.

Think:
data → int[]
condition → number % 2 == 0
state → count
loop → for
output → count

Then code:
int[] nums = {1, 2, 3, 4, 5, 6};

int count = 0;

for (int n : nums) {
    if (n % 2 == 0) {
        count++;
    }
}

System.out.println(count);

Output:
3

static boolean isPalindrome(String s) {

    int left = 0;
    int right = s.length() - 1;

    while (left < right) {

        if (s.charAt(left) != s.charAt(right)) {
            return false;
        }

        left++;
        right--;
    }

    return true;
}

Then code:
static int secondLargest(int[] nums) {

    int largest = Integer.MIN_VALUE;
    int secondLargest = Integer.MIN_VALUE;

    for (int n : nums) {

        if (n > largest) {

            secondLargest = largest;
            largest = n;

        } else if (n > secondLargest && n != largest) {

            secondLargest = n;
        }
    }

    return secondLargest;
}

90. ONE IMPORTANT STREAM CONFUSION: MAP VS FLATMAP
map:
List<List<Integer>> nums =
        List.of(
            List.of(1, 2),
            List.of(3, 4)
        );

map keeps nesting:
nums.stream()
    .map(list -> list.stream().map(x -> x * 2).toList())

Conceptually:
[[1,2], [3,4]]
      ↓
[[2,4], [6,8]]

flatMap flattens:
nums.stream()
    .flatMap(List::stream)
    .toList();

Result:
[1, 2, 3, 4]

Remember:
map     → transform
flatMap → transform + flatten
